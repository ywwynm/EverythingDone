# Thing Background 编辑器的配色模型

重构 `COLOR_EDIT` 颜色编辑器（详情页与首页卡片外观面板）时，颜色条采用
**一条「纯黑 → 全色相饱和彩虹 → 纯白」的一维复合渐变带**作为颜色选择控件：
拖拽 handle 落在该曲线上取色；对任意来源（预置色、RGB/Hex、随机、从世界取色）
的颜色，用「在曲线采样点中取最近点」反向定位 handle，并在 handle 圆点内部
**填充当前真实颜色**。RGB/Hex 输入框是颜色的**精确数据源**，颜色条只承担
**粗选与可视化**。

## 为什么

一维颜色条本质是在三维颜色空间里走一条曲线，无法精确覆盖所有颜色——尤其是
浑浊、偏暗、粉彩这类颜色（本项目 10 个预置色大多如此）。用户明确要求颜色条
要「包含几乎所有颜色，包括黑色和白色」，因此曲线必须经过黑与白并扫过全部色相。
我们接受「浑浊色拖拽时 handle 落在近似位置」这一损失，并用两点补偿：
handle 内部恒显真实色（所见即当前色），RGB/Hex 提供无损精确输入。

## 考虑过的方案

- **纯色相彩虹（不含黑白）**：最标准、最简单，但颜色条无法到达黑/白/灰，
  直接违背「颜色条要含黑白」的要求，否决。
- **双控件（色相条 + 饱和度/明度条）**：能较完整覆盖色彩空间，但不再是用户
  要的「一根条」，且明显增加布局与交互复杂度，否决。

## 后果

- 颜色条对非曲线颜色的 handle 定位是近似的；这是有意为之，不是 bug。精确取色
  走 RGB/Hex。
- 颜色条同一套实现会在渐变 tab 的两个色区各实例化一次。
- 反向定位用轻量加权 RGB 距离即可（不必上 CIEDE2000），仅用于 handle 摆放，
  不影响最终落色。
