# 正在做的记事可被组织与选择，破坏性批量动作在执行层排除它（Doing Thing is organize-consistent and selectable; destructive batch actions exclude it at the action layer）

**Doing Thing**（`App.doingThingId` 标识、覆盖"正在做"蒙层的唯一计时记事）在组织维度
——拖拽重排、拖拽建夹 / 拖入文件夹、移动到文件夹、置顶——与普通正在进行记事完全一致，
并且在选择模式下**完全可被选中**（点按与"全选"都包含它）。它不被完成 / 删除 / 设为私密
作用，但这层保护**在动作执行层实现**（执行时跳过 Doing、在确认弹窗里写明），而不是靠
"让它不可选中"。这取代了此前散落在各触摸入口、把它弄成不可拖拽 / 不可选中的特判挡板。

## Considered Options

- **A（已选）**：完全可选中，破坏性动作执行层跳过 + 弹窗写明。
- **B**：仅手动点选可选、"全选"跳过它。
- **C**：完全不可选，移动到文件夹另造专属入口。

选 A：它最简单、让"移动到文件夹"直接复用既有"选中 → 工具栏"流程而无需新入口；并且把
"排除 Doing"统一收敛到一个执行层规则，而不是在选择层做不一致特判。B 增加"点选可、全选
不可"的别扭不一致；C 要为单条移动另造 UI，且与"可进入选择界面"的结论相悖。

## Consequences

- "排除 Doing"的逻辑从 Activity 触摸层下沉到 `ThingManager` 的选择 / 范围 / 状态变更层，
  顺带根治两个潜伏 bug：(1) "全选"扫入 Doing 而点按不能，口径不一致；(2) 选中含 Doing 的
  文件夹做完成 / 删除时递归命中并**真的**改了 Doing 状态，而 `changeFolderSubtreeContentState`
  只停常驻通知、不停计时，导致计时器指向已完成 / 删除的记事。
- 受保护的只有完成 / 删除 / 设为私密三类，且只影响"正在进行 → 完成 / 删除"这一类的所有
  成批路径（多选、文件夹内"完成 / 删除文件夹中所有记事"、根目录"全部完成"）；恢复 /
  永久删除作用于已完成 / 回收站记事，本就不含 Doing。
- "设为私密"无确认弹窗（靠私密密码 / 鉴权把关），其跳过反馈保留一个仅此动作使用的极简 Toast。
- 多个组织挡板被对称移除（建夹的 source 与 target 用同一判定，故两个方向一起放开）。
- "正在做"蒙层的尺寸与图标 / 文字缩放完全依赖卡片最终几何，因此卡片外观对 Doing 可编辑后，
  蒙层必须在最终几何上重算（"先外观、后蒙层"），此约束与既有的蒙层撑高渲染 bug 同源。
