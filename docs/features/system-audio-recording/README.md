# 系统音频录制

本功能为录音对话框增加可选择的音频输入源，并让所选输入同时用于 FableSol 实时响应与最终音频附件保存。

设计与代码实现已完成，自动测试和 Debug 构建已通过；真实 `MediaProjection`、后台录音和厂商音频栈行为仍需在 Android 10+ 真机上按 `execution.md` 验收。

## 已明确范围

- 在录音对话框的 `TimelyClockView` 下方增加一行“音频输入”。
- 提供“麦克风”“系统”“麦克风+系统”三个选项。
- 选项在首次开始录音前，以及点击“重新录音”回到准备态后可用。
- 最近一次选择的音频输入需要跨录音对话框记忆。
- 记忆值为“系统”或“麦克风+系统”时，新 Dialog 显示后立即请求系统捕获授权，使准备态 FableSol 能够响应系统声音。
- 系统授权取消、拒绝或采集初始化失败时，当前选择和持久记忆均回退到“麦克风”，并显示简短提示。
- 麦克风录音保持单声道；系统与麦克风+系统录音保存立体声，混合模式把麦克风居中加入左右声道。
- FableSol 分析最终保存混音的单声道副本，使实时动画与成品内容一致。
- 正式录音由带正确类型的前台服务持有，切换其他 App 后继续录制；返回后 FableSol 直接恢复当前实时响应，不回放后台动画历史。
- Android 14+ 请求整个屏幕范围的 `MediaProjection` 授权，但应用只消费音频，不读取或保存画面；界面必须在授权前向用户明确说明。
- “音频输入”使用带副说明的下拉 Popup，各选项说明采集范围、权限、版本与可捕获限制。
- 准备态显示并启用来源选择器；录音态与停止态整行隐藏且不占空间（2026-08-15 用户裁定），来源在通知中持续显示；重新录音回到准备态后再次显示并启用。
- 所选输入必须驱动 FableSol 动画，并能保存为正常的音频附件。

## 实现后的链路

- `AudioRecordDialogFragment` 绑定 `AudioRecordingService`，由服务持有捕获、混音、文件和投影生命周期。
- `AudioCaptureEngine` 生成最终 PCM，并把其单声道分析副本送给 FableSol；Dialog 不可见时解除接收器并清除边界队列。
- `AudioInputPicker` 继承项目 `PopupPicker`，以标题和副说明呈现三种来源；仅录音前的准备态显示并可选，录音态与停止态整行隐藏。
- 正式录音在前台服务内继续运行；通知可返回 Dialog 或“停止并保留”。
- 旧 `AudioRecorder` 继续供 FableSol 调参工具使用，不承担本 Dialog 的新服务会话。
