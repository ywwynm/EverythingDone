# 2026-08-16 - 通知停止录音后的返回路径验收与停止态时长修复

用户确认通知内"停止并保留"之后各返回路径的行为正确性。真机逐条验收并修复一处显示缺陷。

## 更新内容

- 修复：从通知"停止并保留"后再回到录音窗口（点"已停止"通知、点应用图标或从最近任务切回），停止态时钟此前不显示实际录音时长（重建的窗口没经历过录音计时）。录音会话现在记录停止时刻的最终时长，任何路径重建的停止态时钟都正确显示；窗口内正常停止的显示不受影响。真机复验：录约 14 秒经通知停止再从通知返回，时钟正确显示 00:00:14。
- 验收结论（OPD2515，Android 16）：通知"停止并保留"会封装录音文件并换发一条可点的"已停止"通知；点它、点应用图标（自动接力）、从最近任务切回，三条路径都正确回到停止态录音窗口（文件名、时长、重录/保存/导出视频/取消按钮齐全），保存与丢弃闭环正常。"已停止"通知未被系统聚合（显式分组生效）。
- 说明：通知里只有"停止并保留"，没有"取消丢弃"入口——丢弃需回到录音窗口操作，避免误触直接丢掉录音。
- 全量 Debug JVM 单测 901 例通过。
