# 2026-08-17 - 录音收尾防抢占与来源偏好持久化时序修正

外部审查第八轮 3 项发现（2 项 P2、1 项 P3）全部修复。

## 更新内容

- 会话收尾期间不再响应外部异步事件：关闭录音窗口的收尾窗口内若恰逢输入故障或系统撤销投屏授权，此前这些事件的处置会作废收尾流程（残留后台服务与假会话状态）；现在收尾一旦开始，这些事件一律忽略，收尾必定完整执行。
- 修正来源偏好的确认时机：此前"系统"来源可能在录音文件真正打开前就被记为"已确认"，存储故障时一次没成功的授权会话会把下次的默认来源改成"系统"（再次弹授权）；现在文件打开与输入启动全部就绪后才确认偏好，任何一步失败都不改写。
- 补上"未检测到系统音频"警告的最后一个残留窗口：旧预览迟到的静音警告如果赶在清零之后送达，新预览启动时会兜底清掉，不再出现健康预览上常驻假警告。
- OPD2515（Android 16）真机回归：预览、关闭窗口后服务完整退出、录音-停止-丢弃全部正常；全量 Debug JVM 单测 911 例通过。
