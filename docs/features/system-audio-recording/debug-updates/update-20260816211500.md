# 2026-08-16 - 录音封装失败路径的诚实化

外部审查第三轮提出 4 项发现（逐条核实全部属实，全部集中在录音收尾失败场景的反馈），全部修复并真机注入验证。

## 更新内容

- 录音收尾封装失败时（例如磁盘故障、空间不足），后台通知不再错误宣称"录音已停止并保留"：标题与正文明确说明"未能保留"。
- 收尾失败后的录音窗口不再显示文件名与导出按钮，保存按钮淡化且不可点，仅保留"重新录音"与"放弃"：界面不再诱导保存一个并不存在的文件。
- 任何类型的收尾失败（不限于常见 IO 错误）都会清理中间数据并正确结束流程：修复了此前个别异常会让录音停留在"处理中"、后台通知一直挂着的问题。
- 修复收尾失败时提示文案与事实相反的问题：此前非空间不足的失败会显示"已保留此前录音"（实际未保留），现区分为"录音收尾失败，未能保留"的专属提示。
- 简体、繁體（台/港）、英文四语言录音文案完整性审计通过。
- OPD2515（Android 16）真机注入验证：失败路径（通知、窗口状态、丢弃清理）与正常停止回归双向通过；全量 Debug JVM 单测 906 例通过。
