# 决策

## 2026-08-17 - MediaProjection 返回后的方向样本延迟采用一次性 Toast 提示

方向传感器限制发生在系统服务把样本交给应用之前，应用不能可靠绕过。录音 Dialog 只在
MediaProjection 授权成功返回后启动短时监测；若监测窗口内收到任一方向样本则静默取消，
只有持续没有样本时才显示长 Toast。取消授权、麦克风来源、普通 Activity 往返、已关闭实时
倾斜及正常快速恢复均不得触发。提示展示状态写入录音功能的持久偏好，安装期间最多展示一次。
文案使用通用“系统设置/设备动作与方向权限”表述，不检测或展示厂商品牌。

## 2026-08-15 - 系统来源只在完整配置成功后记忆，失败态保留恢复入口

“系统”和“麦克风+系统”不能在用户点选或系统授权页返回前写入跨 Dialog 偏好；只有服务已经取得有效 `MediaProjection`，完成 `AudioRecord` 配置并启动准备态预览后才提交。麦克风仍可作为无需外部授权的安全值立即记忆；授权拒绝、初始化失败和回退继续明确记忆麦克风。

为修复旧实现已经写入但无法证明配置成功的系统类偏好，持久化值同时带“已确认”标记。升级后第一次读取到没有该标记的“系统”或“麦克风+系统”时，一次性迁移回麦克风；之后只有新的完整成功配置才能写回带确认标记的系统类来源。

开始按钮与来源选择器使用不同的可用条件：开始录音必须处于已配置的准备态；来源选择器在 Binder 已连接、没有正在执行的操作且处于 `IDLE`、未配置 `PREPARED` 或 `ERROR` 时仍可点击。系统或麦克风准备操作超过 8 秒必须离开永久忙碌态：系统来源回退麦克风并显示原因，麦克风失败则进入仍可重新选择来源的 `ERROR`。

## 2026-08-15 - 记忆系统类输入时在 Dialog 打开后立即请求授权

音频输入选择跨录音对话框持久记忆。若记忆值为“系统”或“麦克风+系统”，新的录音对话框显示后立即请求 `MediaProjection` 授权，不等用户按下开始录音。这样准备态便能取得系统 PCM，并让 FableSol 在正式录音前响应当前系统声音。

## 2026-08-15 - 系统捕获不可用时回退并记忆麦克风

若用户取消或拒绝 `MediaProjection` 授权，或者系统音频采集初始化失败，则当前 Dialog 自动切换到“麦克风”，并把跨 Dialog 持久记忆同步更新为“麦克风”。界面显示简短原因提示；用户仍可重新选择系统类输入再次授权。

## 2026-08-15 - Android 8/9 显示但禁用系统类输入

项目最低支持 Android 8（API 26），而 `AudioPlaybackCapture` 从 Android 10（API 29）才可用。在 Android 8/9 上仍显示“麦克风”“系统”“麦克风+系统”三个选项，但后两项置灰并标注“需要 Android 10+”；麦克风正常可用。

## 2026-08-15 - 系统类输入保留立体声，FableSol 分析最终混音

- “麦克风”继续保存单声道 WAV，保持现有行为。
- “系统”保存立体声 WAV，保留来源音频的左右声场。
- “麦克风+系统”保持系统音频的左右声道，并把单声道麦克风居中混入两侧。
- FableSol 不分别分析两个输入，而是消费最终保存混音的单声道分析副本，使动画响应与成品内容一致。

现有 `FableSolAudioFilePlayer` 已能按解码器实际声道数播放，并在分析前下混为单声道，因此播放对话框能够接纳该可变声道策略。

## 2026-08-15 - 混合模式使用固定比例，不做自动 ducking

“麦克风+系统”不因检测到讲话而自动压低系统音频。两个输入采用固定、经实测标定的混音比例，混合前预留峰值余量，并在最终总线上使用透明软限幅防止削波。这样系统内容不会随讲话产生音量抽动，FableSol 也不会被人为的动态增益变化驱动。

## 2026-08-15 - 仅混合模式启用平台 AEC

“麦克风+系统”在手机外放时，麦克风会再次收进扬声器播放的系统内容。该模式优先避免延迟重影：设备支持时，为麦克风采集会话启用平台 `AcousticEchoCanceler`；纯“麦克风”模式继续保持现有低处理采集与关闭 AEC 的行为。若设备不支持 AEC，则仍允许混合录制，但显示使用耳机可避免重影的提示；第一版不引入自研软件回声消除器。

## 2026-08-15 - 系统输入静音时不自动切换来源

系统采集成功但持续没有信号时，不自动切换到麦克风，因为应用无法可靠区分“来源 App 禁止捕获”和“当前播放暂停或内容本身静音”。界面保留用户选择，并在持续未检测到系统信号时显示“未检测到可捕获的系统音频，部分 App 可能禁止捕获”；信号恢复后提示自动消失。“麦克风+系统”按独立的系统输入流判断该状态，不能被麦克风信号掩盖。

## 2026-08-15 - 正式录音由前台服务支持后台持续运行

- 用户按下开始录音后，三种输入模式都必须在切换到其他 App 时继续可靠录制，并显示不可省略的持续录音前台服务通知。
- “麦克风”使用 `microphone` 前台服务类型；“系统”使用 `mediaProjection`；“麦克风+系统”同时使用两种类型。服务必须在 Activity 可见且权限有效时启动。
- 准备态和停止态进入后台时不继续采集。正式录音的采集、同步混音、文件写入与 FableSol 音频分析状态由服务持有，不能继续由 Fragment 生命周期独占。
- FableSol 在后台不绘制，也不向不可见 View 无限积压特征。返回 Dialog 后直接响应当前实时声音，不快速回放后台期间的动画历史。

## 2026-08-15 - 必需输入硬终止时停止并保留部分录音

正式录音期间，若 `MediaProjection` 被用户或系统撤销，或“麦克风+系统”中的麦克风发生不可恢复错误，不静默降级为剩余输入。服务立即停止整次录音、正常封装并保留截至故障点的 WAV；若应用在后台，则更新通知说明录音已经停止，返回 Dialog 后进入停止态，允许保存或重新录音。

该规则只适用于捕获会话结束或不可恢复读取错误。系统输入内容本身静音、暂停或来源 App 禁止捕获时，仍按上一项决策继续录制，不误判为硬终止。

## 2026-08-15 - 前台录音通知提供返回与停止并保留

正式录音的前台服务通知显示当前音频输入来源和录音时长。点击通知返回现有录音 Dialog；通知提供“停止并保留”操作，该操作结束采集与对应的 `MediaProjection`，正常封装已有 WAV 并让 Dialog 进入停止态。通知不提供暂停，避免引入新的录音状态及不连续的音频时间线。

Android 13+ 首次从附件入口打开录音 Dialog 时，在麦克风权限之后按需请求通知权限，并只主动请求一次。用户拒绝后仍允许录音，但通过 Snackbar 说明：系统只会在“活动应用”入口显示前台服务状态，通知栏中的来源、计时和“停止并保留”操作不可用。

## 2026-08-15 - 系统类准备态在后台保留授权通知但停止 PCM 采集

系统类输入取得 `MediaProjection` 后，服务在 Dialog 可见时进行实时预览。Dialog 进入后台但尚未正式录音时，停止 `AudioRecord` 和 FableSol PCM 预览，不写入任何音频；为了在 Android 要求的 `mediaProjection` 前台服务中继续合法持有尚未结束的授权，会保留低优先级通知，并把文案改为“系统音频授权已启用”。返回 Dialog 后恢复预览。关闭 Dialog、改选麦克风、停止正式录音或系统撤销授权时才结束该投影会话。

## 2026-08-15 - Android 14+ 请求整个屏幕范围但只消费音频

Android 14+ 发起 `MediaProjection` 授权时，请求整个屏幕范围，而不是把系统音频输入限定到单个 App。这样正式录音期间切换不同播放器后仍能继续采集符合系统规则的播放音频。应用只创建和消费音频捕获链路，不读取、不编码也不保存任何屏幕画面。

由于系统授权页会使用“整个屏幕”等范围措辞，录音 Dialog 必须在用户选择系统类输入时主动说明：授权范围覆盖整个屏幕，但本应用仅采集音频，不读取或保存画面；部分 App 仍可能按自身策略禁止音频被捕获。

## 2026-08-15 - 音频输入使用带副说明的下拉 Popup

`TimelyClockView` 下方的“音频输入”选择器使用下拉 Popup。每个选项同时显示名称和位于名称下方的提示性文本，说明其实际采集内容、所需权限、系统版本限制、系统音频可捕获限制，以及系统授权虽覆盖整个屏幕但应用不读取或保存画面。Dialog 收起 Popup 后显示当前选中的输入名称。

建议使用以下首版文案，允许根据实际宽度自然换行：

- “麦克风”：录制设备麦克风。正式录音在切换到其他 App 后仍会继续，可从通知停止并保留。
- “系统”：录制其他 App 允许捕获的播放音频。需要 Android 10+ 和整个屏幕范围的系统授权，但本应用不会读取或保存画面；部分 App 可能禁止捕获。正式录音在切换 App 后仍会继续。停止录音会结束授权；也可从系统的屏幕共享状态入口撤销，撤销后将停止并保留当前录音。
- “麦克风+系统”：同时录制系统播放音频和设备麦克风。需要 Android 10+、麦克风权限和整个屏幕范围的系统授权，但本应用不会读取或保存画面。建议使用耳机减少回声。正式录音在切换 App 后仍会继续。停止录音会结束授权；也可从系统的屏幕共享状态入口撤销，撤销后将停止并保留当前录音。

系统撤销入口由 Android/设备厂商提供：Android 15 QPR1+ 可点击状态栏的屏幕共享状态条，其他版本通常可从系统的屏幕共享、投屏或录屏状态入口结束。应用始终监听 `MediaProjection.Callback.onStop()`，不依赖具体厂商 UI 名称。

## 2026-08-15 - 音频输入选择器按录音状态展示

- 准备态：在 `TimelyClockView` 下方显示“音频输入”行，允许展开 Popup 并更改来源。
- 录音态：在 Dialog 内完全隐藏该行，避免多余元素影响 FableSol 动画的观看效果；前台服务通知持续显示当前来源。
- 停止态：继续完全隐藏来源行，不展示本次录音采用的来源，也不保留该行的纵向空间。
- 用户点击“重新录音”并回到准备态后，来源行恢复到 `TimelyClockView` 下方并重新允许选择。

## 2026-08-15 - 来源选择收敛为右侧胶囊和前景 ripple

“音频输入”行只负责布局与状态位置，左侧标签不响应点击；右侧 36dp 高胶囊是唯一的 Popup 锚点和可点击区域。水平结构参考录音完成后的文件名行，但左右边界取当前字体下 `TimelyClockView.contentLeftPx()` / `contentRightPx()` 返回的稳定实际着墨包络，不能用固定 24dp 或 View 的 `left/right` 代替。标签按内容宽度布局，胶囊在固定 8dp 间距后以 `0dp + weight=1` 填满到实际着墨右边界；胶囊内部来源文字同样吸收剩余宽度，使下三角固定在胶囊最右侧。胶囊边缘本身就是可见边缘，因此不套用播放进度条手柄的 2dp 或保存图标路径的 1dp 光学校正。胶囊以记事纯色或渐变为底，并使用与 FableSol 未录音态相同的 `0.16` 透明度；来源文字与下三角图标使用未淡化的记事颜色。停止态隐藏下三角并禁用胶囊，但不额外降低整行透明度。

音频输入 Popup 使用 272dp 目标宽度、16dp 屏幕边距，并按当前可见窗口再次收窄及启用窗口裁剪，避免右侧越界。可用选项把项目现有的渐变触摸 ripple 放在前景层；点击后延迟 90ms 再关闭 Popup 和提交选择，使快速点击时仍可看到实际波纹反馈。
