## 修好了侧边封面下清单被截断的问题

卡片宽度为「宽」、封面放在左边或右边时，如果清单项的文字长到需要折行，卡片算出来的高度
容不下全部内容——最后一条会被压成十几像素，末尾那行省略号整个消失，看上去就像这条记事
只有两三项。现在修好了。

### 原因

卡片上的清单原先用 RecyclerView 承载，而它的子行**不会因为自己变宽而重新折行**：实测
RecyclerView 已经是 803 像素宽，子行却仍停留在上一次的 426，于是文字按 342 的可用宽度去
折，明明放得下也折成两行。侧边封面的宽度又要根据内容高度反推（封面是全高的，用户设定的
是它的形状），预先测量同样拿不到按新宽度计算的高度，两件事叠在一起就把内容挤出了卡片。

这不是上一版新增「清单项最大显示个数」带来的——把上限设成 8 时字号与旧版完全相同，一样
会被截断。

### 改动

卡片上的清单不再用 RecyclerView，改成逐行排布。行的测量因此变成同步的，会按当前宽度重新
折行，上面两个问题一并消失。卡片上最多显示十几条，本来也不需要回收。

字号、行间距、按级缩进、图标与首行文字的对齐这几项排版规则改为新旧两处共用同一份，避免
以后改了一处另一处对不上。

### 验证

侧边封面在左、在右，各配上限 2、3、4、5、6、8、11，共十四种组合全部正确：条目数与设定一致、
省略行都在，卡片高度随上限单调变化。封面在上方的普通形态与改动前一致。清单项的勾选、点击
卡片进入详情、已完成项折叠都照旧。

多级清单的缩进以及计时页、提醒全屏页的「不限条数」这两条路径未在设备上单独验证，前者的
缩进与层级样式是原样沿用的。
