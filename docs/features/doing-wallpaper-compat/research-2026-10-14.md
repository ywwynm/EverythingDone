# 卓易通环境下的桌面壁纸访问调研

日期：2026-10-14。

## 范围与证据边界

用户要求联网调研解决方案。本轮只核对项目实现和公开资料，不连接设备、不修改应用代码。用户反馈卓易通内 DoingActivity 背景为黑色；这不是本轮设备实测结果。真实运行原因需要最小测试页或应用内诊断进一步区分。

既有设备记录见 `memory/profile.md`：用户使用鸿蒙 7；此前其它功能诊断中，卓易通对应用报告 Android 16／API 36。该信息不等于当前壁纸问题的专项诊断，也不能证明宿主壁纸已经映射给 Android 服务。

本轮结论是“未找到有证据支持的公开自动获取方案”，不是“已经证明任何方案都不可能”。按用户的调研范围，本轮不开展 diagnose 技能中的设备复现、修复及回归阶段；不得把以下候选解释当作复现后的根因。

## 已核实的项目实现

- `app/src/main/java/com/ywwynm/everythingdone/activities/DoingActivity.kt:183`：`beforeSetContentView()` 设置 `FLAG_SHOW_WALLPAPER`、`PixelFormat.TRANSLUCENT`，清除窗口背景。
- 同文件 `clearOpaqueAncestorBackgrounds()` 清除内容视图到 DecorView 的祖先背景；`initBackground()` 只叠加 `0x66000000`，即 40% 黑色蒙版。
- 当前 DoingActivity 没有读取 `WallpaperManager.getDrawable()` 或壁纸文件。因此，“读取壁纸缺少权限”不能直接解释当前代码路径。
- `app/src/main/res/values/styles.xml` 的 Doing 主题另有 `windowShowWallpaper=true`；较高版本资源的主题定义不同，但运行时代码仍显式设置窗口标记。
- `docs/features/android-16-migration/review.md` 中旧版 DoingActivity 读取壁纸的描述属于历史记录，不能代替当前实现。

## Android 官方资料已确认的限制

- 官方推荐通过 `FLAG_SHOW_WALLPAPER` 在应用背景显示壁纸；项目已经采用这条路径。
- `getDrawable()`、`getWallpaperFile()` 等读取接口从 Android 13 起对普通应用受限；Android 14 起普通调用会抛出 `SecurityException`。官方同时注明持有 `MANAGE_EXTERNAL_STORAGE` 的应用可以读取，因此不能简化成“Android 14 完全禁止读取壁纸”。
- 获取 Android 运行环境中的壁纸数据与获取宿主鸿蒙壁纸是两个不同问题，不能仅根据 Android 接口存在就认定后者可用。

来源：[Android WallpaperManager](https://developer.android.com/reference/android/app/WallpaperManager)、[FLAG_SHOW_WALLPAPER](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_SHOW_WALLPAPER)。

## 原生接口与辅助应用的限制

- OpenHarmony 官方壁纸文档说明，壁纸管理接口从 API 9 起调整为系统 API。
- `wallpaper.getImage()` 是系统接口，需要 `ohos.permission.GET_WALLPAPER`，并明确只获取通过 `setImage` 设置的静态壁纸；旧 `getPixelMap()` 自 API 9 废弃。
- `GET_WALLPAPER` 属于 `system_basic`、`system_grant`，支持证书授权，但不是普通应用向用户弹窗申请即可获得的权限。
- 本地 DevEco SDK 的 `openharmony/ets/api/@ohos.wallpaper.d.ts` 也把旧 `getFile()` 标为 API 9 起废弃，并注明 `GET_WALLPAPER` 权限。
- 上述证据足以排除“给 APK 加一个普通权限”或“随便写一个普通原生辅助应用就能读取”这样的承诺；不能据此声称所有华为系统版本或平台合作接口都不存在其它能力。华为官网壁纸文档正文未能成功提取，本轮没有拿 OpenHarmony 上游文档代替对华为鸿蒙 7 实现的实测。

来源：[OpenHarmony 壁纸模块](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/reference/apis-basic-services-kit/js-apis-wallpaper.md)、[壁纸系统接口](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/reference/apis-basic-services-kit/js-apis-wallpaper-sys.md)、[系统应用权限表](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/security/AccessToken/permissions-for-system-apps.md#ohospermissionget_wallpaper)。

## 方案比较

| 方案 | 能否自动显示宿主当前壁纸 | 判断 |
| --- | --- | --- |
| `FLAG_SHOW_WALLPAPER`／`windowShowWallpaper` | 取决于卓易通的窗口与壁纸支持 | 项目已使用；值得做最小窗口验证，不能把重复添加标记当作修复 |
| `getDrawable()`／`getWallpaperFile()` | 未证明 | 受 Android 读取权限限制；即使可读，也须验证结果是否为宿主当前壁纸，不能只检查非空 |
| `MANAGE_EXTERNAL_STORAGE` 后读取 | 未证明 | Android 文档有权限例外，但授权不等于宿主映射；不建议仅为背景新增此广泛访问权限 |
| 普通鸿蒙原生辅助应用 | 没有已证实途径 | 已查到的原生读取接口属于系统接口，不能作为现成解决方案 |
| 用户选择壁纸原图，复制到应用私有目录显示 | 不自动跟随，能使用同一静态图片 | 可实现的替代方案；换壁纸后需重新选择，裁剪与动态效果可能不同 |
| `getWallpaperColors()` 派生背景 | 不能还原壁纸 | 只返回颜色且可能为空；必须确认是否对应宿主，不能作为获取图片的方案 |
| 改 `windowIsTranslucent` 或其他透明参数 | 未证明 | 仅作为兼容性实验；普通透明窗口显示下层内容，不保证下层就是壁纸 |

无需优先尝试的方向：`peekDrawable()`／`getFastDrawable()` 与 `getDrawable()` 受相同读取限制；`getBuiltInDrawable()` 取得系统内置壁纸，不是用户当前壁纸；反射隐藏方法或硬编码系统壁纸路径没有本环境的成功证据，不列为推荐方案。普通截图／录屏取得的是已合成屏幕，不能据此承诺得到无图标、无窗口遮挡的壁纸原图。

## 后续最小验证设计（尚未实施）

最值得先区分的是三种情况，按当前证据排序：

1. 卓易通没有将宿主壁纸提供给 Android 壁纸服务或合成窗口。预测：无业务内容的标准壁纸测试页也呈黑色；切换宿主静态壁纸后仍不变。
2. 壁纸存在，但当前窗口配置或 AppCompat 与卓易通兼容有差异。预测：原生 `Activity` 的透明测试页可显示，现有 DoingActivity 不可显示；仅调整对应窗口条件即可形成差异。
3. 卓易通支持部分静态壁纸，却不支持当前动态／主题壁纸类型。预测：宿主换成一张明显可辨的静态图片后测试页恢复。不能仅凭黑色认定“不支持”，用户也可能选择纯黑壁纸。

若继续实施，只做一轮合并诊断：

- 在应用内记录当前窗口 flags、格式、相关视图背景、`isWallpaperSupported()`、`getWallpaperId(FLAG_SYSTEM)`、`getWallpaperInfo()`、`getWallpaperColors()` 的返回或异常，以及系统与卓易通版本；不保存壁纸像素。
- 将原生 `Activity` 的标准壁纸窗口与现有 Doing 窗口进行对照，并由用户用两张明显不同的静态壁纸检查是否跟随。若额外试验透明主题，每次只改变一个窗口条件。
- 这些查询的结果仅用于区分问题，任何单项 true、非空、ID 变化或空 `WallpaperInfo` 都不能独立证明宿主壁纸可用；`WallpaperInfo` 为空也可能仅表示静态壁纸。
- 卓易通环境不以 ADB 为前提，诊断结果在应用内导出。无真机对照前不能宣称修复。

## 建议

保留现有标准 Android 显示路径。如目标是恢复自动跟随当前桌面壁纸，先做上述最小验证，再决定是修正应用窗口还是向卓易通反馈适配缺口。如目标是尽快提供有图像的背景，则可提供用户选择原图的选项，并明确它不自动同步桌面壁纸。此轮没有替用户确定产品方案。
