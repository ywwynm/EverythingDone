# 实现决定

## 2026-10-14 — 自选背景与按方向裁切

- 默认背景继续使用现有系统壁纸显示方式；用户图片作为可主动选择的背景来源，保留现有深色蒙版保障计时文字可读性。
- 设置位于“正在做事”分组，行高 72dp；三项菜单、裁切对话框外壳和裁切操作视图复用抽屉头图的现有组件。横竖屏各存中心与缩放，屏幕比例在运行时计算，不保存为可编辑参数。
- 用户指出平板 `9018f404` 已可横屏，随后明确要求 DoingActivity 允许横竖屏切换。页面将遵循系统方向设置，以实际背景区域宽高决定使用哪一套裁切。编辑器用当前屏幕尺寸的短边／长边分别计算两个固定比例，不假定设备自然方向为竖屏。Android 16 对目标 API 36 的大屏应用可忽略 Manifest 方向限制，见 [官方说明](https://developer.android.com/develop/adaptive-apps/guides/app-orientation-aspect-ratio-resizability)。
- 选图保持与抽屉头图相同的来源策略：可直接读取的本地文件引用原路径，其他 content URI 复制到应用目录后使用；不为本功能申请广泛存储权限。实际解码失败或文件丢失时显示默认背景。
- 用户图片按实际视图大小经过 `MediaCropTransformation` 渲染；默认背景与自定义图片均保持深色蒙版。支持现有图片加载器可播放的动图，裁切编辑器仍使用静态预览。
- 切换裁切选项卡先保留当前方向的草稿，确认时一次保存两套；取消调整不覆盖已保存的裁切。新选图片从两套居中裁切开始，与抽屉头图一样，取消裁切仍保留新选图片。
- DoingActivity 使用 `screenOrientation="user"`，自行处理方向和窗口尺寸变化；保留同一服务绑定、计时控件与粒子场景，只重算卡片宽高和背景取景。自定义图片放入既有内容树、位于原蒙版之下，不改变粒子运动及数字变形逻辑。
- 裁切对话框支持显示期间旋转，并保存两套未确认草稿用于配置／进程恢复。图片导入及预览解码在后台进行，不改变旧配置直到新图成功解码。
- 三星实机截图发现系统栏回调会覆盖旋转后重新计算的卡片左右间距。为 `applyBottomInsetAsScrollPadding` 增加仅在 Doing 使用的保留水平间距选项；其他调用保持原行为，测试补充旋转后卡片中心断言。
- 根据用户对初版外观的反馈，横竖屏切换改为与颜色面板、计时数字风格对话框一致的等宽文字选项：44dp 高、15sp，选中项加粗并使用完整强调色渐变，未选中项使用提示色；无下划线，触摸反馈复用 `GradientRippleDrawable` 的胶囊形波纹。
- 根据后续反馈移除可见裁切提示行，编辑器保留无障碍描述。动态创建的取消／确定按钮显式调用 `installAppChromeDialogActionButton`，统一字号、内边距和胶囊裁剪；确定按钮再应用完整强调色文字与同色胶囊波纹。路径文本与抽屉头图一样使用 `wrap_content`，移除单行限制及中间省略，设置行仍为 72dp。
- 用户反馈卓易通选图成功但提示网络文件后，用普通 PNG 的真实 ActivityResult 分发复现。保留新式回调分发，旧式通用文件校验仅处理铃声请求，避免重复处理新式图片结果；不把该误报归因于 HEIC，也不增加存储权限。
- 手机横屏时用现有 `DisplayUtil.isTablet()`（`sw600dp`）排除平板，按实际窗口宽高切换原有三个按钮的排列。按钮在右侧安全区域竖排；根据用户后续纠正，主体内容保持整页宽度，计时、卡片和提示相对整页水平居中，不预留右侧按钮列宽度。卡片下边界使用窗口安全底边，不再以按钮上沿限制高度。竖屏及平板继续底部横排，保留原按钮、计时控件与粒子场景实例。
