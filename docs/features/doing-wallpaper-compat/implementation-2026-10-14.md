# 正在做事背景与横竖屏实施记录

## 行为

- 设置的“正在做事”分组增加“正在做事界面背景”，与抽屉头图相同的 72dp 两行结构；下行显示默认选项或图片路径。
- 三项菜单提供默认背景、选择图片、调整裁切；只有可读的自选图片才显示调整。
- 复用 `MediaCropAppearanceDialogFragment` 和 `ThingCardCropEditorView`。竖屏、横屏选项卡分别保存中心及缩放，比例取当前窗口短长边；不提供自由比例滑条。
- 确认一次保存两套取景，取消保留原值；新选图成功解码后即生效，两套裁切从居中开始。对话框随旋转调整大小；配置恢复保存未确认草稿。
- DoingActivity 遵循系统方向设置，方向变化由当前 Activity 处理，保留计时服务、计时控件与整页粒子场景。

## 实现

- `DoingBackgroundSettingsController` 处理入口、后台 URI 导入、静态裁切预览及确认。原路径可读时直接引用，否则复制到应用文件目录；不申请新增存储权限。
- `DoingBackgroundCrops` 保存横竖屏独立状态，并限制非法中心与缩放值。
- `DoingBackgroundDisplay` 用实际背景视图尺寸选择裁切，通过现有 `MediaCropTransformation` 加载。原图丢失或解码失败回退默认系统壁纸；保留原有深色蒙版。
- 新背景 ImageView 位于原内容树和原蒙版之下，随既有粒子整页场景绘制。未修改粒子运动、着色器或计时数字变形逻辑。
- 旋转后重新计算卡片宽度、居中间距、可用高度，并解除此前横屏留下的高度上限。
- 三星截图复核发现 `applyBottomInsetAsScrollPadding` 会写回初始化时的水平间距，导致横屏卡片偏左。增加仅 Doing 启用的保留水平间距参数，其他调用默认行为不变。
- 新增可见文案覆盖项目现有语言资源。回归探针仅放在 debug 源集，没有新增普通设置中的诊断入口。

## 选图成功却提示网络文件的排查

- 用户反馈：卓易通选择本地图片后出现“无法添加网络文件”，但随后可进入裁切且图片正常显示；用户询问是否与 HEIC 后缀有关。
- 代码定位：`SettingsActivity.onActivityResult()` 调用 `super` 分发新式图片选择回调后，还会继续执行旧式结果处理。未识别的新请求也会进入通用路径校验；拿不到直接路径时显示上述提示。这一分支位于后缀检查之前。
- 现有设置回归直接调用 `onImagePicked()`，没有覆盖 Activity 结果分发层。本轮改为通过图片菜单启动选择器、由 instrumentation 返回可读但不暴露直接路径的 PNG URI，并在真实结果分发后检查裁切成功时是否同时出现错误提示。
- 修复前在三星 `R5CW20BLNKL` 确定性复现：普通 PNG 已复制并成功进入裁切，界面同时出现“无法添加网络文件”，新增回归因此失败。该错误分支不依赖图片后缀；HEIC MIME 已在 `FileUtil` 中映射，此次无需修改格式支持。卓易通的实际返回 URI 未获取，不声称已测量其提供器实现。
- 最小修复：抽屉图片、备份及记事导入等旧请求处理完成后，剩余路径及后缀检查只接收旧式铃声请求。保留 `super.onActivityResult()`，确保新选图回调继续完成导入。
- 修复后用同一入口及同一 PNG 在三星重跑：未出现网络或格式错误，导入、菜单、72dp 行高、两套裁切保存、旋转与取消恢复均通过。本轮修复前后各一轮设备验证，构建通过；测试恢复原背景与系统方向，不修改真实记事。证据为 `tmp/doing-background-picker-{red,green}.txt`。
- 本轮无需扩大到 HEIC 解码或卓易通文件桥接改造；尚未在卓易通实机复测用户的原始 HEIC 文件。遗漏此问题的原因是旧探针绕过结果分发层，现已改用真实 ActivityResult 路径。
