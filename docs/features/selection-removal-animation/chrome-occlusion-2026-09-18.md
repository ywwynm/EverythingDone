# 顶栏与半透明阴影遮挡修正

## 复现与归因

- 原验证页仅有不透明 TextView 顶栏，缺少真实渐变阴影。补用 `include_contextual_toolbar_things`，复用其实际高度、透明度与 drawable，不接触记事数据库或设备偏好。
- 魅族基线 `chrome-before-short`：左滑保持段卡片覆盖顶栏标题；`chrome-before2/partial`：批量移除在主体仍完整时出现与阴影等高的空白带。最终合成录屏与截图保存在 `tmp/` 对应运行目录。
- 假设一成立：共享粒子 Surface 和临时快照高于窗口 View，目前前景交接仅覆盖 FAB。
- 假设二成立：批量捕获以 `rl_contextual_toolbar.bottom` 裁切，该容器包含半透明阴影，导致阴影下的卡片材料提前消失。
- 假设三不成立：复现页没有选择模式退出逻辑，也没有改变阴影可见性或透明度，仍出现相同问题。

## 修正约束

- 顶栏及阴影是独立前景，保持原生透明度和叠放顺序；不烤入卡片素材，不把半透明阴影当成硬裁剪。
- 覆盖正常首页、选择模式、手势取消及回聚、菜单移除后顶栏退场；复用现有同步交接与缓冲释放机制。
- 兼容 Texture 路径应放在列表之上、首页前景之下，不新增粒子参数。

## 回归检查进展

- 先运行 `check_chrome_recording.py`：旧实现的顶栏区域平均 RGB 误差 16.983；批量移除主体仍完整时，阴影区域材料覆盖率最低为 0。两项均明确失败。
- 修正后魅族 `chrome-after-short` 顶栏区域平均 RGB 误差 0.0037，阴影区域误差 3.637（包含正在消散的材料变化）；短滑恢复正常。
- `chrome-after/partial` 的阴影区域材料覆盖率最低为 0.920，原先整条空白带不再出现；动画完成、补位与设置保留检查通过。
- 编译和 27 项相关 JVM 检查通过。

## 双设备合并回归

- 魅族 `chrome-normal-return`：正常顶栏下完成及回聚均提交到末帧，完成回调一次，原卡片属性恢复；192 帧合成录屏顶栏区域最大误差 2.863。FAB 内圈最大误差 3.764，未被覆盖。
- 魅族 `chrome-exit/partial`：卡片主体释放后补位，contextual toolbar 按生产使用的旧式平移动画退出，普通顶栏及阴影接替；前景 transitionAlpha 最终全部归还到 1。
- 三星 `chrome-samsung-short`：正常顶栏下短滑保持、回弹通过，静态截图顶栏误差 0.0041、阴影区域误差 3.332；FAB 内圈最大误差 3.910。
- 三星 `chrome-texture/partial`：同一 API 设备显式强制 Texture 兼容路径，半透明阴影下材料、补位及选择顶栏退出均通过。没有真实旧版 Android 系统，不能将此替代完整系统兼容性验证。
- 检查脚本排除两类无关信号：动画前先以同一静止画面标定录屏编码误差（三星 5.402），不能把编码误差误判为顶栏被覆盖；原卡片消失后停止评估其阴影材料，避免将补位卡片自己的圆角误判为裁切空白。改进后的检查对旧批量基线仍失败，材料覆盖率为 0。
- 两台设备 crash 缓冲为空，结束后无 `ParticleHomeForeground`、`ParticleFabForeground` 或 `ParticleCardHandoff` 残留。全程使用虚构页面，没有访问记事 DAO 或修改粒子偏好。
