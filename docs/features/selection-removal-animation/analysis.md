# 调用链分析与实现核对

## 2026-09-18 静态核对

本轮不修改应用代码、不连接设备。以下是当前工作区代码的静态事实，不是实机动画验证结果。

- `ThingsActivity.confirmSelectedStateChange` 将纯记事与包含文件夹的选择分开处理。
- 纯记事大部分状态变更进入 `handleUpdateStates`，最终调用 `ThingManager.updateStates` 后直接 `notifyDataSetChanged`，单选也不例外。
- 回收站的纯记事恢复单独调用 `restoreTrashedThings`；包含文件夹的内容操作通过 `applyUnionStateChange` 执行业务。二者最终经过 `refreshHomeAfterScopeStateChange` 重载当前搜索或普通投影并整表刷新。
- `ModeManager.backNormalMode` 在退出选择模式时也执行整表刷新。仅在动作末尾补一个 `notifyItemRemoved` 无法完整解决这条链路。
- `notifyItemRemoved` 仍用于滑动完成等单项入口。当前选择模式入口没有根据单选切换到该通知的分支。
- 抽查 2026-05-21 的 `6e824e7a7`：当时选择菜单也进入 `handleUpdateStates` 并整表刷新；尚无依据将当前缺少动画归因于最近的粒子改动，也未证实更早版本曾有“单选且可见”的专门移除分支。
- 文件夹为稳定组织骨架；内容操作是否使其卡片离开当前列表，取决于操作后子树是否还有当前筛选或搜索命中。不能根据“被选中”直接让文件夹消散。
- 需要先经过现有确认、私密鉴权和习惯/目标处理分支，得到最终操作集合，再确定真正离开列表的卡片；被跳过的正在做事记事，以及仍有匹配内容的文件夹，不应播放移除动画。
- `ParticleCardClip` / `ParticleVisibleBounds` 已支持沿父容器裁剪卡片可见矩形；这不等同于判断所有前景控件的遮挡。后续需要结合首页顶栏和 FAB 层级确定动画可见范围。
- 当前粒子规格 `ParticleDismissSpec` 使用一张位图和一个原点。批量消散可以评估将多个卡片的可见片段按原坐标合成透明素材，但需核对快照交接、透明间隔的材料预算及大范围性能，尚未验证。
- `ParticleMicroflakeModel.build` 的网格尺寸受素材宽高和 `max_cells` 上限影响；透明间隔即使最终不显示，也不能先假定没有材料构建成本。稀疏多选覆盖较大屏幕范围时，需防止粒径随包围矩形无意变粗。
- `AlertDialogFragment` 的确认按钮先调用 `onConfirm` 再 `dismiss`；`BaseDialogFragment` 自身可能播放消散粒子。因此列表动画不能直接从原 `onConfirm` 同步起播，否则可能被尚未退出的弹窗和暗层遮挡，或与其争用准备资源。
- 现有 `ModeManager.finishCurrentModeWithoutListRefresh` 可作为退出选择模式而不触发全表重绑的参考；它已经被移动到文件夹的动画路径使用。是否直接复用，留待实现设计。

## 已确认边界（2026-09-18）

- 动画范围为本次操作造成的“旧投影中存在、新投影中不存在”的卡片，与操作启动时实际可见范围的交集。通过类型和业务 ID 区分记事、文件夹，不依赖会变化的位置或选中标记。
- 屏幕外的条目直接更新数据；半露出的卡片只采集其可见片段；当前列表未展开显示的文件夹后代不额外生成卡片动画。
- 多张卡片保持原位组成同一透明素材，共用一次消散过程，卡片间空白和未受影响卡片不进入素材。
- 文件夹仍有匹配内容、习惯/目标被用户排除、正在做事记事被保护时，保留对应卡片，仅更新必要内容。
- 等最后一个确认或鉴权界面的主体退出后，再启动卡片消散；取消任一前置步骤不触发卡片动画。弹窗尾部粒子与列表动画是否允许重叠，需结合最终时序与性能验证。
- 整屏移空的提示与列表补位在同一阶段出现，避免仍有完整卡片时提前盖上空状态。
- 当前粒子大小、颜色精度、性能自动调节和系统动画关闭设置继续生效；合成失败的回退不改变业务动作结果，也不留下隐藏卡片。

## 实现与首轮验证

- 用户已确认共用设置、向左消散、主体消失后平滑补位，其余边界采用上述建议，详见 `decisions.md`。
- `ThingListRemovalAnimator` 固定旧 adapter 投影，执行变更后按带类型的稳定 ID 求差分，将可见退场卡片合成一次粒子动画。补位只派发差分，退出选择模式不再整表刷新。
- 共享渲染器根据实际材料计算主体消失相位，并以实际呈现帧触发补位。批量交接允许多个源卡片，补位时解除 holder 归属，避免动画收尾影响复用后的卡片。
- 粒子参数仍从 `ParticlePerfTuning` 读取，后者接收现有 `ParticleTuning` 设置；稀疏合成素材对透明间隔补偿材料预算。
- 27 项相关单元测试通过。两台授权设备的虚构列表各完成单选、混合多选、半可见、仅屏幕外选择、整屏移空五项测试，结果和可见性正确，布局抑制均解除，设置保持原值。实际菜单和视频核对继续进行。
- 实际菜单验证发现顶部占位记事的 ID 会在业务更新后递增；在本次差分中将其归一为固定身份，避免把顶部占位误判为移除并重新插入。该处理不改变业务 ID 或全局列表模型。
- 纯记事与混合选择统一通过现有同步状态批处理 API 执行，移除失去调用方的 `handleUpdateStates` / `alertForHabitGoal` 旧分支；保留习惯/目标二次确认、部件更新和永久删除后的资源清理。移空列表继续显示操作后的空状态提示。
