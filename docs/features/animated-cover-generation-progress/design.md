# 动态封面生成状态与进度设计

日期：2026-10-15。状态：已实现并完成两台指定设备的装机验证，已发布 debug `202610150954`。

## 用户可见行为

首页记事卡片的所有封面布局统一复用原附件数量行，不新增独立的一行。普通上下／左右封面沿用图片内原位置；整卡背景封面沿用底部内容区原位置。生成结束后恢复原附件数量。

| 状态 | 文案 | 图标与交互 |
| --- | --- | --- |
| 等待调度、排队或等待自动重试 | 等待生成动态封面 | 应用常用的小型转圈 ProgressBar |
| 准备源媒体、提取动态照片视频等 | 准备动态封面 | 应用常用的小型转圈 ProgressBar |
| 实际生成 | 动态封面生成中 | 饼状图反映真实处理进度，不额外显示数字百分比 |
| 成功 | 恢复原附件数量 | 恢复原图标和交互 |
| 最终失败 | 动态封面生成失败 | 停止进度动画，点击该行重试，保留静态封面 |

最终失败沿用此前已确认的决定：保留失败提示，直到重试成功或当前封面来源改变；普通重绑不自动抹去失败状态。

## 布局与外观约束

- 保持原数量行的单行高度、边距、对齐方式和省略规则；图标不能把这一行撑高。狭窄侧图仍单行截断，不因状态文字变长增加卡片高度。
- 图片内提示沿用已确定的深浅文字与 42% 不透明度遮罩配色；整卡背景继续沿用现有底部数量行的配色与排布。
- 进度刷新只更新图标；阶段变化才替换文字，不逐帧重新绑定整张卡片，不触发卡片尺寸、选择或列表进出动画。
- 完成后恢复数量行，不隐藏原行，不改变音频、提醒／目标、习惯等底部内容的顺序。

## 状态来源与生命周期

- `VideoCoverPreviewManager` 沿用现有缓存身份和 WorkManager 唯一任务机制，不修改生成参数、编码器或裁切逻辑。
- `VideoCoverPreviewWorker` 区分等待、准备、实际生成、自动重试和最终失败。进度来自真实帧处理，最终文件写入成功前不能展示完成。
- 普通图片尚未确认含有动态内容时不展示生成提示。`MotionPhotoCoverHelper` 确认动态照片后才进入准备状态，并覆盖提取失败的情况。
- 状态跟随当前媒体来源、源文件身份和选定视频帧。改变封面来源不取消旧任务，但旧任务不能更新新来源或已复用的卡片。
- 卡片重新出现时读取当前状态；正式回收时释放 UI 订阅。保持现有临时离屏保留媒体请求、正式回收清理请求的区别。
- 关闭自动播放、隐藏封面或私密内容未解锁时，遵循现有封面展示规则，不额外暴露状态。

## 已核对的兼容重点

- `card_thing.xml` 中图片内数量文字和底部数量文字均已限制单行，可以复用原位置；底部数量行参与自然内容高度计算，因此不能再追加一行。
- `BaseThingsAdapter` 在正常绑定、配色局部更新和选择态更新中分别处理数量行，状态展示需覆盖这些路径，避免被数量文字或原图标覆盖。
- `InterceptTouchCardView` 默认拦截子视图触摸，`ThingsAdapter` 还根据清单和当前模式调整拦截。失败重试不能只给文字设置点击监听，也不能全局关闭卡片拦截；必须保留普通点击、长按、拖动、清单点击和多选的既有行为。
- 文件夹卡片与普通记事复用 holder，文件夹缩略图也使用卡片布局。需要清除旧状态和回调，避免状态或点击入口带到文件夹上。
- 现有生成失败会丢弃完成回调，普通请求又可以重新入队。实现手动重试时需要同时处理失败状态保留和成功后的动态封面换装，不能只重新启动后台任务。
