## 动态封面：修正大视频进度与长后台恢复

用户反馈生成饼图接近闭合后仍需等待很久，长时间后台及反复切换前后台后可能进度错乱、重复生成。本轮在指定 OPPO、Samsung、魅族三台设备，用约 109 MB 的 4K／30 fps／24 秒视频复现，并按补充要求全程不主动锁屏，通过系统设置与测试应用切换模拟日常使用。

实测旧版到 99% 后仍需集中编码约 14 秒；三星发生已停止的旧 Worker 继续取帧，与新一轮交错上报进度和争用临时文件。`CoverGenerationState`、`VideoCoverPreviewManager` 与 `CoverGenerationBinding` 现将逐帧处理和最后编码分开：最后一帧处理完显示“正在编码动态封面”及转圈，完整文件发布后才恢复附件数量，保留原单行高度、编码器、720 长边、25 fps 和 3 秒内容。

生成过程增加停止检查、同源互斥、每轮独立临时文件、进度轮次校验及源文件身份校验。已停止的任务不能继续交付旧进度或结果；进程恢复优先使用已完成文件，否则重新准备。系统停止／回收不消耗真正生成失败的自动重试额度，实际失败仍有限次重试并保留手动重试入口。

`VideoCoverPreviewWorker` 生成期间使用静默低优先级前台媒体处理通知，完成自动移除。补测发现原 WorkManager 2.9.1 在进程回收后会发生前台服务超时崩溃，现升级到包含 Android 15 超时处理及前台任务交接修复的 2.10.5，重新执行完整三机矩阵。通知只含通用生成提示，不包含附件名或记事正文。

最终三机各完成：12 次前后台往返后再后台停留约 3 分钟；生成时回收测试进程并后台停留 3 分钟；集中编码时取消并立即重试，再后台停留 1 分钟。9 组场景均恢复数量和 GIF 播放，未新增应用崩溃；产物均为 720×405、75 个不同画面帧、3 秒。每机 72 项卡片回归通过，完整 JVM 测试 1685 项零失败／错误、3 项跳过，另补强并通过 7 项状态与并发检查。隔离包及夹具已清理，正式包数据未修改。

魅族等 ROM 仍可能暂停后台编码或回收进程；本次保证状态按当前任务恢复，必要时从头生成，不承诺所有 ROM 持续后台执行或原生编码断点续跑。
