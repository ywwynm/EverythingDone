# 动态封面生成进度决策

## 2026-10-17 - 缓存完成交接与创建异常处理

- 请求登记回调后，后台入队检查若发现 GIF 已完成，仍须调用既有完成交付入口；仅跳过入队会遗漏此前完成通知未覆盖的新回调。
- 创建临时文件及初始化媒体资源也属于可能失败的生成步骤，必须位于有限重试对应的异常处理与清理范围。取消异常继续单独传播，不计入普通失败。
- 本功能香港繁体采用“生成”，台湾繁体保留“產生”，按应用既有地区词表区分；其他语言保留相同封面名词和自然的动画表述。

## 2026-10-17 - 集中编码单独显示，后台执行可恢复

- 大视频实测和编码器源码确认，逐帧 API 只是保存输入图像，最后 `close()` 才完成全局色表、量化及编码。逐帧处理结束改为“正在编码动态封面”及转圈，取代原先最多显示 99% 的收尾方案；保留编码器、720 长边、25 fps 和 3 秒内容。
- 真实前后台切换复现已停止的旧 Worker 继续取帧、同一任务多轮进度交错。停止检查贯穿取帧、缓存帧、原生收尾和发布；同一输出互斥，临时文件按轮次独立，进度带运行轮次。
- 系统停止／回收不计入实际生成失败预算；只有真实生成失败才消耗最多三次自动重试。源文件身份变化后旧任务结束，不能重新计算新身份并代替新任务生成。
- 持续取帧需要前台媒体处理状态，生成期间使用静默低优先级通知，完成自动移除；Android 15+ 使用 `mediaProcessing`，较早系统使用 `dataSync`。通知仅显示通用提示，不包含媒体名称或记事内容。系统限制前台启动时仍由 WorkManager 等待重调度。
- WorkManager 从 2.9.1 升至 2.10.5，接入 Android 15 前台超时停止及前台命令交接修复；三机强制回收实测暴露的前台超时崩溃必须重新验证，不能只检查最终 GIF 可用。
- 校验文件完成后优先恢复可用封面，即使上次进程尚未提交 WorkManager 成功状态。详情、卡片等继续共享同一份派生预览。
- 复现、测试范围及限制见 [本轮排查](background-progress-investigation-2026-10-17.md)。

## 2026-10-15 - 等待与准备阶段可见

- 已提交但等待调度的任务显示“等待生成动态封面”；开始准备源媒体时显示“准备动态封面”。两种状态均使用应用现有的小型不定进度 `ProgressBar`。
- 实际生成阶段显示“动态封面生成中”，使用饼状图展示真实进度，不另外显示数字百分比；用户已明确选择等待／准备转圈、实际生成显示饼状进度的方案。生成完成后恢复附件数量提示。
- 普通图片尚未确认具有动态内容时，不因后台检测而显示动态封面生成提示。

## 2026-10-15 - 最终失败提供重试入口

- 自动重试用尽后，保留“动态封面生成失败”，停止进度动画，继续显示静态封面。
- 点击失败提示整行可重新生成；任务进行期间该行不作为重试按钮。
- 实现须区分自动重试等待和最终失败，卡片重新绑定不得仅因重新显示就覆盖最终失败状态或重复触发生成。

## 2026-10-15 - 所有封面布局统一复用附件数量行

- 用户选择所有封面布局统一采用临时替换数量行的方案，覆盖上下／左右封面与整卡背景封面。
- 等待、准备和生成期间，在原数量行的位置显示相应状态与进度图标；完成后恢复“X 张图片，Y 个视频”。
- 不新增独立状态行，不根据剩余空间在一行与两行之间切换；实现时保持原单行占用高度，兼容卡片与列表现有布局及动画。

## 2026-10-15 - 文字视觉对齐与失败持久化

- 用户查看实机截图后指出文字与图标未垂直居中。进度图标按当前文案的实际字形边界与文字基线计算视觉中心，保留原数量行的测量尺寸，不通过增加行高调整。
- 安装 TextView 的 compound drawable 后再设置饼状进度，避免系统在首次安装时把进度重置为零；同阶段刷新只更新进度图标。
- WorkManager 会清理已完成任务的历史记录，因此最终失败另按现有媒体缓存身份持久化。普通重绑仍保留失败；显式重试或成功后清除记录，附件源身份改变自然使用新状态。
- 动态照片准备失败时，一张卡片发起重试后，展示相同来源的其它卡片也恢复观察新任务；准备状态订阅随卡片释放，避免同源多卡保留过期失败提示。

## 2026-10-15 - 拖动软件快照中的加载图标

- 补测确认系统转圈的渲染线程动画在软件 Canvas 中仅有极短初始弧线。软件捕获时绘制同色、同尺寸的固定圆弧帧；真实窗口保留系统 ProgressBar 动画。
- 沿用拖动悬浮层与粒子材料的既有快照机制，捕获后不单独刷新其中的进度。后台任务继续，交接结束显示当前内容和封面；实机断言检查目标卡片自身恢复，而不是仅检查背景卡片。

## 2026-10-15 - 静态封面交接到 GIF 时保留占位

- 录屏发现首次生成完成与生成后重开自动播放都会出现短暂空封面；修复前绘制前检查分别复现 14 次空封面、缩略图 2 次／背景 3 次空封面。
- 复用已有有界位图缓存保存当前静态封面作为 GIF 解码占位。生成完成回调仍先核对绑定、来源和帧；关闭及重开自动播放仅忽略 `:anim` 标记，来源、帧、尺寸和裁切必须一致。不复用其它来源的图片，不增加解码器持有或改变动画方案。
