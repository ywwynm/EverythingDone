## 已知需求

首页记事卡片在动态封面尚未生成完成时，临时将附件数量提示替换为生成状态与进度图标；生成完成后恢复附件数量。所有封面布局统一采用这一规则，不新增独立状态行。详细要求见 [preferences.md](preferences.md)。

## 实现要点

- `VideoCoverPreviewManager` 通过 WorkManager 按媒体及起始帧去重生成 GIF，提供可释放的状态订阅；Worker 按实际处理帧数反馈饼图进度，最后一帧处理完切换为“正在编码动态封面”及转圈，文件完成后恢复数量。
- 同源生成串行且响应系统停止，临时文件、进度和源身份均按当前执行轮次核对；生成期间使用静默前台媒体处理通知。WorkManager 更新到 2.10.5，支持 Android 15 前台超时停止和命令交接。
- `VideoCoverPreviewWorker` 可能等待系统调度或存储条件，失败后存在自动重试和最终失败；这些阶段与实际生成不同。
- `MotionPhotoCoverHelper` 在生成 GIF 前检测动态照片并提取内嵌视频。普通图片检测期间保持数量；确认动态内容后展示准备状态，准备失败支持手动重试，同源多卡同步跟进。
- 切换封面来源不会取消旧来源的后台任务；进度展示必须跟随当前来源，避免旧任务回调更新已经复用的卡片。
- 普通上下／左右封面的数量提示叠加在图片内。媒体作为整卡背景时，数量提示位于底部内容布局，排在音频／提醒／习惯上方；卡片高度取封面目标高度与自然内容高度的较大值。新增状态行可能在留白不足时撑高卡片，因此已确定直接复用原数量行，不再增加独立的一行。
- 现有普通滑动持续加载／播放、离屏缓存与正式回收规则见 [动态视频封面](../animated-video-cover/README.md)，本功能须保持这些行为。
- `CoverGenerationBinding` 复用原数量行，阶段变化更新文案，同阶段仅更新饼图。转圈与饼图按字形视觉中心对齐；图片内沿用 42% 不透明度遮罩和现有明暗配色。
- 最终失败按缓存身份持久化，WorkManager 清理历史后仍保留；重试点击通过现有卡片触摸流程处理，保留多选、长按和拖动规则。

## 已确认方案

等待／准备阶段已确认显示，分别使用“等待生成动态封面”／“准备动态封面”和应用现有的小型不定进度圈。最终失败保留“动态封面生成失败”，点击整行重试，详见 [decisions.md](decisions.md)。

已确认所有封面布局统一临时替换附件数量行，完成后恢复数量；不采用新增一行或按剩余空间切换布局的方案。最终失败继续沿用保留失败提示、点击该行重试的决定。现有两种数量提示均限制为单行，实现时保持原有行高与截断规则。

用户已确认：等待／准备阶段使用应用常用的小型转圈 `ProgressBar`；实际生成阶段改用饼状图展示真实进度，不另外显示数字百分比。
