# RadioChooser 单选状态修复

本次修复设置等 dialog 中 `RadioChooserAdapter` 在迁移到渐变 radio 后出现的视觉单选回归。

用户反馈：radio chooser 不再像真正单选控件一样工作，并且可能出现文字已经高亮但 radio 未高亮，或 radio 高亮但文字未高亮的不同步状态。

诊断结果：`RadioChooserAdapter.pick()` 旧实现会在更新 `mPickedPosition` 前先刷新旧 item，导致旧 item 重新绑定时仍按选中态绘制；点击监听随后又额外刷新新 item，最终可能留下多个视觉选中项。这个刷新顺序也让文字和 radio 的视觉状态容易走到不同绑定路径。

修复内容：
- `pick()` 现在先记录旧位置并更新唯一选中位置，再分别刷新旧 item 和新 item。
- 重复点击当前项时会强制重绑当前 item，用于纠正 holder 复用或动画中断造成的临时不同步。
- 点击监听不再自行额外 `notifyItemChanged()`，统一交给 `pick()` 处理状态和刷新。

验证：
- 用最小状态机确认旧逻辑会得到 `old=0,1` 的多选视觉状态，新逻辑只保留 `new=1`。
- `./gradlew.bat :app:assembleDebug --console=plain` 通过。
