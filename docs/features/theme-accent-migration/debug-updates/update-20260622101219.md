# RadioChooser 渐变 radio 终态修复

本次继续修复设置等 dialog 中 `RadioChooserAdapter` 的 radio 视觉状态不同步问题。

上一轮只修正了选中位置的刷新顺序，但用户验证后反馈问题仍存在。重新排查后确认，问题与“加入渐变 radio tint 后才出现”直接相关：自定义 `GradientRadioDrawable` 的动画被 TextView compound drawable 或 RecyclerView 重绑流程打断时，没有恢复到真实 checked/unchecked 终态。

具体原因：
- `GradientRadioDrawable.jumpToCurrentState()` 原本只取消 animator，不会把 `checkedProgress` 设置到目标值。
- 如果系统在选中/取消选中动画刚开始时调用 `jumpToCurrentState()`，radio 会停在动画起点，也就是反状态。
- 于是会出现文字已经按当前 `mPickedPosition` 高亮，但 radio 仍显示未选中；或者文字已取消高亮，radio 仍显示选中。
- 另外，原来的动画触发依据是 ViewHolder 上一次绑定状态，滚动复用或普通重绑也可能触发不该有的反向动画。

修复内容：
- `GradientRadioDrawable` 记录 checked 终态和 `targetProgress`。
- `jumpToCurrentState()` 取消动画后立即把 `checkedProgress` 恢复到真实终态。
- `RadioChooserAdapter` 改为只在选中项真的变化时通过 payload 触发 radio 动画，普通 bind 和 holder 复用不再触发动画。
- 保留 `pick()` 的有效位置校验、旧/新 item 成对刷新，以及重复点击当前项时的强制重绑。

验证：
- 全项目搜索确认渐变 radio 入口只有 `RadioChooserAdapter`。
- `./gradlew.bat :app:assembleDebug --console=plain` 通过。
