# Cloud Sync 决策记录

云同步功能（账号内多设备同步记事与文件夹数据）的决策索引。设计文档落地前，本文件是权威决策来源。

## 2026-07-06 - 服务定位：公开多用户服务，小规模起步

同步服务按公开多用户服务设计（协议、账号体系、配额、防滥用都按多用户前提规划，避免将来推倒重来），但部署按最低成本起步：单台阿里云 ECS + OSS。接受随之而来的一次性合规功课（域名备案、隐私政策等），不在一期引入水平扩展、CDN、推送集群等规模化设施。

背景事实（调研确认）：当前主工程无 INTERNET 权限、无网络栈、无账号体系；ADR-0001 的 debug 更新渠道是"阿里云服务器静态文件 + ssh/scp"，刻意未运行 API 服务；Everything-Android 的 Thing 模型曾预留 `remoteId: String` 字段但未实现任何同步代码。

## 2026-07-06 - 一期同步范围：内容全量 + 设置漫游

一期同步：`things`、`thing_folders`、`reminders`、`habits`、`habit_reminders`、`habit_records` 全部行数据，附件文件（图片/音频/视频），以及应用设置漫游（SharedPreferences 按键逐项分类，内容/偏好类漫游，设备能力/权限/通知渠道等本地类不漫游；抽屉头图是文件，走附件管线）。

排除项：`doing_records`（计时历史）延后到二期追加（记入 followups）；`app_widget`（桌面小部件配置）是设备本地概念，永久不同步。

已知硬性前置：数据库中附件引用是绝对路径（`getExternalFilesDir()/image|audio|video/...`），跨设备路径不同，同步要求附件引用改为与设备无关的形式。

## 2026-07-06 - 后端形态：自建 API 服务

自建单体 HTTP API 服务 + 关系型数据库 + OSS 存附件，部署在已有阿里云 ECS 上。否决 BaaS（LeanCloud 等：锁定风险、配额费用、增量同步协议仍要自己实现）与 WebDAV/网盘目标模式（Joplin 式：与公开服务的账号体系定位冲突，冲突检测只有文件 ETag 级，服务端无法做校验与配额）。代价：自己运维、域名备案、HTTPS 证书。

## 2026-07-06 - 账号体系：用户名+密码登录，邮箱验证/找回，identity 预留扩展

登录标识是**用户名**（全局唯一），凭密码登录；注册与找回密码通过**绑定邮箱**收验证码完成（发信用阿里云邮件推送 DirectMail，零资质门槛）。账号模型把"登录方式"抽成独立 identity 层（user 表与 identity 表分离），一期只有用户名+密码一种，将来拿到资质后可追加手机号、微信登录而不动已有账号。短信/微信一期不做（个人开发者资质门槛）。

## 2026-07-06 - 加密策略：TLS + 服务端静态加密，不做端到端加密

传输全程 HTTPS；PostgreSQL 与 OSS 开启静态加密；服务端可读内容（增量校验、冲突修复、将来 Web 端/客服排障都依赖这一点）。不做 E2EE，也不做"仅私密记事 E2EE"的折中（同表明密文混存会让冲突副本、搜索、附件全部分叉）。现状佐证：本地"私密记事"本就是展示层保护（`PRIVATE_THING_PREFIX` 标题前缀 + 解锁查看），从来不是内容加密。隐私政策需明示服务端可读。详见 ADR-0012。

## 2026-07-06 - 增量同步机制：账号级单调序列号 + 墓碑 + 基线版本并发检测

服务端为每个账号维护单调递增变更序列号，任何实体写入即 +1 并盖到该实体；客户端持有"已同步到 N"水位，增量拉取 `>N` 的变更；推送时每条实体携带基线版本，服务端据此检测并发并触发分域冲突处理；删除以墓碑保留在变更流中传播。时钟不参与任何协议判定。否决：时间戳 updated_since（时钟偏斜丢变更）、Joplin 式全量状态比对（O(全量) 流量）、版本向量（单中心架构下过度设计）。

客户端 ID 前提：`things`/`thing_folders`/`habit_records` 新增 UUID 列（DB v22 迁移补发存量行），本地自增 Long id 继续做应用内主键（闹钟、小部件、表间关联不动），服务端只认 (账号, UUID)，离线创建无冲突。

## 2026-07-06 - 附件管线：OSS STS 直传 + 内容哈希寻址 + 缩略图先行按需下载

上传：客户端向 API 换取 STS 临时凭证后直传 OSS，附件字节不过 ECS（固定带宽是最贵资源），服务端只登记元数据。对象组织：SHA-256 内容寻址，跨记事/跨设备重复文件天然去重。上传时生成封面级缩略图（供 Thing Card 封面用）。下载：同步时只自动拉缩略图，原件（原图/音频/视频）用户打开时下载并留存本地；设置提供"仅 Wi-Fi 自动下载全部原件"开关。否决全量镜像默认（首次同步 GB 级不可接受）与纯在线不留本地（违背离线优先）。

## 2026-07-06 - 验证分层：协议模拟器为主 + 用户真机手测，不使用 adb/模拟器 E2E

同步引擎核心逻辑做无 Android 依赖的单元测试；服务端用真实 PostgreSQL 跑集成测试；另写"多客户端协议模拟器"（对真实服务端并发执行随机操作序列 + 收敛性/无丢失不变量断言）覆盖并发场景；端到端由用户按手测剧本在真实设备上验收（走现有 debug 更新渠道），开发过程不使用 adb 驱动模拟器。

## 2026-07-06 - 服务端代码位置：本仓库 server/ 目录

服务端子项目放在 EverythingDone 仓库的 `server/` 目录（而非独立仓库）：单人开发，协议改动天然跨端，同仓便于一次会话内同时改两端并保持文档统一。

## 2026-07-06 - 配额护栏：一期全免费 + 保守配额，服务端强制

每账号总存储 1GB、单附件 ≤100MB、设备数 ≤10；注册频率限制 + 邮箱验证码防批量注册。配额由服务端强制（客户端校验仅为体验优化），账号模型预留档位字段但不实现支付。需要清晰的配额占用 UI。原则：放宽容易收紧难。

## 2026-07-06 - 首绑定归并：合并 + 内容指纹去重，绝不清空任何一方

设备首次登录账号：本地数据全部上传、云端数据全部下载合入，不清空任何一方；上传前对"无 UUID 的存量数据"与云端做内容指纹匹配（createTime+类型+标题+正文哈希完全一致 → 绑定为同一实体而非新建），使曾用 ZIP 备份跨设备复制过数据的老用户免于成对重复。否决登录时"保留本地/云端二选一"（破坏性，违背绝不丢内容原则）。

配套语义：登出保留本地数据（可继续离线使用，数据标记归属原账号）；换账号登录必须先确认清除本设备上属于前账号的数据（云端数据不受影响）；未登录期间产生的数据在登录时并入所登录账号。

## 2026-07-06 - 触发时机：变更防抖推送 + 前台拉取 + 周期兜底

本地写库后防抖数秒自动推送；App 进前台/下拉刷新时拉取；WorkManager 周期后台同步（约每小时，仅联网）兜底。无常驻连接、零推送依赖。SSE 前台实时通道记为二期增强（followups）。否决纯手动同步（离线窗口长反而推高冲突概率）。

## 2026-07-06 - 冲突语义：分域处理——内容域出冲突副本，结构域字段级 LWW

并发修改同一条 Thing 时按字段分域处理：**内容域**（标题、正文/清单、附件列表）检测到并发修改（基于基线版本）→ 不覆盖任何一方，为落后方生成**冲突副本**（完整 Thing 副本，放同一文件夹，标题加标记），用户手动取舍，绝不静默丢内容；**结构域**（状态、folderId、置顶/location、卡片外观等）→ 字段级最后写入赢，静默收敛，不产生副本。"一边改正文、一边移动/置顶"不出副本，两边都生效；"两边都改正文"才出副本。

否决：记录级任何并发都出副本（Evernote 式，副本多到烦人）；纯 LWW 全静默（丢内容，笔记产品大忌）；CRDT 文本合并（单人多设备收益有限，实现/测试复杂度最高，清单结构还要定制）。

**Thing Folder 例外（2026-07-06 同日修正）**：文件夹不生成冲突副本——副本会复制"容器"语义（子项归属只能二选一，副本要么空要么抢走子项，均不可接受）。文件夹全字段按字段级 LWW 收敛：并发改名丢掉一方的新名字，代价远小于凭空多出一个空文件夹。冲突副本仅适用于 Thing。

## 2026-07-06 - 服务端技术栈：TypeScript + Hono + Drizzle + PostgreSQL

Node.js LTS + TypeScript，HTTP 框架 Hono（若实现期遇到生态短板，备选 Fastify），Zod 校验，Drizzle ORM，PostgreSQL（预留 pgvector 以支持将来的语义搜索）；ECS 上以 Docker Compose 部署（api + postgres 两容器），前置 Caddy 反向代理自动管理 HTTPS 证书。

选型过程：用户排除"古老的 Spring Boot"；结合"后续要上 AI/大模型功能"的规划，曾推荐 Python + FastAPI（AI 生态最厚），用户最终选定 TypeScript——各家大模型的 TS SDK 足以支撑 API 编排型 AI 功能。架构后门：若将来 AI 功能重到需要 Python 工具链（重 RAG 管线、本地模型），加挂独立的小 Python worker 服务，不动同步 API。详见 ADR-0011。
