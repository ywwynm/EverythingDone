# Opus 波浪：解耦"丰富度"与"主次" —— 各层独立波形/独立时间响应 + 波峰净空深度阶梯 + tanh 防平台

## 本次更新

针对两个问题：①近处深色浪盖过远处浅色浪（层次遮挡）；②浪峰撞到计时器护栏被硬性饱和成一条平台，很丑。

**根因**：此前把"谁主导"和"谁振幅大"绑死了，于是只能在"后层随机窜高盖前景"与"前景一律遮死后层"两个极端间来回摆；护栏用的是硬饱和（softplus 渐近成一条线），浪一超就拍平。

**改法（把两件事解耦，各用一套机制）**：

- **丰富度（各层不重复）**：各层恢复**独立波形**（不同波长/相位/流向流速/振幅倍率），并新增**各层不同的时间响应**——近层（深色前景）`tau` 小、灵敏、先涨快落；远层（浅色）`tau` 大、迟缓、滞后平缓。于是远近波浪高度不同、对声音的涨落节奏也不同，绝不重复。
- **主次（前景主导、后层不盖过）**：不再靠振幅，改用**波峰净空的深度阶梯**。每层波峰用 `tanh` 压进"该层自己的净空上限"，上限 = 该层到护栏的净空 × `mLayerCeilFrac`（前景 1.0 满、越远越小，0.55→1.0）。于是后层**无论多响、相位多巧，其最高点在结构上就低于前景**，根治窜高；同时后层仍有自己的起伏 + 更高的基线（`mLayerOffset` 加大到 9dp 梯度），在前景波谷/斜坡之间露出，有层次、有存在感。
- **平台问题顺带根治**：`tanh` 软压缩严格 `< 净空`、中小浪几乎不变、越高越圆润，永不拍平成平台；去掉旧的硬性 `softLowerLimit` 截顶。

## 验证

- `:app:assembleDebug` 通过；`:app:publishDebugUpdate` 发布（debug code **202607031537**）。
- 真机验证：
  1. 前后层是否**都有存在感**，且各层**高度不同、涨落节奏不同**（不再是远近重复的波浪）；
  2. 深色前景是否不再盖死浅色后层，浅色后层是否也不再窜高盖过前景（前景结构性主导）；
  3. 浪峰是否**不再拍平成平台**（撞护栏附近应为圆润峰）；
  4. 流动、峰谷、水位涨落是否保持。
