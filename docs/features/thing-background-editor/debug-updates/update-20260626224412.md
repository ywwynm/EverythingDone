# 撤回顶层面板层级改法，改为限制首页颜色面板高度

## 用户反馈

上一版把首页外观颜色面板提升到 contextual actionbar 之上，但用户认为这不是正确方向。更合理的行为是在选择模式、渐变页、键盘弹出并触发可滚动时，降低中间滑动区域的布局高度，从而降低整个 panel 高度；这样 panel 不会顶到 contextual actionbar，也能让正在调整颜色的记事/文件夹卡片保持可见。

## 诊断

首页卡片外观面板原本就是 `fl_things` 内的底部浮层。现有列表逻辑会根据 panel 高度给 `RecyclerView` 增加底部 padding，并调用 `ensureThingCardAppearanceSelectedCardVisible()` 把正在调整的卡片滚到可见范围。因此，正确修复点不是提高 panel 层级，而是控制 panel 自身最大高度，让中间 `NestedScrollView` 收缩。

## 修改

- 撤回上一版 `activity_things.xml` 的顶层 include 改动：`panel_thing_card_appearance` 回到 `fl_things` 内，contextual toolbar 仍是顶层 sibling。
- `ScrollAwareColumn` 新增 `maxMeasuredHeightPx`，调用方可给它设置运行时最大测量高度；超过上限时仍然只收缩第一个可见 `NestedScrollView`，标题和取消/确定区域保持固定。
- `ThingsActivity` 在外观面板显示、切换颜色页、键盘/布局变化后的空间更新链路中，按 `fl_things` 高度减去 actionbar/contextual toolbar 区域、底部 margin 和列表卡片间距计算 panel 最大高度。
- panel 高度降低后，现有 `RecyclerView` 底部 padding 和选中卡片可见性检查会自动使用新的 panel 高度，让正在调整的卡片更容易保持可见。
