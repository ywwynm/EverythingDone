# 文件夹语义用例矩阵 - 2026-06-22

本文用于验证“稳定文件夹骨架 + 状态筛选 + 类型筛选 + 回收站投影”的新语义是否自洽，尤其覆盖混合状态子树、Drawer、移动到文件夹 Dialog、记事列表 Widget 配置，以及文件夹相关操作。

## 核心规则

### 1. 三个稳定维度

普通记事列表由三个维度共同决定：

- Thing Scope：全部记事，或某个未进入回收站的 Thing Folder。
- 状态筛选：正在进行、已完成，或回收站。
- 类型筛选：全部类型，或记录/提醒/习惯/目标的组合。

实现更新（2026-06-23）：回收站不再是“筛选区下方的独立 Drawer 区域”，而是状态分段胶囊控件（`ThingStatusSegmentedView`）里的第三段——正在进行 / 已完成 / 回收站。它在数据层仍是 `Def.ThingStatus.DELETED` 这个独立状态（不是普通的“已完成”），切换它会保留当前 Scope 和类型筛选；只是 Drawer 呈现由“独立区域行”变成了状态分段的一段。本文后续提到的“回收站作为独立区域/独立列表”应按此理解。

### 2. 文件夹是稳定组织骨架

Thing Folder 是纯组织骨架，**本身没有任何状态**（既没有“完成”，也没有“删除”）。文件夹永远留在骨架里；它是否在某个状态视图出现，取决于其子树是否有命中该状态（和类型）的 Things。

因此“删除文件夹”作为“把容器移入回收站”的操作**不存在**。对文件夹的“删除”实际是“删除文件夹中所有记事”：递归把子树里所有未删除的记事（正在进行+已完成）移入回收站，**跟随当前类型筛选**，容器原地不动；删空后该文件夹因没有命中记事而自然从首页消失，并以 Projection Folder 形式出现在回收站投影里。

文件夹相关操作分两类：

- **内容操作**（不动容器，跟随当前类型筛选，递归整个子树）：完成文件夹中所有记事、恢复文件夹中所有记事、删除文件夹中所有记事、永久删除文件夹中所有记事。完成命中习惯/目标时会再弹三选项 dialog（去掉习惯目标 / 继续全部 / 取消）。早期 F2/F3/F4 里“只处理当前筛选命中”的 filter-scoped 版本（如“完成当前筛选下的内容”）已删除，现在统一是“…文件夹中所有记事”系列，且都跟随当前类型筛选。
- **结构操作**（改变骨架，与状态/类型筛选无关，作用于整个物理子树）：移动文件夹、解散文件夹、永久删除文件夹。

如果只是文件夹内的某些 Things 进入已完成或回收站，文件夹本身仍保持原组织位置。已完成和回收站列表通过 Projection Folder 显示命中路径，不把内容搬离原文件夹层级。回收站就是 `DELETED` 状态投影：含有已删记事的文件夹以 Projection Folder 形式出现，里面是已删除的记事。

### 3. 范围选择器稳定

以下位置都显示所有未进入回收站的 Thing Folders，包括空文件夹、只含已完成内容的文件夹、只含当前类型筛选不命中的文件夹：

- Drawer 文件夹范围区域。
- 移动到文件夹 Dialog。
- 记事列表 Widget 配置中的文件夹范围区域。

这些范围选择器不受当前状态筛选或类型筛选影响。

### 4. 列表投影只显示命中路径

普通列表中的 Folder Card 是内容投影，不是完整范围选择器。一个子文件夹只有在其子树中存在命中当前状态和类型筛选的 Things 时，才作为 Projection Folder 出现在当前列表中。

如果用户已经通过 Drawer 进入某个文件夹范围，而当前状态/类型没有命中内容，则显示该范围下的空状态；在“正在进行”状态下仍可创建新 Thing。

因此，已完成列表和回收站列表不会显示完全没有命中内容的空文件夹；它们只显示命中的 Things，以及通向这些 Things 的必要文件夹路径。

### 5. 状态操作和结构操作分离

状态操作按当前投影处理命中的 Things，并保留这些 Things 原本的文件夹归属。完成、恢复或删除单个 Thing，不会因为状态改变而把它移动到根目录。

结构操作按物理文件夹处理整个子树，并保留子项状态。结构操作包括解散文件夹、移动文件夹（含拖拽移动）、永久删除文件夹。注意：“删除文件夹”已不是结构操作——它被“删除文件夹中所有记事”这一内容操作取代（详见核心规则 2），容器在删除内容后仍留在骨架里。

### 6. 创建入口

创建新 Thing 只在“正在进行”状态下可用。新 Thing 创建在当前 Thing Scope 中，状态为正在进行，不受已完成投影或回收站影响。

## 基础测试树

以下用例默认使用这棵树：

```text
全部记事
├─ A
│  ├─ B：正在进行，记录
│  ├─ C：已完成，提醒
│  └─ D
│     ├─ E：正在进行，习惯
│     └─ F：已完成，目标
├─ X
│  └─ G：正在进行，记录
├─ Y
│  └─ H：已完成，提醒
└─ Z
   └─ 空文件夹
```

## Drawer 范围区域

### 用例 D1：默认 Drawer 文件夹范围

无论当前状态是正在进行还是已完成，Drawer 文件夹范围区域都显示：

```text
全部记事
A
  D
X
Y
Z
```

解释：

- A 同时有正在进行和已完成内容，但 Drawer 不关心状态。
- Y 只有已完成内容，仍然显示。
- Z 是空文件夹，仍然显示。
- D 作为 A 的子文件夹显示。

### 用例 D2：类型筛选不影响 Drawer 文件夹范围

当前选择“正在进行 + 记录”时，列表内容只命中 B、G，但 Drawer 文件夹范围仍显示 A、D、X、Y、Z。

解释：类型筛选只影响列表投影，不影响可选范围。

### 用例 D3：删除 A 中所有记事后

对 A 执行“删除文件夹中所有记事”后，Drawer 文件夹范围**仍然显示** A、D：

```text
全部记事
A
  D
X
Y
Z
```

文件夹没有删除状态，A、D 永远留在骨架里——只有解散或永久删除才会让它们从范围选择器消失。被移入回收站的是 A 子树里原本未删除的记事；它们在回收站投影里以 A（Projection Folder）为路径显示。

## 普通列表投影

### 用例 L1：全部记事 + 正在进行 + 全部类型

根列表显示：

```text
A：Folder Card，命中 B 和 E
X：Folder Card，命中 G
```

不显示 Y，因为 Y 子树没有正在进行内容。不显示 Z，因为 Z 没有命中内容。

### 用例 L2：全部记事 + 已完成 + 全部类型

根列表显示：

```text
A：Folder Card，命中 C 和 F
Y：Folder Card，命中 H
```

不显示 X，因为 X 子树没有已完成内容。不显示 Z。

### 用例 L3：A + 正在进行 + 全部类型

A 内显示：

```text
B
D：Folder Card，命中 E
```

C 被隐藏，因为它已完成。

### 用例 L4：A + 已完成 + 全部类型

A 内显示：

```text
C
D：Folder Card，命中 F
```

B 被隐藏，因为它正在进行。

### 用例 L5：A + 正在进行 + 记录

A 内显示：

```text
B
```

D 不显示，因为 D 子树中的 E 是习惯，不命中“记录”类型筛选。

### 用例 L6：A + 已完成 + 目标

A 内显示：

```text
D：Folder Card，命中 F
```

打开 D 后显示 F。

### 用例 L7：选择空文件夹 Z

`Z + 正在进行 + 全部类型` 显示文件夹空状态，并允许创建新 Thing。

`Z + 已完成 + 全部类型` 显示已完成空状态，不显示创建入口。

### 用例 L8：选择只有已完成内容的 Y 的正在进行投影

`Y + 正在进行 + 全部类型` 显示当前投影空状态，并允许创建新 Thing。

Y 物理上不是 Empty Thing Folder，因为它包含已完成的 H；这里只是“正在进行”投影为空。

`Y + 已完成 + 全部类型` 显示 H。

### 用例 L9：类型筛选导致的投影空

`A + 正在进行 + 提醒` 显示当前投影空状态，并允许创建新 Thing。

A 物理上包含 B、C、D/E/F，但没有命中“正在进行 + 提醒”的 Thing。

行为（2026-06-22 修正）：创建入口可用，但创建流程不预设类型——不把当前类型筛选作为新 Thing 的默认类型，类型由用户在详情页设定。创建完成回到列表后，类型筛选持久重置为“全部类型”（保留当前 Scope 和正在进行状态），以保证新建记事无论类型都立即可见。

## 状态切换

### 用例 S1：在 A 内切换状态

从 `A + 正在进行 + 全部类型` 切到已完成：

```text
原来显示：B、D(命中 E)
切换后显示：C、D(命中 F)
```

Thing Scope 保持 A，类型筛选保持全部类型。

### 用例 S2：在 A 内切换类型

从 `A + 正在进行 + 全部类型` 切到 `A + 正在进行 + 习惯`：

```text
原来显示：B、D(命中 E)
切换后显示：D(命中 E)
```

Thing Scope 和状态筛选保持不变。

### 用例 S3：当前范围被解散或永久删除后

只有解散或永久删除才会让 A 从骨架里消失。若用户正在 `A + 正在进行`，随后 A 被解散或永久删除，则当前范围不再存在，下一次刷新退回 `全部记事 + 正在进行`。注意：对 A 执行“删除文件夹中所有记事”**不会**让 A 消失，用户仍停留在 A（此时 A 的正在进行投影为空，可创建新记事）。

## 完成文件夹

### 用例 F1：在正在进行投影完成 A

在 `全部记事 + 正在进行 + 全部类型` 中对 A 执行“完成文件夹”：

```text
B：正在进行 -> 已完成
E：正在进行 -> 已完成
C：保持已完成
F：保持已完成
A、D：文件夹本身不写完成状态
```

完成后：

- `全部记事 + 正在进行` 不再显示 A，除非 A 后续又创建或移入正在进行内容。
- `全部记事 + 已完成` 显示 A，命中 B、C、E、F。
- Drawer 仍显示 A 和 D。
- `A + 正在进行` 为空，可创建新 Thing。
- `A + 已完成` 显示 B、C、D(命中 E、F)。

### 用例 F2：在类型筛选下完成 A

在 `全部记事 + 正在进行 + 习惯` 中对 A 执行“完成文件夹中所有记事”，操作**跟随当前类型筛选**，只完成命中习惯的正在进行记事：

```text
E：正在进行 -> 已完成（习惯，命中筛选）
B：保持正在进行（记录，不命中筛选）
C、F：保持已完成
```

确认 dialog 在有具体类型筛选时显示安抚句“仅作用于当前类型筛选（习惯），其它类型不受影响”。

### 用例 F3：已完成投影中的恢复

已完成投影不提供“完成文件夹”。恢复由“恢复文件夹中所有记事”（长按文件夹）或工具栏“全部恢复”承担，把已完成记事恢复为正在进行，**同样跟随当前类型筛选**。例如 `全部记事 + 已完成 + 目标` 下对 A 恢复，只把命中目标的已完成记事（F）恢复为正在进行，C（提醒）不受影响。filter-scoped 的“恢复当前筛选下内容”这一旧入口已不存在。

## 删除文件夹中所有记事与回收站

### 用例 T0：删除单个记事 B

在 `A + 正在进行 + 全部类型` 中删除 B：

```text
B：进入回收站，仍记得自己属于 A
A：文件夹本身不进入回收站
D、E、C、F：不受影响
```

删除后：

- Drawer 仍显示 A 和 D。
- `A + 正在进行 + 全部类型` 显示 D，命中 E；B 不再显示。
- `回收站 + 全部类型` 根列表显示 A 作为 Projection Folder，命中 B。
- 进入回收站中的 A 后显示 B。

从回收站恢复 B 时，B 回到 A，并恢复到删除前状态：正在进行。

### 用例 T0b：删除已完成记事 C

在 `A + 已完成 + 全部类型` 中删除 C：

```text
C：进入回收站，记录删除前状态为已完成，仍记得自己属于 A
A：文件夹本身不进入回收站
B、D、E、F：不受影响
```

删除后：

- Drawer 仍显示 A 和 D。
- `A + 已完成 + 全部类型` 显示 D，命中 F；C 不再显示。
- `回收站 + 全部类型` 根列表显示 A 作为 Projection Folder，命中 C。
- 进入回收站中的 A 后显示 C。

从回收站恢复 C 时，C 回到 A，并恢复到删除前状态：已完成。恢复 C 不应把 C 变成正在进行。

### 用例 T1：删除 A 中所有记事（正在进行投影）

在 `全部记事 + 正在进行 + 全部类型` 中对 A 执行“删除文件夹中所有记事”：

```text
B、E：移入回收站（各自记录删除前状态）
C、F：移入回收站（删除针对全部未删除记事，已完成的也算未删除）
A、D：文件夹本身不动，留在骨架里
```

该操作移入回收站的是子树里**所有未删除的记事（正在进行+已完成）**，并跟随当前类型筛选；全部类型时 B、C、E、F 都进回收站。删除后：

- Drawer / 移动 Dialog / Widget 配置**仍显示** A 和 D（文件夹未消失）。
- `全部记事 + 正在进行` 不再显示 A（无命中正在进行记事）。
- `回收站 + 全部类型` 根列表显示 A 作为 Projection Folder；进入后见被删记事，D 在 A 内、其下为 E、F。

### 用例 T2：在已完成投影删除

已完成投影的工具栏“全部删除”把当前命中的已完成记事移入回收站（跟随筛选），只作用于记事、不涉及容器。已完成投影的文件夹菜单**不**提供“删除文件夹中所有记事”（避免与工具栏“全部删除”重复）。要把整个文件夹（含正在进行）的记事一并删除，在正在进行投影长按该文件夹用“删除文件夹中所有记事”。

### 用例 T3：恢复 A 中所有记事

在回收站里对 A（Projection Folder）执行“恢复文件夹中所有记事”（长按文件夹的菜单项，或回收站工具栏“全部恢复”作用于当前范围），跟随当前类型筛选，把 A 子树里在回收站的记事恢复到各自删除前状态：

```text
B、E：回到正在进行（若删前是正在进行）
C、F：回到已完成（若删前是已完成）
A、D：始终在骨架里，从未移动
```

因为容器从不进回收站，恢复只改记事状态——A、D 的位置和父子关系全程不变，**不存在**“恢复文件夹到原父级 / 原父级不可用”的问题（旧模型的 T3b/T3c 已不适用）。

### 用例 T4：永久删除 A（结构操作）vs 永久删除 A 中所有记事（内容操作）

回收站里对 A 有两个不同操作：

- **永久删除文件夹**（结构操作，长按文件夹菜单 / 文件夹内 overflow）：销毁 A、D 文件夹记录及其子树全部记事（B、C、E、F，含所有状态），无法恢复。确认 dialog 警告“含当前状态/类型筛选下看不到的内容”（它跨当前回收站投影、销毁整个容器）。相关 Widget 若曾选 A 作范围，刷新时持久改写为“全部记事 + 原状态 + 原类型”。
- **永久删除文件夹中所有记事**（内容操作，长按文件夹菜单 / 工具栏“全部永久删除”）：只永久删除该范围回收站里的记事（跟随类型筛选），**不**销毁容器、不影响其它视图里的记事。

### 用例 T5：删除子文件夹 D 中所有记事

在 `A + 正在进行 + 全部类型` 中，长按 D 执行“删除文件夹中所有记事”：

```text
E、F：移入回收站（各自记录删除前状态）
D、A：文件夹本身不动
B、C：不受影响，仍在 A 内
```

删除后：`A + 正在进行` 只显示 B（D 因无命中正在进行记事而隐藏）；`回收站` 里 A 作为 Projection Folder，进入见 D，再进入 D 见 E、F。

## 解散文件夹

### 用例 R1：解散 A

解散 A 是结构操作，处理整个物理文件夹。解散与删除无关：它把文件夹容器本身彻底删除（正在进行、已完成、回收站里都不再有 A，不是把 A 移入回收站），并把 A 的所有直接子项按各自原状态移到 A 的父级，**包括原本就在回收站里的子项**：

```text
B 移到 A 的父级，保持正在进行
C 移到 A 的父级，保持已完成
D 移到 A 的父级，保持文件夹结构（D 的内容随 D 一起）
E 仍在 D 内，保持正在进行
F 仍在 D 内，保持已完成
若 A 内还有已在回收站的子项，也一并移到父级并保持其回收站状态
A 文件夹记录被删除（不可恢复，回收站里也没有 A）
```

当前列表刷新后只显示当前投影命中的内容。例如在根目录正在进行中，解散后显示 B 和 D(命中 E)；在根目录已完成中，显示 C 和 D(命中 F)。

确认 Dialog 的影响计数统计 A 子树的全部内容（含已在回收站的），因为它们都会被移动；与删除文件夹只统计“新移入回收站的未删除内容”不同。

### 用例 R2：解散只在正在进行投影提供

解散是结构操作，仅在正在进行投影的文件夹菜单 / overflow 提供（已完成、回收站投影不提供解散）。解散始终处理整个物理文件夹，包括当前投影看不见的已完成、回收站内容。确认文案说明“解散整个文件夹，所有直接子项按各自原状态移到上一级”。

## 移动文件夹

### 用例 M1：把 A 移动到 X 下

操作后物理树变为：

```text
全部记事
├─ X
│  ├─ G：正在进行
│  └─ A
│     ├─ B：正在进行
│     ├─ C：已完成
│     └─ D
│        ├─ E：正在进行
│        └─ F：已完成
├─ Y
│  └─ H：已完成
└─ Z
```

`全部记事 + 正在进行` 显示：

```text
X：Folder Card，命中 G、B、E
```

`全部记事 + 已完成` 显示：

```text
X：Folder Card，命中 C、F
Y：Folder Card，命中 H
```

因此，虽然 X 原本只有正在进行的 G，把 A 移入 X 后，已完成列表也会显示 X，因为 X 的子树现在包含 C 和 F。

### 用例 M2：打开 X 的已完成投影

在 M1 之后，`X + 已完成 + 全部类型` 显示：

```text
A：Folder Card，命中 C、F
```

G 不显示，因为它正在进行。

### 用例 M3：打开 X 的正在进行投影

在 M1 之后，`X + 正在进行 + 全部类型` 显示：

```text
G
A：Folder Card，命中 B、E
```

### 用例 M4：把 C 移动到 X 下

如果只把已完成记事 C 移动到 X 下：

```text
C：仍是已完成
```

移动后：

- `X + 正在进行` 仍显示 G。
- `X + 已完成` 显示 C。
- 根目录已完成会显示 X，因为 X 子树包含 C。

### 用例 M5：移动目标 Dialog

```text
全部记事

  D

```

如果正在移动 A，则 A 自身及 D 等后代目标应禁用，防止循环移动。其它文件夹即使没有当前投影命中内容，也仍可作为移动目标。

### 用例 M6：把 A 移动到 X 后 Drawer 显示

## 合并与拖拽创建文件夹

### 用例 G1：A 的正在进行投影中不能直接用 B 和 E 创建新文件夹

`A + 正在进行 + 全部类型` 中实际可见的是：

```text
B
D：Folder Card，命中 E
```

E 不在 A 这一层直接显示，因此用户不能在 A 的列表中直接把 B 和 E 拖拽合并为新文件夹。

如果用户把 B 拖到 D 上，语义应是“把 B 移入已有文件夹 D”；如果允许该操作，它不是创建新文件夹 N。

### 用例 G1b：B 和 E 同层可见后创建新文件夹

仅在 `正在进行` 状态下允许拖拽创建文件夹。若用户先把 B 移入 D，然后进入 `D + 正在进行 + 全部类型`，此时列表显示：

```text
B
E
```

此时用户可以把 B 和 E 合并为新文件夹 N：

```text
D
├─ N
│  ├─ B：正在进行
│  └─ E：正在进行
└─ F：已完成
```

新文件夹 N 是正常文件夹。B、E 状态不变。

### 用例 G2：已完成投影不允许拖拽创建文件夹

`A + 已完成 + 全部类型` 中实际可见的是：

```text
C
D：Folder Card，命中 F
```

F 不在 A 这一层直接显示，因此不能在 A 的列表中直接把 C 和 F 拖拽合并。

即使 C 和 F 通过移动变成同层可见，也不允许在已完成投影中拖拽创建新文件夹。原因：

- 这是创建/组织当前进行内容的手势。
- 已完成投影中创建新结构容易让用户误以为新文件夹本身是已完成对象。
- 若需要整理历史内容，应使用显式的“移动到文件夹”操作。

### 用例 G3：拖拽已有 Folder Card 到另一个文件夹

把 A 拖到 X 上按结构操作处理整个物理 A，而不是只移动当前投影命中的 B/E 或 C/F。

决议（2026-06-22）：保留拖拽移动文件夹。规则统一为“移动整个物理文件夹子树，与当前状态/类型筛选无关”。按非正在进行禁用拖拽的总规则，拖拽移夹只在“正在进行”状态可用；显式“移动到文件夹”Dialog 作为更精确的补充入口保留，并在已完成状态下提供。

## Widget 配置

### 用例 W1：Widget 范围选择

记事列表 Widget 配置中的范围选择器显示所有未进入回收站的文件夹，包括 Y 和 Z。

用户可以配置：

```text
范围：X
状态：已完成
类型：全部类型
```

即使 X 当前没有已完成内容，也允许保存；Widget 显示空状态，等 X 以后出现已完成内容时自动显示。

### 用例 W2：A 移动到 X 后的 Widget

如果 Widget 配置为 `X + 已完成 + 全部类型`，在 A 移动到 X 后，Widget 应显示 X 范围的直接子项投影：

```text
A：Folder Card，命中 C、F
```

G 不显示，因为它正在进行。Widget 不递归拍平显示 C、F；C、F 仍在 A 内，点击 A 应打开 App 的 `A + 已完成 + 全部类型` 投影。

如果 Widget 配置为 `X + 正在进行 + 全部类型`，则显示：

```text
G
A：Folder Card，命中 B、E
```

### 用例 W3：Widget 目标进入回收站

如果 Widget 选择 A 作为范围，后来 A 被删除进入回收站：

推荐行为：Widget 刷新时持久改写配置为“全部记事”范围，并继续使用原状态和类型筛选。

理由：回收站不是普通 Widget 范围；让桌面 Widget 指向回收站内文件夹会让恢复/永久删除生命周期和桌面展示混在一起。持久改写配置后，Widget 标题、点击行为和重新打开配置页时的回显都保持一致。

## 操作菜单（2026-06-23 现状）

文件夹操作有两个并行入口，职责不同：

- **进入文件夹后**：工具栏承担内容批量操作（作用于当前范围=当前文件夹的当前状态，跟随类型筛选，当前投影无内容时整组隐藏）；overflow 只放结构操作，外加正在进行视图的“删除文件夹中所有记事”（因为该视图工具栏没有删除项）。
- **长按文件夹卡片**（从外部对某文件夹操作）：选择模式上下文菜单，提供该文件夹的内容操作 + 结构操作。

### 工具栏批量动作（根目录 / 进入文件夹后）

| 状态 | 工具栏 |
|---|---|
| 正在进行 | 全部完成 |
| 已完成 | 全部恢复、全部删除 |
| 回收站 | 全部恢复、全部永久删除 |

### 文件夹内 overflow（结构为主）

| 状态 | overflow |
|---|---|
| 正在进行 | 删除文件夹中所有记事（首项）、设私密、移动到文件夹、解散文件夹 |
| 已完成 | 无（结构操作仅正在进行可用；删除由工具栏“全部删除”承担） |
| 回收站 | 永久删除文件夹（结构） |

### 长按文件夹卡片的上下文菜单

| 状态 | 菜单项 |
|---|---|
| 正在进行 | 完成文件夹中所有记事、解散文件夹、删除文件夹中所有记事，外加外观/重命名/隐私/置顶/移动 |
| 已完成 | 恢复文件夹中所有记事、删除文件夹中所有记事 |
| 回收站 | 恢复文件夹中所有记事、永久删除文件夹中所有记事、永久删除文件夹 |

要点：

- 文件夹没有删除状态，不存在“还原文件夹（容器）”这一项；回收站里恢复内容统一用“恢复文件夹中所有记事”。
- 回收站里区分“永久删除文件夹中所有记事”（内容，跟随筛选、只动回收站记事）和“永久删除文件夹”（结构，销毁整个容器）。
- 旧的 `showThingFolderActions` 卡片动作弹窗及 filter-scoped 的“完成/恢复当前筛选下内容”入口已删除。

## 确认 Dialog（2026-06-23 现状）

所有“…文件夹中所有记事”内容操作与结构操作都有二次确认。Dialog 由“正文 + 条件提示”组成：

- 正文：动作 + 数量（内容操作“共 N 件”；结构操作“X 个子文件夹、Y 件记事”，0 段省略）+ 去向/可逆性。
- “（含所有子文件夹中的记事）”：仅当受影响记事确实落在子文件夹时追加（挂在数量后面）。
- 内容操作（完成/恢复/删除/永久删除记事）：有具体类型筛选时追加安抚句“仅作用于当前类型筛选（X），其它类型不受影响”；全部类型时不追加。
- 结构操作（解散/永久删除文件夹）：追加警告句“含当前状态/类型筛选（…）下看不到的内容”，提示影响超出当前投影。

结构操作的影响计数：解散、永久删除文件夹统计整棵子树（含已在回收站的）；“删除文件夹中所有记事”统计当前会移入回收站的未删除记事（跟随筛选）。

## 实现要点（现状）

- Folder Card 的计数表示当前投影命中的 Things 数量，不是物理子树总数。
- Drawer、移动 Dialog、Widget 配置是范围选择器，显示所有未被解散/永久删除的文件夹，不受状态/类型筛选影响，不复用列表投影查询。
- 解散、移动、永久删除文件夹是结构操作，确认文案说明“整个文件夹”；“删除文件夹中所有记事”是内容操作，跟随类型筛选。
- 内容批量操作（完成/恢复/删除/永久删除记事）都跟随当前类型筛选，只影响命中类型的 Things。
- 回收站中的恢复保留子项删除前状态和文件夹结构（容器从不移动）。
- 永久删除文件夹销毁整个子树，并把指向该文件夹范围的 Widget 配置持久改写回“全部记事 + 原状态 + 原类型”。
- 当前范围被解散/永久删除而失效时，普通导航与 Widget 配置都持久回退到“全部记事 + 原状态筛选 + 原类型筛选”。
- 在根目录且筛选非默认（状态≠正在进行 或 有具体类型筛选）时，按返回先回到“正在进行+全部类型+根目录”，再按返回才退出；因此按返回键退出后再打开不保留类型筛选，按 Home 退到后台再打开则保留。新建记事完成回到列表后，类型筛选重置为全部类型。
