## 恢复拖拽飞入动画并重算 Dialog 飞入坐标

本次修正上一版移动到文件夹动画的两个问题：

- 用户反馈：拖拽移入文件夹的飞入动画没有恢复，甚至完全没有飞入动画；同时 Dialog 飞入坐标偏下并不是 `translationY` 导致，需要重新计算。
- 已确认实际长按拖拽主要走 `ThingListOverlayDragController`，而该路径的 `MOVE_TO_FOLDER` 仍在走 shrink in place。现在已改回对当前命中的目标 Folder rect 执行 `animateOverlayIntoTarget`，恢复拖拽飞入目标文件夹的动画。
- Dialog 移动路径不再在 `notifyItemRemoved` / `notifyItemChanged` 后重新查找 F 的坐标；改为在确认移动前读取目标 Folder Card 的 `getGlobalVisibleRect`，转换到 activity root 坐标后，与当前 `RecyclerView` 可见 viewport 求交，并扣除 selecting mode contextual toolbar 的遮挡。
- 撤销上一版“偏下来自 RecyclerView translationY”的判断；本次实现不再依赖该假设。
- 旧 `ItemTouchHelper` 提交动画仍保持自身目标矩形计算，不套用 Dialog 的缓存目标规则。
