## 修复首页搜索结果中文件夹命中时误显示“找不到对象”

用户反馈：有时首页明明存在搜索结果，但“找不到对象”的空结果图和文字仍会出现，怀疑空提示只根据记事搜索结果判断，没有把文件夹结果算进去。

本次诊断确认：文件夹搜索结果已经进入 `ThingManager` 的混合列表 `mThingListEntries`，但 `ThingsActivity.handleSearchResults()` 仍用 `mThingManager.getThings().size == 1` 判断是否为空。`mThings` 只包含 header 和记事，不包含文件夹，所以当只有文件夹标题或颜色命中时，会被误判为空。

修复内容：
- `ThingsActivity` 的搜索空结果判断改为复用 `ThingManager.hasVisibleProjectionContent()`，同时把记事和文件夹都算作可见搜索结果。
- 搜索空提示的延迟隐藏回调也改为使用同一判断，避免动画结束时按旧条件把提示重新留在屏幕上。
- `ThingManager` 记录当前搜索关键词和颜色过滤条件；搜索态下因完成、删除、恢复、撤销等操作触发列表重建时，文件夹投影继续按当前搜索范围过滤，避免把搜索范围外的文件夹计入结果。
- 补充 `home-empty-state` 和 `thing-folders` 决策文档，明确搜索 no-result 必须按混合可见内容判断。

验证：
- `git diff --check` 通过，仅有仓库既有 LF/CRLF 提示。
- `:app:assembleDebug --console=plain --no-configuration-cache` 构建通过。
