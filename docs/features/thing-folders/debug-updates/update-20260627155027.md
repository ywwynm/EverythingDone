## 修复搜索态批量操作后跳出搜索结果

本次更新根据代码 review 逐项核对搜索模式文件夹支持的刷新路径，修复一组已确认的列表刷新一致性问题。

已确认的问题：
- 搜索态中执行含文件夹的完成、删除、恢复、永久删除等内容操作后，部分路径会经由 `ThingManager.loadThings()` 清空 `mEntryFilterKeyword` 和 `mEntryFilterColor`。
- 搜索态中恢复纯记事、批量移动到文件夹、批量置顶文件夹、批量设置文件夹私密时，也可能让列表跳回当前文件夹全量内容。
- 此时搜索框仍显示原搜索文本和颜色筛选，但列表结果已经不再是搜索结果。
- 搜索结果被操作清空时，部分刷新路径还会走首页空状态，而不是搜索模式的“找不到对象”状态。

本次没有改动的 review 项：
- `enterSelectionMode()` 中重复调用 `setListEntrySelected(...)` 是幂等冗余，第二次调用覆盖 `toSelectingMode(...)` 可能重置选择状态的情况，本次不改。
- DAO SQL 搜索与内存搜索剥离 checklist/private signal 的维护风险属于理论一致性问题，目前未发现实际可达 bug，本次不改。

主要修改：
- `refreshHomeAfterScopeStateChange()` 改为先按当前搜索态重建列表，再刷新 UI 和空状态。
- `moveSelectedThingsIntoFolder(...)`、`toggleFolderSticky(...)`、`updateFolderPrivate(...)` 增加默认 `reload` 参数；批量/搜索感知入口传 `reload=false`，由 Activity 统一恢复搜索投影。
- “移动到文件夹”视觉刷新路径在计算新 item count 和新目标位置前，先调用 `loadThingsForCurrentSearchState()`。
- 批量置顶、批量私密和单文件夹置顶后，都会恢复当前搜索文本与颜色筛选。
- 当前文件夹/单文件夹范围内容操作在搜索态下收集记事时，也透传当前搜索文本与颜色筛选，并在确认弹窗中加入搜索范围提醒。
