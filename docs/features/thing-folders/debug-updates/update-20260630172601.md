# 完善 folder.updateTime 在内容增减时的刷新（底层元数据，无可见变化）

把文件夹的"修改时间"（updateTime）刷新规则补全为借鉴文件系统目录 mtime 的语义。这是底层元数据改动，
界面上没有可见变化（目前 updateTime 仅被大文件夹缩略图缓存内部使用，且缓存另有多重兜底），主要用于让语义
正确、为将来（同步 / 最近修改 / 增量备份）铺路。

## 主要改动

- 文件夹"修改时间"现在会在其**直接内容增减**时刷新（此前只有改文件夹自身名称/外观/私密等才刷新）：
  - 把记事/子文件夹移入或移出某文件夹 → 刷新源、目标两个文件夹；
  - 在文件夹内新建记事 → 刷新该文件夹；
  - 永久删除文件夹内的记事、永久删除子文件夹 → 刷新所属/父文件夹；
  - 解散文件夹（内容上移到父级）→ 刷新父文件夹；
  - 拖拽两个记事建成新文件夹、以及撤销该操作 → 刷新相关文件夹。
- 不刷新（与文件系统目录一致）：把记事删到回收站 / 标记完成（仍物理属于原文件夹）、编辑记事内容、纯排序
  置顶、以及更深层级的变化（不向上冒泡）。
- 实现上把"永久删除记事"的刷新统一收敛到底层物理删除点，确保所有删除入口（批量删所选、详情页清空删除、
  回收站永久删除）行为一致，不遗漏。

## 验证重点（主要是确认无回归）

界面无可见变化，重点确认这些操作仍正常、无异常：

1. 移动记事 / 子文件夹进出文件夹；批量移动；拖拽两个记事建成新文件夹及撤销。
2. 文件夹内新建记事。
3. 删除到回收站、从回收站永久删除（单条、批量、整个文件夹）。
4. 解散文件夹。
5. 大文件夹缩略图在上述操作后显示正确、滑动正常（与上一版一致）。

## 备注

`folder.updateTime` 目前没有界面直接展示，此版属语义正确化；若日后做"最近修改"排序或数据同步会用到。
