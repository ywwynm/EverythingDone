## 清理搜索态批量操作中的冗余刷新

本次更新处理两个 review nitpick，属于轻量性能与代码路径整理，不改变用户可见行为。

处理内容：
- 状态类批量/范围操作在 Activity 层已经统一刷新列表，因此 `ThingManager.finishThings(...)`、`unfinishThings(...)`、`trashThings(...)`、`trashThingsPreservingState(...)`、`deleteThingsForever(...)`、`restoreTrashedThings(...)` 增加默认 `reload` 参数。
- 选择模式、文件夹范围等会马上调用 `refreshHomeAfterScopeStateChange()` 的路径改传 `reload=false`，避免 manager 先 `loadThings()`，Activity 又按当前搜索条件 `searchThings(...)`。
- `restoreThingsToPreTrashState(...)` 与 `trashThingsPreservingState(...)` 内部也改为多组状态变更后只按需要 reload 一次。
- 批量置顶记事时，每个记事不再逐个 `rebuildThingListEntries()`；循环结束后统一 `rebuildCurrentThingListEntries()` 一次。
- `enterSelectionMode(...)` 删除进入选择模式前的重复 `setListEntrySelected(...)`，保留 `toSelectingMode(...)` 之后的那一次，避免模式切换重置选择状态。

影响：
- 普通调用仍使用默认 `reload=true`，旧路径行为保持不变。
- 搜索态最终仍由 Activity 按当前搜索文本和颜色筛选刷新一次。
- 本次没有改变选择范围、操作对象、弹窗文案或搜索结果语义。
