# 置顶记事状态变更按操作时间重新排到置顶区顶部

本次 debug update 取代上一版 `202606240609` 中“置顶记事状态变更保留原负数 `location`”的做法，修正为更符合置顶列表排序语义的规则：

- 用户指出一个关键场景：一开始置顶记事 A 排在置顶记事 B 前面，先完成 A、再完成 B 后，在“已完成”列表里 A 和 B 都应该仍然置顶，并且后完成的 B 应该排在 A 前面。
- 因此，状态变更时不能简单保留原负数 `location`；原本置顶的记事需要重新分配到目标父级置顶区顶部之前的新负数 `location`。
- 新实现放在 `ThingDAO.updateState` 的最终落库路径中：如果原记事 `location < 0`，使用同一个数据库连接查询当前父级下记事与文件夹混合后的置顶区最小 `location`，再写入 `min - 1`。
- 批量状态变更在同一事务中逐条写入，因此先处理的置顶项会被后处理的置顶项看到；后完成、后删除、后恢复的置顶记事会排在对应置顶区更前面。
- 原本未置顶的记事仍沿用既有行为，状态变更后进入目标状态列表的非置顶区顶部。
- header 更新只按非置顶记事数量前移；置顶记事状态变更不消耗 header 位置。

同时保留上一轮移动/拖拽建夹规则：

- 移动记事或文件夹时保留源条目自身置顶状态。
- 拖拽两个记事创建文件夹时，任一成员置顶则新文件夹置顶，成员记事移入后也保留各自置顶状态。

验证：

- `:app:assembleDebug` 已通过。
