## 修正移动到文件夹 Dialog 飞入终点偏下

> 后续修正：本条把偏下问题归因到 `translationY` 的判断已被下一版撤销。最终实现见 `update-20260627121026.md`：拖拽路径恢复飞入目标 Folder；Dialog 路径改为在确认移动前读取目标 Folder 的实际可见矩形，不在列表变更后重新取坐标。

本次继续复核“移动到文件夹”Dialog 的飞入动画坐标：

- 用户反馈：上一版按 F 可见区域中心计算后，飞入位置仍感觉有点偏下。
- 复核后确认一个可能原因：Dialog 移动触发 `notifyItemRemoved` 后，如果目标文件夹 F 位于被移走源项下方，`RecyclerView` 会把 F 布局到最终位置，同时用 item move animation 的 `translationY` 让 F 从旧位置移动到新位置。此时如果读取带 translation 的屏幕视觉坐标，飞入终点会落在 F 的旧视觉位置，表现为偏下。
- 已将 Dialog 飞入终点改为使用目标文件夹 F 的最终 layout rect，再与移动前缓存的可见 viewport 求交并取中心；普通可见性判断和源项 overlay 起点仍使用当前视觉坐标。
- 旧拖拽提交动画仍不套用这条 Dialog 坐标规则，继续按拖拽路径自身语义处理。

验证：`E:\projects\EverythingDone\gradlew.bat :app:assembleDebug` 已通过。未使用 adb。
