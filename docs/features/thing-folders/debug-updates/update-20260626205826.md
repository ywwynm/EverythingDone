## 2026-06-26 - 拖拽建夹/移入文件夹命中区域继续收紧

本次 debug update 继续修正首页拖拽移动模式中创建文件夹、移入文件夹的 hover 触发区域。

用户反馈上一版“16dp 内缩”几乎没有感觉，拖拽中的记事/文件夹卡片只要左上角靠近另一张卡片，仍然会触发创建文件夹或移入文件夹动画；同时指出被拖拽卡片处于放大状态，命中判断应考虑这一点。

排查结果：

- 上一版只收紧了 `ThingsActivity` 中旧 `ItemTouchHelper` 拖拽路径的命中区域。
- 当前首页拖拽更可能走 `ThingListOverlayDragController` 的 overlay 拖拽路径；这一路仍然是 overlay 内容左上角只要进入目标卡片原始区域就算命中，所以真机上会表现得像“16dp 没生效”。

本次调整：

- `ThingListOverlayDragController.findFolderDropTargetUnderOverlayTopLeft()` 也加入目标卡片内缩命中判断。
- 旧 `ThingsActivity.findFolderDropTargetUnderDraggedTopLeft()` 和 overlay 路径统一使用同一套规则。
- 命中点按被拖拽卡片放大后的可见左上角计算，而不是未缩放的布局左上角。
- 目标卡片内缩阈值从 1 倍首页相邻卡片可视间距提高到 2 倍，当前等价于约 32dp。
- 目标卡片尺寸较小时仍会自动压缩阈值，避免小卡片完全无法命中。

验证状态：

- `git diff --check` 通过，仅有仓库既有 LF/CRLF 提示。
- `:app:assembleDebug --console=plain --no-configuration-cache` 已通过。
- 拖拽 hover 手感需要在真机上通过 debug update 验证。
