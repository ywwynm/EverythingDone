# 修复 full-span 大文件夹两处问题：预览缩略图数量、拖拽时列表闪动

> 后续更正：本次更新（更新码 202606291603）发布后，用户确认"拖拽时列表闪动"与下文第二项的方案
> 无关，该项改动已在源码中全部撤回，仅保留第一项"预览缩略图数量"的修复。第二项内容仅作历史记录。

## 主要改动

- **修复：把普通宽度的大文件夹（缩略图模式）改成 full-span 时，预览里只显示 3 个缩略图**（手机上
  应显示 6 个）。此前点击确定后能正确显示 6 个，只有预览不对。
  - 根因：外观面板的"预览"是直接揭示列表里那张真实卡片来显示的。切换大小模式只改了文件夹的草稿外
    观并重绑卡片，但卡片渲染优先用列表构建时缓存的缩略图投影——那份投影是按旧外观（普通宽度，取数
    上限 3）取的。切到 full-span 后显示数量变成 6，缓存里却只有 3 条，于是只显示 3 个。
  - 修复：正在外观编辑预览的那个文件夹绕过缓存投影，按草稿外观实时取数（full-span 取数上限 10），
    预览即可显示 6 个，与确定后一致。

- **修复：一个很高（高度接近或超过整屏）的 full-span 大文件夹露在画面上方一部分时，拖拽记事/文件夹
  会让列表"上下闪一下"、被拖卡片相对手指往下挪位**；进入选择模式后退出、或真正完成一次拖拽移动时，
  列表会再闪一下。
  - 根因：拖拽开始（进入移动模式）、退出选择模式、重排提交这三处都做了全量 notifyDataSetChanged。当
    一个很高的 full-span 大文件夹跨在视口锚点上方时，StaggeredGridLayoutManager 的 gap 修正会把列表
    整体上下挪一下，表现为闪动；拖拽开始时这一挪还会让源卡片相对手指错位。
  - 修复：仿照已有的 folder-drop 收尾重绑，在这三处重绑前后用 LayoutManager 自带的锚点 save/restore
    保住滚动位置，覆盖掉这次 gap 滚动。只还原滚动位置，不改重绑/动画/数据。

## 验证重点

1. 把一个普通宽度的缩略图大文件夹（手机上）改成 full-span：**预览阶段就应显示 6 个缩略图**，点确定后
   仍是 6 个；再切回普通宽度，预览与确定后都应是 3 个。省略号"+N"按真实总数显示，不回退。
2. 准备一个很高的 full-span 大文件夹（高度接近或超过整屏），把它滚到只露出上方一部分的位置：
   - 拖拽下方任意记事/文件夹，**开始拖拽时列表不应上下闪动，被拖卡片应保持在手指中央**。
   - 拖拽中途进入选择模式后退出：**列表不应闪动**。
   - 真正完成一次拖拽移动（重排）：**收尾时列表不应闪动**，卡片落位正确。
3. 普通高度文件夹 / 非 full-span 文件夹的拖拽、选择、重排不回退（保住滚动位置在无 gap 时是无操作）。
4. 文件夹拖入/创建文件夹（folder-drop）收尾不回退。

## 备注

第二处的滚动保护沿用 `rebindHomeListAfterFolderDropModeExit` 既有方案，统一加到
`ModeManager.notifyThingsSelected`（拖拽开始 / 进入选择）、`ModeManager.backNormalMode` 的 SELECTING
分支与取消分支、以及 `ThingsActivity.runOverlayDragModeExitRebind`（重排提交）。这些重绑本就不应让列表
跳动，因此对所有选择/移动模式切换都生效，而非仅大文件夹场景。
