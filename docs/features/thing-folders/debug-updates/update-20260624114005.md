# 移动与拖拽建夹保留置顶状态

本次 debug update 统一了记事和文件夹在移动、拖拽建夹时的置顶语义：

- 用户排查了 5 类场景：未置顶记事拖到置顶记事上建夹、置顶记事拖到未置顶记事上建夹、置顶记事移入置顶文件夹、未置顶记事移入置顶文件夹、置顶记事移入未置顶文件夹。
- 经过讨论，最终确定“置顶”视为记事/文件夹条目自身状态，而不是只属于当前目录的一次性排序意图。跨目录移动、移入下级目录、移回根目录时都保留源条目的置顶/非置顶状态。
- 拖拽两个记事创建文件夹时，新文件夹只要任一成员置顶就置顶；两个成员移入新文件夹后也分别保留自己的置顶/非置顶状态。
- 拖拽或通过“移动到文件夹” Dialog 移动记事时，移动后的记事会进入目标父级对应的置顶区或非置顶区顶部。
- 拖拽或通过“移动到文件夹” Dialog 移动文件夹时，移动后的文件夹会按自身置顶状态进入目标父级对应区域；已有目标文件夹接收子项时，自身置顶状态不会被子项改变。
- 状态筛选和类型筛选仍只影响入口可用性与列表可见性，不改变移动落位规则；操作发生在根目录还是某个文件夹内，也不改变该规则。

涉及实现：

- `ThingManager.createFolderFromThings`：根据两个成员是否置顶计算新文件夹的目标位置。
- `ThingManager.moveThingIntoFolderInternal`：移动记事时按记事当前 `location < 0` 保留置顶状态。
- `ThingManager.moveFolderIntoFolder`：移动文件夹时按 `folder.isSticky()` 保留置顶状态。
