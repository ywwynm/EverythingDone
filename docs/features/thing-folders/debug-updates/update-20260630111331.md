# 加回 folder-drop 收尾重绑的滚动保护（上一版撤回后确认确有跳动）

## 主要改动

- **重新加回 `ThingsActivity.rebindHomeListAfterFolderDropModeExit` 的滚动 save/restore**。上一版
  （更新码 202606300300）把它撤回后实测确认：把记事拖到另一条记事/文件夹上做"合并成文件夹 / 移入
  文件夹"，收尾松手时列表确实会上下跳一下。说明这处改动有真实作用，故恢复。
- 实现：folder-drop 收尾的全量 `notifyDataSetChanged` 前后，用 LayoutManager 自带的锚点
  `onSaveInstanceState`/`onRestoreInstanceState` 保住滚动位置，覆盖掉 StaggeredGridLayoutManager 的
  gap 修正滚动。只还原滚动位置，不改重绑/动画/数据等收尾逻辑。

## 验证重点

- 把记事拖到另一条记事/文件夹上做"合并成文件夹 / 移入文件夹"，**收尾松手时列表不应再上下跳**。
- 普通的拖拽重排、进出选择模式等其它收尾行为不受影响（本版只动 folder-drop 这一处）。
- 之前三处大文件夹缩略图修复（预览数量、侧图高度闪动、媒体背景置底）保持有效。

## 备注

与早先被否掉的"拖拽缩略图闪动→SGLM gap"方案用的是同一思路，但作用场景不同：那次的真因是侧图投影的
异步二次结算（已另行修复），与滚动位置无关；而 folder-drop 收尾这处确实是 SGLM 的 gap 修正滚动，save/
restore 有效。
