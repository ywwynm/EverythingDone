# 把缩略图缓存复用修复延伸到单记事 Widget 配置界面

上一版修好了主列表大文件夹缩略图缓存复用（onViewRecycled 摘树）。本版把同一修复补到单记事 Widget 配置
界面——那里也有记事/文件夹列表与大文件夹缩略图，存在同样的缓存失效。仍带诊断埋点。

## 主要改动

- **修复：单记事 Widget 配置界面的大文件夹缩略图缓存，在“滑出较远再滑回”时也未能复用、仍重建。**
  - 根因：配置界面列表外层是另一套适配器，文件夹卡的渲染委托给内部适配器完成。列表项被回收进复用池的
    回调只到外层适配器，内部委托适配器收不到，于是它身上挂着的缩略图树不会被摘下，滑回时缓存无法复用
    （与上一版主列表修复同因）。
  - 修复：外层适配器在回收列表项时，把文件夹列表项转发给内部委托适配器处理，使其摘下缩略图树（仍按
    文件夹 id 保留在缓存中），从而可被复用。
- 配置界面缓存的其余环节（按文件夹缓存、签名含私密揭示态、列表刷新清缓存、列宽/滚动状态）此前已随
  公共渲染入口生效，本版只补这一处回收转发。

## 怎么验证

1. 主列表：滑到全宽大文件夹，向下滑远再滑回，重复几次。
2. 单记事 Widget 配置：进入桌面单记事 Widget 的配置界面，若其中能看到大文件夹缩略图，同样上下滑动几次。
3. 取日志：`Android/data/com.ywwynm.everythingdone/files/debug_logs/folder_thumbnail_perf.log`，发回。
   重点看同一文件夹 id 第二次及以后是否为 `cache=HIT`、`build≈0`。

## 备注

仍是诊断版（每次绑定多做一次测量取数，体感略卡，以日志 `cache=HIT`、`build≈0` 为准）。两条路径都确认缓存
生效后，会出一版去掉诊断埋点的正式版，并视 `measure` 耗时决定是否进一步优化测量/布局。
