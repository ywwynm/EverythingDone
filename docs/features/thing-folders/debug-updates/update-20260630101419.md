# 修复媒体背景卡置底元素长按重绑时短暂失去置底

## 主要改动

- **修复：图片/视频作背景的记事卡，置底元素（音频数量、图片/视频附件数量、提醒/习惯/目标信息）在长按
  等触发重绑时，会短暂失去置底、改成紧跟标题/内容从上往下排，松手后才恢复。** 普通列表里的记事卡、
  以及大文件夹缩略图里该记事的预览卡都有此问题；长按另一条记事进出选择模式时也会再闪一下。
  - 根因：媒体背景卡的置底锚定（内容列高度固定为背景高度 + 底部 spacer 以 weight=1 撑满余下空间把状态
    块压到底部）原先放在 `holder.llTextContent.post` 里**异步**生效。而每次重绑，`applyCardContentGeometry`
    都会先把该 spacer 复位（GONE / weight=0）。于是重绑后到异步 post 执行前的一段时间里，置底元素就按
    正常流跟在正文下方；长按 / 进出选择模式会反复触发重绑，期间一直是未置底态，松手稳定后才由 post 锚定。
  - 修复：把锚定逻辑抽成 `applyThingCardMediaBackgroundBottomStatusAnchor`，在绑定时**同步**锚定一次，使
    重绑首帧即置底；异步 post 仅保留"分割线/放大等绑定后步骤改变自然高度时的高度再校正"（仍按 bindToken
    防止旧的更高绑定覆盖新的更矮绑定）。普通列表、缩略图预览、缩高预览三条路径行为一致，且缩高预览还能
    即时收缩。

## 验证重点

1. 图片/视频作背景、且带置底元素（音频数量 / 附件数量 / 提醒 / 习惯 / 目标）的记事卡：
   - 长按该记事进入移动/选择：置底元素**应始终保持置底**，不再短暂跟到正文下方；
   - 长按另一条记事进出选择模式：该卡片**不再因此闪一下**。
2. 同一记事作为大文件夹缩略图预览时，上述两点同样成立。
3. 媒体背景卡的静态外观（背景高度、遮罩、置底排版）与修复前一致。
4. 详情页拖动"卡片高度"滑条做缩高预览：高度即时跟随，不回退（仍只在确定后才落库）。

## 备注

这与前两版修复（大文件夹预览缩略图数量 202606300157、侧边图文缩略图高度闪动）属同一类"被 post 的二次
布局结算在重绑后留下中间态"问题，但触发的是不同代码路径（媒体背景置底 vs 侧图投影），此版只动媒体背景
置底路径。
