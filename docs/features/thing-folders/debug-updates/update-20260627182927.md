# 修复大文件夹里第一个正在做缩略图的图标/文字不显示（真正根因）

## 主要改动

- **修复：大文件夹（缩略图模式）里，正在做的记事作为第一个预览缩略图时，火箭图标 + "正在做"
  文字不显示**（蒙层在、图文没了；第二个及以后的预览正常）。上一版（更新码 202606271018）对此项
  的修复方向错了、没生效，本版定位到真正根因并修复。
  - 根因：缩略图预览卡与文件夹卡用的是同一个卡片布局、带相同的"正在做"蒙层 id。文件夹卡在测量
    时用 `findViewById` 找"自己的"蒙层，结果深度遍历先抓到了**第一个预览卡的蒙层**，把它按整张
    文件夹卡的尺寸强行铺满，导致那个预览里居中的图标 + 文字被摆到整张文件夹卡的中心、跑到小预览
    卡之外被裁掉。
  - 修复：卡片改为只在自己的直接子节点里找蒙层，不再深度遍历误抓预览子卡的同名蒙层。

- （沿用上一版）**选择模式下点击大文件夹缩略图 = 选择 / 反选该文件夹**，与点击文件夹卡片空白区域
  一致。

## 验证重点

1. 把一个正在做的记事放进缩略图模式的大文件夹、并让它成为**第一个**预览：火箭图标 + "正在做"文字
   应正常显示。短文字卡、高图片卡、全宽 / 非全宽文件夹都验证一遍。
2. 文件夹里第二个及以后的正在做预览仍正常（不回退）。
3. 普通列表里的正在做记事、右滑开始做事的蒙层外观不回退。
4. 选择模式点大文件夹缩略图仍能选中 / 反选该文件夹。

## 备注

此项此前有三次误判（图片异步加载、卡片高度→缩放归零、full-span 稳定卡重布局落不了地），均被复现
推翻；决定性线索是"只有第一个预览坏、第二个正常"，指向 findViewById 在共享布局里抓到了同 id 的蒙层。
详见 `docs/features/doing-thing-organize/decisions.md` / `sessions.md`。基于错误理论加在
`applyDoingCoverScale` 的强制重测等改动已全部回退。
