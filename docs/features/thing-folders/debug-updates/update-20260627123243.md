## 拖拽到 thumbnail 文件夹时原地缩小提交

本次 debug update 继续修正记事/文件夹拖拽到已有文件夹时的提交动画。

- 用户进一步确认：剩余问题集中在拖拽到 thumbnail-mode 大文件夹上，无论该文件夹是否 full-span，都会出现没有飞入动画或飞入坐标错误的问题。
- 重新梳理历史设计后确认：对于拖拽移入已有文件夹，目标 Folder 已经被 hover 高亮，overlay 也已经被用户拖到目标中的正确位置；这里不应该再计算目标 Folder 中心点，也不应该飞向目标中心。
- `ThingListOverlayDragController.finishFolderDrop(...)` 现在对 `MOVE_TO_FOLDER` 恢复为 `animateOverlayShrinkToTopLeft(...)`：保持释放位置，以 overlay 内容左上角为 pivot 原地缩小。
- `CREATE` 路径仍保留目标 rect 合并/飞入动画；`targetRectInRoot` 也只在 `CREATE` 候选上缓存，避免继续把 thumbnail 文件夹的 expanded shadow inset / content rect / CardView rect 混进移入已有文件夹的提交动画。
- 上一版释放阶段修复仍保留：松手时先校验已 armed 的目标 holder 和业务候选，不再因为最后一帧 overlay 左上角重新命中失败而丢掉提交动画。
