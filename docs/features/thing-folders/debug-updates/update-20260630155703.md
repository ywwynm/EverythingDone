# 修复大文件夹缩略图缓存复用失效（滑回仍重建），诊断埋点保留

根据上一版诊断日志（同一全宽大文件夹滑回时 cache=MISS_DETACHED、又重建约 44ms），定位并修复了缓存复用
失效的问题。本版仍带性能诊断埋点，供验证修复效果。

## 主要改动

- **修复：大文件夹缩略图整树缓存在“滑出较远再滑回”时未能复用、仍重建。**
  - 根因：列表项滑出被回收进复用池时，系统不会清理该项身上挂着的缩略图预览树，这棵树仍“附着”在那个
    待命的列表项上。等同一文件夹滑回、被绑定到另一个列表项时，缓存里的树因为还附着在别处而无法挂载，
    只能重新构建（约 40ms）。
  - 修复：列表项被回收时，把它身上的缩略图树摘下（但仍按文件夹 id 保留在缓存中），使其可被任意列表项
    复用。近处来回滑动本就由系统直接复用、不受影响；只有滑远再回这条路径会用到缓存，现在能正确命中。

## 怎么验证

1. 滑到一个全宽大文件夹缩略图，继续**向下滑较远**（让它滑出屏幕一段），再**滑回**它。
2. 取日志：`Android/data/com.ywwynm.everythingdone/files/debug_logs/folder_thumbnail_perf.log`
3. 发回。重点看同一文件夹 id 第二次及以后出现时是否变为 `cache=HIT`、且 `build` 接近 0ms。

## 备注

- 本版仍是诊断版，每次绑定会额外做一次测量取数，**体感会比正式版略卡**；判断缓存是否生效请以日志里的
  `cache=HIT`、`build≈0` 为准。
- 确认缓存生效后，会再出一版去掉诊断埋点的正式版，那才是真实手感。
- 日志另一项 `measure`（约 8~12ms）是缓存命中后仍需付出的“测量大卡”成本，缓存省不掉；若正式版仍有可感
  卡顿，下一步会专门优化它。
