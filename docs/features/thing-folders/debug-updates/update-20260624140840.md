# 记事状态变更保留置顶状态

本次 debug update 修正了上一版置顶状态修复没有覆盖到“完成/删除/恢复记事”的问题：

- 用户验证发现：无论在根目录还是在某个文件夹内，完成置顶记事后，在“已完成”列表中该记事不再置顶；据此推断删除、恢复路径也可能同样丢失置顶状态。
- 重新诊断后确认，状态变更最终由 `ThingDAO.updateState/updateStates` 写入 `things.location`。上一版在 `ThingManager` 预先计算目标位置的方案没有可靠覆盖实际落库路径。
- 新实现改为在 DAO 层统一处理：状态变更时，如果原记事 `location < 0`，直接保留原负数 `location`；因此完成、删除、从回收站恢复时都不会把置顶记事写入非置顶区。
- 原本未置顶的记事仍保持既有行为：完成、删除、恢复后进入目标状态列表的非置顶区顶部。
- 批量状态变更和内存态 `ThingManager` 的 header 更新也同步改为只按非置顶记事数量前移，避免置顶记事状态变更影响 header。
- 移除了无关的 header 解释性改动；详情页和通知/远程动作继续传原 `location`，由 DAO 统一保留置顶。

同时保留上一轮移动/拖拽建夹规则：

- 移动记事或文件夹时保留源条目自身置顶状态。
- 拖拽两个记事创建文件夹时，任一成员置顶则新文件夹置顶，成员记事移入后也保留各自置顶状态。

验证：

- `:app:assembleDebug` 已通过。
