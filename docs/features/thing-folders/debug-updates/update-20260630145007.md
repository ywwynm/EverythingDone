# 优化全宽大文件夹缩略图：分列不均与滑动卡顿

## 主要改动

- **修复：全宽大文件夹缩略图瀑布流分列不均——某列明显还能放下一张卡，卡片却跑到另一（更高）列，把
  整张大文件夹卡撑高。**
  - 根因：瀑布流用粗略估算（标题按单行、正文按固定行数、媒体按固定高度）选"最矮列"，估算误差累积后
    把卡放进实际更高的列、留下空列。
  - 修复：改为"先建预览卡、按列宽实测真实高度、再选最矮列放入"，分列即精确；仅在测量异常时回退旧估算。

- **优化：滑动记事列表从下往上滑到大文件夹时容易"一顿再继续"，缩略图含封面图/视频或布局较复杂的
  记事时更明显。**
  - 根因：每次绑定大文件夹卡，都对 6~10 个预览同步 inflate 整个记事卡布局并跑完整绑定，且无复用；
    滑入与全量刷新都从零重建，整批挤在一帧。
  - 修复：新增"按文件夹缓存整棵已构建缩略图树"，内容未变时原样复用，跳过重复 inflate / 重绑 / 重缩放。
    来回滚动、以及模式切换/选择这类内容未变的刷新都直接命中复用。

- **缓存正确性：内容指纹签名 + reload 兜底，确保文件夹内容任意更改都及时刷新缩略图。**
  - 签名直接对渲染输入取指纹（记事的标题/正文/附件/背景/卡片外观，子文件夹的标题/背景/外观/计数等），
    不只依赖 updateTime。
  - 再加一道兜底：列表 reload（任何内容更改的必经路径）会替换 entry 列表实例，据此清空缓存强制重建，
    连习惯/目标打卡进度这类不改记事字段的更改也覆盖。
  - 文件夹重新上锁时清除其缓存树，避免私密预览内容滞留。

## 验证重点

1. **分列**：全宽大文件夹（手机 3 列、最多 6 个缩略图）内部排布是否均匀，不再出现"空列旁边却把卡堆到
   另一列、整卡过高"。
2. **滑动手感**：记事列表从下往上滑到大文件夹是否明显更顺，尤其缩略图里含封面图/视频、或带提醒/习惯/
   清单等复杂布局的记事；来回滚动多次复用是否流畅。
3. **内容更改即时刷新**（重点）：在大文件夹缩略图可见的情况下，对其中内容做以下更改后返回列表，缩略图
   应**立即反映**，不显示旧内容：
   - 编辑某条记事的标题/正文/封面图/卡片外观/颜色；
   - 在该文件夹内新增、完成、删除、移入/移出记事；
   - 置顶/取消置顶、重排；
   - 子文件夹改名、改背景色；
   - 习惯/目标打卡后进度变化。
4. **私密与外观**：私密文件夹认证揭示前后、详情页外观面板拖动实时预览、进出选择模式时，缩略图是否
   仍正确（内容、可点击性、上锁态）。

## 备注

性能方案最终选"整树缓存"而非"单卡复用池"：预览卡的文字缩放是累乘真实尺寸、且部分字号与每条记事内容
相关，单卡复用易二次缩放或字号不一致且无真机难验证；整树缓存命中即原样复用、永不重绑重缩放，规避了
这类风险。代价是某文件夹首次进入可视区仍需构建一次（无法在不引入上述风险下安全消除），但来回滚动与
内容未变的全量重绑这两类主要卡顿场景已覆盖。
