# 调试更新

## 2026-10-09 — 横向意图判定与可取消粒子准备

用户要求在清单解析优化之后，继续避免普通竖滑触发粒子截图和材料准备，并让取消能阻止尚未开始的后台工作；同时要求在三星、魅族、OPPO 三台真机验证后发布。

- 首页和 Doing 在按下时只记录候选与最初触点。横移达到系统 touchSlop 的一半、且横纵位移比达到 1.5 时开始准备；ItemTouchHelper 正式接管横滑时即时兜底。保留原位消散、触点、完成及回拖行为。
- 竖滑、取消、多指、实际长按接管、目标内容／位置失效时取消未接管的准备。未确认方向的候选可超时；已确认横向意图不会仅因截图提交等待跨过超时而被误取消。
- 新增 ParticlePreparationScope，取消可阻止排队中的像素复制、材料和飘散分析，并在快照读回、交接复制、前景准备及 GL 阶段检查取消。已提交的 GPU 工作安全收尾，位图要等正在读取的任务真正结束才能回收。
- 保留上一版共用 CheckListHelper 线性归一化和父项查询优化，详情编辑等调用者仍使用完整独立结果，存储格式不变。
- 407 项本地回归通过。三台设备均完成流体／飘散测试：72 次主要竖滑对照，旧版 36 次均截图，新版 36 次均不截图；另有 54 个新版虚构卡片场景，左右完成、回拖、取消及非零呈现检查通过。最终包再次通过三机真实首页横滑取消和 12 次竖滑复核。
- 观察到三星按住窗口的重帧由约 44–45 ms 降至约 15 ms，OPPO 部分起手超时减少。三星偶发超限仍在，不能宣称掉帧全部解决。魅族清单解析的采样热点明显减轻，但首次复杂卡片创建／绑定仍会卡顿，新装包的代码热身也造成明显波动。
- 横滑首帧有代价：虚构卡片按住后再横滑，流体首个非零画面从约 49–58 ms 增至 124–176 ms；真实复杂大卡还可能更慢。此版改善普通竖滑的无用工作，后续仍需压缩实际横滑准备、卡片行创建与媒体绑定成本。

完整实现与测量见本功能目录的 `swipe-preparation-2026-10-09.md`、`verification-2026-10-09.md`。测试只通过虚构卡片触发完成，真实记事仅执行滚动和取消手势；不发布用户记事内容。未创建 Git 提交。
