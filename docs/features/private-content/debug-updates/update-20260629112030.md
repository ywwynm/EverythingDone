# 私密"层层设防"统一排查与堵漏

系统排查了散落各处、用 `thing.isPrivate()`（只看前缀）而非"有效私密"的判定点，以及缺少"已认证豁免"的鉴权点，堵了几处泄露并统一了口径：

- **验证总闸 `AuthenticationActivity` 改用有效私密**：处于私密文件夹内、自身无前缀的记事，从桌面小部件 / 通知点进来时也会正确要求验证。之前这道闸只看前缀，会把上一批 P5 已正确路由过来的这类记事又放行——等于 P5 的通知/小部件堵漏被这道闸架空。
- **提醒 / 习惯通知的动作**（完成 / 开始做 / 延迟）改用有效私密判定，避免对"私密文件夹内无前缀"的记事直接执行、不验证。
- **记事移动鉴权与文件夹移动对齐**：在已认证的私密文件夹里移动记事不再重复验证，只有源 / 目标是"未认证的"私密文件夹时才验证（此前文件夹移动有此豁免、记事移动没有，不一致）。
