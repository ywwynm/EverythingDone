# dialog-particle-dismiss 决策记录

## 2026-09-11 局部解除速度加强弧度，距离换算实际运动幅度

- 保留共同释放、速度场、随机布局及寿命。加入沿解除边界法向的短时展开，随材料年龄衰减，使横向边缘向外弯出，并保留下方较早释放的拖尾；微小独立幅度差使边缘保留粒状厚度。不读取人物名称或图片坐标。
- 单纯对空间流场速度乘倍数，或叠加共同顺风位移，仍不足以稳定体现近远差异。改为在材料坐标中积分共同运动，同时按真实触点距离换算实际位移和实际速度；幅度限定为 0.55～1.45，默认为 1。触点不作为吸收点，屏幕和控件边界不产生碰撞。
- 新增固定局部弧边三栏视频、三素材单方向近中远视频及同位置切换。检验同一播放时刻的真实变化，不再用数值不同替代可见差异。详见[本轮记录](rim-flow-2026-09-11.md)。

## 2026-09-11 弧边分支由供料关系恢复，触点距离按可用背景解释

- 单纯减弱顺风补偿与速度下限不能恢复用户指出的弧边分支；冻结随机坐标和时序变换则恢复。共同模型保持原场，按局部起点独立程度连续调节随机变形幅度，避免连贯卷边的源材料被大幅错开；不添加人物专属规则或独立描边。
- 近远以实际触点占该方向可触摸背景的比例影响速度，保留绝对距离用于温和偏向。它是交互尺度映射，不宣称是华为的内部物理公式；屏幕边界不限制粒子运动。
- 增加弧边整体／局部三栏连续对照；回归复查既有 234 组状态但不重新导出全部历史标注视频。详见[本轮诊断](curve-split-2026-09-11.md)。

## 2026-09-11 撤回过强目标汇聚与全面替换释放场

- 用户指出上一候选既丢失原钢铁侠轨迹，又出现过强目标汇聚，屏幕外距离演示也不可复现。撤回该候选，保留其参考提帧、分析记录和冻结结果，不发布到阿里云。
- 下一实现以 `archive/before-targeted-release/` 为运动基线；先联合比较两段钢铁侠、灭霸、科比，再验证同一模型的输入变化能够覆盖这些形态。
- 触点用于有界的输运速度与局部方向变化，不再用剩余时间分母驱动所有材料趋近一个点。距离验收改用素材内的真实可触摸区域，保留原运动和形状的对照，不能只满足远近比值下限。

## 2026-09-11 触点参与轨迹，释放前沿从局部区域扩展

- 取代仅按距离增加小幅顺风速度的做法：用实际背景触点减粒子当前位置，并结合整段动画剩余时间计算输运。短寿命不再意味着更早高速冲向触点；保留原流场和相干卷动，不在终点或屏幕边缘停靠。
- 局部起始区域沿控件周界错开，位置和范围随种子变化、数量随长宽比变化；释放时间与后续流场时钟衔接。方向不再把完整释放前沿旋转成横贯宽高的轮廓。
- 新增向上钢铁侠参考取材和相机配准，作为共同模型的额外对照；源图合成限制、参考时间映射、固定种子均明确标注。
- 验收同时看实际位移、速度、目标接近和前沿形态，不能再用“距离数值单调”替代可见差异。详见[真实触点与局部释放记录](targeted-release-2026-09-11.md)。

## 2026-09-11 卷动形变与触点距离

- 只证明粒子发生位移不够；对容易呈刚性运动的区域，增加随主流迁移的相干旋度，并测量扣除平移、旋转后的形变。
- 控件纹理尺寸与局部流动尺度分离，长轴尺度平滑封顶，重叠区域共同覆盖长面板。所有场景使用同一几何规则。
- 实际触点距离从控件边缘沿射线开始测量，以短边归一化，平滑映射到有界输运增量。触点不作为到达后停止或反弹的边界；返回键保持左上与默认中距离。
- 默认验收集增加颜色八方向和三素材双方向三距离，原速、半速共 118 视频。利用全部既有输入复查状态，不重导 226 组标注视频。详见 [本轮记录](flow-shaping-2026-09-11.md)。

## 2026-09-11 无观测区域不再作为零速度目标

- 静态拍摄背景、没有粒子的区域不提供有效运动证据。对共同速度表作邻域延拓与平滑，不再让进入这些区域的材料被拖停；保留可靠运动样本和原释放／材质／随机规则。
- 验收利用全部已有标注做状态分析，只对重点输入重新渲染；检查固定身份在完整可见窗口内的实际路程与轮廓迁移，不能用很小的速度阈值宣称视觉修复。
- Android 采用后台建材与图形初始化重叠，避免嵌套线程竞争；每次固定的随机时钟预计算求逆初值，仍作精确数值修正。实测收益有限，保留原始耗时记录，不把离屏提交帧数当显示帧率。

## 2026-08-27 掀起点位于运动上游并近同时出现

用户指出参考视频中粒子最终向上飞，但最早的掀起发生在画面下方，几个局部掀起点也近乎
同时出现。重新按 60fps 逐帧复核后确认：最早可见粒子化在下方通知卡，其他左侧/较上方
局部缺口约在随后 6–8 帧（约 100–130ms）内出现；不是从一个起点完整扫过所有内容。

因此取消“触点近侧边缘优先起碎”的建议。新模型按运动方向的反向一侧（上游侧）布置首批
局部起点，并让 3–5 个起点在很短的时间窗内近同时激活；它们各自形成局部帷幔，随后沿
触点主方向运动。起点之间允许细小错时以避免机械同步，但不形成明显的先后扫描感。

这里的“反向一侧”是概率偏置而非排他规则。用户特别强调必须保留“主要”二字：多数起点
位于飞行方向的反向一侧，但不能全部集中在那里；侧边以及少量顺向一侧也应出现局部起点，
共同构成多处近同时掀起，避免重新退化成单侧扫描线。

## 2026-08-27 无触点关闭的默认方向

用户确认：返回键或代码关闭等没有有效触点的路径，默认采用向上掀起并飞散。该默认方向
只替代缺失的触点方向，不改变“起点多数在飞行反向一侧、少数分布在其他边缘”的规则。

## 2026-08-27 受控随机

用户确认每次关闭可对掀起点位置、帷幔弧度和横向摆动施加受控随机，使重复操作不完全
相同。随机结果必须始终满足以下约束：主方向跟随触点（无触点默认向上）、多数但非全部
起点位于飞行反向一侧、3–5 个局部起点近同时激活、同一帷幔早期保持邻域相干。不能再用
“随机性”容许单侧扫描、整齐矩形边、漏斗、白团或从起始帧散成独立砂砾。

## 2026-08-27 未触及区域保持完整

用户确认取消当前“动画开始即对整张 Dialog 全局打孔、快速露底”的策略。新消失动画中，
只有局部掀起点及其扩张帷幔经过的区域逐步露出底层；尚未被任何帷幔触及的区域保持完整、
清晰。多条帷幔扩张并交叠后，Dialog 才完全消失。

因此移除普通区域 3%–9% 保留率与被剔除粒子极短闪现的组合；静止层和粒子层应共享同一
多种子激活场，在局部激活发生时无缝交接。

## 2026-08-27 新帷幔模型继续保留内容色强调

用户指出第四十二轮桌面视频重新以白色/中性色粒子为主，要求保留此前已定案的真实内容色
强调。粒子颜色继续逐位继承快照，不统一染色；同时不能只做数学上的“原色保留”，因为
Dialog 本体色面积占绝对多数，视觉上仍会淹没彩色内容。

新消失模型恢复高饱和内容色专属的两个小副本，并保留按色距与饱和度计算的尺寸、寿命
权重；白色面板和黑字仍为单颗。副本共享所属帷幔的激活时间、主方向和前段连贯运动，
只在切向错开不到一个采样格，中后段才随独立 hash 轻微分离。因此内容色增强不能以破坏
多起点结构、局部完整性或早期片层相干为代价。

## 2026-08-27 立体感采用连续 2.5D 片层

用户确认立体感目标是“有厚度的半透明粒子片层发生空间卷曲”，而不是粒子明显、随机地
朝屏幕内外飞散。伪深度必须由每条帷幔的连续曲面产生：相邻粒子共享曲面坡度和前后层，
深度只受控地影响投影尺度、速度、透明度与明暗；中后段才允许少量个体深度差。

因此后续不得用逐粒子随机 `z`、强透视放大或向镜头爆散制造立体感。现有主方向跟随触点、
多起点近同时、未触及区域完整和早期邻域相干仍是更高优先级的不变量。

## 2026-08-27 透明材质只作用于已激活片层

用户确认透明材质不得在动画开始时作用于整个 Dialog。尚未被任何局部帷幔触及的区域
继续保持原始快照的完整、不透明显示；只有在局部激活、静止层与粒子层完成交接后，粒子
片层才进入半透明材质状态。

接近 Dialog 本体色的粒子应更通透，让底层界面参与混合；彩色控件、图标和文字粒子保持
更高不透明度与颜色身份。透明度可以随连续伪深度和曲面朝向小幅变化，但不能再次形成
整卡提前淡出或全局打孔。

## 2026-08-27 2.5D 采用固定的中等强度

用户确认首版先采用中等空间层次：后层投影尺度暂以约 0.86–0.94、前层约 1.08–1.16，
前后层速度差暂以约 ±12% 为候选起点。定格时应能辨认前后层和卷曲厚度，连续播放时不能
产生粒子朝观察者扑来的强透视感；具体数值须在真机目验后再收敛，当前不是最终常量。

用户随后取消“保留 2.5D 独立开关和参数调节能力”的要求。后续不新增正式设置、开发者
调节入口或专门为运行时调参扩充的 `ParticleDismissSpec` 字段；中等强度直接作为消失
动画的一部分实现。实现所需常量仍应在代码中保持清楚、集中，并由 canonical 桌面渲染
与 Android Shader 使用一致定义，但不为其建设额外的配置层或用户界面。现有控制整个
粒子出现/消失动画是否播放的设置保持不变。

## 2026-08-27 返回操作的消散方向改为右上

用户要求通过系统返回操作关闭 Dialog 时，粒子向右上方消逝；这取代此前“返回键默认
向上”的决定。当前 `GestureAnchoredDialog.dismiss()` 只接收最近一次 `lastTouch`，既不
记录关闭原因，也可能在返回操作中误用更早的触点，因此实现时必须显式区分返回关闭与
触摸触发的关闭，不能只把默认角度常量从向上改为右上。

用户进一步确认，异步完成后自动关闭、代码主动关闭等其他无触点路径也统一采用右上。
实现时使用位于 Dialog 右上方之外的同一个虚拟触点，同时作为运动目标和虚拟光源的平面
位置；只有与本次关闭存在直接因果关系的真实触点才覆盖该回退点，历史触点不得继续生效。

右上回退方向固定为从屏幕正上方向右偏约 30°，即 Android 屏幕坐标中的单位方向约为
`(0.5, -0.866)`。该方向仍以上行为主，同时具有清楚的右移分量，不采用横向占比更高的
45° 对角线。

真实触点不再使用现有约 40dp 的中心回退区。只要 Dialog 中心到真实触点的方向向量能够
可靠归一化，就严格按该向量确定消散方向；只有向量长度接近数值零时才采用右上回退方向。
即使发生这一极小概率退化，虚拟光源的平面位置仍保留真实触点，不改到右上回退点。

## 2026-08-27 空间层次集中在帷幔相干阶段

用户确认 2.5D 深度与触点光照均采用局部生命周期包络：未激活区域完全不变；局部激活后
迅速建立卷曲深度，在高密度、邻域相干的帷幔阶段达到峰值；粒子开始个体解耦后，前后
尺度差、速度视差和光照响应同步减弱，末段只保留轻微空间层次。不得让尾粒子继续维持
明显分层，从而增加末段视觉重量。

## 2026-08-27 帷幔与尾流采用真实粒子数量差

用户指出参考效果中揭开帷幔的粒子密度明显高于其他已消散区域，而当前实现不同区域近乎
等密。检查确认当前 `density` 仅在约 0.88–0.99 间调制 alpha，每个已激活网格实际仍绘制
相同三层粒子，不能形成足够清楚的数量对比。

后续改为按粒子局部年龄控制真实占用率：揭开后的约 120–220ms 保留完整网格采样，形成
高密度帷幔；进入尾流后，以稳定的逐 cell 哈希把面板本体色粒子降到约 22%–30%，内容色
保留约 45%–60%。后/主/前三层必须共享同一 cell 抽稀结果，避免厚度结构被随机拆散；
未激活区域仍由完整静止快照绘制。密度差主要来自实际粒子数量，不用单纯提高亮度或再次
叠加同位置副本伪造。

## 2026-08-27 增强 3D 感以相干回卷轨迹为主

用户真机确认第四十三轮的空间感仍然偏弱，并要求提高 3D 感强度。增强方式不采用单纯
放大固定三层的粒径或静态深度值，而是把伪深度真正投影到随时间变化的二维轨迹：同一条
帷幔的浓带应围绕推进锋线形成相位连续的回卷截面，前后层沿该截面产生更明显的速度差、
横向视差、尺度差和动态覆盖/显露；不同帷幔保持各自的受控弯曲方向，避免再次变成平行
移动的三张粒子图。

透明材质与触点光源继续作为辅助线索。面板色片层仍允许底层参与混合，原始内容色保持
更实；光照由连续曲面法线决定。运动结构、密度锋线和遮挡线索优先于提高全局高光或辉光，
不得以洗白彩色粒子、随机逐粒子 z 或朝观察者爆散来换取强度。

## 2026-08-27 新参考切换为不透明表面的粒子化解体

本轮以 `93292e5c744d4770c4f7ecb686f3dd60.mp4` 为主要运动参考。分析对象从“透明控件是否
带来空间感”切换为不透明表面如何经过连续断裂锋线转化为保留原始颜色的粒群，以及粒群
如何在相干流场中形成弯曲轮廓、前后遮挡、速度差和稠密到稀疏的过渡。网络调研只搜索这类
效果本身及相关运动规律，不再搜索华为或鸿蒙实现。

研究用并排视频新增左上方向的模型输出。该输出是视觉对照场景，不进入运行时方向决策；
正式应用仍保持真实触点方向优先、无直接触点时默认右上的既有规则。

## 2026-08-27 激活场增加方向性速度梯度与柔化交接

用户逐帧对比后确认三个需要同时修正的差异：飞行顺向角不应在开场明显停留；孔洞边缘
不能是锐利的完整表面切口；宏观消融进度应从飞行反向侧更快地向顺向侧推进，同时保留
其他边缘的近同步局部起碎。

因此激活场不再只依赖五个种子的欧氏距离与大幅噪声竞争。后续以运动轴上的归一化投影
提供稳定的宏观时序梯度；运动反向侧种子负责更快、更大范围的表面传播，顺向侧保留一个
更早但更短、传播更受限的局部出口，使角部粒子能尽早脱离而不主导整卡消融。静止表面和
粒子层使用带短暂预转换区的同一交接包络，在局部前缘内逐渐从连续表面转为细粒，不使用
全局透明或后处理模糊。

## 2026-08-27 高密帷幔必须是窄带而非大半粒云

用户指出更新方向时仍不能忽略粒子群密度组织：参考效果依靠贴着揭开锋线的高密度粒群
形成帷幔，已揭开区域则明显更稀；当前连续画面中两者仍近似等密。检查发现旧回归只比较
各自支撑区内的像素覆盖率，没有检查高密阶段占全部可见粒子的比例；旧 200–380ms 密度
窗口使高密粒子在测量帧中占约 71.9%，因此 4× 以上的局部覆盖率仍可能对应一大片等密云。

密度回归改为把主体层每个存活 cell 固定绘制成 1px，排除粒径、alpha 与三层重叠后统计
真实点中心，同时约束高密点占比。高密窗口收窄到局部出生后的约 68–175ms；面板色尾流
保留约 20%–32%，内容色尾流保留约 62%–74%，高密带保留约 88%–100%。本轮先以桌面
canonical 对照确认连续观感，不发布新的 Android 调试版本。

用户查看桌面对照后授权进入 Android 实机确认，因此上述“不发布”只约束授权前的桌面
迭代阶段。当前 canonical 参数已随调试版本 `202608271156` 发布；后续是否继续调整，以
同一实机上的连续播放和逐帧录屏为准。

## 2026-08-27 归一化阶段约束与统一的内容色粒子

后续不再只约束动画结束时是否收净，而是把参考视频的归一化阶段作为 canonical 回归：
约 0.32 时飞行顺向角和反向主揭开区都必须已有缩放后可辨认的粒子群；约 0.47 时紧贴
消融锋线的帷幔条带必须在亮度和局部光学密度上明显强于普通尾流；约 0.70 时完整表面
应基本清空并进入风场输运阶段；约 0.90 时不得再出现完整内容残片。

彩色控件粒子统一使用与面板粒子相同的局部时钟、寿命、运动、点尺寸、透明度和深度响应，
不得再用更慢、更大或更持久的单粒子造成脱离粒群的观感。颜色存在感只通过更高的真实
cell 保留率强化，即同一彩色源区域产生更多粒子；三层仍共享同一占用掩码。主风强度按
全局动画时间增长，避免晚出生粒子从弱风重新起步；末段以全局包络统一收尾。

## 2026-08-27 帷幔验收必须排除未粒子化表面

帷幔是否成立不得再从普通合成帧的白色亮区或全局 band/tail alpha 比推断。canonical
回归必须分别渲染静止表面、全部粒子、高密帷幔粒子和稀疏尾流；沿静止表面锋线的外法向
测量纯粒子局部密度。浓带峰值应位于表面之外但仍贴近锋线，既不能落在 0–4px 白边内，
也不能远离锋线退化成悬浮粒云；同时约束高密粒子覆盖完整表面的质量占比。

高密阶段不再在粒子刚出生、静止表面仍占主要权重时达到峰值。它应在局部 handoff 基本
完成后快速建立，再释放为尾流；这样高亮来自独立粒子浓带，而不是 Dialog 残余表面。
帷幔亮度以真实满采样、空间聚集和较硬粒子核心共同形成，单粒子 opacity 不得高到使三层
全部饱和成白色实边。面板尾流进一步抽稀，彩色内容仍只通过更多真实粒子保持存在感。

## 2026-08-27 分离后的帷幔与内容色继续增加真实采样

在已经证明高密条带不是残余 Dialog 白边之后，按用户反馈继续提高两类真实粒子数量。
高密窗口的基础 cell 保留率由约 88% 提高到 92%，内容色在该窗口追加少量保留权重并钳制
在 100% 以内；尾流面板基础保留率进一步降低，内容色保留斜率提高，使有色区域相对其源
像素占比产生更多粒子。所有颜色仍共享相同的激活场、局部时钟、速度、寿命、粒径、透明度
和三层深度响应，避免内容色再次游离成独立粒群。

同时把高密窗口内向共同回卷截面的屏幕空间汇聚系数从 0.55 提高到 0.68，使新增粒子集中
到真正的帷幔窄带，而不是平均填满整个粒云。最终固定 1px 点中心回归中，帷幔/尾流真实
占用密度由 2.09× 提高到 2.19×，高密点占 31.3%；内容色数量表示由 2.54× 提高到
2.86×，颜色 alpha 表示为 2.07×。纯粒子法向峰仍位于静止表面外约 14px，浓带相对
0–4px 表面粒雾为 5.30×、相对 24–44px 外侧尾流为 3.94×，与静止表面重叠质量仅
0.35%，因此增强没有退化成贴边白线或大面积等密粒云。

## 2026-08-27 夸张密度采用窄带满采样与尾流统一抽稀

按用户给出的定量目标，canonical 回归把固定 1px 主体层点中心的帷幔/尾流占地密度比
下限提高到 `4.2×`，把内容色真实粒子数量表示下限提高到 `4.5×`。高密窗口继续接近
满采样；尾流在完成 `contentWeight` 构成后统一乘以 0.60 的保留系数，使所有颜色一起
变稀，不为彩色内容设置独立速度、寿命、尺寸、透明度或深度规则。最终四个种子的平均
占地密度为 4.47×，内容色数量表示为 4.61×。

高密点占全部点的比例不再作为“帷幔是否过宽”的判据。提高密度比会必然提高该比例，
旧上限与本轮目标相互冲突。新回归改为约束膨胀后的几何支撑面积：高密带当前只占整帧
2.8%、占 band/tail 联合支撑区 19.1%，即允许窄带内部有大量真实点，同时禁止高密状态
铺满画面。纯粒子法向峰继续位于表面外约 14px，并与 still layer 分开验收。

## 2026-08-27 全局非线性风势与局部沿边转向分工

主输运使用全局动画时钟的 `t^3.85` 风势，并减去每颗粒子出生时已经存在的风势，确保
出生位置连续而速度随全局过程明显增强。固定同一批长寿命主体层 cell、排除出生和淡出
后，模型中段/早段速度比为 5.77×，后段/中段为 3.01×；参考视频实测分别约为 6.88×

## 2026-08-28 真机截图夹具成为桌面一致性基准

桌面连续布面网页与 Android 生产 Shader 是两套不同的运动实现，不能再把前者的观感直接
当作后者的桌面预览。建立真机截图夹具后，一致性检查固定使用同一背景、同一 Dialog、

`ParticleDismissRenderer.kt` 中的 canonical GLSL 离屏渲染，右侧才显示旧 JS/PBD 连续
布面模型。canonical GLSL 是 Android 行为基准；JS/PBD 只负责研究目标运动，不再承担
“已迁移效果”的证明。

本轮实测真机截图为 `1440×3168 px`，Dialog 边界为 `(160,1082)–(1280,2181)`，尺寸
`1120×1099 px`、圆角约 `64 px`；背景暗化量为 `0.6016`，与生产常量 `0.6` 一致。
Dialog 有效区域约 `96.5%` 像素为 RGB 各通道均大于 240 的近白色，仅约 `0.83%` 为
明显彩色像素，因此生产 Shader 的中性色占用率会主导这类真实素材的粒群质量。
左上真实触点排除了返回键右上回退造成方向差异的假设。归一化 `t=0.32/0.47` 时，两套

Android 逐点程序化流场与较低的普通尾流占用率，而 JS/PBD 保留连续布面及更持久的材料
相干性。此前把凝聚 Shader 的 `0.16–0.28` 短寿命段误读为消失路径；生产消失 Shader
实际寿命约为 `0.80–0.995`，中性普通尾流的基础占用率约为 `7%–10%`，高密带另有约
`43%–55%` 的占用率。后续不能再以“约 85% 消失粒子短寿命”作为调参依据。

## 2026-08-28 Android 与桌面 A 共享有状态连续薄面轨迹

`sampler2DArray`。逐帧顶点 Shader 只读取当前曲面与脱离时刻的曲面状态，避免 CPU 每帧
更新顶点，也避免继续用多个独立粒子条带拼出帷幔。

触点仍决定主风方向；左上 `-128°` 必须与桌面 A 的固定方向得到相同轨迹。其他方向通过

继续只增加同一轨迹上的采样数量，不进入释放、脱离、速度、寿命、尺寸或风场。

消失材料采样固定为约 `144` 列，最多绘制 `1` 个主体加 `2` 个密度副本；真机截图夹具

点径和亮度共同承担，不再用更多全局副本堆叠。PBD 轨迹使用 `RGBA16F` 纹理数组上传，

## 2026-08-28 dim 与粒子以已交换到屏幕的 GL 首帧为共同起点

消失请求、PixelCopy 回调和动画首帧是三个不同的时刻。dim 淡出不得在消失请求返回时
立即启动，而要由 `ParticleDismissOverlay` 在粒子渲染器完成第一次 buffer swap 后回调
启动；粒子时钟同样从该首帧开始。GL 建链或求解失败时，降级淡出路径仍必须恰好一次触发
同一回调，避免暗层滞留。

真实 Dialog 的移除还必须同时等待两个条件：Activity overlay 已实际提交，以及上述 GL
首帧已经交换。只等待 overlay 提交会让 Dialog 在 PBD 准备期先关闭，使输入法和背景先于
粒子变化。`ParticleDismissStartGate` 对两个条件做与门并保证回调恰好一次；因此 dim、
粒子、真实 Dialog 移除及其引发的背景状态变化从同一个可见起点衔接。

实机诊断确认 PixelCopy 只耗时约 `10–14 ms`，旧时序的主要延迟来自 PBD 初始化：旧实现
在 `R5CW20BLNKL` 冷启动约 `944 ms`，恰好接近 dim 的 `1000 ms` 时长，因而视觉上表现为
“dim 播完后粒子才开始”。这不是特定设备的 PixelCopy 差异，而是两个动画时钟的启动顺序
错误。

生产 PBD 求解保留 `240` 个归一化步长，但状态改为连续 primitive SoA 数组；空间控制网格
采用 `16×10`，约束从每步 `9` 轮换算为累计刚度等效的 `1` 轮。粒子采样密度不受控制网格
分辨率影响，Shader 仍对曲面双线性插值。桌面 A 的开场贴附、`t=0.15/0.25/0.55/0.70`
顺风位移、释放比例和连续曲面时序由数值回归约束。实机冷启动 PBD 降至约 `216 ms`，同一
进程第二次约 `70 ms`；首帧与 dim 的启动偏差为 `0–1 ms`。

## 2026-08-29 桌面与真机统一使用原分辨率光栅过程

漂移、噪声尺度与网格步长按同一物理像素比例缩放。

t=0.47 的分层诊断必须同时输出残留表面、全部粒子、高密折叠粒子与普通尾流。高密部分
当前是一条沿剥离前沿传播的单一弯曲段，不是残留白色表面边缘，也不再出现多个互不连接

## 2026-08-30 释放拓扑改为方向压力、材料阻力与内部附着脊

逐帧材料坐标统计确认，参考动画并非从四条外边缘按最近距离向中心侵蚀。旧模型把主体
方向场与上、左自由边距离场做平滑最小值，去除风向趋势后仍有 `0.626` 的最近边缘相关性，

运行时释放场现统一为一张连续材料相位：沿风方向的压力在内部附着脊达到最晚解除，越过
附着脊后自由侧因约束减少而略早解除；低频材料阻力弯曲等时线；反向法向压力、反向剪切、
顺风角张力及其相邻剪切区形成几个有限宽度的同期起始区域。所有区域通过加法势场自然
汇合，不读取参考遮罩，不使用 `distanceX`、`distanceY`、最近边缘距离或多场 `min`。

个高阻力网格点压成相同的最晚时刻，导致后段留下轮廓规整、整块同步消失的区域。新实现
仅在最终输出阶段映射到 `0.018–0.585 s`，再由完整层的 `120 ms` 软过渡收束，整个动画
仍严格在 `1.000 s` 内结束。

拓扑回归不再强制“单值方向前沿”或“所有留存像素始终单连通”。它改为约束：去除风向
趋势后的最近边缘相关性不超过 `0.45`；四边中大范围向内领先的不超过两条；释放区必须
连接外部；至多允许两个宽留存分支，但禁止小于全场 `1.5%` 的孤立残片和形态学尖刺。

## 2026-08-30 高密前沿禁止使用横向截断弓形

用户指出中段右下高密粒群的下缘过度突出，并呈现多段曲线拼接的轮廓。分层探针确认该
缺陷只存在于高密帷幔粒子，不来自未粒子化表面或普通尾流；降低自由飞行横向漂移、PBD
折叠频率／幅度以及 release field 细节均几乎不改变该轮廓。直接原因是 Shader 在真实
布面和释放相位之后，又沿接缝横向叠加了一段截断抛物线；其端点只有位置连续，切线并不
连续。最长 `165 ms` 的脱离相位跨度又让多个年龄层同时显形，放大了拼接感。

## 2026-08-30 按复测结论重建消散模型

用户在看过 [research-2026-08-30-reference-remeasure.md](research-2026-08-30-reference-remeasure.md)
后确认按该方案实现，要求先桌面模拟器、再 Android，两端一致，并在真机
`R5CW20BLNKL` 上验证。模型定为三层，全部无状态：

1. **静止层**逐格硬切：`uTime >= curtainReleaseTime(cell)` 即整格 `discard`，
   否则原样绘制快照。取消 alpha 渐隐、`softPores`/`finePores` 与 3×3 相位滤波；
   交界的柔和只来自逐 cell 抖动。
2. **释放场**自归一化：主核到卡片最远角的距离定义相位 1，两个次核只做局部
   提前、永不抬高最大值。因此最大相位与种子、长宽比无关，表面恒在动画 60%
   处消耗完，也不会因为 clamp 让最后一批 cell 同刻消失。
3. **粒子层**每 cell 一个粒子，`v = W(t)·d·s + k`。`W` 线性升到 `n≈0.50`
   后走平，位移取 `S(t) − S(birth)`；`k` 是固定不变的随机踢，方向散布随共同
   风长大而自然收窄。粒径恒定，寿命 `lifeMax·(1 − √u)`（生存函数即实测的
   `(1 − age/lifeMax)²`），其中 8% 的粒子取更长的 `lifeMax`，对应参考末段的
   稀疏尘埃，也落实 2026-08-27「少量尾粒子最晚在约 1.0 秒内结束」。

**两端一致的实现方式**：除几何、时间、种子和飞行方向外，全部参数改为 GLSL
`const float`；释放核也在 Shader 内由 `uHashSeed` 与 `uSweepDir` 生成。桌面
canonical 直接抽取同一段源码，因此不存在需要同步的第二份参数或 CPU 模型。

**已删除**：`ParticleDismissClothModel.kt`（PBD 薄面，427 行）、
`ParticleDismissReleaseField.kt`（预解算释放场，316 行）、薄面轨迹纹理数组与
释放场纹理、`DISMISS_REPLICAS` 由 5 降为 1、`ARC_BOW` 与 `SWEEP_TIME`
常量、静止层的软孔与渐隐。`SWIRL`/`FLOW_EVOLVE`/`PINCH`/`KICK`/
`TURBULENCE_CELLS`/`LIFETIME` 仍由凝聚（出现）动画使用，本轮不动。

**`ARC_BOW` 的依据作废**：该常量注释所称的"按华为截图要求"的弓形，在本轮
逐帧测量中不成立，随常量一并删除。

**布褶重叠假设否决**：用户提出浓带是"被风吹起的布局部重叠、上下两层都粒子化"。
三项检验均否定——覆盖率上限（最新鲜带已达 0.808，两层重叠最多再贡献 1.18×，
产生不了 12×）、静止表面位移 < 0.12 px（折叠需要位移）、以及把年龄回归掉后
残差各向同性（各向异性 1.00–1.33，折叠残差必然沿褶线拉长）。浓带的连贯曲线
形状来自释放场本身的低频团块，浓淡来自"刚释放的格子还一个没死"。

即消失；噪声跟着薄片被搬走、拉伸，洞与残条自然沿风向拉长，不另做方向性。噪声 = 粗斑块
（手指大小的洞与残条）+ 细颗粒（两到四像素一粒，最后的尘）。消失边缘一到两像素硬切，不做
雾状渐隐（雾状即"蓬松"）。释放前的侵蚀暗区沿用同一张噪声：材料在前沿到达前一小段时间里
按噪声成片变暗，然后释放。否决 C（显式条纹会与平流拉伸叠成两套方向）。

## 2026-09-02 打光：法向光照，双面异色（用户选 A）

**决定**：法向从变形后的网格算；一盏方向光从平面上方、偏迎风侧照来，前沿卷起的边正对光即
亮带；内容色保留，受光面朝白提一点，背光面按余弦压暗；背面压暗到约六成并略去饱和度，折脊
两侧一亮一暗。亮度里除法向外没有任何随时间变的项。否决 B（单面，白底上褶皱几乎不可见）。

## 2026-09-02 只有一条前沿；尘粒子层接入（用户指出中间破碎与放大镜后）

**决定**：
1. 顺风角不再另起一片。那块孤岛的前沿向内推、材料却向外飞，网格被拉成 1.5-1.7 倍
   （用户："像个放大镜"），而且它在完整内容中间出洞（用户："不希望控件内容中间突然破碎"）。
   破碎只能发生在前沿那条边上。
2. 溶解噪声改由 CPU 生成一张纹理（粗斑块拉开到 0-1 + 细颗粒），薄片着色器与尘的发射共用，
   两者的时序一致。
3. 尘粒子层：格子中心的噪声一过阈值，这格就发出 3 个点粒子（格内随机位置、格子颜色朝白提
   35%、当地流场速度 + 很小的随机速度 sd 25 px/单位时间），寿命 0.20±30%，粒径 2.6 px，
   alpha 随年龄淡出，在薄片之后画、不参与深度。用户明确"还是得做粒子化，现在是 0 粒子"。

## 2026-09-02 位移改为真正的卷起（圆柱卷），粒子化从卷的自由端开始（用户提议）

**决定**：不再用流场平流薄片。前沿是折痕，折痕后面距离 u 的材料绕一根轴在折痕上、半径 R
的圆柱卷起：位置 = m + (u − R sin θ)·e + R(1 − cos θ)·z，θ = u/R，e 为折痕推进方向。弧长
等于材料长度，不拉伸，不放大（用户："像个放大镜"的根源是孤岛被拉长）。卷过约 110° 之后
（LIFE_START）才从卷的自由端开始溶解成尘（LIFE）。左上角同样一个卷：折痕垂直于对角线、
从角尖向内推进，角尖处的材料先卷；两个卷交界处的三角形不画。位置是时间的函数，不再逐帧
积分（尘仍然积分）。

**为什么**：用户 2026-09-02："你现在这个效果就像是卷起，但又不是真的卷起……不如就设计为控件
边缘被卷起来，粒子化都是从边缘开始……左上角也仍然可以被卷起，只是不要把控件内容放太大。"
流场平流出来的抬起没有几何上的卷，顶视看只是一条发亮的边。

**常量**：CURL_RADIUS 90、CORNER_RADIUS 70、CORNER_START_T 0.26、CORNER_SPEED 520、
FRONT_SWEEP 0.60、LIFE_START 0.16、LIFE 0.32、Z_CAMERA 3500（透视约 5%）。

## 2026-09-02 卷改浅、封顶角度、关掉左上角的卷（用户：卷得太厉害、末期冒出残片）

**决定**：卷曲半径 90 → 170，卷到 1.1 弧度（约 63°）就不再往上卷，材料停在卷的自由端等着
碎（LIFE_START 0.15、LIFE 0.28）。左上角不再另起一个卷（CORNER_START_T 设 9.0 关闭）。

**为什么**：半径 90 的整卷翻过顶之后，没碎完的材料按圆柱公式继续沿风向飞出四百多像素，在
0.70 前后从别处冒出一块（用户截图红框）；两个卷交汇处留下尖角。用户要"跟华为接近、柔和一点"，
华为的边只是轻轻翘起，不是紧卷。封顶之后卷的自由端跟着折痕走，不会飞离。

## 2026-09-02 翻折：圆弧之后是一块倾斜的平板；左上角从一开始就翻；光从顺风侧照

继续伸出去（弧长守恒）。此前把超出封顶角度的材料按常量平移，那是一块平放在半空里、正对

自由端就是最早那条卡片边（或已碎掉的末端），尘从那里出来。左上角同样一块翻板，从 0.04 起

## 2026-09-02 翻起到约 46° 就脱离、沿风向飞走并碎成尘；去掉白晕与折痕线（用户四条意见）

平板顶视像整个控件翻了个面。
