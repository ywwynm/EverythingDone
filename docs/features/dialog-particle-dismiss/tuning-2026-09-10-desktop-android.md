### 2026-09-10 方法边界澄清

用户追问钢铁侠参数是否为单独拟合及过拟合。核对当前代码：钢铁侠 `profile.json` 包含 18 个传播参数与 36 个空间残差系数，并有左上特定归一化区域额外延迟 55 ms 的视觉标定；运动还使用该序列独立的 `flow-profile.json`。这些参数并非仅由输入控件几何、材质和触点自动推导。

照片序列各自拟合，自有弹窗及 Android 使用通用释放场和综合流场。已有同段视频其他时刻的检查，以及不同场景分别运行的模型性质检查，不能证明同一套参数对未参与拟合的素材仍然贴近华为。当前存在针对参考画面过度适配的风险，尚未通过跨素材验证量化。此前“移植完成”仅准确描述引擎与通用配置的接入，不能解读为钢铁侠专用形态已经泛化到任意 dialog；这一点此前解释不充分。

桌面验收区分视觉判断与自动检查：重点检查灭霸末段紫色卷束、科比中段聚散、自有白底弹窗连续交接；保留钢铁侠已获认可的改善，不能恢复粒群反弹。当前起点 r31 仍有可见差距，不预先宣布达标。

## r33 桌面候选

- r32 完整比较后未采用：较强面积增量使钢铁侠变重；灭霸收束场过早过强，末段留下过长细束。r32 已归档供审计。
- r33 将照片初段线性尺寸增量降到 8%，白底仅 3%；随机分散接近 r31，保留白色微面明暗。灭霸应变区缩窄并延后，科比只在中后段有限收束；共用综合流场随之更新。
- 低通颜色分布误差（与 r31 对比）：钢铁侠 2.985→3.101，灭霸 2.978→3.084，科比 4.005→4.016。这里的变化不证明数值更贴合；选择依据是卷束结构与运动质感改善，保留这种取舍，不宣称所有指标都提高。
- 七场景模型性质、30 个方向端点与 70 组实际顶点中心轨迹检查均通过。白底粗尺度边界与 r31 接近，添加附件末段稍柔和；细颗粒指标有升有降。后续实机需要重点判断像素密度差异对细粒观感的影响。

## 桌面判断与移植基准

本轮选择 r33 作为移植基准。选择理由是整体释放节奏与方向保持稳定，白底交接没有恢复清晰硬边，卷束处理有节制，未观察到需要再次重做模型的整体运动问题。华为与候选在局部粒群密度和曲率上仍有细节差异，尤其灭霸细束和科比中段；经过强度、寿命、流场带宽和局部应变候选比较，继续增强会牺牲轻盈程度或已认可场景。此为本轮自主视觉判断，不把误差数字包装为相似度百分比。

Android 移植采用同一固定步长速度积分、释放场、微片几何及材质，直接携带综合引导场。保留原出现动画，增加实际 GLES 渲染与桌面数据对照；旧解析薄片消失路径不再作为主实现。

## Android 实际验证进展

- 首次编译通过后，GLES 语法检查发现桌面允许的 `uint >= int` 比较在 ES 中非法，已显式转换。正式资源加入语法编译测试，八方向释放场通过桌面冻结输入比较。
- 两台设备已安装本轮调试 APK，七场景固定输入均在实际 GLES 3.2 跑完。0.567 秒可见材料中心相对桌面的最大误差低于 0.13 个逻辑像素；两台结果接近。像素级误差还包含不同 GPU 的哈希细分与栅格覆盖，不能用中心误差代替视觉验收。
- 首次性能检查暴露两个实际问题：大颜色弹窗无效绘制较多；TextureView 的交换不总是限制提交频率，小弹窗出现一秒提交 1500 余帧。已增加不可见绘制裁剪、静态分支和刷新率限速，正在重新测量。
- 真实横屏测试提醒逻辑粒径应以视口短边归一化，避免旋转后材料突然变粗；已修正坐标归一化。两台原有语言设置分别是 English 与跟随系统，测试通过取消退出，不修改语言。
- 两台设备原先均跟随系统深色模式。为验证真实白底，暂时在应用设置关闭跟随系统，强制深色原值为关闭；完成后须恢复跟随系统。三星深／浅色语言弹窗已保存完整录屏，OPD2515 的系统 `screenrecord` 写入测试路径被拒绝，标准输出方式也没有产生帧，不能把离屏输出冒充系统录屏。
- 首批裁剪前后固定像素比较未出现可见模型改变，OPD2515 颜色场景离屏 P90 由约 24 ms 降到 11 ms，三星由约 29 ms 降到 20 ms。真实语言弹窗已限制为一秒 121 次提交，准备耗时在本次暖运行中分别约 124／266 ms，继续定位更大场景的准备耗时。

## 实机细化与回归

- 后续白底颜色弹窗检查将逻辑坐标最终改为基于屏幕密度（`density / 1.875`），取代前述短边归一化；单粒约 1.25 dp，大弹窗上限 160000 个材料。这样横屏窄弹窗不会因为视口宽度变大而明显变粗。
- 最终消失渲染上限为每秒 60 次提交，物理积分仍为 240 Hz。两台真实大颜色弹窗在一次记录中均提交 61 帧，提交间隔 P90 约 17.5–17.8 ms；这是渲染线程记录，不能等同于显示帧率。消失过程约 1 秒。
- 真实语言、颜色、添加附件弹窗已检查。颜色控件的圆形色块和文字来自实际 PixelCopy 截图，不会变为方形块。三星已保存系统录屏；OPD2515 保存实际关闭阶段截图，并单独记录截图时间范围，不冒充连续录屏。
- 修正背景暗层和降级淡出的系统倍率重复相乘：ViewPropertyAnimator 只接收逻辑时长，GL 路径自行应用一次倍率。待完成 0／0.5／2 倍实机复核。
- 进一步将位图上传改为一次读 ARGB 像素、批量重排并上传 RGBA，减少大弹窗的逐像素 JNI 写入；正在重跑固定材料 GPU 比较。
- 八方向测试最初在弹窗外 40 px 触摸未关闭。实际 window frame 与 UI 树一致；检查发现该距离仍处于高密度设备的 windowTouchSlop 容差内。测试改为 128 px，保持产品取消规则不变，随后重跑。
- 双设备八方向均通过，角度误差最大 0.059°。每台连续 10 次打开后立即返回：OPD2515 在打开约 78–103 ms 时返回，三星约 115–145 ms，覆盖出现动画尚未结束的情况。窗口均移除，最终宿主视图层级无粒子层或无 ID 的全屏暗层。
- 位图批量上传优化前后，两台设备共 84 张固定输入图逐像素一致；七场景终帧 alpha 均为零。最终固定材料 GPU 对照仍为可见中心最大误差小于 0.13 个逻辑像素。
- 两台均完成颜色编辑器输入法弹出后点击取消的检查，键盘正常隐藏，原有颜色未改变。三星系统动画倍率 2／0.5／0／1 检查通过，GL 过程实测约 2001／501／无 GL 路径／1001 ms，结束后无粒子层和暗层；系统倍率已恢复原值 1.0。
- `:app:testDebugUnitTest --tests '*Particle*' :app:assembleDebug` 最终复跑通过。正在归档、恢复应用跟随系统深色设置并准备默认调试更新发布。
