# 恢复弧边分支与可辨认的近远变化

## 本轮反馈与对照

用户新截图指出，初版钢铁侠左中部的一条曲线随后呈现横向黄线弧边和下方红线拖尾两条轮廓，当前实现没有保留该观感；近、中、远仍看不出区别。不能把统计量变化当作完成，也不能重新采用所有粒子向一点收束。

已冻结修改前八个主素材帧、桌面代码和共享资源于 `tuning-0909-gpt6/archive/before-curve-split/`。当前问题在固定种子 909602、122°、0.31／0.43／0.55／0.65 的对照中可重复；原片、认可控制组和当前实现均使用相同时间口径。

依次检验三个假设：附加顺风速度破坏卷动、全场速度下限消除聚散、随机坐标及释放变换改变参与卷边的源材料。前两项单独／联合减弱均未恢复分支；固定坐标和时序变换时，横向弧边与下方拖尾显著恢复。当前固定输入有约 0.185／−0.128 短边尺度的坐标偏移，局部释放偏移可达 0.05 秒；无限场中的形态变换并不保证有限矩形内仍保留同一批供料区域。

因此先调节共同随机规则中的变化幅度，让连贯卷边具有接近原始形态的样本，局部起点独立程度高的样本继续保留较大的变化。不改变人物专属参数，不绘制亮曲线代替粒子运动。

## 距离设计

旧距离增益在绝对距离上较早饱和。钢铁侠屏幕内的可用背景窄，近远仅相差少量像素；附件的中远又都落入饱和区。这使同屏比较的差异小于数值报告给人的印象。

正在验证按实际可触摸背景范围表达触点远近：沿中心到触点的射线，计算控件边缘到屏幕可用边缘的距离，再将真实触点位置映射到有界速度变化。它是交互尺度选择，不是从华为视频唯一推导出的物理定律。粒子保持连续流动，不聚集或停止在终点。原始距离仍保留供方向偏转计算。

[SideFX 的粒子体积输运说明](https://www.sidefx.com/docs/houdini/nodes/dop/popadvectbyvolumes.html)区分位置、速度和力的更新，提醒不要重复叠加位移；本轮继续在同一积分路径内调整目标速度。该文档是方法参考，形态是否改善以固定素材的连续画面判断。

## 已进入实现的调整

共同坐标、弯曲、释放偏移的随机幅度由同一次关闭的局部起点独立程度连续调节，变化系数为 0.08～1；镜像仍独立保留。初版钢铁侠示例因此恢复横向弧边与下方拖尾，但粒子明暗和时刻尚不等同参考。共同速度场、释放底表和置信度场均未更换。诊断脚本改为显式读取本轮前的归档，以免重复对已经收敛的随机幅度再作缩放。

距离速度增益为 0.72～1.28，默认方向关闭取中间值 1。真实触点在该方向可触摸背景中的相对位置决定增益，原始像素距离仍用于温和偏向；不会随粒子当前位置吸向触点，也不截断粒子位置。三素材、两个方向的可见运动中，远／近中位速度比约 1.47～1.65，中位位移比约 1.47～1.66。已检查同屏画面中前沿位置和流束展开程度的差异，接下来核对完整播放及两端一致性。

Android 已同步随机幅度和距离映射；窗口可见区域只用于解释用户触点，不作为粒子运动边界。新增缩放、窄背景、宽背景及斜向触点测试，本轮 13 项 JVM 测试通过。9018f404 开始独立渲染验证；R5CW20BLNKL 再次检查仍未授权 USB 调试。
