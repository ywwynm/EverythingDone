## 粒子动画在华为等 Mali 设备上恢复；新建记事的出现动画不再时快时慢

本版修两处，都是在华为 MatePad Pro 13.2（麒麟 9000s / Maleoon 910）上定位并实测验证的。

**一、Mali 系设备上粒子动画完全播不出来。** 弹窗出现与消散、记事卡片、新建记事三处入口
全部退化成最简单的淡出。根因是绘制用的顶点着色器声明了三个 SSBO，而 Maleoon 910 的
`GL_MAX_VERTEX_SHADER_STORAGE_BLOCKS` 是 0——这是 GLES 3.1/3.2 规范允许的最小值，不是
驱动缺陷，Mali 系历来报 0，链接因此必然失败。开发用的两台真机都是高通 Adreno（这一项报
24），所以此前一直没暴露。改为按实例读取的顶点属性：绑的是同一批缓冲对象，计算着色器
一侧一字未动，也不依赖任何扩展。该机实测：出现 15.9 万片 33 帧 60fps、消散 30 帧、左滑
手势首帧正常上屏，启动预热不再报错。搭载 Mali 的其他设备（部分联发科、三星机型）此前
应是同样表现，本版一并恢复。

**二、新建记事的粒子动画时快时慢，慢的时候卡一下直接显示详情页。** 创建页的轨迹会在首页
空闲时提前算好，但用于判断"这份预算还能不能用"的指纹里，新建按钮的坐标取自含位移动画的
瞬时读数。按钮会随底部提示条上移，而点击处理的第一步正是关闭提示条，于是预算读到的是
上移后的位置、点击读到的是落回后的位置，两者对不上，整份算好的轨迹被丢弃——只要返回首页
时出现过提示条就必然如此。代价是双份：白算一次 600 毫秒的预算，再在前台重新算一遍，这期间
画面停在首页截图上。改为两侧统一取按钮的布局位置（不含位移），该坐标只用来定粒子的出发
方向，上移与否的方向差不到 4 度，肉眼无从分辨。实测同一节奏下预算命中率由 1/4 升至 4/4，
从点击到首帧由 759~829 毫秒降至 172~228 毫秒；快慢混合 12 轮复测命中 7/7，首帧 170~203 毫秒。

**三、诊断增强（仅 debug 包）。** 启动时记录 GPU 驱动型号与本管线依赖的全部能力上限；
出现动画的 1100 毫秒兜底不再静默返回，会记下未能开播的原因与当时状态；预算判废的日志
连具体数值一起给出，而不是只报变动项的名字。这三处都是本次定位过程中被卡住后补上的。

已知未处理：预算未命中时（冷启动、切换文件夹等）仍会在前台现场计算 570~1150 毫秒，
画面在此期间静止；该机上消散动画约 30fps，出现动画 60fps，尚无同口径的高通机型对照。
本版未在高通设备上回归。
