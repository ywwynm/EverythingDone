# 弹窗粒子动画调试更新

## 弹窗叠弹窗时，粒子不再被下层弹窗盖住

用户报告：详情页打开「改变颜色」面板、再点「从世界取色」，取色弹窗的出现与消散粒子都跑在颜色面板的下面，而实际上应该在上面，因为它是后打开的；相比之下首页 contextual menu 里同一条路径层级是对的。

真机确认了这一点，并查清了原因。粒子表面是挂在 Activity 根视图上的 SurfaceView，置于顶层——它在 Activity 窗口之内最上，但仍在弹窗这种独立窗口之下，这一句本来就写在那个类的注释里。两边的差别正好卡在这里：详情页的改变颜色面板本身就是一个弹窗、是独立窗口，所以压在粒子之上；首页的调整外观则是页内面板而不是窗口，所以粒子在它之上、层级本来就对。

不能简单地把粒子挂进下层弹窗自己的窗口：本项目的弹窗按内容尺寸浮动布局，挂进去会被那个弹窗的矩形裁掉，而粒子本来要飞出卡片一个身位。只有另起一个全屏、且在那些弹窗之后加入的窗口，才同时满足「在上面」和「不裁剪」。本版因此新增一个按需显示的全屏透明承载窗口：不可聚焦、不可触摸、无窗口动画、没有系统暗层，只是一块画布，焦点与点击照旧穿过去；用完空闲即撤，不会一直压在所有弹窗之上。粒子表面的索引也从「一个界面一个」改成「一个承载窗口一个」。

启用判据只有一条：这个弹窗下面还压着另一个会留下来的弹窗。正在离场的弹窗不算——一个弹窗关闭紧接着另一个打开是最常见的连续操作，现有设计把并发的动画合成进同一张表面、交接靠同一份帧时间戳，把后一个抬到另一个窗口就成了跨窗口交接，那是本项目记录在案的必闪路径。

实现期间遇到一处边界并已解决：承载窗口显示之后，它的根视图要等下一次布局遍历才附着，而消散是同步判定的，第一版因此直接得到「宿主未附着」、整场不播。现在两条一起兜——叠加状态还在的时候不撤窗口，以及承载窗口尚未附着时退回原来的表面，层级仍是旧的但绝不会因此不播。承载窗口也会在界面销毁时一并收掉。

逐场景在 OPPO 平板上确认了闸门的启用与否，用一行调试日志逐条核对。启用的只有叠加那一种：详情页颜色面板之上的取色弹窗，出现 35 帧、消散 62 帧，粒子都盖在面板之上。其余全部维持原路径，帧数与改动前一致：单个弹窗开关 34 与 62 帧；一个弹窗关闭紧接着另一个打开 34 与 62 帧，实测前一个弹窗在消散期间仍然吞触摸、从操作栏根本点不开后一个；FableSol 调参弹窗（自带独立表面）开关 34 与 62 帧；新建记事入场 35 帧，连闸门都不经过；首页调整外观面板开关 34 与 62 帧；左滑完成记事正常完成。也就是说，除了弹窗叠弹窗这一种，其余路径一条都没有进入新代码。

共同粒子模型、着色器、时长、密度与任何已认可的视觉参数均未改动。构建通过，本地检查 1036 项，唯一失败是既有的 FableSol 曲线那一项。

请重点复看三处未在设备上单独复现的：其一，提醒或习惯记事的详情页里点开始做事，弹出的选择做事时长是本项目第二处弹窗叠弹窗，走同一个入口与同一个闸门；其二，首页调整外观面板里的从世界取色，那个面板是页内视图、闸门必然不启用，层级本来就对，但请确认没有变坏；其三，本轮只在 OPPO 平板上验过，三星那台未连接，窗口层级在不同系统上的行为本项目踩过坑，麻烦也过一遍。另外请确认承载窗口没有挡住任何点击——它设成了不可触摸，但这一点值得实际点几下。

测试记事已移入可恢复的回收站，平板首页恢复为原有的两个文件夹十五条记事，三项动画档位与开始时一致，设备上的临时文件已清理，用户现有记事一条没动。本轮未提交 Git。
