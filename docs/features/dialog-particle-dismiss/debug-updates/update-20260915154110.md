# 弹窗粒子动画调试更新

## 修复由新 Activity 承载的弹窗背景不变暗

用户报告开始做事（选择做事时长）与更突出的记事通知这两类弹窗出现时背景完全不变暗，开始做事的两条入口（详情页右下角按钮、首页右滑记事卡片）都复现，并推测与"这类弹窗会新建一个 Activity"有关。排查确认推测成立，且不止这两处：开始做事、更突出的通知、延迟提醒、私密内容认证、列表小组件配置共五处入口都由透明 Activity 承载，并在宿主首帧之前的 onCreate / onPostCreate 里就提交弹窗。提醒与习惯的开始做事走详情页内的 ThingDoingDialogFragment，宿主已经在屏上，因此不受影响——这就是"只有部分弹窗不变暗"的分界。

根因在第一批性能改动。背景暗层全程由应用接管（主题已禁用系统 dim），此前挂宿主 DecorView 用的是 addView 加 MATCH_PARENT；为省掉整窗重新布局改挂 ViewGroupOverlay 之后，overlay 的内容不再参加宿主的测量布局，尺寸必须自己给，而 ParticleOverlayHost 只在挂上去的那一刻算了一次。这几处宿主附着发生在 ViewRootImpl 第一次布局之前，此刻 DecorView 宽高仍是 0，暗层于是以 0×0 留在 overlay 里，之后再没有任何人给它布局，整个弹窗期间一个像素都画不出来。

本版三处修正。ParticleOverlayHost 在挂载之后注册宿主布局监听，宿主每次改变布局都按最新尺寸重新测量并布局这一层，同时修好同源的第二种失效——宿主挂载之后改变尺寸（旋转、分屏、insets 变化）时 overlay 里的层不跟；监听器只弱引用层本身，层撤下或被回收后自己摘掉。粒子叠加层、滑动关闭的锚点层与暗层共用这条挂载路径，三者一并覆盖。DialogDimLayer 的淡入改挂 doOnLayout：宿主首帧前这一层既没有尺寸、也从未进入绘制树，此刻启动的 RenderThread 动画会立刻结束；宿主已经布局过时当场执行，与改动前逐帧一致。BaseDialogFragment 在延迟挂上暗层之后按当前状态补一次浓度，堵上同一症状的第三条路径——出现动画若在暗层挂上之前就结束，进度回调会全部落在空引用上，暗层同样停在全透明。

本轮没有改动共同粒子模型、着色器、时长、密度与任何已认可的视觉参数，只改挂载层的尺寸与暗层的起步时机。新增 DialogDimCoverageTest 三项，逐项确认在修正前的源码上都会失败，是真回归而非恒等式。全量单测 1023 项，唯一失败是既有的 FableSolCurveFairnessTest，与本轮无关。

本版没有上真机验证，实际观感待确认：模块只有 JUnit、没有 Robolectric，View 行为无法在本地驱动，因此三项契约定在源码上。请重点复看五处入口的背景是否随粒子出现一同变暗、关闭时暗层是否与消散同步淡出，以及旋转后暗层是否仍然铺满。本轮未提交 Git。
