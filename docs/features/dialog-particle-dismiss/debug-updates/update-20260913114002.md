## 加快弹窗出现，并修复动画与最终面板的高度差

用户要求出现动画播放更快、开始更及时，同时指出更新应用／更新日志弹窗在动画期间和结束后的高度不同，并要求修复其它同类弹窗。

出现动画由一秒缩短为 0.6 秒，继续从下方随机位置进入，完整倒放已认可的共同消散轨迹。ParticleReversePlan 按实际播放时长和刷新率保存状态，通常由 60 个间隔改为 36 个；history.comp 只保存绘制需要的位置 xyz 与速度 xy，全部保留 float32 精度。原始 240 Hz 积分、100 次压力迭代和粒子数量不变，历史缓存约减少六成。准备等待进一步小幅缩短，仍不是零延迟；普通弹窗的本地轨迹准备请求到首帧约 0.21–0.31 秒，布局和捕获另需少量时间。

通过实际 DebugUpdateDialogFragment 注入固定长短日志复现高度差：长日志曾从快照的 1557 像素变为最终 1105 像素，窗口居中位置也随之变化。原因是首次布局后还会调整滚动区域最大高度、分隔线和间距；不是用户滚动导致。ParticleDismissController 现在同时检查可见子树与窗口根节点的待处理布局，完成后才捕获最终快照和屏幕位置。该共用修复覆盖更新日志、颜色信息及其它二次调整尺寸的弹窗，并继续等待渐变配色初始化完成。

22 项粒子相关 JVM 检查和实际 GLSL 编译通过。两台指定设备上，钢铁侠、添加附件、调整颜色的 37 个对应采样，以及系统慢放使用的 61 个采样，共 344 帧正反渲染的 RGBA 散列完全一致。两台设备的更新日志、长文本、颜色信息、选择框、确认框共 24 组真实出现检查，输入与最终面板尺寸、位置一致，整图像素差为零，播放稳定在约 0.6 秒。
