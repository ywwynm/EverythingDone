# 恢复真实内容色粒子强调

修复第四十二轮多起点帷幔消失模型中，彩色内容被 Dialog 本体色粒子淹没的问题。

## 问题与原因

- 新消失 Shader 虽逐位保留快照颜色，但把此前已经确认的“高饱和内容色专属副本”与
  白色浓带副本一并删除，导致粒子颜色在数学上正确、视觉上却仍以白灰色为主。
- canonical Shader 原始离屏统计：测试快照高饱和 alpha 占 14.79%，旧实现的粒子阶段
  只占 19.71%，强调倍率仅 1.33×。
- 单变量验证排除早期提亮和视频编码；恢复尺寸/寿命只能达到 1.40×，恢复彩色专属
  副本则达到 2.76×，确认副本机制是主要缺失项。

## 修复

- 消失动画恢复每格最多 3 个粒子，但两个副本只对高饱和内容色生效；白色面板和黑字
  始终只有一个主粒子，不重新堆亮整条白色锋线。
- 彩色副本与主粒子共享局部激活场、帷幔 ID、主方向和前段运动，仅沿切向错开不到一个
  采样格，中后段才随独立 hash 轻微分离，不破坏片层相干。
- 恢复内容色的尺寸与长尾概率权重，使彩色控件、图标和标题在白色面板先退后继续形成
  清楚的彩色尾流；粒子 RGB 仍直接继承快照，不统一染色。

## 验证

- 新增 `check_color_emphasis.py`，直接编译 Android canonical Shader，以 4 个随机种子 ×
  4 个时间点检查高饱和 alpha；要求强调倍率 ≥2.0×，修复前 1.33× 失败，修复后
  2.82× 通过。
- 重新生成单次、12 随机种子和上、下、左、右上四方向 60fps 视频，颜色增强未改变
  多起点分布、方向跟随和未触及区域完整性。
- `:app:compileDebugKotlin` 与 `:app:testDebugUnitTest` 通过；未使用 ADB。
