# 弹窗从下方出现并缩短准备等待

用户要求出现来源固定在下方范围内，同时继续减少准备延迟。本版每次在下方 90° 扇区内选择来源，涵盖左下、正下与右下；继续完整倒放当前共同消散模型，保留一秒时长、随机种子、粒子数、卷曲和材质。

定位到逆向预计算的压力求解在大量没有颗粒的网格上执行了全部迭代。现在通过 GPU 非空块队列执行相同的 100 次压力迭代，并跳过已超过可见寿命颗粒的无效积分；正常消散的共享资源与调度保持原样。尝试合并积分步骤时未通过严格像素校验，已撤回，避免为加速改变画面。

共同资源与着色器改为在应用首个界面绘制后异步预热；出现程序的编译与本次材料准备重叠，历史缓存复用预编译程序。不预缓存用户画面，不使用固定种子，不通过降低粒子数或先播放其它动画掩盖等待。

本地验证：21 项粒子相关 JVM 检查通过，包括全部实际 GLSL 编译。两台指定设备上，钢铁侠、添加附件、调整颜色与三个下方方向的 366 个对应帧，逆向画面与同一模型正向画面逐像素相等。十二组真实 Chooser / Alert、纯色及正反渐变完整播放，下方随机方向正确，动画输入与最终面板的整图像素差为零。已导出三个素材各 1 倍速、0.5 倍速预览。

同口径的真实弹窗渲染请求到首帧，当前 9018f404 约 210–248 ms，R5CW20BLNKL 约 294–323 ms；上一版分别约 454–593 ms、673–850 ms。布局与最终配色捕获另约 47–72 ms，仍不能称为零等待；大尺寸弹窗或资源尚未预热时可能更慢。完整一秒轨迹的临时 GPU 缓存仍在动画结束或取消时释放。
