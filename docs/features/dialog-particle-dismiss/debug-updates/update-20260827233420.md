## Dialog 粒子消散：真机密度一致性、统一颜色运动与逐帧边缘修正

### 用户反馈

用户在 Android 真机上确认上一版帷幔密度远高于桌面模拟器；彩色控件粒子再次呈现像是
独立运动的观感；归一化约 0.47 时还出现一条从左下到右上的突兀斜带，右上端尖锐越过
Dialog 上边界，而左上起始粒群不够清楚。用户要求按参考视频逐帧检查四条边缘，而不是
继续只看全局密度指标。

### 根因与修正

- 桌面 ModernGL core context 未启用 `GL_PROGRAM_POINT_SIZE`，导致 canonical Shader 写入的
  `gl_PointSize` 被退化为约 1px；Android GLES 使用真实动态点径，所以此前在桌面上调出的
  4.2×/4.5× 密度目标会在真机叠成白色实带。`render_curtain_model.py` 现显式启用
  `moderngl.PROGRAM_POINT_SIZE`，并新增 2.4/3.6 density 的等效栅格回归。
- 旧 `contentWeight` 同时使用面板色差与饱和度，灰色文字、阴影和暗色区域也可能被误判；
  同时普通尾流只保留不到 1%，彩色区域最高接近满保留，数量差会形成独立矩形色块。现改为
  只识别真实饱和色；中性色尾流保留 10%–18%，彩色最多额外增加 18%，所有颜色继续共享
  完全相同的激活、运动、寿命、点径、透明度、光照、深度和淡出公式。
- 删除会把不同局部年龄压到同一曲线的 `ribbonCompressionDrift`；高密窗口改为较宽的局部
  粒云，降低点径与单点 alpha，并重新配平后/主/前三层。帷幔仍由更高真实 cell 占用率
  形成，但单粒子保持可辨，不再连接成白色片面。
- 宏观方向延迟由约 110ms 降到约 50ms，让五个局部种子与空间噪声主导边缘形态，避免
  多条锋线被串成贯穿 Dialog 的单一对角等时脊线；左上顺向侧短起点扩大，早期即可看到
  向左上移动的粒群。
- 下边缘侧流和扇面剪切更早停止累积，随后短暂强化本次触点主方向的纵向分量，再交回
  非线性主风。该规则不读取颜色；主方向向下时仍向下、水平时仍水平，不会硬编码最终向上。

### 回归结果

- 桌面默认 2.4 density 与高密度 Android 等效 3.6 density 的平均 alpha、强像素占比、
  局部密度相对差均低于 3%。全灰压力图的彩色误判率为 0。
- 帷幔/尾流真实占地密度为 2.74×；彩色 cell 数量表示为 2.07×、颜色 alpha 表示为
  1.58×。`contentWeight` 的静态契约保证它只进入两个占用率公式和诊断 varying。
- t=0.47 的纯粒子高密连通区平均厚度为 4.67px，参考为 6.15px；模型右侧越界 P95 为
  0.0058 个 Dialog 宽，参考为 0.0065。t=0.32 左上粒群、t=0.47 顶部外移和端点形态均
  已加入逐帧自动回归。
- 法向密度峰位于完整表面外约 22px；峰值带相对贴边粒雾为 8.09×、相对峰外尾流为
  2.51×，且与未粒子化表面的质量重叠低于 0.001%。0.70 时完整表面已清空。
- 固定同一批下边缘 cell 后，left/up 从 0.46–0.62 的 1.05 降为 0.62–0.78 的 0.68，
  接近参考的 0.83→0.62；全局粒子光流中段/早段为 7.30×，保持明显先慢后快。
- Python canonical 回归、逐帧边缘回归、`:app:testDebugUnitTest` 和 `:app:assembleDebug` 均
  通过；`ParticleDismissShaderCompileTest` 未跳过，四种展开后的 GLES 3.00 Shader 全部
  真实编译成功。
- 未使用 ADB，也未自动安装到任何设备；发布后请手动安装并连续播放确认真实屏幕观感。
