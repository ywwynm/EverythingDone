# 修正弹窗粒子消散中的内部孤立细缕

此前扩大粒子剥离响应的随机范围后，用户在真机上仍几乎每次都能看到一条或几条突兀的内部细缕。本次重新配准新录像第 37～38 帧，定位用户圈出的两条细线，并在多素材、多方向和多种子下拆分原表面、运动层、流场及明暗因素。

根因是共同剥离力在某些区域造成过度汇聚：一条宽材料带被压向同一条窄曲线。现在根据剥离场的局部空间导数估计压缩程度，并在共同计算着色器中连续减轻强压缩；弱汇聚尽量沿用原运动，保留正常卷边与主流场。没有通过删粒子、缩短寿命、降低透明度或图片专用遮罩来隐藏问题。

桌面 `unified_model.py` 和 Android `ParticleMicroflakeModel.kt` 独立生成压缩输入，交由相同的 `step.comp` 计算。调试验证增加模型身份、压缩数组、释放后 0.30 秒的实际 GPU 状态，并固定追踪同一组 940 个材料 ID。旧版来源带被压至约 9.56 像素，新版约 26.32 像素；两台设备实际结果与桌面一致。

验证包括 14 项材料与 GLES 单测、18 个素材与 30 个方向、18 个屏幕内近远输入、两台指定设备各 12 组独立材料和真实 GPU 对照，以及真实弹窗的近触点、远触点、返回关闭和动画层清理。返回键保持向左上方消逝。三星另保留三次实际关闭录屏；9018f404 的系统录屏写文件被拒绝，其验证采用实际 GPU 输出和真实关闭检查，没有改设备权限。

已重新导出 194 个本轮视频，包含既有的 1 倍速、0.5 倍速、八方向和近中远，以及新增 12 组完整画面前后对照。审阅页 `peel-compression.html` 提供原录像准确定位图与本次对照。钢铁侠的正常卷边作为保护项：本轮完整动画区原始 RGB 误差小幅下降，低频结构误差约增加 1.53%；本轮主要处理孤立细缕，不宣称达到对华为的像素级一致。
