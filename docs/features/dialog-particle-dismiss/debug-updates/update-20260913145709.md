# 弹窗触摸反馈与音频海浪交接优化

用户反馈添加附件点击录音时，ripple 被截断并停顿，随后才播放两个弹窗的粒子动画；进一步指出这是各类弹窗的共同问题。

本版保留已认可的粒子模型、方向与出现／消失时长。共同入口在真实控件继续完成 ripple 的同时准备不含反馈的快照，随后交给粒子；返回与背景关闭没有反馈时立即准备。确认、取消、中性胶囊、录音／播放／海浪参数的圆形按钮、开始做事和文件夹选择行统一可观测的反馈生命周期，去除强调色背景与旧灰色前景的重复波纹。按钮原有业务仍在点击时执行。

逆向动画准备改为按小批次向 GPU 提交，优先正在呈现的反馈与动画，不改变颗粒数量、解算或轨迹。动画期间临时表达刷新率偏好，重叠动画结束后恢复窗口原策略。音频海浪只在需要 Canvas 回退时创建备用模拟并恢复完整状态；源海浪冻结延续到消散结束，避免销毁前短暂重启。

9018f404 七条实际交接／关闭路径通过，真实窗口撤下时 ripple 均已自然归零；录音交接的源消散最长提交间隔由基线约 166 ms 降到最终该轮 19 ms，出现最长 18 ms、录音关闭最长 27 ms。仍可能受系统合成节奏和复杂界面首次创建影响，不能承诺全部设备固定 60 fps 或零准备时间。

31 项 JVM／GLSL／冻结状态检查通过。三组反馈快照与结束后的真实面板整图相等，三组原有出现配色和尺寸回归通过；GLES 海浪、Canvas 回退、快速关闭、音频播放及捕获期退出通过。钢铁侠、添加附件、调整颜色共 111 个实际 GPU 正反帧相等，包含前台优先调度分支。R5CW20BLNKL 未连接，恢复后补测。本轮未提交 Git。
