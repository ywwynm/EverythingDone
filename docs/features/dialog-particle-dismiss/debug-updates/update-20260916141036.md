## 叠加弹窗抬升：补测两条开始做事路径（20260916141036）

**应用行为与上一版 `202609160402` 完全一致**，`app/src/main` 一行没动。这一版的差异只在调试包：
为了能从应用进程内拉起「更突出的记事通知」，`ParticleDialogRouteProbeActivity` 的 `route=notice`
多认一个可选的 `thingId` 参数（默认行为不变）。发这一版是为了把补测的结论和当前工作区对齐。

补测一，**提醒记事详情页 → 开始做事 → 选择做事时长**，这是全项目第二处弹窗叠弹窗，此前只推理过、
没在设备上跑过。在 OPD2515 上用一条临时提醒实测：出现与消散都是 `elevate=true stack=2`，
出现 35 帧、消散 62 帧；七帧整屏近黑 0.0%/0.3%/0.3%/0.3%/0.3%/0.1%/0.0%，**没有黑屏**。
逐帧看画面：出现时粒子明确盖在开始做事弹窗的白卡之上（「Auto start doing time」几行被粒子覆盖）
并溢出到卡片外的深色背景；消散时 CONFIRM 正在碎开、粒子同样在白卡之上并溢出右缘；收尾后回到
开始做事弹窗，无残留、暗层档位正确。即抬升在这一处同样生效、层级正确。

补测二，**更突出的记事通知 → 开始做事**，结构与上一条不同：通知 Activity 自己就是一个内容弹窗
（单窗口栈），点「开始做事」后它 `finish()`，再由 receiver 起 `StartDoingActivity` 展示选择做事
时长的弹窗，两个 Activity 各自 `stack=1`，按设计都不抬升。已拿到的证据：内容弹窗出现时日志为
`elevate=no stack=1`，闸门判定正确；`dumpsys window` 里该 Activity 的两个窗口分别是
`ty=BASE_APPLICATION fmt=TRANSPARENT`（Activity 自身）与 `ty=APPLICATION fmt=TRANSLUCENT (672xwrap)`
（内容弹窗），**没有多出承载窗口**。缺的是画面：驱动过程中平板被锁回 6 位 PIN 的锁屏，ColorOS
锁屏下 `screencap` 一律返回全黑，后续步骤无法进行，解锁后补跑。

过程中查清三件与应用无关、但会误导排查的设备事实，已写进 `.claude/rules/adb.md`：这台平板的
`USE_FULL_SCREEN_INTENT` 是 `default`（Android 14 起只自动授予通话/闹钟类应用），**真实闹钟到点
时通知正常发出、但全屏 Activity 被拒**，`rejectTime` 正好是响铃时刻；`run-as ... am start` 起不了
非导出 Activity（`am` 把调用包写死成 `com.android.shell`）；以及 `dumpsys activity activities`
对有独立 `taskAffinity` 的 Activity 不输出 `topResumedActivity=`，按它过滤会误判成「Activity 没起来」。
