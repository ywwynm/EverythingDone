# 多起点连贯帷幔消散模型

用户提供 HarmonyOS 7 清空通知屏摄视频，要求重新分析并实现更轻盈、灵动、优雅的 Dialog
粒子消散：从多个局部边缘近同时粒子化，形成高密度弯曲帷幔，再被气流带走。

## 分析与交互约束

- 逐帧复核参考视频最初约 200ms：最早可见粒子化位于画面下方，其他局部缺口在随后约
  6–8 帧（100–130ms）内出现；不是单锋线依次扫过所有内容。
- 消散主方向继续跟随触点：点下方向下、点左方向左；无触点的返回键/代码关闭默认向上。
- 掀起点**主要但不是全部**位于飞行反向一侧：五个受约束种子中三个在上游侧、一个在
  侧边、一个在顺向侧，均在约 100ms 内近同时启动。
- 允许每次对起点位置、帷幔弧度和横摆做受控随机，但不能破坏方向、分布和邻域相干。
- 未被帷幔触及的区域保持完整，不再在动画开始时整卡全局打孔。
- 本轮仅重做消失；出现动画保持既有凝聚模型，不做严格倒放。
- 主体时长约 0.85 秒，少量尾粒子最晚在 1.0 秒内结束，并继续遵循系统动画缩放。

## 实现

- `ParticleDismissRenderer.kt` 将出现和消失拆成独立 Shader 路径；出现动画继续使用旧模型。
- 新消失路径以共享 `curtainActivationField` 生成五个局部弯曲锋线，静止层和粒子层直接
  复用同一段 GLSL，局部擦除与粒子接管逐格对齐。
- 同一帷幔的粒子在前 120–200ms 共享前进、折叠与低频流场，个体横向差异只在中后段
  逐渐加入；移除早期全角度随机、强 `pinch`、`flare` 和触点轴漏斗。
- 取消消散阶段三副本堆亮、普通区域 3%–9% 保留率及被抽稀粒子极短闪现；所有采样格先
  参与局部浓带，再按生命周期形成稀疏尾流。
- `ParticleDismissController.kt` 不再随机旋转消散主方向；变化由受控帷幔参数承担。
- 新增 `render_curtain_model.py`，直接提取 Android canonical Shader 在桌面 OpenGL 3.3
  编译，输出单次 60fps、12 个随机种子矩阵和四种触点方向矩阵。旧 `render_frames.py` /
  `index.html` 标记为历史模型，避免继续误调旧 Shader。

## 验证

- Android Kotlin 编译通过：`:app:compileDebugKotlin`。
- 单元测试通过：`:app:testDebugUnitTest`。
- canonical GLSL 已由 ModernGL 编译并完成 60fps 离屏渲染；12 个种子与上、下、左、右上
  四个方向均保持“多数但非全部在反向侧、多起点近同时、尾流沿主方向”的结构。
- 已生成与参考视频相同时间尺度的并排对照。按仓库规则未连接物理设备或模拟器；真机材质、
  曝光和 GPU 性能仍需安装本调试版后目检。
