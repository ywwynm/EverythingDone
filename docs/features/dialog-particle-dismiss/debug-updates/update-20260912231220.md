# 弹窗粒子动画：缩短关闭操作后的启动等待

## 弹窗关闭后更快开始粒子动画

用户认可当前粒子效果，要求先提交，再解决背景触摸、返回、取消和确认之后存在的可察觉等待。认可的视觉阶段已提交为 `d37b42cb`，本次只加速 Android 准备链。

真机逐段测量发现，原先主要等待来自关闭后才执行的材料计算，四条实际关闭路径的首帧提交平均约 463 毫秒。本次通过本地批量计算、稳定排序和上传缓冲打包加速，并让 GPU 公共准备与后台建材重叠；首个弹窗显示期间预热驱动首次编译。核心修改位于 `ParticleMaterialNative`、`ParticleMicroflakeModel`、`ParticleMicroflakeRenderer`、`ParticleDismissRenderer` 和 `ParticleMicroflakeGpuWarmup`。

共同运动模型、释放规则、随机性、触点响应、粒子数量和播放时长保持原样。保留 Kotlin 计算作为独立参考与本地库加载失败时的回退，不以减少粒子或改变画面换速度。

9018f404 上四条真实路径各两次，首帧提交为 86–110 毫秒，平均约 99 毫秒；首次 TextureView 界面合成为 91–120 毫秒，平均约 107 毫秒。测量从动画控制器接到关闭请求开始，不包含按钮业务回调此前的耗时，也不声称零延迟或每次必定低于 100 毫秒。

40 组尺寸、方向、种子及材质输入的材料和上传缓冲对照通过，最大差值为零。钢铁侠、添加附件和颜色弹窗在同一模型下与 Kotlin 参考路径比较，材料、GPU 状态及 27 个关键帧逐值一致；另外钢铁侠和添加附件共 18 个帧与认可版本已保存输出一致。19 项粒子模型、时间线及着色器 JVM 检查通过，新增本地库四种 ABI 的 ELF 加载段均为 16 KB 对齐。

发布后继续校验远端 APK 身份，并在 9018f404 安装实际发布包复测四条关闭路径。R5CW20BLNKL 当前不在线，不能将历史测试视为本轮完成。完整数据和诊断见本功能的 `startup-latency-2026-09-12.md`。
