## 修复工具栏反复打开掉帧与录音海浪闪烁

用户补充直接打开添加附件较正常，实际触摸工具栏 menu item 则反复掉帧；录音和音频播放关闭仍有单帧闪烁，录音出现结束处偶发巨大三角形。本版按这三条独立路径重新复现，保留已认可的共同粒子模型、数量、材质和轨迹。

通过同一详情页真实工具栏 View 的按下／抬起重放，旧版八轮有多次仅显示 12–15 个不同粒子帧，GL 却提交 35–37 帧。ParticleDismissController 现在登记 Activity 工具栏仍在播放的反馈；ParticleGpuWork 使用有界 GPU 同步队列，让逆向准备避让正在显示的 ripple，同时减少逐批同步等待。ParticlePlaybackClock 保留一个最新待绘制节拍，避免稍微错过一拍后再空等下一拍。

重复实测出现恢复到 35–37 个不同提交帧，P90 间隔约 17–19 ms。逆向准备由约 330 ms 降到约 180 ms，真实触摸抬起到首帧中位时间约 491→436 ms。仍有偶发约 49 ms 出现间隔及 67／71 ms 关闭起步空档，严格联合帧预算未全部通过，不宣称零等待或所有情况下全程 60 fps。

巨大三角形已在首次海浪 framebuffer 中复现，同时检测到 4,704 个未写顶点。FableSolGlRenderer 的延迟数组此前在并行行计算中被竞争初始化；现在由 GL 所属线程统一取得引用，再供工作线程使用。首次冻结也以零步长生成初始水面和应用重力，避免恢复时突然变换水位。六轮 36 张冻结／恢复捕获均无未写顶点和 GL 错误。

录音／音频播放关闭闪烁另有独立窗口原因：原 Dialog 的 Surface 先退出时，下方 Activity 的粒子快照无法覆盖上方窗口的空洞。ParticleSnapshot 在原根 View 同时保留合成图，两个窗口提交后才撤下原窗口。实际移除 Surface 的有／无保护像素回归中，有保护时超过 2/255 的像素差为零，无保护时约 98% 区域改变；实际关闭及快速关闭清理另行验证。

26 项 JVM 检查通过；最终两轮各录音、取消、返回交接通过，录音出现 35／36 帧，关闭 59／60 帧，反馈尾段间隔 9 ms，末帧、暗层与资源释放均匹配。只测试已授权的 9018f404；R5CW20BLNKL 未连接。没有开始真实录音、修改记事或提交 Git。发布包身份及安装后回归结果记录在功能诊断文档中。
