# 弹窗粒子动画调试更新

## 并行播放触摸反馈与弹窗出现，改善真实关闭流畅度

用户要求出现粒子和触摸 ripple 同时播放，并继续优化通过返回键、触摸外部、取消、确认等实际操作触发的消失卡顿。本版取消新窗口出现的反馈播放门槛，准备完成即可出现；源反馈继续自然结束。撤下原反馈窗口时仍保留正确交接，避免把未结束的 ripple 截断或冻结进粒子。

系统跟踪定位到源 Dialog 和 Activity 在焦点转移时才发生 120→60 Hz 模式切换，与 55–82 ms 长间隔重合。ParticleWindowFrameRate 和 ParticleDismissController 现在从准备阶段共同持有源及承载窗口请求，结束后按引用计数恢复。ParticleDismissRenderer 在有／无反馈的全部正逆路径均限制 GPU 在途准备队列；没有缩减粒子数量、模型、积分、材质、随机性或播放时长。

ParticleDismissOverlay 改在 OnPreDraw 登记提交回调，修正此前在 TextureView.updated 中登记晚一帧的问题；保留有效首末帧、暗层同步与独立 Surface 保护。DialogDimLayer 的纯黑背景直接应用透明度，省去不必要的全屏离屏合成。

9018f404 的六轮真实工具栏／返回、各三轮外部触摸／取消／确认通过严格帧预算。普通出现为 36–38 个不同纹理帧，关闭 59–62 帧，关闭最长间隔约 34 ms 内；实际触摸抬起至首帧回调由约 450–459 ms 降到 306–364 ms，和 ripple 尾段重叠约 31–99 ms。三轮真实附件→录音→返回的 12 个动画也满足预算，录音出现均 38 帧，完整交接最长间隔约 36 ms。

仍有首次选择框约 56 ms 的出现间隔和一个约 43 ms 的确认反馈间隔；首次录音窗口触摸到首帧约 699 ms，后续约 437–466 ms。首次创建与完整逆算仍需准备，不能宣称零等待或全部场景不掉帧。统计来自窗口纹理提交回调，刷新率原因有系统跟踪支持，并非外部高速摄影测量。

录音、音频播放独立 Surface 交接像素检查及出现中快速关闭通过，7 项 JVM 检查通过，完成的回归没有残留刷新率请求。R5CW20BLNKL 未连接；未实际录音或修改记事。共同视觉模型保持不变。本轮未提交 Git。发布包身份、安装后复测和失败实验记录在功能诊断文档中。
