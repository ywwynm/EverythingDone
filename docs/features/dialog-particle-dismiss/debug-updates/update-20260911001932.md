## 弹窗粒子持续流动与启动准备优化

修复弹窗消失时两类可见问题：粒子被停在原控件边缘、角落或后段曲线附近，形成固定轮廓后淡出；部分区域的材料释放后几乎没有运动距离。

此前只对低速区域补很小的速度，实际画面改善不足，已经放弃该方案。本次延续共同运动场中缺少有效运动观测的区域，使粒子经过这些位置后继续流动；平滑延拓接缝，不把控件轮廓、观测范围或屏幕边缘作为碰撞边界。保留原有主要卷曲聚散、内容色配额、随机起始位置与释放顺序，返回键仍固定向左上消散，触点关闭仍由实际触点决定方向。

Android 与桌面共用相同模型资源。后台材料准备与叠加层布局、图形初始化重叠，缓存不变的模型资源；优化每次随机时钟的重复求逆计算。没有缩短整段动画或提前消耗首帧等待期间的动画时间。撤回实测收益不稳定的嵌套法线并行计算。启动改善幅度有限，继续保留分阶段耗时。

重新分析全部 226 组已有标注和 7 个画廊实际输入，仅推进 GPU 状态；另有四个未参与本轮调参的输入回归。检查九个重点输入的前后慢放，原标注视频没有重渲染。正式 110 个视频已按原有双速度、八方向同屏和随机种子设置导出并校验。

两台指定设备分别完成钢铁侠、调整颜色、添加附件三个素材的独立建材和实际 GPU 跨端对照；各连续三次真实返回关闭完成，随机实例独立，动画约一秒。15 个相关自动化测试通过。此次为调试版，发布后继续校验远端文件与安装后的真实关闭和残留清理。
