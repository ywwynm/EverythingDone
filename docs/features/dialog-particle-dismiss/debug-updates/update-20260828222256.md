# Dialog 粒子消失：修复遮罩与粒子错时并优化真机性能

本版修复 Android 端关闭 Dialog 时，应用自定义 dim 动画先结束、粒子动画随后才出现的
时序错误。实机诊断确认根因不是 `PixelCopy`：其耗时约 14 ms，主要延迟来自首次构建连续
布面模拟，以及 Dialog、遮罩和粒子动画此前分别按不同事件启动。

- 在粒子渲染链路中加入首帧握手：只有首个 GL 粒子帧完成提交后，才启动应用自定义 dim
  动画；初始化失败和超时路径也会安全地触发一次，避免界面卡住。
- 增加双条件启动门：真实 Dialog 的移除同时等待粒子覆盖层提交和首个粒子帧。准备期间
  Dialog、键盘、背景与遮罩保持稳定，消除背景提前位移和粒子出现前的空档。
- 将 `ParticleDismissClothModel` 从对象列表求解器改为 primitive SoA 数组，并把空间控制网格
  调整为 `16×10`；仍保留 240 个归一化时间步、原有粒子采样密度和连续布面轨迹，Shader
  通过双线性插值恢复每个粒子的布面位置。
- 把每步 9 次约束迭代合并为一次等效累计刚度求解，显著降低冷启动 CPU 开销，同时保留
  位移、释放进度、折叠形态和末段运动的数值约束。
- 清理本轮临时诊断日志；粒子颜色、统一运动规律、帷幔折叠密度和左上触摸消逝方向均保持
  当前已确认的实现。

已通过粒子消失相关单元测试和 `:app:assembleDebug`。在三星 SM-S9180
（设备序列号 `R5CW20BLNKL`）上完成整段录屏与逐帧复核：冷启动布面准备约 216 ms，
触摸至首帧约 248 ms；热启动分别约 70 ms 和 99 ms；dim 与粒子首帧启动差为 0–1 ms。
最终完整动画 121 帧，平均帧间隔 8.34 ms（约 119.93 FPS），P95 9.39 ms，最大
17.40 ms；未发现遮罩先结束、背景提前移动、闪烁或末段停顿。
