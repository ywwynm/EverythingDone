已在 9018f404 使用真实 Chooser / Alert 弹窗的渐变标题、按钮作为固定输入，直接比较动画使用的 Bitmap 与出现完成后的真实 View 画面。该像素检查不读取或修改用户记事。

## 方案方向

1. 轻浮现与边缘短距离成形：主体尽早可读，轻微位移及缩放，少量颗粒在边缘就近归入面板，约 240–300 毫秒。优先推荐。
2. 多个局部区域成形：几片宽而柔和的区域错开出现，边缘微粒补合；避免一条贯穿全宽的扫描线，约 280–360 毫秒。
3. 从触发位置展开：面板从有明确来源的按钮附近轻微展开到最终位置；无来源的自动弹窗回退到第一种，约 240–300 毫秒。
4. 轻微纵深聚焦：完整面板由稍远位置迅速浮现到当前深度，内容不模糊，颗粒存在感最低，约 200–260 毫秒。

以上时间是待体验的设计起点。每种方案都保持最终文字颜色，避免长距离吸入、整块文本破碎、孤立细缕和高亮描边。随机性只影响细节，不改变交互可预测性。

参考 Material 的[时长与缓动](https://m1.material.io/motion/duration-easing.html)中频繁过渡应简短、避免让用户等待的原则，以及[编排](https://m1.material.io/motion/choreography.html)中保持焦点、关联输入来源、避免多条轨迹交叉的原则。具体时长、颗粒比例和区域成形机制均为本项目设计提议，不宣称是官方规定。

## 逆向播放实现与验证（2026-09-13）

- Android 出现使用当前共同消散积分器的完整一秒轨迹，按 60 Hz 原采样点倒序恢复位置和速度；每次仍用新随机种子，默认倒放向左上的消散。当前模型包含压力迭代和阻尼，直接把时间改成 `1-t` 无法反向积分，因此先解算再倒播。
- 只保存每片粒子可见寿命附近的状态，不保存全屏视频；钢铁侠轨迹缓存约 58 MB，添加附件约 77 MB，播放结束释放。
- 逆向预计算将每八次压力 Jacobi 迭代放进一个带完整边带的共享内存块；迭代总数、公式、边界条件不变。共同模型资源和正向消散算法未修改。钢铁侠、添加附件均通过全部 61 帧 RGBA 哈希相等检查。
- 实测轨迹准备仍约 0.40 秒，不能描述为立即出现；当前版本优先保持严格倒放的一致性，不用旧出现轨迹替代。

- 三组素材全部 183 帧相等；颜色高弹窗缓存 120 MB。两台设备恢复在线后，Chooser / Alert × 三种配色各六组均在日志确认 GPU 逆向完整播放，同时原图和最终 View 整图最大色差为零。
- 9018f404 四条正常关闭首帧 97–112 ms，两次出现过程中立即返回为约 90 ms，均完成动画并清理窗口与叠加层。
- 20 项 JVM 检查通过；旧出现着色器散列测试替换为实际使用的共同模型及缓存 GLES 编译验证。
- 钢铁侠、添加附件、调整颜色的 GPU 逆向视频已分别导出 1 倍速与 0.5 倍速，入口 `videos/reverse-appearance.html`。视频仅展示实际动画帧，不包含准备等待，页面已明示。
