# 后续验证

## 2026-09-14 光带与放大承接

- OPPO OPD2515 的 `screenrecord` 仍被拒绝，本轮只能用约 2 帧/秒的截图连拍，分辨不了 216 ms 的内容放大段。该机的精确时序始终缺失；若要在该机做毫秒级时序验收，需要先解决录屏权限或换用别的取帧手段，不能用动画时长缩放后的等比结论替代常速时序。
- 本轮未做「光带播到一半旋转屏幕」的中断验证：OPPO 常驻横屏、未改自动旋转，Samsung 未安排。旋转会触发 `onConfigurationChanged` 与 content 尺寸变化两条 `finish()` 路径，值得补一次。
- 卡片级光带的边完成时刻在 Samsung 上受粒子残留干扰，自动的头部单调性判定会误报；本轮靠逐帧目视与头部坐标确认走向。若要把它做成可重复的断言，需要把粒子从检测里排除。
- `ShiningBorder.mReassignBeforePlay` / `mPathAssigned` 这次修的是「显式矩形被 View 边界覆盖」。其余以 View 自身边界播放的入口（`restoreShiningBorderDefaults` 之后）未逐一回归，若以后新增按矩形播放的调用点，应按同样方式核对第一次播放。

## 2026-09-14

- 首帧与轮廓专项已完成：左滑改为按下预备及增量轨迹，新建分段上传与建材并发。新建热运行仍约 338–380 ms，已有若干无收益或改变像素的方案明确撤回，后续不得当作已解决为零等待。见 [专项验证](startup-and-outline-2026-09-14.md)。

- 发布包一次全屏粒子首帧为 333 ms，多个热运行约 338–380 ms；仍需继续压缩准备与窗口交接成本。当前不改成 View／Fragment，也不通过降低共同模型质量缩短等待。
- 8 轮真实开关未见持续内存增长，但进程 PSS 峰值约 495 MiB；低内存机型、长时间压力和功耗尚未验证。未获授权连接其他设备，本轮仅报告 9018f404 的实测范围。
