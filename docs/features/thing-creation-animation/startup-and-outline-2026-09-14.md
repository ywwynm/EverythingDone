# 首帧等待与媒体卡片轮廓

- 目标：缩短真实点击新建与左滑起步的粒子首帧等待，保留含图片卡片的实际圆角。
- 既有正式基线：全屏粒子首帧约 363–415 ms，手势约 235–304 ms；取整导致的慢拖阶梯感已修复，本轮针对准备等待。
- 反馈环：9018f404 的系统输入真实新建／保存／拖动；只读观察器与既有分段计时；轮廓另用真实手势停住截图验证，截图轮不计入帧率统计。
- 待验证假设：手势必须等待完整逆向预计算；窗口捕获与像素读回／上传占用首帧；重复着色器／缓冲准备；根节点 clipToOutline 未带入离屏 RenderNode。
- 保留共同材料、随机规则、运动与粒子数量，保持 Activity 架构及“腾位 → 粒子 → 完整卡片”顺序。测试仅操作本轮明确命名的记事并在结束后恢复设置。

## 已确认的原因与第一组修改

- 本轮开始时首页为 2 个文件夹、15 条记事，新建档位 2、左滑档位 0、弹窗档位 3、自动旋转 1、方向 0。此前用户增加的两条记事不属于测试数据。
- 两轮纯文本卡片左滑约 254–260 ms 才提交首帧，其中完整轨迹预计算约 207–211 ms，建材 13–20 ms、管线 5–6 ms。先将左滑改为起点立即呈现、按需增量计算，利用后续节拍逐步备齐缓存。
- 增量积分与历史回放使用独立状态缓冲：五分量绘制历史不能覆盖继续积分使用的八分量状态，回拖也不能把积分时步拨回去。普通出现仍保留原完整逆向准备路径。
- 独立图片通过真实附件菜单和系统文件选择器加入测试记事。左滑后回到零进度停住，两个顶角与原卡片的平均像素差为 86／91；抬手后又恢复，稳定复现圆角消失。
- 根节点 `View.draw` 不会拷贝根 RenderNode 的裁剪属性。离屏硬件捕获现从根 View 的实际 OutlineProvider 取得轮廓并赋给新 RenderNode，覆盖图片卡片的自定义圆角，不从 CardView.radius 猜测。

## 分段结果与继续优化

- 相同 577×573 图片卡片，原首帧为 235／253 ms；按需推进后为 103／103／104 ms。长帧仍约 33–35 ms，尚不能据此宣称完全跟手。
- 为本次按中的卡片提前准备零进度纹理；识别左滑才显示，点击、纵向移动、多指、取消和长按超时均清理未接管的准备。预备不推进后续轨迹。三轮中两轮零进度纹理早于识别左滑就绪，一轮晚约 9 ms；下一步核对首次非零进度及取消资源。
- 图片圆角修复后，两顶角差值由 86／91 降为 19.6／16.6，抬手后整张卡片与原图平均差约 0.0025。手势停住时仍有阴影／抗锯齿差异，不宣称整图逐像素相等。
- 全屏新建约 389 ms，其中管线约 4 ms、等建材约 37 ms、上传约 21 ms、轨迹与首次绘制约 226 ms。试验了内部格索引简化、跳过空格邻域运算、线程私有散度与占用值；60 组桌面 GPU 输出逐位相同，但实机总量改善不稳定，均撤回。
- 强制同步诊断只用于定位：压力求解仍占主要部分；逐段同步显著放大总耗时，诊断轮不纳入交付性能数据，临时同步已撤除。继续评估有界准备队列，保留全部材料、240 Hz 积分及 100 次压力迭代。

- 后续排除了四批在途队列、寿命索引压缩和提前暂停表单过渡：未获得稳定收益，已撤回。CPU 逐步时间作为 uniform 的批量积分也在 Adreno 829 的 61 帧对照中出现差异，完整撤回；原始结果在 `tmp/thing-animation-device/startup/batch-parity-failed.json`。对照由真实手势触发的只读观察器另开离屏验证，不通过广播或 Intent 驱动业务，也不计入性能轮。
- 保留前景上传拆分：后台只先交出同一份 ARGB 像素，然后继续建材，GL 线程同时转换并上传颜色。状态缓冲稍后独立上传，与原打包字节对照。先把颜色打包放在建材前的版本只转移等待，已修正为实际并发；三个热运行首帧为 367–380 ms，改善仍有限。
- 试验首页捕获与 Activity 初始化并发，热运行可减少部分窗口前置等待，但首轮出现约 4 秒承接等待。即使与首次初始化也可能有关，目前不足以确认安全收益，已完整撤回，保留既有 Activity 交接顺序。
- 最终左滑候选的第一帧非零进度在识别左滑后约 43–45 ms、按下后约 170–176 ms；原版同一手势按下到完整起点约 379–407 ms。新版用更严格的非零进度指标。预备零帧与尚未开始左滑之间的静止间隔不算播放掉帧。
- 真实 60% → 20% → 60% 回拖，两个 60% 画面逐像素相同；停住不变，抬手后原卡片逐像素恢复。最终候选两个顶角差约 19／16，圆角保留。

## 保留实现的回归

- 30 项相关 JVM 测试通过，无失败或跳过，包含实际 GLSL 编译和按下预备的进度门控。
- Adreno 829 上以真实图片卡片输入另做离屏对照：61 帧与原正向模型散列相等；拆分前景／状态上传与原 `packUploads` 字节相等。详见 `tmp/thing-animation-device/startup/final-gpu-parity.json`。
- 两轮真实新建／保存首帧为 372／338 ms；两次保存均没有提前可见或与列表腾位重叠，末帧确实提交后交接。三次入场约 124 ms 时按系统返回，进程不重启、页面无残留，再次打开正常。
- 连续六轮“已有图片记事按下打开 → 返回 → 按下后取消”，每轮粒子线程都为 0、进程不重启、记事数量不变。PSS 从 355984 KiB 到 334628 KiB，循环范围 311264–337544 KiB；这是结束时资源检查，不能代表瞬时峰值或长时间功耗。
- 一次采样等待超时没有算作通过；实际页面正常、当前进程无崩溃，清理采样标签后以新的 run id 完整重跑。用于验收的是 `startup-save-verified-*`，而非该次不完整记录。
