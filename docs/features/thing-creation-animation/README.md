# 新建记事动画

本功能统一点击首页新建按钮与保存后新卡片入场的动画选择，复用已有涟漪、边框光效和弹窗粒子出现模型。

2026-09-13：已实现三档设置、旧偏好兼容和全部 13 组语言资源。创建页保留 Activity，通过一次性首页快照承接跳转；粒子在目标内容完成布局后从右下出现。保存后的卡片也使用同一选择。

已在 `9018f404`（OPD2515，Android 16）检查真实新建／保存和提前返回，修复入场结束崩溃及键盘过早展开。操作脚本、证据与限制见 [实机验证](device-validation-2026-09-13.md)。

保存后粒子档按“腾位 → 粒子 → 完整卡片”执行：等待 RecyclerView 插入／移动完成再启动粒子，解决默认插入淡入提前露出完整卡片的问题。真实逐帧回归见 [保存顺序验证](device-order-validation-2026-09-13.md)。

相关历史见 [首页新卡片入场](../home-new-item-animation/README.md)；共同粒子模型见 [弹窗粒子决策](../dialog-particle-dismiss/decisions.md)。

2026-09-14（二）：全屏与卡片光带统一改为从右下角起步（底边向左 → 左边向上 → 顶边向右 → 右边向下），光带播完后编辑页内容以右下角为轴从 0.84 放大到 1、216 ms、全程不透明；涟漪圆心改回新建按钮中心。顺带修掉「显式矩形被 View 自身边界覆盖，导致进程内第一次保存播整屏光带」的既有缺陷。双机逐项数据见 [实现记录](sessions.md) 的同日条目。

2026-09-14：补测真实系统输入的帧耗时、首帧等待、CPU／GL 开销、8 轮开关内存及三档对照，发现并修复左滑慢拖的进度取整问题。使用只读观察器的 `device_performance.py` 作为当前正式测量入口，分析器同时验证保存顺序；不再以启动诊断 Activity 代替用户操作。结果及未解决的等待和漏帧见 [性能验证](performance-validation-2026-09-13.md)。
