# 实现决策

## 2026-09-15 新建按钮坐标不参与预算判断

原委与实测见 [提前预算被 FAB 坐标必然判废](prewarm-fab-key-2026-09-15.md)。

- **`fab` 项整项移出指纹**（用户裁定：出现动画一律从右下角来）。该坐标的全部作用是微调
  粒子的出发方向，实测那点位移对应的方向差不到 4°、肉眼分辨不出，却足以作废一份 600 ms
  的预算。指纹项数 15 → 14。
- **不改用「稳定读数」来保留这一项**：先试过取不含 translation 的标称中心，它只堵住了
  Snackbar 一种来源；按钮还会随列表滚动收起、`getLocationInWindow` 又受 `shrink()` 的
  scale 影响，用户实测仍有判废。逐一堵不如不要。
- **交给转场的 `sourceX/sourceY` 仍取标称中心**（`fabNominalCenter()`）：它是涟漪档的揭示
  圆心与粒子方向，取稳定值本身是对的，只是不再参与「预算能不能用」的判断。
- **不给预算加「按钮正在动」的门槛**：实测位移不经过 `showFromBottom()`
  （`settling=false` 而 `ty=-111.6`），这类门槛拦不住，且把时序耦合进了按钮。

## 2026-09-15（第四批）创建页的粒子轨迹在首页空闲时提前算好

数据见 [粒子动画性能专项第四批结果](../particle-animation-performance/batch4-results-2026-09-15.md)。

- **轨迹与贴图分离。** 首页空闲（无触摸、无动画会话、静置 500 ms）时，用**上一次真实创建页的
  首屏像素**当预测素材建材并预算整条倒放轨迹，缓存在常驻 GL 上下文里；点新建按钮后照常抓
  **真实**快照，只把它换成前景贴图就开播。命中时点按钮到首帧上屏 OPPO **484 → 171 ms**、
  三星 **871 → 305 ms**。
- **末帧仍与真实页面逐像素相同**，依据写死在 `material.vert`：第 0 遍按 `uv = source / card`
  采样、画在 `world = offset + source`，采样位置与屏幕位置是同一个恒等仿射映射，末帧就是前景
  贴图的一次逐像素拷贝，**与格子分辨率无关**。预测偏差只影响途中每一片的出生、寿命与复制片数。
- **离屏渲染一张真正的创建页判定为改造过大**（inset 链、`updateNewThingColor` 的副作用、
  actionbar 走 AppCompatDelegate、5840 行 / 50 个字段），四条阻碍详见性能专项的 decisions.md。
  代价是**进程启动后的第一次新建必然未命中**。
- **新记事随机背景的掷点从创建页 `initMembers` 提前到首页**，改成「创建页只标记消费、首页
  `onResume` 重掷」；每一个读预掷值的地方都先 `App.ensureNewThingBackground()`，已消费而未重掷
  时立刻补掷——两条记事绝不会同色。
- **缓存键**：背景、文件夹（整条祖先 id 链 + 私密鉴权态）、深浅色、语言、字号、密度、窗口尺寸、
  方向、多窗口、系统栏与刘海 inset、输入法高度、新建动画档位、动画时长缩放、刷新率、FAB 中心、
  影响轨迹的全部开关。键在**点击那一刻**由首页算出并随 Intent 传给创建页。键之外还有两道硬核对
  （快照尺寸与原点、共享资源尺寸），任一不过就原样退回完整路径。

## 2026-09-15（3b）出现动画的最终配方：方向 + 触点距离，门槛 10%

同快照同种子的四档对照（见
[粒子动画性能专项第三批结果](../particle-animation-performance/batch3-results-2026-09-15.md) 第 12 节）：

- **「从右下角那一点扇形汇入」只来自触点距离归零**。`step.comp` 的
  `destination = card*.5 + wind*(edge + span*touch_gap)`，`touch_gap` 为 0 时汇聚点落在内容边界
  上，每片按到那一点的方位角偏转，倒放就是从那一点扇开。只改方向（仍用默认距离 0.65）时，
  前沿仍是接近直的斜带，和原来差别不大。
- **触点强度也归零只是让分布更散、前沿更糊**，观感增益很小，OPPO 上每采样预计算再贵 5 个
  百分点。所以默认取 `ParticlePerfTuning.TOUCH_DIRECTION_GAP`（方向 + 距离），其余三档留开关。
- **跳过尾段的门槛从 5% 提到 10%**：两台都多跳一个采样，首帧的存活片占比从 6–7% 提到
  10.1%（OPPO）/ 15.6%（三星）——用户要的就是起始段更明显——预计算也按比例少算一档。
- **点新建按钮到首帧真的上屏：OPPO 596 → 484 ms。** 省下来的不是动画本身，是两段空等：
  节拍原本只在播放阶段才跑，预计算结束才启动要重新登记 Choreographer 再等一拍；粒子显示层的
  第一张缓冲要等系统合成器给这一层做首次合成（第一次动画 82–88 ms、之后 14–17 ms）。
  现在准备期间就让节拍跑，表面一就绪先交换一张全透明帧。

## 2026-09-15 粒子档：新建按钮成为出现动画的真实触点，并跳过倒放尾段空白

性能专项第三批的 2b / 2c，完整数据见
[粒子动画性能专项第三批结果](../particle-animation-performance/batch3-results-2026-09-15.md)。

- **粒子档的出现动画不再用固定 315° 的虚拟远触点。** `ThingCreationTransition` 把首页新建按钮
  的窗口坐标（涟漪档本来就在传的那一份）一并交给 `appearContent`；抓图那一刻换算到快照局部
  坐标，方向取「内容中心 → 按钮」，`touchGap` / `touchStrength` 按真实触点算。按钮落在内容内部，
  所以两项都是 0——与弹窗里点按钮关闭时的配置相同，是既有已验证的取值范围。
  实测方向：OPPO 横屏 328.3°、三星竖屏 292.8°（原来固定 315°）。观感差别主要来自触点距离
  0.65 → 0：`step.comp` 的 `destination` 从控件外 1.1 倍对角线处移到内容边界上，倒放时粒子
  从右下角那一点扇形汇入，而不是近似平行地飘来。开关 `ParticlePerfTuning.creationAppearanceFromFab`，
  默认开；关掉即恢复原来的虚拟远触点。
- **倒放的最初几帧几乎是空的，现在直接跳过。** 按 `material.vert` 的裁剪条件
  （`0 < t - birth < life`）在 CPU 上算每个历史采样的存活片数，取「仍 ≥ 5%」的最晚采样作为
  倒放起点；播放时长按 `起点/总采样` 缩短（每帧速度不变），预计算也只算到那一个采样。
  实测起点 34/36（OPPO）、33/36（三星）——原来的第 0 帧存活片占比恰好是 **0.0%**。
  开关 `creationAppearanceSkipEmptyTail`，默认开，只作用于创建页。
- **「跳过」绝不能通过缩小 samples 实现。** `ParticleReversePlan.time(frame) = frame / samples`，
  samples 一变，每个采样的积分时刻全变，保留段就不再与原来逐位相同。实现是 samples 不动，
  只改预计算终点与播放起点；设备端新增的「截断预计算逐帧」散列对照在两台上零差异。
- **创建模式的启动耗时只做了一处保守延后**：「快速新建」常驻通知从 `initMembers` 挪到入场动画
  结束之后（`ThingCreationTransition.afterFinish`，没有入场动画时立即执行）。分段实测
  `onCreate` 到首次布局只占「点按钮 → 首帧上屏」整条链路的 4%，大头是 GPU 预计算（44%–53%）。

## 2026-09-14 光带起点角、内容放大承接与涟漪圆心

- **起点角而非翻转。** `ShiningBorder` 新增 `setStartCorner`，`START_BOTTOM_LEFT` 为默认值（历史行为），`START_BOTTOM_RIGHT` 走新写的 `addRoundRectCWFromBottomRight`：底边向左 → 左边向上 → 顶边向右 → 右边向下，回到右下角。旋转方向与 `addRoundRectCW` 相同，只换起点，不再使用 `scaleX = -1`。新函数按绝对坐标写，段长直接给出（不沿用 `-rh + r` 那种靠 `arcTo` 隐式补线凑出来的写法），r = 0 与 r > 0 都正确。
- **翻转为什么不该用。** 水平镜像会把顺时针变成逆时针：镜像后的走向是「右下起步 → 右边向上 → 顶边向左 → 左边向下」，与目标相反。也就是说即使翻转生效也不是要的效果。翻转在真机上为何完全看不出效果未查明，见 sessions.md。
- **路径接收端抽象。** 三条边角构造改为写入 `ShiningBorder.BorderPathSink`，Android 侧用 `Path` 适配，JVM 测试用折线采样器。几何只有一处实现，测试不重写一遍；否则 `Path`／`PathMeasure` 是框架实现，单测里根本建不出来。
- **内容承接是纯放大，不是淡入。** 光带 `onAnimationEnd`（此时暗段余光已退完）后，内容以右下角为轴（pivot = content 宽高）从 0.84 放大到 1，216 ms，`DecelerateInterpolator`。内容从第一帧起 alpha 就是 1，没有透明度变化——用户第二次裁定明确去掉了淡入。放大结束的回调里才 `finish(true)`，此前首页快照一直在底层。
- **中断必须复位。** `finish()` 统一 `animate().cancel()` 并把 scaleX／scaleY／alpha 复位为 1，覆盖 onPause、onConfigurationChanged、content 尺寸变化与 attach 失败四条路径，不允许留下缩小或半透明的页面。
- **卡片级光带同样右下起步。** `findViews()` 里对 `mShiningBorder` 设一次 `START_BOTTOM_RIGHT`，卡片级覆写与 `restoreShiningBorderDefaults()` 都不再碰起点角，避免一次右下一次左下。1600 ms、末尾 220 ms 淡入、几何保护与中断逻辑不变。
- **显式矩形不能被 View 边界覆盖（既有缺陷）。** `assignPathAndFrame(l, t, r, b)` 现在同时置 `mPathAssigned = true`、清 `mReassignBeforePlay`。此前 `onDraw`（View 之前是 INVISIBLE、从未绘制）与 `startAnimation`（布局后尺寸变过）都会用 View 自身边界重算，把卡片矩形覆盖成整屏，表现为进程内第一次保存播的是整屏光带、第二次起才正常。两台设备均已复现并在修复后验证。
- **涟漪圆心取 FAB 中心。** `ThingsActivity` 用 `mFab.getLocationInWindow` 加宽高一半算出窗口坐标传给 `launch()`，`startRipple()` 换算为 content 局部坐标并钳制到 [0, w]×[0, h]，终止半径取 `hypot(max(cx, w-cx), max(cy, h-cy))`。没有来源坐标（NaN）时退回内容右下角。600 ms 不变。粒子档未改。

## 2026-09-14 首帧准备

- 同一份快照像素先用于 GL 前景转换与上传，同时后台继续建材；不更改像素、材料、积分或轨迹。分段上传在设备上与原打包字节相等。
- 新建首帧仍需要完整轨迹准备，实测改善有限，不宣称立即开始。压力微调、扩大队列、寿命索引及提前暂停页内过渡均因收益不足撤回；批量积分因实际 GPU 像素差异撤回。
- 不保留捕获与 Activity 并发启动的试验：首轮出现长等待，不能用未证实稳定的窗口交接换取少量热启动收益。保持原承接顺序与 Activity 架构。

## 2026-09-13 保存后的三阶段入场

- 用户要求“列表腾位 → 粒子出现 → 显示完整记事”。实机逐帧观察确认原实现与 RecyclerView 插入动画并发：粒子进度约 22% 时，默认添加动画已把真实卡片 alpha 写回 1。
- 粒子档在原滚动门控之后继续等待真实 ItemAnimator 的完成通知，等待期间用 INVISIBLE 保留布局空间；不依赖固定延时，也不提前结束旧卡片的移动。
- 待列表动画全部结束，再让共同粒子管线接管 alpha。正常结束仍以粒子末帧实际提交为准恢复真实卡片；延后启动受原有代次与生命周期清理保护，失效回调不再启动动画。
- 回归通过 debug 专用 NewItemAppearanceProbeActivity 旁观真实首页及真实保存入口，逐帧断言腾位与粒子不重叠、粒子末帧前真实卡片不可见。探针不修改生产参数或记事数据。

## 2026-09-13

- 使用新整数键保存三档选择，旧 Boolean 键保留只读兼容，原 true 对应边框光效、false 对应涟漪。
- 保留 DetailActivity 架构。尝试在本次跳转中禁用系统过渡，通过一次性的首页快照承接窗口切换，再在详情窗口播放实际内容的入场动画；Activity 初始化等待仍然存在，不宣称消除启动成本。
- 保存后卡片继续沿用已有“滚动到完整可见再播放”的编排，粒子使用固定右下来源，不受弹窗动画开关控制。
- 转场期间保持输入法隐藏，内容完整显示后再恢复正文焦点并展开；避免首页快照阶段先出现键盘，也避免快照准备过程中窗口高度变化。
- 粒子层释放通知必须在父容器完成子节点移除后发出，不能在 detach 回调中同步移除同一父容器的其它层；实机已复现原顺序导致 ViewGroup 子节点数组异常。

实现边界：使用 ActivityOptions 的本次自定义零时长过渡，不动态修改 Activity 主题。AOSP 的 [ActivityRecord 起始窗口选择](https://android.googlesource.com/platform/frameworks/base/%2B/d29b9cdc8e4061321fa602baac1382c408a1c810/services/core/java/com/android/server/wm/ActivityRecord.java)区分同任务内启动与新任务／任务切换；本入口保持现有同任务跳转，不引入透明 Activity 或 Fragment 重构。厂商系统上的窗口切换观感仍须实际验证。
