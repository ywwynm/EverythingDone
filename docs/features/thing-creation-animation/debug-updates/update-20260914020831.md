## 新建与左滑粒子起步、图片卡片轮廓（20260914020831）

用户反馈点击新建和开始左滑时都要等待粒子准备，图片卡片在粒子中还会失去圆角。本轮继续只在 9018f404 通过实际按钮、返回及系统手势操作验收，保留详情 Activity、共同粒子模型和“先腾位、再粒子、最后显示完整新记事”的顺序。

新建准备将同一份 ARGB 像素先交给 GL 线程，颜色转换和纹理上传与后台建材重叠；状态缓冲随后独立上传。没有减少粒子、积分次数或压力迭代。真实新建热运行首帧约 338–380 ms，改善有限，仍存在准备等待。若干队列、索引和着色器试验没有稳定收益或改变像素，均已撤回；首页捕获与 Activity 并发启动的试验出现长等待，也未保留。

左滑在按下卡片时准备零进度纹理，确认左滑才接管显示；点击、纵移、多指、长按超时和取消会清理未接管资源。轨迹按手势所需进度增量计算，并逐步补齐缓存；回放使用独立状态缓冲，避免回拖覆盖继续积分的状态。最终横屏样本中，识别左滑后约 43–45 ms 呈现第一帧非零进度；原版同一慢拖在按下后约 379–407 ms 才呈现完整起点，新版第一帧非零进度约为 170–176 ms。

ParticleHardwareSnapshot 现复制根 View 的实际 OutlineProvider 与 clipToOutline，保留图片卡片使用的自定义轮廓。首次呈现前的占位绘制也使用已捕获的圆角快照，尚未捕获时按实际轮廓裁剪。

30 项相关 JVM 测试通过，包含实际 GLSL 编译。设备上 61 帧与原正向模型散列相同，拆分上传与原打包字节相同。真实回拖 60% → 20% → 60% 的相同进度画面完全一致，停住不推进，抬手后原卡片逐像素恢复。两轮新建保存无提前可见或腾位重叠，三次提前返回正常。六轮已有图片记事打开／返回／取消均无粒子线程残留，PSS 结束值约 327 MiB，没有持续上升。

本轮数据不能证明稳定 60 fps，仍有约 25–35 ms 的纹理间隔；低内存机型、长时间压力及功耗没有覆盖。完整诊断与撤回依据见 startup-and-outline-2026-09-14.md；发布后另核验实际安装包及真实操作。
