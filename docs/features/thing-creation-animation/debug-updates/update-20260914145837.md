# 调试更新日志

## 修复涟漪档保存后卡片级揭示在长距离滚动后直接出现的问题

涟漪档新建记事保存返回首页时，如果置顶记事占据的位置很多、新卡片需要经过一段较长的平滑滚动才进入视口，卡片会直接整张出现，没有从右下角扩开的揭示动画。真机日志确认揭示动画启动后十几毫秒就结束了：这张卡片的 View 是列表在脱离窗口时绑定的复用 View，之后一直处于不可见状态、重新挂回窗口后从未参与过绘制，在这样的 View 上启动的渲染线程动画会立即完成。现在在揭示前的等待期内让卡片以完全透明的可见状态先参与一次绘制，再启动揭示；同时先结束列表自带的插入淡入，避免它把透明度抢回不透明。卡片级边框光效末尾的淡入同样走渲染线程，光带期间改用同样的处理。粒子档不受影响，未改动。

平滑滚动的兜底不再是固定 1200 毫秒后放弃：列表仍在滚动就继续等待（硬上限 9 秒），滚动停止后再给 1200 毫秒让卡片绑定，仍没有卡片才直接显示。置顶块约 4.5 屏时滚动本身已接近 1 秒，更高的置顶块会撞上旧超时而丢失动画。列表任何一次停止滚动时只要揭示仍在等待都会重试，覆盖原地揭示时列表恰好还在惯性滚动的情况。

三星 SM-S9180 上以 20 张高卡片组成约 4.5 屏的置顶块复现并修复：涟漪档揭示动画实测 550 毫秒完整播放，同场景边框光效的卡片按原样淡入，带小段滚动的新建也揭示完整且揭示前没有提前露出；OPPO OPD2515 原地新建在 5 倍动画时长下揭示 2720 毫秒完整。相关 7 项 JVM 测试通过。debug 包保留 NewItemReveal 标签的时序日志，便于按日志核对。
