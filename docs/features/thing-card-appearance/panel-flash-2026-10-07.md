### 回归命令

已获本轮设备授权后，用指定设备执行 `am instrument -w -e run_id <本轮标识> -e style drift -e hold_window_ms 320 -e rounds 1 -e capture_handoff true -e video_second true com.ywwynm.everythingdone/.views.particledismiss.AppearancePanelInputProbe`。流体改为 `-e style flow`；正常操作去掉 `hold_window_ms`、`capture_handoff`，可用 `-e rounds 4`。

入口读取系统界面树、通过系统输入派发点击及滑动；回归依赖首页存在至少两条有图片或视频封面的普通记事，指定 `video_second` 时第二条须有视频。遇到不满足条件的列表会报告失败，不伪造通过。

## 用户场景

首页长按带图片的记事 A → 打开外观面板 → 关闭面板 → 取消 A 的选中状态 → 选择另一个带图片的记事 B → 打开外观面板。用户反馈第二次面板有概率闪烁一帧，要求先复现，再修复并发布阿里云。

用户随后补充，飘散和流体两种样式都有此问题，必须共同验证。
用户进一步指出，滑动记事列表似乎会提高复现概率，后续复现加入列表滚动。

## 已核对的入口

- 首页界面为复用的 `panel_thing_card_appearance` 页内面板，实际入口是 `ThingsActivity.openThingCardAppearancePanel`。
- 每次打开先绑定所选记事的外观和媒体控件，再通过 `ParticlePanelAnimator.appear` 进入共同粒子出现管线。
- 根容器开启 `LayoutTransition`；已有 `ParticleSnapshot.hold` 负责暂时结束布局过渡，并在捕获前检查稳定布局。
- 既有 `ParticlePanelReuseProbeActivity` 仅覆盖 A 颜色页关闭后重新显示 B 外观页，没有真实选择切换，也不绑定两条记事的图片控件，不能单独证明用户场景已复现或修好。
