# 2026-10-07：Android 取消黑白灰内容额外强调

## 范围与当前基准

用户选择先迁移桌面五项实验中的第 4 项，其他四项继续留在桌面。基础代码核对到 `4ee756ce2`，包含近期粒子大小倍率、播放去重、两阶段参考概率和内部裁剪修复；另一会话已完成该提交，当前 Android 与共享着色器没有未提交改动。

本轮以当前 `shared/particle-dismiss/drift-update.comp` 为入口，保留 `ParticleDriftContent` 的整字取样、精确颜色权重缓存、副本候选分布，以及渲染器工作面覆盖窗口和重复帧复用。取消强调应只影响低彩度内容的额外副本、尺寸、透明度和寿命；不能把基础文字颗粒重新归为面板颗粒并额外削弱。

## 实现与验证计划

- 与桌面试验使用相同的 RGB 通道差阈值 0.04–0.20，深浅主题共用规则。保留来源色、已有暗色下限和饱和彩色内容的强调。
- 保留候选副本总数与分布，按同一粒子索引的固定哈希拒绝黑白灰副本，不重新抽取或把预算转移给彩色区域，以保持桌面选定方案及彩色颗粒的行为。
- 没有明确本体色、内容强调未启用的照片输入沿用原效果。
- 用正式 GLSL 做离屏对照，检查深浅主题、单色与低彩度过渡、强调色、无内容强调、大小倍率、相反风向及进度回退；运行既有飘散与着色器编译测试。
- 本轮没有设备操作授权，不调用 ADB。按仓库现有发布约定完成验证后发布阿里云调试版，由用户在 Android 上查看实际视觉效果。

## 实现结果

`drift-update.comp` 在原内容权重之后计算低彩度比例：通道差不超过 0.04 时完全撤去额外强调，达到 0.20 时保留全部强调，中间用 `smoothstep` 过渡。副本用原索引加 81 的固定哈希筛选；基础颗粒的尺寸、不透明度和寿命仅撤去原增益，原来源颜色和暗色下限保留。`bodyShare` 继续使用原内容权重，避免把普通文字误判为本体后再次缩小、变淡。

运行逻辑只改上述着色器；`ParticleDriftContent.kt` 仅更新说明，明确 CPU 生成的是副本候选。没有新增纹理、缓冲、均匀变量、绘制遍数或准备阶段计算，也没有把拒绝的副本预算重新分配。未修改流体样式、参考选择、预热去重、大小倍率、窗口绘制范围或重复帧复用。性能收益没有在 Android 设备上测量。

## 验证结果

- 新增 [正式 GLSL 检查脚本](checks/check_neutral_content.py)，在桌面 OpenGL 上仅替换版本声明后执行正式计算着色器，对照提交 `4ee756ce2` 的原实现。161 组检查、391 次计算通过；把待测源码换回旧提交时，基础黑白灰仍有增益的检查按预期失败。
- 深浅主题各取三档黑白灰、六个时间点；充分反差的基础文字颗粒与关闭强调的同索引状态一致。稳定阶段每组保留 4,096 个基础颗粒，原来的 4,096 个候选副本全部取消。
- 两套低彩度梯度的副本保留数量一致，随通道差从 0 单调增到 4,096；尺寸和不透明度的增益独立核对通过。饱和彩色的全部状态与旧版一致，本体的基础状态、无明确本体色的输出也保持一致。
- 检查包含标准叠加／加光、0.5／1／6 倍大小、相反风向、真实触点、120／144 Hz、旧参考不淡出的规则、透明边缘。混合纹理加非均匀副本分布与空间遮罩覆盖 9,819 个强调色样本；倒放及反复回退与同时间点正放逐字节一致。
- 64 项相关 JVM 测试通过，0 失败、0 跳过，包括正式 GLES 着色器编译、内容分析缓存、模型、参考选择、画布和大小设置迁移。结果位于 `tmp/drift-neutral-2026-10-07/`。
- 本轮未连接设备；上述检查证明规则与兼容性，实际手机观感由调试版本继续验证。
