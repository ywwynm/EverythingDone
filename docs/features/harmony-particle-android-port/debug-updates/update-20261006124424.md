## 飘散动画：缩短新建与弹窗起播等待，减少重复帧渲染

### 本次需求与接续范围

用户要求接续 Claude 尚未结束的性能优化，重点是从真实交互开始到动画播放的延迟，以及播放中的渲染耗时；完成后发布阿里云并详细记录结果。本次包含此前已实现但尚未发布的高帧率调度、空闲刷新率投票修正和左滑补帧，并新增下述截图、内容分析和渲染复用优化。

### 新建记事：减少点击后的截图等待

首页用于承接页面跳转的截图只由硬件 ImageView 显示，现在飘散档可以直接保留 GPU 硬件位图，省掉整张截图从 GPU 读回内存的步骤。适用条件为 Android 12 及以上、硬件加速、无可见独立 Surface；截图失败时回退原捕获方式。保留现有 Activity 架构、首页截图完成后再启动编辑页的顺序，以及键盘与真实内容的交接。

三星 SM-S9180 上，分别安装优化前后 APK，真实点击新建各 4 次，取排除首次后的 3 次中位数：
- 点击回调（抬手）到首次粒子上屏：237.3 → 187.9 ms，缩短约 49 ms（21%）。
- 输入按下到首次粒子上屏：274.4 → 213.3 ms。
- 首页承接截图：42.7 → 9.4 ms。
- 编辑页内部的动画请求到首帧：135.7 → 126.5 ms。此项不包含首页截图和 Activity 启动，不能代替完整点击延迟。

### 弹窗与卡片：减少准备阶段的重复计算

内容分析用一次 32 位读取替代逐字节读取，并在单次分析内缓存完全相同 RGBA 颜色的权重。保留原计算公式、浮点求和顺序、透明像素处理及内容强调效果，缓存冲突会重新计算。

同设备同脚本的前后对照中，弹窗分析阶段中位数 14.75 → 4.70 ms，卡片 20.05 → 7.15 ms；点弹窗外到首帧的热运行中位数 55.9 → 47.2 ms。后台分析与纹理上传并行，各阶段中位数不能直接相加当作总耗时。

### 动画渲染：复用同一个模拟状态

慢滑、回退及交接过程中，相邻显示帧可能对应相同的 120 Hz 模拟状态。现在只在模拟帧变化时重新计算并绘制颗粒工作面，窗口位置合成与卡片本体仍每帧正常绘制；画布尺寸变化或资源释放时使缓存失效。

固定输入的成对 GPU 基准中，重复模拟状态的整套每帧耗时：新建页 1.478 → 1.000 ms，多选移除 1.003 → 0.693 ms，弹窗 0.564 → 0.412 ms，左滑卡片 0.551 → 0.388 ms；额外加光场景 0.503 → 0.406 ms，约减少 19%–32%。普通非重复帧约 0.87–1.53 ms，与原来在同一范围，不能将重复帧收益外推至每一帧。

### 同步发布的高帧率与跟手改进

- 只有飘散会话活动时按高帧率节拍出帧，粒子 Surface 请求 120 Hz；混有流体会话时仍按原 60 Hz 管线运行。
- 粒子 Surface 空闲时撤销刷新率投票，解决空闲图层仍常驻请求 60 Hz、从而限制整个应用帧率的问题。
- 左滑位置在本拍较晚更新时唤醒 GL 线程，在允许的时间窗口内补画；同一窗口每拍最多合成一次，避免把本帧位置推迟到下一拍。
- 左滑旧日志的首帧计时从截图完成后创建动画规格开始，不能当作完整按下延迟。本轮真实输入到卡片交接约 98–104 ms，未测到稳定缩短；这里的确定收益是跟手出帧和减少重复渲染。

### 验证与适用范围

- 粒子相关 35 类、335 条单元测试全部通过；新增不同字节序、只读缓冲、半透明像素、随机颜色和缓存冲突的原实现逐位对照。
- 5 类输入共 40 帧，对复用开关前后的实际渲染结果逐字节核对，差异为 0；覆盖同一模拟帧内不同浮点时间、倒放、位置移动、尺寸变化、深浅背景、加光、旧钢铁侠变体及非默认颗粒大小和数量。
- 飘散和流体各完成弹窗 3 轮、左滑与回位 3 轮、多选移除 1 轮、新建页 2 轮；飘散各场景上屏间隔 p90 均约 8.3 ms，没有抓图失败、未开播或异常日志。流体既有的左滑与多卡移除漏帧仍存在，与接手前回归在同一范围。
- 新建页另录屏 2 轮，检查浅色与深色渐变背景下的首页承接和编辑页交接，未见黑帧、倒置或缺图；结束后真实页面与键盘正常显示。
- 多选移除确认弹窗自身约 398 ms 才开始消散的编排等待，本轮未改。
- 本轮性能数据来自授权的三星 SM-S9180（Adreno 740）；其它 GPU、长时间功耗与并发压力没有据此认定通过。测试后恢复粒子偏好和诊断控制文件，确认旋转设置一致，新建流程只打开空白记事后返回并核对首页记事数。
