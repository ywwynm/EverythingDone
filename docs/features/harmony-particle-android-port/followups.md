# 后续工作

- 左滑释放点的格点低值：真机上看得到「从按下处开始化开」（首页左滑、探针左滑），没有做定量验收。
- 帧耗时只在 R5CW20BLNKL（Adreno 740）上量过：4.3 万颗 61/61 帧。Mali / 麒麟 GPU 未验证（只授权了这一台）。
- 全屏快照（新建页）在飘散下是大块的消蚀斑块（格点间距约 490 px，源码的取值），观感与流体样式差别大；用户看过截图后再决定要不要给大快照加密格点。
- 背景亮度门槛 L* 50 是按「中灰」定的，还没在真正的深色主题下截图核对（本次不改用户的深色设置）；深色背景的证据来自调整外观面板探针
  （底色 #566C7A）。用户若在深色模式下觉得加光太亮或太暗，再调门槛或在两种合成之间做过渡。
- 弹窗暗层不计入背景亮度：浅色模式下弹窗消散时白色颗粒压在半透明暗层上，起手那几帧是一团亮白，随暗层淡掉而消失。若用户觉得刺眼，
  可以只对弹窗把暗层按当时的透明度折算进去。
- 参考样式的选取概率 0.5、夹角 22.5° 是初值。左上方向旧钢铁侠一族约一半（原样 20%、变体 30%），其余参考合计 25%、随机 25%；
  朝上（竖直 ±35° 以内的几段）0.75（原样 30%、变体 45%）。只在单元测试与 1404 组输入核对里验证过比例，真机上只看了少量抽样。
- `ParticleSwipeShadowProbeActivity` 的右滑回位前整卡静止约 0.25 秒（两种样式都有，探针自己的问题），未修。
- 「彻底删除」没有在真实回收站里跑（会永久删数据）；它与删除 / 完成 / 恢复走同一个 `ThingListRemovalAnimator`，由多选移除探针覆盖。
- 播放速度：Android 按第 4 问把设备时刻 startSeconds → totalSeconds（约 1.1–1.2 秒）压进 1 秒，模拟器的「Android 移植口径」照此播放；
  「华为原生 · 逐项等价」仍按设备时间 1× 播到 1.5 秒（开头有一小段静止、结尾有约 0.25 秒空白）。两者画面逐帧相同，只是快约 10%。
  若要与华为原样同速，把 Android 的时长改成按设备时间播放即可。
- 模拟器自有序列的背景：「添加附件 · 纯色背景」有真机无弹窗截图；其余三段是开着弹窗的截图、弹窗下方插值重建，暗层情况只确认了「更改应用语言」
  （已按 0.6 还原）。「调整颜色」「添加附件 · 图片背景」本来就暗，判定不受影响。
- `device/stage_b_probes.py` 的 alert / chooser 两项只能录出现（出现探针播完会自己关闭）；要录这两种弹窗的消散需要另做一个不自动关闭的探针。
- 新建页的零拷贝快照只在 API 31+ 生效（取硬件位图的缓冲要 `Bitmap.getHardwareBuffer`），只在 R5CW20BLNKL（Adreno 740）上验证过；
  Mali / 麒麟 GPU 上 EGLImage 能否绑成 `GL_TEXTURE_2D` 没有验证，失败会自动退回拷贝上传。
- 新建页的首页承接截图已于 2026-10-06 在飘散档去掉 GPU 读回：该图只由硬件 ImageView 显示，完整点击链路热运行中位约 237 → 188 ms。
  流体、涟漪及光带档仍走原捕获，若以后扩展需分别验证；本轮证据见 `performance-continuation-2026-10-06.md`。
- 弹窗出现的末段常丢 1–2 帧（流体 4 轮里 1 轮、飘散 4 轮里 3 轮，位置都在倒数第 4–5 帧附近），原因没查。丢帧不再拖慢收尾（见 decisions.md 2026-10-06）。
- 多选移除在确认弹窗里点「确定」之后，卡片的粒子很快开始（飘散约 80 ms、流体约 180 ms），确认弹窗自己的消散却要约 420–440 ms 才开始
  （两种样式相同），属于编排顺序，没动。
- 触点远近的观感差别主要是颗粒走多远（风力 0.55–1.45 倍），朝终点的偏转只有几度。若用户觉得不够明显，可以加大 `TOUCH_TURN` 或改用流体那样的终点吸引。
- 120 Hz 与新的刷新率投票只在三星 SM-S9180 上验证过。别的厂商对 `Surface.setFrameRate` 与 uid 帧率覆盖的处理可能不同；
  GPU 弱的设备上 120 Hz 的每帧开销没有量过（这台每帧 1–1.5 ms）。144 Hz 面板上飘散按 144 帧出，没有限到 120。
- 流体仍是 60 Hz（轨迹按 60 Hz 预算、缓存按采样数取），要上 120 Hz 得把预算与缓存的采样率一起改。
- 首页空闲时不再投 60 Hz，首页滚动会跟随面板到 120 Hz；这一项没有单独复测首页滚动的帧率（2026-09-26 的分析指出过它是限制之一）。
- 左滑补帧只在三星 SM-S9180 上验证过。主线程更新距 vsync 超过半个节拍间隔（约 4.2 ms，主线程卡顿时）的那一拍仍会漏，
  补帧窗口取半拍是为了让补出来的帧与下一拍的帧至少隔半拍；别的设备上 SurfaceFlinger 的取缓冲时刻不同，这个窗口可能要调。
- 2026-10-06 进度核对：`q34` 回归已完成，但 `s2` 左滑的上屏统计与录屏实际内容变化次数仍未对齐。补帧开时日志 121/121，缩小录屏仅约 71 帧变化；
  三组帧率覆盖均为 120 Hz，不能简单归因于录屏限为 60 Hz。需核对慢滑进度与 120 Hz 模拟时间量化、固定区域和差异阈值，之后再判断视觉验收是否通过。
  见 [进度核对](progress-review-2026-10-06.md)。本次只分析已有资料，未修改代码或操作设备。
## 2026-10-06：本轮性能优化后的边界

- 左滑从真实按下到粒子接管仍约 100 ms，旧的「首帧Ms」仅覆盖截图完成后建动画规格到首帧。后续继续优化须保持这两个口径分开，并采样识别、截图、首次呈现的完整链路；本轮未把内部阶段缩短当作完整起播收益。
- `ParticleDriftBackground.copy` 在窗口未就绪、区域太小或 PixelCopy 失败时，虽然文案写「按主题」，目前仍可能等到 48 ms 截止时间才返回主题值。本轮成功路径没有触发该问题，未纳入修改；后续可用可控失败场景验证即时回退并检查位图释放。
- 普通非重复帧约 0.87–1.53 ms。本轮未引入静态粒子预计算缓冲；如果以后设备实测仍由 compute 限制，再量额外缓冲与准备时间的总成本，不按着色器代码长度决定。

- 2026-10-07：用户选择的「取消黑白灰额外强调」已接入 Android，深浅主题共用，离屏与单测通过；其他四项建议本轮不迁移。没有新的设备操作授权，实际手机观感、实际 GPU 耗时仍由后续设备验证确认。详见 [Android 实施记录](android-neutral-content-2026-10-07.md)。
