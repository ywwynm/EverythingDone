## 待检验的假设

1. 跟手进度在慢滑时反复落在同一个 120 Hz 模拟状态，渲染器仍执行整套计算与颗粒绘制。如果成立，应能在不改变画面的情况下复用既有颗粒工作面。
2. 内容分析对纯色面板、文字和按钮的重复颜色反复做浮点权重计算；若缓存完全相同 RGBA 的权重、用整字读取像素，结果应逐位相同而分析耗时下降。
3. 计算着色器每帧重算的固定粒子数据占据可观成本；需通过 GPU 基准决定是否值得引入额外缓冲，不能凭代码长短判断。

先检验前两项；着色器拆分若无稳定收益则不纳入。慢滑是否需要连续时间采样属于运动语义问题，本轮优先保持桌面逐帧等价。

## 已验证：重复模拟帧复用

- `ParticleDriftRenderer` 以 120 Hz 模拟帧编号与跳步档位为键复用颗粒工作面，位置合成和内容卡片仍每帧绘制；画布尺寸变化、工作面释放时失效。复用也消除了每次绘制分配 viewport 数组。
- `codex-reuse/bench-result.json`：三星 Adreno 740，重复时间输入的配对 GPU 完整耗时，新建页 1.478 → 0.989 ms（−33.1%）、移除卡片 1.008 → 0.695 ms（−31.0%）、弹窗 0.557 → 0.426 ms（−23.6%）、左滑 0.516 → 0.391 ms（−24.3%）。这是重复模拟状态时的收益，不能外推成全部动画帧均下降同样比例。
- 四类尺寸各比较 8 帧，包含重复时间、倒放、移动合成位置、调整画布尺寸；与关闭复用的生产渲染器逐字节比较均为 0 差异。
- `ParticleDriftContent` 用固定小表缓存完全相同 RGBA 的权重，并按小端整字读取像素；既有逐位对照测试及新增随机颜色、半透明、缓存冲突、不同缓冲字节序测试均通过。

## 计时边界核查

新建页现有「出帧对比」从 `appearContent` 开始计时，不包含首页承接快照和 Activity 启动，不能直接当作点击到首帧。已有 `ParticleLaunchTrace` 从 FAB 抬手记录完整链路，后续沿用该证据补齐测量，并检验首页承接快照能否避免 GPU 像素读回。

首页承接图只交给硬件 ImageView 显示；在 API 31+、粒子新建且样式为飘散、无可见独立 Surface 时改为保留硬件位图，不读回全屏像素。截图失败仍调用原捕获路径，其他条件沿用原逻辑。保持先截图后启动 Activity 的既有顺序。待真机完整链路验证后决定保留。

## 左滑计时口径修正

`ParticleSwipeAnimator.buildOverlay` 在截图完成且方向已知后才创建 `ParticleDismissSpec`，未覆盖其缺省 `requestedAtNanos`，所以历史日志中的左滑「首帧Ms」不包含按下、识别及截图。`ParticleFramePacing` 原注释「左滑在识别时发起」不够准确，不应据此宣称完整输入延迟减少了 11 ms。

从两轮保留的虚构卡片探针结果恢复真实输入与卡片隐藏时刻：基线按下到交接为 102 / 104 / 98 ms，优化后为 99 / 99 / 98 ms。采样随主线程帧运行，误差约一拍，当前没有稳定的完整左滑起播收益；复用的确定收益在 GPU 重复状态渲染。原始证据补存为各运行目录下 `swipe-probe-0..2.json`。

完整新建页脚本区分观察器输入的种类字段与 action 字段，只取触摸 `ACTION_DOWN`；按下到首帧的正确中位为 274.4 → 213.3 ms。抬手回调到首帧 237.3 → 187.9 ms 不受此修正影响。
