# 阴影过渡重新诊断（2026-09-17）

## 基线与验证约束

- 代码基线为 `88e570bb`，上一轮阴影实现已全部撤回；工作区中的旧决策、发布记录保留，不覆盖。
- 当前 `ParticleSwipeAnimator` 在 `prepare` / `activate` 中将卡片整体 alpha 置零，`dispose` 一次恢复；`ThingSwipeReturn` 的 `appearContent` 同样整体隐藏。快照只含卡片内容，不含原生外部阴影。
- 建立 debug 专用的虚构卡片列表，复用生产 `ParticleSwipeAnimator`、`ThingSwipeReturn` 与 `ItemTouchHelper`，用真实系统输入测慢拖、快速拖动、回弹、跨原点及完成后仍留在列表的回位。
- 调试页不调用记事 DAO、不写记事或动画设置。仅操作用户授权的 OPPO 和 Samsung。
- 阴影读数应选择没有邻居干扰的一条边，同时记录 `alpha`、`elevation`、`translationZ`、呈现进度和卡片身份。基线与修复使用相同输入。

## 复现与修复

- OPPO 基线：同一虚构卡片上缘的阴影深度约 26.769 灰阶，激活时一步降到 0，回弹末尾一步回到 26.769。采样来自窗口 PixelCopy，不包含独立粒子 Surface，避免把飞过的粒子误当成阴影。
- 按可能性依次验证：整体 alpha 隐藏导致投影归零；快速输入跳过整个强度区间；按压与 ItemTouchHelper 同时写 z 导致回位深浅变化。
- 保留真实卡片的 RenderNode 及内容，`StablerRecyclerView.drawChild` 在卡片轮廓内部做差集裁剪，只让它的外部阴影显示。快照及粒子材料不变，不新增阴影 Surface，也没有两份阴影要交接。
- `ParticleCardShadow` 独立控制原生阴影颜色的 alpha。强度目标随已呈现粒子进度变化，满幅退场最快 96ms、回升最快 144ms；每次处理至多 32ms，避免单次迟到回调直接跳到终点。慢拖时直接跟上目标，停住后不持续刷新。
- 卡片回位从当前阴影强度继续恢复；同一张卡片快速再触摸复用控制器及原始阴影颜色，不把中间透明值当成新的原值。粒子期间限制按压与 ItemTouchHelper 对 z / scale 的写入，卡片保持布局原位。
- API 29+ 用原生阴影颜色强度及父层 Z 绘制控制；API 26–28 沿用整体隐藏路径，本轮无对应实机。

## 本轮实测纠正的判断

最初尝试在 `InterceptTouchCardView.draw` / `dispatchDraw` 直接跳过内容，回弹路径确实改善，但新 holder 的倒放回位没有改善：Samsung 上强度属性在 0→255 递增，窗口阴影像素一直为 0，最后仍一步变为 7.263。不能据此认定“有 outline + z 就一定能投影”。本次观察具体成立于**新创建且在首次正常绘制前已跳过 draw 的 CardView**。

改为父列表裁剪后，同一 Samsung 回位场景的最大相邻采样变化降到 1.368，起点、终点都是 7.263；OPPO 回位上升阶段最大步进约 1.923，终点回到 26.769。说明真实投影已在卡片内容恢复之前逐渐出现。

随后固定进度截图又发现：只调用 `clipOutPath` 仍会露出完整卡片，父列表的 Z 重排把子节点延后到了裁剪恢复之后。新增独立 Z 区间，并把验证扩展为**阴影外圈 + 卡片内部**两个区域。最终 Samsung 回位 195 个有效隐藏样本的内部像素差全为 0；上升最大步进约 0.889，结束时阴影与起点一致。该轮将上缘采样高度固定为整数 5dp，Samsung 基线相应为 6.889，不与旧版采用另一种像素取整的 7.263 混比。

最终 OPPO 回位上升最大步进约 3.077；快速拖动与跨原点回拖同样恢复到 26.769，内部像素断言通过。Samsung 快速完成的上升最大步进约 1.0，完成回调恰好一次。固定进度截图确认没有残留整张卡片，也没有内部硬边阴影块。

发布包 `202609161709` 的快速甩动补测再次被内部像素断言拦住：旧 holder 的 13 个样本仍有 132 的蓝通道差，新的回位 holder 正常。原因是 ItemTouchHelper 已停止重画，而列表显示列表仍缓存准备期 `drawOriginal`；改阴影颜色只更新子 RenderNode 属性，不会撤掉父列表里的占位命令。`onAnimationStarted` 显式使父列表失效后，同一 Samsung 快速甩动的 54 个有效隐藏样本全部为 0，完成恰好一次，回位上升最大步进约 0.833。首个发布包随即由修正版替代。

## 测量边界

- 数值是原生阴影上缘的空间平均值，相邻 PixelCopy 采样并非严格每个物理显示帧，不可当作动画流畅度或性能基准。
- OPPO 的系统 `screenrecord` 无法创建输出，原始流模式也不返回数据；已关闭本轮本机录制客户端，改用固定进度截图和窗口逐帧像素测量。没有更改设备录制权限。
- 关闭本机客户端后，该次设备录屏进程（19151）仍存在；SIGINT / SIGKILL 都返回 `Permission denied`。没有为清理它而改权限、重启设备或终止此前已有的录屏进程，此限制已在最终答复告知。
- 产物留在 `tmp/swipe-shadow-probe/<serial>/<run>/`，不纳入版本控制。实际业务的隐私认证、习惯打卡分支没有触碰用户数据；本轮验证它们共用的 `ThingSwipeReturn` 换 holder 和倒放链路。

`202609161713` 已发布并安装双机，本地 / 远端完整 APK / 两台安装包的 SHA-256 一致。`final-fling` 的快速完成与倒放回位断言均通过，内部没有原卡片残留，完成回调恰好一次，最终阴影与起始一致；OPPO 上升最大采样变化约 3.38、Samsung 约 0.78。退出调试页面后双机 crash 缓冲区均为空。完整单测 1046 通过、1 跳过。
