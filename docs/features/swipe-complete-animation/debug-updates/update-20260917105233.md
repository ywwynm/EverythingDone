## 卡片粒子恢复 SurfaceView 并同步交接阴影

用户指出上一版为解决阴影跳变改用了 TextureView，而此前切到 SurfaceView 的目的是改善性能，因此要求尝试保留 SurfaceView 的方案。

Android 14 及以上，首页卡片消散、回弹与完成后回聚现复用每个窗口原有的一个 SurfaceView。阴影继续随卡片进入粒子材料，保持原粒径；新增 `ParticleCardSurfaceHandoff`，只在开始、回位的交接阶段短暂显示含阴影的快照层。窗口通过 `applyTransactionOnDraw` 同帧切换，GL 通过 `applyTransactionToFrame` 把切换绑定到对应粒子缓冲，正常播放不再经 TextureView 合成。

一并处理预热后立即取消、外部透明度改写、快速连续滑动、完成后旧卡片停在屏外、回聚及页面退出时的资源回收。Android 13 及以下保留上一版 TextureView 兼容路径，普通弹窗仍沿用原 SurfaceView。

只在魅族 `392QBFED2226B` 的虚构列表中验证，没有访问或改动现有记事、没有修改动画偏好。短滑保持、回弹、跨原点、快甩、完成后回聚、连续滑动、系统取消及回弹中退出均通过；最终合成录屏未见完整轮廓残留或双影，临时图层无残留。完整 JVM 检查 1044 通过、1 跳过。

同一 APK 固定种子、关闭录屏与 PixelCopy 的热运行对照中，Surface 首个提交约 120–128ms，Texture 约 116–160ms。当前只能确认没有额外固定等待及已恢复 Surface 合成路径，尚未证明帧率或功耗显著改善。没有操作已拔掉的 OPPO 或其它设备，本轮未创建 Git 提交。
