# 滑动完成记事动画调试更新

## 滑走之后仍留在列表里的卡片，回位也按档位播动画

用户指出：部分记事左滑之后并不会从列表里消失——习惯只是记一次打卡，目标等记事也可能留在原位——它回到原位置、原状态的过程同样需要动画，按设置里的档位决定是滑动还是粒子。排查确认首页共有六条这样的分支：非记事条目、大于通知目标的类型、需要隐私认证、右滑开始做事的暂停习惯与普通情形、习惯左滑打卡、以及完成后记事仍留在当前列表的情形。它们原本都只做一次变更通知，而列表收尾会把位移与透明度复位成卡片好端端地待在原位，画面上就是弹回来的那一帧。

动手之前有两个结构问题必须先解决。其一，两条消息的先后不固定：业务上这张卡片留不留得住，与列表把卡片归还回来，并没有确定顺序——滑动档在滑走回调里同步就有结论，早于归还；粒子档要等整段消散播完约一秒才知道结果，而消散途中归还早已把卡片复位。本版把这段时序抽成不含任何界面对象的纯逻辑，归还一律先把卡片藏起来，真正要离开的那一条分支负责把它交还给列表自己的移除动画；四种交错各有对应结果，另有超时兜底，任何一条消息没来都不会把卡片永久藏住，并用七项本地检查逐项定死——真机上把四种交错凑齐既慢又难复现，这正是应当在本地锁住的部分。其二，不带附加标记的变更通知会换掉卡片本身：默认动画器在这种情况下会另建一个视图持有者做交叉淡入淡出，被滑走的那张卡片随即回收，回位动画根本找不到它。因此这六处改用带附加标记的变更通知，列表复用同一个持有者原地重新绑定，内容照常刷新，交叉淡入也一并省掉——那一段正是要用回位动画替换掉的。这只影响这六处，没有改动全局的变更动画开关，详情页返回的变更动画按既有决策保留。

回位动画本身：滑动档从卡片飞走的那一侧滑回并淡入，256 毫秒；粒子档复用既有的倒放消散，方向取左或右，正好是左滑消散虚拟触点的镜像，粒子从同一侧重新聚成卡片，起不来时退回滑动回位。方向按实际位移取，不看起止方向常量，因此不受布局方向影响。右滑开始做事只滑回来，不倒放粒子——回位要与刚飞出去的那一段同一种语言，而首页右滑一直只是滑动淡出。另有两处沿用既有经验：藏卡片用不可见而不是透明度归零，否则变更动画会把透明度抢回去；起步之前先结束变更动画，并让卡片以透明度零可见地画过一帧，否则挂在渲染节点上的动画会立刻结束。接管只在滑走回调里登记，拖动排序与半途取消的滑动不会被误当成回位。

共同粒子模型、着色器、时长、密度与任何已认可的视觉参数均未改动。构建通过，本地检查 1035 项，唯一失败是既有的 FableSol 曲线那一项，与本轮无关。

本版没有上真机，请重点复看五项。其一，六条分支的回位是否都播了、有没有哪一条漏掉——漏掉的表现是卡片藏两秒多之后才出现，最容易验的是习惯左滑打卡。其二，粒子档倒放消散用在列表卡片上是新用法，此前只用于新建卡片与弹窗，画面与位置是否正确。其三，滑走回调早于列表归还这个前提，是从粒子档必须在归还清理之前拿到会话反推的，没有在设备上直接观测。其四，带附加标记的变更通知之后，这六处的内容是否照常刷新，例如习惯打卡后的记录、目标的状态显示。其五，拖动排序与滑到一半松手不应被误接管。本轮未提交 Git。
