## 阴影进粒子（第二版）：光源逐项复刻窗口渲染器，交接期不再叠两层（20260916213000）

回到「把阴影抓进快照」这条路，并把你提的「离屏渲染要与显示完全一致」查清楚了。

### 离屏阴影与显示不一致的根因

查 AOSP 的 `ThreadedRenderer.setLightCenter`，光源高度不是主题值直接用的：

```java
final float zRatio = Math.min(displayMetrics.widthPixels, displayMetrics.heightPixels)
        / (450f * displayMetrics.density);
final float zWeightedAdjustment = (zRatio + 2) / 3f;
final float lightZ = mLightZ * zWeightedAdjustment;
```

这台平板上 `zRatio = 1680 / (450 × 2.625) = 1.422`，系数 1.141，**真实光源高度 1497.6 px**，而我上一版按主题值 1312.5 px 算——偏低 12%，`z / (lightZ − z)` 偏大，离屏阴影因此更深更散。

补上这一步之后做了干净对照：取第一行卡片的**上缘**（上方是空白标题区，没有邻居卡片的阴影混进来），快照与屏幕实拍的压暗灰阶在距边 2/4/6 px 处的比值是 **0.94 / 0.87 / 1.13**，可以认为一致。上一版测到的「下缘深 2 倍、左缘浅 15%」是**相邻卡片阴影叠加**造成的假象——列表卡片间距只有 42 px，而阴影余量 30–48 px，必然重叠；只有朝向空白区的那条边可测。

### 松手后偶尔闪一下

根因是快照现在带阴影，而粒子层撤除走的是「先显后撤」：真实卡片已经恢复、粒子层还在的那一两帧里，**阴影叠了两层**。是重叠期差几帧决定的，所以偶尔才出现。

修法是重叠期内只让一层投影，按的是卡片的阴影**颜色**（置透明），等粒子层撤干净再还回去。**没有去动 elevation**，那条路按不住：按压反馈会用 `ObjectAnimator.ofFloat(card, "cardElevation", …)` 一路写它（探针实测交接期被写成原值的 2/3），而抬 Z 那一套又会按 elevation 反推 translationZ 把高度补回来。阴影颜色没人抢，也与 outline、圆角裁剪无关。探针确认交接期 `spotAlpha/ambientAlpha` 都是 0。

### 这一版没覆盖的

**滑走之后留在列表里的卡片回位（倒放出现）仍然没有阴影**：那条路走 `appearContent`，它的抓图链路还要兼容弹窗与「逐个 Surface 合成」（`ParticleSnapshot.capture` 按 `at − rootAt` 把 SurfaceView 的像素叠回底图，底图一带外扩余量这些坐标就都要跟着挪），单独做。

取景框外扩让粒子变粗约 24%（这一格实测 577×166 的卡片，取景涨到 1.53 倍），这是这条路线固有的代价。

请看：左滑到一半停住、回拖取消、**快速甩动完成**（上一版就是这一格不行）、正在做事界面左右滑。设置里「滑动完成记事动画风格」要选「粒子」。

本版已验：`:app:assembleDebug` 通过，单测全过；真机上逐点量过阴影剖面，并用探针确认交接期只有一层投影。
