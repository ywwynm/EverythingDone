## 粒子消散时保住卡片的 elevation 阴影（20260916174550）

左滑完成记事的粒子动画在接管的那一瞬间，卡片的 elevation 阴影整块消失；回拖取消时阴影又一次
性满强度弹回来。这一版让阴影跟着粒子一起退、一起回。

根因：**elevation 阴影不由卡片自己画，而是父容器按卡片 RenderNode 的 z 与 outline 画的，落在
卡片矩形之外。** 首页记事卡的 `cardElevation` 是 8dp，滑动期间 `keepActiveTouchItemAboveSiblings`
还会再抬 4dp，这一层在浅色列表上是明确可见的。于是三处一凑成了现在的观感：粒子接管时
`view.alpha` 置 0，阴影作为 RenderNode 属性的一部分一起归零；离屏快照按卡片自身尺寸取景，
拿不到落在矩形之外的阴影，粒子材料里因此也没有；收尾时 alpha 一次性复位，卡片本体那时已被
粒子聚合到接近完整、看不出跳变，只有阴影是从 0 直接回到满强度。

修法是在卡片原位放一个只有 outline、没有任何内容的替身（`ParticleCardShadow`），粒子播放期间
由它接着投影。阴影像素仍由系统按同一套光源参数生成，与静止时逐像素同源，交接不需要对齐任何
东西。替身挂在**列表自己的 overlay** 上：列表的裁剪因此自动生效（超出列表的那一截阴影屏幕上
本来就是被裁掉的，正在做事界面按直线截断卡片时尤其明显），叠放顺序也跟着对了——在列表全部
卡片之上、在页面控件之下，与真实卡片的阴影一致；overlay 不参与测量布局，挂上来不会让整棵树
重新测量。替身一律按布局位置摆放，不跟 `translationX`、不跟按压反馈的缩放，与快照的取景口径
一致。浓度放在外层容器上、替身自己恒为不透明：Skia 只在 caster 半透明时才把阴影铺满 outline
内部，而这一层正摆在卡片位置上，内圈阴影会叠到粒子画面上去。

阴影浓度跟的是「还有多少内容留在卡片原位」，曲线不是猜的，直接量自粒子模型的释放场
（`ParticleCardShadowFade`）：实测进度 0.17 处还有 78–95% 未释放、0.33 处 42–55%、0.50 处
2–19%、0.65 处已全部释放，因此衰减区间取 0.05→0.65 而不是 0→1。同一份释放场被写成了单测的
对照基准，模型哪天改了释放节奏就会报出来。

顺带说明一条设计取舍：**没有按消散前沿去收缩阴影的形状。** 实测释放顺序是「最右先走、最左
次之、中部最后」（左滑时各列平均释放时刻 0.33 / 0.47 / 0.13），剩余区是从两侧向中部收缩的
窄条，用一个矩形去跟它只会得到一段往回走的形状。浓度是唯一既物理正确、又不需要方向假设的量。

同一根因还影响滑走之后留在列表里的卡片回位（习惯打卡、隐私认证取消这几条）：倒放出现期间
卡片 alpha 同样是 0，末尾恢复时阴影整块出现。这一版一并修了，替身从「完全散开」起步，跟着
粒子一起聚回来。

另外修掉一个顺带发现的问题：正在做事界面把列表常驻浓度烤进快照的那一步，原先在捕获回调里
读容器透明度，而宿主在粒子接管的那一帧就把它还原成 1 了——「绘制过程中就地构造会话」那条路
因此读到的是还原后的值，快照没乘上 0.84，接管时会整体提亮。现在改在会话构造时读。

请重点看这几格：左滑到一半停住、回拖取消（看阴影有没有跳变）、快速甩动完成、正在做事界面
左右滑完成（那里的卡片可能被截断）、习惯记事左滑打卡后的回位。设置里「滑动完成记事动画风格」
要选「粒子」。

本版已验：`:app:assembleDebug` 通过；单测 1048 项全过，其中 `ParticleCardShadowFadeTest` 5 项
是本次新增（含与释放场的逐点对照）。**真机画面未验证**——本机不接设备，这一版按代码分析与
JVM 侧的模型实测发出来，请以你在设备上看到的为准。
