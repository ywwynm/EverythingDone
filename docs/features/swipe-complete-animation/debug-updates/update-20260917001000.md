## 交接：等空帧真的上屏，而不是提交完就算（20260917001000）

"先深了一点然后才回到默认值"——峰值超过默认值，那就是两层同时在。找到了：

`eglSwapBuffers` 只是把帧**交给合成器**，屏幕上还会停留一两帧旧画面（带阴影的快照）。而上一版
的通知钩子（`flushCleared`）就挂在 `eglSwapBuffers` 的下一行——**提交即通知**。于是卡片那一侧
立刻开始把阴影渐入回来，而屏幕上旧帧还在，两层阴影一起出现，旧帧退场后再回落到正常。你描述的
顺序（先深、后回落）和这个机制完全对得上。

改成等那一帧**真的上屏**。判据用现成的两条，都在 `ParticleWindowSurface` 里：

- `surfaceDirty` 为假 → 最后一次提交的是空帧；
- `pending` 队列为空 → 所有提交过的帧都已判定上屏（`resolvePresented` 走
  `ParticleFrameTimestamps` 的真实呈现时刻，并带超时上限，不会把交接卡死）。

通知因此从 `compositeOnce` 移到 `resolvePresented` 的末尾。实测 dispose 到通知的间隔从 **17 ms
变成 49–51 ms**（约三帧），正是合成器那两帧的延迟。这期间屏幕上的阴影一直是粒子层那一层，
卡片这边保持透明，不会叠加。

另外 `needsWork()` 把这个待办队列算进去了，GL 线程不会在还欠一次通知时先休眠；通知不来时仍有
200 ms 兜底。阴影还回去那一下仍是四帧渐入（上一版加的）。

如果还看得出来，剩下的就只有"渐入这 64 ms 里阴影比正常淡一点"——那与"先深"是相反方向，你一看
就能分辨。真要一点差异都没有，只能做那条零交接方案：**让粒子 Surface 的最后一帧就不画阴影圈**
（GL 侧按卡片本体范围丢掉阴影圈的格子），卡片全程保留自己的阴影、根本不需要按住再还回去。

本版已验：`:app:assembleDebug` 通过，单测全过；真机上逐点量过交接时序。设备上的动画档位保持你
设的「粒子」，没有改动。
