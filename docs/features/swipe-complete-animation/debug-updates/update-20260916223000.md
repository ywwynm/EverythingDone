## 交接那一帧：三处叠加源全部堵住（20260916223000）

你让我去看默认状态下的 `cardElevation` 和 `elevation`，量出来是 `z=21 elevation=21
translationZ=0 cardElevation=21 maxCardElevation=31.5`——和上一版恢复的目标值一致，所以那条路
是对的，阴影"还是变了"来自另外三处。这一版把它们都堵住了。

### 一、会话读到了交接中间态（会让阴影永久消失）

交接期我把卡片的阴影**颜色**按成透明，而下一次按下可能就落在那之前（连续快速滑动时必然发生）。
会话一读到透明，收尾时就把"透明"当成原值还回去——**那张卡片从此再没有阴影**。现在原值记在
动画器级别、只取第一次读到的非透明值。

### 二、阴影比粒子 Surface 清帧早一帧还回去（会让阴影突然变深）

`afterRelease` 是在会话 `cancel()` 之后**同步**触发的，而粒子 Surface 要等 GL 线程的下一次
合成才抹成全透明（`ParticleWindowSurface.needsFrame` 在会话退完后再提交一次空帧）。立刻把阴影
还给卡片，那一帧屏幕上就是「Surface 上的阴影 + 真实卡片的阴影」**两层**，观感正是阴影突然
变深一下。现在等两帧（约 34 ms）再还。

### 三、兜底时限太长

`afterRelease` 万一不来，原来要等 320 ms 才还阴影——那段时间屏幕上一层阴影都没有。缩到 160 ms
（`release()` 内部本来只等宿主窗口的下一帧，兜底 100 ms）。

### 实测

`PROBE-REMIND` 上缘（无邻居阴影干扰）逐点量：冷启动 / 连滑 2 次后 / 再连滑 2 次后三列**逐点
相同**（15.3 / 11.3 / 6.3 / 1.3），不累积也不消失。上一版修掉的 z 残留也仍然成立（回位后
`21 / 21 / 0`）。

### 如果还看得出来，麻烦说一下方向

交接那一刻跨着两个 Surface，理论上做不到绝对同帧，只能把差异压到一两帧。所以还剩两种可能，
**观感完全相反**，你告诉我是哪一种我就能直接定位：

- **阴影突然变深一下** → 还有叠加源，两层同时在（往"再多等一帧"的方向调）；
- **阴影先没了、随后才出现** → 是我按住的那段还回来得太晚（往"提早还回去"的方向调）。

另外这一版起**不再改你的设置**——你设的是「粒子」，之前我每次测完都当成默认值改回「滑动」，
那是我搞错了，抱歉。设备上现在就是「粒子」。

本版已验：`:app:assembleDebug` 通过，单测全过；真机上量过默认值、z 与阴影剖面。
