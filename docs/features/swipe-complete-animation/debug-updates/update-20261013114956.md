## 修复粒子预热取消后，滚动列表偶发空白卡片和异常阴影

用户反馈：稍作按住后不抬手滚动列表，某张记事可能只剩空白矩形和浓重阴影；短卡片较易观察到，渐隐档未发现。本轮在三星和 OPPO 平板复现相同屏幕现象，并确认卡片的透明度、可见性、尺寸及圆角属性均正常。

根因在捕获资源的生命周期：粒子预热的离屏绘制借用了真实 View 的子绘制节点，取消／释放后部分子资源被清理，但原卡片仍将父绘制缓存视为有效。只改变清理线程不能解决；释放后同步通知被借用的 View 重建缓存，才消除了原复现。

- ParticleViewCaptureTree 记录借用范围，释放时只发出一次正常绘制失效通知，包括已经离屏的缓存卡片；不重绑记事、不重新加载媒体，也不在每帧刷新整个列表。
- ParticleLiveBackdrop、ParticleHardwareSnapshot、Doing 整页及同步快照兜底统一补齐清理与失效；共享节点的清理与主线程记录串行。独占软件位图的前景及 GPU 读回仍走原后台队列。
- 保留 SurfaceView、动态背景、原有阴影、手势识别、粒子轨迹和首尾交接。保留应用内对照与诊断导出，新增捕获树清理耗时记录。

三星、魅族、OPPO 平板最终 21 组列表回归通过，包含 342 次滚动／短滑输入、4156 个可见卡片像素样本，以及媒体、清单、正在做标识和批量退出恢复。另有 18 组 Doing、独立 Surface／连续弹窗、设置页消散回聚测试通过。正常包编译成功，1448 项单元测试无失败、1 项跳过。

两种粒子的同条件持续提交间隔与旧包接近；魅族初轮一次首帧等待和长提交停顿未在重复测试中再现，原始结果保留，未把它宣称为已解决。所有测试只操作独立测试包的虚构数据，原应用与既有记事未修改。用户自己的 OPPO 手机与卓易通仍请安装此包复测。
