## 阴影替身不再露出系统画在卡片内部的那一块（20260916181019）

上一版（202609160946）你截到的问题：粒子把卡片内容带走之后，卡片矩形**内部**露出一块比卡片
小一圈、四边硬边的浅色区域。这一版把它去掉。

你的判断对了两条：它在 Z 轴上位于卡片之下（不是压在内容上面），而且它就是系统画 elevation
的内部产物。几何上能对上本影区：以卡片 840×490 px、滑动时 z 约 12dp 估算，本影相对卡片向内
收缩约 `2400 × 36 / 1800 = 48 px`，并因光源在屏幕上方中央而向下偏移——实测那一块的边距正是
「上 145 / 下 70」这种不对称。静止时它被不透明的卡片挡着，所以平时根本看不见；现在卡片交给
粒子了，替身自己没有任何内容去遮它，就露了出来。

上一版我假设「不透明 caster 时系统会剔除被遮住的那部分阴影几何」，据此让替身恒为不透明、把
浓度放到外层容器。实测说明这条假设在你的设备上不成立。这一版不再推断平台内部怎么画，而是让
结果确定：阴影层先画进一个离屏层，再**按卡片的圆角矩形擦一遍**。卡片矩形内部因此一定是透明
的，不管系统往那里画了什么；那一块的画面本来就该由粒子和快照负责，剩下的外圈渐变正是静止时
能看到的那一圈。

离屏层还顺带堵住另一种可能：容器没有自己的离屏层时，阴影绘制内部若有任何擦除动作，会直接
落在列表的共享画布上、把已经画好的内容一起擦掉——那同样会表现为「露出一块浅色」。两种可能
现在被同一层挡住。

代价是每帧多一次离屏层合成。为此把这一层的尺寸从「列表全域」收紧到「卡片可见区外扩 3 倍 z」
（约 1056×726 而不是 924×1600），父容器自己的裁剪改由绘制时的裁剪补上，卡片滚到列表上下边缘
时阴影仍然按列表边界裁。

请照上一版那几格再看一遍：左滑到一半停住、回拖取消、快速甩动完成、正在做事界面左右滑完成、
习惯记事打卡后的回位。**尤其看卡片内部还有没有任何东西露出来**，以及外圈那一圈阴影的浓淡
变化是否跟得上粒子。

本版已验：`:app:assembleDebug` 通过，单测 1048 项全过。**真机画面仍未验证**——本机不接设备。
