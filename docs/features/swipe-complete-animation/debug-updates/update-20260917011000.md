## 首页粒子滑动的阴影连续过渡

### 本次需求

修复首页左滑粒子动画接管时阴影突然消失，以及松手回弹、完成动作后卡片回位时阴影突然出现的问题。前轮阴影改动已撤回，本次从撤回后的代码重新复现和验证。

### 实现

- 阴影继续由真实卡片产生。列表只裁掉卡片轮廓内部的内容，把内容交给粒子显示，阴影不进入粒子快照，不增加第二份阴影。
- 为裁剪建立独立的 Z 绘制区间，避免整张卡片被延后画到粒子下方；快照大小、粒子数量和运动模型保持不变。
- 阴影强度跟随已显示的粒子进度，并限制变化速度：完整淡出最快 96ms、恢复最快 144ms。快速拖动及一次迟到的回调也不会一步跳完；极快完成会先等短退场结束，再移出旧卡片。
- 回弹与完成后回位都从当前强度继续，卡片保持正常高度，避免按压动画和滑动抬高叠加造成恢复时额外加深。
- 共用的正在做事界面同步采用原位投影，修正容器透明度读取时机。Android 10 及以上采用新方案，旧系统保留原有动画路径。

### 验证

只在不读写记事数据的虚构列表中，通过真实系统输入调用生产动画代码，未操作已有记事或修改动画设置。

OPPO 平板与 Samsung 手机均验证了回弹、快速拖动、跨原点回拖以及完成后更换卡片再倒放回位。窗口像素采样确认阴影逐渐变化、最终深度与起始一致；卡片内部像素和固定进度截图确认粒子下方没有完整卡片残留。已测量 OPPO 原始阴影一步跳变约 26.8 灰阶，本轮回位上升的最大相邻采样变化约 3.1；Samsung 约 0.9。数值不是逐物理帧的性能基准。
