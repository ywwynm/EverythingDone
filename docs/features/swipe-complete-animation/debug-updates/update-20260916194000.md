## 阴影进粒子：快照连阴影一起抓，跟着一起消散（20260916194000）

按你的判断换了方案：**阴影烤进快照、参与粒子消散**，替身那一套整套删掉（`ParticleCardShadow`
与 `ParticleCardShadowFade` 已移除）。替身方案的结构性问题你说得对——就算把露出来的那块弄成
透明，阴影本身也还是停在原地，不会跟着粒子走。

这一版在 OPPO 平板（9018f404）上实测定位，改了三处：

**一、快照的取景框四周按阴影余量外扩，卡片本体套进一个带 z 与 outline 的子节点。** 阴影由父
节点画在子节点矩形之外，于是落进快照。余量不是拍的数，按投影几何逐边算
（`ParticleShadowInset`，纯几何 + 7 项单测）：光源是悬在屏幕上方的圆盘，卡片越靠下、越靠边，
阴影伸得越远，所以四边的余量是不对称的。这张卡片实测是左 54 上 17 右 24 下 55 px。

**二、少了 `Canvas.enableZ()` 就一点阴影都没有。** Z 排序与投影是这对调用打开的（框架里
ViewGroup 画子 View 的阴影用的是 `insertReorderBarrier` / `insertInorderBarrier`）。第一版没加，
实测快照四周的 alpha 全是 0——这一条是整件事的关键，落盘快照逐通道量出来才发现。加上之后
alpha 在 1–50 区间的像素从 40 个变成 37276 个。

**三、光源参数必须从设备读，不能硬编码。** 原来那行 `setLightSourceGeometry(..., 600dp, 800dp)`
+ `setLightSourceAlpha(.039f, .19f)` 是按 AOSP 常见默认值写的；实测这台设备的 `lightZ` 是
**500dp** 而不是 600dp。这四项都是框架的主题属性（`lightY` / `lightZ` / `lightRadius` /
`ambientShadowAlpha` / `spotShadowAlpha`），设备可以覆盖，现在按名字查 attr 读回来，并且用
`hasValue` 判断读没读到——`getDimension` 的默认值会把「没读到」伪装成「值就是这个」。

**四、准备期补画的那一层不画阴影圈。** 粒子 Surface 的首帧与它有一两帧的重叠（先显后撤），
两边都含阴影时那一圈会叠两层，实测接管瞬间阴影深一倍（9.5 灰阶 → 20.8 灰阶）。现在那一层只
补卡片本体，阴影交给 Surface 那一层。

## 实测数据

- 快照里卡片本体与屏幕**逐像素一致**（平均差 0.0，最大 3）。
- 消散推进时阴影跟着一起淡：下缘阴影深度从静止的 9.5 灰阶，随进度走到 14.1 → 11.4；左缘
  14.9 → 6.5 → 3.4；右缘 12.5 → 3.2 → 0.3（粒子从右侧先走，那一侧的阴影先消失）。
- 回拖取消之后逐项回到静止值（9.5 / 14.9 / 12.5）。

## 已知的两点差距

1. **快照里的阴影比系统画的「紧」一些**：紧贴卡片处偏深（下缘约 1.7–2 倍），远处衰减更快
   （左缘 20px 外约 0.5 倍）。光源那一组参数已经逐项对齐，差异来自离屏渲染器与窗口渲染器本身。
   观感上是接管瞬间阴影略微收紧一下，不是整块消失。**请你重点看这一点能不能接受。**
2. **滑走之后留在列表里的卡片回位（倒放出现）这一版没有阴影**：那条路走 `appearContent`，
   它的抓图链路还要兼容弹窗与独立 Surface 合成，一起改的风险大，留到下一轮。

请重点看：左滑到一半停住、回拖取消、快速甩动完成、正在做事界面左右滑。设置里「滑动完成记事
动画风格」要选「粒子」。

本版已验：`:app:assembleDebug` 通过，单测 1050 项全过（`ParticleShadowInsetTest` 7 项新增）；
真机上按剖面逐点量过阴影深度。设备上的动画档位已改回你原来的「滑动」，测试用的临时文件已清理。
