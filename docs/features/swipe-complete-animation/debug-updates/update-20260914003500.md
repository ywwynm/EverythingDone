## 真实操作性能补测与左滑慢拖修复（20260914003500）

用户要求补齐新建和左滑粒子的性能验证，并明确必须模拟真实按钮、返回和拖动，不能通过 ADB 直接调用业务入口。正式测试现由系统输入操作实际界面；ThingAnimationPerformanceObserver 只旁观真实输入、窗口帧、粒子呈现和资源。最初进程内驱动数据已排除，默认安装不启用采样循环。

在 9018f404（OPD2515 / Android 16）对照普通滑动和粒子慢拖，发现手势被 ParticleGestureProgress 取整到 60 档，输入约每 16.7 ms 更新，但画面约每 50 ms 才改变。现保留 60 档缓存和原正向解算，在 ParticleReverseHistory 与 history.comp 中插值相邻状态，ParticleMicroflakeRenderer 以连续进度绘制；普通出现动画的整数帧路径保持原样。

同一卡片、同一 1.2 秒慢拖前后各 4 轮，纹理更新间隔中位数从约 50 ms 降到 16.6 ms，P95 从 67–84 ms 降到 18–22 ms，GL 提交加等待完成 P95 约 3.7–4.3 ms。实际回拖归零与系统取消后卡片像素完全恢复，快速甩动正确完成记事。

补测横屏三档新建、竖屏粒子与 12 行正文长卡片、按钮／系统返回、提前返回及 8 轮反复开关。五轮保存均为 0 帧完整卡片提前可见、0 帧列表动画重叠，确认上一轮“先腾位、再粒子、最后完整卡片”的修复仍生效。29 项相关 JVM 测试通过，包含真实 GLSL 编译。

结果边界：全屏粒子首帧准备仍约 363–412 ms，页面初始化峰值最高约 69 ms，偶有 33–40 ms 纹理间隔，不能声称稳定 60 fps。8 轮开关未见内存持续增长，粒子线程均退出；进程 PSS 峰值约 495 MiB。尚未覆盖低内存机型、长时间压力和功耗。详细方法与数据见新建动画功能目录的 performance-validation-2026-09-13.md。
