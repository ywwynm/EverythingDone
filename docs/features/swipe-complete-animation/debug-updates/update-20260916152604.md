## 被截断的卡片：粒子不再把它补全（20260916152604）

正在做事界面的记事卡片比列表高时会被按一条直线截断，但左右滑动完成记事的粒子动画在接管的
那一帧会把**整张卡片**显示出来，观感是卡片突然长高、被截掉的内容凭空出现。这一版让粒子只
按卡片真正露出来的那一块播放。

根因是两处一凑：截断由列表做，不由卡片做——`DoingActivity` 每次全局布局后把列表高度压到
「时钟下方到按钮上方」这一段，卡片自身高度不变，超出的部分由 RecyclerView 的 `clipChildren`
裁掉，只是没画出来；而粒子快照按 `view.width × view.height` 离屏渲染整张卡片，离屏渲染器不
经过列表那一层，列表的裁剪对它根本不存在。于是材料比屏幕上那一块大，摆放又按卡片的布局
原点，多出来的部分正好长在截断线以下。

修法是让快照只抓露出来的那一块，动画层跟着挪到那一块的左上角。新增两个文件：
`ParticleVisibleBounds` 是纯几何（逐层并进容器的裁剪矩形，附 7 项单测），`ParticleCardClip`
沿父链读出每层的 `clipChildren` / `clipToPadding` / `scrollX/Y` 与 padding。一律按 `left`/`top`
这类布局位置算，不看 translation 与 scale——滑动中的位移、按压反馈的缩放都不改变卡片静止时
露出的形状。整张卡片都露着时返回空，走原来那条不裁的路，逐帧与以前完全一致。捕获侧
（`captureContent` / `ParticleHardwareSnapshot` / 软件绘制）新增可选的裁剪区：离屏节点按可见
区定尺寸，记录前平移画布，outline 用 `Outline.offset` 跟着挪，阴影光源原点加同一偏移。
在捕获时裁而不是抓完再裁，省掉一次整张卡片大小的位图拷贝。

截断线与圆角的三种关系不需要额外判断：圆角本来就由 `setClipToOutline` 烤进快照，而截断是
矩形裁剪，两者相交自然得到「完整圆角 / 半截圆角 / 直角」。

影响面要说清楚：`ParticleSwipeAnimator` 由首页与正在做事界面共用，**首页上被列表上下边缘截住
的卡片**（滚到一半时滑动）也会跟着按可见区播放。那是同一个缺陷的同一处修复，不是新行为。
滑走之后回位的倒放出现走的是另一条路（`appearContent`），这一版没有动。

本版已验：`:app:assembleDebug` 通过；新增的 `ParticleVisibleBoundsTest` 7 项全过。
**真机画面尚未验证**——原定用来测试的魅族这一轮从 adb 上掉线了，OPPO 平板锁着，所以这一版
是照代码分析发出来的，请以你在设备上看到的为准。
