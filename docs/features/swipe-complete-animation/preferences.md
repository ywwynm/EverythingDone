# 功能偏好

## 2026-10-09 撤回方向预判与后台准备取消

- 用户阅读三机复验文档后要求撤回本轮粒子准备优化，保留清单项解析改动。当前恢复此前按下预热，不继续完善这轮已撤回方案。

## 2026-10-09 滚动优化需维护横滑首帧响应

- 用户强调按下预热的目的就是降低滑动卡片时粒子动画的延迟；评估方向判定与延迟准备时，必须同时衡量横滑首个非零粒子画面的响应，不能只验证竖滑变顺。
- 当前仅分析方案。共用范围、早期预判与准备分层的候选及风险见 [首页滚动性能后续讨论](../home-list-scroll-performance/design-discussion-2026-10-09.md)。

## 2026-09-19 从触摸起点开始消逝

- 首页和 DoingActivity 滑动完成记事时，粒子消逝至少有一个起点对应本次手指最初按下的位置，其余起点仍然随机。
- 起点固定在原卡片上，不随手指移动；粒子飞出方向继续服从滑动方向，沿用设置中的粒子参数。

## 2026-09-18 顶栏遮挡连续性

- 左滑、消散、回弹和回聚期间，首页顶栏及半透明模拟阴影保持原有前后关系；不能在接管粒子后露出被顶栏遮挡的卡片。
- 与菜单批量移除统一修正；沿用现有粒子参数和两台授权设备，详见 `selection-removal-animation/preferences.md`。

## 2026-09-17 FAB 保持在卡片动画上方

- 用户确认采用推荐方案：起滑、消散、回弹和回聚时，FAB 始终位于卡片、阴影及粒子之上，不能在交接帧短暂被覆盖。
- 修正需同时覆盖临时快照和播放中的 Surface，保留 SurfaceView 方向；测试页需加入真实 FAB 控件及遮挡场景。

## 2026-09-17 改用 SurfaceView 验证同步交接

- 用户要求尝试用 SurfaceView 解决阴影消散与回位，保留之前减少应用内合成的性能方向；不能仅凭视觉回归通过认定性能没有退步。
- OPPO 已拔掉，本轮仅授权操作魅族 `392QBFED2226B`。设备现已在线（MEIZU 20 Inf）；继续只用虚构卡片，不读写现有记事或修改应用偏好。

## 2026-09-17 阴影应与卡片共同消散

- 用户反馈上一版短距离左滑后仍能看到原位的卡片轮廓和阴影；独立调节完整阴影的透明度不满足要求。
- 阴影应进入粒子材料，与卡片一起消散、回聚，不能在下方留下完整轮廓。
- 三星已拔掉，本轮真机授权改为 OPPO OPD2515（9018f404）和魅族（392QBFED2226B）。继续仅使用不读写业务数据的虚构测试卡片。

## 2026-09-17 阴影过渡重新诊断

- 首页左滑粒子消散、松手回弹及完成动作后回位时，阴影都应自然过渡，不能瞬间消失、出现或短暂变深。
- 本轮授权测试 OPPO OPD2515（9018f404）和 Samsung SM-S9180（R5CW20BLNKL），不得影响现有记事。
- 优先用不读写业务数据的虚构卡片调试页面复现；不修改设备的动画偏好。

## 2026-09-14 回拖崩溃与快速起滑

- 必须覆盖手指不松开、向左拖动后回到原位及略微越过原点的操作；用户日志显示 Android 16 在绘制 DecorView 时发生子节点被移除异常。松手自然回弹与未回到原点不能替代此回归。
- 优化按下后立即左滑的首次响应，按下预热不能假设用户会停留；同时测量交互到首个非零粒子进度的延迟与播放帧率。
- 设置标题改为“左滑完成记事动画风格”，原“滑动”选项改为“滑动渐隐”，同步全部支持语言。
- 本轮用户授权在 9018f404、R5CW20BLNKL 上通过实际系统输入测试；后者为新增 Samsung SM-S9180。

## 2026-09-14 起步跟手与图片圆角

- 不仅播放中的进度要连续，左滑开始时也要尽快响应手指，不能在卡片静止约 0.3 秒后才接管。
- 含图片卡片的粒子快照必须保留实际轮廓；图片卡片使用的自定义圆角不能在动画中变为直角。

## 2026-09-13

- 粒子消散进度由手指左移距离控制，允许手指回退后恢复此前画面。
- 消散方向固定向左；在设置中提供动画选项并同步全部支持语言。

## 设备上的设置不要动（2026-09-16）

**用户的「滑动完成记事动画风格」是「粒子」(`swipe_complete_animation=1`)。** 2026-09-16 我在
第一次读到 0 之后就把它当成他的原值，每轮真机验证结束都 `sed` 改回 0，连着覆盖了他好几次设置。

规则：**验证需要某个档位时直接用他已有的设置**，确实要临时改就在同一轮里改回去，并且改回的是
**读到的那一次原值**——不是「第一次见到的值」。更稳的做法是先问他，或者干脆按他的设置来设计
验证路径。
