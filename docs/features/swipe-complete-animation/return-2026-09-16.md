# 滑走之后留在列表里的卡片，回位动画（第三次，真机实测）

## 需求与前两次的失败

习惯左滑「完成」只是记一次打卡，目标等记事也可能留在原位，私密记事还要先认证——这些卡片回到
原位置的过程需要按「滑动完成记事动画风格」播动画。

2026-09-15 做过两版（debug `202609151007`、`202609151018`），用户实测都不成立：第一版是卡片
**藏 2.4 秒后才出现**，第二版是**卡片直接不见了**，整体撤回到 `a72b83cb`。两版的共同错误是
**按推断改时序，从没在真机上看过实际发生了什么**。这一轮先测后写。

## 实测：探针量到了什么

2026-09-16 在 OPD2515（1680×2520，横屏，4 列）上加临时探针，记录 `onSwiped` / `clearView` /
业务判定的到达时刻与卡片每一刻的 `translationX` / `alpha` / `identityHashCode`。测试用自建的
习惯记事 `PROBE-HABIT-0916`，不碰用户原有记事。

**滑动档，修改前：**

```
 0.5ms  onSwiped          view=56bf6aa tx=-2520 alpha=0.00   ← 旧 View
 4.5ms  notifyChanged 后   view=56bf6aa            children=15
24.9ms  +0ms              view=c78684e tx=-2520 alpha=0.00   ← 换成新 View，children=16
131.6ms +120ms            view=c78684e tx=-1664 alpha=0.34
290.2ms clearView.enter   view=56bf6aa tx=0 alpha=1.00       ← 归还的是旧 View
407.1ms +400ms            view=c78684e tx=0    alpha=1.00
```

由此确定四件事，每一件都推翻了前两版的前提：

1. **滑走后卡片停在 `translationX = -RecyclerView.width`**（−2520 px），不是卡片自己的 577 px。
2. **`notifyItemChanged` 会在约 25 ms 换上另一张 View**，由 `DefaultItemAnimator` 从 −2520、
   透明度 0 动画回原位。
3. **默认那段动画并不是「没有」**：卡片要走完约 75% 才进入屏幕（`tx > −619` 才可见），只剩
   最后几十毫秒可见——这正是「啪地弹回来」的由来。
4. **被滑走的旧 View 仍归 ItemTouchHelper 管**，`clearView` 约 290 ms 才到。

第二轮实验直接验证了前两版为什么坏：**给这几处的 `notifyItemChanged` 加 payload**（让 holder
原地复用、保住被滑走的 itemView）之后，

```
30.0ms   +0ms     view=c810aef tx=-2520 alpha=0.00  children=15   ← holder 复用了
2619.7ms +2600ms  view=c810aef tx=-2520 alpha=0.00               ← 一直没动
```

`clearView` **2.6 秒内根本没来**。原因是它由「这张 View 从窗口上摘下来」触发，而摘下来又要靠
换位动画换掉它；holder 一复用，这条链就断了，**没有任何人把卡片放回来**——这就是用户看到的
「卡片直接不见了」。更糟的是在此期间 ItemTouchHelper 每一帧都把 `translationX` 按回 −2520，
第三轮实验里「在旧 View 上摆好起点」被它当场抹掉（14.4 ms 设成 0，27.6 ms 又变回 −2520）。

## 方案：接管那张新 View

既然旧 View 归 ItemTouchHelper 管、而新 View 是自由的，就**接管新 View**：业务判定说「留下」
之后的下一帧，按位置把新 View 找出来，`endAnimation` 掉默认的换位动画，按档位重新播一遍。

- **滑动档**：从卡片自己左边一个身位（`itemView.width`，577 px）滑回来并淡入，256 ms，
  decelerate——全程可见。
- **粒子档**：`appearContent` 倒放消散，方向 180°（虚拟触点落在卡片正左方，正好是左滑消散的
  镜像），粒子从同一侧重新聚成卡片。起不来就退回滑动回位。
- **不改 `notifyItemChanged`**：不加 payload，换位动画照常发生，只是被我们接管。**接管失败
  （找不到新 View 等）时默认动画照旧把卡片放回原位**，最坏只是没有改善，不会把卡片弄丢——
  这是前两版最缺的那道保险。
- **只在卡片真的离开过时才回位**：右滑（开始做事）实测走到这一步时 `tx=0 alpha=1.00`，卡片
  根本没离开，再播一段滑入是凭空多出来的动画。

## 实测结果

同一张卡片、同一条手势，120 ms 时刻的对比：

| | translationX | 屏幕上可见宽度 |
|---|---:|---:|
| 修改前 | −1767 | 0 / 577 px |
| 修改后（滑动档） | −214 | 405 / 577 px |

粒子档：新 View 停在 `tx=0 alpha=0`，粒子在上方聚拢，约 1.2 秒后透明度恢复 1。截图确认粒子
确实从左侧聚向卡片区域（`card2.png`，卡片区域非背景像素 10.5%，呈现为向右汇聚的粒子带）。

其余路径：

- **普通记事左滑（移除）**：`changed=false` → `notifyItemRemoved`，不触发回位；列表从 17 条
  变 16 条，正常。
- **右滑（开始做事）**：`displaced=false`，不播回位；`StartDoingActivity` 正常打开，返回后
  卡片完好。
- **滑到一半松手**：`onSwiped` 根本不触发，探针无输出，不接管。
- **连续 6 轮**（两档各 3 轮）：每轮结束后卡片都回到完全相同的 bounds，区域填充率 100%，
  没有残留、没有半透明、没有卡片丢失。

## 验证状态与边界

`:app:assembleDebug` 通过；单测 1036 项，唯一失败是既有的 `FableSolCurveFairnessTest`
（与 `a72b83cb` 基线同一项、同一数量，本轮未增减用例）。临时探针已全部删除。

**六条「留下」分支共用同一个入口**（`stays(listPosition)` → `ThingSwipeReturn.start`），
本轮在真机上直接验到的是**习惯打卡失败**这一条（两档各 3 轮）。其余五条——非记事条目、
大于 `NOTIFICATION_GOAL` 的类型、需要认证的私密记事、右滑的暂停习惯、完成后仍留在当前列表——
走的是同一段代码，但**没有逐条在设备上复现**。其中私密记事那条还有一个未验证的细节：认证界面
若导致 `onPause`，`cancel()` 会把回位收尾成直接就位（卡片正常显示，只是没有动画），不会出错。

设备状态：测试用的 `PROBE-HABIT-0916` 与 `PROBE-NOTE-0916` 已移入可恢复的回收站，首页恢复为
原有的 2 个文件夹 15 条记事，动画档位改回用户原来的「滑动」（0），设备上的临时文件已删除。
