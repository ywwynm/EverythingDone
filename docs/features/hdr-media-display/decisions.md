# HDR 显示决策

## 2026-10-16：结束常规包的诊断暴露

- 按用户要求移除设置入口、HDR 标识长按入口及 debug 清单中的 HDR 对照页／回归仪器注册；删除无调用方的 debug／release 入口门面。单击 HDR 标识继续切换显示，不改渲染与生命周期策略。
- 查看器诊断默认关闭，日志执行器延迟创建；只有显式恢复注册并运行的开发回归仪器在进程内临时开启记录，不新增 Intent、偏好或产品开关。保留诊断／导出源码、测试和已有调查资料，便于后续定位。
- 将这轮卓易通 PQ、APP5 兼容、首帧与动态照片修复及相关发布记录合并提交；其他功能的未提交改动不纳入。

## 2026-10-16：首次揭示由 PQ 首帧统一完成

- 用户继续反馈大图加载结束后先亮、再暗、再渐亮。首帧回归确认原图在 PQ 就绪前可见，六次均为单层创建。改为保留加载态直到 PQ 首帧完成，避免原生位图和 PQ 容器之间的初始亮度跳变；不据此宣称已确定卓易通内部的白亮度映射。
- 仅兼容路径处理初次加载的当前静图。PQ 就绪后保留 PhotoView 的 Drawable、矩阵和触摸，但停止其像素绘制；撤层恢复。初始等待有超时、强制 SDR、页面切换及失败回退；不在退出冻结时揭示迟到原图。
- 在后台预检无原生 Gainmap 的 JPEG 头，确认只包含已知普通元数据时立即 SDR 显示并跳过重复解码。未知格式及 HDR 线索继续原解码路径，边界解析失败不等于无 HDR。
- 保留同层开关、动态照片交接、窗口退出冻结、PQ 参数和诊断文件导出。实际物理亮度平滑程度仍以用户的卓易通复测为准。

## 2026-10-16：视频交接与窗口退出保持已有输出

- 用户提供动态照片结束和返回的黑帧录像，继续要求优化首次 SDR 到 HDR 延迟；本轮覆盖下述旧方案的“播放、暂停即撤层”策略。
- 动态照片的 TextureView 保持原播放和矩阵规则；同一张图的 PQ 层留在其下方，播放时收至 SDR，结束恢复增益，不再经历 Surface 重建。尚未就绪时也允许在播放期间完成准备。普通视频、GIF 和非卓易通 Android 的 HDR 路径保持原逻辑。
- `finish`／`onPause` 冻结当前增益和输出，阻止迟到准备回调重新挂层；`onStop` 才释放 Surface。`onResume` 恢复当前页。播放器的延迟揭示、完成、错误及尺寸回调校验播放器身份，避免旧回调操作新的播放实例。
- 同一 180 ms 曲线由 EGL 工作线程按经过时间推进，首帧 Callback2 完成后开始，不依赖主线程 ValueAnimator。空闲时不持续绘制；原有 PQ 编码、参考白和 APP5 公式不变。
- 首帧测量按打开代次隔离，防止上一窗口退出动画污染新窗口时间。新增数据准备、主线程排队、首个增益帧、完整增益帧及窗口冻结日志，继续使用原 TXT 导出。

## 2026-10-16：同层切换和首帧准备

- HDR 开关与生命周期暂停分开：当前图的开关复用 PQ Surface，只在 180 ms 内调整增益；切页、播放、空间模式及后台仍撤层。没有已显示的层时，强制 SDR 不会新挂 HDR 层。
- 首帧保留 SDR 基图，通过 SurfaceHolder.Callback2 完成重绘同步后才增加增益，避免 alpha 切换和未绘制 Surface 的交接。错误与取消要释放重绘回调，不能持有 EGL 锁等待系统事务。
- 兼容路径优先取得 Glide 位图和 Gainmap 的独立副本；大图仍遵循原采样和内存预算，未知格式保留 ImageDecoder 回退。只在静图兼容分支阻止小图放大、绕过派生磁盘缓存，保留内存缓存。
- sRGB／Display P3 的不透明 ARGB_8888 基图直接上传 sRGB 纹理，保留其基色矩阵，避免 FP16 中间转换；其它格式继续 FP16。APP5 参数及最终增益公式不变。
- 首次创建时并行准备当前页，输出层仍等待前台状态；不改变普通 Android 的 HDR 路径。后续卓易通物理过渡由用户实测，测试设备的接口就绪时间不能当作面板 HDR 响应时间。

## 2026-10-16：接入正式图片查看器

- 用户决定暂停 APP5 私有重建曲线调查，将已确认观感接近图库的模式 6 接入 `ImageViewerActivity`，沿用自动参考余量 4 倍及现有 PQ 编码，不改动未知私有参数。
- 默认仅 API 34 及以上、命中碰一碰 `TapGroupRolePolicy.isKnownCompatibilityEnvironment` 的环境启用；普通 Android 保留现有 PhotoView／系统 HDR。现有判据是 HUAWEI 厂商与 `System ` 显示版本特征，属于已观察环境兼容规则，不宣称识别所有卓易通版本。
- PQ 层跟随 PhotoView 矩阵，不替换其触摸、缩放和图片加载；只处理当前静态图片，切页、动态照片／视频播放、空间照片、后台和失败时撤下。原生 Gainmap 优先，APP5 使用已验证的严格解析和参考曲线。
- 用户授权在 `3B1629006YC00000` 验证并发布阿里云 debug。该机实际为 OPPO PLZ110；测试通过 debug 仪器临时覆盖环境判据，正常启动保持原判据，不向用户设备写入常驻开关。不能以 OPPO 测试代替卓易通最终观感验证。
- 保留 HDR 对照页和日志文件导出，追加查看器的解码、输出和回退事件；不记录原图像素、记事内容或原始文件路径。

## 2026-10-16：APP5 曲线研究的验收依据

- 用户希望在模式 6 已接近华为图库的基础上继续精确还原。将“自动余量下接近、4／8 倍差异不明显”记为视觉反馈，不视为参考公式或私有参数语义已被证明。
- 本轮找到独立 Old 内核、参数表与固定常量，但缺少可验证的完整算法；不凭常量大小或字段看似合理就替换当前曲线。后续以原生 HDR 像素、受控输入和另一张样本验证来确认重建公式，再单独核对显示亮度适配。

## 2026-10-16：按封装适配华为照片

- 两份 Pura 70 Ultra 原文件为 APP5／CUVA 路径，标准增益图标记未检出；第三张现场照片同时带 Vivid APP8 和标准 ISO 21496-1，用户确认 PQ 正常。文件识别与兼容分支依据实际元数据，不能依据 HDR Vivid 名称或华为品牌一概判定。
