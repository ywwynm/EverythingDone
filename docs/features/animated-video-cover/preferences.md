# 动态视频封面偏好与验收要求

## 2026-10-15：复杂列表拖动期间必须显示内容

- 用户要求在包含大量长清单、图片、视频和派生 GIF 的复杂列表中验证，触发足够多的独立加载，不能只用单个视频和简单文字卡片。
- 拖动须横跨整个列表，检查的是拖动／滚动过程中的其它卡片内容；停滚后才恢复不能算通过。
- 同时检查持续加载 GIF 时的内存变化、资源回收和失败原因。用户怀疑卓易通可能限制 Android 应用内存，此点作为待验证条件，不能写成已确认的平台事实。
- 延续先复现再修复的要求，允许继续使用此前授权的三台设备和隔离测试包。

## 2026-10-15：内存优化约束

- 继续深入定位高内存的具体来源，检查 GIF 离屏释放、重复解码、位图与图形缓冲；先复现和归因，再决定修复。
- 优化必须保留拖动过程中其它记事的正常加载与播放，不通过停滚后才加载、停止动图或改变既有功能和 UI 表现来降低内存。

## 2026-10-15：普通滑动与离屏返回

- 普通手指滑动、手指持续接触及 fling 期间，加载完成的 GIF 应及时显示并播放，不能持续显示加载圈直到 IDLE。
- 已经显示过的 GIF 离屏返回时，应减少重复加载和加载圈；继续遵守有界内存及正式回收释放要求，不恢复无限持有动图。
- 验收须覆盖普通 RecyclerView 的 DRAGGING／SETTLING 状态；长按卡片后的边缘自动滚动不能替代这两类检查。

## 2026-10-15：取消暂停后的性能对照

- 用户要求用大量 GIF、视频和长清单的同一复杂列表，比较取消暂停前后的流畅度与内存；覆盖普通触摸、fling、长按拖动以及选择模式滚动。
- 必须同时记录实际加载／播放，不能以恢复滚动暂停、降低画质或改变 UI 为优化手段。没有配对性能证据时，不宣称没有退化。
- 魅族冷却补测遇到锁屏后，用户要求“先按已有结果整理”。当前只整理现有证据，补测暂缓，不等待解锁后自动重试；保留未确认的异常及后续项。
