# 普通滑动与 GIF 离屏回显

## 反馈与覆盖修正

用户反馈 fling 或手指持续接触时 GIF 一直转圈，离屏返回也频繁转圈。继续要求先复现、核对历史、保留滑动中的加载播放及前轮内存回收优化。

前轮长按卡片进入 MOVING 后由控制器执行边缘自动滚动，RecyclerView 可保持 IDLE；它验证了卡片拖动，但未覆盖普通手指滑动的 DRAGGING／SETTLING。本轮新增隔离包 `RegularMediaScrollAudit`，真实注入普通手指滑动、按住及 fling，再单独记录同一卡片离屏返回的等待。

## 历史与初始复现

- `43e0ee2f3`（2016-07-25）明确在非 IDLE 暂停图片请求；后来迁移 Kotlin 时保留，当前暂停的是 Application RequestManager。
- `d4cc84298` 引入视频动图时主动增加 M2，滚动时停止可见动图以减轻软解负担。用户当前要求修改此行为，需验证实际滚动播放，不能只取消加载暂停。
- `1b4c07096` 已为静态封面引入 adapter 级有界位图缓存，同步回显；当时明确暂不调整滚动暂停。后续 GIF 分支绕过该烘焙缓存，须区分正常缓存淘汰与异常重复请求。

`regular-samsung-red-1015`：37 张混合卡片，541 个采样，其中 DRAGGING 123、SETTLING 128；两种状态的请求暂停均为 100%。动图加载圈样本分别为 80、189，惯性滑动无帧变化。原数据库／设置哈希一致。测试已按“滑动期间请求被暂停”断言失败。

排序假设：全局请求暂停阻止新媒体交付；M2 停止已显示 GIF；GIF 缺少静态回显导致淘汰后空等；若前三者不能解释，再查重复请求／解码耗时。每次只调整一个因素，保留对照。

## 单变量结果与修复

`regular-samsung-unpaused-1015` 仅删除首页全局 pause/resume：所有采样的请求暂停变为 0，滑动加载圈从 269 个降至 1 个；但已显示 GIF 在手指接触时仍被 M2 停止，按新断言失败。再删除 M2 的 `regular-samsung-playing-1015` 中，普通滑动／fling 均有连续帧变化，停止样本为 0。

第二轮同时捕获了生命周期缺口：退出后仍有 3 个 loader 运行。owner 证明三者位于 RecyclerView 的 `mCachedViews`，而非前轮已经清理的 RecycledViewPool。新增 attached/detached 可见性同步；自定义 `DrawableImageViewTarget` 在 Glide 安装 Drawable 后再核对实际附着与显示状态，避免未附着的预取请求交付后自行播放。保留临时缓存里的请求／画面，只在正式回收时 clear。`regular-samsung-poster-1015` 已验证退出后运行 loader 为 0。

离屏重解码的旧回显等待约 73–105ms。GIF／视频预览现在仅复制已完成裁切的首帧，与静态封面共用原 8–24 MiB 有界缓存；命中时同步作为 placeholder，完整 GIF 请求继续执行。key 复用完整动画内容签名，含实际 GIF 文件大小／修改时间、目标尺寸、裁切与所选视频帧。缓存不持有 GifDrawable 或 decoder，不另行解码首帧。缓存未命中时，120ms 后仍在运行且无画面的同一请求才显示进度，避免本地快速重解码反复闪圈；请求身份与绑定 key 同时保护旧延迟回调。

`poster-meizu-red-1015` 的真实加载入口在清空 Glide 缓存后无法同步回显，断言先失败。修复后缩略图通过，媒体背景初次探针未等布局重新测量，returnKey 尚不存在，不能据此认定缓存失败；随后在同一正式背景加载入口固定原几何检查同步边界。`poster-meizu-final-1015` 两种呈现均通过：首帧像素完全一致、无加载圈、随后恢复 GIF、文件变更拒绝旧首帧、离屏／重附着／正式回收生命周期均正确。常规 RecyclerView 的绑定仍由普通滑动测试覆盖。

缓存上限不变，因此长距离返回且首帧也已被淘汰时仍需正常解码；首次／慢加载超过 120ms 仍可显示进度，不承诺所有场景永远无加载提示。卓易通原宿主和原始媒体仍未直接验证。
