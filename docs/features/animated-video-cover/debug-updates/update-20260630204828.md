# 动态视频封面：改用原生 NDK 编码器（debug 发布）

## 定位结论

上一版逐帧日志确诊：**取帧不慢（~90ms/帧），但纯 Java 的 Square 编码器约 12 秒/帧**（480×320），31 帧要 6 分钟——所以永远到不了 `GEN done`，目录只有不断变大的 `.gif.tmp`。Square 此路不通。

## 本次改动

按"研究 JNI/C++"的方向，换成**原生 NDK GIF 编码器** `io.github.waynejo:androidndkgif`（Maven Central 正规依赖，AAR 自带 arm64-v8a 等四个 ABI）。原生编码约几十毫秒/帧，比 Square 快几十倍。

- 仍保留逐帧计时日志（`f<i> encoded et=..ms`），这次 `et` 应是几十毫秒而非上万。
- 参数暂定 480px / 12.5fps / 2.5s ≈ 31 帧（先确认通畅，再据你反馈把分辨率/帧率往回提）。
- APK 因含原生库四 ABI 略增（每 ABI 约 150–290KB）。

## 后续（你提的"扛进程被杀"）

原生编码已快、生成窗口很短，被杀概率大降。但我接下来仍会把生成迁到 **WorkManager**（持久化、进程重启可恢复、可重试），彻底覆盖"后台被杀"场景——这版先确认原生编码跑通。
