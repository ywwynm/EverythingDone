## 修复普通滑动时 GIF 等待停滚，改善离屏返回的回显

用户反馈普通手指滑动、持续触摸或 fling 时 GIF 一直转圈，已经显示的 GIF 离屏返回后也经常重新加载。本轮核对相关提交历史并补充真实 DRAGGING／SETTLING 回归，确认此前长按卡片后的边缘自动滚动没有覆盖这两种普通滚动状态。

`ThingsActivity` 取消历史上的滚动期间全局图片请求暂停；`BaseThingsAdapter` 取消可见 GIF 的滚动暂停。加载完成即可显示和播放，不再等待松手或惯性滚动结束。原来用于减轻软解负担的策略改为按卡片实际附着状态管理：临时离屏／预取目标暂停动画，返回时保留请求和画面并恢复，正式回收仍清理请求。

GIF 与视频预览的已裁切首帧现在可在原有界位图缓存中作临时回显，随后继续加载完整动画。与静态封面共用原 8–24 MiB 上限，不缓存整个解码器，不提高画质或帧率开销。文件、尺寸、裁切及所选帧变化会使首帧缓存失效。缓存未命中时，120ms 后仍在加载才显示进度，减少快速本地加载反复闪圈；坏 GIF 的静态回退另有失败状态保护。

修复前三星所有普通滑动采样均暂停请求。逐项对照后，三机普通滑动／惯性滚动共 707 个采样中请求暂停、停止播放及加载圈停留均为 0；每台随后完成 97 卡全列表长按往返，80 个媒体全部显示，48 张 GIF 均有帧变化，共 1111 个移动采样通过。退出后运行 GIF loader 为 0，位图缓存未超过原上限。

首帧像素一致性、内容变更失效、离屏与重附着、正式回收及坏 GIF 延迟静态回退回归通过。1496 项 JVM 测试 0 失败、1 项既有跳过。三机原数据库／设置哈希不变，隔离测试包已卸载。缓存淘汰后的实际解码和首次慢加载仍可能出现正常加载提示；卓易通原环境仍待实际验证。
