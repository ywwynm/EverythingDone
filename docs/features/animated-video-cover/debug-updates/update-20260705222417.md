# 2026-07-05 - 修复特殊视频封面不播放（派生 GIF 被静态缓存）

本次修复此前诊断出的问题：在横屏、普通宽度 Thing Card、封面视频位于上方或下方、目标比例为 4:3 时，派生 GIF 已经生成却仍然不播放。

根因：动图加载给 Glide 的缓存签名只由视频派生的 `loadKey` 构成，不含实际被加载的 GIF 文件内容。某一几何下这个 GIF 曾被解码成静态首帧位图并写入 Glide 资源缓存后，即使 GIF 重新生成为正常动图，签名不变、Glide 继续返回旧的静态位图，导致该几何的封面长期不播放。同一 GIF 在其它请求尺寸下能正常播放动图，证明 GIF 文件本身没有问题，问题在缓存。

本次改动（均在 `BaseThingsAdapter`）：

- 主修复：新增 `getAnimatedThingCardMediaCacheSignature(loadKey, modelPath)`，动图缩略图与媒体背景两条加载分支的 Glide 签名改用它——在视频派生的 `loadKey` 之外，叠加实际被加载文件（派生 GIF / 真动图 / Motion Photo GIF）的 `length` 与 `lastModified`。GIF 内容一变签名即变，绕开被静态化的坏缓存、重新解码为动图；视图 tag 与静态回退仍用 `loadKey`，身份判定不受影响。
- 顺带修复 replay 路径的 `:anim` 归一化：replay 重算 `loadKey` 的两处（媒体背景、缩略图）此前漏了绑定路径都有的 `:anim` 后缀，导致动图封面的 replay 快路径退化为每次完整重绑（有下游同 key 短路兜底，非用户可见 bug，但有无谓开销与语义不一致）。抽出 `isAnimatedCoverActive` / `animatedCoverKeySuffix` helper，绑定路径与 replay 四处统一归一化。

说明：旧的坏缓存条目随 Glide 磁盘/内存缓存 LRU 自然淘汰；安装本包后新签名不再命中坏条目，此前不播放的卡片会重新解码为动图。如需立即在设备上验证，可清一次 App 存储 / Glide 缓存。
