## 降低复杂媒体列表的内存占用，保持拖动期间正常加载和播放

根据对 GIF 未及时释放、重复解码和卓易通内存限制的补充反馈，本轮先在授权设备复现并采样，再逐项修改；作决定前核对动图、裁切、请求管理和粒子显示的相关提交历史，保留原有功能及画面表现。

定位并修复两项实际问题：`MediaCropTransformation` 原先每帧重新创建裁切位图，现在复用 Glide 位图池；`BaseThingsAdapter` 原先未清理正式回收的媒体目标，导致回收池内仍有 GIF 继续播放，现在在回收时结束请求并清除旧绑定标记。临时离屏但仍保持绑定的卡片继续沿用原显示流程。

真实列表对照证明原一屏位图池容易被高卡片帧挤出。新增 `MediaGlideModule`，仅在 Android 8.0 及以上、非低内存设备、且不压缩原资源缓存时采用两屏位图池，仍受 Glide 原有总预算限制。保持动图分辨率、帧率、裁切、透明度、颜色、缓存签名、后台生成和失败回退策略。没有采用等待停止拖动才加载或播放的方式。

魅族同条件采样中，拖动期间相关位图累计分配约减少 94%，全程峰值 PSS 从约 1226 MiB 降至 760 MiB，约降低 38%；累计分配量与驻留内存分别统计。120 帧复用用例从 120 张输出位图降为 1 张；48 组像素／透明／色域／尺寸检查通过，包括修改前记录的像素基线。

最终三台设备各使用 97 张复杂卡片、80 个媒体项跨全列表往返拖动，共 1114 个实际移动采样通过；每台 80 个媒体均显示、48 张 GIF 均有帧变化，未出现透明卡片、加载失败或 OOM，退出后运行中的 GIF loader 为 0。1496 项 JVM 测试为 0 失败、1 项既有跳过。原数据库及设置校验和不变，隔离测试包已卸载。

本包同时包含前轮已经复现并修复的拖动源控件复用后误隐藏其它卡片的问题。首条 A／B 疑似误删反馈仍未复现，删除链未修改。尚未直接验证原卓易通环境、其内存限制及用户原始视频，不把 Android 测试结果当作这些环境的结论。
