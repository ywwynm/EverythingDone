# 动态视频封面：生成迁到 WorkManager（扛进程被杀 + 边界情况）（debug 发布）

## 本次改动

把派生 GIF 的生成从内存线程迁到 **WorkManager**（持久化后台任务），满足"后台持续生成、扛进程被杀"：

- 每个视频封面的生成 = 一个**唯一后台任务**（按"视频+帧"定键，重复请求自动去重）。进程被系统杀掉后，任务**持久保留、重启后自动继续**，失败有限次重试。
- **各种 UI 变化无需特殊处理**（按你的思路）：
  - 生成视频 A 的过程中，封面被改成图片 B、或新增图片 C 自动变成封面 → A 的生成**不取消、照样跑完**，A 的 GIF 缓存留着，以后切回 A 即可用；
  - 改了视频的封面帧 → 按新帧生成新的，旧帧产物由缓存上限自动回收；
  - **视频被删除** → 任务检测到文件不存在，**优雅放弃**（不崩溃、不无限重试）——这种就确实没办法了。
- 即时换装：生成完成时若该卡片还显示这个视频，立即换成动画；若此时 App 已被杀/重启，文件已落盘，下次该卡片绘制时自动取用。

参数不变：720px / 25fps / 2.5s，原生编码 `STABLE_HIGH_MEMORY`。VERSION→7，旧缓存按新机制重新生成（便于这次观察 WorkManager 路径）。

## 请测

1. 正常情况：视频封面是否照常生成、动起来；
2. **扛被杀**：进入有视频封面的列表触发生成后，立刻从最近任务里划掉 App（或设置里强停），过会儿重开——`…/cache/video-cover-previews/` 里 `.gif` 是否最终出现（WorkManager 应已在后台/重启后补完）；
3. **改封面**：生成中途把某条记事封面从视频改成图片，稍后看该视频的 `.gif` 是否仍生成出来了（留作备用）；
4. 发我 `video-cover-preview.log`，里面新增了 `ENQUEUE` / `WORKER run ... attempt=N` / `GEN done` 等行，可看到 WorkManager 驱动的生成。
