# 取消滚动暂停的性能对照

状态：三机完整 A/B 已完成，现按用户“先按已有结果整理”的要求归档。魅族冷却补测暂缓；异常轨迹保留为未确认，不再等待解锁后自动继续测试。

## 当前结论

- 普通触摸、选择模式和长按拖动的已有对照未见一致的明显流畅度退化；三机当前策略均在滚动中显示并播放全部 48 个 GIF／视频预览。
- 内存确有额外开销：三星、魅族、OPPO 的整体 PSS 峰值分别增加 1.65%、1.70%、4.81%，其中三星和魅族的惯性阶段工作占用增幅更明显。不能据此确认“所有场景无性能退化”。
- 魅族一段惯性呈现轨迹异常尚未厘清，补测按用户要求暂缓。本轮仅整理测量与记录，没有追加生产代码修改、发布或 Git 提交。

## 对照边界

- 使用同一隔离包、97 张卡片，其中 48 个独立 GIF／视频预览、80 个媒体项、32 张包含 96 项的清单；包含约屏高 5/6 的视频背景卡片。
- A 在调试入口恢复历史两层策略（非 IDLE 暂停应用 RequestManager，并停止当时可见的 Animatable）；B 使用当前持续加载／播放策略。其余代码、裁剪、GIF 规格、缓存预算、离屏回收保持一致。因此测量隔离的是“暂停策略”，不冒充两个历史完整 APK 的比较。
- 普通手指滚动、fling、选择模式滚动与长按边缘拖动都跨全列表，往返包含初次访问及返回。禁止在计时阶段截图和密集反射资源图。结束后再做图片与退出回收检查。
- 用后台 FrameMetrics 回调记录窗口帧耗时、各阶段耗时与系统 deadline；按实际手势时段归组。普通滚动与 fling 分开，静止时 GIF 的帧不能稀释滚动掉帧率。每 1.5 秒后台读取 PSS、Java／native 堆，记录实际采样耗时。
- 先对三机做相反顺序的 A/B，再按波动与疑似退化决定必要复测；记录刷新率、温度、位移和覆盖，避免把热状态或滚动距离变化算成优化。

## 历史约束与待验证预测

- `43e0ee2f3`：2016 年的 RequestManager 暂停；`d4cc84298`：M2 可见动图暂停的软解负担考虑。
- 10 月 9 日首页性能记录明确指出“减少准备”不等于整页更流畅，且方向预判方案因横滑反馈取舍被用户撤回；本轮保持粒子准备行为。
- 风险按优先级：①持续 GIF 解码争用 CPU，会提高解码密集阶段的长帧；②更多可见帧上传／绘制增加 RenderThread 或 GPU 耗时；③离屏资源累积，会让往返后的内存与存活 loader 持续增长。三个预测分别由帧阶段／必要时调度轨迹、GPU 耗时、按遍历阶段的内存及退出快照验证。

方法依据：[Android FrameMetrics](https://developer.android.com/reference/android/view/FrameMetrics)；TOTAL_DURATION 是应用提交帧的耗时，不等同于实际屏幕呈现间隔。必要时通过 Perfetto FrameTimeline 交叉核验。

## 采集过程约束

- 三机首批普通／选择模式区间完成后，调试入口因拖动控制器字段名写错而终止；已修正为实际字段 `mOverlayDragController`。这批六个完整区间仅作初步数据，不记作整轮通过，拖动与退出必须使用后续完整轮次。
- OPPO 前两次在列表进入前发生 ADB 短暂断连，UiAutomation 连接死亡，未产生有效性能区间。后续关闭额外 Perfetto 采集后完成六个区间；该设备保留窗口 FrameMetrics，不能虚构 FrameTimeline 结果，也尚不能认定断连由 Perfetto 导致。
- 内存采样放在独立后台线程，间隔 1.5 秒，实际单次耗时约 30 毫秒并单独记录；两组采用同样开销。计时阶段不抓图。全程含截图的峰值与滚动阶段峰值分别保存。

### 魅族惯性轨迹的限制

- 魅族 fling 的 FrameMetrics 回调严重缺报，旧策略 47～86 个窗口回调对应约 3400 个系统呈现记录；新策略也有同样现象。故不采用这一小样本的 P95/P99 作惯性验收。
- 第一轮 B 的惯性往返系统呈现约 117.83／119.18 帧/秒，A 为 118.88／118.50；呈现间隔 P95 约增加 0.1ms。
- 第二轮 B 结束时系统 thermal status 为 3（开始为 0，电池温度 40→41℃）；normal-fling-down 的 FrameTimeline 仅 1667 个区间记录，并出现 3.48 秒记录空洞，同时实际 onScrolled 有 3116 次，最大相邻间隔约 83ms。尚不能将其解释成真实 3.48 秒卡屏，也不能据此宣称该程完全平稳。其它区间未出现同等缺口。
- trace stats 没有报告 packet loss／overwritten；仍未排除厂商记录路径、系统负载或实际显示问题。需要冷却后的独立呈现复核，不删去不利样本后宣布全绿。
- 冷却补测 `perf-meizu-a3-1015` 在进首页前因锁屏要求密码而停止，没有性能区间。代理熄屏冷却触发此状态；请求用户在设备解锁后，用户选择“先按已有结果整理”，因此补测暂缓，异常继续保留为未确认。

## 内存：确有阶段性增加

单位 MiB，均为测量包 PSS。前后池／资源缓存预算、媒体尺寸及帧率相同。

| 设备 | A 全部滚动阶段峰值 | B 峰值 | 增幅 | A / B 遍历结束静置值 |
| --- | ---: | ---: | ---: | ---: |
| 三星 | 882.61 | 897.20 | +1.65% | 798.86 / 793.67 |
| 魅族 | 997.16 | 1014.16 | +1.70% | 827.55 / 781.96 |
| OPPO | 502.64 | 526.83 | +4.81% | 470.80 / 484.87 |

不能仅用峰值掩盖工作阶段占用。三星普通 fling 两程中位数 608.53／596.80→779.18／799.09 MiB，约增加 171～202 MiB；较另一旧策略轮次仍增加约 126～168 MiB。魅族为 673.53／714.18→765.68／799.66 MiB，约增加 85～92 MiB；较早 B 轮还高一些。OPPO 普通 fling 变化约 +6／−10 MiB，选择模式 fling 为 389.29→438.75 MiB。

该差异与暂停策略下大量媒体不进入加载／播放、持续策略增加工作资源相符；但仅凭配对不能将全部 PSS 差值精确归入某个 decoder。堆、图形缓存、系统分配器与 GC 时机共同影响 PSS。停止后阶段性占用回落，六轮完整测试 Activity 退出后运行 loader 均为 0，无 OOM、加载失败或已复现的持续解码泄漏。

本轮未发现需要靠恢复滚动暂停来规避的明确流畅度回归，但**不能给出“内存不增加、所有场景无性能退化”的结论**。不以缩小缓存／重新清除离屏 GIF／降低预览规格来换取未经 UI 验证的数字。生产代码暂未追加改动；后续精确压低惯性阶段工作内存和魅族显示复核须继续遵守播放、首帧回显及原画质约束。
