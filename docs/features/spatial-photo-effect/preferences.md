# 偏好 / 空间照片效果

## 2026-07-30

- 所有涉及图片内容的计算都必须在手机上完成，不把附件图片上传到服务端。
- 用户需要的是应用内的空间视觉与交互效果，不要求导出符合 Apple 规范的空间照片文件。

## 2026-07-31

- 空间照片效果生成一次后应在本机持久保存，后续查看直接复用，不要每次重新计算。
- 持久内容是可重建的派生深度与参数，不替换原图片，也不参与跨设备同步。
- 入口放在全屏图片查看器中，由用户主动进入；不在详情附件网格自动播放，也不让普通全屏查看默认进入效果。
- 空间模式同时支持轻微倾斜手机和单指拖动视点；进入时锁定当前附件，退出后恢复普通查看手势。
- 设置提供默认开启的全局设备倾斜开关；关闭后完全停用姿态传感器并保留单指拖动，不设置逐图片开关。
- v1 只处理普通静态图片，不处理 Animated Image 或 Motion Photo。
- 后续希望支持对 Animated Image、Motion Photo 等动态内容生成跨帧空间效果；该能力命名为
  **Spatial Video Effect**，只指应用内交互呈现，不要求导出空间视频文件。
- HDR 静态图可以生成空间照片效果；v1 接受空间模式暂时显示 SDR，退出后继续查看原图的 HDR。
- 深度模型按需下载，不随安装包强制提供全部权重。
- ZipDepth 与 Depth Anything V2 Small 都应支持独立下载；首次只下载其中一个后，用户仍可在设置中
  下载第二个并选择使用哪一个。
- 双模型支持是 v1 发布门槛；如果其中一个无法可靠转换、分发或运行，应暂停并提供证据后重新确认，
  不能静默只发布另一个。
- 首次生成且没有模型时显示模型选择界面，默认推荐 ZipDepth，但必须由用户确认，不静默下载。
- 模型先下载到开发电脑；访问外网下载源时使用代理 `127.0.0.1:7890`。校验后上传到用于发布 debug
  更新的阿里云服务器，App 内部从该阿里云服务器下载，不直接访问 GitHub/Hugging Face。
- 模型 catalog 与 APK 的 debug/release 发布渠道分离；两种构建默认使用同一稳定 catalog，debug
  可以通过显式配置使用 staging catalog。
- stable 与 staging 模型 catalog 使用不同的 Ed25519 签名密钥；release 只信任 stable 公钥。
  私钥必须离线保管，App 在采用模型地址、大小和哈希前必须先验证 catalog 签名。
- 设备能力按模型分别判断；某个模型不兼容时允许使用另一个，两个都不兼容时明确提示本机暂不支持。
  不上传图片做云端回退，也不强制使用可能崩溃或长时间卡顿的 CPU 路径。
- 图片生成采用前台、分阶段、可取消流程；离开全屏查看器时取消，不在后台继续，成功后自动进入空间
  模式。
- 模型下载可离开界面后继续并支持续传；设置和通知显示进度与取消。下载完成时只有原查看器仍在前台
  才继续生成，否则只提示模型已就绪。
- 不强制模型仅通过 Wi‑Fi 下载；在计费网络或流量节省模式下显示准确大小并再次确认，禁止静默使用
  移动流量。
- 模型更新不自动下载；只提示用户，主动更新成功后才替换旧模型，并且不重算既有效果。
- 完整空间效果不得作为普通 LRU 缓存自动淘汰；设置显示总占用，并支持按图片移除或清除全部。空间
  不足时拒绝新生成，不静默删除既有结果。
- v1 空间模式不支持双指缩放、图片平移或附件翻页；固定适应屏幕，退出后恢复普通查看态的完整手势。
- 空间模式内第一次系统返回只退出效果，回到同一图片的普通全屏查看；第二次返回才离开查看器。
- 已生成图片在详情附件网格显示 icon 形式的空间徽标，不使用文字；Thing Card 封面不显示。
- 全屏查看器使用独立的顶部工具栏 icon 作为空间效果入口，不放入更多菜单；入口随查看器界面一起
  显隐，并按是否已有派生结果进入生成或查看流程。
- 空间图标在模式激活时作为高亮开关，再次点击退出效果；左上角 Toolbar 导航保持直接返回 Thing
  详情，系统返回仍先退出空间模式。
- v1 不加入手动深度编辑器；只提供强度调节、使用当前模型重新生成和移除效果。
- 不用不可靠的内容/质量分类隐藏生成入口；尽量生成并保守呈现，只有硬技术错误才中止。
- 切换模型只影响新生成和主动重新生成，不自动使既有效果失效或触发批量计算。
- 删除模型包不删除由它生成的空间效果；单张图片重新生成时，用当前模型原子替换旧派生结果。
- 每张图片提供独立保存的“空间强度”；自动给出保守默认值，用户调整时只改变实时渲染，不重新生成
  深度，并限制在安全范围内。
- 空间强度使用空间模式画面底部的紧凑滑杆，与顶部工具栏同步显隐；拖动实时预览、松手保存，不使用
  模态对话框或底部弹窗。
- 空间模式在没有姿态或触摸输入时保持静止；首次只提示如何倾斜或拖动，不自动播放相机运动。
- ONNX Runtime 也不应导致基础 APK 体积暴涨；只在首次需要生成空间效果时，按当前设备 ABI
  下载对应运行组件。运行组件由两个深度模型及后续空间视频能力共用。
- 当前空间效果的视觉层次偏弱；在不重新估深、不破坏既有派生结果的前提下，提高视点响应、前后景
  分离与深度边缘的可感知程度，同时继续保留有界强度和伪影控制。
- 用户希望对 schema v2 空间照片提供可即时切换的单层 P0／双层 P1 对照，以便按图片判断哪种表示
  更自然；不能把双层默认视为对所有内容都必然更好。
- 用户认为 MI-GAN 在大视差、宽显露背景上的补全质量一般，希望允许下载并选择不同的本机补全模型；
  候选可以包含 diffusion，但仍须遵守图片不上传、模型按需下载和按设备资源准入。

## UI 与文案（2026-07-31 用户反馈）

- 空间效果的一切界面着色跟随记事强调色（accent→accent2 渐变），不允许硬编码颜色：
  查看器激活图标、强度条、生成进度圈、按钮 ripple 都在内。
- 详情附件网格的空间角标与 HDR/GIF/实况角标同语言：偏白、低调，不用彩色。
- 触摸 ripple 形状有一套固定语义：对话框「确定/取消」类按钮=胶囊；逐行选项（三键
  对话框）=整行矩形；设置页文字动作（下载/取消/清除）=胶囊；图标动作=圆形。颜色一律
  accent→accent2 渐变。
- 设置页文案要专业、面向用户：不出现「本机空间计算」这类含混词（改「推理运行环境」），
  分组名用「深度估计模型」「背景补全模型」；模型行不写开源协议、实测耗时、"推荐/快速"
  等修饰，只保留模型名 + 大小/状态；模型专属选项（AOT-GAN 工作分辨率）只在该模型被
  选中时出现。
- 已装组件的「删除」用小图标（圆形 ripple）而非文字按钮，占位更小。
- 面向用户的模式名不用内部代号：P0/P1 改「稳定 / 立体」。

## 2026-08-01

- 视觉质量优化必须从表示、生成与渲染链的通用根因出发，不能针对当前两张测试图片调阈值、增加内容特判或做样本级补丁；这两张图片只作为故障探针和回归样本。
- 质量验收应覆盖跨场景不变量与通用数据集，至少包括零视点无损还原、轮廓完整性、纹理清晰度、遮挡/显露正确性、不同方向与幅度的一致性，以及人物、多人、细发丝、透明/反光物、室内复杂背景等场景。
- 用户明确不接受为了掩盖伪影而把大范围画面塑造成连续曲面的观感；空间感应优先来自对象/区域之间的视差与遮挡变化，而不是主体周围的大范围连续深度坡。
- 可以引入图像分割模型，把画面构建为多个具有明确所有权的对象或场景区域并分别处理；但语义标签本身不能直接等同于独立运动层，脸、头发、皮肤、衣服等属于同一物体的部件默认应保持整体一致，避免层间开裂和纸片感。
- 空间照片整条模型链都要按截至 2026-08-01 的最新一手资料重新审计，包括深度估计、通用/对象分割、matting、背景补全以及单图新视角表示；不能预设 Depth Anything V3、MODNet、MI-GAN 或 AOT-GAN 仍是当前最佳选择。
- 选型必须同时展示模型发布时间与最新版本、许可、权重/运行内存、端侧可行性和任务适配性。旧模型若继续存在，只能作为明确标注的兼容/低配选项；旧手机上的历史基准不能单独作为 2026 年设备选型依据。
- 用户接受继续加入更多端侧模型来改善自然度，但新增模型必须解决明确的独立职责，并继续遵守手机本地计算、运行时按需下载、可关闭/删除和失败安全回退；不能用职责重叠的模型叠加代替表示与渲染根因修复。

## 2026-08-03

- 连续倾斜手机画小圆时，观感应是视点围绕画面平滑环绕；前后方向不得主导成周期性的
  整图放大/缩小。取景安全裁切必须对等半径视点旋转不变，不能随圆周方向产生呼吸缩放。

## 2026-08-04

- 单人图在水平倾斜/拖动到大视角时，人物脸宽、五官横向比例和头部轮廓必须保持稳定；明显的水平拉伸即为失败，不能用“整体仍像同一个人”或空间感较强来接受。
- 视觉质量结论必须来自用户指定真机上的实际生成与左/中/右视角截图；如果截图中存在明显形变，不能只依据应变预算、自动指标或主观粗看宣称脸型一致。
- 用户认为当前把分割引入几何生成后的技术路线已经偏离目标：系统虽然消除了明显黑缝、漏洞和白色伪影，
  但新增了显著且不自然的内容形变；后续不得以保住既有实现为前提继续叠加补丁。
- 需要从空间照片目标、场景表示、生成链、实时渲染和交互映射五个层面重新进行完整审计，允许平行重写核心表示与
  渲染链；可以复用已验证的下载、存储和补洞基础设施。
- 分割只能在有明确证据时承担对象所有权、置信度或遮挡辅助职责，不能因为存在语义掩码就直接改写深度、切边或赋予
  区域独立运动。
- 质量提升必须同时保留当前已经解决的黑缝、漏洞和白色边缘伪影问题；不能用新的拉伸、模糊、纸片感或整体缩放来交换。
- 方案范围仍严格限定为普通单张图片在 App 内生成并实时交互的空间照片效果，不转成 Apple 文件格式、普通缩放动画、
  预制 Ken Burns 视频或其他无关的三维功能。
- vNext 不得通过把视差压到不明显、把深度整体钳平或退化为整图平移来换取低形变；“清晰的前后表面相对视差、
  遮挡显露和连续二维环绕响应”与“人物/文字/细结构低形变”是并列验收门槛。安全视点包络的职责是在形变约束内
  最大化可感知空间效果，而不是采用一个保守固定小幅度。
- 2026-08-04 真机反馈补充：“稳定”模式不能继续使用比 vNext 更容易形变的旧单纹理 depth warp；“稳定”与
  “立体”都必须首先是空间照片效果，不能一个明显扭曲、另一个几乎没有视差。两者只能在边缘 alpha、隐藏区显露
  等伪影取舍上区分，不能以是否具有可感知空间感来区分。

## 2026-08-05

- `4.28 px` 的主体内部满幅位移跨度不可作为可感知体积的通过标准；大型人物区域如果大部分像素近似同速移动，
  即使数学上并非严格刚性，视觉上仍是联合纸片，必须判定失败。
- 主体内部的可靠深度证据必须实际参与新视角合成；不得为了控制脸部形变而把整个人物或多人主体压成近常量深度。
  需要同时实现局部形状保持和跨身体尺度可感知的前后层次，而不是在二者之间二选一。
- 后续每次真机动态验收必须至少同时录制原单人图、原双人图，并加入多个未参与调参的额外场景；禁止只录一个附件
  或把当前两张探针当作完整验收集。额外场景应覆盖单人全身／半身、多人、近景物体、室内纵深、文字和细结构。

## 2026-08-06

- 空间照片不要求从单张图片生成特别大的侧视角；此前 OVIE `r=0.20` 探针相对原图偏移过大，超出了单目信息
  的合理范围。后续以小基线、适度但可感知的视差为目标，不把“大角度”本身当作质量或空间感指标。
- 强度滑杆仍需提供清楚的空间层次，但默认值和最高档都必须受单目安全视角约束；不能通过放大相机基线来证明
  空间效果，也不能因改回小基线而退化为整图卡片平移。
- 不得仅凭 `6–10 px` 之类的数字预算冻结默认值或上限；确定范围前必须提供同一图片、同一圆周轨迹下的可交互／
  动态视觉对照，并保留更高档位作为参照，让用户直接判断空间感与形变的取舍。
- 首轮可交互对照表明 `14 px` 仍不足以达到期望的空间感；后续校准必须纳入 `18 px` 与 `20 px`，并以动态观感和
  形变门禁共同决定默认值，而不能回退到此前偏保守的 `6–10 px` 区间。
- 可感知空间效果的候选下限提高到长边 720 像素下约 `20 px` 的 p5–p95 相对视差，并继续评估 `24 px`；优化职责是
  在该有效空间感范围内降低局部形变，而不是再次把全图幅度压回低于 `20 px` 来规避问题。
- `24 px` 不能被预设为产品上限；视差校准继续提供 `28 / 32 / 36 px` 及更高参照档。用户当前认为目标可能达到
  `36 px`，最终范围必须由同轨迹动态对照确定，而不是由开发侧提前收窄。
- 用户已把当前实现主目标收敛到长边 720 像素下约 `36 px` 的 p5--p95 有效投影视差；`40 px`
  继续保留为上界参照。该目标优先由可信遮挡层和不同深度 chart 之间的相对运动实现，不能靠脸部、
  文字或单一连续表面的强非相似拉伸凑数。
- 2026-08-06 真机动态反馈再次确认：主体区域近似整体上下左右平移、内部缺少可感知深度变化时，
  无论全图视差是否达到 `36 px`，都必须判定为“纸片／卡片”失败；主体内部约 `1--4 px` 的响应不具备验收意义。
- 分割与 matting 不得继续主导前景／背景采用不同运动策略。语义掩码质量不稳定，而且主体级单块分区会把人物内部深度
  压成近刚性运动；后续方案必须先证明主体内部体积与局部保形可以同时成立，不能再靠调整分割阈值或层间平移凑空间感。
- 当前 vNext7 真机路线已被用户否决并冻结。未经用户明确许可，不得继续修改实现、操作真机、发布阿里云，
  也不得擅自回滚现有工作区；下一步只能先说明现状与候选方向，等待用户决定。

## 2026-08-07

- 用户已明确允许继续优化并重新连接手机供真机测试；此前对 vNext7 的停止要求解除，但不包含发布阿里云授权。
- 技术方向回归早期的全局连续空间效果：从单张图片生成范围有限、明显可感知但不过大的连续多视角响应，
  画面各区域依据深度共同参与，不得把人物或其他显著主体退化为整体上下左右平移的纸片。
- 分割／matting 结果不得作为空间运动的主要目标、主要依据或直接运动层；最多只能在不改变连续全局运动场的前提下，
  辅助判断低置信边缘、遮挡显露或质量门禁。关闭、缺失或改变分割结果时，主体内部的主要视差结构不应发生实质改变。
- 真机验收必须包含连续倾斜和圆周轨迹，而非只看静态极值截图；若主体内部缺少可感知深度变化，或出现整块边界与背景断裂，
  即使全图跨度达到目标也直接失败。视角范围应在真机动态质量下校准，不预设极小范围，也不追求超出单目信息能力的大视角。
- 不得把“分割／matting 不驱动运动”误解为停用已有模型。深度模型必须实质参与连续几何、遮挡次序和主体内部视差；
  背景生成模型必须只在真实反遮挡区域补全不可见内容；分割与 matting 可以辅助补全条件、边界覆盖和置信度判断，
  但不得把语义区域变成刚性卡片或直接改写其运动场。
- 模型是否启用必须用最终呈现收益验证：在相同视角与位移预算下，应增加可见的前后层次和正确遮挡显露，同时不增加脸部、
  文字和细节的局部形变。仅生成但从未被渲染采样的背景、被过度平滑后几乎不再影响运动的深度，均视为没有真正使用模型。

  主要可由对原图的一次单层 warp 解释，缺少前后景相对运动、遮挡次序变化和真实反遮挡显露，即使
  自动形状门禁全部通过，也必须直接判定为“空间效果被移除”。

  空间视差、正确遮挡、显露内容、主体内部体积响应与局部保形是并列硬门禁，不允许拿其中一项抵消
  另一项。代理必须先让被否决方案在新的空间性门禁中稳定失败，再继续候选优化。
- 再次明确禁止“卡片人”：即使人物与背景之间已有明显相对视差和真实显露，只要整个人物仍由一个
  matte 驱动的近刚性平面整体移动、头身与手持物内部缺少一眼可见的连续深度响应，就必须直接判定
