## 2026-07-31 - 空间计算按需下载与更强空间效果

用户反馈空间照片功能使 APK 体积明显膨胀，希望运行组件也只在真正需要时下载；同时认为当前空间
效果偏弱，要求在不改变原图、不依赖云端计算的前提下增强视觉层次。

- 通用 APK 不再包含四套 ABI 的 `libonnxruntime.so` 与 `libonnxruntime4j_jni.so`。设置页新增
  独立“本机空间计算”条目；首次需要生成深度时只下载当前设备 ABI 的组件，ZipDepth、
  Depth Anything V2 Small 与后续空间视频共用一份。删除组件不会删除模型或已生成效果。
- Runtime 与双模型共用 Ed25519 签名 stable/staging catalog。下载继续支持前台进度、取消、
  `.part` 续传和计费网络确认，并校验压缩包精确字节数、SHA-256、解包后双库名称、大小及哈希；
  完整验证后才原子安装到 App 私有 no-backup 版本目录并设为只读。
- 已将官方 ORT 1.28.0 按 arm64-v8a、armeabi-v7a、x86、x86_64 发布为四个不可变阿里云对象。
  当前 arm64 下载包为 10,605,072 字节，解包占用 28,748,928 字节；四包均已通过代理从公网完整
  取回并与签名 catalog 的大小、SHA-256 逐项一致。
- ORT 官方 Java loader 在 Android 上会忽略 `onnxruntime.native.path`。本次使用固定上游 AAR 和
  `classes.jar` 哈希、可重复生成且不含 native library 的 Java-only jar，只对固定方法增加受结构
  校验的绝对路径分支；不修改不可变系统属性，也不使用未校验的 linker 搜索路径。
- 查看已有 Spatial Photo Derivative 不要求 Runtime 存在；新生成或重新生成才检查组件。模型
  下载任务若发现组件缺失，会先复用同一受信下载/安装事务，避免重复下载。
- 连续逆向 UV 重投影的视差幅度与过扫描范围提高，触摸、倾斜映射和新生成图片默认强度同步提高。
  曾测试的离散多层方案在深度断层出现重复条带，已撤回。
- 首次发布候选包回装后，人物近景在极限视点暴露出原始深度断层导致的 UV 折返。最终版本在场景
  加载时生成斜率受限的渲染深度，真实素材的水平折返点由左右 20,075/13,973 个降为 0；原始深度
  只用于最多 4% 的有界明暗塑形。OnePlus 多人近景与 Samsung 人物剪影的左右极限回归均未再出现
  重复切片、条带、露边或着色器错误，视差上限保持不变。
- 发布前 Debug APK 为 27,707,941 字节（26.42 MiB），拆包确认 0 个 ORT `.so`；相对上一版
  145,939,475 字节减少约 81%。完整 Debug JVM 测试为 84 个套件、593 例，0 失败、0 错误、
  1 项既有跳过，`:app:assembleDebug` 通过。

  明确显示私有目录双库 absolute-path load 为 `ok`。OnePlus 使用 ZipDepth、Samsung 使用
  DAV2 Small 分别对新图片完成生成并进入增强空间模式；两套 Adreno 驱动均无着色器错误。
