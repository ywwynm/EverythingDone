# Debug Update - 2026-08-16

## 空间照片：NPU 执行期失败自动改走 CPU（修复 OPPO 平板生成报错）

修复 OPPO Pad Mini 等设备上生成空间照片弹出「QNN graph execute error. Error code: 1003」且一张都生成不出来的问题。连机定位（D276）确认根因：该机的 Big-LaMa NPU 预编译产物按另一颗 SoC 编译，单次执行超过 CDSP 侧 10 秒定值看门狗，DSP 用户进程被终止；而此前 NPU 只在建 session 失败时回落 CPU，执行期失败会把整条生成链路打死。

### 本次改动

- **执行期回落**：「建 session + 推理」整段失败时自动用 CPU 重跑同一步。Big-LaMa 分块循环按整图粒度重试（失败时 session 已失效，只能连 session 一起重建），本次生成不再弹错，只是这一步慢一点。
- **记住结论**：执行期失败按「模型 / HTP 架构 / 运行组件版本」指纹落盘，之后的生成直接走 CPU，不再每次白等一次 10 秒看门狗；更换运行组件或更换预编译产物后自动重试一次。回落是逐模型的：同一次生成里其他模型（如 RF-DETR 实例分割）不受影响，仍走 NPU。
- **标注如实**：进度文案的 (NPU) 后缀改为跟随实际执行路径——回落改走 CPU 后撤回标注，不再「沾过 NPU 就一直挂着」。
- **守门单测**：QNN 调用点的回落检查改为扫描全部主源码推导调用者名单，防止未来新引擎接 NPU 时漏包回落。293 个 spatial 单测全过。

OPD2515 真机验证：首次生成 14 秒出现 (NPU)、26 秒撤回改走 CPU、69 秒无报错完成；之后两次补全阶段直接走 CPU，无 CDSP 崩溃、无 ORT 报错。剩余待办：等 Qualcomm AI Hub 提供 8 Gen 5 设备条目后按实机 SoC 重编 Big-LaMa 预编译产物，让这台机真正用上 NPU 补全。
