# 空间照片：渲染核心改为真透视视差，并接进实际出像素的那条路

## 空间照片：渲染核心改为真透视视差（与网页/桌面端对齐）

用户反馈端上效果"不像空间照片，像是根据传感器数据直接对图片做 warp"，并要求渲染核心与
桌面端保持一致。本次把运动构造从局部刚性拟合换成**由米制深度与相机内参直算的真透视视差**，
并在真机（三星 SM-S9180）上用九张语料逐张验证。

### 新增两个端侧模型

- **MoGe-2 ViT-S 深度模型**（`moge_2_vits_normal`，134 MB）：输出 point map，能同时给出
  **米制深度与相机内参**，这是真透视重投影的前提；其余深度模型只给相对深度。
  真实照片实测 540×720 用时约 5.7 秒，恢复出的绝对尺度合理（近物 0.80～1.97 m、
  雕像 5.9～33.5 m、人宠 1.7～5.0 m）。
- **Big-LaMa 补全模型**（`big_lama_places2_512`，198 MB）：512 分块推理，桌面端 A/B 中
  保真最好的一档。补全质量新增 `maximum_1024` 档位。

两者都通过设置页按需下载，未打进 APK。运行组件包同时升级到 `1.28.0-r7`（补齐 MoGe 需要的
算子三元组，并编入 XNNPACK）。

### 运动构造改为真透视

原先的运动基由局部刚性拟合得到，实测它的交叉项不为零（水平视点会产生竖直位移）、两个主项
也不同源——那不是视差，是拟合出来的形变场。现在直接按公式给：

    Δu = fx·tx·(1/Z₀ − 1/Z)，  Δv = fy·ty·(1/Z₀ − 1/Z)

与网页端逐字相同。幅度单位随之变成**米**（物理基线 4.5cm，对齐实测的 iOS 空间照片），
不再是归一化系数。支点取**主体深度中位数**，与网页端同口径——支点处位移恒为零，所以它决定
"什么东西钉在屏幕上不动"。

真机实测（九场景 × 八方向，一次按住走完）：

- 交叉跨度全线塌下去：16→3 / 16→2 / 11→0 / 10→0 / 10→0 / 17→12 / 9→0 / 11→5 / 12→0，
  "像 warp"的症状消失；
- 00 场景左右满偏移对开视差实测 152.6 px，闭式预测 154 px；
- 九场景与桌面端 4.5cm 物理预测的秩相关从 +0.800 升到 +0.900；
- 视差按场景分化（00 最大 153 px、远处雕像只有 6 px），这正是固定物理基线该有的表现。

### 同批修掉的三处

- 新一代派生的 schema 未登记进回读白名单，导致刚保存的派生**回读即失败**（错误信息是
  "无法回读刚保存的空间派生"），且失败被兜底吞成静默。已补齐并加了防回退的契约测试。
- "当前世代"判定仍指向上一代 renderer，会让新派生每次进空间模式都被判过期重算。
- 隐藏底板的运动基仍是旧口径，与前景不是同一套幅度，一并换成真透视。

### 已知问题

大偏移下沿人物剪影会出现棋盘状的细小缺口（00 场景空洞占比 0.765%）。根因是真透视场在深度
断崖处按设计不做平滑，而点元大小仍按未形变的网格间距计算，合成遍只能补一像素裂缝。已定位
并记录，修法待定，本次未改。

另外，连续生成多张之后立刻打开查看器可能出现无响应，重新打开应用即可恢复。
