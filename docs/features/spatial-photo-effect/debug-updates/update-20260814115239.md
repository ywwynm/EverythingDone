## 空间照片：背景补全真正接上 NPU 了，整步快 1.6 倍

### 上一版漏了一半

上一版（`202608140339`）把 NPU 预编译产物的下载做完了，但**补全引擎从没去用它**——
产物下下来躺在手机里，实际仍然全程跑 CPU。那一版的说明写成"背景补全现在也能跑在
NPU 上"，是不对的，本版修正。

### 现在真的接上了

打开「骁龙 NPU 加速」后，背景补全（Big-LaMa）会用预先编好的 NPU 产物。同一张图、
同一条遮挡带、四个 512 分块，本机实测：

- NPU 开：**16.0 秒**
- NPU 关：**26.1 秒**

**整个补全步骤快 1.63 倍。** 单看模型推理本身是 5.6 秒 → 2.1 秒（2.7 倍），
整步的收益小一些，因为准备、分块与合成这些环节不受影响。

没有下发到预编译产物时（比如机型不在覆盖范围内），补全会老实走 CPU，**不会**尝试在
手机上编译计算图——那条路对这个模型行不通，硬试只会白等再被系统杀掉。

### 目前哪些模型会用 NPU

| 模型 | 作用 | NPU |
|---|---|---|
| RF-DETR | 人物连续性 | 用 |
| Big-LaMa | 背景补全 | 用（需下发预编译产物） |
| MoGe-2 | 深度估计 | 不用 |
| MODNet | 发丝边缘细化 | 不用 |
| MI-GAN / AOT-GAN | 背景补全（备选） | 不用 |

深度估计不上 NPU 是刻意的：NPU 要求固定输入分辨率，会让「深度细节」那三档失去意义。
