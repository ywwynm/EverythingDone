# 空间照片：NPU 可用性判定重整与重启闭环

## 空间照片：骁龙 NPU 可用性判定重整

- 架构判定分为两层：这颗硅是哪一档（catalog 判定表 → 厂商内置库自证 → QNN 自探三条来源依次回答），以及该用我们发布的哪一份（不超过硅档的最高已发布档，与 QNN 自身的选法一致）。未登记的新骁龙由全 arch 运行组件兜底，开箱即用；比已发布最高档更新的硅自动落到最高档，预编译产物照常可用。
- 三条来源都回答不了时，装完组件后用一个极小的探测图问 QNN 本尊：成功则得到确切档位并解锁按架构分发的预编译产物；连续失败则判定本机不支持。修复了探测在进程仍加载着 CPU 版组件时被误计失败、把健康设备永久误判为不支持的问题——这种情况现在会静默跳过并提示重启。
- 确定不支持的机型分两种处置：下载前就能判出的（判定表、厂商库、过老的架构）整行隐藏；装完组件才实测出起不来的置灰并说明，且只要组件还在磁盘上就保留删除入口，删掉后整行隐藏。判定不可用时总开关自动收口，推理与顺带安装整体回落 CPU 版，不再给确定不支持的机器下发组件。
- 在 CPU 与 NPU 之间切换（打开/关闭开关、NPU 组件下载完成、删除组件）且进程里确实加载着另一份运行组件时，弹出与应用同风格的对话框提示重启；点「立即重启」自动重启并直接回到空间照片效果设置页，随后自动完成架构探测。进程没加载过组件时不打扰。
- 探测结论只得出一次并持久保存，换运行组件版本后自动重新得出；"不支持"的结论在应用升级更换组件版本后自动失效，允许用新组件重试。
- Big-LaMa（NPU 版）在本机架构没有可用预编译产物时整行隐藏，不再显示「未下载 · 0 B」。
