# 决策记录 / 空间照片效果

## D1：目标是应用内 2.5D 效果，不是空间媒体文件（2026-07-30）

用户明确要求的是普通图片在 EverythingDone 内呈现空间视觉与交互效果，而不是导出符合 Apple
规范的空间照片。

因此本功能：

- 以原图片和派生的深度信息驱动交互渲染；
- 不生成左右眼媒体、不实现 Spatial HEIC/MV-HEVC，也不以 Apple Photos 或 Vision Pro 的识别作为验收条件；
- 不新增与 IMAGE、VIDEO、AUDIO 并列的附件类型；
- 不修改或替换原图片附件。

该决定同时解决术语歧义：本项目称其为 **空间照片效果（Spatial Photo Effect）**，不把它简称为
Apple 文件格式意义上的 Spatial Photo。

## D2：派生效果在本机持久保存，但不是同步内容（2026-07-31）

用户确认：一次生成完成后，空间照片效果应在本机跨应用重启保留，后续查看直接复用，不要重复运行
深度模型。

持久化边界：

- 保存派生深度信息、生成版本与渲染参数，不复制或替换原图片；
- 派生内容属于可重建的本地数据，不加入 Thing 的附件列表，也不参与跨设备同步；
- 派生内容跟随源附件生命周期：源附件删除后可一并清理；
- 模型或派生算法升级后可以判定旧版本失效并重新生成；
- 用户应能移除或重新生成效果，而不影响原图片。

这是功能内的缓存与生命周期决策，不创建 ADR：派生数据可重建，方案可逆，也不会形成新的跨系统媒体契约。

## D3：仅在全屏查看器中由用户主动进入（2026-07-31）

用户确认空间照片效果不在详情附件网格或普通图片查看中自动激活。

- 全屏图片查看器提供“空间效果”入口；
- 尚未生成时，入口启动本机生成流程；
- 已生成时，入口进入空间交互视图；
- 用户可以退出效果并立即回到原图；
- 详情附件网格继续显示普通静态图片，不承担模型生成或连续空间渲染。

这使首次等待、持续 GPU 渲染和交互手势都限定在用户明确选择的界面中，同时保留原图作为稳定回退。

## D4：空间模式同时使用姿态与单指拖动（2026-07-31）

用户确认两种交互都要支持：

- 进入空间模式时锁定当前附件，避免单指拖动与 ViewPager 翻页争抢；
- `TYPE_GAME_ROTATION_VECTOR` 的相对姿态驱动细微、连续的视差；
- 单指拖动直接控制视点，拖动期间以手指输入为准；
- 手指释放后平滑回到姿态输入对应的位置，不发生跳变；
- 没有可用姿态传感器时，单指拖动仍提供完整功能；
- 退出空间模式后恢复普通查看态的翻页、图片平移、缩放和既有长按语义。

具体阻尼、最大视差与回正速度属于可调参数，先由 PoC 和真机舒适度测试确定，不写入领域词汇表。

## D5：v1 仅支持普通静态图片（2026-07-31）

用户确认 v1 不为 Animated Image 或 Motion Photo 生成空间照片效果：

- JPEG、PNG、静态 WebP、静态 HEIC 等普通静态图片可以进入生成流程；
- Animated Image 保留其逐帧 Animated Playback；
- Motion Photo 保留其静态主图与内嵌视频播放语义；
- 不从动态内容中任取一帧冒充完整空间化结果。

用户同时提出后续希望让这些动态内容获得 **Spatial Video Effect**。该方向需要跨帧一致的深度和
遮挡处理，作为独立后续能力设计，不扩大 v1 范围。

## D6：HDR 图片可生成，但 v1 空间模式使用 SDR（2026-07-31）

用户接受以下取舍：

- 带 Gain Map 的 HDR 静态图片仍可进入空间效果生成流程；
- v1 从 SDR 基础画面生成颜色纹理并进行空间重投影，不宣称在空间模式中提供 HDR Display；
- 进入空间模式不修改、重编码或移除原文件的 Gain Map；
- 退出空间模式后，普通全屏查看器继续按既有能力显示原图 HDR；
- 真正的 HDR 空间重投影留作后续增强。

这样不会因 HDR 附件而禁用功能，也不会为了 v1 把 Gain Map 解码、颜色空间、HDR framebuffer 和
深度重投影同时绑成一个高风险交付项。

## D7：两个深度模型可独立下载并由用户选择（2026-07-31）

用户确认模型不全部内置于安装包：

- standalone ML Runtime 随 App 提供，不把 Google Play Services 作为运行前提；
- ZipDepth 与 Depth Anything V2 Small 分别作为可下载模型包；
- 首次生成前由用户下载其中一个，下载完成后它成为当前选择；
- 设置界面显示两个模型的下载状态、版本和占用空间，可继续下载第二个模型；
- 用户可以在已下载模型之间选择当前使用的模型，也可以删除不需要的模型；
- 下载使用 `.part`、SHA-256 校验和原子完成，图片数据不参与下载或上传；
- 每个模型的 Android 算子覆盖、数值一致性、性能、实际包体和许可声明必须分别通过发布门槛。

两个模型共享同一套派生数据协议，但派生结果必须记录模型身份与版本，不能把一个模型生成的深度缓存
误认为另一个模型的结果。

## D8：切换模型不改动既有派生结果（2026-07-31）

用户确认：

- 当前模型是后续生成任务的默认模型，不是全局重解释既有结果的开关；
- 切换模型不让已有空间效果失效，也不触发后台批量重新生成；
- 每张图片只保留一份当前派生深度及参数，并记录其生成模型家族与版本；
- 用户对单张图片主动“重新生成”时，使用当前模型生成临时结果，成功后再原子替换旧结果；
- 重新生成失败或被取消时，旧结果继续可用；
- 删除模型包不删除它已经生成的效果，因为查看阶段只读取自包含派生结果；
- 原附件删除时，仍按 D2 清理对应派生结果。

这把模型生命周期与派生结果生命周期解耦，避免设置切换引发不可预期的耗电、等待和画质变化。

## D9：每张图片独立保存有界的空间强度（2026-07-31）

用户确认提供 **Spatial Effect Strength**：

- 生成流程根据深度动态范围、边缘不连续和预估空洞风险给出保守默认值；
- 用户可在空间模式中实时调节，每张图片独立保存；
- 调节只改变渲染阶段的最大视点位移/视差幅度，不修改深度图、不运行模型；
- 可调范围由渲染器限定，不能越过舒适度和伪影预算；
- 重新生成深度后重新计算默认值；是否沿用用户旧值由实现时以“保留相对档位并重新限幅”为原则处理。

术语已写入 `CONTEXT.md`，避免把“空间强度”误解为模型重新估计了更深的真实场景。

## D10：无交互时保持静止（2026-07-31）

用户确认空间模式不自动循环移动虚拟相机：

- 画面只响应设备相对姿态和用户拖动；
- 当两者都没有变化时，视点保持稳定；
- 首次进入空间模式时可以显示一次简短操作提示；
- 提示不通过实际的大幅相机动画演示，以免在用户尚未操作时产生眩晕或边缘伪影；
- 该效果不纳入 Animated Playback 或 Detail Autoplay。

这保留了“用户改变视点”的交互语义，也避免把空间照片效果变成自动播放动画。

## D11：首次明确选择模型，默认推荐 ZipDepth（2026-07-31）

用户确认首次点击“生成空间效果”且本机没有模型时：

- 显示 ZipDepth 与 Depth Anything V2 Small 的选择界面；
- 默认推荐并预选 ZipDepth，但不自动开始下载；
- 用户确认后才下载所选模型，也可以首次直接选择 Depth Anything V2 Small；
- 界面显示实际下载字节数、许可和已由 PoC 验证的性能事实；
- 在没有实测证据前，不使用“高画质/低画质”等结论性标签。

## D12：模型由 EverythingDone 的阿里云服务器分发（2026-07-31）

用户指定模型获取与发布路径：

1. 在开发电脑上从上游官方来源下载；访问外网需要代理时使用 `127.0.0.1:7890`；
2. 核对上游版本、许可、文件字节数与 SHA-256；
3. 上传到当前用于发布 debug 更新的阿里云服务器；
4. App 只从 EverythingDone 控制的阿里云地址获取版本化模型，不直接依赖 GitHub/Hugging Face。

ZipDepth 为 MIT，Depth Anything V2 Small 为 Apache-2.0；发布模型时必须同时保留对应许可/NOTICE
信息。远端对象应采用不可变版本路径，更新通过 manifest 指向新版本，不能原地替换同一 URL 的内容。

当前仍是设计阶段，本次确认没有授权立即上传，实际模型获取、转换、校验与发布在实现/PoC 阶段执行。

现有 `publishDebugUpdate` 会清理 `/debug/apk` 中超过最近 5 个的 APK，因此模型只能复用同一服务器、
连接配置和发布模式，不能放入 debug APK 目录或复用其轮转清理规则。

## D13：稳定模型 catalog 独立于 APK 发布渠道（2026-07-31）

用户确认：

- 阿里云建立独立的稳定模型 catalog，例如 `/models/spatial-depth/catalog.json`；
- debug 与 release 构建默认读取同一稳定 catalog；
- debug 构建只有在显式开发配置下才读取 staging catalog；
- release 构建不能意外跟随 staging；
- 模型对象使用包含模型家族和版本的不可变 URL；
- 稳定发布只原子替换 catalog manifest，不覆盖已发布模型对象；
- APK 发布、回滚或 debug APK 清理不改变模型 catalog。

这样模型版本与 App 版本可以独立演进，同时仍由 manifest 的 `minRuntimeVersion` 等字段阻止不兼容组合。

## D14：图片生成是前台可取消任务（2026-07-31）

用户确认 v1 的深度生成不在离开查看器后继续：

- 模型已就绪后，在全屏查看器内启动生成；
- 界面展示“准备图片、估计深度、生成效果”等真实阶段，不伪造百分比；
- 用户主动取消、返回详情、切换附件或 Activity 结束时取消任务；
- 取消或失败会清理临时文件；已有旧结果继续可用；
- 只有完整生成并验证成功后，才把临时结果原子替换为正式派生结果；
- 首次生成成功后自动进入空间模式；
- v1 不用 WorkManager、前台服务或通知让图片计算在后台继续。

模型文件下载的生命周期另行决定，因为其体积和网络耗时与本地图片计算不同。

## D15：模型下载可后台续传，但不触发后台图片生成（2026-07-31）

用户确认模型下载与图片计算采用不同生命周期：

- 模型下载可以在离开查看器后继续，并在网络中断或 App 重启后恢复；
- 设置界面与系统通知显示进度，并提供取消入口；
- 下载先写 `.part`，支持安全续传；完成后校验字节数和 SHA-256，再原子发布为可选模型；
- 取消或长期未恢复的临时文件按明确的保留期限清理，期限在实现时确定并写入测试；
- 如果发起下载的查看器仍在前台，模型就绪后承接原生成请求；
- 如果用户已经离开，只提示模型就绪，不在后台解码或处理任何附件图片；
- 本地图片生成继续遵守 D14 的前台可取消边界。

具体采用系统 DownloadManager 还是受约束的持久 Worker，由实现 PoC 根据内部存储、续传、校验和
Android 版本行为决定；产品语义不依赖某个调度 API。

## D16：计费网络可下载，但必须二次确认（2026-07-31）

用户确认模型下载不设 Wi‑Fi 硬门槛：

- 在非计费网络上，仍按 D11 的首次明确确认启动下载；
- 在计费网络或系统流量节省模式下，额外显示准确 `sizeBytes` 并再次确认；
- 用户拒绝时任务保持未开始/等待，不偷偷切换网络或下载；
- 用户确认后允许继续，并保持 D15 的后台续传与取消能力；
- 首次下载、第二模型下载和模型更新都使用同一规则；
- App 不根据模型名称估算流量，以 catalog 中经发布校验的真实字节数为准。

## D17：模型更新手动且不破坏既有结果（2026-07-31）

用户确认：

- catalog 发现已安装模型的新版本时只在设置中提示，不自动下载；
- 在用户主动更新前，兼容的旧版本继续用于新生成；
- 更新下载沿用 D15/D16 的续传、取消、计费网络确认、字节数和 SHA-256 校验；
- 新版本完整可用后才原子替换旧模型包；
- 当前选择保持在同一模型家族，新生成开始使用新版本；
- 已有空间效果继续使用其原派生深度，不触发重算；
- catalog 可以把存在严重兼容/安全问题的版本标记为禁止继续生成，但不能阻止查看其已产生的自包含
  派生结果；
- 被禁止版本不可作为当前生成模型，设置界面说明原因并引导更新或选择另一个已下载模型。

## D18：完整派生结果持久保存，不受普通缓存淘汰（2026-07-31）

用户确认完整生成物命名为 **Spatial Photo Derivative**，其生命周期为：

- 存在 App 私有持久目录，而不是可被普通 LRU 清理的 cache 目录；
- 每张源图片最多一份，重新生成遵守 D8/D14 的原子替换；
- 删除源附件时删除对应 derivative；
- 单张图片提供“移除空间效果”，只删 derivative、不动原图；
- 设置显示全部 derivatives 的总占用，并提供“清除全部空间效果”；
- 临时文件、过期下载片段和已经失去源附件的孤儿 derivative 可以自动清理；
- 开始生成前检查可用空间；不足时拒绝新任务并提示，不静默删除完整结果；
- derivative 不参与 Thing 同步，也应排除出系统自动备份。

术语已写入 `CONTEXT.md`，明确其“持久但可重建”，既不是附件，也不是随时可淘汰的普通缓存。

## D19：v1 空间模式固定适应屏幕（2026-07-31）

用户确认空间模式不复用普通图片查看器的缩放语义：

- 当前附件锁定并以 fit-screen 加必要过扫描呈现；
- 单指只控制交互视点；
- v1 不提供双指缩放、缩放后的图片平移或 ViewPager 翻页；
- 退出空间模式后，普通查看态恢复现有 PhotoView 缩放、平移和附件翻页；
- 需要检查原始像素或 HDR 时使用普通查看态。

因此 v1 的颜色纹理只需覆盖屏幕像素密度与最大视点过扫描，不必为任意深度缩放常驻完整原图纹理；
实际纹理上限由设备与 PoC 决定。

## D20：已生成状态使用纯图形 Spatial Effect Badge（2026-07-31）

用户确认：

- 完整 Spatial Photo Derivative 存在时，详情附件缩略图显示 Spatial Effect Badge；
- 徽标必须是 icon，不使用“空间”“3D”等文字；
- 徽标只表达“本机已生成”，不作为生成或进入按钮；
- 点击缩略图仍按 D3 先进入普通全屏查看；
- Thing Card 封面不显示该徽标；
- 全屏查看器的空间效果入口显示已就绪状态；
- derivative 被移除或源附件删除后，徽标同步消失。

现有详情布局的媒体徽标位于左下角 40dp 横排，Motion Photo 已使用 16dp 图形标识。Spatial Effect
Badge 应复用该容器、尺寸层级、透明度与可访问性规则，并能与 HDR 徽标并排。

术语已写入 `CONTEXT.md`。

## D21：v1 不提供手动深度编辑（2026-07-31）

用户确认 v1 不包含：

- 深度画笔；
- 前景/背景蒙版；
- 物体选择与局部深度修正；
- 遮挡补图的人工编辑。

结果不理想时只提供三种处理：

1. 实时调低或调整 Spatial Effect Strength；
2. 选择另一个模型后对该图片主动重新生成；
3. 移除 Spatial Photo Derivative，继续查看原图。

这让 v1 验证自动深度、后处理与交互渲染本身，不把范围扩大为通用图像编辑器。手动编辑只有在真实
用户样本证明自动方案系统性无法修复、且简单重做不足时才重新评估。

## D22：软质量风险不阻止生成（2026-07-31）

用户确认采用“尽量生成、保守呈现”：

- 不因图片被判断为截图、文字、镜面、透明物、毛发或复杂细线而隐藏入口；
- 不把模型置信度或启发式质量分数当作绝对可用性结论；
- 风险较高时降低自动 Spatial Effect Strength，并在首次进入时给出简短、非阻塞提示；
- 用户仍可实际查看并调强度、换模型重新生成或移除 derivative；
- 只有确定的硬失败才中止，例如解码失败、深度含无效值且无法修复、输出尺寸/完整性错误、设备资源
  或磁盘空间不足、模型初始化失败；
- 硬失败不发布 badge 或半成品，并保留原图及已有旧 derivative。

自动质量指标仍用于测试 corpus、默认限幅与遥测日志（仅本机技术日志），不成为内容准入分类器。

## D23：远端模型 catalog 使用分离信任根的 Ed25519 签名（2026-07-31）

用户确认模型分发不能只依赖 HTTPS 与服务器同源提供的 SHA-256：

- stable 与 staging 各使用一套独立的 Ed25519 密钥；
- 私钥离线保管，不进入代码仓库、APK、阿里云模型目录或服务器运行环境，仅在受控发布步骤中用于签名；
- release 构建只内置并信任 stable 公钥；
- debug 默认使用 stable catalog 与 stable 公钥；显式 staging 构建配置改用 staging catalog 与
  staging 公钥，不在运行时混合信任两个渠道；
- 签名覆盖版本化、确定性的 catalog payload 字节。App 只能先读取签名封装所需的最小元数据，
  验证签名成功后再解析或采用 URL、`sizeBytes`、SHA-256、兼容版本与禁用状态；
- catalog 验签失败、格式错误、密钥标识未知或暂时不可用时关闭新的安装/更新流程，但保留已安装模型
  和已有 Spatial Photo Derivative 的使用能力；
- 模型下载完成后仍须验证已签名 catalog 中的准确字节数、SHA-256，并通过模型初始化自检，全部成功
  后才原子发布为可用模型；
- catalog 自身不能授权新的信任公钥。正式密钥轮换需要先通过 App 更新加入新公钥，并保留明确的
  双密钥过渡窗口，之后再移除旧公钥。

HTTPS 继续提供传输机密性与常规服务端认证，Ed25519 则把模型版本及其哈希绑定到离线发布身份。该
决定详见 [ADR-0019](../../adr/0019-signed-spatial-model-catalog.md)。

具体内存、耗时和设备能力阈值由双模型 Android PoC 以真实数据确定，不在需求阶段臆定机型白名单。

## D31：模型准入使用设备总内存与实时可用内存（2026-07-31）

双机集成时发现 Android 的 `memoryClass` 只表示当前 App 的 Java heap 上限，不能代表设备物理内存，
用它判断 DAV2 会把两台实际可稳定运行该模型的设备错误标记为不兼容。因此准入分为两层：

- 下载前静态准入读取 `ActivityManager.MemoryInfo.totalMem`，ZipDepth 至少 3 GB，DAV2 Small
  至少 6 GB；
- 每次生成前再读取 `availMem` 与 `lowMemory`，分别要求至少 512 MB 与 1024 MB 实时可用内存；
- 不根据机型名称建立白名单，也不把 Java heap `memoryClass` 当作设备内存；
- 下载后的完整 ONNX session 自检仍是最终可用标记的必要条件。

这些阈值来自本轮双机峰值内存与推理实测；后续低内存设备矩阵可以提高门槛，但不能在没有证据时
降低到可能触发系统回收或崩溃的水平。

## D33：ONNX Runtime 按设备 ABI、按需下载（2026-07-31）

用户确认 ONNX Runtime 不再作为四套 ABI 原生库全部进入通用 APK：

- APK 保留编译所需的 Java API，但排除 `libonnxruntime.so` 与 `libonnxruntime4j_jni.so`；
- 首次需要执行模型自检或生成空间效果时，只下载当前设备 ABI 对应的运行组件；
- 运行组件与模型使用同一个由 Ed25519 签名的 stable/staging catalog 信任边界，并继续校验准确
  字节数、SHA-256、解包后文件哈希和运行时版本；
- 安装位置为 App 私有、no-backup、版本化目录；完整校验并设为只读后才允许加载；
- ZipDepth、Depth Anything V2 Small 以及后续 Spatial Video Effect 共用同一份兼容运行组件；
- 删除运行组件不删除模型或 Spatial Photo Derivative；已有结果仍可查看，后续重新生成时再下载；
- 设置界面独立显示运行组件的状态与占用；模型下载在运行组件缺失时把它作为前置步骤，不重复下载；
- 直接分发版本可从 EverythingDone 的阿里云服务器取得 `.so` 包。若未来通过 Google Play 分发，
  该渠道必须改用 Play Feature Delivery 或把裁剪运行时放回 Play 交付物，不能从 Play 外下载
  可执行代码。

当前 ORT Java Android 加载路径默认使用 `System.loadLibrary()`；实现必须在任何 ORT 类初始化前，
按绝对路径先加载核心库和 JNI 库，并用两台授权设备验证重复加载、进程重启、删除和升级行为，不能
仅通过 Gradle 排除 `.so` 后假定运行正常。

反编译 1.28.0 AAR 后确认：`OnnxRuntime.load()` 在 Android 分支会提前返回，确实不会读取
`onnxruntime.native.path`。Android 也不允许修改 `java.vendor`，因此不使用伪装平台属性的方式
绕过该分支。App 改用固定上游哈希、可重复生成的 Java-only ORT jar，只对
`OnnxRuntime.load(String)` 增加一个受结构校验的条件：设置 `onnxruntime.native.path` 时复用上游
已有的绝对路径分支，否则保留官方 `System.loadLibrary` 行为；jar 不含任何 native library。

所有调用仍统一经过 `SpatialOrtRuntime`：先对私有目录两库完成哈希、只读检查和绝对路径预加载，
再在首次 ORT 初始化的同步窗口设置 native 目录，初始化完成立即恢复属性。任何推理或 Debug
benchmark 都不得绕过该入口；不能回退到未校验的 linker 搜索路径。

## D34：增强连续逆向重投影（2026-07-31）

用户反馈首版空间效果偏弱，因此在不重新生成既有 derivative 的前提下升级渲染器：

- 保持单值、连续的逆向 UV 映射，不采用会在深度断层形成条带的离散分层；
- 发布前的人物素材极限视点回归发现，非线性深度对比与单纹素补偿仍会在近远景突变处产生 UV
  折返。最终改为仅在加载场景时生成斜率受限的渲染深度：分别计算深度的上下 Lipschitz 包络并取
  中点，将相邻深度变化限制为 0.02，再以线性深度执行位移。该副本不写回 derivative，也不参与
  默认强度计算；
- 将最大视差幅度由纹理宽高的约 2% 提高到约 3.4%，过扫描同步由 4.5% 提高到 5.8%，避免露出
  纹理边缘；
- 原始深度保留为独立纹理，只在视点发生偏移时用于最多 4% 的有界明暗变化；几何位移不再直接
  使用原始深度断层；
- 提高触摸与姿态的映射灵敏度，新生成结果采用更高的默认强度；用户仍可在单图强度滑杆中降低；
- 渲染升级直接作用于已有 derivative，深度数据格式和持久化 schema 不变，也不引入重新推理。

## D35：以形变预算限制危险视差，并用刚性取景移动保留交互强度（2026-07-31）

D34 消除了 UV 折返，但真实人物素材仍有约 0.586～1.414 倍的局部采样步长，连续坡面会把人物和
直线拉伸。短期渲染安全层按以下方式落地：

- 场景上传时分析**实际传给 GPU 的 8-bit 渲染深度**，而不是未量化的浮点副本；对相邻深度差按
  归一化纹理坐标换算梯度；
- 当前映射的局部雅可比附加项为 `motion ⊗ depthGradient`。把其算子范数上界限制为 0.22，相当于
  将局部尺度变化保守控制在约 0.78～1.22；超限时只同比例缩小当前视差向量，不改变视点方向；
- 常量深度和平缓坡面不削弱；只有高梯度素材的极端视点受限。真实 OnePlus 回归素材在当前默认强度
  下，局部采样步长收敛为约 0.8245～1.1755，左右方向折返点均为 0；
- 为避免“降低危险视差”等同于“交互变弱”，另加入 0.012 的整幅刚性取景移动。刚性分量不改变
  局部形状，与最大相对视差合计仍小于 0.058 过扫描边界；
- 原始深度产生的明暗 relief 从增益 0.35、最大 ±4% 降为增益 0.18、最大 ±1.8%，避免在人脸、
  文字和高对比轮廓上强化不真实起伏。

该决策不改变 Spatial Photo Derivative schema，已有结果立即受益。它是连续单纹理渲染的安全阀，
不能替代 DIBR 的遮挡表示；困难图片若要在保持强相对视差的同时进一步减少形变，仍需按专项调研推进
LDI-lite / 软分层。

## D36：P1 使用显式遮挡表示，并把生成式窄带补全纳入主路径（2026-07-31）

用户同意继续推进 P1。使用真实多人近景原图与 ZipDepth derivative 的一次性原型确认：

- P0 因全局形变预算只能保留 36.1% 请求视差；显式断边网格可保留完整 0.054 请求视差；
- 600px 长边、RGB 引导的边界网格在左右极限视点共使用 531,698 个三角形，未发生三角形折返；
- 规则背景传播虽然能把安全区空洞率降到 0，但会在人物肩部、头发和车体旁形成明显错误色带，
  不能作为产品补全方案；
- 官方 MI-GAN ONNX pipeline 只处理约 6.05% 的隐藏背景窄带后，真实素材中的主要错误色带明显
  消失；本机桌面 CPU 单次记录为 session 加载约 226ms、推理约 303ms，仅用于路线验证，不能
  代替 Android 真机数据。

因此正式架构不把 LDI-lite 与 inpainting 当作二选一：

- derivative v2 必须保存显式连接/遮挡关系、高分辨率软边界、隐藏背景颜色与保守背景深度；
- 交互渲染只做背景层与可见表面层的 GPU 前向投影、深度测试和合成，不逐帧执行任何模型；
- 生成式补图只在创建或重新生成 derivative 时运行一次，并且只处理最大允许视差可能显露的窄带；
- 现有 derivative v1 继续走 D35/P0；只有重新生成成功后才原子替换为 v2；
- PoC 的 53 万三角形只是质量上界，不直接照搬到手机；正式实现需采用分块索引或边界自适应网格，
  用真机帧时间与内存决定最终密度；
- MI-GAN 已证明接口方向可行，但是否作为第三个按需下载组件、采用哪个导出版本及其手机准入门槛，
  仍须在 Android PoC 后单独确认，不能把桌面结果写成发布承诺。

## D37：P1 v2 采用双层前向网格与按需 MI-GAN（2026-07-31）

在 D36 的原型证据上，首个可安装实现采用以下产品与技术契约：

- 新生成结果使用 Spatial Photo Derivative schema v2，保存 600px 长边 RGB 引导网格所需的表面
  深度、保守背景深度、断边/隐藏区 bitset 与补全背景；每个文件单独校验 SHA-256，完整验证后才
  原子发布；
- GLES2 交互渲染先画背景层，再画按断边拓扑切开的表面层并深度测试。网格用重叠行块拆分为
  `uint16` 索引缓冲，保持 GLES2 兼容；运行时不执行 inpainting；
- 官方 MI-GAN pipeline v2 作为第三个独立按需组件，由既有 Ed25519 签名 catalog 和私有
  no-backup 原子安装链路分发；设置页允许下载、删除和重新下载；
- MI-GAN 缺失、自检失败、资源不足或生成失败时，不使用已被真实素材证明不合格的规则传播结果
  冒充 P1，也不替换现有 derivative。原图与 schema v1/P0 结果保持可用；
- 首版准入门槛为设备总内存至少 4 GB、准备推理前可用内存至少 768 MB；这只是保护条件，不代表
  已完成 Android 性能承诺；
- 既有 schema v1 不后台迁移。用户必须主动重新生成并成功完成 v2 事务，才会获得双层效果。

MI-GAN 模型本体为 28,079,181 字节，不进入 APK；它与 ZipDepth、DAV2 Small 共用同一按需
ONNX Runtime。首个 debug 版本只完成编译、JVM 和离线素材验证，Android 推理峰值内存、耗时及
不同 GLES 驱动的帧时间仍属于发布后的真机验收项。

## D38：P0/P1 按图片即时切换，双层也执行形变预算（2026-07-31）

用户反馈 P1 双层并非对所有内容都更自然，因此 schema v2 结果同时保留原始深度与 LDI-lite 数据，
查看器提供同图即时对照：

- P0 单层与 P1 双层共用当前视点、强度和交互状态，切换时不重新估深、不重新补图，也不重置视角；
- 选择写入当前 derivative manifest，下一次打开同一图片恢复；schema v1 只能使用 P0；
- 强度与模式这两类小型 manifest 更新统一使用 Android `AtomicFile`，写入异常时恢复旧 manifest，
  不允许一次设置操作使完整 derivative 失效；
- 开关只改变当前图片的渲染表示，不改变全局模型选择，也不影响已生成背景；
- P1 不能再以“有背景层”为由绕过 D35 的 Jacobian 形变预算。两条渲染路径统一通过
  `safeParallaxMotion` 限制危险的连续表面拉伸；P1 的预算分析会忽略已经声明为断开的边，只约束
  仍有三角形连接的表面，因此背景层承接的遮挡视差不会被 P0 的全局最坏边缘错误削弱；
- P1 的优势限定为显式遮挡与背景显露，不把完整请求视差当作质量目标。

这项切换也是后续盲评的必要观测工具；设置默认或产品文案不得宣称 P1 对所有图片必然更好。

## D39：补图提供 MI-GAN 与 AOT-GAN 两种按需选择（2026-07-31）

统一转换与真实显露带对照后，稳定产品提供两个本机补图模型：

- MI-GAN Places2 pipeline 保留为快速选择，28,079,181 字节，适合人物轮廓等较窄显露带；
- AOT-GAN Places2 使用官方 `G0000000.pt` 导出为 opset 18 动态空间 ONNX，60,989,366 字节，
  PyTorch/ONNX 最大绝对误差小于 `0.001`；
- AOT-GAN 提供 512、768、1024 三档工作长边，默认 768；用户选择的档位不静默降级，生成前按
  总内存与实时可用内存门禁；
- 两个模型可以分别下载、删除和选择。选择只影响新生成或主动重新生成；derivative 记录实际模型、
  版本与 AOT 工作分辨率；
- AOT-GAN 不是统一的“更高质量”标签。设置文案明确它在较宽显露区和规则场景可作为另一种结果，
  但可能不如 MI-GAN；由用户结合 P0/P1 对照选择；
- AOT mask 下采样使用保守覆盖，任何源显露像素都不能被最近邻采样漏掉。

Big-LaMa FP32 ONNX 约 208 MB，在本次两个样本上没有形成稳定质量优势，session 初始化和内存代价
又显著更高，因此不进入 stable catalog。Moebius、其它 diffusion 与 Flow Matching 候选在缺少
可再分发移动权重、端侧峰值和时延验证时也不进入设置页；长期仍按任务专用
`RGB + mask + depth + camera` student 推进。

## D40：裁剪 Runtime r2 保持 API 1，并以包版本触发安全升级（2026-07-31）

AOT-GAN 新增 `Cast`、`Pad`、`ReduceProd`、`Sqrt`、`Tanh` 等算子；发布前的完整模型审计还确认
MI-GAN pipeline 使用 opset 17，并需要 `GatherND`、`NonZero`、`ScatterND` 等此前深度模型配置
没有包含的算子。按需 Runtime 使用四个发布模型的完整算子并集重建为 `1.28.0-r2`，但这些变化只
扩大算子集合，不改变 ORT Java/JNI ABI：

- catalog 的 `runtimeApiVersion` 继续为 1，使旧版 App 可以安全使用 r2 超集包，不因 catalog 更新
  被整体拒绝；
- AOT-GAN 不直接加入旧版 App 会逐项严格校验的 `inpaintingModels`；它进入 schema 1 的可选
  `additionalInpaintingModels` 扩展。旧 Gson 忽略该字段并继续取得 MI-GAN 与 r2，当前版合并两组
  后再执行完整 ABI 校验；
- 当前版 App 同时要求精确 `packageVersion = 1.28.0-r2`，因此已安装但缺少 AOT 算子的 r1 会被
  视为需要升级；
- r2 安装并切换 current marker 后清理 App 私有目录中的旧 Runtime 包，避免升级造成永久重复占用；
- 四个发布模型都只使用标准 `ai.onnx` 域；构建关闭未使用的 ML 算子域，并由逐模型算子清单裁剪
  标准 CPU kernels。非 minimal build 为布局优化自动保留的少量内部 contrib kernel 不属于
  catalog 声明的模型能力；
- 模型、Runtime 和许可仍通过同一 Ed25519 签名 catalog、不可变 URL、准确字节数和 SHA-256
  信任链；APK 继续不携带四套 ABI 的原生库。

若以后 Java/JNI 契约、加载顺序或可观察执行语义发生不兼容变化，必须提升
`runtimeApiVersion`，不能继续借用包版本表达真正的 ABI 断裂。

## D41：SHARP 与 MetaView 只作为任务专用模型参考，不进入产品依赖（2026-07-31）

复核最新单图新视角路线后，不把“更接近 Apple”直接解释为采用 Apple 研究权重或桌面 diffusion：

- SHARP 的 metric 3D Gaussian 表示与邻近视角实时渲染是长期架构的重要参考，但官方模型约
  2.81 GB，模型许可只允许非商业科研并明确排除 product development；不得下载后集成、转换后
  发布或上传 EverythingDone 的阿里云目录；
- MetaView 把目标相机、metric depth 与隐式几何条件注入 diffusion，适合作为未来 teacher 设计
  参考；当前实现依赖 20B 参数 Qwen-Image-Edit、两个 Depth Anything 3 Giant 模型和桌面 PyTorch
  栈，其中 DA3-GIANT 还是 CC BY-NC 4.0，不能构成 Android 产品依赖；
- 未来若出现许可允许、可再分发且满足 Android 资源门槛的新视角权重，必须按独立 provider、
  派生 schema 和渲染器做 PoC，不能把它伪装成现有 RGB inpainting ABI；
- 当前 stable 方案继续使用 P0/P1、MI-GAN/AOT-GAN 和裁剪 Runtime；长期目标仍是由合法 teacher
  训练或蒸馏 `RGB + mask + depth + camera` 条件 student，输出隐藏 RGB/深度、软分层或少量
  3D Gaussian。

## D42：Runtime r2 不全局禁用 contrib 源码，只保留 ORT 优化器所需的最小注册（2026-07-31）

四个发布模型均不使用 contrib operator，`required_operators.config` 也不包含 `com.microsoft`
域；但 ONNX Runtime 1.28.0 的 arm64 FP16 `Conv` 实现会复用
`contrib_ops/cpu/fused_activation.cc` 中的 `GetFusedActivationAttr`。若同时传入
`--disable_contrib_ops`，算子裁剪仍会实例化该标准 `Conv` kernel，却不会编译辅助函数，最终在
`libonnxruntime.so` 链接阶段产生未定义符号。

因此 r2 构建采用以下边界：

- 不再传入全局 `--disable_contrib_ops`，保证 ONNX Runtime 自身的跨模块源码依赖闭合；
- 发布模型算子清单仍只有 `ai.onnx`；reduced-op 生成代码排除普通 contrib kernel，只保留
  ONNX Runtime 非 minimal 布局转换自动加入的 `NhwcFusedConv`、量化 NHWC 等内部依赖；
- 保留 `--disable_ml_ops`、逐模型标准算子并集、LTO 与链接器 section GC；这不是给 App 增加
  contrib 模型能力；
- 这些保留项不是新的可选模型 provider，也不改变模型 catalog 的兼容性契约；
- 四个 ABI 的最终 ZIP、内部 so 和 catalog 仍须逐项记录字节数与 SHA-256，实际体积以产物验证
  为准，不能用一次 armv7 成功推断 arm64 链接也必然成功。

## D43：裁剪 Runtime 上的推理会话一律 NO_OPT，算子配置改从优化后模型生成（2026-07-31）

用户真机上 AOT-GAN 下载后自检失败：`ORT_NOT_IMPLEMENTED, Failed to find kernel for
com.microsoft.FusedConv(1) (node: '/encoder/encoder.1/Conv')`。根因是 D40/D42 的算子
配置只统计了四个模型的静态图算子，而两个引擎的会话使用 `ALL_OPT`：ORT 图优化器在会话
初始化时会新造图里不存在的算子。桌面 1.27 对四个发布模型的优化转储证实：

- EXTENDED 级下四个模型（含 MI-GAN 与两个深度模型）全部会产生 `com.microsoft.FusedConv`；
  DAV2 另有 `FusedMatMul`、`Gelu`、`SkipLayerNormalization` 与 `ai.onnx.Split`；
- BASIC 级下 DAV2 会经 MatMulAddFusion 产生 r2 未编译的标准算子 `ai.onnx.Gemm`。

因此：

- `SpatialDepthEngine`、`SpatialInpaintingEngine` 与 debug 基准接收器的会话在已发布的
  r2 上一律使用 `NO_OPT`——这是唯一不依赖任何未经真机验证的优化器行为的级别；模型导出
  时已做常量折叠，且每次生成只推理一次，优化损失可接受；
- 算子配置改由 `generate-ort-required-operators.py` 从「按 BASIC+EXTENDED 优化后的模型」
  生成（ORT 文档对 reduced build 的既定要求），`verify-spatial-model-operators.py` 降级为
  静态回归工具；
- 用新配置重建 Runtime r3、发布并通过四模型真机自检之后，才允许把会话恢复到
  EXTENDED/ALL 并同步提升 `REQUIRED_PACKAGE_VERSION`；
- 遗留悬案（当日已解）：OnePlus 真机的 runtime 标记显示 r1 实为 `1.28.0-full-r1` 完整版
  ORT（核心库 28.6 MB），并非裁剪包——深度模型当时通过 `ALL_OPT` 自检靠的是全量 kernel，
  与桌面转储并不矛盾。首个真正的裁剪包就是 r2，其真机首秀即暴露本缺陷。

PoC 文档中的推理耗时均在完整 Runtime + `ALL_OPT` 下测得，不再代表当前 NO_OPT 路径；
性能数字以 r3 真机重测为准。

## D44：补图模型不可用时提供显式单层回退（2026-07-31）

此前任何生成（包括 P0 单层）都硬性要求「当前选中的补图模型已安装且可用」，而设置页的
补图单选钮只有已安装才能点选。AOT-GAN 自检必失败、失败即删除的组合把整个生成入口封死，
用户无法退回本来可用的仅深度路径。修订为：

- 深度模型与 Runtime 仍是生成的硬前置；补图模型不可用（未安装、内存不合格或实时内存
  不足）时不再拦死，而是弹出三键对话框：「仅生成单层」立即走 P0-only 生成（derivative
  落为 schema v1，不含 LDI 数据），「前往设置」保留原有的 pending 承接流程，取消则不动；
- 重新生成场景下若现有结果为双层，对话框额外明示「双层效果将被单层结果替换」；
- 这不是静默降级：单层回退必须经用户在对话框中明确选择，D36/D37「不用不合格结果冒充
  P1」的边界不变，P1 仍要求真实补图；
- 下载自检失败与下载失败在 Worker 与设置页分开呈现（`模型真机自检未通过：…` 与
  `下载失败：…`），不再把 ORT 初始化错误伪装成网络问题。

## D45：视差幅度短期三项的取值（2026-07-31）

依据 research-2026-07-31-parallax-uplift.md 的量化结论实施：

- **统一斜率尺子**：新常量 `MAX_RENDER_SLOPE = 9`（归一化满幅单位），P0 的
  `stabilize` 与新增的 P1 `stabilizeConnected` 都按 `9 / 网格宽（高）` 钳制逐格相邻差；
  P1 只沿仍连通的边传播包络，显式断边两侧互不影响（跳变由背景层承接）。取代原
  `MAX_NEIGHBOR_DELTA = 0.020`（该值只在 384 网格上等效 7.68，不同模型/网格不一致，
  且 P1 完全没有钳制）。渲染网格顶点与预算分析共用钳制结果，两趟包络在断边网格上的
  少量残留仍会被随后统计计入预算，不会漏出约束。
- **预算统计改高分位**：`SpatialWarpBudget` 从全图最大梯度改为水平/垂直各取 P99.5 再
  合成（`BUDGET_PERCENTILE = 0.995`）；孤立坏点不再吞掉整图行程，分位以上零星边的
  局部拉伸为可接受代价。`MAX_DISPLACEMENT_GRADIENT` 0.22 → 0.32（局部尺度约
  0.68～1.32）。
- **幅度与过扫描**：`MAX_PARALLAX_AMPLITUDE` 0.068 → 0.09，`OVERSCAN` 0.058 → 0.09
  （覆盖 0.09×0.5 + 刚性平移 0.012 + relief 0.018 = 0.075）；`MIN_PARALLAX_AMPLITUDE`
  与 `RIGID_PAN_AMPLITUDE` 不变。折返安全裕量：0.09 × 9 = 0.81 < 1，钳后深度在满幅
  视差下不可能折返。
- **数字口径**：最坏内容上限 2.86% → 3.56% 画宽；平滑内容从被最坏单点连坐的 ~2.9%
  解放到完整 9%；P1 上限不再低于 P0。debug 构建每次 setScene 在 logcat（tag
  `SpatialWarpBudget`）打印双路径 P99.5 梯度与实际位移上限，供真机验证。

## D46：P1 连通陡带从「钳斜率」改为「升格断边」（2026-07-31）

用户反馈「立体」高强度下画面明显扭曲。机制：D45 第一版把陡而未断的连通边钳成斜率 ≤9
的坡保留在网格里，满幅 9% 视差下坡上的局部形变可达 0.09×9=0.81——预算的 P99.5 统计
豁免了这些尾部边，橡皮拉伸因此在高强度下直接可见。修订：

- `stabilizeConnected`（连通面 Lipschitz 钳制）删除，替换为
  `promoteSteepEdgesToCuts`：量化斜率超过阈值的连通边直接升格为断边，跳变交给背景层
  显露；连通面深度原样保留，不再被包络磨平。
- 升格阈值由预算反推：`MAX_DISPLACEMENT_GRADIENT / MAX_PARALLAX_AMPLITUDE ≈ 3.56`
  归一化斜率。残余连通边在满幅视差下的单轴局部形变必然 ≤0.32，预算限幅对单轴陡度
  失效，仅双轴同陡的对角内容才会再收紧行程。
- 这是 research-2026-07-31-parallax-uplift.md 中期项「过渡带归入断边」的渲染端实现；
  生成端的深度边缘锐化仍留作后续。已知代价：升格处从「拉伸」变为「层间显露」，显露
  内容是背景板在该处的原图像素，遮挡轮廓附近可能出现轻微重影或碎屑边，属软边界
  中期项范畴。P0（稳定）路径不变。
- 已有派生结果免重生成受益（升格发生在渲染时）。

## D47：生成端深度边缘锐化与补图掩码加宽（2026-07-31）

轮廓显露带的深色碎屑有两个生成端来源，一并治理：

- **深度边缘吸附（edge snap）**：`upsampleDepth` 与 `guidedFilterDepth`（系数二次 box
  均值，halo 可宽至 4×半径≈25 格）会把真实遮挡边摊成逐格差低于断边阈值的过渡带，
  `buildEdgeGraph` 漏检后 `regularize` 再把它磨成大范围宽坡——这是高强度扭曲与显露
  碎屑的共同根源，低 RGB 对比（深色头发对深色背景）时最严重。现在在断边判定前运行
  `snapDepthEdges`：行、列两方向把「逐格差 ≥0.004、同向、长度 ≤4r+2 格、总落差
  ≥HARD_DEPTH_EDGE」的短陡单调带以最陡边为界吸附成锐利台阶。真实缓坡（逐格差低于
  下限）与长距离陡坡（超带长）不受影响。
- **补图掩码膨胀 1→2 格**：背景板在轮廓两侧 1–2 像素是前景/背景混合像素，只膨胀
  1 格会把这圈暗环留作补图上下文，显露时呈现深色碎屑；半径 2 让补全覆盖暗环。
- 真机对比（满强度极限视点）：肩部/身体轮廓旁碎屑散点基本消失、显露内容连贯；头发
  等柔性边缘的锯齿仍在，属软边界（soft alpha/matting）课题。改动在生成时生效，旧
  结果通过「重新生成」获得改善；D46 的渲染端升格保留为旧派生的兜底。

## D48：显露黑块与发虚轮廓的两级修复，MPI PoC 启动（2026-08-01）

用户以「测试空间效果」记事（真实弱光人像）复现：大视差下轮廓旁出现锯齿状纯黑碎块与
随前景移动的发虚色边。诊断与修复：

- **黑块 = 背景层网格空洞**（主因，与补图质量无关）：`buildLdiChunks` 此前按
  `backgroundDepth` 相邻差 ≥0.05 丢弃背景三角形，而隐藏带外缘必然存在「传播远深度跳回
  表面深度」的跳变——每条带的外缘都缺一圈三角形，前景移开时两层皆空，露出 GL 清屏
  黑。修复：背景层永远全连通（删除该判定与 `BACKGROUND_HARD_DEPTH_EDGE`）；接缝斜坡
  大部分被前景遮挡，远好于露黑。渲染时生效，旧派生即时受益。
- **发虚色边 = 前景断边内缘的混合像素**：生成端新增 `carveForegroundRim`——每条断边
  近侧 1 格四边全断（不再产生表面三角形），由背景扩展标记为隐藏、交补图覆盖。只剥
  近侧；重新生成后生效。
- 真机同图对比（满强度极限视点）：黑色碎块完全消失，显露带呈连贯背景内容；残余为
  显露区轻微接缝拖影与更柔的头发边缘期待。
- **MPI PoC 首轮点亮**：`SpatialMpiBuilder`（10 层 800 长边软切，深度三角核 + 3×3
  预乘羽化，前景 + 隐藏背景两路贡献）与渲染器 MPI 路径（预乘 alpha 由远及近合成，
  无形变预算，内缩采样窗防越界）落地；`SpatialRenderMode.MPI("mpi")` 仅 debug 构建

## D52：Runtime r3 定版与 DA3-SMALL 接入方案（2026-08-01）

- **r3 内容**：算子清单 = 五模型（ZipDepth/DAV2/MI-GAN/AOT-GAN/DA3）BASIC+EXTENDED

  r2 catalog（空间功能不受影响，仅不再刷新）。这是 runtime 升级的既有过渡语义；若

- **许可**：DA3 仅 SMALL 档为 Apache-2.0（更大档位 CC BY-NC，禁止误发），许可文件随

## D53：锐边深度模型的渲染端适配（闭运算 + 旁路引导滤波）（2026-08-01）

第三轮 A/B 判明 DA3 碎屑机理后（深度 1–2 px 过渡 → 450×600 网格上全部越过 D46
晋升阈值 → 发丝外缘与内部条缕密集断边 → D48 剥边成散点洞 + 细带补图块状涂抹），
按「渲染端适配锐利深度」定案两步，均以 `SpatialDepthModel.sharpDepthEdges` 标志
（现仅 DA3 为 true）作用于生成期、不改既有模型行为：

1. **归一化后灰度闭运算（半径 3，方形结构元，可分离实现）**：把 ≤ 约 6 px 的
   发丝间隙并入前景团块，消除亚网格的前/背景交替；外轮廓位置与锐度不变。半径 2
   的首验不足（碎屑仅减少），加到 3 并叠加第 2 步后达标。实现于
   `SpatialDepthNormalizer.normalizeAndCrop(closeRadius)`，边缘统计与默认强度按
   闭合后的深度计算；`SpatialDepthData.sharpEdges` 随之置位（仅生成期语义，
   不落盘）。
2. **几何构建跳过引导滤波**：引导滤波是给糊边模型做图像边缘对齐的补偿；对已贴合
   轮廓的锐边深度，它反而在低对比区（暗发对暗背景）把边缘按亮度重新糊开、再被

真机复验（同管线、立体满强度六方向 + 稳定双向，放大 2.2×，证据
`out/device-ab-20260801/skip_ab_*.png` 与 `stable_check.png`）：碎屑链与发际缺口
消失，边界连贯贴合轮廓；DAV2 的宽粘连晕类伪影在 DA3 上不存在。残留：断边路径的
格级台阶（网格分辨率固有）、显露区补图保真度（MI-GAN 暗景平涂，与 DAV2 显露区

## D55：公制深度模型的视差对比度压缩（2026-08-01）

用户目检发现 DA3 在单人像上扭曲/破碎/模糊反而更差（真机 A/B 证实：主体位移
过大、近物拉伸、耳坠被吞、耳颚与双人像边界成串阶梯撕裂）。定量根因：1/depth
线性归一化后主体-背景视差间隔达 ~0.9（DAV2 类输出仅 ~0.6）、脸部内部梯度 2.6 倍
——层间位移、显露带宽、边界撕裂、面内弯折全部随对比度放大。

**修法**：`SpatialDepthModel.disparityContrast`（默认 1，DA3 = 0.72）——归一化与
闭运算后绕 0.5 线性压缩视差。线性映射保持单调、梯度均匀衰减；此前尝试的
17 结点分位数重映射（DA3→DAV2 形态）已被证伪弃用（单调双射压近端必然在值域
别处变陡，跨图相关性反降）。0.72 由间隔比 0.6/0.9 定，也落在偏好数字上。

真机复验（同管线 A/B，立体满强度，脸部/躯干双窗口 + 双人像 L/U，证据
`out/device-qa-20260801/`）：耳坠恢复、耳颚撕裂与双人像阶梯撕裂基本消退、主体
位移回到 DAV2 量级、酒杯与手臂边界优于 DAV2 且无其青色镶边。残留：耳垂下 1–2
格小台阶、椅板镂空硬边（两模型同有）、显露区补图保真度（既有类）。

## D56：公制遮挡判据取代归一化步进（2026-08-01）

用户批评连环补丁在过拟合单图（D53/D55/被撤销的内部愈合阈值均按同一张照片校准），
要求根因分析。根因：**断边（遮挡）判定消费归一化相对视差**——该信号跨模型、
跨场景无稳定语义；0.05 步进阈值在 DAV2 的糊边分布下恰好近似遮挡，在 DA3 的锐利
分布下把颈颚、手袖等连续褶皱也判成遮挡（倾斜/持续偏移下头身分离、手袖滑移撕裂），
近摄场景整体被切碎（旧判据切 4% 像素）。DA3 本携带公制几何，被归一化销毁。

**修复**：公制模型的遮挡判据搬进公制空间——`metricInverseDepth`（未归一化逆深度
裁剪副本，与归一化场同做闭运算保持拓扑一致）随 SpatialDepthData 传到几何构建；
断边 ⟺ 远/近深度比 ≥ `OCCLUSION_DEPTH_RATIO = 1.2`（0 = 无穷远天然成立）。常量
有几何含义：连续人体/物体结构相对深度差 ≲15%，分离物体 ≳30%。归一化视差只再
服务渲染幅度（D55 保留，定位为渲染域整形）。非公制模型走原判据不变。

**验证**：五张测试图交叉分类（ratio_cut_validation.py 叠加图：剪影全保留、内部
褶皱与近摄碎切全移除、att2 人-人贴近段愈合为软过渡）；真机 att1 四角驻留手袖
分离清零、耳坠/酒杯完整，att2 近者脸缘亮缝消失。被撤销方案：分位数重映射
（跨图病理）、归一化域内部愈合阈值补丁（0.5/0.12 无物理含义）。

## D57：以 source-locked layered splat 取代删面式 LDI 与手工 MPI（2026-08-01）

两张“测试空间效果”附件仅作为故障探针。代码不变量证明当前三条路径都没有严格满足
`camera=0 ⇒ 原图`：P0/LDI 零视点仍做固定 overscan；LDI 在 depth cut 处删除表面
三角形并让生成背景从参考视点透出；matting 把已经合成的原图 RGB 再乘 alpha；MPI 把
十个低分辨率深度桶做 `compositeBehind` 后又逐层 over，且零视点仍 inset。继续调深度、
matting、层数、MSAA 或只替换补图器无法修复这些表示层错误。

质量主线改为 **source-locked layered splat**：全分辨率原图可见层、断层两侧完整样本、
遮挡处 1～2 个带 RGB/depth/alpha/confidence 的持久隐藏层，以及基于 z/置信度的前向
splat 可见性解析。生成内容只进入真实新显露区域，零视点使用与普通查看器一致的原图
变换。当前 handcrafted MPI 与删面式 LDI 不再作为最高质量架构继续堆参数。

实施顺序固定为：P0 先建立参考恒等、源像素锁定、拓扑与清晰度门槛并替换渲染基元；
P1 构建真正的 soft-LDI/分层 splat 与隐藏深度；P2 再用多视角/视频监督训练端侧
task-specific student。Diffusion 或 Flow Matching 只作为 P2 的 teacher/student 训练
与采样候选，不作为面向用户的架构标签，也不阻塞 P0/P1。

## D58：P0 使用原图锁定、拓扑感知 splat 与前景去污染合成（首轮形变验收失败，2026-08-01）

按 D57 落地第一阶段，不再沿旧 LDI/MPI 调参：

- `camera=(0,0)` 直接走全分辨率原图纹理，不读取深度、补图、matting 或 MPI；固定
  overscan/inset 改成按当前逐轴位移计算的动态 cover margin，零视点严格为 0。
- 可见表面改成独立前向 splat，单个样本四角深度相同，消除跨深度三角形插值。连续表面
  相邻 splat 按最大相对视差对称扩张并由 z-buffer 解析重叠；只有几何阶段已确认的遮挡
  断边不扩张。渲染期不再把“陡但连续”的梯度升格为 cut，避免主体内部噪声变成补图洞。
- MODNet 不再把已合成原图 RGB 直接乘 alpha。断边窄带先用隐藏背景近似反解前景颜色
  `F=(C-(1-a)B)/a`，再做预乘 alpha over；参考视点仍绕过该路径。
- 手工十平面 MPI 的端点回归出现明显碎片，旧 manifest 的 `mpi` 偏好自动迁移到新的
  source-locked「立体」路径，模式按钮只保留「稳定 / 立体」。MPI 代码暂留作历史实验，
  不再面向用户或承担最高质量路线。

JVM 回归覆盖参考视点、动态边界、splat 拓扑/足迹、matting 合成语义和旧 MPI 迁移。
OnePlus `3B1629006YC00000` 上零位与普通查看器图像区域同为 1216×1622，MAE 0.861、
PSNR 41.45 dB；但满强度截图被用户审图否决：人物脸型、双眼相对位置和下颌轮廓仍有
明显非刚性扭曲。此前“纹理清晰即几何正确”的验收结论撤销，当前版本不得发布。

失败根因不是补图，而是独立 splat 中心仍按各自深度走满 9% 视差；足迹扩张只能覆盖孔洞，
不能约束相邻样本的相对位移。下一修正采用跨内容的几何硬门槛：除显式遮挡 cut 外，最大
视差下任一相邻样本的局部应变不得超过 4%，同时验收面部关键结构和直线保持，不能再以
像素锐度代替形状正确性。该 4% 是 renderer 不变量，不按两张附件拟合。

4% 应变钳制的独立 splat 真机截图仍出现额头、眼部和发际的矩形分片，说明只限制位移幅度
不能修复离散拓扑。P0 可见层因此进一步改为混合拓扑：非 cut 区域使用共享顶点的连通
三角网格保持形状连续；三角形严格不跨 cut；仅 cut 两侧样本生成独立 splat，以保留前后景
分离和新显露区。该实现已通过纯 JVM 拓扑测试，视觉结论必须等待同设备端点复验，复验前
仍不得发布。

## D59：连续主体不得由 matting 建硬断边，取景边距必须各向同性（2026-08-01）

混合拓扑真机复核后，用户再次指出脸型仍被改变。两条跨内容不变量由此定案：

- **Matting 只提供语义约束和软覆盖率，不创建可见性 cut**。曾试验沿人物 matte 建硬
  断边，实际会把脸部和头发内部切成独立运动区域，端点下直接破坏五官与脸型；该方案
  已撤销。主体掩码现在只用于稳定连续主体的渲染深度，cut 仍只来自公制遮挡关系。
- **动态 cover margin 必须各向同性**。旧实现分别按 X/Y 位移计算裁剪边距，水平视点会
  只放大宽度而不放大高度，人物因此呈现脸宽变化，即使网格内部已经近似刚性也无法补救。
  `SpatialSourceLock.coverMargin` 现统一取两轴所需边距的最大值，保证 X/Y 使用同一缩放。

OnePlus `3B1629006YC00000` 两张附件端点量化：单人像五个面部特征的 X/Y 尺度比
`1.00752/0.99593`，最大非仿射残差 `1.02/0.94 px`；双人像八个特征为
`1.00145/1.00172`，最大残差 `1.24/1.08 px`。剩余变化属于统一缩放和平移，不再是
局部脸型形变。两张附件仍仅是故障探针，算法没有人物位置、肤色或单图阈值。

## D60：发缘质量采用连续覆盖率、单次合成和亚像素采样联合治理（2026-08-01）

用户指出黑发亮背景处仍偶发白色碎屑和锯齿。派生数据取证表明旧
`display-alpha.a8z` 在 matting 活性格边界从接近透明直接跳回 255：单人像相邻像素
跳变大于 128 的位置有 284 处、最大 253；双人像为 562 处、最大 242。该硬门控会把
原图里的背景混色像素突然作为前景显示，和补片重复合成共同形成白屑，不是单纯的 MSAA
不足。

定案为以下组合，全部在渲染期兼容既有派生数据：

- `SpatialAlphaEdgeRefiner` 先将透明覆盖向硬门控外扩一个 alpha 像素，再以可分离
  `[1,2,1]` 核重建连续覆盖率；两张探针的大于 128 跳变均降为 0，远离边界的不透明
  像素保持 255。
- 连续表面和断边补片分两批绘制；补片改用 `GL_LESS`，不再在连续面已写入的同深度
  像素上重复累积半透明 alpha。仅当存在 matting 时，近侧补片可跨 cut 多覆盖半个网格
  采样间距，真实轮廓仍由高分辨率 alpha 决定；无 matting 的显露区语义不变。
- 低 alpha 像素先做前景/背景去污染；不稳定区域沿 alpha 梯度向主体内部取色，避免
  除以小 alpha 放大成亮点。最终 alpha 改为四点旋转亚像素采样，并用同四点计算向内
  梯度，只平滑透明边缘，不对脸部或画面内部做全屏模糊。

同设备两张附件的左右满强度端点放大复核：离散白色碎屑基本消失，轮廓台阶减弱，未见
黑边增厚、细发成片丢失或脸部形变回退。原照片分辨率、MODNet 输出能力及极细半透明发丝
仍构成质量上限；不得以扩大全局模糊半径换取表面上的“无锯齿”。真实陀螺仪倾斜时序仍由
用户终验，ADB 拖动端点不能替代该项。

## D61：宽深度羽化退役，P1 转向对象中心 soft-LDI（2026-08-01）

用户真机观察指出当前效果像把画面贴在曲面上。代码复核确认主因不是补图或 matting：
`SpatialSubjectLayer.applySoftRenderLayer` 把主体统一深度后，在主体外侧铺设占归一化画面
半径 `0.12～0.36` 的深度坡；LDI 顶点着色器又把每个深度值直接转换为位移，因此这段
区域必然产生方向相关的连续局部缩放。该方案虽降低硬裂缝与人物内部形变，却把伪影转化为
大范围曲面感，不再作为最高质量路线继续调参。

P1 定案为 **对象中心 soft-LDI / layered splat**：分割负责对象/区域的像素所有权与真实
遮挡边界，公制深度负责层序和层间视差，soft alpha/matting 只负责轮廓覆盖率；人物、
文字和显著物体默认整体刚性或单平面运动，场景平面用 homography，不规则远背景才允许
受约束的低频深度面。每条遮挡边保存 H1、必要时 H2 隐藏内容，参考视点继续直通原图。

语义部件不直接等同于运动层：脸、头发、皮肤、衣服默认合并为同一对象父层，只有分割、
公制深度和遮挡关系共同证明存在独立表面才拆分。分割不确定时合并回父层，禁止为增强视差
制造新接缝。通用分割 PoC 比较 MobileSAM 与 RepViT-SAM，但先以现有 MODNet 人物层 +
隐藏背景完成无新模型 tracer bullet，A/B 证实表示收益后再接入按需下载模型。完整依据见
`research-2026-08-01-object-centric-layering.md`。

> D61 的表示决策继续有效；模型候选已由 D62 更新，不再以 MobileSAM/RepViT-SAM 或
> MODNet 代表当前质量前沿。

## D65：RF-DETR Seg Nano 进入可选的端侧实例 ownership 路径（2026-08-02）

真实权重导出、桌面 ORT 数值运行和 12 张跨场景样本验证通过后，将 RF-DETR Seg Nano
接入可选的按需下载目录。它只回答“哪些像素属于同一实例”，不替代深度、matting 或
隐藏背景补全；未识别区域继续走连续深度表面。模型契约固定为 312×312 RGB、100 queries、
91 个按 COCO 稀疏 category ID 排列的分类槽、78×78 mask logits。slot 0 是保留空槽，
slot 1..90 均为前景类别；RF-DETR 使用 sigmoid/focal 分类，没有独立 no-object logit。

- 置信度固定为 0.45，最多保留 12 个实例；人物、车辆和动物优先。大型沙发、床、餐桌等
  支撑面覆盖超过 18% 时不刚性化，普通类别覆盖超过 52% 时也回退连续表面，避免把整个
  房间或桌面变成一张移动贴片；这些阈值来自公开类别语义和跨场景失效模式，不针对用户的
  两张附件设特例。
- RF-DETR 提供互斥实例身份；MODNet 只把人像发丝/身体软边界扩展到最近的人物实例，不能
  覆盖已识别的非人物对象。两个相邻人物保持不同 label，alpha 仍只表示轮廓覆盖率。
- 几何构建保留深度模型原始层序，不再先用人物 union mask 把相邻实例压成同一代表深度；
  renderer 按每个 label 的深度中位数建立独立刚性层。完整实例足迹仍进入隐藏背景补全。
- 模型约 117.14 MiB，只在用户主动下载后启用，可在设置中关闭或删除；APK 不包含权重。
  下载、自检失败或运行内存不足时安全回退到既有深度/MODNet 路径，不阻断空间效果生成。
- ORT Runtime 升级为 `1.28.0-r5`，算子清单由 ZipDepth、DAV2、MI-GAN、AOT-GAN、DA3、
  MODNet 和 RF-DETR 七个实际 ONNX 图在 BASIC+EXTENDED 优化后的并集生成；四 ABI 仍按需
  下载，不进入 APK。

EdgeTAM 不作为静态照片自动默认：官方自动 mask 路径需要密集 prompt 网格，端侧成本与
当前“单次自动 ownership”目标不匹配；它保留为后续少 prompt 边界细化和 Spatial Video
跨帧 tracking PoC。RF-DETR 的 COCO 闭集之外对象仍是明确能力边界，不能把“更多模型”
等同于所有内容都应拆层。详细证据见 `segmentation-poc-2026-08-02.md`。

## D68：独立运动层按显著性准入，高分辨率 matte 与身份网格解耦（2026-08-02）

真机极端视点证明，“检测到实例”不等于“应成为刚性运动层”。占画面不足 1.2% 的远处
人物、椅子和餐具缺少足够轮廓采样，独立平移会放大成块状贴片；它们继续留在连续深度表面，
仍保有空间视差。满足面积门槛的显著实例才获得独立代表深度。

人物边界的 coverage 必须保持在 matting 输出分辨率，450×600 categorical label 只负责
互斥身份。允许人物身份向外传播一个网格采样宽度，为亚网格 matte 提供门控支持；最终
alpha 仍逐像素来自 MODNet，不能乘以标签命中率或裁回标签像素。MODNet 向网格身份的生成期
扩张另设约长边 1% 的上限，并保护非人物标签，防止高分辨率 false positive 吞并桌面。

前景去污染使用原图轮廓外侧的局部背景估计，不使用生成式隐藏背景。隐藏背景模型只可填补
真实 disocclusion，不能参与已知前景颜色反解；否则模型的颜色误差会在低 alpha 除法中
放大为白边、暗边。该不变量对后续 MODNet 替换模型和 diffusion/flow student 同样成立。

## D66：类别 ABI 与语义实例／运动实例分离（2026-08-02）

对照 RF-DETR 官方源码和真实导出图后纠正 D65 的分类契约：slot 0 是 COCO 稀疏 ID 的保留
空槽，slot 90 是有效的 toothbrush 类，不能当 no-object 丢弃。App 后处理固定只扫描

实例 mask 也不再直接等同于独立运动层。新增确定性的 attachment relation resolver：

- 人与人永不自动合并，继续保持各自深度和运动身份；
- 只有明确的穿戴、手持、身体部件或骑乘类别，且同时满足接触、相对面积、深度邻近和空间
  布局约束时，才并入对应人物父层；
- 仅在二维轮廓上偶然接触的人前杯子、大型前景物和深度不一致对象保持独立；
- 关系判定只使用类别、mask、深度和接触几何，不包含用户两张图片的位置或内容特例。

12 张跨场景样本分别以 ZipDepth、DAV2、DA3 深度复算后，规则稳定地只合并真实手持杯，

## D67：EdgeTAM 仅作为受约束的可选边界细化器（2026-08-02）

EdgeTAM 真实权重拆分为 image encoder、box prompt encoder 和 mask decoder 三个 ONNX 图后，
完成 PyTorch／ORT 数值对齐与 12 张、71 个 RF-DETR 实例的少 prompt 对照。它不替代
RF-DETR ownership，也不运行 automatic mask grid；RF-DETR 每个实例的 box 只触发一次
decoder。桌面结果如下：

- 三图合计约 34.5 MiB；encoder 中位约 102 ms、每实例 decoder 中位约 11.6 ms；
- 62/71 个实例通过质量门，RF/Edge mask IoU 中位 0.798；
- 原始 EdgeTAM 会在脸和衣服内部产生纹理相关孔洞，因此禁止整 mask 覆盖；
- 只允许 EdgeTAM 在一个 RF 78×78 mask cell 对应的轮廓窄带内选边，RF 内部保持锁定，
  扩张也受 RF 膨胀区约束；质量门不通过时逐实例回退 RF；
- 融合后 59/71 个实例的边界 RGB 梯度对齐提升，中位提升比为 1.296，未再出现内部孔洞；
  完整桌面进程峰值 RSS 约 758 MiB。

因此 EdgeTAM 进入“高内存设备可选下载”的实现路径，最低总 RAM 先设 8 GiB、生成前可用
内存 2 GiB；安装、自检、内存或逐实例质量门任一失败均退回 RF-DETR。Android 真机时延、
峰值 PSS 和驱动兼容尚未验证，不得把桌面数据写成手机结论；在真机验收前也不设为默认。

实现进一步固定以下安全边界：RF-DETR 的 box 是 EdgeTAM 唯一 prompt；每图 encoder 只执行
一次，每实例 decoder 一次；predicted IoU、RF/Edge IoU 和面积比逐实例验收。细化器最多在
RF 轮廓四个 78×78 mask cell 的带宽内改动，RF 可信内部、内部拓扑和实例身份均不可被覆盖；
新孔洞、脱离原实例的扩张岛和跨实例重叠分别通过拓扑恢复、连通域删除和置信覆盖率竞争处理。
这使 EdgeTAM 成为可撤销的边界建议，而不是第二套 ownership 真相源。

端侧运行契约随之升级为裁剪 Runtime `1.28.0-r6`，算子集合来自十个实际 ONNX 图。EdgeTAM
33,502,118 字节 bundle、四 ABI runtime 和签名 stable catalog `20260801183734` 已发布；
模型与当前 ABI runtime 都只在实际需要时下载，不进入 APK。Android 性能和真机观感仍是准入
门槛，因此该选项保持未下载、未启用的默认状态。

## D69：相接且近深度的实例共享运动，不合并持久化身份（2026-08-02）

相邻人物或同一装配体可能被 RF-DETR 保留为多个实例。若它们在图像中存在足够长的直接接触，
且组合深度跨度不超过 0.10，则运行时共享按像素数加权的代表深度；短暂一点接触或明显深度差
仍保持独立。union-find 合并时继续检查整个候选组的深度跨度，禁止通过中间实例发生跨深度的
传递合并。

派生文件继续保存原始互斥 label，便于未来重新解释关系；renderer 构图时才把同一运动组重映射
成一个绘制 label 和一个刚性平面。这样能消除相接实例之间由低分辨率 label 门控产生的内部
裂缝，同时不丢失实例身份，也不把不相接或远深度对象强行粘连。单运动组在运行时完全跳过
categorical label coverage，最终外轮廓只由高分辨率 ownership alpha 决定。

## D70：隐藏背景只生成最大视差可显露带（2026-08-02）

指定真机两张附件的最大视差复核发现，旧派生会要求 MI-GAN 一次性重建整个人物足迹。第一张
附件的持久化 `background.png` 在人物内部已出现大面积结构幻觉；实际交互只会显露轮廓附近的
窄带，却在强视差下把这些无关的大面积错误带入视野。该问题不是 alpha 抗锯齿可以修复的。

生成期改为从对象外轮廓及其内部孔洞向对象内部传播，半径按
`ceil(max(width,height) × MAX_PARALLAX_AMPLITUDE) + 6 px` 计算。只把该范围与原有几何
disocclusion mask 的并集交给补全模型；在全部允许视角下不可能被采样的对象深处保留源像素。
该半径来自 renderer 的最大相对位移上界，不依赖图片类别、人物位置或当前测试样例。内部孔洞
同样作为已知背景边界参与传播，保证手臂、衣物开口等位置具有足够的双向显露余量。

旧边界稳定器曾把最近的外侧纹理向遮挡区复制最多 24 px，容易形成可见条纹和拉伸块。其职责
现收窄为 3 px 接缝色差处理，深处内容由补全结果负责。派生 renderer 版本提升为
`ldi-lite-v14-reveal-band`，旧版本必须重新生成后才能进入该路径。

## D71：高内存设备的 ownership alpha 与隐藏层提升到 1440 长边（2026-08-02）

v14 真机端点复核确认人物内部结构已保持刚性，剩余衣物开口台阶来自 900×1200
`ownership-alpha` 本身，而非低分辨率 label gate。对 alpha 做全局 guided filter 或扩大
shader 模糊半径会改变孔洞拓扑、损失细发，不能用作通用补救。

高内存档 MODNet 推理长边由 1024 提升为 1440，并以源图长边为硬上限；隐藏背景与
ownership alpha 持久化长边由 1200 提升为 1440。对当前 1080×1440 照片，这使 alpha
接近源图逐像素覆盖率，避免先降采样再依赖运行时平滑恢复不存在的轮廓信息。中内存档由
768 提升到 1024，受限设备继续使用模型 reference size。几何 mesh 仍保持 600 长边，
因为对象身份和运动层序不需要通过增加顶点密度来伪造细节；外轮廓 coverage 独立使用高分辨率
alpha。派生版本提升为 `ldi-lite-v15-source-alpha`。

## D72：显露补全半径按实际运动层深度差计算（2026-08-02）

v15 第一张真机派生的对象代表深度约为 0.5105。逐像素比较对象运动层与其下方
`backgroundDepth` 后，最大相对深度差约为 0.176；在最大视差幅度 0.09、隐藏背景长边
1440 的条件下，所需对象内显露半径为 `ceil(1440 × 0.09 × 0.176) + 6 = 29 px`。
D70 使用 0..1 理论最坏深度差得到 136 px，虽不会漏补，却额外要求模型生成超过实际需求
四倍宽度的前景内部区域，扩大了补全幻觉、前景残影和模糊块进入强视差视野的机会。

生成器现复用 renderer 的实际运行时 ownership graph，包括实例接触运动分组和对象代表深度；
逐对象像素计算 `abs(objectRepresentativeDepth - backgroundDepth)` 的最大值，并据此确定显露
半径。半径仍保留 6 px 采样安全余量；缺少可解释运动层时回退 0..1 最坏上界，不能以缩窄
范围换取漏洞。对象拓扑优先来自与隐藏背景同分辨率的 ownership alpha，包含细发、软边和
内部开口；低分辨率 subject mask 只作兼容回退。派生版本提升为
`ldi-lite-v16-adaptive-reveal`。该规则由实际几何和允许的最大视差推导，不包含指定附件的
内容或位置特例。

## D73：补全推理上下文与持久化显露带分离（2026-08-02）

v16 真机派生显示，大面积无关补全已消失，但衣物开口和下摆附近仍可能出现深色残片。代码
复核发现两个同源问题：补全模型只遮住实际显露带，因此会在显露带内侧直接看到仍保留的衣物、
头发或皮肤；边界稳定器又把显露带两侧所有未遮挡像素都当成可信背景，可能主动把内侧前景
颜色回填进隐藏背景。这两条路径都会把前景残影保存到真正可见的 29 px 区域。

生成期现额外向对象内部遮住约长边 `1/45`、最多 32 px，作为仅供模型推理的隔离上下文；
推理完成后严格恢复实际显露带与原几何 hidden mask 之外的源像素，不把额外生成范围落盘。
边界稳定只允许从完整对象 mask 之外的已知背景传播，完整对象内部即便无需补全也不得成为
背景种子。派生版本提升为 `ldi-lite-v17-isolated-inpaint`。同时，对角视点的等比例取景边距
增加 0.5% 光栅安全量，覆盖 GLES2 网格边缘、MSAA sample 和深度量化误差；零视点边距仍为
严格 0，不改变参考图。

## D74：空间运动必须裁在固定的参考图画框内（2026-08-02）

v16 对角极限视点的上下边界弯曲并不是隐藏背景缺口，而是 LDI 网格为覆盖视差扩大并移动后，
不同深度的外缘越过原始 aspect-fit 画框，被直接绘制进 letterbox。继续增加 overscan 或曲面
补偿只能改变弯曲形状，不能恢复稳定的照片边界。

LDI-lite 现按参考视点的 aspect-fit 矩形设置 GLES scissor，所有背景、连续面、边界 splat 与
ownership 对象运动都只能发生在该固定画框内部；清屏仍在 scissor 之前完成。OnePlus PLZ110
上第一张附件的水平 ±100% 与两个对角极限复核均保持直线矩形边界。该规则只约束照片画框，
不改变框内几何，也不依赖图片内容。

## D75：撤销扩大的补图输入掩膜；ownership 只做连续 coverage 抗锯齿（2026-08-02）

D73 中“额外遮住最多 32 px 前景上下文”的假设经同一附件、同一 AOT-GAN 的 v16/v17 派生
A/B 被证伪：扩大掩膜使 `background.png` 在人物轮廓内生成大片近黑人形内容，MI-GAN 也在
发缘产生明显像素块；真实最大视点并未获得相应改善。补图输入因此恢复为“实际运行时显露带
与原几何 hidden mask 的并集”，仍保留 D73 已验证正确的可信背景种子隔离：完整对象内部绝不
作为背景回填源。派生版本提升为 `ldi-lite-v18-conservative-reveal`。

真机两张附件在强度 1.0 与约 0.65、水平 ±100% 和两个对角极限下复核后，脸部、五官和已知
纹理均由刚性源图层保持；剩余主要缺陷集中在 ownership 轮廓。旧 shader 先做 1.5 alpha texel
九点取样，再对检测到的硬边做 65% 二次锐化，会重新强调模型 alpha 中已有的格级台阶。现改为
一个 alpha texel 的标准九点 tent coverage，不再执行硬阈值锐化；颜色纹理和不透明内部仍只取
单个源图样本，避免用全屏平滑换取边缘改善。

## D76：动态取景边距使用旋转不变的视点半径（2026-08-03）

用户在真实姿态输入下连续倾斜手机画小圆时，看到的主要效果是整图周期性放大、缩小。确定性
回归将视点固定在同一欧氏半径，只改变圆周方向，复现了全局取景缩放变化：旧
`SpatialSourceLock.coverMargin` 先分别计算 X/Y 安全边距，再取
`max(|x|, |y|)` 作为等比裁切。该 L∞ 半径在轴向等于圆半径，在 45° 方向降为
`1/sqrt(2)`，因此每绕一圈产生四次缩放呼吸。以视点半径 0.6、最大视差幅度为例，旧全局
尺度在约 `1.0555×` 与 `1.0804×` 之间周期变化。

取景边距现分别以 `sqrt(x²+y²)` 计算视点半径和实际限幅后视差向量半径，再合成为单一等比
边距。欧氏半径不小于任一轴所需位移，继续满足防露黑、X/Y 等比、最大边距上限与零视点严格
归零，同时让等半径圆周运动只改变视差方向，不改变全局取景尺度。传感器 pitch/roll 增益、
滤波与前后景层间位移本轮不调整，避免用降低空间强度掩盖取景计算错误。回归覆盖半径
0.2/0.6/1.0 各 72 个圆周方向；修复前失败、修复后全部一致。该修正纯属运行时 renderer
行为，已有 Spatial Photo Derivative 无需重新生成。

## D71：P1 交互层三修——恒定取景、传感器软饱和、视点圆形域（2026-08-03）

按 design-2026-08-03-segmentation-as-prior P1 执行，治用户反馈的「前后呼吸/跳变/
硬截断」：

- **恒定取景边距**：`SpatialSourceLock.coverMargin(parallaxAmplitude)` 只依赖当前
  幅度（每档强度常量），按单位圆最坏视点一次算足；废除「参考视点零裁切 + 随视点
  半径动态放大」（满偏移 ~13% 整帧缩放的根源）与回中直通分支（过中心缩放突跳）。
  代价：静止时轻微恒定裁切（满强度边距 0.062，约 1.13×），换运动全程零呼吸。
- **传感器**：SENSOR_FULL_SCALE_RADIANS 0.16→0.5（9°→约 28° 才近满偏移），tanh
  软饱和替代 ±1 硬钳——大角度渐进逼近、无饱和拐点、对角不再先后撞轴折角。
- **视点圆形域**：applyViewpoint 把视点向量钳到单位圆（方形域对角可达轴向 sqrt(2)
  倍，方向手感不一致，且迫使边距按对角放大静止裁切）。
- 预算钳制经核实已是旋转不变（欧氏范数 + 单标量 gradientNorm），设计中第 4 项无需
  改动。

真机客观核验：中心/轴向/对角/回中四帧图像画框包围盒漂移 **0 px**；松手保持视点为
既有摇杆语义（settled≈diag，diff 0.4），非缺陷。传感器手感（tanh + 28°）依赖真实
陀螺仪，由用户终验。单测/构建全绿（SourceLock 契约测试同步重写）。

## D72 补遗：立体视差塌缩修复（2026-08-03）

用户实测「立体倾斜幅度远小于稳定」。根因：P2 移除刚性平面后，网格深度仍沿用

p99.5 梯度 2.94 → 行程上限 0.109 > 0.09，满幅不受钳制。

真机模板匹配量测（att1 满强度 L↔R 端点，置信度 ≥0.89）：立体 主体-背景相对
视差 77px、近桌-远窗总跨度 138px（前景/主体/背景三层反向分离）；稳定 仅 19px/
22px（p0 梯度 12.24 → 钳到 0.026，其固有权衡）。立体幅度反超稳定约 4 倍。
派生无需重建（纯渲染端修复）。教训二连：源码契约测试再次被自己的解释性注释
判死（改为限定调用点名）；跨层测量窗口混层会让相位相关抵消（改小模板匹配）。

## D76：实例内深度残差软限幅（2026-08-04）

D75 之后用户反馈"物体在不同视角下明显改变长度/形状"。机理：对象级伸长 =
幅度 × 物体内部深度跨度，满幅 0.12 下大跨度物体可达 ~11%（感知容差 ~4-5%）。

**修法**：实例组内保留组均值（层间弹出不变）、残差软限幅——膝点 0.09 内恒等，
超出部分 ×0.24 压缩，极端残差 0.5→~0.19，满幅伸长 ≈4.5%。连续场景（组 0）
不限幅：其延展读作透视，且承载全场景深扫掠。首版按连通分量限幅被真机证伪
（手臂-桌面深度比 <1.2 天然连通成巨型分量，均值吸走主体，全场跨度 126→56px）；
改实例组粒度后跨度完整保留 126px，人物/手持杯形状两端点一致，无撕裂。

测试教训又两枚：窄坡测试撞 D47 吸附带（≤26 格单调带折台阶）、均匀色测试让
引导滤波退化成箱型模糊——几何测试的场景构造必须避开这两个通道（宽坡 +
sharpEdges 路径），断言下限只证"未压平"。

`ldi-lite-v19-segmentation-prior`。旧核心固定为 schema v2；新生成路径使用 schema v3
和 renderer `surface-charts-vnext1`。旧派生仍可读取，且不会在打开图片时自动迁移；用户
明确执行“重新生成空间效果”后才会用 vNext 覆盖该附件的派生，避免一次算法更新把历史
对照样本静默改写。

vNext 的可见几何只消费深度证据：旋转／转置等变的去噪、遮挡候选和宽过渡 ridge 细化
先建立可断开的 connected chart；RF-DETR、EdgeTAM、实例分组和 ownership 不再拥有改写
深度、禁止断边或建立运动层的权力。MODNet 仅在深度几何已经确认的遮挡边近侧细化 alpha，
且窄带按网格长边缩放，避免 256 长边 vNext 网格沿用 v19 的 4 格后把软化宽度放大约 2.3 倍。
设置页不再允许新下载或选择 RF-DETR/EdgeTAM，只保留取消既有下载和删除已安装文件；下载、
校验与模型存储基础设施暂不删除。

每个 chart 保留自身平均深度和低频起伏，围绕均值统一约束残差，使最大允许视点下的二维
局部 Jacobian 扰动不超过 4%；chart 之间的平均深度不被压缩，前后表面仍可使用最高 0.12
的相对位移预算。永久合成测试同时要求硬台阶前后相对视差不低于 0.08、最大包络不低于
0.115，禁止靠压平整图通过形变门槛。连续斜坡、宽过渡、孤立深度尖峰和转置等变也分别有
回归测试。

参考视点不再预裁约 15% FOV：vNext 使用零 cover margin，背景网格在照片画框外延伸，固定
scissor 保持照片边界；中心视点关闭 matting 显露，原始高分辨率纹理完整覆盖背景层。
运行时消费随派生保存的 16 方向安全包络；当前第一阶段在全方向 4% 约束后得到对称包络，
接口为后续按隐藏区覆盖和方向置信度收缩预留。传感器低通改为依据事件时间戳和 65 ms 时间
常数计算，不再因 60 Hz／200 Hz 采样率不同而改变响应；交互仍只有二维 lateral/orbit，
没有 dolly 或 z 轴缩放。

此阶段仍复用 connected surface + boundary splat 的混合光栅器，画框外背景是边缘延展，
尚未完成 adaptive textured surfel/2D Gaussian、真正的生成式 outpainting、逐方向隐藏区
质量搜索和 50—100 张 held-out corpus。因此它是可测试的 vNext 几何基线，不宣称已经达到
Apple Spatial Scenes，也不能在真机盲评前替换 v19 的历史质量结论。
## D78：vNext2 将低频仿射视差与非仿射形变分离，稳定/立体统一使用分层几何（2026-08-04）

用户在 vNext1 真机实测中指出：“稳定”形变更严重，而“立体”可视视角过小、几乎没有空间效果。代码审计和确定性测试确认这是两个独立且相反的根因：

- “稳定”仍旁路 vNext chart，退回 v19 的源图逐像素深度形变；它虽然保留了较大位移，却会直接改变人物五官、轮廓和物体局部比例。
- vNext1 对每个 chart 只拟合标量平均深度，再按总梯度的最大值整体缩放残差；这把合法的连续斜面和低频场景深度也当成局部形变压平。精确仿射深度斜坡的理论相对视差为约 `0.0696`，vNext1 只剩 `0.0281`，约保留 40%。

vNext2 改用每个连通 chart 的最小二乘仿射深度平面，并把深度运动分解为“低频仿射分量 + 非仿射残差”：仿射应变上限为 8%，非仿射残差应变上限为 4%。安全视点包络也分别约束这两个量，不再用原始总梯度把整个场景统一压平。精确仿射斜坡回归要求相对视差不低于 `0.066`、请求幅度不低于 `0.115`；高频皱褶测试同时要求残差不超过 4%。

“稳定”和“立体”在 vNext2 中都使用相同的 shape-preserving chart、隐藏背景和完整横向/orbit 视差；二者只在遮挡边缘合成上不同：“稳定”关闭 matting alpha 显露以减少软边和补图暴露，“立体”启用完整 alpha 显露。模式切换不再决定是否具有可感知空间效果。v19 历史派生仍保持原行为，避免静默改变已有对照样本。

派生格式升级为 schema v4，renderer 标识为 `surface-charts-vnext2-affine-residual`；schema v3 仍可读取，但只有用户执行“重新生成空间效果”后才会生成并原子覆盖为 v4。

真机 `3B1629006YC00000` 的旧版固定条件基线（两张“测试空间效果”附件、最大强度、触控视点 `0/+1/-1`）进一步验证上述根因：第 1 张立体右端出现人物头后矩形拼接/拉伸区，第 2 张立体端点相对运动过弱；稳定模式位移更明显但人物面部与轮廓随视点发生形变。两张附件只作为回归探针，阈值与算法没有按图片内容拟合。
## D79：主体内部近刚性，空间感改由深度支持的 chart 间相对运动承担（2026-08-04）

用户复核真机单人图后明确指出：vNext2 在水平极限视角下显著改变了人物脸宽，此前“脸型保持一致”的目测结论错误。D78 中分别允许 8% 仿射应变和 4% 非仿射应变的做法没有约束二者叠加后的总形变，现由本决策取代。

vNext3 对每个连续可见 chart 使用单一总形变预算：满幅视角下仿射与残差叠加后的局部应变不得超过 1.5%，其中仿射最多占 1%，残差只能使用剩余预算。该约束只保护主体内部形状，不能以缩小全局交互幅度来满足；请求的最大视差仍为 0.12。

真机 `3B1629006YC00000` 对单人附件重新生成后的诊断日志为 `charts=1, largest=1.0, amplitude≈0.12`。这证明仅靠深度边缘构建拓扑时，一个轮廓缺口会把人物和整幅背景连成同一 chart；继续压低单 chart 形变只会同时消除空间效果。

因此新增“深度门控的运动分组先验”：已有 alpha/matting 结果只允许补闭合一个已被深度证据支持、但轮廓不完整的前景边界；它不得改写深度值，也不能在缺少前景/邻域深度差和局部边缘证据时自行创建 chart。边界闭合后，主体与背景分别保留自己的平均深度，以 chart 间近刚性相对位移产生明显空间视差，主体内部仅保留上述 1.5% 的受控连续立体起伏。该机制面向任意 alpha 提案，不使用人物类别、图片位置或当前两张附件的内容特判。

回归测试必须同时证明：有缺口但有深度支持的轮廓能闭合并形成至少两个运动 chart；无深度支持的 alpha 提案完全不改变切边；主体内部总应变不越界且主体/背景相对视差不低于 0.065。视觉验收仍须在真机重新生成后，以同一附件的左、中、右极限视角检查并量化脸宽变化，不能仅凭模拟或代码推断宣布通过。

## D80：补全条件 mask 与实际写入 mask 必须分离（2026-08-04）

vNext3 在真机 `3B1629006YC00000` 上以单人附件、最大强度重新生成后，AOT-GAN 768 与
1024 都在头发、肩臂和桌面显露区产生人物残影。持久化 `background.png` 证明伪影在生成期
已经写入，并非实时 renderer、抗锯齿或 matting 临时产生。解码同一派生的
`connectivity.bits.z` 后，实际写入显露带占 1080×1440 背景的 20.90%；它沿人物轮廓向内
覆盖，但把脸部和身体中心作为已知像素留给补全模型。模型因而会把未遮住的脸、手和衣服
继续传播进显露带。AOT-GAN 从 768 提升到 1024 只增加纹理分辨率，没有消除该语义污染。

生成链从此区分两种职责：

- **补全条件 mask**：送入模型并在模型输入中抹除完整遮挡物，至少包含实际写入 mask；
  优先使用已经通过深度门控的 motion-group alpha，不能让未经几何证据验证的分割直接生效；
- **实际写入 mask**：仍只把最大安全视角可能显露的隐藏带写入持久背景，mask 外像素严格
  复制原图，避免为了模型推理而重绘永远不会显露的区域。

这项分离只改变隐藏背景的生成条件，不让分割重新拥有深度、断边、位移或可见表面几何。
MI-GAN、AOT-GAN 及后续补全 provider 共用该契约。若完整遮挡物条件仍不能在真机消除残影，
再以同一输入／同一两张 mask 比较更新的端侧模型；不得用继续增大旧 GAN 工作分辨率代替。

## D81：通过深度门控的主体必须是严格刚性层，而非低应变网格（2026-08-04）

用户复核 vNext3 真机截图后指出单人图的脸仍有明显水平形变。局部光流仿射测量确认，左右
端点相对中心的面部主应变仍约 0.5%，水平剪切约 0.75%；这不是“已经保持一致”。根因是
vNext3 只把 chart 的总应变限制到 1.5%，但顶点仍按逐像素深度移动，所谓 rigid chart
实际只是 low-strain chart。

从 schema v6／renderer `surface-charts-vnext4-rigid-subjects` 起，通过 D79 深度门控的
完整主体占据的最终 chart 使用主体像素渲染深度中位数作为单一深度。刚性化作用于 cleaner
完成后的整个 chart，而不只原始 accepted mask；因此被连通图修补进主体的小孔、细缝和边缘
像素也不会留下局部深度斜率。chart 内所有顶点获得完全相同的二维位移，几何上不再允许
缩放、剪切或局部拉伸；多个彼此分离的主体 chart 分别计算代表深度，不会被强行合并到同一
平面。原始逐像素深度仍可供 fragment relief 的有界明暗使用，但不得再改变主体形状。

空间效果不通过压低交互幅度换取：最大请求视差仍为 0.12，主体代表深度与背景 chart 深度
之间的差值完整保留。无深度支持的 alpha 提案仍不得建立刚性层；未被接受的场景 chart 继续
使用 vNext3 的 1.5% 总形变预算。永久回归同时要求主体组内 `surfaceDepth` 严格常量、
主体／背景相对视差不低于 0.065，并在指定真机以同图左右端点重新量化。

## D82：撤销语义纸片，改用持久化局部相似位移基（2026-08-05）

用户在完整大角度轨迹中确认 vNext4 的人物上身表现为随倾斜整体平移的纸片，并在人物与
其余区域交界处出现明显断裂。指定真机 `9018f404` 的 70.59 秒有效录屏包含横向、纵向和
大圆周轨迹；逐帧特征测量与派生文件解码给出同一结论：人物主体 chart 占网格 17.46%，
其渲染深度跨度严格为 0；运动帧内主体特征相对位移中位数仅 0.21 px，而主体／背景位移
突跳中位数为 25.8 px、最大 36.9 px。主体补偿对齐后，边界时序残差为主体内部的中位
3.99 倍、最高 6.73 倍。D81 只凭静态脸部局部仿射指标宣布形状稳定，漏掉了动态纸片感与
边界断裂，因此其产品质量结论被本决策取代。

从 schema v7／renderer `surface-charts-vnext5-local-similarity` 起，不再把通过深度门控的
主体改写成常深度 chart。深度门控的 matting 提案只产生“保形权重与补全条件 mask”，不得
创建、闭合或删除任何几何断边；同一语义主体内部可能存在自遮挡，matting 漏分也不得变成
穿过手臂、酒杯或躯干的硬运动边界。几何拓扑重新只由深度遮挡证据决定。

生成阶段为横向和纵向单位视点预计算二维屏幕位移基：普通场景仍使用原深度投影；受保护
主体从稳健低频深度锚点构造局部 similarity MLS 位移。它在每个位置优先拟合平移、旋转与
等比缩放，保留头部、躯干、手臂等宏观深度响应，同时抑制把单目深度误差直接兑换成水平
拉脸或单轴拉伸。小型 matting 孔洞及未被几何断开的连接处使用连续权重过渡；真实遮挡断边
仍保留前后景完整相对视差与隐藏背景显露。二维位移基随 derivative 持久化，运行时只按
视点线性组合，保证确定性、圆周闭合和逐帧低开销。

安全视点包络改为按 16 个方向直接评估位移基的非相似形变与局部等比尺度，不再用已与实际
运动解耦的标量深度梯度估算。永久合成回归同时要求：主体保留非零宏观体积、局部横纵尺度
差不超过 1.5%、小孔不形成运动缝、前后景相对视差不低于 0.035，且没有主体提案时完全
退化为原深度投影。真机同轨迹复测完成前，vNext5 仍是待验实现，不能宣称质量已经通过。

首次 schema v7 真机派生推翻了本决策中“matting 不得闭合任何断边”的实现细则：MI-GAN
实际写入恢复到 154,194 像素，但 99.98% 网格仍属于同一个连通表面；为恢复前景均值而加入
的连续过渡在水杯轮廓附近产生 11.93—15.93 的 p99.5 非相似系数，16 方向安全幅度全部跌到
最低值 0.012。显著层间视差与同一连续表面上的低形变约束无法同时成立，这是拓扑矛盾，
不能靠放宽应变阈值解决。

因此 D82 的最终拓扑规则修订为“matting 定位、组件级深度验证、验证后闭合”：单条柔和
轮廓边不再重复要求局部深度门槛；只有整个候选的内部／外环中位深度、局部支持或既有切边
覆盖通过稳健门控后，才输出闭合遮挡轮廓。内部 matting 孔洞若与周围前景深度连续则吸收，
明显更远的真实背景孔洞保留。输入深度和既有切边仍不被 motion prior 原地改写，调用方只
合并已验证的轮廓提案。已闭合 chart 自然保留各自平均深度，不再对仍连通的局部 mask 强行
恢复深度均值。该修订以动态真机失败证据取代最初的逐边门控实现，并增加闭合软边、小孔
吸收和真实深度孔洞保留回归。

同一轮 32.91 秒真机大角度复录继续否决了“单独用 MODNet + 深度判断内孔”的方案。人物
面部仿射各向异性中位为 0.42%、P95 为 0.86%，说明局部相似位移已控制脸部形变；主体／
背景相对位移中位 31.5 px、最大 50.8 px，也保留了明确空间视差。但派生 chart 可视化显示
人物内部硬轮廓仍沿黑色衣服、手臂和酒杯穿过，动态边界／内部残差比中位仍为 3.21；这与
用户所见的上身纸片交界断裂一致。MODNet 的内部孔洞与单目深度在暗衣／透明叠加处可能
同时出错，二者相互确认仍不构成独立证据。

因此最终连续性规则增加可选 RF-DETR Seg Nano（2026）实例先验，但不恢复旧的“每个实例
刚性平移”路线：实例分割只提供可信人物身份；MODNet 仅在人物实例窄外边界细化 alpha；
整块候选仍须通过深度门控后才能闭合外轮廓。只有同一可信人物 label 内部、且两端均属于
已接受前景时，才允许否决错误深度断边；真实背景孔洞、不同实例和酒杯等非人物对象没有
该权限。位移仍由同一 vNext5 局部相似场计算，不按人体部件拆纸片。模型未选中、未安装、
内存不足或推理失败时退回 MODNet + 深度链。永久回归新增暗衣大孔的内部断边抑制，同时
验证人物外轮廓继续闭合、非人物实例不能获得人物连续性权限。

由于这项先验只有在用户安装并选中模型后才会运行，设置页重新开放 RF-DETR 的按需下载、
删除和选择；首次发起下载即预选该模型，下载 worker 自检成功后确认选中。界面明确说明它
只提供人物内部连续性，不能创建独立刚性实例层。EdgeTAM 不随之恢复，仍只允许取消历史
下载或删除旧安装。未下载 RF-DETR 时 APK 体积和生成路径均不增加该模型权重。

RF-DETR 真机 v5e 复录证明拓扑修复本身仍不等于充分的空间体积：171.06 秒、约 52.5 fps
录屏覆盖横向、纵向和闭环满幅轨迹；16 方向幅度均为 `0.12`，人物内部硬切线消失，动态
边界／内部残差比由 v5d 的中位 `3.21`、最大 `5.84` 降至 `1.80`、`2.14`，脸部各向异性
P95 由 `0.86%` 降至 `0.63%`。但人物 motion basis 的 p5—p95 满幅横向跨度仅 `2.70 px`，
仍可能呈现整片移动。原始深度同一区域的 p5—p95 跨度为 `0.2404`，受限 surfaceDepth 只剩
`0.0405`；直接用后者构造 MLS 锚点已经先把宏观体积压掉。

因此 protected motion 改为双深度职责：surfaceDepth 继续负责可见几何和主体／背景均值
视差；受组件深度门控的原始 denoised depth 只提供主体内部低频锚点。锚点先做 24 轮稳健
扩散、组件分位裁剪和两轮邻域中值，删除暗衣、玻璃、反射产生的孤立深度脉冲；再以
surfaceDepth 的组件中位数重新定心，保证主体／背景主视差不变。最终只缩放“局部相似候选
减近刚性基线”的体积残差，通过 16 方向二分搜索把满幅非相似形变限制在 `1.2%`、局部等比
缩放限制在 `2.2%`；若场景基线本身更高，则不得比基线更差，也不得降低整幅 `0.12` 请求
幅度。小于等于 2 个网格的内部孔洞使用完整 MLS 影响，避免重新形成运动缝。

真机 v5f 派生的离线解码否定了上述实现中的“锚点插值已足够平滑”这一隐含假设。虽然
16 方向幅度仍为 `0.12`、人物拓扑保持 2 个 chart，但人物 motion basis 的 p5—p95 满幅跨度
从 v5e 的 `2.70 px` 反而下降到 `0.87 px`；与此同时 p99.5 非相似形变升至满幅 `1.16%`。
最高形变单元集中在 `(100,100)`、`(124,148)` 等 8 像素锚点网格中心，证明近奇异的
`1 / (d² + 1e-8)` MLS 权重把预算消耗在离散锚点尖峰，而非可感知的低频体积上。因此不再
使用近奇异权重：查询核加入半个锚点间距的有限半径，保证相邻锚点平滑接管。新增通用回归
以 192×256 的平滑宏观深度场同时约束“主体运动 p5—p95 跨度不得塌缩”和“锚点附近
p99.5 离散曲率不得形成尖峰”；旧版红灯指标分别为 `0.0196` 与 `0.1278`。形变预算、
主体／背景均值视差、人物连续性拓扑和 `0.12` 全局幅度职责均保持不变。

有限 MLS 核只消除了锚点奇异性，v5g 真机派生仍只有 `1.97 px` 的人物内部满幅跨度；将
该派生的真实 `surfaceDepth`、源深度、cut 与人物 chart 重新送入构建器后，可精确复现
`0.01517` 的 p5—p95 位移系数。未限幅候选跨度为 `0.11419`，但 p99.5 非相似形变系数高达
`0.73790`，说明剩余问题是短程低通保留了局部深度台阶，而非全图预算或层间视差不足。
受保护深度因此改为长程弱数据项扩散：固定 256 长边网格执行 768 轮、数据权重
`0.00015`，只在同一受保护组件内且不跨 cut 传播；它提取十几个网格尺度的宏观体积，局部
衣服、玻璃和反射证据不再独占预算。默认满幅非相似形变上限同时从 `1.2%` 收紧为 `0.95%`，
优先保护脸型。相同通用输入的运动跨度回归下限提高到系数 `0.040`；真实派生输入的离线重建
预计人物满幅跨度为约 `4.32 px`，同时非相似形变为约 `0.95%`。该预计值必须由新 APK 的
持久化派生和完整真机动态录屏再次验证，不能直接当作通过结论。

v5h 的真机持久化派生与离线预测完全一致：schema v7、2 个 chart、16 方向幅度均为
`0.12`，人物 motion basis 的 p5—p95 满幅横向跨度为 `4.32 px`，p99.5 非相似形变为
`0.95%`。随后在指定真机用一个连续触控手势完成横向全程、纵向全程和双向大圆周轨迹，
OEM 录屏前 75 秒逐帧分析得到：人物／背景相对位移中位 `37.18 px`、最大 `46.44 px`，
边界／内部残差比中位 `1.60`、最大 `1.84`，人物内部运动离散度中位由 v5e 的 `0.47 px`
升至 `0.90 px`。因此“增加主体连续体积必然重新制造内部硬接缝”的假设被否定，空间主
视差也没有因形变保护而塌缩。但脸部各向异性形变 P95 为 `1.25%`、最大 `1.53%`，高于
v5e 的 `0.63% / 0.81%`；在第二张附件和更严格局部形状复核完成前，v5h 仍是候选而非
最终质量结论。

## D83：vNext5 以双探针满幅动态门禁作为当前基线（2026-08-05）

第二张双人附件已独立生成 schema v7 派生，未复用单人图缓存。派生包含 6 个 chart，但
主体 mask 的全部 32,204 个网格顶点都属于同一个连通 chart；人物内部 cut 只占可连接边的
`0.186%`，没有把头部、上身或两个人物拆成独立平移纸片。16 个方向幅度均为 `0.12`，主体
motion basis 的 p5—p95 满幅横向跨度为 `4.28 px`；全幅 p99.5 非相似形变为 `0.92%`，局部
缩放为 `0.88%`。因此空间体积与局部形状保护同时成立，不能再用严格刚性主体替换该场。

指定真机上的第二段 OEM 录屏为 139.32 秒，其中前 118 秒逐帧取样；有效移动样本 149 个，
覆盖横向、纵向满幅和顺逆时针圆周轨迹。主体位移范围为横向 `-16.66—16.67 px`、纵向
`-22.10—22.11 px`，主体／背景相对位移中位 `53.74 px`、最大 `69.90 px`，证明形变保护
没有把空间效果压缩成小角度平移。两张脸分别独立拟合局部仿射，形变 P95 为 `0.55%`、
`0.56%`，最大为 `0.86%`、`0.66%`；圆周连续帧未见脸宽跳变或人物内部接缝。

双人图的主体外轮廓／内部亮度残差比中位为 `4.27`，该值主要响应 54—70 px 的真实前后景
遮挡位移，不能单独当作人物内部断层指标；内部 chart 连通性、局部形状、极值帧和圆周序列
必须联合验收。结合单人图与双人图证据，v5h 作为当前 vNext5 基线通过本轮动态门禁；保留
真实传感器倾斜下的用户复核，不再为压低单一残差指标牺牲 `0.12` 视角包络或主体体积。

## D84：撤销 D83 的产品质量通过结论，主体深度保留与形状稳定改为独立门禁（2026-08-05）

用户在真实传感器倾斜下复核 v5h 后确认：单人和双人主体仍表现为一块大面积联合纸片，
`4.28 px`—`4.32 px` 的主体内部满幅位移跨度肉眼不可感知。D83 只证明了该实现没有恢复
明显内部硬接缝、局部脸宽指标较低和主体／背景主视差存在，错误地把“数学上非严格刚体”
当成了“具有可感知主体体积”。因此撤销 D83 的产品质量通过结论；v5h 仅保留为失败对照，
不得作为后续质量基线或发布依据。

真实单人派生进一步显示，主体原始深度的 p5—p95 跨度约为 `0.2404`，最终 motion basis
只剩约 `0.0333`，深度跨度保留率约为 14%。当前连续三角网格为满足 `0.95%` 非相似形变
预算主动删除了约 86% 的主体深度；直接放开该预算会重新产生脸部、身体和文字的拉伸。
这说明问题不是单个平滑轮数或阈值不足，而是“连续纹理网格承载完整逐点视差”与“二维
身份形状保持”在大视角下存在结构冲突。

后续门禁拆分为互不替代的两组：一组测量主体可靠深度的保留率、全分辨率内部视差、局部
遮挡顺序和二维圆周响应，要求肉眼可感知的跨身体尺度体积；另一组独立测量脸部、身体、
文字和细结构的局部仿射形变、接缝、孔洞、模糊和重影。主体／背景相对位移、全局请求幅度
和“非零内部位移”不能代替第一组门禁，低形变也不能代替空间效果验收。数值阈值须由包含
原单人、原双人及多类留出图的真机动态样本共同确定，不得按两张探针拟合。

表示层停止在 vNext5 的局部相似网格上继续调压缩常数。下一阶段先比较能够同时保留局部
身份和连续体积的显式新视图表示，包括带归一化合成的自适应 surfel／2D Gaussian，以及
端侧可行的单图 3D Gaussian／新视图生成模型；既有硬矩形 forward splat 已由 D58 证明会
产生马赛克式碎片，不得原样恢复。分割仍只提供所有权、置信度和遮挡辅助，不重新承担把
整个人体变成刚性层的职责。

## D85：否决“更强深度 + 传统重投影”作为根治路线（2026-08-05）

使用官方 MoGe-2 `vits-normal` ONNX 的完整 point map、法线、有效掩码与恢复相机内参，构建
真实相机平移的连续三角重投影；同时以归一化双层 z-softmax surfel 对照，排除旧实现仅仅
没有正确使用三维点图的可能。相机恢复自测可在已知焦距 `0.82`、深度平移 `1.35` 上达到
小于 `0.001%` 的误差，因此实验结果不归因于相机参数求解错误。

在原单人、原双人两张探针上，MoGe 点图能够把主体内部视差提高到约 `22 px`，但横向局部
伸缩 p99 已为约 `14%—20%`。在未参与调参的室内、办公室、交通、近景蛋糕、雕像、食物和
人物／宠物 7 类场景上，办公室、近景物体与人物／宠物的局部伸缩 p99 达到约 `50%—65%`，
并在遮挡显露处形成撕裂块、接缝和缺失背景。归一化 soft-splat 虽减少硬孔洞，但引入明显
模糊、重影与发丝颗粒；全图低频深度场和深度阈值切边也无法同时通过可感知体积与形变门禁。

据此否决“继续替换更强单目深度模型，再用传统网格／点精灵重投影”的生产路线。深度仍可
作为几何先验，但不能独自承担新视角合成；后续候选必须显式学习或预测表面支撑、Gaussian
尺度／旋转／透明度、隐藏侧内容与视角相关颜色，并通过同一组多场景连续大角度轨迹验收。

## D86：以 InfiniSplat 作为学习式 surface-aligned Gaussian 的研究门禁（2026-08-05）

InfiniSplat（2026-08-03 发布）直接针对单图 spatial photo 与大基线新视图：它不把每个输入
像素固定为局部纸片，而是先把支撑点移动到几何引导的表面位置，再由隐式 Gaussian decoder
预测位置、尺度、旋转、颜色和透明度。官方代码与 RGB checkpoint 为 Apache-2.0，可进行
产品可行性研究；但 RGB checkpoint 约 `3.14 GB`，尚不满足直接端侧分发要求。

因此 InfiniSplat 只进入离线 PoC 门禁，不直接并入 App。先在开发机 GPU 上对原单人、原双人
与 7 个留出场景生成 Gaussian，并以水平、垂直、对角和圆周连续大角度视频检查体积、脸型、
细结构、遮挡显露、漂浮物、模糊和重影。只有跨场景视觉证据通过后，才分析模型拆分、FP16／
INT8 量化、按需下载、一次生成后持久化 Gaussian，以及 Android Vulkan／GLES3 实时渲染；
若 PoC 失败，不用其庞大体积或发布时间为实现背书。

checkpoint 审计得到 1,261,411,174 个参数：其中 Depth Pro 约 9.52 亿参数、以 FP16 占
`1.82 GiB`，DINOv3 ViT-L 约 3.03 亿参数、以 FP32 占 `1.16 GiB`，Gaussian 特征融合与
隐式解码头合计不足 `24 MiB`。即使把全部参数量化到 INT8，原结构仍约 `1.18 GiB`，且
1536×1152 输入与 150 万 Gaussian 的计算和中间激活远超当前端侧准入。因此桌面 PoC 即使
通过，也只能证明表示方向；端侧候选必须至少替换／蒸馏 Depth Pro、缩小图像 backbone、
降低或分级 Gaussian 数量，并重新训练或蒸馏解码头，不能把原 checkpoint 简单转成 ONNX。

InfiniSplat 顶层代码与 checkpoint 标注 Apache-2.0，但内嵌 DINOv3 仍受 Meta 单独的
DINOv3 License Agreement 约束，Depth Pro 也保留 Apple 的单独许可。进入产品实现前必须
按实际保留的子模型与权重逐项保存许可和 attribution；顶层 Apache 声明不能覆盖第三方条款。

官方 demo 会把所有输入无条件缩放到 1536×1152；这对原单人、原双人的 3:4 竖图会先制造
约 78% 的横向比例错误，不能用于人物质量判断，也不能进入 App。PoC 改为按方向在
1536×1152 或 1152×1536 包络内等比缩放，并把宽高落到 16 的倍数；方图和其他长宽比同样
保持原比例。零视角重建必须与等比缩放后的原图比较，任何模型带来的初始脸宽变化直接失败。

## D87：Gaussian 生成、派生压缩与实时渲染分离（2026-08-05）

单图模型只在用户生成或主动重新生成时执行一次；交互期间只读取持久化 Gaussian 派生，
不得逐帧运行深度或新视图网络。实时端改用 Vulkan／compute 路线评估，不继续扩展当前
GLES2 三角网格 shader。2026 年 Mobile-GS 已在 Snapdragon 8 Gen 3、1600×1063 报告约
116 FPS，说明移动端渲染和数 MiB 级压缩表示具备可行性；但其移动 Vulkan 代码未公开，
不能把论文性能直接当作本项目实现证据。

若 InfiniSplat 视觉门禁通过，派生压缩优先组合贡献度 pruning、位置／尺度／旋转／颜色的
分组量化、低阶或无球谐颜色，以及视图包络限定下的 LOD；同时以未压缩结果为质量上界逐级
A/B。渲染器先复用许可兼容的 Vulkan 参考实现和 2026 年推理专用 fp16 packing 思路，随后
在授权真机测量帧率、显存、功耗和热降频。生成模型大小与每张派生大小分别显示和治理，不能
因为模型按需下载就忽略每张照片的派生占用。

## D88：不采用依赖多视图监督的轻量 MPI 冒充单图方案（2026-08-05）

2026 年 6 月的《Fast and Lightweight Novel View Synthesis with Differentiable Multiplane
Image》虽然使用 32 层 MPI、单步 diffusion 增强，并报告约 22.83 MB 场景表示与高帧率，
但其核心质量来自多张已知视角、逐场景八轮可微优化以及生成的伪视图监督；论文也明确把
单图前馈 MPI 的隐藏区补全质量列为限制。普通记事附件只有一张图，无法提供这种监督，故
该方案只能说明 MPI 的播放端可以很轻，不能作为当前单图生成路径，也不能用其多视图结果
推断现有手工 MPI 加一个 diffusion 后处理就能达到同等质量。

InfiniSplat 离线门禁新增独立对角往返轨迹，并为每个方向保存正负极值帧；水平、垂直、
对角与圆周轨迹全部保持 `z=0`，以逐帧主点补偿固定中值深度平面。后续录屏必须同时包含
原单人、原双人及多类未参与调参的留出场景，不能再用单张照片或静态小角度截图宣称通过。

## D89：InfiniSplat 官方 RGB checkpoint 未通过真实人物门禁（2026-08-05）

InfiniSplat 只保留为研究失败证据，不进入 App、模型目录或 student 蒸馏。RTX 5090 上的官方
1,500,000-support RGB checkpoint 与 `gsplat 1.5.3` 已完整跑通，仓库自带室内阳性对照能得到
可接受的零视角和侧移画面，证明 CUDA、相机和 rasterization 链路有效；但原单人真实照片在
保持竖向比例时，零视角已经出现脸部涂抹、枝叶状黑斑、酒杯／手部重影和整体发虚，PSNR 仅
`23.70 dB`。关闭 floater filter 后下降到 `22.76 dB`，排除过滤器误删为主因；严格采用官方
1536×1152 固定横屏预处理虽提高到 `25.53 dB`，仍有明显涂抹和大角度黑洞，而且会破坏竖图
比例。仓库自带 `animate_room.jpg` 阳性对照为 `27.87 dB` 且运动稳定，说明失败集中在产品关键的
真实人物、透明／反射物、细发丝与强遮挡场景，而不是评测脚本无法生成任何结果。

因此，不得以 InfiniSplat 在合成室内图上的成功、约 `1.24 s` 的桌面推理或高渲染帧率替代产品
验收，也不得继续把巨型 checkpoint 压缩后发布。后续候选必须先满足“零视角保真 + 原单人／原
双人 + 多类留出图连续轨迹”三重门禁；零视角已改脸或明显发虚时直接淘汰，不进入 Android 改造。

## D90：SHARP 只作为学习式多图元表示的质量上限，不作为产品权重（2026-08-05）

Apple SHARP 官方 checkpoint 已在 RTX 5090 上完成原单人、原双人与 7 类留出图的同配置
评测。模型为每张图预测约 118 万个三维 Gaussian，原单人和原双人的零视角 PSNR 分别为
`28.69 dB` 与 `32.74 dB`；在水平、垂直、对角及圆周纯侧移中，脸、头发、手和身体能够随
各自深度连续响应，没有 vNext5 的整块人体平移或人物内部硬交界。原单人左右极值间的主体
光流横向 p5—p95 跨度为 `32.38 px`，去除整体平移后的残差 P95 为 `25.94 px`，从表示层
否定了“为了保持人物形状只能把主体深度压到约 4 px”的旧假设。

同一 `0.085` 强度并非跨场景安全：交通图的右上建筑出现大面积拖抹且透明度降到零；近景
蛋糕、办公室和雕像在极值方向出现边缘露底或拉丝。由此确定产品路线必须同时包含按场景、
按方向估计的可见性／置信度和安全视点包络；固定全局强度即使在人物图上很好，也不能作为
通用默认值。验收继续要求连续视频，零视角、极值帧和环形闭合只提供互补证据。

SHARP 模型约 7.02 亿参数、权重约 2.81 GB，单图峰值显存约 7.4 GB；更关键的是官方模型
许可明确限制为研究用途，不允许上传阿里云、随 App 分发、用于商业产品或训练产品 student。
因此本轮只把它作为架构阳性对照：产品候选应独立训练、取得商业许可，并输出高分辨率、
多层或带纹理的 Gaussian／surfel；现有深度可以提供几何先验，但不能继续由连续二维网格
独自承担逐点视差。未经多场景桌面门禁通过，不修改 Android 主渲染链。

## D91：主体整体位移与内部体积独立预算，拒绝用全局深度平滑掩盖图元裂缝（2026-08-06）

为 textured micro-surfel 原型建立统一的九场景动态反馈脚本，以原单人、原双人和 7 类留出图的
同一圆周轨迹测量整体位移、主体内部 p5—p95 运动跨度、宏观起伏、微小抖动、刚性像素占比和
深度／运动秩相关。原单人的实例整体位移上限从 `18 px` 降至 `12 px` 后，整体位移中位数从
`33.86 px` 降至 `22.44 px`，整体位移／内部跨度比从 `2.38` 降至 `1.41`，深度／运动相关性从
`0.39` 升至 `0.49`；降到 `8 px` 虽进一步把该比值降至 `1.10`，但同时压缩了可见视角。因此
`12 px` 暂定为图元实现实验的工作基线，不作为最终产品常量；整体运动和主体内部体积必须分别
验收，不能再用一个总位移数字证明空间效果。

在 `12 px` 基线上，对实例深度施加 `6 px` 和 `12 px` Gaussian 平滑并恢复原深度中位数及
p5—p95 范围。原单人的微小抖动 P95 可由 `3.27 px` 降至 `1.79 / 1.60 px`，但宏观起伏中位数
由 `1.91 px` 降至 `1.25 / 1.34 px`，整体位移／内部跨度比反而升至 `2.16 / 2.10`；视觉上也
重新趋向平面。因此拒绝把大范围深度平滑并入候选。极值帧中手、透明酒杯和细轮廓的梳齿会被
平滑暂时隐藏，但根因是固定 `2×2` 图元的投影覆盖、局部 footprint 与可见性门控，而不是所有
主体深度都应更平。下一步只改变图元栅格化：验证带深度门控、局部 Jacobian 和归一化合成的
自适应椭圆 EWA splat；在其通过单人／双人细节门槛前不扩展到 Android。

## D92：EWA、目标域补洞与手工 LDI 未改变单可见表面的拓扑上限（2026-08-06）

完成自适应椭圆 EWA footprint、放宽局部 z 容差、扩大 footprint，以及 `6 / 12 px` 目标域
最远可见表面填充的单变量对照。EWA 能减少固定 `2×2` 图元造成的梳齿，但原单人的手、透明
酒杯、躯干与桌面仍会在极值视点碎裂；扩大 footprint 或 z 容差只会把碎裂改成跨深度模糊，
目标域填充则形成方向相关拉丝。全图不可见像素虽然通常只有约 `2%—2.5%`，却集中在产品最
显眼的手、发丝、酒杯和前后景交界，因此全局 hole ratio 不能作为通过指标。

进一步实现源空间持久双深度样本：在近表面后传播更远邻域表面，先保存 H1，再以同一 EWA
renderer 合成 H1 与前层。原单人 smoke 中隐藏样本虽覆盖约 `10.86%` 的源图，实际在目标视图
显露的像素仅约 `0.06%—0.08%`；手／杯／躯干仍发生大块断裂，证明主要错误不是缺少少量补洞
像素，而是单目深度把本应连续或相互遮挡的内部表面拓扑判断错了。禁止继续以传播半径、膨胀
宽度或更大 splat 调参替代学习式表面表示。

2026 年 Moebius 官方 226M 图像修复模型也已用头发边界、近景人物和双人遮挡掩码隔离测试。
它能在部分窄发丝边界生成背景，但在手／透明杯附近生成无关纹理；较宽人物掩码会重绘脸，并在
双人图生成畸形的第二张脸。通用 inpainting 不知道掩码后应是哪一层表面，只能作为未来隐藏层
中低置信度像素的候选纹理，不能修改可见人物，也不能修复错误的前层拓扑。

## D93：淘汰 PVSDNet Lite，转向独立训练的持久多层 Gaussian 资产（2026-08-06）

用 PVSDNet Lite 官方 AGPL-3.0 权重完成两种预处理、九场景零视角和三个人物场景 48 帧圆周
轨迹门禁。模型固定输出 `256×256`，共有 `188,771,780` 个参数，checkpoint 为
`755,310,722` 字节；RTX 5090 暖机后约 `9.6 ms/帧`，峰值 CUDA 内存约 `2.71 GB`。零视角
PSNR 尚可，但高分辨率原图细节已不可逆降到 256；连续目标视图表现为整幅画面的非刚性透视
变形，双人脸和建筑线条一起弯曲，而不是得到稳定的三维表面。

其位置编码还存在明确边界退化：官方把相机坐标 `[-0.1, 0.1]` 映射到 `[0, 1]`，同时使用
`sigma=1` 的周期 Fourier encoding；半径为官方上限 `0.1` 时，正负端点编码完全相同，左右
极值帧重复。改用官方默认半径 `0.06` 后虽产生较大运动，原单人／原双人相反帧 SSIM 仅约
`0.410 / 0.372`，视觉上伴随整体弯曲。该模型不进入 Android，也不作为产品 teacher。

下一条产品 tracer bullet 改为独立训练、一次生成后持久化的多层 Gaussian 资产：可见层在
参考视点直接复用高分辨率原图纹理，网络只预测连续几何、多个隐藏样本、opacity／confidence
和受限的视角修正；交互期间只运行 Gaussian renderer，不逐帧生成整张 RGB。分割／matting
最多作为训练损失权重或可见性先验，不再拥有把人物切成独立运动卡片的权力。首个训练门禁使用
具备真实相机、深度、法线、分割和光流且为 CC BY 4.0 的 Charge 多视图数据，并保留场景级
held-out；再补充经逐文件许可筛选的 MegaScenes 与自生成 CC0／CC BY 合成场景。任何研究用途
权重或许可不明数据都不得进入最终 student。

## D94：隐藏内容采用独立三维残差，不能继续绑定到规则 MPI／LDI 射线（2026-08-06）

使用 Charge `050_0130/frame_0416` 的九个同步 RGB-D 视角建立表示层真值实验，首先穷举相机
矩阵、轴系与深度语义，确认数据约定为 `c2w + Blender axes + axial depth`；单源深度在已覆盖
区域投影到相邻视角可达 `24.61—29.74 dB`，排除了相机解析错误。随后严格留出目标相机，以其余
八个真实 RGB-D 点云作为非规则三维真值。相同 CUDA 深度门控 splat 下，单个参考视角在四个
目标视角的覆盖率为 `27.58%—43.99%`，非规则多视图真值提高到 `71.04%—89.73%`，增加
`27.49—62.15` 个百分点；人物／物体轮廓和后方表面也随之恢复，而非依靠二维补洞拉伸。

再把留出目标之外的真值压回参考相机的规则像素射线，比较 `K=1/2/4/8` 的 LDI。`K=2` 只比
`K=1` 增加约 `1.36—6.58` 个百分点覆盖，`K=4` 之后增益已低于约 `1` 个百分点；即使保存更多
射线深度，仍远低于非规则三维真值。由此确认早期双层 LDI 的失败不只是隐藏层数量不足，而是
规则 MPI／LDI 把隐藏几何锁在原图像素射线上，无法表达大视角下的横向延伸、斜面和遮挡拓扑。

产品资产因此调整为两部分：参考视点使用原图建立连续、高分辨率的可见表面，保证零视角身份与
细节；网络另外预测可在三维中自由偏移的稀疏 Gaussian 残差，负责遮挡后内容、横向延伸和局部
体积，并携带 opacity、confidence 与安全视点包络。隐藏残差不能按语义实例整体移动，分割／
matting 仍只作为训练监督。层数开关可保留为诊断项，但不再把规则双层或四层 LDI 当成最高质量
路线。下一步先训练一个小型 student 验证该资产能从单图学出有效残差，再决定 Android schema。

## D95：首个自由三维残差 student 只通过表示门禁，未通过显露区质量门禁（2026-08-06）

以 Charge Dense 中心相机及 `10° / 14.1°` 八邻域建立首个端到端 tracer bullet。公开 Dense
数据实际只有 `050_0130`、`050_0160`、`060_0100`、`070_0123` 四个场景；前三个场景各取四个
时间点训练，`070_0123` 的四个时间点全部作场景级留出。student 为 451,640 参数的轻量
encoder-decoder，输入 RGB 与归一化深度，在扩展参考画布上输出每格两个可横向偏移的 Gaussian，
交互端仍只需要持久资产与 renderer。

训练前发现硬 z-buffer 会让低 opacity 的近点完全遮住后方高 opacity 可见表面，造成“加入隐藏
点后覆盖反而下降”。renderer 已改为逐像素、按深度排序的前向 alpha compositing；修正后新增
点不会降低覆盖。300 步 RGB／边缘／源视点身份训练后，训练场景覆盖增加 `14.89` 个百分点，
场景级留出增加 `19.49` 个百分点。留出场景原有稳定支持区 PSNR 反而提高 `0.23 dB`，证明
“原图可见表面 + 自由三维残差”能够在不破坏已有主体的前提下增加显露内容，表示方向成立。

但新增显露区在留出场景只有 `16.70 dB`、MAE `0.105`，视觉上出现低分辨率局部纹理块；把
新增低质量区域计入后，整体已覆盖区域 PSNR 下降 `0.79 dB`。因此该 checkpoint 明确不进入
Android、不上传模型目录，也不能以覆盖率提升宣称质量通过。下一轮必须为同批目标视角加入真实
depth 监督，分别测新增区域的几何相对误差与颜色误差，并训练 confidence 抑制低质量残差；随后
扩大有许可的场景多样性。扩大 Gaussian footprint、提高 opacity 或只增加训练步数均不能替代
这个门禁。

## D96：把隐藏几何与隐藏纹理解耦，并对真实照片训练数据执行逐图许可白名单（2026-08-06）

为 Charge Dense 的所有目标相机补齐真实 depth，并在首轮 student 上增加主要作用于新显露区域的
log-depth 监督。相同 300 步下，场景级留出的新增区域 depth AbsRel 由 `0.521` 降至 `0.448`、
log RMSE 由 `0.906` 降至 `0.703`；新增区域 RGB 由 `16.70 dB / MAE 0.105` 改善到
`17.17 dB / MAE 0.095`，原有稳定支持区仍提高约 `0.23 dB`。这证明独立三维残差的几何可以
学习，但新增纹理仍为低分辨率块状，第二个 checkpoint 同样判定失败，不进入 Android 或阿里云。

后续不再把“显露区 RGB 很差”笼统归因于 renderer。Charge 继续作为相机、遮挡、覆盖与隐藏
几何的受控门禁；真实照片数据用于训练跨场景纹理、曝光和内容先验。两类数据保留独立的场景级
held-out，不以混合平均分掩盖其中任一类失败。新增纹理必须单独报告新显露区域的 RGB／感知质量，

MegaScenes 顶层 metadata 虽为 CC BY 4.0，但照片各自拥有独立许可。产品训练切片必须逐图读取
`raw_metadata.json`，并且一对图片均通过后才能入选；当前白名单仅为 Public Domain、CC0 与
CC BY，同时保存作者、许可名称、许可 URL、原始说明页面、S3 对象键与 SHA-256。CC BY-SA、
CC BY-NC、CC BY-ND 和许可缺失内容全部排除；CC BY-SA 是否可用于未来训练须另行法律审查，
不能因为技术上可下载而默认纳入。首轮冒烟审计从 17 个候选场景选出 5 个合规场景、10 张
CC BY 图片，已验证官方 split 文件名中的空格必须按官方 dataloader 规则替换为 S3 对象名中的
下划线。该 5 场景切片只验证下载与合规链路，不足以证明 student 泛化。

## D97：真实照片 pair 必须同时通过许可、外观和三维重投影三道门禁（2026-08-06）

把 MegaScenes 许可切片扩展到 20 个 train 场景和 10 个官方 test 场景，并对每张图片保存作者、
许可、原始页面、S3 对象键和 SHA-256。外观门禁使用 SIFT + MAGSAC 对应点覆盖、对应点亮度相关、
逐通道仿射颜色残差、全局饱和度和灰度比例，train/test 分别保留 19/8 对。Windows OpenCV
不能直接读取含 `Drehbrücke` 等 Unicode 字符的路径，DA3 预处理已改为 Python 字节读取后
`cv2.imdecode`，并显式把日志编码设为 UTF-8；不得通过删除非 ASCII 场景绕过工具缺陷。

随后以真实 SIFT 内点直接检验 COLMAP 相机和 DA3 输出：按 `c2w = inv([R(q), t])`、
`SIMPLE_RADIAL` 去畸变／重投影，并在对数尺度网格上拟合源深度尺度。19 个 train pair 中，
DA3 `depth` 解释的基础重投影中位数为 `5.99 px`，明显优于把输出解释成逆深度的 `20.63 px`；
最优尺度因子的跨场景中位数为 `0.974`，确认现有 DA3 ABI、深度方向和相机轴系总体正确。
但 Rathaus、Hungarian Parliament、Cristo Rei 等 pair 的最佳误差仍为数十到数百像素，证明
仅靠 SIFT 外观一致性不足以保证相机元数据可用于稠密 NVS 监督。

训练数据因此增加硬门禁：至少 50 个内点，DA3 depth 经单一尺度校准后的中位重投影误差
`≤10 px`、P90 `≤55 px`，尺度因子位于 `[0.25, 4]`。最终 train 为 13 个场景，官方 test 为
7 个完全隔离场景；每个入选 pair 把拟合尺度和完整检验报告写回 manifest。任何真实多视图
训练数据以后都必须经过相同三道门禁，不得用训练损失去吸收错误相机、裁剪或时序变化。

## D98：自由三维残差是必要表示，但低容量点预测器不能承担隐藏纹理生成（2026-08-06）

在上述 13/7 场景上训练同一 451,640 参数 student，输入原图和 Android 同 ABI 的 DA3 depth；
高分辨率可见表面始终由原图建立，网络只输出每格两个可横向偏移的自由 Gaussian。损失分别
约束新显露区 RGB、边缘、覆盖、对齐后的 target depth 和源视点身份，评估严格使用官方 test
split。300 步后，test 稳定支持区 PSNR 变化仅 `-0.0006 dB`，再次确认“可见原图旁路”能避免
网络重绘主体；但覆盖只增加 `1.98` 个百分点，新显露区仅 `13.64 dB / MAE 0.245`，depth
AbsRel 为 `0.447`。放大图仍是源纹理复制、拉伸和低频块，不能形成可信的遮挡后表面。

该 checkpoint 判定失败，不进入 Android、不上传阿里云。结论不是退回规则 LDI，也不是继续
增加 opacity、footprint 或训练步数：自由三维残差适合作为最终持久资产，但隐藏 RGB 必须先在
图像空间生成。下一条产品原型改为：只在少量正负水平／垂直极值 keyview 中生成由几何 warp
标出的新显露 mask；所有可由原图投影的像素硬锁定，不允许生成模型修改脸、身体、文字和已见
背景；再对合成 keyview 估深并把仅属新显露区的颜色／几何融合成自由 Gaussian，交互阶段仍只
运行持久 3D renderer。快速模型和高质量模型都必须输出 confidence，并允许按方向缩小安全包络。

## D99：Flow Matching 可用于隐藏区生成器，但不替代多视图表示和产品许可（2026-08-06）

重新审计 2025—2026 官方候选后，WorldStereo 2.0 和 Lyra/GEN3C 共同支持“先生成一致 keyview，
再重建持久 3D”的结构方向，但不能直接成为端侧产品模型。WorldStereo 依赖 Wan 2.1 I2V 14B，
完整依赖和 checkpoint 为数十到上百 GB；GEN3C 即使全量 offload 仍报告约 43 GB 峰值；Lyra 1
同样约 43 GB，Lyra 2 权重为内部科研许可。SEVA 1.1 虽只有 1.3B 参数，但权重为 Stability AI
Non-Commercial License。DreamLite 权重为非商用许可，BlazeEdit 尚无可核验的官方公开权重。
这些模型只能作为架构或质量上限证据；许可受限模型及其受限制输出不能用于产品 student 蒸馏。

Flow Matching／rectified flow 是生成器的训练与采样方式，能把高质量模型压到少量步数，但不会
自动提供遮挡拓扑、相机一致性或持久表面。因此高质量可下载模型可采用自研 masked conditional
flow，快速模型可采用确定性 masked decoder；二者共享相同的“可见像素硬锁定、极值 keyview、
新显露区三维融合、运行时只渲染”的资产协议。训练只使用逐图许可通过的真实 pair、Charge 等
许可明确的合成多视图和允许生成衍生训练数据的 teacher；没有可分发权重、许可或端侧内存证据
的近期论文不得因为年份新而进入模型目录。

## D100：显露区生成必须先通过真实域门禁，不能用混合平均分掩盖失败（2026-08-07）

已建立统一的 masked keyview 数据协议：由源 depth 和真实相机生成清晰前向 warp、精确显露 mask、
warp depth 与 Telea 基线；模型只预测显露 mask 内的 RGB／confidence，最终使用硬合成逐像素恢复
mask 外的几何 warp。首轮缓存包含 109 个训练 pair 和 39 个场景级留出 pair，其中 Charge 为
96/32、通过三重筛选的 MegaScenes 为 13/7。该协议下可见区域最大改动严格为 `0`，后续任何模型
都不得以重绘整幅图来换取新区域分数。

11.24M 参数确定性 U-Net 在 1500 步后把混合 test 显露区从 Telea 的 `14.91 dB / MAE 0.135`
提高到 `17.34 dB / MAE 0.102`，但增益主要来自 Charge；MegaScenes 真实域仅变化 `-0.016 dB`，
宽显露区仍是模糊拖抹。相同容量的 4-step conditional rectified flow 在 2000 步后混合 test 为
`16.73 dB`，真实域比 Telea 低 `1.39 dB`，并出现彩色噪声。两者 checkpoint 均判定为数据探针，
不进入 Android、不上传模型目录；这不否定 flow，而是否定用 13 个真实 pair 从头训练生成先验。

训练与验收今后必须分域报告 Charge、真实照片和原记事附件，真实域必须独立提升且放大后没有
重复纹理、颜色噪声或低频涂抹，不能用 Charge 的高增益抵消真实域失败。下一轮先把逐图许可、
外观一致性和重投影三重门禁后的 MegaScenes 扩到百场景级，再训练快速确定性模型；高质量 flow
从已通过门禁的确定性权重初始化，只学习多解残差。只有 keyview 质量通过后才实现新区域 depth
对齐和持久自由 Gaussian 融合，最后以连续水平／垂直／对角／闭环轨迹验证三维一致性。

## D101：停止独立补图、插帧和二维重投影叠加，改为联合多视图生成的显式资产（2026-08-06）

把逐图许可审计扩展到 MegaScenes v2 后，train/test 分别从 808 个审计候选中保留 220/80 个
许可合规 pair；外观门禁保留 178/66 个，三维重投影门禁最终保留 112/44 个，train/test 精确
类别交集为 0。由此生成的 masked keyview v2 含 208 个训练样本和 76 个场景级留出样本。11.24M
参数确定性 decoder 训练 5000 步后，留出显露区相对 Telea 提高 `2.20 dB`，其中 MegaScenes
提高 `1.92 dB`，mask 外像素改动仍严格为 0；但大显露区的梯度能量只约为真值的 `0.55`，放大后
仍是明显拖抹。以该 decoder 为底座训练 residual rectified flow 后又下降 `0.31 dB`；此前从头
训练的 conditional flow 也有彩色噪声。两种 flow 和 decoder 均作为失败探针保留，不进入产品。

进一步使用 Charge 的真实 RGB-D 做表示上界实验。中心视图加四个极值 keyview 的稀疏 mesh
在目标视点只有 `72.66%` 覆盖率；改成完整 keyview 也只有 `77.31%`。加入八个外圈真实
RGB-D keyview 后，严格遮挡边界仍只有约 `77.5%` 覆盖；取消深度断边可达到 `97.89%`，但会把
前后景跨遮挡连接并拉伸，已覆盖区域 PSNR 只有 `17.39 dB`。源层严格、隐藏层宽松的折中为
`92.78% / 17.04 dB`，仍有明显遮挡重叠和形变。结论是二维 mesh、point fragment 或规则 MPI
即使拿到真实 keyview，也不能可靠恢复连续大角度的可见性拓扑。

使用 MIT 许可的 RIFE 4.26 对真实中心视图和外圈 keyview 插值到中间真实相机，PSNR 从线性
混合的 `17.13 dB` 提高到 `17.87 dB`，但梯度能量只剩真值的 `59.6%`，并出现明显重影和模糊。
插帧模型只能在两个已经正确且足够接近的视图之间做辅助，不能创造缺失表面，也不能成为空间
照片的几何表示。

产品路线因此改为一次生成、持续渲染的联合系统：生成器必须在同一次前向中预测完整的小半径
水平、垂直和对角视图轨迹及其共享几何，而非逐方向独立补图；显式 decoder 直接输出固定数量、
可自由定位的 layered textured Gaussian／MPI primitive、alpha、方向置信度和安全包络；参考视点
以原图高分辨率纹理硬锚定，模型不得重绘已经可见的人脸、身体、文字和背景；交互阶段只渲染并
在资产内连续移动相机。快速档使用确定性联合生成器，高质量档使用少步 flow／diffusion 联合
生成器，但二者共享相同资产 schema。任何单视图深度 mesh、语义卡片、独立补图、RIFE 插值或
事后二维防扭曲都不再作为主路径。

现成模型只作为结构和质量证据。Lyra 1 的静态 3DGS decoder 为 32.75M 参数、checkpoint 约
62.5 MiB，NVIDIA 模型卡明确允许商用；但它要求 Cosmos/GEN3C 先生成 121 帧多视图 latent，
官方整套系统即使全量 offload 仍约 43 GB，不能直接端侧部署。Lyra 2 为 14B 且明确禁止生产
使用。TokenGS 的 checkpoint 约 0.83--1.38 GiB，C3G 多视图 checkpoint 约 4.31 GiB，且二者
只重建已有多视图，不能由单图补出隐藏内容。因此后续只采用“联合多视图监督、固定 token 直接
回归自由 primitive、原图旁路”这些一般原则，独立设计和训练手机尺寸模型，不复制受限模型，
也不把任何候选权重上传阿里云。

## D102：OVIE 证明联合视角生成可产生真实空间响应，但 256 checkpoint 不直接进入产品（2026-08-06）

对 2026 年发布、MIT 许可的 OVIE v1.0 做完整本地门禁。官方 checkpoint 为 143M 参数、
`571,288,316` 字节，单张 RGB 与目标相机 token 可在一次确定性前向中生成目标视图。原单人、
原双人和七类留出场景的 256×256 扫描显示：中心视图 PSNR 为 `19.54--26.76 dB`；半径
`0.2` 的连续进场、圆周和回中轨迹具有明确的前后景相对运动与遮挡变化，循环回差约 `1e-5`，
不是语义卡片刚性平移。半径 `0.4` 已在手、酒杯、桌面和遮挡边界产生明显生成漂移，因此
`0.2` 只作为后续训练与资产采样的初始安全范围，不是产品定值。

官方权重只在 256 训练，放大检查仍明显发软。直接将网络扩到 512 并重建更大的 sin-cos 位置
网格会产生周期条纹；把训练时 32×32 位置网格插值到 64×64 后，中心 PSNR 可提高到单人
`27.07 dB`、双人 `29.68 dB`，但非零视角即使降到半径 `0.03` 仍出现蜂窝纹理、拖影和脸部
发虚，说明中心重建改善不等于高分辨率视角生成已经泛化。把 512 画布切成九个重叠 256 窗口也
失败：各窗口独立解释相机运动，重叠区产生重复五官、人物重影和接缝。两种外推均不得进入 App。

NTIRE 2026 Mobile Real-World Image SR 冠军 VIPSL PLKSR-Rep 的 27.18 MB 权重也完成了原尺寸
复核。缩略图看似变锐，但 1024 输出会重绘眼睛、嘴唇、手指和发丝，形成塑料感与错误轮廓；
经典 DIS 光流迁移原图残差则出现交叉纹理和错位。因此生成式超分、传统光流、原图与生成视图
交叉淡化都被排除，尤其禁止通过重绘人脸掩盖 256 输出。参考视点仍必须硬旁路原图，但相邻视图
须由同一高分辨率模型连续生成，不能混合两套不一致的几何。

OVIE 当前只保留为可商用训练初始化和联合视角正例，不作为已通过的产品模型。下一步使用
CC BY 4.0 的 Charge 真实 RGB-D／相机多视图，在 512 网络上冻结大部分已学语义，只训练
分辨率相关位置／相机调制与解码参数；同时用未参与训练的真实人物和多类别场景验证中心身份、
圆周连续性与大视角细节。只有该适配在放大视频门禁通过后，才评估 FP16／INT8、按需下载和
端侧一次性资产生成。LagerNVS 512 与 UniSHARP 虽然方向接近，分别受 FAIR Noncommercial
Research License 与 CC BY-NC 4.0 限制，只作研究对照，不参与产品蒸馏或分发。

## D103：高分辨率外观改用原图直采样，OVIE 只生成联合视角几何引导（2026-08-06）

Charge 适配进一步确认 512 OVIE 不是可接受的产品出口。相机／调制参数适配能改善中心身份，
解码器联合训练也能提高真实 pair 数值，但非零视角仍以周期纹理、连续拖影或整体发糊吸收误差；
直接 512、分块 512、PLKSR 重绘以及“目标图加原图残差”均无法同时守住人脸和纹理。因此不再
要求生成器直接输出最终高分辨率 RGB，也不再继续用像素损失硬训 512 decoder。

新的候选表示以官方 256 OVIE 生成同一相机轨迹的低分辨率联合视角，只把它当作几何／遮挡引导；
使用 Apache-2.0 的 NeuFlow v2（官方 mixed checkpoint `36,195,519` 字节）估计目标视图到中心
视图的双向稠密对应和前后向一致性。高置信可见区直接从原始附件采样，不把两套人脸纹理相加；
越界、遮挡和光度不一致区才回退到联合视角 RGB。中心视点继续逐像素硬旁路原图。原单人、原
双人以及室内、办公、交通、近物、雕塑、食物、插画人物共九类场景的 79 帧圆周序列显示，人物
五官、直线和细小物体均明显优于 512 生成与传统 DIS，且相邻逐帧胶片带没有可见跳变。

画布边界不能使用反射或模糊 overscan：前者会生成重复人物，后者会把模糊边当成场景幕布。
当前桌面候选先用一次 `tz=-0.2` 的 OVIE 后退视角生成画外内容，再以该结果生成半径 `0.2`
圆周视角，并按附件宽高比裁回约 `80%` 的中心安全视场；这是同一联合生成器的两阶段自扩图，
不是运行时动态缩放。它在九场景门禁中显著减少了边界复制，但仍须在更多真实附件和真机大角度
录屏中检查极端边缘，未达到可直接发布的结论。

产品资产方向由自由 Gaussian 改成可验证的二维联合视角场：中心原图、固定数量外圈 key-view
的反向 flow、可见性／置信度以及低分辨率显露 RGB。交互阶段按倾斜的极坐标在相邻外圈 flow
之间插值，径向与零 flow 插值，并由 GPU shader 直接采样原图；这保留 OVIE 学到的内部深度差
与遮挡响应，又不让生成器重画已见人脸。下一门禁是量化非刚性视差、缩放漂移和时间二阶差分，
随后导出、量化 OVIE 与 NeuFlow，验证 Android 算子、内存、耗时和 key-view 数量；通过前不改
稳定 catalog、不上传模型、不发布阿里云。

## D104：运行资产必须是周期共享运动场，不保存逐帧独立光流（2026-08-06）

对九场景 79 帧候选补充了运动结构门禁：每帧先拟合目标到中心的最佳相似变换，再分别统计全局
scale、剩余非仿射位移和环形中位 flow 的时间二阶差分。候选的 scale 跨外圈 `P95-P05` 为
`0.0126--0.0720`；剩余 P90 位移相对总 flow 的中位比例为 `0.153--0.998`，证明它没有统一退化
成刚性卡片，但也暴露出不同场景的对应可靠度差异。更关键的是二阶差分／一阶差分比达到
`0.33--2.53`，明显高于 64 点平滑圆周约 `0.10` 的离散曲率基线；单人、室内、近物和雕塑尤其
容易出现逐帧 NeuFlow 失配。此前静态胶片带“未见跳变”只能算人工初筛，不能覆盖连续倾斜。

因此产品派生不得保存或运行逐帧独立估计的 flow，也不得在传感器每帧重新推理。生成期只在固定
方向估计外圈 key-view，并把它们投影到一个首尾相接的周期运动场；运行时由同一组周期基函数连续
求值。8、12、16 个方向必须用完整 79 帧圆周统一比较，门禁同时约束：中心原图硬旁路、闭环误差、
全局 scale breathing、二阶差分、去除相似变换后的可感知视差，以及遮挡／显露区域的错误纹理。
只有 key-view 数量和周期插值通过后，才冻结 Android 资产 schema；OVIE／NeuFlow 的 ONNX 导出
可以并行做可行性验证，但不得因为模型可运行而跳过运动场门禁。

## D105：产品视角改为单目小基线，连续深度逆向重采样重新成为主基线（2026-08-06）

用户明确纠正此前压力测试目标：普通单张附件不需要生成特别大的侧视角。重新以无 bootstrap 的
OVIE `r=0.05 / 0.075 / 0.10` 做九场景圆周门禁后，`r=0.05` 在原单人仍保留约 `5.86 px`
非相似位移，8 个外圈 key-view 的一阶周期基可把运动场二阶／一阶变化稳定到约 `0.098`；但
OVIE 在交通和雕像两类场景几乎不响应，而且单人原始运动含约 `9.1%` 的全局 scale span。
`r=0.075` 又把单人非相似位移推到约 `9.12 px` 并降低对应置信度。由此否决“统一放大或缩小
OVIE 半径”作为产品解，也不得把生成模型的呼吸缩放误计为空间感。

在相同九场景上新增从高分辨率原图直接采样的连续深度小基线原型：先对逆深度做稳健归一化、
双边去噪和原图引导平滑，再用固定点逆解完成二维圆周重采样；参考视点逐像素保持原图，运行时
不做前向 splat、不切语义卡片，也没有黑缝和动态缩放。`6 / 8 / 10 px` 的全图 p5--p95
视差扫描在人物、多人、室内、交通、近物、雕像、食物和人物／宠物上均产生响应；静态极值门禁
中 `8 px` 保持了脸、身体、直线与细结构，且修复了 OVIE 对交通／雕像无空间响应的问题。

因此 Android 下一基线改为“小基线连续 disparity field + 原图 GPU 逆向采样”。默认先采用
长边 720 像素下约 `8 px` 的稳健场景视差，高强度不得直接扩大到旧大角度，而须由局部 Jacobian、
边界可靠度和显露预算共同限制；不同分辨率按显示像素等比例换算。OVIE／NeuFlow 暂退为离线
对照和未来显露区候选，不再阻塞第一版端侧实现。该决定只在小基线前提下重新启用连续深度，
不恢复旧的大角度 mesh、语义分层或人物卡片路线；真机圆周录像仍是发布前门禁。

## D106：撤销 D105 的 `8 px` 默认预算，扩大动态校准到 `18 / 20 px`（2026-08-06）

用户查看同图同轨迹的 `6 / 8 / 10 / 14 px` 可交互对照后，确认 `14 px` 仍不足以达到期望的空间感。
因此 D105 中“默认约 `8 px`”及把 `6–10 px` 当作主要产品范围的数值结论立即撤销；连续 disparity
field、原图逆向采样和单目安全视角约束本身暂不撤销。

下一轮对照扩展到 `18 px` 与 `20 px`，其中 `20 px` 仅作为当前可观察候选，不直接等同于最终默认值或
全场景安全上限。冻结参数前仍须在单人、多人和额外场景的连续圆周运动中同时检查空间感、脸部／身体形变、
细结构清晰度与边缘显露；如果 `20 px` 视觉上合适但局部应变越界，应优先改进形变约束和可靠区分配，不能再次
靠统一压低全图视差解决。

## D107：把 `20 px` 设为下一轮有效空间感下限，并加入 `24 px` 候选（2026-08-06）

用户继续校准后确认：`18 px` 仍不是目标下限，下一轮产品候选至少应达到长边 720 像素下约
`20 px` 的 p5--p95 相对视差，并比较 `24 px`。这里的“下限”是视觉目标，不表示每个高风险局部
都必须无条件使用相同位移；局部可靠度、遮挡拓扑和形变约束仍可重新分配位移场，但不得通过把
全图统一压回 `20 px` 以下来掩盖问题。

因此当前任务从“寻找足够小的安全基线”转为“在 `20 / 24 px` 有效空间感下解决局部形变”。
冻结 Android 默认值前，必须先把桌面候选移植为同口径 GPU 逆向采样，再以单人、双人和额外场景
的真机连续圆周录像验证；现有 vNext/LDI 前向几何不能作为该范围的质量结论。

## D108：视差校准上界保持开放，扩展对照到 `40 px`（2026-08-06）

用户明确指出 `24 px` 也可能不足，目标可能达到 `36 px`。因此不把 `24 px` 当作终点，下一轮同图同轨迹
对照改为 `14 / 18 / 20 / 24 / 28 / 32 / 36 / 40 px`；其中 `20 px` 仍是当前候选下限，`40 px`
仅作辨认空间感饱和点与形变拐点的参照，不代表产品默认值。

后续形变优化必须在用户选出的有效视差范围内进行：允许按局部可靠度重分配位移、约束 Jacobian 和在可信遮挡
边界引入显露，但不得因为高档位更难处理而静默降低标称 p5--p95 相对视差。

## D109：vNext6 以方向校准的 `36 px` 保形位移场取代固定 UV 幅度（2026-08-06）

用户将当前主目标收敛到长边 720 像素下约 `36 px`。九场景原始连续 inverse warp 在该档位的
局部应变 p95 中位数已达 `0.445`、最差人物／宠物为 `0.872`，p99 中位数为 `1.142`；直接把
连续深度放大到 36 px 会产生折返、脸部拉伸和细结构破坏。随后验证的 naive forward splat、
窄隐藏带、root-search inverse、分层 forward warp 与独立 shape-vector 方案分别出现锯齿轮廓、
污染显露纹理、断边条纹或明显正交漂移，均不迁移 Android。D107 中“把原始连续 inverse warp
直接作为 Android 主路径”的实现要求由本决策取代；它仍保留为视差标尺和无洞基准。

vNext6 使用已有显式 cut graph 和隐藏背景拓扑，但把所有深度 chart 都纳入局部 similarity MLS，
不再让语义分割／matting 决定哪些区域有资格保形。分割只补充经过深度验证的遮挡连续性和补图条件，
未识别物体、建筑、交通、雕塑及普通背景同样使用二维保形位移基。可信 cut 两侧可以分别近刚性移动，
连续 chart 内只保留经过低频平滑和局部相似约束的宏观体积，避免恢复逐像素单轴橡皮形变。

视点预算不再使用每张图片相同的固定 UV 常量。生成期对 16 个方向分别计算位移场在物理长边坐标中的
p5--p95 投影跨度，并以 720 px 为参考把满强度包络校准到 `36 px`；请求上限从 `0.12` 提高到
`0.20`，使低跨度场景仍有达到目标的余量。几何正则化继续按 `0.12` 参考预算执行，不能因为开放
更大视点而额外压平连续表面。若单一连续表面在 1.5% 非相似形变与 2.2% 局部等比缩放门槛内无法
达到 36 px，安全包络必须保形限幅；不得伪造 36 px 标签，主要空间跨度应由可信 chart 间视差承担。

Jacobian 统一在屏幕物理坐标中计算：横向位移对纵向坐标的导数按图像宽度换算，纵向位移对横向
坐标的导数按图像高度换算。新增竖图纯旋转回归，防止把宽高比换算错误误判为剪切并无端压缩斜向
包络。新派生使用 schema v8／renderer `surface-charts-vnext6-directional-36px`，旧 vNext5
继续可读，但只有重新生成空间效果才会得到新的方向包络、扩大后的隐藏背景和全 chart 保形场。

## D110：否决并冻结 vNext7 的 chart 内局部刚性路线（2026-08-06）

vNext7 没有引入新的推理模型：仍使用 Depth Anything 3 Small、MODNet、RF-DETR Seg Nano 与 MI-GAN。
新增内容只是几何求解与渲染约束：16 方向 `36 px` 包络、所有 chart 的 local-similarity MLS、
更强的深度低频平滑，以及 schema v9／renderer `surface-charts-vnext7-directional-36px-volume-balanced`。

九场景真机派生证明该路线的总视差指标失真：单人图被切成 2 个 chart，全图中位跨度达到 `36 px`，
但人物内部中位跨度只有 `1.36 px`；双人图为 `3.96 px`，人物／宠物图为 `2.09 px`。办公室和雕像等
单 chart 场景在保形门禁下全图也只能达到约 `12.10 / 11.16 px`。因此大部分 `36 px` 来自 chart 之间的
近刚性相对平移，而不是主体内部深度；这正是纸片感。此前已被明确否决的 `4.28 px` 主体内部响应也没有被超越。

该失败不是继续调分割阈值、MLS 平滑次数或应变预算即可解决的局部问题：单张纹理在一个大 chart 内若严格保形，
内部深度响应会被压平；若直接放大连续深度 warp，又会恢复脸部与身体扭曲。分割不是三维表示，且不稳定掩码会进一步
制造错误边界。故 vNext7 路线不再推进，也不得把全图 `36 px` 当作通过证据。后续只有在用户明确批准新的表示路线后才能开始；
当前代码、真机测试包与工作区均保持原状，不擅自继续或回滚。

## D111：vNext8 回归全局连续深度运动，分割退出生成主路径（2026-08-07）

用户解除暂停并明确要求回归早期方向：空间效果必须来自单张图片的全画面连续多视角响应，不能再把主体分割结果
转换为独立运动层。诊断回归首先在修复前稳定复现两项失败：同一深度仅改变分割／matting 提案就会改变 cut；

直接根因是分割仍在改写拓扑，以及整幅 `protectedMotionMask=true` 后执行 256 轮弱数据扩散与近刚性拟合。

新生成结果改用 schema v10／renderer `surface-depth-vnext8-global-continuous-28px`。主运动场只消费单目深度：

持久隐藏背景继续保留，用于真实显露而非定义对象运动。

视角从 vNext7 的满强度 `36 px` 改为长边 720 像素下最多约 `28 px`；现有默认强度映射预计落在约 `22--24 px`，
请求幅度上限从 `0.20` 收回到 `0.16`。这是一轮真机校准起点，不是不可调整的产品常量。自动门禁改为：分割输入

正式撤销。是否进入发布只能由跨场景真机连续圆周录屏与用户观感决定。

## D112：vNext8 主表面改用全局 inverse warp（2026-08-07）

`3B1629006YC00000` 的首段默认强度连续圆周录屏证明，D111 已消除人物整块刚性平移，人物内部会随连续深度场响应；
但 forward mesh 仍会在头发等深度突变轮廓删除三角形，并在部分视点形成肉眼明显的三角撕裂、锯齿和补图显露。
该问题来自前向离散拓扑，不是分割边缘质量，因此不得重新引入语义 mask 修补。

vNext8 的普通“稳定／立体”模式改为全屏 backward/inverse warp：将持久化的四通道连续位移基上传为 RGBA8 纹理，
每个 fragment 用四轮固定点迭代反解源 UV；相邻屏幕像素始终有定义，不再因深度 cut 丢三角、产生洞或显露错误补图。
位移仍完全来自 D111 的深度连续场，方向包络和约 `28 px` 上限不变，分割、matting、ownership 与主体 mask 仍不参与。
MPI 作为用户显式选择的实验模式可以保留原分层路径；它不能反向影响默认全局空间效果。

由于 schema v10 已完整保存 inverse warp 所需的 motion basis 与方向包络，这次只改变兼容的消费方式，不重写派生格式；
已有 vNext8 缓存可直接获得修复。验收继续以同一真机上的单人、双人和非人物场景连续轨迹为准。

同时把 vNext 方向包络的低强度基线从旧 P0 的 `0.024` 解耦为 `0.012`。否则 vNext8 多数方向的满强度幅度本就只有
约 `0.020--0.027`，默认 `0.72` 会几乎等于满强度，滑杆失去意义。新映射使默认档约为目标视差的 84%，即
`28 px` 包络下约 `23.5 px`；最大档仍完整保留约 `28 px`，无需增大单目外推范围。

## D113：vNext9 使用与遮挡拓扑解耦的双尺度全局运动场（2026-08-07）

## D114：vNext10 让模型服务于连续深度可见性，不再生成语义运动卡片（2026-08-07）

用户确认 vNext9 虽回到全局连续空间场，但仍有形变且空间感不足，并要求重新实际利用已经下载的深度、分割、

独立决定所有可见像素的运动与主体内部视差；RF-DETR Seg Nano 只删除同一可信人物实例内部的伪遮挡 cut，并提供

AOT-GAN／MI-GAN 只写入最终运动确实会显露的窄背景带。分割缺失、低置信或非人物区域继续使用全局深度场，不能退化
为整块平移。

显露带宽改由最终 motion basis 与 16 方向安全包络的最大法向相对位移计算，而不是用原始深度跳变乘理论最大幅度。
两个真实附件在 512 长边网格上的实际写入区分别收敛到约 `2.54%` 与 `1.82%`，隐藏网格分别约 `0.98%` 与
`0.66%`；完整人物 mask 只作为模型条件，生成结果只回写窄显露带。主表面网格从 256 提升到 512，降低头发和
斜边的栅格台阶；参考视差候选开放到 `36 px`，但每张图仍受 8% 非相似形变与 10% 局部尺度门禁约束，困难双人图

生成内容正确，也会因前景、远景运动不同步在人物轮廓产生拖影或接缝。该背景运动基由已持久化的表面运动、cut 与
方向包络确定性重建，不需要再次运行模型，也不增加派生格式。中心视点仍硬旁路为原图；当前离线真实附件极值／圆周
预览和完整 JVM 测试已通过，但真机 GPU 连续轨迹因设备锁屏尚未完成，因此本决策不等同于视觉验收或发布结论。
