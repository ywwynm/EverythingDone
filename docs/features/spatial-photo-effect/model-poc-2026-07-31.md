# 空间深度模型 Android PoC

日期：2026-07-31

## 结论

ZipDepth 与 Depth Anything V2 Small 均已从官方权重导出为 ONNX，并在两台授权的 arm64 Android
真机上完成模型加载、推理、输出形状、有限数值和动态范围校验。双模型的基础算子可运行性门槛通过，
但性能定位明显不同：

- ZipDepth 适合作为默认推荐模型；在本轮设备上单次推理约为 36～330 ms。
- Depth Anything V2 Small 可作为用户主动选择的质量模型；OnePlus 上约 0.69 秒，Samsung 上约
  5.54 秒，且原生内存增量约 363～617 MiB。
- XNNPACK 没有成为通用优选路径。它对 Samsung 的 ZipDepth 略有帮助，但对两台设备上的
  Depth Anything V2 Small 都显著变慢。正式实现先使用 ORT CPU，并将线程数限制为 4；不按模型
  静默切换到尚未验证的 NNAPI/GPU。

这不是最终发布准入。当前两台设备均为 API 36、高内存 Qualcomm 设备，仍需真实图片画质、完整生成
链路、OpenGL 帧时间、低内存与较旧 Android 覆盖。

两个模型均使用 ONNX opset 18：

- ZipDepth 使用官方 mobile/NPU 导出路径。
- Depth Anything V2 Small 使用官方模型和静态 legacy exporter。
- 正式图片预处理不得把任意宽高比直接拉伸到正方形；应按比例缩放、补边，推理后去除补边并映射回
  原图坐标。

桌面固定输入的 PyTorch/ONNX Runtime 数值核对：

| 模型 | 最大绝对误差 | 平均绝对误差 | 有限数值 |
|---|---:|---:|---|
| ZipDepth | `8.20e-08` | `1.51e-08` | 通过 |
| Depth Anything V2 Small | `2.86e-06` | `6.55e-07` | 通过 |

## Android 运行环境

PoC 使用 `com.microsoft.onnxruntime:onnxruntime-android:1.28.0` 的完整预构建 AAR，目的是先验证模型，
不是最终 APK 体积方案。当前 universal debug APK 因包含多个 ABI 的完整 runtime 增长到约 136 MiB；
发布前必须改为目标 ABI 打包或基于两种模型的算子配置构建精简 ORT。

| 序列号 | 设备 | 系统 | 内存 | GPU |
|---|---|---|---:|---|

| `RFCT90LSFGT` | Samsung SM-F9360 | API 36，arm64-v8a | 约 12 GB | Adreno 730，OpenGL ES 3.2 |

## 真机结果

表中时间是固定合成输入、一次 warm-up 后的稳态中位数，不包含图片解码、预处理、深度后处理与磁盘
写入。内存是 Android Debug API 观察到的原生堆增量，只用于本轮相对比较。

| 设备 | 模型 | Provider / 线程 | Session | 推理 p50 | p95 | 原生内存增量 |
|---|---|---|---:|---:|---:|---:|
| OnePlus | ZipDepth | CPU / 6 | 46.60 ms | 36.69 ms | 43.33 ms | 158.16 MiB |
| OnePlus | ZipDepth | XNNPACK / 6 | 88.00 ms | 35.52 ms | 38.05 ms | 164.87 MiB |
| OnePlus | DAV2 Small | CPU / 6 | 216.87 ms | 691.74 ms | 714.09 ms | 617.49 MiB |
| OnePlus | DAV2 Small | XNNPACK / 6 | 235.22 ms | 2,380.19 ms | 2,398.36 ms | 644.40 MiB |
| Samsung | ZipDepth | CPU / 4 | 74.42 ms | 330.14 ms | 337.36 ms | 90.95 MiB |
| Samsung | ZipDepth | XNNPACK / 6 | 326.17 ms | 311.72 ms | 321.77 ms | 133.46 MiB |
| Samsung | DAV2 Small | CPU / 4 | 704.51 ms | 5,544.68 ms | 5,584.29 ms | 363.14 MiB |
| Samsung | DAV2 Small | XNNPACK / 6 | 703.39 ms | 10,403.65 ms | 10,480.57 ms | 482.76 MiB |

Samsung 的 ZipDepth CPU 线程扫描结果为：

| 线程数 | p50 |
|---:|---:|
| 1 | 821.14 ms |
| 2 | 447.44 ms |
| 4 | 330.14 ms |
| 6 | 514.25 ms |
| 8 | 780.33 ms |

因此先采用 4 线程作为保守默认值。正式准入仍应按完整任务的峰值内存与总耗时判定，不能只依据
`availableProcessors()` 或合成输入自动扩大线程池。

## 下一道验证门槛

1. 使用真实图片完成按比例缩放、补边、去补边和深度方向核对，并保存可视化深度图。
2. 用同一组图片对比双模型的主体边缘、头发、树叶、文字与低光结果。
3. 完成单层 UV 位移的 OpenGL 纵向链路，记录两台设备的帧时间与边缘伪影。
4. 在完整生成事务中记录解码、推理、后处理、写入和峰值内存；DAV2 的较高内存必须有明确准入检查。
5. 生成两种模型的 required-operators 配置并构建精简 arm64 ORT，确认 APK 体积与数值不回退。
6. 补充至少一台较低内存或较旧 Android 设备；本轮两台高端 API 36 设备不能代表发布矩阵。
