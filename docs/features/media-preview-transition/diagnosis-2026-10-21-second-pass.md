# 第二轮转场诊断

## 反馈与复现方法

用户反馈四项问题：HDR 动态照片返回疑似纵向拉伸、大图展开等待明显、返回顶栏图标闪烁变色，以及“新的测试君”首个视频返回附件区域闪烁。

继续使用已授权三星、一加、魅族，仅打开真实记事和附件；不修改原记录和播放偏好。基于现有 instrumentation 增加真实指定记事、多停留时长、关键帧几何及前后画面采样；性能轮次关闭截图，视觉轮次独立运行。先保存失败证据和分阶段基线，再修改生产代码。

## 已确认的基线与对照

- 一加真实样本：200 MP HDR 照片、24 MB HDR 动态照片，以及「新的测试君」首个 168,695,573 字节 4K 视频；分别停留 700 ms 与 4200 ms。
- 「新的测试君」两次返回均出现黑→白→黑的顶栏配色变化，时间点与附件容器 alpha 置 0、恢复为 1 对应。只移除容器透明度修改后，两次回归均保持黑色；覆盖层本身已完全覆盖窗口，不需要隐藏底层附件。
- 同一视频每次返回有四次 Drawable 身份，需继续分离未改变附件的结果处理与临时播放暂停。
- 大图展开的截图完成到准备结束仍耗 63–86 ms；大图和 HDR 动态照片静态返回前的完整图软件重绘耗 81–167 ms。性能修复应移除这次主线程重绘，而非削减最终预览质量。
- 一加 HDR 动态照片当前两次采样未检出实际纵横拉伸：静态/播放状态的像素特征仿射缩放比均约 1.000，末端播放帧为 1.003。继续覆盖三机及照片/内嵌视频的取景交接，不把该结果当作用户反馈已解决。

## 第二次定位

- 保留资源后，一加「新的测试君」仍在交接后从 GIF 第 5／14 帧回到第 0 帧；这是播放一次的 `startFromFirstFrame()` 与临时暂停混用。增加同实例接续后，实际记录分别为 5→6、32→33；三星与魅族继续正常递增。
- 魅族大图有一次目标截图于 225 ms 就绪，但异步取色直到 242 ms 才把白色图标改为黑色；动画结束于 538 ms，旧截图因此与真实按钮颜色不同。新增静态取色就绪检查与截图配色代次检查，不调整原取色算法或增加固定等待。
- 动画结束约 945 ms 后出现的静态主图资源更新不属于交接闪烁。资源稳定断言限定在准备完成至交接后 64 ms；仍保留后续 1 秒观测和帧号记录，正常播放结束回主图不误判。
- 取消额外 HDR 软件重绘后，三机 200 MP 图片重复打开准备时间分别由 315／212／329 ms 降至约 175／186／236 ms（三星／一加／魅族）。首次进程内打开受初始化影响更大，单列记录，不用重复打开的数字代替。

## 最终验证

三机真实记事合计 505 项，类型与边界合计 528 项，独立截图轮次 136 项，共 1169 项有效检查通过。覆盖普通图片、GIF、视频、动态照片、原生 HDR／强制 PQ、缩放、翻页、删除、快速返回、横屏、预览内旋转与目标离屏。删除会真实改变播放队列，因此不要求沿用删除前的 GIF 实例／帧；首轮两个不适用的断言已纠正，并在一加重新运行 86 项边界检查，全部通过。

JVM 共 1732 项，0 失败／错误，3 项既有跳过。三星 374、一加 114、魅族 181 条原记事逐行 SHA-256 不变；所选真实附件全文件 SHA-256 不变。测试修改仅使用专门模拟记事。
