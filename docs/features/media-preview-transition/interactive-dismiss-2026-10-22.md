# 图片／视频预览交互式返回

## 已确认交互

2026-10-22 按 `grill-me` 完成六项设计确认，用户随后要求开始实现。

- 单指上滑、下滑均可返回；放大状态先平移，触及对应边缘后继续向外拖动才接续返回。
- 两个方向均随向外拖动缩小，回拖时放大恢复，从接管时的尺寸连续变化。
- 黑底随拖动变淡并显露详情，回拖时恢复。
- 达到距离阈值或短距离快速向外甩动可返回；小幅慢拖松手回弹，保留接管时的倍率和位置。
- 拖动和回弹期间保留原播放规则与进度，确认返回后再停止；原本未播放的保持不播放。
- 空间模式保留单指视角控制，退出后启用滑动返回。

## 实现安排

- `MediaPreviewDismissPolicy` 独立计算方向、边缘剩余位移、缩放和松手判定，便于覆盖真实边界情形。
- `MediaPreviewDismissGesture` 只变换当前附件页外层，保留 PhotoView 矩阵、GIF／WebP Drawable、视频 TextureView 和 PQ Surface。根据当前实际媒体区域裁剪整页，避免缩小时拖出整块黑色页面。
- 详情背景复用打开时已捕获的单张画面，生命周期限定在此次查看器；尺寸变化后尝试重新捕获，来源失效时退回黑底。该背景是详情静态画面，当前预览媒体保持实时渲染。
- 接管时向原控件发送取消事件，单独撤销长按识别，不把该内部事件当成真实松手而停止播放器。真实松手仍遵循原有长按结束规则。
- 确认返回时先保留拖动位置，交给既有转场捕获；媒体几何包含父容器的变换，避免跳回全屏或仅偏移而遗漏缩放。
- 旋转、后台、第二根手指和资源替换需撤销交互并恢复外层属性；横向翻页、双指缩放和顶部控件保留原入口。

## 验证边界

- 新增 24 项 JVM／Robolectric 专项，覆盖多指中断、短距离快甩、背景像素变化、中断后下一次操作、边缘平移、回弹保倍率和媒体几何。
- 用户随后在本会话明确授权三机测试，已核对三星 `R5CW20BLNKL`、一加 `192.168.100.184:36007`、魅族 `192.168.100.67:40807`。已有记事只读，变更使用专用夹具，结束后清理。卓易通宿主的物理观感仍不能由 Android 的强制 PQ 验证替代。
- 全套 JVM 首轮的背景像素断言使用了不进行真实像素混合的 legacy Canvas；改用 Robolectric 原生绘图后，最终全套 1756 项，0 失败、3 项既有跳过；APK 构建成功。
- SurfaceView 的裁剪与窗口透明区域由平台合成处理；实现保留原 Surface，并裁剪同一媒体父容器。核对依据：[AOSP SurfaceView](https://android.googlesource.com/platform/frameworks/base/+/master/core/java/android/view/SurfaceView.java)。不调用隐藏裁剪 API。

## 实机回归方法

- 扩展现有 `MediaPreviewTransitionProbe`，使用真实 Activity 的触摸分发链、媒体区域坐标和真实播放器。覆盖静图、GIF、动态 WebP、视频、动态照片、原生 HDR 及强制 PQ。
- 先检查小幅慢拖、外拖缩小、回拖恢复、回弹后媒体实例和播放进度，再通过手势松手接续原返回转场，验证返回起点、视频比例、目标附件及输入释放。
- 放大测试根据实际屏幕与图片尺寸计算足够的倍率，确保存在可平移边缘；不能假定三倍图片一定超过所有设备的屏幕高度。
- 快甩测试在主线程发送固定时间间隔的事件，避免测试调度时间改变手势速度；先等待高清图就绪，资源替换撤销交互由单元测试另行覆盖。真实上下拖动和回弹按实际时间推进。
- 返回起点按屏幕可见范围裁剪后比对；全图几何与裁剪框分别验证，避免把正常的屏外裁剪误报为跳变。
- 使用系统合成截图核对包括 PQ Surface 的最终画面，保存拖动、回弹、确认返回的画面。空间模式在 Activity 层验证门控，未重新生成空间资源或完整复测空间渲染。
- 每轮核对原记事逐行摘要；真实样本另校验原附件 SHA-256。模拟数据仅在带本轮时间戳的专用记事中创建和清理。
