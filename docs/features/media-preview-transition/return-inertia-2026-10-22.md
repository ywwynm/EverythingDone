# 松手返回的停顿与惯性衔接

## 用户反馈与修复前证据

用户反馈 `202610220826` 中慢拖和快速甩动确认返回后，图像在中间停住，再启动缩回动画；期望沿松手方向继续一点，再连续收回详情。

以该版本三机原始时间线重放，24 次确认返回至首个运动帧均超过 48 ms：115.6–213.2 ms，平均 185.2 ms。回归脚本为 [check-dismiss-continuity.py](checks/check-dismiss-continuity.py)，修复前输出保存在 `tmp/media-dismiss-continuity-red.txt`。此前的 1125 项检查覆盖终点几何和播放，却没有检查初始时延，因此没有覆盖这次反馈。

按优先级区分了三项原因：冻结后等待跨窗口准备、松手速度丢失、截图额外开销。时间线与调用链表明，主要等待来自源截图、Activity 交接、详情布局稳定及第二次截图；速度只参与是否返回的判定。故减少一个等待帧或调整旧插值器不能完整解决。

## 修改

- 手势返回直接在当前预览窗口移动原媒体页，复用已经保留的详情画面；松手至运动之间没有截图和详情窗口就绪的依赖。左上角／系统返回与无有效目标时仍使用原回退。
- `MediaPreviewReturnMotion` 使用起点、终点和松手初速度生成 432 ms 连续轨迹；初速度不归零，终点速度为零。快速向外甩动自然先沿原方向前进，再收向目标；初速度较小时不会强行加入同样幅度的回弹。
- `MediaPreviewReturnAnimation` 在显示帧回调中变换原页，保持等比及媒体裁剪。原窗口之外缺失的取景由详情已解码的图片控件补齐，末端交接到详情缩略图，不重新解码图片或改变视频内容矩阵。只画图片自身，不把截图中叠加的工具栏、徽标和删除按钮一起移动。
- 确认返回后暂停播放器并保留实际纹理、停止动图的帧推进、冻结 PQ 当前增益；窗口退出后释放资源。取消返回不进入该路径，保留原规则。
- 运动完成后切换 Activity。详情尚未恢复时，用端点画面暂时遮盖，等布局稳定后淡出；这样窗口准备的等待不会插在松手与运动之间。后台／旋转中断只完成一次，退出前不恢复全屏图。

## 验证结果

- 新增 7 项初速度、惯性轨迹、实际页变换、后台中断、后台详情目标及补图像素检查。全套 1763 项本地测试无失败、3 项既有跳过，APK 构建通过。
- Robolectric 在推进主循环时连续处理帧回调，因此相关测试断言实际记录的第一运动帧和终点，而不是把 `idleFor` 返回时刻误当成中间帧。
- 实机探针增加确认到首个运动帧的时延、快甩首段方向和全程等比断言，并保存逐帧位置。
- 三星夹具回归 222 项断言通过，8 次返回均走即时运动路径且首帧时延不超过 48 ms。实机发现后台详情不能用 `getGlobalVisibleRect` 判断目标，改为保留布局与祖先裁剪求交；另将新路径的探针截图窗口改为仍承载动画的预览窗口。
- 三机首轮即时运动检查均通过。视觉核对发现末段复用整张详情截图的局部区域会携带上层工具栏，已改为直接重绘详情图片控件；新增像素检查覆盖图片上方存在工具栏的情况，随后重跑最终包。
- 一加一次快甩检查误把 0.35 ms 内的第二个零进度回调当作运动帧；实际第一运动帧在 16.64 ms，位置继续向外，初速度约 13376 px/s。修正探针为检查首个正进度帧，仍保留 48 ms 时延限制。另有一次真实媒体批次在打开详情前超时，未算作有效通过；后续重新启动并完成原生／PQ 全批次。

最终三星、一加、魅族各 406 项、合计 1218 项断言通过。42 次返回首个运动帧时延 0.743–19.278 ms，平均 8.431 ms；全部从交互路径起步，无截图准备等待。详见[检查摘要](checks/return-inertia-2026-10-22.json)。真实 200MP 图片、4K 大视频、GIF、HDR 动态照片及 PQ 输出检查通过，672 条原记事及选中附件 SHA-256 保持。

一加系统录屏逐帧核对了快甩：中心从约 1584 px 继续至 2221 px，再收回 456 px，移动过程保持等比，末段没有随图移动的工具栏副本。录屏在 `tmp/media-dismiss-inertia-oneplus-final-fixtures/recording.mp4`，关键帧在 `tmp/media-dismiss-inertia-final-fling-frames.png`；该录屏对应最终生产代码，之后只修正探针对零进度回调的判定。
