# HDR 动态照片播放中返回拉伸

## 用户反馈与边界

2026-10-22，用户反馈卓易通上的 HDR 动态照片在播放过程中返回仍出现纵向拉伸。继续使用已授权三星、一加、魅族三台设备；卓易通宿主无法通过当前 ADB 访问，三机强制兼容模式用于验证同一 PQ 输出路径，不能代替宿主物理观感。

## 诊断进展

- 正在补充专门的播放中返回场景。现有真实记事质量回归在返回前调用 `verifyHdrReady`，可能等待播放结束，不能作为播放中返回的验收证据。
- 检查完整链路：正在显示的视频几何、离屏截图中的视频帧、返回动画裁剪和缩放、详情目标交接。保留最终完整尺寸解码与 HDR 参数，原始记事只读。

## 已复现

- 一加当前真实 HDR 动态照片（记事 3226，第 2 个附件，24,558,787 字节，6120×4596）在强制 PQ 模式下连续两次返回都出现视频纵向撑满屏幕。原有矩形等比断言仍全部通过，说明测试没有检查截图内像素。
- 本轮原始截图保存在本地 `tmp/media-motion-return-before/`，文档不复制真实附件内容。
- 排查顺序：①离屏树的 `TextureView.bitmap` 丢失内容变换；②PQ 独立 Surface 使截图切入特殊合成分支；③停止播放与捕获异步竞争。分别使用冻结帧内容比对、原生输出对照、保持播放状态返回进行区分。

## 根因与修复

- 原生输出对照没有拉伸；冻结同一视频帧后，兼容输出的转场截图仍与屏幕不同，排除停止播放竞争。普通倍率与 2 倍缩放的平均通道误差分别为 52.17、50.99，约 69% 像素明显错位。
- PQ 独立 Surface 使截图进入 `ParticleViewCaptureTree`；它通过 `TextureView.bitmap` 读取视频，遗漏 `getTransform()` 的内容矩阵。1422×1067 视频被铺到 1216×2640 View，原本应有的纵向 0.3456 缩放与 863.79 像素平移均未应用。
- 初版仅补内容矩阵，在一加通过；三星、魅族仍检出约 1.234% 纵向差异，与视频解码缓冲的 1312／1296 高度差一致。没有用放宽阈值掩盖，改为让 `TextureView` 继续使用原生硬件 Canvas 绘制，完整保留内容矩阵、解码缓冲裁剪与原有色彩转换。独立 PQ Surface 仍单独捕获，不把它的活 RenderNode 交给另一渲染器。一次性与缓存捕获均删除有损的纹理位图替代。
- 原生绘制行为核对 [AOSP TextureView 源码](https://android.googlesource.com/platform/frameworks/base/+/HEAD/core/java/android/view/TextureView.java)；本轮最终效果仍以三机真实像素验证为准。未更改播放器、转场轨迹、最终图片解码和 HDR 参数。
- 新回归在真实查看器中冻结视频帧，直接对比 Window PixelCopy 与生产截图入口；随后恢复真实播放并在返回捕获发起时断言仍在播放。原有缩放场景的几何断言修正为比较屏幕内可见区域，避免把正常裁剪误报为拉伸。
- 一加原生 HDR 的 Window PixelCopy 会整体压暗，原始通道误差不能用于几何断言；使用同位置归一化亮度相关性 >0.99，并保留通道误差供诊断。失败截图的相关性约 0.13–0.15；初版三星／魅族仅 0.80–0.86，仍应失败。另以特征仿射拟合检查实际纵横缩放，不以相关性单项代替完整验收。

## 三机专项结果

- 三台设备当前均有同一真实 HDR 动态照片：三星记事 4864、一加 3226、魅族 2874，均为第 2 个附件。已有记事仅打开、缩放、播放与返回。
- 最终实现的兼容路径，原倍与 2 倍下六组冻结视频截图均与窗口同位置像素一致：平均通道误差 0、相关性 1。每次随后恢复播放，返回捕获时明确断言播放器仍在播放。
- 原生路径六组同位置相关性为 0.999776–0.999985，三机专项状态断言通过；一加原生 HDR 的亮度归一化差异单独保留，不把截图亮度当作物理 HDR 效果。
- 真实大图／HDR 完整位图的像素散列、宽高、色彩空间及 Gainmap 状态均与本轮基线一致；增益公式参数一致。PQ 纹理及其增益纹理仍按原有动态内存预算取尺寸，存在小幅波动，不能声称纹理尺寸逐项相等。本轮未修改该预算或最终解码。
- 三机最终相关实机检查 1749 项通过，覆盖真实 200MP 大图、168.7 MB 视频、GIF、动态照片、动态 WebP、快速返回／旋转／删除／裁剪等边界；48 组冻结帧及实际返回中间帧仿射检查通过，纵横缩放比为 0.999942–1.000870。
- 三星 375、一加 115、魅族 182 条原记录（合计 672）及所选真实附件散列不变。相较上次发布，用户三机各新增一条真实记事；本轮基线按当前数据建立，不误用旧的 669 条基线。
- JVM 1732 项无失败／错误，3 项既有跳过。结构化数据见 [检查摘要](checks/motion-return.json) 和 [像素几何](checks/motion-return-geometry.json)。真实图片只保留在本地诊断目录。
