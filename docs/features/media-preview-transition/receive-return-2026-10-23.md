# 接收更新入口展开后的手势返回

## 问题与验证

用户报告详情下拉展开“接收并更新记事”胶囊后，图片／视频预览的上下滑返回位置错误，返回键正常。

检查生产路径发现：手势使用打开时的详情快照，目标从后台详情重新读取；返回键则等待详情恢复后重新捕获。详情接收控制器在 `ON_STOP` 收起胶囊并复位列表。先用独立测试 APK 验证背景与实际终点的一致性，再确定修复；同时检查祖先位移和裁剪，避免只补固定偏移。

回归覆盖普通详情、下拉入口展开、接收中三种状态，图片与视频、上下滑与返回键。所有数据使用临时记事，测试前后核对原记事逐行摘要。接收中布局通过生产控制器进入后停止传输，验证不需要真实来件。

## 已确认原因

三星原发布包 `202610221516` 的专项回归：背景附件区域的像素采样差异率 100%，返回目标与恢复后的真实附件矩形完全一致。下拉列表位移为 575 px，打开查看器后控制器按既有规则复位，但手势背景仍保留胶囊和下移后的附件。坐标遗漏或重复、终点裁剪均未造成此次错位。原有 375 条记事摘要一致，临时数据已清理，证据在 `tmp/media-receive-baseline/`。

修复方向：详情在后台完成复位后预先刷新手势背景，使背景和目标取自同一状态。松手阶段仍直接进入既有弹簧，不等待截图或窗口恢复。

同机再次运行原包，背景差异率仍为 100%；对后台实际详情重新捕获的差异率为 0，确认无需修改坐标公式。修复后的本地包通过同一 7 项检查，背景一致，取消、返回目标和首帧时延均通过。

## 实现与测试入口

`MediaPreviewTransition` 在来源详情 `ON_STOP` 的整轮通知结束后比较打开时与当前的附件矩形，仅位置变化时刷新背景。`ImageViewerActivity` 在背景尚未就绪时不启动新返回手势；松手路径不增加等待。观察者及异步代次沿会话关闭清理。

独立回归：`MediaPreviewReceiveReturnProbe`。测试构建使用 `:app:assembleDebugAndroidTest -PdetailTestRunner=com.ywwynm.everythingdone.detail.MediaPreviewReceiveReturnProbe`；默认入口仍为既有附件换位回归。AGP 会统一改写测试清单里的 instrumentation 名称，故通过构建参数选择单一入口。

实机命令：`adb -s <已授权序列号> shell am instrument -w -e run <批次名> com.ywwynm.everythingdone.test/com.ywwynm.everythingdone.detail.MediaPreviewReceiveReturnProbe`。`-e quick true` 仅运行图片下拉入口的最小复现。完整专项固定详情为静态代表帧以比较像素，仅改进程内设置且最终恢复；预览仍按原规则播放。
