# 返回空区的记事背景

用户纠正上一阶段的黑色空区，并明确返回键也需修复。返回时原附件仍不显示静止媒体，但空出的区域应呈现记事的实际背景，包括渐变。

## 原因与实现

手势 Backdrop 和返回键 Presentation 均先绘制黑色，再排除固定附件矩形；此前验收还把黑色像素当作正确结果。本次已知原因明确，按 diagnose 直接建立新的像素回归，不再枚举推测性根因。

新增 MediaPreviewDetailBackground，复制实际详情根容器的 ColorDrawable／GradientDrawable，保留其尺寸与窗口位置。两种返回路径都在空区绘制它，不将渐变缩放到附件大小，也不使用平均色代替。手势原黑色遮罩仍随拖动淡出或恢复；返回键使用原页面显露进度。完整快照、真实媒体、图标渐显、取色、波纹清理、弹簧与播放规则不变。

## 本地回归

修改原像素检查后，旧实现稳定失败：空区蓝色通道应为 83，实际为 0。修复后媒体专项 42 项全部通过；覆盖八种渐变方向、根容器偏移、裁剪、来源 Drawable 不被修改、复制后相互独立，以及渐显后的透明度恢复。

## 实机验证范围

沿用三台设备授权。每台覆盖图片／视频／GIF × 普通详情／接收入口展开／接收会话后台退出边界 × 下拉／上滑／返回键。普通详情为纯色，入口展开为对角渐变，接收边界为垂直渐变。短拖取消的硬件窗口截图检查空区与背景同位置的颜色；返回键从实际转场 View 绘制中采样中途帧，允许原有渐显亮度变化，但拒绝黑色和静止媒体。返回键采样不用于判断运动时延。

实际接收会话按原设计拦截页面触摸，该组直接向附件发送 DOWN／UP 验证生命周期边界，不代表用户可点击路径或真实 NFC 来件；普通和入口展开组走完整 Activity 触摸分发。
