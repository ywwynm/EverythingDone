# 返回过程的图标、配色与触摸反馈

> 后续纠正：本文记录的 `202610230232` 黑色空区不符合用户要求；手势和返回键均已改为显示记事背景，见[返回空区的记事背景](return-background-2026-10-23.md)。下文保留当时的实现与测试记录。

用户反馈手势返回的图标出现和配色不及返回键连续；接收状态返回后还会续播旧触摸波纹。保留现有拖动和弹簧，修复详情画面的准备与叠加顺序。

上一轮 `receive-return-2026-10-23.md` 检查了附件主体和坐标，排除了工具栏区域且用 `performClick()` 打开附件，没有覆盖真实点击波纹。已存一加录屏可以观察到返回后的白色顶栏变黑，不能将此前 240 项通过视作本轮现象已验证。

按顺序验证：移动媒体覆盖固定背景中的图标；后台截图跳过顶栏取色；打开附件时的反馈在后台未结束并在恢复后续播。新增回归需要实际点击、明亮封面、GIF 标识、双向滑动与返回键对照，采样确认前、运动途中和恢复后的图标与波纹。

## 已复现的原因

在三星 SM-S9180 的原发布包 `202610221711` 上，用真实按下、抬起打开白色图片，展开接收入口后下滑返回。24 项断言中 5 项失败：后台配色、背景附件采样、全过程配色、顶栏渐显、删除图标渐显。运动进度 60%、76%、90% 时，被图片覆盖的顶栏 634 个采样点、删除图标 548 个采样点均不可见。顶栏白色在恢复详情后才变黑。

背景截图包含灰色点击波纹，附件采样区域与干净详情的差异为 99.84%；返回前真实详情已没有活动波纹。因此本次证明的是波纹被旧截图冻结并在交接时消失，不能把截图现象直接认定为真实 Drawable 重新播放。

原因分别是：固定背景被不透明移动媒体覆盖；手势末段渐显用了线性时间而返回键用缓动进度；后台顶栏取色因窗口不可见而跳过；来源停止时立即截图保留了点击反馈。

## 修复设计

来源窗口停止后统一准备手势背景：先结束该窗口内未完成的触摸反馈，按布局坐标完成顶栏取色，待异步取色稳定后同时保存背景与小尺寸详情覆盖控件。普通详情也执行准备，因为真实点击的波纹与是否展开接收入口无关。

手势运动沿用原有弹簧与惯性，只在当前移动媒体覆盖的范围内按详情原坐标补绘图标和遮罩；未被媒体遮住的部分由背景显示，避免重复加深。渐显和返回键共用末段比例，输入改为弹簧缓动进度。后台取色显式忽略窗口隐藏，仍遵守内容视图的可见性、裁剪和现有颜色判定。

## 验证范围与过程

本地新增三项原生像素／触摸回归：固定图标坐标、父层透明度与媒体覆盖裁剪；嵌套波纹清理和再次点击；整段返回中真实半透明帧与图标不随媒体移动。全套 1778 项测试无失败／错误，3 项既有跳过。

三星最小复测的图标采样已全部可见，但测试把 Float 的 `0.9` 转成 Double 后与精确 `0.9` 比较，误报末帧缺失；用采样区间容差修正断言，不修改生产逻辑。完整验证前六组（图片普通／入口展开 × 上下滑／返回键）通过。

真正进入接收会话后，`TapReceiveStageView.onTouchEvent()` 按既有设计拦截页面触摸，不能实际点击附件；用户所述的可点击路径对应下拉展开入口。回归将两者明确区分：普通和入口展开组走 Activity 完整触摸分发；接收中边界组直接向附件分发 DOWN／UP，以保留真实点击反馈并检查后台退出，不计作用户可点击路径，也不计作实际 NFC 来件测试。

图标修复阶段发布 `202610230219`，三机各 27 组／554 项通过。魅族首次冷启动在附件配色完成前采样，测试补充静态小图和附件配色就绪条件后通过；应用代码无需为此调整。

## 补充：返回期间原附件位置空出

用户随后指出，背景仍保留一份静止媒体，原位置应在拖动和返回时空出。复核返回键实现发现，其背景已使用 `clipOutRect` 排除固定媒体；手势 `Backdrop` 却绘制完整详情截图，确实不一致。

手势背景现在按当前附件身份取得后台目标矩形，在绘制时排除这一区域，与返回键使用相同的黑色空区规则；不改真实媒体的 alpha 或取色输入。完整截图仍留给动画结束后的交接。固定图标补绘范围为移动媒体与挖空区域的并集，相交部分只画一次，保持已有渐显。补充原生像素测试和三机拖动中原位置采样；全速返回仍在短拖采样完成并取消后另行测试，不被截图等待打断。

新增“原附件位置空出且没有静止媒体副本”实机检查在 `202610230219` 上失败，其余 24 项通过；修复后同样的 25 项全部通过。40 项媒体专项及全套 1779 项本地测试无失败／错误，3 项既有跳过。单元像素回归同时确认完整背景快照未被修改，挖空和移动区域重叠时图标不会被重复加深。
