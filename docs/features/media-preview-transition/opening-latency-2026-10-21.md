# 真实大图展开延迟优化

## 目标与反馈循环

- 在上一版清晰度修复基础上，进一步减少点击后开始展开的等待，不降低最终正常尺寸位图或 HDR 输出质量。
- 三台授权设备使用只读真实记事，选择最大图片、最大 SDR 图片、HDR 动态照片，分别测首次打开与再次打开。原记事逐行及样本文件 SHA-256 前后核对。
- 基线先复用真实转场探针，分开统计点击到开始展开、动画结束、正常尺寸加载、HDR 实际输出就绪；必要时补充阶段计时。报告存于 `tmp/media-latency-*`，最终摘要归档至本目录 `checks/`。
- 已知上一轮魅族首次真实 200MP 兼容路径有一次准备超时，重跑仍需约 1.78 秒；热缓存成绩不能替代该情况。

## 当前状态

兼容路径基线已复现真实 200MP 图片的等待，三机共 221 项检查通过。首次／再次点击到展开准备完成：三星 769／187 ms，一加 606／407 ms，魅族 1787／932 ms。没有降低最终正常尺寸：三星 2319×3088、一加 1983×2640、魅族 2397×3192，PQ 均使用相同尺寸。

## 待证伪假设与测量

1. 首张转场小图仍从 36 MB、200MP 原图解码。若成立，独立记录请求与资源就绪会覆盖主要等待；可复用的完整预览来源应明显缩短该阶段。
2. 小图已经就绪，但布局稳定条件迟迟不满足。若成立，资源就绪到矩阵／布局就绪之间占主要耗时。
3. 屏幕捕获主线程成本过高。若成立，来源／目标捕获阶段占主要耗时，而不是图片请求。
4. 多附件并发争用。若成立，非当前页的解码会发生在展开准备期间。

先只加入 debug 阶段计时和最终像素／HDR 参数记录，不改变生产加载流程。详情 Drawable 可能已烘焙裁剪，不能直接作为完整原图使用；另外只读检查原照片是否包含可用的内嵌完整预览。

## 定位结果

- 分阶段复测：200MP 首次小图请求分别耗时 599／505／1417 ms（三星／一加／魅族），资源到达后布局约 9—31 ms；所有旁页请求均在动画结束后启动。主要原因是重复解码大原图，排除旁页竞争及布局作为主要原因。
- 三机的「点击到展开不超过 500 ms」性能断言在旧路径失败（共 4 次，含魅族再次打开），其余清晰度及数据保护检查通过。
- 同一 200MP 原图带 240×320 内嵌预览，HDR 动态照片带 320×240 预览；一加只读提取约 4 ms。SDR 对照无内嵌预览，保留原加载路径。
- 第一个变更仅替换展开小图来源：后台读取并验证 JPEG 内嵌预览，检查尺寸与原图比例、处理 EXIF 旋转／镜像；无合格预览则回退原小图请求。高清请求、HDR 准备门槛、内存预算、数值公式均保持。

## 第一轮结果与下一步

- 200MP 首次点击到展开降至 339／137／566 ms；三机真实样本的最终位图尺寸、色彩空间、Gainmap 标记及像素 SHA-256 均与各自旧兼容路径一致，HDR 增益参数一致。
- 魅族首次仍未达到 500 ms 测试目标，其中 Activity 创建到小图请求约 149 ms、小图请求到主线程接收约 151 ms。第二步只提前读取轻量内嵌图，使其与来源截图及窗口创建重叠；不提前解码大原图，也不修改正常尺寸加载时机。

第二轮三机首次／再次展开为 322／185、164／174、425／200 ms，14 次真实图打开均低于 500 ms，235 项检查通过。内嵌图均在窗口初始化使用时立即可用，未重新解码 200MP 小图。继续进行普通 HDR 路径、完整增益恢复、方向／回退／迟到回调，以及真实视频和 GIF 的回归。

## 回归进展

- 三机各 200 项内嵌预览接缝回归通过：EXIF 全部 8 种方向、裁剪比例不匹配、过小和缺失预览、超时后迟到小图不覆盖已就绪高清。各 88 项边界、20 项超时、121 项清晰度与动态照片播放结束回归也通过。
- 三机真实图完整增益与合成截图检查通过，200MP 最终位图仍与旧版像素散列一致，HDR 增益最终达到 1；一加真实 HDR 动态照片播放结束也恢复完整增益。
- 扩大到全部真实附件时，测试时间轴新增图片回调与保存报告发生并发访问，一加普通路径、魅族兼容路径各中断一轮。异常位于 debug 探针 `JSONArray` 序列化，不是应用图片加载；改为主线程串行收集／快照后重跑这两个场景。原始失败报告保留。
- JVM 1732 项无失败／错误，3 项既有跳过。

## 最终验收

- 修正测试时间轴后，两项中断场景完整重跑通过。选定有效报告共 **2582 项**检查通过，摘要见 [checks/opening-latency.json](checks/opening-latency.json)。原有 **669 条**记事逐行 SHA-256 及各轮真实附件文件散列不变。
- 同一计时探针、同一真实 200MP 图片，兼容路径首次／再次点击到开始展开：三星 **797／188 → 322／185 ms**，一加 **607／183 → 164／174 ms**，魅族 **1731／1125 → 425／200 ms**。不含后续 360 ms 动画；没有清空用户磁盘缓存，不将其称为存储冷态成绩。
- 兼容路径大图、SDR 对照、HDR 动态照片的最终位图尺寸、色彩空间、Gainmap 标记和像素 SHA-256 与修改前一致；HDR 数值参数一致。200MP 的实际 PQ 纹理尺寸也一致。动态照片继续遵守原有动态内存预算，并验证播放结束后增益回到 1。
- 普通显示路径的三机真实 200MP 最终位图散列、尺寸和 Gainmap 同样与旧路径一致；完整 HDR 状态检查通过。普通／兼容两条路径均覆盖真实 4K 大视频、GIF、动态照片和多附件记事，返回顶栏／资源连续性检查通过。
- 合成截图复核打开／返回构图和最终清晰画面；截图不能量化物理 HDR 高光，卓易通宿主仍未直接连接。本次优化主要消除带合格内嵌预览大照片的重复解码，不修改 HDR 着色器、采样及内存预算。
