# 详情附件自适应配色实施与验证

状态：已实现，三台授权设备的最终合并验证全部通过，已发布阿里云 debug `202610101718` 并在三机安装；用户已确认将代码、测试和相关文档一并提交。

## 实现

- `MediaOverlayContrast` 独立计算 sRGB 相对亮度、透明合成、参考对比度覆盖比例与几何平均值；主体计算通过 6 项 JVM 回归，附件现有 Glide 生命周期 5 项回归通过。
- `DetailMediaOverlayColors` 接入真实附件 Adapter。与显示请求并行取得最长边 256 的静态封面，缩放、裁剪与解码由 Glide 后台执行；已显示静态资源先就绪时，用原生缩放复制一个同尺寸小副本并取消重复请求。原生动图使用静态首帧，视频使用所选封面，动态照片使用原始静态主图。
- 每个图形最多 256 个有效样点，HDR／GIF 使用镂空字形和近邻填充成对取样；实际描绘的图形参与判断，点击区域留白不参与。
- 主线程只一次复制小图像素并准备图形遮罩，点集整理、评分和图标黑白位图准备在单工作线程执行；回到主线程前校验绑定身份、布局签名和请求代次。队列中的旧任务取消并移除，不会在快速滚动时积压过期工作。
- 静态小图缓存上限 4 MiB，图形点集缓存 64 项，最终颜色缓存 256 项。缓存命中直接设置颜色，播放帧变化不触发计算。
- 图标黑白位图缓存 16 项；位图保留原始密度、尺寸及 alpha。主线程原生小图复制结束后不继续持有 Glide 原位图，避免后台读取已回收或已用于其它附件的资源。
- `KnockoutTextBadge` 增加黑白底色切换，保留原透明度与 CLEAR 镂空；图标仅改变颜色，不改变路径、尺寸、层内透明度或记事色波纹。

## 首次验证与修正

- 首台平板验证确认纯白、纯黑、左右分区，以及播放期间稳定和缓存重开均符合预期。
- 初次测试入口将生成的 `white.png`、`split.png` 与全屏截图保存为同名文件，截图覆盖了测试媒体，导致后续裁剪、多附件样本失败。修正为原始测试图片独立保存在 `media/`；保留失败结果，不计为最终验证通过。
- 初始实现把完整点集整理与评分放在主线程，首批多个标记约 29.8 ms，随后约 9–15 ms；按用户对速度的要求改为后台计算，主线程只准备小图形并应用颜色。旧数据中的媒体就绪后耗时还包含人为追加测试标记的等待，现改为记录同一绑定首次完成的延迟。
- 首轮已有记事整行指纹均保持一致；测试过程中没有修改这些记事的内容、外观或附件。
- 三台首轮中，平板横竖屏全部通过。手机的远距离重开缓存断言受正常 LRU 淘汰影响，改为立即重开验证，不为测试扩大生产缓存。
- 魅族开启强制深色时，会改写离屏 Canvas 的画笔和颜色滤镜；取回测试原图确认黑白素材均被生成成 `#2e2e2e`。测试素材改用像素写入；生产图标和 HDR／GIF 标记也直接写入黑白 RGB，沿用原 alpha 与镂空，避免系统再次改变所选颜色。
- 静态取样从 Canvas 缩图改为逐行读像素，避免首次软件绘制开销与强制深色干预；字形近邻搜索移除逐点临时序列和 Pair 分配。
- 修正后，三台设备横竖屏的正确性断言均通过，但冷启动逐行取样在魅族最坏仍达到 217 ms，不能满足速度要求。进一步改为与显示请求并行的 Glide 小尺寸静态封面请求，解码、裁剪在后台；主线程仅一次复制至多 256×256 像素，不逐行访问完整显示位图。图标黑白位图的像素着色也移入后台评分任务。
- 小尺寸请求的首批三机数据中，主线程像素复制约 0.1–0.4 ms，透明图片断言通过。扩展撤销测试误把 `Menu.performIdentifierAction()` 返回值当成成功标志；该 Activity 执行动作后仍返回父类结果，改为等待实际外观身份与配色变化，未改动生产菜单行为。
- 扩展验证的 238 个断言全部通过，但已有大图／视频封面在小图首次解码时仍有 0.5–0.7 秒等待。增加已显示静态位图先就绪时的快速取样路径：原生缩放到小位图后一次复制，透明像素检查仍放在后台；取消对应重复解码请求。小尺寸独立请求提高优先级，始终不取派生动画当前帧。

## 验证入口

`run-overlay-probe.ps1` 仅允许本轮明确授权的三台设备，默认覆盖横竖屏，运行后恢复原系统旋转。

- 合成白、黑、明暗分区与复杂纹理；多个标记、裁剪/比例变化、附件重排、滚动复用。
- GIF 与视频的播放期稳定、静态和动态资源的缓存重开。
- 竖屏查看多个已有记事；前后比较整行 SHA-256，输出仅记录 ID、图标颜色和耗时，不输出正文或附件路径。
- 临时记事使用独立创建时间标记，结束只删除本次创建且标记匹配的行。

### 性能读数的含义

主线程列为一次小图复制耗时与记录到的图形准备／设置耗时之和，不是整屏渲染耗时。所有记录的合计中位数 **0.419 ms**，P95 **1.861 ms**，最大 **5.162 ms**；不透明图片缓存重开从绑定到颜色就绪 **2–10 ms**。

从媒体就绪到首次配色完成的记录中位数 **3 ms**，P95 **98 ms**，最大 **126 ms**；可能包含静态封面准备、队列及布局等待。整张媒体的首次解码、视频取帧和页面进入时间另计，不能据此承诺所有媒体首次打开都在数毫秒内完成。已有媒体的磁盘缓存保留，未通过清空用户缓存来制造冷启动；新建合成媒体使用每轮独立路径。

本轮保留旧照片默认展示、已保存的外观与原图文件，不增加数据库字段、用户开关或逐帧监测任务。
