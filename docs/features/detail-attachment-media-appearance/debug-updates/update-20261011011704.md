## 2026-10-11：详情附件标记和按钮自动选择半透明黑白

用户反馈图片、视频附件上的 HDR、GIF、动态照片、空间效果标记，以及外观和删除图标，在浅色内容上难以辨认。经讨论确定逐个元素按局部背景独立配色，只依据静态封面，播放期间固定；保留原透明度和镂空样式，不增加描边、阴影或衬底。用户特别要求保证配色速度，并授权三台设备覆盖多个已有记事。

`MediaOverlayContrast` 分别计算半透明黑白合成后的相对亮度对比度，优先比较达到参考值的加权覆盖比例，再比较加权几何平均值，相同则选白。`DetailMediaOverlayColors` 与 `ImageAttachmentAdapter` 按封面、裁剪和实际布局维护有界缓存；小封面在后台准备，显示静态位图先就绪时直接取小副本，取消重复解码。点集整理、评分和图标着色在后台执行，滚动复用、异步标记、裁剪、比例、撤销／重做及视频选帧均更新相应结果。

魅族强制深色会改写画笔和颜色滤镜，因此图标与 `KnockoutTextBadge` 使用保持原 alpha 的黑白位图；HDR／GIF 文字继续镂空。测试过程中修正了测试图片被截图覆盖、缓存淘汰断言和菜单返回值断言，失败的中间结果不作为最终验证通过。

最终三台授权设备横竖屏共 238 个检查项全部通过，覆盖 19 条已有记事，所有已有记事整行指纹未变化；最终测试创建的 42 条临时记事已清理，系统旋转已恢复。6 项配色及 5 项原附件生命周期 JVM 回归通过。主线程取样与颜色应用记录合计中位数 0.419 ms、P95 1.861 ms、最大 5.162 ms，不透明图片缓存重开的颜色就绪时间 2–10 ms；首次媒体解码和视频取帧另计，测试保留已有磁盘缓存。

详细实现、计时口径和原始验证结果见 `docs/features/detail-attachment-media-appearance/implementation-overlay-contrast-2026-10-11.md`。本轮不新增数据库字段或用户设置，未创建 Git 提交。
