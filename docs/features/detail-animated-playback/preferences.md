# 详情动态内容播放的验收要求

## 2026-10-20

- 用户要求进一步核查按 holder 独立解码对内存、大 GIF 播放和滚动性能的代价，不能只凭崩溃回归通过就认定没有性能影响。
- 本轮明确授权使用 OPPO `3B1629006YC00000`、三星 `R5CW20BLNKL`、魅族 `192.168.100.67:40807` 测试，必须覆盖真实首页，且不得影响现有记事。
- 测试使用独立包和隔离记事；原应用数据只作只读校验，禁止改写原有内容、覆盖安装测试包或清空原应用数据。

## 2026-10-15

- 用户反馈默认同时循环播放下，视频、动态照片派生 GIF 在循环结束或滑动回来重新加载时可能闪烁，表现接近短暂露出记事底色。
- 已授权本轮在 OPPO `3B1629006YC00000`、三星 `R5CW20BLNKL`、魅族 `192.168.100.67:40807` 复现并修复。采用隔离包，保留原应用数据。
- 同时核对首页近期提交是否已经包含相似修复；要区分首页和详情的独立加载路径，不把首页修复当作详情已经覆盖的证据。
- 首轮修复后用户补充更容易触发的步骤：设置「在记事详情界面中自动播放动态内容」为「逐一播放」，打开键盘后再滑动。用户怀疑统一 RecyclerView 改造影响了「逐一播放」语义，须同时复核可见性、队列与资源交接。
- 用户观察复现操作后强调必须快速滑动，慢速拖动不足以代表该故障。回归须包含键盘保持打开时连续快速甩动、惯性未停止时反向甩动。
- 用户进一步要求覆盖复杂记事页面，尤其是生成的 GIF 较大的情况。不能只用低细节、小文件夹具作通过依据；须加入多份较大派生 GIF、混排和长内容。
- 用户再次确认是否真正复现「循环结束露出记事底色」，要求重点测试多个大 GIF 混排。须单独报告这一症状，不能以滚动重载、静动交接或内存失败的复现代替；补充实际窗口像素与真实循环边界的对齐检查。
