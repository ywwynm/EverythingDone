## 详情大 GIF 混排与跨播放模式返回露底修复（2026-10-15）

用户再次要求确认循环结束时是否真的露出记事底色，并重点测试多个大 GIF 混排。本轮在三台指定设备使用 12 个动态附件，包含实际编码的约 32–35 MB 派生 GIF、约 10–16 MB 的已有 GIF 独立副本；静态图穿插其间，另有长正文。增加实际应用窗口 PixelCopy 采样，对齐 GIF 帧回绕及逐一播放完成，同时补测通栏首图、真实键盘和快速甩动。

四组检查累计观察 1497 次持续循环回绕、66584 次循环窗口采样，仍未独立复现持续循环交界露底，不能将其他加载问题当作这项症状已经解决。窗口采样不保证覆盖每次物理刷新，具体媒体及未采中的极短问题仍保留为未复现范围。

补测确实发现此前遗漏的露底：已经循环显示的附件离屏后切到逐一播放，打开键盘快速返回，OPPO／三星／魅族分别捕获 29／42／71 条空白，实际窗口也显示底色。尺寸、裁切没有变化，原因是先前的动态占位按完整 play 请求缓存，而返回时请求 static 资源，无法借用已经显示过的帧。

ImageAttachmentAdapter 将占位身份与 Glide 解码身份分离：按原附件文件版本、目标尺寸、裁切及视频选帧关联占位，保留静态和动态两类独立帧，优先匹配当前类别，缺失时用另一类帧暂时填充。实际解码请求继续按静动资源严格区分，最终仍切回正确静态代表帧；缓存预算、独立位图生命周期与标准 Glide 回收不变。

三机同条件对照，以及清空隔离包 Glide 磁盘缓存后的完整复测均通过：快速返回、后续甩动和逐一完成均无控件空白或成片窗口露底。每机每轮 74 次 IME 快速动作，冷缓存轮触摸中位数约 77／84／82.5ms；无 OOM、致命异常或已回收资源异常，原应用数据库及偏好校验均不变。225 个 JVM suite、1507 项测试无失败和错误，1 项既有跳过。
