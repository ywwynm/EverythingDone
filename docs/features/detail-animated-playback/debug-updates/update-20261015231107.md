## 详情逐一播放、键盘快速滑动与大 GIF 修复（2026-10-15）

用户在首轮闪烁修复后补充：选择「逐一播放」，打开键盘后快速滑动更容易露出记事底色；要求使用连续快速甩动，并覆盖派生 GIF 较大的复杂页面。核对统一 RecyclerView 改造与既有播放定义，保留「当前可见附件按索引各播一轮，离开后返回可重播」的语义。

三台指定设备均复现静态待播图回收后的空白。复杂页面包含 12 个动态附件、17 张静态图、80 段正文和首项通栏；实际生成的视频／动态照片 GIF 约 32–35 MB，另有三份真实派生 GIF 的九个独立路径副本（约 10–16 MB）。修复前复杂网格出现数百条空白记录，键盘快速甩动也能触发。

ImageAttachmentAdapter 现在同时为静态代表帧与 GIF 保存独立占位副本，单张持久占位最多 65,536 像素，总预算仍为 8 MiB 与最大堆 1/32 的较小值，保留标准 Glide 清理及完整请求身份。DetailAttachmentPlaybackController 先整体更新可见集合、清除全部离屏候选，再按索引推进一次队列，避免批量回收期间短暂启动已经离屏的项。

进一步测试默认同时循环发现，大 GIF 的 String 加载路径会在 Java 堆中扩容读取并复制整文件，导致内存分配失败；这也说明仅检查无空白不足以验收。现将本地动态请求改为 File，使用 Glide 的只读文件映射，保留静态和非文件来源的原加载方式，没有提高堆上限或减少播放并发。测试同时检查实际映射路径、OOM、致命异常和已回收资源异常。

最终三机普通／复杂页面的逐一快速滑动共 54,885 条绘制记录无空白、无误并发，复杂通栏占 40,472 条；每台复杂页面执行 130 个快速动作，单次触摸中位数约 75–85ms，包含惯性中反向及真实 IME。大文件默认循环及模式、前后台、回收、热缓存、重排检查共 64,331 条绘制记录通过对应断言，循环按实际至少两次回绕验收；运行日志无 OOM 或生命周期异常，原应用数据库与设置校验均未变化。JVM 1507 项测试无失败／错误，1 项既有跳过。

首页此前的 45bc4cd5b、10f009c3d 确实处理过类似封面交接问题，但未覆盖详情独立路径。本轮更新 ADR-0017 与领域文档，纠正旧全量布局前提。仍未独立捕获用户最初描述的所有循环结束闪烁，不声称覆盖任意媒体、首次解码或所有缓存淘汰情形。完整证据见 docs/features/detail-animated-playback/sequential-ime-investigation-2026-10-15.md 及 checks/sequential-results-2026-10-15.json。发布使用正常包名，不包含私有测试媒体或探针入口。
