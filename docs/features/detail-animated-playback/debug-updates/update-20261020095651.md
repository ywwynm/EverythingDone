## 修复 GIF 从首帧重播时偶发崩溃

用户在首页看到一次崩溃，提供 OPPO PMA110 的 crash_20261020091302.log。调用栈来自详情附件逐一播放的延迟调度，异常为 Can't restart a running animation；日志无法单独确定当时的页面切换顺序。

使用真实 Glide 4.16.0 的本地 JVM 测试复现：同一 GIF 的两个请求会拿到不同 GifDrawable，却共享底层 GifFrameLoader。一个位置仍在播放时，另一个对象即使 isRunning 为 false，也无法从首帧重启。原有单对象检查没有覆盖这个共享状态，仅调用 stop 也不能解决。

ImageAttachmentAdapter 现在为逐一、同时一次和手动一次的动态请求使用 DetailGifPlaybackOwner，以稳定的 holder 所有者身份隔离活动资源、内存缓存与并发加载。该身份不引用界面对象，也不改变磁盘缓存签名；默认同时循环及静态资源仍复用原有缓存。加载标记区分独立与共享播放，模式切换不会继续沿用不适合重播的资源。保留首帧重播、标准 Glide.clear 与有界过渡占位，没有通过吞掉异常规避崩溃。

6 项真实 Glide 回归和原有 5 项生命周期检查通过，覆盖共享异常对照、独立重播、并发请求、缓存复用与磁盘身份；全量 1692 项测试无失败或错误，3 项跳过。Robolectric 仅为测试依赖，不进入 APK。本轮未连接设备，真机页面切换、模式切换及滚动体验由用户更新后确认。未创建 Git 提交。
