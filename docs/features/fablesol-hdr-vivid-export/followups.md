# FableSol HDR Vivid 视频导出遗留项

- UWA 编码侧参考代码和 FFmpeg 编码转码工具需要按联盟流程申请；自行实现完成后，仍需决定
  是否申请参考代码进行交叉验证。
- UWA 技术支持页在 2026-06-11 记录的 HDR Vivid `ffprobe` 提取工具与编码转码／校验工具
  最新版本为 v1.1.3。首个真机导出样本已经由 FFmpeg 等价解析器完成 471／471 帧全量核对；
  后续若能取得 UWA 工具，再将其作为官方实现的交叉验证，而不是阻塞当前结构验收。
- 公开产品中使用 HDR Vivid 名称或认证标识前，需要确认 UWA 商标与认证流程。
- HDR 自动顺序中的位置必须等待至少一台 HDR Vivid 终端和一台 HDR10 回退终端完成验证。
- OPPO PLZ110 真机样本已用 400 nit 参考显示峰值验证非平凡 Base Curve，并在 7.108 秒
  成片中得到 2 组稳定载荷与 29 帧平滑过渡。后续仍需使用超过 10 秒、安静／强烈／安静
  分段明显的录音，重点验证由内容变化触发的硬场景边界；当前样本的边界来自默认 5 秒软
  分段上限。
- 当前完整曲线样本的 HEVC 流没有 B 帧；按 PTS 关联已由 JVM 回归覆盖，但仍可在实际支持
  B 帧的编码器上补一份乱序输出样本证据。
- 获得 HDR Vivid 终端后，需分别检查硬场景切换、连续亮度变化和高亮密集内容，确认接收端
  没有参数闪烁、异常提亮或过曝。
- T/UWA 005.2-1-2026 还定义了 AVC/H.264、VVC/H.266、AVS2 与 AVS3 的 ES 承载。当前
  Android 产品只实现并验证 HEVC Main10；以后只有在 Android 设备实际暴露相应的 10-bit
  编码输入、能够逐帧注入标准元数据并完成 MP4／播放端验证时，才评估新增承载。AV1 不在该版
  系统集成标准的承载清单中，不能用来绕过三星 Z Fold4 的 HEVC 10-bit 输入缺失。
