# 多级清单项 debug 发布日志

## 2026-06-26 代码审查修复：四处残留的旧格式假设

外部代码审查发现四处在“状态位+层级位+文本”新格式迁移后未更新的旧格式假设，均已核实并修复：

1. **SIMPLE_FCLI 汇总行格式错（首页卡片折叠的“已完成 N 项”行）**：原用 `"1" + 文本` 构造（旧的
   状态位+文本），新格式渲染时 `textOf` 的 `substring(2)` 会吃掉文本首字符，且首字符若是 1/2/3 还会被
   误当层级。改为 `"11" + 文本`（状态位 '1' + 层级位 '1' + 文本）。

2. **详情页“N 项已完成”头部统计范围错**：原统计整列表所有状态位 '1' 的项，会把顶部就地完成的
   二/三级项也算进去。改为只统计 '4' 头部之后（底部已完成区）的已完成项。

3. **截图前后恢复清单控制行错位**：原用“最后一个未完成项之后”定位插回“添加行/分隔线”，新模型顶部
   可能出现“未完成父项 + 就地完成的已完成子项”，会把控制行插到父项与已完成子项之间、错位已完成分界。
   改为用分隔标记 "3"/"4" 定位（与截图前的移除逻辑对称）。

4. **空文本转清单不自动聚焦首项**：原判断 `items[0] == "0"`（旧空项格式），新空项是 "01"。改用
   `isEmptyItem` 判断，恢复空清单自动聚焦首项、弹键盘的体验。

重点测：首页卡片折叠的“已完成 N 项”文字是否完整；详情页已完成头部计数是否只数底部已完成区；含
“顶部未完成父 + 已完成子”的记事截图后分界是否正确；空文本切到清单是否自动聚焦首项。
