# 应用内碰一碰 · 真机可行性验证方案

2026-09-21 定。验证对象是二期「双方都打开完事儿，碰一下直接传」的技术形态：
**NFC 握手 + Wi-Fi Direct 传数据**。

## 前提

- **两台都必须有 NFC**。平板通常没有，`OPD2515` 与华为 MatePad Pro 13.2 多半不行；
  能凑成一对的应是三星 SM-S9180 加魅族 20 Infinity（待确认）。
- **碰的那一下由用户本人完成**，adb 做不出这个动作。
- **结果必须在屏幕上直接可读**。不靠 logcat：魅族 20 Infinity 的 main 缓冲只有
  256 KiB，一轮跑完早被冲掉；也不依赖 adb pull。所有耗时与结论直接显示在界面上，
  用户截图即可。
- `NEARBY_WIFI_DEVICES` 是运行时权限，APK 需主动请求。**不代为 `pm grant`**。

## 程序形态

独立最小 APK，独立包名（不能是 `com.ywwynm.everythingdone`，否则与已装的完事儿
冲突），代码在 `probe/`。界面只有两个按钮：**当发送端** / **当接收端**，
加一块结果区。验完卸载。

发送端跑卡模拟并提前 `createGroup()`，把 Wi-Fi Direct 的 SSID、密码与一次性令牌
写进握手内容；接收端 `enableReaderMode`，读到后当普通 Wi-Fi 客户端直接连上去，
跳过 Wi-Fi Direct 的发现与 Group Owner 协商。

## 分段计时

每次都要分开记，出问题时才分得清是哪一层：

| 段 | 含义 |
|---|---|
| T1 | 贴上到 NFC 握手完成 |
| T2 | 握手完成到 Wi-Fi 连上 |
| T3 | 连上到文件传完 |

## 验证项

### 1. 握手容量

一个 APDU 来回实际能装多少字节。标准 APDU 数据段上限 255，扩展 APDU 到 65535 但
并非所有设备支持。SSID + 密码 + 令牌装不下就要做分段，协议形态随之改变。
**这是要先量的第一个数。**

### 2. 能不能碰上

一端读取、一端卡模拟，能否 SELECT 到我们的 AID 并完成一次数据交换。

### 3. 会不会被抢占

One UI 与 Flyme 的默认钱包应用会不会把这次触碰抢走。两台的表现可能不同，
分别记录。

### 4. 天线位置

碰上要试多久、要不要挪位置。系统碰一碰有厂商标定的提示动画，我们没有——
这一项决定界面上要不要给找天线的引导，以及引导能不能通用。

### 5. 读取模式的副作用

接收端开着读取模式时，本机公交卡、门禁是不是真的停了。这条决定「准备接收」
状态能开多久、要不要做自动退出。

### 6. 反向角色

A 发 B 收与 B 发 A 收都要试。两个 ROM 的表现可能不对称。

### 7. 建连与传输

三档文件：1 MB、10 MB、100 MB。附件不设体积上限，大文件的表现必须知道。
每档记 T2 与 T3。

## 否决线

**T1 + T2 超过 10 秒，或 10 次里成功少于 7 次——这条路直接否掉。**

在否决线之上的数据出来后再讨论体验可不可接受，不预先对标系统碰一碰的
「3 秒内、10 次 9 成」：系统那套有厂商天线标定与底层优先级，第三方应用大概率
追不上，拿它当门槛可能误杀一个其实能用的方案。

## 怎么跑

### 编译与安装

```
gradlew.bat :nfcprobe:assembleDebug
```

产物在 `probe/build/outputs/apk/debug/nfcprobe-debug.apk`，约 2.5 MB。
**两台都要装**，包名 `com.ywwynm.nfcprobe`，与完事儿互不影响。

首次运行会申请一个权限：Android 13 及以上是「附近的设备」，12 及以下是位置权限。
授予之后**再点一次**刚才那个按钮（申请是异步的，第一次点只会弹框）。

### 第一轮：量握手容量（验证项 1）

1. 甲机点「当发送端」，等日志出现 `已就绪`
2. 乙机点「**测握手容量**」
3. 两台背面贴上

乙机会从 128 B 开始阶梯试到 60000 B，最后打印 `单次 R-APDU 上限 ≈ N B`。
把这个数与日志里的 `握手内容 xxx B` 比一比——装得下就不用分段。

容量测试同样需要甲机处于发送端就绪状态，前台门控会挡住未就绪时的 SELECT。

### 之后每一轮：真实流程（验证项 2、3、4、6、7）

1. 甲机点「大小」切到要测的档位（1 / 10 / 100 MB），再点「当发送端」
2. 乙机点「当接收端」
3. 两台背面贴上，等日志跑完

乙机日志里会依次出现 T1、T2、T3 与合计耗时。每轮结束后乙机自动离组，可以直接碰下一轮。
角色对调再跑一轮（验证项 6）。

### 验证项 5 单独做

乙机点「当接收端」后，**在读取模式开着的时候**拿它去刷公交或门禁。刷不了就说明
读取模式确实独占了 NFC——这决定「准备接收」状态能开多久。验完点「停止」。

### 注意

- 验证期间**应用必须在前台、屏幕保持常亮**。读取模式绑定在前台 Activity 上，
  切后台或熄屏就会关闭，再贴也不会有反应。
- 两台的 NFC 都要在系统设置里开着。
- 三星与魅族的 NFC 天线一般在背面上部靠近摄像头处，贴的时候从那一带开始找。
- 「复制」按钮会把整份日志复制到剪贴板，方便直接发出来。
- 验完在两台上卸载 `NFC Probe` 即可，不会留下任何东西。
