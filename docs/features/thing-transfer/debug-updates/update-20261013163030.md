## 补充卓易通传输状态诊断，成功后也能从设置复制日志

用户提供首版诊断：Android 发给卓易通时，NFC 握手成功，但卓易通的 Wi-Fi Direct 入组请求在约 6 毫秒内返回 ERROR。反向由卓易通发送时，既有文件已收到但发送端等待完成确认超时，也有完整收到 ACK 并显示成功的记录。本轮分别追踪这两类问题，尚未认定卓易通内部失败原因。

- 设置页新增「碰一碰传输诊断」，位于「碰一碰模拟」下方；成功、失败、退出收发后都可查看和复制，不必重新进入接收。升级保留最近三次历史会话，打开诊断不会新增收发记录。
- 新增 `TapP2pDiagnostics`，在收发通道初始化、组就绪、接收方入组前和被拒绝后，读取服务、发现、网络、本机、连接和当前组状态；分别记录查询编号、耗时、异常及暂未收到回调的情况。
- `TapDiagnostics` 补充目标 SDK、权限实际声明和只读权限执行状态。配置仅记录长度、地址类别和频段；继续隐藏网络凭据、MAC 和私人路径，不记录记事内容。
- TCP 日志区分接收方写出 ACK、发送方读到 ACK、关闭连接及离组顺序，便于定位“收到记事却提示发送失败”。诊断查询异常与实际传输失败分别记录。

本次不调整传输协议、位置权限申请或连接策略。`:app:assembleDebug` 和 34 项诊断／协议 JVM 测试通过；设置布局资源及修改空白检查通过。未使用 ADB，尚未验证卓易通实机的新诊断结果。

升级后可先从 Android 端「设置 → 碰一碰传输诊断 → 复制全部」提供现存接收记录；再用 Android 发送、卓易通接收试一次，双方都从该入口复制完整报告。
