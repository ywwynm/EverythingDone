## 补齐卓易通偶发 TCP 连接失败的诊断

用户反馈接收建组方案仍有偶发失败。对照双方 v5 日志：20:27 的 NFC 和组网方向协商成功，但 OPPO 连接卓易通的 TCP 端口连续被拒绝，最终双方连接超时；没有进入文件或 ACK 阶段。另一次约 173 MB 接收完整成功。发送端重复堆栈挤掉了较早 163 条事件，现有证据不足以判定兼容层端口映射、路由变化或提前关闭中的哪项是根因。

- 诊断升级为 v6。`TapDiagnosticBuffer` 独立保留关键组网阶段和第一次连接异常；`TapConnectRetryLog` 将后续重复异常改为每五秒及结束时汇总，记录失败次数、耗时、源地址和底层错误，避免再次覆盖最初证据。
- `TapReceiverServer` 与 `TapReceiverGroupHost` 增加监听地址、开放状态、accept 次数、原始 TCP 到达和关闭原因。在监听就绪、NFC 完成、等待八秒、超时关闭前记录状态。
- `TapP2pDiagnostics` 补充组接口和本地 IPv4；发送方入组完成及第一次连接失败时查询网络状态。查询不参与传输决策，不记录凭据或记事内容。
- 修正超时主动关闭监听后仍被标为“未取消的传输中断”的诊断；结束后的迟到连接错误不再覆盖首因。设备识别、组网方向、Socket 绑定、连接期限和文件协议保持原有逻辑。

本地 109 项碰一碰 JVM 测试及完整 debug 构建通过。先通过 140 次重复异常的回放测试复现关键日志丢失，再验证修复；另验证日志容量与脱敏、错误变化、原始 TCP 到达和关闭记录。未使用 ADB 或连接实体设备，不能据此宣称偶发连接失败已修复。

两台都更新后照常使用。若再次失败，请从“设置 → 数据 → 碰一碰传输诊断 → 分享文件”导出双方 v6 文本，尽量在连续多次重试之前保存，以便配对同一次传输。
