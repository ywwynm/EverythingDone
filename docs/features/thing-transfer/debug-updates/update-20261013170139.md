## 增加卓易通接收的普通 Wi-Fi 兼容试验

用户更新 v2 诊断后，卓易通接收仍失败。新报告显示 P2P 服务已启用、附近设备权限及执行状态正常、没有残留组、所有状态查询均有回调，但 connect 在 18 毫秒内返回 ERROR；OPPO 发送组正常建在 5180 MHz，随后等待接收 TCP 超时。因此本轮改变接收端连接方法进行对照，不再只增加同类状态日志，也不宣称已确定卓易通内部原因。

- 仅调试版：P2P 入组明确返回 ERROR 后，使用 `WifiNetworkSpecifier` 按同一 NFC 握手中的组名和密码申请普通 Wi-Fi 连接。系统可能弹出连接确认，需要在原有连接时限内确认。
- 发送端读取实际组主 IPv4，通过兼容旧版的可选握手字段提供；没有合法地址时仍使用原有 P2P 流程，不猜测固定网关。要验证新路径，两台都需要更新。
- 接收 TCP 的 Socket 绑定系统返回的网络，不改变应用全局路由。`TapJoinAttempt` 阻止迟到 P2P 回调重复下载或重新激活已取消的尝试；失败、退出和完成时释放普通 Wi-Fi 请求。
- 兼容接收写出 ACK 后，等待发送端 TCP 关闭或最多 2 秒再释放网络申请。日志记录请求、系统回调、绑定网络、TCP 与结束阶段；此前反向传输偶发的 ACK 超时仍待独立证据，不作为本轮已修复项。

本地完整 debug 构建和 44 项相关 JVM 测试通过，其中新增 10 项覆盖可选地址、新旧握手布局、异常输入、迟到／重复回调和回环 TCP 结束顺序。修改空白检查及合并清单权限检查通过。没有使用 ADB，也未进行卓易通实机验证。

请两台更新后再试 Android 发送、卓易通接收；如出现系统 Wi-Fi 连接提示，请允许。无论成功还是失败，都从「设置 → 数据 → 碰一碰传输诊断 → 复制全部」提供双方新记录。报告版本为 v3。
