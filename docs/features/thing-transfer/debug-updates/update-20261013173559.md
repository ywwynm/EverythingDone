## 为系统连接确认预留时间，支持直接分享传输诊断

用户提供双方 v3 日志：卓易通 P2P 入组仍以 17 毫秒返回 ERROR，普通 Wi-Fi 请求启动后，在原有 22 秒期限内未取得可用网络；Android 发送组一直正常，最终等 TCP 超时。用户随后确认，在「要与完事儿搭配使用的设备」系统对话框中等待 Android 手机出现、允许连接后能够接收。因此保留已经得到实测反馈的兼容方式，改善系统选择和人工确认所需的等待时间；原 P2P 内部拒绝原因仍未确定。

- 调试版发送端在具备兼容地址时，通过 `TapHandshake` 的可选 `WFWT` 尾部声明从 HELLO 起等待 60 秒。`TapJoinAttempt` 只在切换普通 Wi-Fi 后，将接收期限延长到本次碰触后的 57 秒；普通 P2P 接收仍为 22 秒。旧握手不含期限时仍按原 25／22 秒处理，两台更新才能使用新的确认时间。
- 首页和详情接收增加「请在系统提示中选择发送设备并允许连接」，确认期间不会被动画进度文字覆盖，网络就绪后恢复传输提示。补充网络请求返回、网络就绪耗时、释放前是否可用等记录；诊断报告升级为 v4。
- 诊断窗口新增「分享文件」。`TapDiagnosticsSharer` 将完整脱敏报告快照写成 UTF-8 `.txt`，通过系统分享面板由用户选择去向；不再需要为了发送长日志创建记事。保留「复制全部」及成功后的设置入口，缓存文件在七天后于下次导出时清理。

本地完整 debug 构建、48 项相关 JVM 测试及修改空白／布局资源检查通过。新增 4 项测试覆盖握手旧字节兼容、损坏／越界期限、系统确认超过旧期限、旧发送端限制与取消／重复回调不能续期。没有使用 ADB，没有创建 Git 提交；本轮新增提示、分享入口及较长期限仍需实际使用验证，不把用户反馈的接通等同于已核验双方 ACK。

两台更新后按正常流程碰触；如出现系统连接窗口，选择发送设备并允许连接。以后从「设置 → 数据 → 碰一碰传输诊断 → 分享文件」即可提供双方完整记录。
