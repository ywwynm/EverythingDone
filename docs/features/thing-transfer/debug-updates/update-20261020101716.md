## 复查附件原名流程，修正长名称接收失败

用户要求再次检查附件保留原名的代码逻辑。本轮复查清单序列化、读取、TCP 下载及重复内容复制、普通导入、更新准备、外观映射、复用文件和失败／取消清理。

发现并复现一处边界问题：合法的 255 字节文件名，在碰一碰接收时被加上 download 前缀，在记事文件导入时又被拼成带目录编号的临时名称，导致正式导入前超过文件系统名称上限并失败。上轮测试验证了最终文件名长度，但没有覆盖临时落盘环节。

新增 AttachmentTempFiles，使用系统原子分配的短临时名，保留有界的常见扩展名；TCP 下载、重复内容的本地复制及 ZIP 解压统一使用。正式附件仍从清单读取原名，仅在目标目录重名时追加 -1、-2 等编号，不缩短合法原名，不改变传输协议和按内容复用规则。

新增真实 TCP 长文件名回归，以及 3 项调用真实 ThingFileReader、ThingFileUpdate.prepare 的 Robolectric 集成测试，确认原名能到达落盘阶段、卡片和详情外观映射正确、取消时不删除或改动借用附件。两个长名称用例在修复前均失败，修复后全部通过。

174 项相关本地回归无失败、错误或跳过，完整 debug 构建成功。保留既有 GIF 重播崩溃修复。本轮未连接设备，未创建 Git 提交。
