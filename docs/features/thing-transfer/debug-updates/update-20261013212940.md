## 接收建组明确绑定 P2P IPv4，验证偶发连接拒绝

双方 v6 日志确认：卓易通已经建组且有客户端，监听始终开放，却未收到原始 TCP；OPPO 在匹配组和正确本地地址上连续被拒绝。用户补充刚进入接收也会失败，新一轮日志约四秒内完成 NFC，仍重复同样问题，所以不以等待时间或碰触快慢作为主要解释。成功记录同样使用通配监听，目前尚不能断言底层根因。

本次只调整接收建组路径的监听地址：`TapReceiverGroupHost` 读取实际组主 IPv4，并与本次组接口交叉核对；`TapReceiverServer` 明确绑定核对过的地址，不再使用通配监听，不写死网关。组地址尚未就绪继续使用原准备期限，异常或绑定失败清理并沿用原接收方式。普通 Android 默认互传、卓易通发送、设备识别、NFC 协议、连接期限及 ACK 保持原有逻辑。

诊断升级 v7，记录 `mode=P2P_IPV4`、核对地址及实际绑定结果，继续保留有界关键事件、重试汇总和日志文件分享。

113 项相关 JVM 测试、完整 debug 构建及空白检查通过。新增测试覆盖明确 IPv4 绑定、不同网段、错误接口地址和组状态；真实本机 TCP 的文件、ACK、错误身份和取消清理均通过。未连接实体设备，不能将本次兼容性调整描述为实机稳定性已修复。

两台更新后照常测试，操作时机无需特殊调整。若再次失败，请及时分享双方 v7 日志文件；本轮重点验证明确绑定组地址能否消除此前连续连接拒绝。
