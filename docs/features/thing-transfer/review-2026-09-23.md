## 高

### 1. 开启「自动提醒」时，导入提醒或习惯会失败，并留下残缺的记事

- 位置：`ThingFileImporter.importOne`（先 `manager.create`，第 75 行；后建提醒与习惯，第 79–87 行）。
- 调用链：`ThingManager.create` 第 528 行调 `AutoNotifyHelper.createAutoNotify` →
  `shouldCreateAutoNotify` 对提醒执行 `getReminderById(id)!!`（第 83 行）、对习惯执行
  `getHabitById(id)!!`（第 87 行）。此时这两行还没建，抛空指针。
- 后果：记事行已经写进数据库和内存列表；`ThingsCounts.handleCreation` 被跳过，计数少一；
  提醒或习惯行永远不会建。提示说「N 件失败」，但记事出现在列表里。缺习惯行的 HABIT 记事，
  点开时 `DetailActivity.onCreateOptionsMenu` 第 1576 行 `getHabitById(...)!!` 崩溃，每次都崩。
- 为什么真机没撞到：「自动提醒」默认关闭（`KEY_AUTO_NOTIFY` 默认 0），两台设备上都是关的。
  代码确认；未复现，复现需要改用户的设置。
- 修法：照 `DetailActivity` 的顺序（第 3567、3576 行先建提醒与习惯，第 3604 行才建记事），
  用 `manager.getHeaderId()` 作 id 先建提醒与习惯，再 `create`。

### 2. 导入页底部按钮没有避开系统导航栏

- 位置：`ThingFileImportActivity.initUI`。应用 targetSdk 36，系统强制内容画到导航栏下面；
  其他带底部内容的页面都调了 `DisplayUtil.applyBottomInsetAsMargin / Padding / ScrollPadding`，
  这个页面没有。
- 手势导航：9-21 的三星截图里按钮一直延伸到屏幕最底，下半部分压在手势条下。代码与截图确认。
- 三键导航：导航栏 48dp，按钮总高约 53dp、文字在距底 16–37dp 之间，会被整条盖住，点击由导航栏
  接收，**导入按钮点不到**。推断；未验证，切换导航方式属于设备设置。

## 中

### 3. 已过期的提醒，导入那一刻立即触发

- 位置：`ThingFileImporter` 第 81 行 `Reminder(thing.id, r.notifyTime)`，状态固定为 `UNDERWAY`；
  `ReminderDAO.create` 不看时间直接设闹钟，过去的时刻会立刻触发，`ReminderReceiver` 随即发通知
  （用户开了「提醒时自动开始」时则直接进入进行中状态）。
- 与决策冲突：决策写的是「过期提醒按应用现有的过期表现走」。现有表现见
  `AlarmHelper.createAllAlarms` 第 140–142 行：时刻已过的直接标 `EXPIRED`，不设闹钟。
- 修法：`notifyTime < now` 时以 `EXPIRED` 写入。`ReminderReceiver` 对非 `UNDERWAY` 的提醒不做任何事，
  即使闹钟照设也不会响。代码确认。

### 4. 选中项含文件夹时，「分享为记事文件」仍然显示

- 位置：`ModeManager.updateMenuItemsForFolderSelection` 第 457 行只给「导出」设了
  `hasThing && !hasFolder`，新菜单项没有规则，始终可见。
- 只选文件夹：点了没有任何反应（`shareSelectedThingsAsThingFile` 拿到空列表直接返回）。
  文件夹与记事混选：文件夹被静默忽略。代码确认。
- 修法：与「导出」同一条可见性规则。

### 5. 详情页改了还没离开就分享，记事文件里是上次保存的版本

- `DetailActivity` 只在 `saveAfterOnPause`（第 2413 行）与 `createThing` / `updateThing` 里把界面
  内容写回 `mThing`；分享对话框是 DialogFragment，不触发 `onPause`。`ThingFileWriter` 用的是
  `mThing`，提醒与习惯从数据库读，三者都是旧的。代码确认。
- 「文本与图片」同样如此，是既有行为；「长截图」取的是界面，不受影响。
- 修法：写文件前按 `saveAfterOnPause` 的取值方式从界面组装一份副本，或先保存。

### 6. 导入的记事落在首页当前所在的文件夹，不是根目录

- 导入器把 `folderId` 置空，注释写「落在当前范围的根上」；但 `ThingManager.create` 第 505–507 行
  会把空值换成 `mProjection.currentFolderId`。
- 结果取决于进程状态：冷启动时是根目录；进程还在时是用户最后停留的文件夹——可能是私密文件夹，
  也可能是在回收站里浏览时停留的已删除文件夹（导入的「未完成」记事随之从未完成列表里消失）。
  代码确认。
- 需要定：落根目录，还是落当前文件夹。落根目录需要一条不继承当前文件夹的建记事路径。

### 7. 导入后桌面列表小部件不刷新

- `DetailActivity.afterCreateOrUpdateThing` 第 3659–3660 行、设置页恢复都会刷新小部件；导入器与
  首页的 `justNotifyAll` 都没有。代码确认。
- 修法：导入完成后调 `AppWidgetHelper.updateAllThingsListAppWidgets`。

## 低

8. **详情页分享私密记事会再验证一次。** `ThingFileSharer.share` 第 66–84 行对有效私密一律鉴权；
   决策（decisions.md「Private Thing 可以传」一节）写明详情页访问即信任、鉴权放在调用方。
   同一对话框里另两项不要求验证。代码确认。
9. **同一次导入中两条记事可能用到相同的附件文件名，后一条覆盖前一条。** 文件名是
   `import_<毫秒>_<序号>`，毫秒在每条记事开始复制时取（第 110 行）；`FileUtil.createFile` 不检查
   是否已存在，`copyFile` 直接覆盖。两条相邻的带附件记事在同一毫秒内处理完才会发生，概率低，
   但结果是静默的数据错误。代码确认。
10. **附件丢失不报。** 导入时复制失败（如空间不足）被跳过、仍报成功；读取时超过 2 GB 的附件被
    静默丢弃，而发送端照写不误。代码确认。
11. **中途被杀进程时的临时目录永远不清。** `ThingFileReader.cleanUpAll` 没有任何调用点，
    残留可能有几百 MB。代码确认。
12. **导入在后台线程直接修改 `ThingManager` 的内存列表。** 首页在分屏里可见，或导入期间恰好有
    提醒触发（`ReminderReceiver` 在主线程读同一个列表）时存在并发读写。推断。
13. **外观映射为空时原样返回。** `ThingCardAppearance.remapSources` 第 126 行、
    `DetailAttachmentMediaAppearance.remapSources` 第 69 行：记事的附件全部缺失时映射为空，
    发送方的绝对路径键被写进文件，接收方数据库里留下失效的键。与非空映射「映射不到就丢掉」的
    语义不一致。代码确认。
14. **文件名按 UTF-16 单元截断。** `ThingFileSharer.fileName` 第 177 行 `substring(0, 16)`，
    第 16 个单元落在 emoji 中间时产生不成对的代理项；`Uri.encode` 会把它换成 `?`，对方按 URI
    找不到文件。推断，未复现。
15. **读取器不校验文件内容的自洽性。** `type` 可以是任意整数（如表头类型 -1）、HABIT 类型可以没有
    `habit` 字段、`things.json` 读入内存没有大小上限。只影响畸形或恶意构造的文件。代码确认。
16. **导入页每个实例新建一个线程池，从不关闭**，每打开一次导入页留下一条空闲线程。代码确认。
17. **选择模式分享在鉴权之前就退出了选择模式**，取消鉴权后选择丢失；导出是鉴权通过后才退出。
    代码确认。
18. **错误消息硬编码中文**（「建不了临时目录」等），英文界面里会显示中文。代码确认。

## 查过、没有问题的

- 压缩包路径穿越：条目名限定 `attachments/` 前缀、拒绝 `..` / 绝对路径 / `:`，落盘前把 `/` 换成 `_`。
- 生成过程中切后台：`BaseDialogFragment.dismiss()` 走不抛异常的路径，不会崩。
- DAO 单例与 `ThingManager` 都只保存 `applicationContext`；冷启动时由导入线程首次构造 `ThingManager`
  也安全（构造过程不依赖主线程）。
- 习惯的统计口径用 `Habit.createTime`（导入时间）与空的 `record`，不受发送方创建时间影响。
- 卡片跨度与图片位置存在 `thingCardAppearance` 里，会随 JSON 一起过去。
- 附件分隔符 `` `启q琼 `` 不含正则元字符，按字面切分与既有代码按正则切分结果一致。
- 请求码 22 无冲突；预览里的复选框不可单独点击，勾选状态不会与内部集合不一致。
