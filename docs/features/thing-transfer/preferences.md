# 记事传输 偏好

## 碰一碰的动画（2026-09-24）

- **动画是这个功能的重点**，要单独讨论、单独设计，不能当成功能的附属品。
- 粒子化与现有的消散动画可能相似，但**要有更强的流动感**。
- 动画节奏**不能匀速**，要有速度曲线（起步缓入、结束缓出），这样才好看。
- 实现时**一定要用真机截图或录屏核对**，不能只凭代码判断。
- 真的贴需要人在两台手机旁边，用户不一定在场，所以**先做模拟**，在单台设备上把动画和相关功能
  跑起来，再做两台真机实测。

## 碰一碰的动画：返工时的要求（2026-09-24 看过第一版录屏之后）

- **在现有的弹窗出现 / 消失粒子动画的基础上改**，要有那种感觉；不要另起一套粒子。参考是
  `tmp/particle-dismiss-tuning/ref-videos-all` 与真机上打开 / 关闭弹窗、滑动记事卡片的效果。
- 发送方：卡片定型、确定天线位置之后，用现有的消散**朝那个位置飞逝**，方向要明确，最终的颗粒流要
  **确实被吸进终点**；不能从屏幕中间开始散、向四周膨胀再凌乱地流回，颗粒也不能粗大。
- 接收方：不要满屏乱窜、拉长成条、轨迹各异的「爆炸化」效果，要优雅、有质感；直接用现有的出现动画，
  不要只拼出轮廓再用「水位」表示进度。
- 抬升的卡片要和首页的记事卡片长得一样（布局、附件等设置照搬），只是更宽；平板上要限制最大宽度。
- 抬升成卡片之后，详情页里的内容**保持显示**，不要消失。

## 接收动画：直接飞进空位（2026-09-24 第二次返工）

- 收到的记事一般在列表顶部：**先算好它们占哪些空位、多大，颗粒直接飞进空位**，不要先在天线附近
  拼成卡片再飞过去。
- 飞进来的颗粒**既有屏幕四周边框上的，也有从天线涌出的**。
- **多条记事一样处理**，不要只拼第一条、其余淡入。
- 接收方有一个或多个置顶记事时，空位可能不在屏幕上：**先滚动列表，再播飞入**。
- 测试要覆盖：**带图片附件的记事（封面在不同位置）**，以及**在文件夹里接收**时记事确实进了那个文件夹。
