## 碰一碰的动画（2026-09-24）

- **动画是这个功能的重点**，要单独讨论、单独设计，不能当成功能的附属品。
- 粒子化与现有的消散动画可能相似，但**要有更强的流动感**。
- 动画节奏**不能匀速**，要有速度曲线（起步缓入、结束缓出），这样才好看。
- 实现时**一定要用真机截图或录屏核对**，不能只凭代码判断。
- 真的贴需要人在两台手机旁边，用户不一定在场，所以**先做模拟**，在单台设备上把动画和相关功能
  跑起来，再做两台真机实测。

## 碰一碰的动画：返工时的要求（2026-09-24 看过第一版录屏之后）

- **在现有的弹窗出现 / 消失粒子动画的基础上改**，要有那种感觉；不要另起一套粒子。参考是
  `tmp/particle-dismiss-tuning/ref-videos-all` 与真机上打开 / 关闭弹窗、滑动记事卡片的效果。
- 发送方：卡片定型、确定天线位置之后，用现有的消散**朝那个位置飞逝**，方向要明确，最终的颗粒流要
  **确实被吸进终点**；不能从屏幕中间开始散、向四周膨胀再凌乱地流回，颗粒也不能粗大。
- 接收方：不要满屏乱窜、拉长成条、轨迹各异的「爆炸化」效果，要优雅、有质感；直接用现有的出现动画，
  不要只拼出轮廓再用「水位」表示进度。
- 抬升的卡片要和首页的记事卡片长得一样（布局、附件等设置照搬），只是更宽；平板上要限制最大宽度。
- 抬升成卡片之后，详情页里的内容**保持显示**，不要消失。

## 接收动画：直接飞进空位（2026-09-24 第二次返工）

- 收到的记事一般在列表顶部：**先算好它们占哪些空位、多大，颗粒直接飞进空位**，不要先在天线附近
  拼成卡片再飞过去。
- 飞进来的颗粒**既有屏幕四周边框上的，也有从天线涌出的**。
- **多条记事一样处理**，不要只拼第一条、其余淡入。
- 接收方有一个或多个置顶记事时，空位可能不在屏幕上：**先滚动列表，再播飞入**。
- 测试要覆盖：**带图片附件的记事（封面在不同位置）**，以及**在文件夹里接收**时记事确实进了那个文件夹。

## 粒子动画第三版：向弹窗粒子靠拢（2026-09-25）

- **发送不要把所有颗粒收进同一个终点**：收束到一点会在中后期形成以天线为顶点的三角，画面尖锐。
  起点、终点可以有，但不强制所有颗粒流入终点 / 从起点流出。
- **接收边缘的粒子要与弹窗的微粒一致**（大小、形状、动作），不要带拖尾的圆点。
- **接收时屏幕四周的粒子随进度慢慢往中间移动**，本身就是进度指示；进度 100% 时，四周的粒子与从天线
  涌出的粒子一起组成收到的卡片。天线处也不能从一点尖锐地涌出。
- 参照弹窗出现 / 消散的实现方式，加入卷曲、翻折；以质感、美感、轻盈、灵动为先，不以实现省事为准。
- 先在 PC 模拟器上改好，再谈移植 Android。
- 动画要**真的看画面**判断（逐帧截图、轨迹图、视频），不能只看代码或数据。

## 粒子动画第三版第二轮（2026-09-25）

- 接收时屏幕四周的粒子**向中间扩散**，不是整体向中间移动：边缘不能空掉，中间不能出现一个框；
  扩散得不用太多，四周粒子形成的「内边框」不能很厚。
- 扩散**要持续**：进度 100% 之后、列表计算空位的那段时间里也要继续扩散，直到和天线涌出的粒子
  一起组成卡片。
- 多张卡片同时拼出时**不能太对称**（左右几乎一模一样会显得机械）。
- 天线位置**一直用波纹表示**：发送碰上之后不要让波纹消失、变成一团光，波纹要一直播放，随发送过程
  收缩即可；接收的天线位置指示也用波纹。
- 模拟器里要能**随机换记事颜色**（含渐变色），放在最上方一个按钮。

## 粒子动画第三版第三轮（2026-09-25）

- 发送：颗粒团**最后不要旋转着进入天线**处。
- 发送完成后卡片的恢复**不要从天线处流出来**（看上去像发送失败、被撤回），改成与打开分享时相同的
  「抬起、形成卡片」。
- 接收：**一开始不显示天线位置的波纹**（可能挡住界面元素）；开始接收、显示进度时才显示。
- 接收：显示进度起，天线处就开始**慢慢冒出正确颜色的颗粒**，朝收到的记事可能落下的位置飞去 / 扩散
  （按收到的条数、卡片宽度与当前列表的情况，尤其是置顶记事决定落在左列还是右列，大概算出方向）；
  到 100%、列表腾出位置之后，这些颗粒与屏幕四周的颗粒一起组成卡片。
- 颗粒的轨迹**不能直愣愣、机械**；粒子群前沿要像弹窗出现 / 消散那样有卷曲、翻折的观感。
- 屏幕四周的颗粒**不要全部离开边缘**：扩散出的一部分用来组成记事，其余从边缘向外退去、渐隐。

## 粒子动画第三版第四轮（2026-09-25）

- 接收时天线处冒出的颗粒**始终只有一团**，不是一团一团地冒出；一开始比较少，随进度越来越多、扩散范围
  越来越大，但不要太大。
- 扩散是**往终点的方向走**，进度期间不直接到达终点。
- 团里能看到颗粒的流动，流动方向**不是直线**；流动要形成卷曲、翻折、成缕、疏密不均。
- 这一团的**轮廓不能有尖锐、笔直的线条**。

## 粒子动画第三版：接收沿用弹窗出现的动画（2026-09-25）

- 自己设计的「一团」的形状与流动（涡旋推着的团、流场里的一团、涡胞流）都被否定：像八爪鱼、触手、乱流，形状古怪。
  **直接沿用弹窗出现的粒子动画**，只让天线处冒出的颗粒、屏幕四周的颗粒也参与进来。
- 进度期间播弹窗出现的**前半段**，**不能停**，要保持动画连贯。
- 颗粒团不能是「一片片的、零散而杂乱、像随机组成的形状」。
- 否定一个方案时也要先上网调研这类动画的设计（产品怎么做、设计与特效工艺怎么讲），不只是找运动模型。

## 粒子动画第三版第八轮：来源按远近、覆盖多种列表状态（2026-09-25）

- 天线处涌出的颗粒应当拼出卡片上离天线近的那一侧，屏幕四周的颗粒拼出靠近屏幕边缘的那一侧（原话：「NFC涌出的
  粒子应该更接近这个记事的右侧才对」，指落在左列的那张卡片）。
- 模拟器要覆盖更多列表状态：收到一条普通宽度的记事、一条通栏记事、三条记事，以及列表里有一两条置顶记事的情形。
