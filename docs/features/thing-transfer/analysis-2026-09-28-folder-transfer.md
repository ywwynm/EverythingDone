# 文件夹的分享与传输：可行性与待定事项（2026-09-28）

用户问：文件夹的分享（记事文件）与碰一碰传输好不好做、有哪些要他来定。本文基于代码与文档的检索，没有改动任何代码。

## 结论

能做。现有链路里与内容无关的部分可以直接用：

- **网络层只搬字节**：Wi-Fi Direct 的 `TapStream` 与 NFC 握手的分块读取都不关心载荷是什么。
- **记事文件是 zip + 清单**（`things.json`），读取时忽略不认识的字段，加一段文件夹结构不影响现有字段。
- **接收端的预计落点**（`TapListPrediction`）按「高度 + 是否通栏」排，不区分记事与文件夹；新建的文件夹与收到的记事落在同一个位置（置顶之后的第一个）。
- **粒子的截图与拼合**对任何视图都成立（`TapParticleFlight.captureComposite` 收的是 `List<View>`）。
- **首页文件夹卡片的绑定**（`ThingsAdapter.bindFolderCard`，protected）已有在列表之外使用的先例：单一记事小组件配置页的
  `FolderCardDelegateAdapter`。

要改的地方：

1. **文件格式**：清单现在没有任何文件夹信息（2026-09-21「`folderId`：文件夹不传」）。要加一个 `folders` 数组（树：父子、
   标题、背景、卡片外观），记事加所属文件夹与在文件夹里的先后。
2. **导入**：现在唯一建文件夹的接口是 `ThingManager.createFolderFromThings`（拖两条记事生成，要求两条正在进行的记事），
   没有「按给定父级、标题、外观建一个文件夹」的接口；要按树建文件夹、按原先后放记事，文件夹与记事共用一个 id 计数器，
   导入时逐个取号。
3. **分享入口**：选择模式里一选中文件夹就隐藏「分享」与「导出」（`ModeManager.updateMenuItemsForFolderSelection`），
   `ThingManager.getSelectedThings()` 也只收记事；文件夹没有详情页。
4. **发送时抬起的卡片**：`TapThingCards` 的适配器没有列表项，只会走记事分支；要能渲染文件夹卡片（正常模式只有标题与计数，
   「大」模式带子项缩略图、高度随内容），放不下时只能整体缩小（没有正文可删）。
5. **接收端**：定位、隐藏、揭示都按记事 id（`findReceivedCard` → `getListPositionForThingId`；适配器的隐藏集合只在
   记事分支），要扩到文件夹（`getListPositionForFolderId` 已有）；完成提示「已收到 N 条记事」要能说文件夹。
6. **文件导入的预览界面**（`ThingFileImportActivity`）：现在是逐条勾选的记事列表，重复的默认不勾。
7. **握手不用改结构**：卡片数、颜色、形状照旧，只是含义从「每条记事」变成「顶层的每一项」（一个文件夹卡片或一条散的记事）。

规模：比 2026-09-26「抬起的卡片放大」那一轮大，约相当于二期里「握手带卡片形状 + 预计落点」那一段，外加文件格式、导入与
导入预览。

## 要用户定的（每条后面是建议）

**范围**

1. 文件夹里带哪些记事：只带「正在进行」的｜连「已完成」的也带、导入后保持已完成（要改现在「导入一律改成正在进行」的规则）。
   **建议只带正在进行的**，与现有导入规则一致，分享也只在正在进行的列表里提供。
2. 首页开着类型筛选时：整个文件夹都带｜只带筛选出来的记事。**建议整个文件夹都带**：分享是把文件夹当一个整体交出去。
3. 子文件夹：整棵子树都带（空的子文件夹也保留）｜只带一层。**建议整棵子树**。

**入口**

4. 选择模式里能选文件夹分享，与「移动」等结构操作一样只在「正在进行」列表里（文件夹与记事可以混选）。**建议做**。
5. 打开一个文件夹之后，右上角的菜单里加「分享此文件夹」（卡片从页面里升起，与详情页相同）。**建议加**。

**保留哪些属性**

6. 私密标记：不随文件走（与记事文件去掉私密前缀一致）｜带上（对方收到的文件夹也是私密的，要对方设过私密密码）。
   **建议不带**。发送前的身份验证沿用现有规则：选中项里有有效私密的就先验证，文件夹子树算在内。
7. 顺序与置顶：文件夹内部的先后与置顶保留；收到的文件夹本身不置顶，落在置顶之后（与收到的记事一致）。**建议如此**。
8. 外观：文件夹的背景、卡片外观（「正常 / 大」、普通 / 通栏）随文件走。**建议带上**，与记事的卡片外观一样。
9. 重名：对方已有同名文件夹时新建一个（应用本来就允许重名）｜合并进同名文件夹。**建议新建**：合并要处理子项冲突、
   也容易合错。

**兼容与导入界面**

10. 旧版本：只有带文件夹的文件把格式版本升到 2，旧版本收到时提示升级；只含记事的文件仍是 1｜不升版本，旧版本把里面的
    记事平铺导入到根目录（文件夹结构丢掉）。**建议升到 2**：静默丢掉结构比提示升级更糟。
11. 记事文件导入的预览：以文件夹为单位勾选、可以展开看里面的记事｜逐条勾选（做成树）｜带文件夹时不给勾选、整体导入。
    **建议以文件夹为单位勾选**。
12. 碰一碰的动画：发送时抬起的是文件夹在首页上的卡片（「大」模式带缩略图），接收时颗粒拼成对方首页上的文件夹卡片；
    混选时文件夹与记事一起叠。**建议如此**。

## 不需要用户定、实现时按现有规则处理的

- 落点：记事文件导入落根目录，碰一碰落在发起接收时所在的文件夹（2026-09-23、2026-09-24 两条决策），收到的文件夹同样。
- id：文件夹与记事共用计数器（`ThingManager` 的 header），导入时逐个取号并推进。
- 回收站、已完成列表里的「投影文件夹」只是路径容器，不提供文件夹分享（第 1、4 条若按建议，自然不涉及）。
- 接收完成的提示按收到的文件夹数与记事数组合措辞。
- 握手里的卡片最多 12 张，指顶层的项；文件夹里的记事数不影响握手。
