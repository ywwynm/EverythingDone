# FableSol 逐层特效回归与高光—暗面耦合调研（2026-07-15）

## 结论

当前问题不是单纯的“阴影太弱”。D135 在恢复 `lighten_far` 时，连带撤销了上一提交已经确认的
逐层特效数量、存在度与 HDR 峰值；同时保留下来的高光由较规则、正向相加的空间场构成，暗面又
与它不相关，所以同时出现“中远层没效果、HDR 变暗、近层光带像塑料”的结果。

修复边界应拆成两部分：保留 D135 的主体色板裁决；恢复 D103～D118 已确定的逐层数量、存在度、
强度与 HDR 峰值合同，只重新设计高光形状、覆盖率、最终 HDR 合成与同源暗面。不能再用一个逐层
权重同时控制逻辑数量、几何面积、SDR 反射、HDR 峰值和银白比例。

## 本地代码证据

- 上一提交的闪点容量为 `4/4/3/3/2/2/1/1/0`，当前为 `3/2/1/0/0/0/0/0/0`；第 3～7 层
  的离散材质事件被直接移除。
- 连续太阳反射当前再乘 `.72/.49/.21/0/0/0/0/0/0`。该门同时作用于 SDR reflection budget
  与 HDR locality，使第 3～8 层的主要连续反射完全归零，也与 D135 文本所说的“继续保留连续
  GGX 微表面”矛盾。
- 连续银泽峰值由 `2.7/2.4/2.1/1.8/1.5/1.29/1.08/1/1` 改为
  `2.3/2.1/1.9/1.7/1.64/1.56/1.49/1.42/1.36`，前三层又乘上述门控，实际超白差量相对上一
  提交最多只剩约 `55%/39%/17%`，第 3 层以后为零。
- 全局 HDR headroom 仍为 `3.6×`，但 `optical.frag` 删除了 `excess / opticalAlpha` 的输出补偿，
  HDR mask 又从 `coverage^1.55 × eligibility` 收紧为
  `coverage^1.85 × eligibility^1.35`。因此名义峰值没有等于最终合成峰值。
- 解析 halo 当前为零。圆环/扩缩主要来自 `mode 3` 的空心单侧剖面、track 尺寸继续以 `0.30s`
  追随候选半高宽，以及 `water.frag` 中 `216×129` 低频移动 patch 的大块等值区。
- 宏观阴影目前只削减最多约 `1.9%` 的新增直射亮瓣，不能让主体低于基线；现有波背暗带虽使用
  正确的随层保色深色，但与连续 GGX patch 不是同一空间场，无法支撑高光对应的立体形体。

## 物理与感知依据

1. Cox 与 Munk 将海面 sun glitter 的亮度直接联系到“恰好把太阳反射到观察者”的局部坡面出现
   概率。这支持由坡面/法线分布产生破碎亮点和亮迹，不支持围绕事件中心绘制规则圆环：
   <https://opg.optica.org/josa/abstract.cfm?uri=josa-44-11-838>。
2. Walter 等人的微表面反射/折射模型以同一个法线分布 `D`、Fresnel `F` 和几何可见性 `G`
   组织 BRDF 与 BTDF；界面无吸收时，透射权重为 `1-F`。因此亮部增强时，对应透射应按能量关系
   减少，而不是另外叠加白光或黑环：
   <https://www.graphics.cornell.edu/~bjw/microfacetbsdf.pdf>。
3. Heitz 说明 Smith masking-shadowing 是可见法线分布归一化和单次散射能量守恒的一部分。
   `G` 约束微表面反射，但不会自动生成一圈可见黑影；粗糙表面还需注意多次散射能量补偿，不能
   通过继续压暗来代替：<https://jcgt.org/published/0003/02/03/paper.pdf>。
4. Filament 的 PBR 文档给出水的 IOR 约 `1.33`、法向 Fresnel 反射率约 `2%`，并强调 BRDF 的
   能量守恒。法向反射率低不等于太阳高光峰值必须低；高峰值可以存在，但应局限在很小的满足
   反射条件的面积：<https://google.github.io/filament/Filament.md.html>。
5. Kim、Marlow、Anderson 的视觉实验表明，高光的位置和方向必须与底层 shading、局部表面结构
   相符；错位会降低光泽感，让高光更像表面标记。这直接支持“亮暗同源”，而不是给圆环机械补一
   圈暗边：<https://doi.org/10.1167/11.9.4>。
6. NVIDIA 的水面实践指出，运行中逐渐改变活动波长会让波峰从原点扩张或收缩，观感不自然；应让
   旧波自然消失、以新参数重生。对应到 FableSol，光迹应随相位平移、淡入淡出，不应通过半径或
   半高宽持续呼吸：<https://developer.nvidia.com/gpugems/gpugems/part-i-natural-effects/chapter-1-effective-water-simulation-physical-models>。

## 建议的渲染合同

### 1. 恢复既定层级存在度

- 恢复离散闪点容量、出生权重、核心 alpha、表面反射、连续银泽和透射的上一提交逐层表。
- 第 0～2 层保持主视觉；第 3～7 层仍有越来越稀疏、越来越小面积的事件；第 8 层退出离散 HDR。
- 保留 `lighten_far`、无界面肩、无周期尺寸呼吸和无解析宽 halo。

### 2. 分离峰值与覆盖率

每个效果至少独立控制：

- `logicalCount`：候选/track 数量；
- `eventRate`：出现频率和占空比；
- `coverage`：实体面积与核心宽度；
- `peak`：最终合成后的 HDR 峰值；
- `neutralMix`：银白核心的中性化比例；
- `shoulderEnergy`：参考白附近、保持 Thing 色的外围能量。

恢复旧 HDR 峰值，但用更小核心、更低覆盖和更短停留控制乳白。最小银白核心可超过 reference
white；肩部以环境反射色或当前水色相关颜色为主，保持在 reference white 附近或以下。Bloom
只消费超白源像素，不在水面 shader 内绘制解析圆形外晕。

### 3. 重做高光形态

- `mode 3` 核心最大值贴近真实水面，然后向水内单调衰减，不再“轮廓处为零、内部成峰”。
- 每个 track 表现为短小、填实、各向异性、沿波峰切线排列的微面片；避免空心月牙和同心环。
- 出生后尺寸基本固定，或只允许小幅低频变化；生命周期主要改变强度和可见性。
- 连续 GGX 不再使用会形成大椭圆等值区的低频白色 patch。空间破碎由带限微法线和像素 footprint
  过滤后的 NDF 产生；远处未解析能量归入稳定的统计银泽。

### 4. 亮暗来自同一法线场

- 同一低频波面法线同时计算 `N·H`、`N·L`、Fresnel 与 Smith `G`。
- `N·H` 接近太阳—视线半向量时形成窄高光；背光坡面由 `N·L` 与遮蔽形成位于一侧的宽缓暗面，
  不包围高光，也不机械镜像高光。
- 暗部从当前层、当前位置的线性水色或 OKLab 保色深色派生，只影响对应直射、局部体色或透射
  分瓣；不得混黑，也不得乘暗环境反射、HDR 核心与最终像素。
- Beer–Lambert 继续只负责具有明确光程的体积吸收，不兼任表面高光阴影。

## Python 单变量消融与验收

依次比较：当前 D135；仅恢复旧数量/峰值；改实心固定尺寸光迹；替换低频 GGX patch；加入同源
保色暗面。每一步只改一类变量，并在十八色固定夹具、多时间点下记录：

- 每层最终峰值和超过 `1.0/1.16/1.29/1.6/2.0× reference white` 的覆盖率；
- `meanExcessLuminance`、净 APL、最大亮连通区面积及银白肩部覆盖率；
- 明区/暗区面积、局部 Weber 对比和高光方向与波面法线/波峰切线的一致性；
- 高光 mask 的孔洞数、圆度、剖面峰值位置以及 track 面积/半径随时间的变异；
- 阴影的明度差、色相漂移、色度保持，以及遮挡后的逐层实际可见覆盖；
- 九层相邻边界在静态和动态帧中的最小可读对比。

通过这些指标和联系表后再同步 Android；真机只负责最终 HDR tone mapping 与运动观感验收。

## 实施与验证结果

D136 已按上述合同实施。闪点容量和 HDR 峰值恢复，光迹改为出生尺寸固定的贴面实心短带，解析
halo 与低频椭圆 patch 删除；连续正向高光和保色负向形体响应复用同一法线与光向。代码审查另
发现并修复了折射/Beer 对当前层 alpha 重复应用、`mode 8` HDR 资格未传入、第 8 层只暗不亮以及
反射身份色错误取自已合成颜色四项问题。

最终 18 色原始离屏帧为 FP16 线性 scRGB，完整效果峰值中位 `2.934× reference white`，去闪点
后峰值中位 `1.898×`；完整效果超过 `1.0/1.29/2.0×` 的 pooled 水体覆盖率分别为
`0.636%/0.346%/0.091%`。普通联系表与诊断 PNG 均为 8-bit SDR，只承担颜色和形态检查；HDR
强度以原始数组、逐层阈值覆盖和伪彩图为准。Python 全量 158 项测试、Android 139 项 JVM 测试和
Debug 构建通过，Python FP16 读回基准约 `63fps`。最终系统 HDR 映射与动态观感留给真机验收。

## 动态复测补充：连续 GGX 等值线光带

随后用 129 BPM、中高能量且不过度抬高前景水位的固定输入做单变量动态消融。`full`、关闭
离散 glint 的 `no_glint`、移除全部 optical 几何的 `water_only` 都保留同一组扩缩月牙光带；
只有把 `uSheenCoverageScale` 归零的 `no_sheen` 会令其消失，关闭 mode 4 表面带则无效。
因此该缺陷与 glint 无关，根因是 `water.frag` 用约 `0.08` 宽的 `smoothstep` 对连续
`sunResponse` 做逐层阈值裁剪：动态波场的闭合等值线被直接显示成会扩张、收缩的亮带，随后又被
SDR 渐近响应压成接近恒定亮度，形成油漆感。

修复前的真实 GPU 基线中，开启/关闭连续 sheen 的正亮度差量在 `ΔY>0.01` 时，单帧最大
8 连通域为 `1368px`；16 个时相的中位数为 `2302px`、最大值为 `3151px`。该结果在把阈值提高到
`ΔY>0.05` 后仍稳定大于 `1286px`，不是由诊断阈值偶然选取造成。

进一步调研支持把“微面片的空间存在”与“GGX 亮度响应”分开：NVIDIA 的程序化多尺度材质研究
强调以稳定的程序化微细节和像素 footprint 过滤同时获得各向异性 glint、空间抗锯齿和时间稳定性；
Projected-Space NDF filtering 也指出掠射角下直接用不稳定的一阶 footprint 会产生明显镜面伪影。
因此 FableSol 的实时近似应让固定尺寸、稳定播种、经 `fwidth` 过滤的短微面片负责覆盖率，GGX
只调制这些面片的能量；不得再让动态 BRDF 响应本身决定几何边界。

- [Real-time Rendering of Procedural Multiscale Materials](https://research.nvidia.com/publication/2016-02_real-time-rendering-of-procedural-multiscale-materials)
- [Stable Geometric Specular Antialiasing with Projected-Space NDF Filtering](https://www.jcgt.org/published/0010/02/02/)

## 稳定有界微面片实施结果

> **结论更新（2026-07-15）：该候选已被用户目测否决。** 它成功消除了扩缩等值线，却把连续
> sheen 变成每层内部大量斜短光点；这些点仍被判断为不自然。下述指标仅保留失败候选的诊断价值，
> 不再描述现行实现。

最终实现没有改动离散 glint 的出生数量、尺寸、亮度或逐层 HDR 峰值，而是只替换连续 sheen 的
空间覆盖。每层使用 `42×16px` 稳定播种的短各向异性微面片，加入层盐与行相位；时间只做连续
坐标平移。解析 footprint 从不含 `floor`/hash 的连续坐标导数计算，避免在随机单元边界放大导数。
逐层命中概率使用 uniform 策略权重；GGX 响应调制命中面片的 SDR/HDR 能量，不再塑造面积边界。
同一 `spatialGate` 同时约束随层保色暗面，因此不会在亮片之外留下宽暗带。第 0 层前景填充提前
返回，避免为大面积遮挡区执行微法线、随机 hash、GGX、折射与体积吸收。

129 BPM、适中主浪、`EmptyOptics` 的 16 时相 GPU 结果如下：

- `ΔY>0.010` 正残差最大连通域：中位 `93px`、最大 `105px`，最大跨度 `22px`；旧实现为中位
  `2302px`、最大 `3151px`。
- 最大连通域占总支持面积：中位 `7.20%`、最大 `9.29%`；长轴晶格相干性中位 `0.106`，动态抽帧
  未见规则晶格或扩缩圆环。
- 60Hz 相邻帧 mask IoU 中位 `0.8716`、最低 `0.8313`，残差相关性中位 `0.9725`，覆盖变化中位
  `2.01%`、最大 `5.24%`；微面片随流平移而非闪烁重生。
- `ΔY<-0.003` 负残差支持面积中位 `0px`、最大 `14px`；降低到 `0.001` 后最大连通域仍只有
  `38px`，并始终局限在单层。

动态联系表同时比较 `full/no_glint/water_only`。三路中的连续短高光形状一致，说明 glint 已被
实证排除；完整画面仍保留各层原有光学实体。PNG/GIF/MP4 只是 SDR 形态证据，HDR 亮度继续以
FP16 原始数组和阈值分布判断。

## 最终裁决：删除层内 continuous sheen

用户明确要求不再继续优化这些短光点，现行方案因此整项删除连续 GGX 可见反射、固定微面片和
配套暗面。预滤波微法线只保留在折射、Beer、SSS 与 HDR transmission 路径；transmission 使用
不随微法线分块的 `V·H` Fresnel 标量。边缘 glint 与其它 optical 实体保持独立，不能把它们的
峰值、数量或轮廓效果与本次删除混为一谈。

最终共享 shader hash 为
`c2d7b3ccfcd435b951eedfafc4f95afbdd146730b856a9c3b6a3c661d77430f6`。129 BPM、适中水位的
动态 `full/no_glint/water_only` 对照均未再出现层内斜点或扩缩光带；`water_only` 四时相不存在
高于 `1.001× reference white` 的连续 HDR excess。18 色完整效果峰值仍为
`2.629/2.934/3.314×`（最小/中位/最大），证明保留的 glint 与独立 optical HDR 合同未被本次
删除改写。Python 160 项与 Android 140 项测试全部通过。
