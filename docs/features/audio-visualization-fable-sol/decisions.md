## D94 Sun-glitter 使用跨连续面的统一出生池（2026-07-14）

镜面闪点继续复用 D70 的锚点跟踪、`0.30s` attack、`0.80s` release、低强度软门和单点亮度，且不新增音频或节拍乘数。变化只发生在出生选择：所有可生成闪点的水层先把未匹配锚点放入同一个候选池，再由一个总出生额度跨层选择；候选分数乘以固定太阳方位导出的连续路径权重，路径外仍保留 `0.12` 的概率底，避免形成常亮光柱。路径近处较宽、远处较窄，并随深度连续偏移，不允许每层各自生成互不相关的亮点系统。

闪点几何沿真实相邻深度行方向轻微展开，近层最大 `2.6dp`、远层最大 `1.3dp`，只改变短轴的水面内展开，不增加数量、不改变 HDR 峰值。Android GLES 与 Python ModernGL/QPainter 使用同构路径、统一出生预算和几何规则；Python 宽度继续固定为 `320dp/640px`。

## D93 水面 SSS 以 Fresnel 互补预算进入 HDR（2026-07-14）

Step D 复用现有 `sunriseSubsurfaceMask()`，只在 scene-linear HDR 分支给真实水面增加超白透射差量；SDR 的 `addSunriseSubsurface()` 公式与输出保持不变。近层目标峰值为 `1.45× reference white`，到 `depth01=0.62` 平滑归回 `1.0`，并始终受设备实时 `uHdrHeadroom` 和统一 `uHdrGain` 封顶。透射乘以 `(1-R)`，与 Step C 银泽的 Fresnel 反射预算互补：掠射角让位给反射，较正视角保留身份色透射；颜色从本层 `subsurfaceColor` 归一化派生，不混灰、不改色相。

独立 optical mode 8 仅保留很弱的肩部，逐层峰值收为 `1.08/1.06/1.04/1.02/1.0…`，避免与真实水面上的 Step D 重复记账。该变化不改变几何、闪点数量、音频映射或 SDR 基色。

## D92 HDR 银泽使用独立低通法线，闪点只在不可感知后退出（2026-07-14）

HDR 水体银泽不得继续直接放大 25×最多 120 顶点网格上的原始坡度。原始坡度仍供几何、微法线、
SSS 和 D91 背坡阴影使用；银泽新增一组专用坡度属性，在实际渲染网格上做横向 3 次、纵深 4 次
`[1,2,1]/4` 预滤波，再进入 Fresnel。近层目标 headroom 从 `1.6` 提到 `2.0`，Fresnel×太阳
响应以 `0.70` 次幂拓宽；只在 scene-linear HDR 分支生效，SDR 基色不变，最终仍受设备
headroom、深度退出和统一 HDR 增益约束。Python 保持 320dp/640px 宽度，只同步新增顶点属性。

镜面闪点取消 `intensity < 0.04` 的硬裁剪。强度 `0.018～0.060` 使用 smoothstep 软门与原
幂次包络相乘，track 在 `0.015` 退休前已经不可感知；两显示帧间隔用于闪点身份跟踪时封顶为
`1/15s`，暂停、卡顿或恢复后的长时间差不得在单帧内吃完整个 `0.80s` release。Android Canvas
回退和 Python QPainter/ModernGL 使用同一包络；顺流流光仍按真实时间推进，不受此封顶影响。

`depthScattering` 函数、`uDepthScatteringStrength`、固定为 0 的参数和两处调用全部删除。
`deep` uniform 仍是 D91 背坡阴影的身份色目标，`subsurface` uniform 仍由日出 SSS 消费，二者
不是死代码，继续计算和上传。本决策在 Android 定稿后一次性同步 Python，避免两端反复改动。

## D80 HDR 使用 SurfaceView 独立的 FP16 线性 scRGB 管线（2026-07-13）

代码与 Android 官方行为核对确认：`Window.setColorMode()` 不会改变 `SurfaceView` 的
surface 颜色管理，因此 FableSol 不把录音 Dialog 整个 Window 切换为 HDR。API 34+
只在当前显示器报告 HDR 且实时 `hdrSdrRatio` 可用时尝试 HDR；EGL 必须同时
支持 `EGL_EXT_pixel_format_float`、`EGL_KHR_gl_colorspace` 与
`EGL_EXT_gl_colorspace_scrgb_linear`，并成功建立 float component config 及 linear scRGB
window surface。任一条件失败都在同一 `SurfaceView` 上自动回退 RGBA8 SDR，不创建
第二套水体渲染器。

HDR 场景先在 `GL_RGBA16F` framebuffer 中以线性值合成，再输出 linear scRGB；
`GL_RGBA16F` 不可渲染时取消 HDR excess 并回退 SDR scene target。API 35+ 仅在
RECORDING 且 HDR 链路已就绪时，为 `SurfaceView` 请求 `2.0×` desired headroom；
PREPARED/STOPPED 以 `0.36s` 统一增益平滑回到 SDR，状态变化不重建 surface。显示器
headroom 下降时立即服从实际上限；上升时才平滑展开。

只有镜面闪点核心、符合朝向的窄表面反射和少量薄峰透射可生成
`>1.0` 线性值；其它光学实体的 HDR eligibility 固定为零。由于光学 pass 仍使用
`SRC_ALPHA` 保持 SDR 外观，着色器只对 reference white 之上的局部 excess 做 alpha 预补偿；
暗色 Thing 的补偿只能使用显示器实际 headroom 中、超过当层目标峰值的剩余部分。
SDR 路径的 excess 严格为零，不加入 tone mapping、shoulder 或全局曝光补偿。

## D79 材质去雾与 HDR 分成两个 Debug 版本验收（2026-07-13）

用户同意按可归因顺序实施并发布：第一阶段只建立共享 SDR 材质基线，完成内部宽光去重、色相归一
和窄高光片段调整；环境、景深阶梯、阴影与 HDR excess 保持不变。该版本先通过真机判断水体是否
更通透、颜色是否仍保留 Thing 身份以及高光覆盖是否合适。

只有第一阶段方向确认后，第二阶段才启用 FP16/scRGB HDR 输出、D57/D74 的分层超白峰值、运行时
能力检测和自动 SDR 回退。两个阶段不得合并到同一首轮 Debug 中，以免无法区分材质清晰度与显示
峰值各自造成的变化。

## D78 首轮去雾不额外压暗阴影，只移除冗余宽光（2026-07-13）

用户同意首轮内部光学重组不主动压暗波背、深水区、ThingBackground 基色或现有中间调，也不提高
`back_shade_gain`。取消九层 `body light`、收紧重复柔光后，先观察由宽光减少自然产生的局部
对比提升。

该约束避免在同一轮同时“去亮”和“加暗”，使 APL 变化与材质清晰度的归因保持明确，也防止
FableSol 从柔雾直接摆向沉闷、厚重的水体。若首轮真机仍显得扁平，才允许把波背/深水阴影作为
第二轮独立、可归零的 A/B 项；阴影即使调整也必须继续由 Thing 身份色派生，不得变成脏灰或纯黑。

## D77 光学高光不再独立旋转色相，只沿 Thing 色到中性白变化（2026-07-13）

代码核对确认，当前高光颜色除固定冷色目标外，还通过 `pearl_shift_deg=6` 以约 `12s` 周期进行
`±6°` 色相摆动，并叠加 `hue_temp_deg×0.6`、即约 `+3°` 的固定偏移。用户同意取消高光、
受光浪峰和顺流流光的这些独立色相旋转。

重组后，各位置的光学颜色只沿“该位置的 ThingBackground 本地颜色 → 中性白”轴改变亮度与彩度；
不得通过周期或固定 hue rotation 产生额外冷暖漂移。现有强度呼吸、高光出现频率和实体生命周期
继续保留，不把色相静止误解为动画静止。仅最深传播路径继续允许 D58 约定的相对身份色不超过
约 `2°` 轻微冷移。

## D76 顺流流光保持 SDR，不参与 HDR 超白分配（2026-07-13）

现有 `flow streak` 是低 alpha、沿背景流平移的长寿命光学实体：单条约持续 `5～9s`，每层最多
约 `2～3` 条。用户同意继续把它定义为运动与流向线索，而不是满足镜面朝向条件的瞬时强反射。

因此 `flow streak` 保持 Thing 色系和 `<=1.0` 的 SDR 亮度，不生成 HDR excess。D57、D74～D75
的超白预算只用于表面反射、受光浪峰和镜面 `glint`；不得因流速、寿命包络或音频驱动让长亮带
进入 HDR，以免形成发光拖尾并混淆 D17 已区分的流光与镜面闪点语义。若流光本身需要调整，只能
作为共享 SDR 材质对比的独立 A/B 项处理。

## D75 HDR 覆盖通过增加窄高光片段实现，不扩宽柔光（2026-07-13）

用户同意把“高光稍微多一些”落实为近、中层上更多离散且较窄的合格高光片段，而不是加宽单个
闪点、`halo`、`thin glow` 或 `crest veil`。高光采用“清晰核心 + 很弱的窄柔边”双尺度结构；
允许适度提高窄片段数量、连续性和浪峰占用率，但不得把整段浪峰变成连续白线。

当前镜面闪点核心本身较窄，但 `analytic halo` 以核心厚度约 `4.2×` 展开，并与多类波峰柔光
叠加。实现时应先收紧、降能或合并这些外围通道，再调整合格片段的空间密度。不得用更宽的低频
亮区完成 D57 的中等 HDR 覆盖，否则会抵消 D72～D73 的去雾和局部对比目标。

## D74 HDR 高光随水层深度递减，远层不争夺超白峰值（2026-07-13）

用户同意在 D57 的亮度档位之上增加明确的景深分配，避免九层水体都以相似超白峰值破坏 D59 的
层级辨识：近层 `0～2` 可完整使用约 `1.6～2.0×` 的镜面核心；中层 `3～5` 仍保留较多高光，
但超白峰值约收在 `1.2～1.5×`；远层 `6～8` 基本保持 SDR，不产生明显 `>1.0` 的高光。

远层继续通过既有的偏白、透明、柔化和羽化表达距离，而不是依靠 HDR 峰值。深度衰减只约束额外
高光能量，不改变几何、九层 alpha、`lighten_far` 或既有景深阶梯。这样超白覆盖主要分布于近中
六层，满足“比极少数亮点稍多”的目标，同时让近层最晶亮、远层保留空气感。

## D73 “整体更亮”指局部峰值与主观晶亮感，不要求提高 APL（2026-07-13）

用户同意把最初的“整体亮度更高”界定为：高光峰值更明确、局部明暗对比更强，最终使水体在主观上
更明亮、更晶莹；不要求平均画面亮度（APL）或整片水体填充亮度同步上升。D72 取消九层独立
`body light` 后，如果 APL 自然小幅下降，可以接受。

首轮不得通过抬高 environment、ThingBackground 水体基色、九层 alpha 或宽范围补光，补偿被移除的
宽光能量；否则会重新降低局部对比并带回雾感。亮度提升集中由更窄的表面反射、受光浪峰与镜面
闪点承担，其中 HDR 设备按 D57 获得受控超白峰值，SDR 设备则依靠共享材质重组获得更清晰的局部
对比。APL 只作为防止意外整体变暗或过亮的诊断指标，不作为必须上升的优化目标。

## D72 去雾首步锁定环境，只重组内部光学层（2026-07-13）

代码核对显示当前 `environment_tint=0.16`，而 `body light` 覆盖九层、`thin glow` 覆盖前五层、
`crest veil` 覆盖前三层，另有 surface band、analytic halo 与远层 edge feather 叠加。用户同意把
D60 的首轮隔离进一步拆分：第一步连环境 top/horizon/bottom 的颜色、亮度和插值都完全锁定，只
处理内部光学层累计。

该步骤按 D63 取消独立九层 body light 并并入统一材质/透射预算，收窄 thin glow，保留低能量
crest veil；同时继续锁定 `lighten_far`、九层 alpha、远层 edge feather、水面几何和景深阶梯。
只有内部重组经真机 A/B 后仍显得过雾，才允许开启第二个独立环境色 A/B，不得在第一步中用环境
变化掩盖内部光学层的归因。

## D71 SDR 从源头不生成超白增量，不加入高光肩部压缩（2026-07-13）

用户同意：当设备、显示器、surface、实时 ratio 或录音状态不允许 HDR 时，将内容可用 headroom
直接约束为 `1.0`，使 HDR excess 从源头为零；不先生成 `>1.0` 场景值再由应用 tone-map 回 SDR。
所有既有 `<=1.0` 的 SDR 输出保持原亮度，不加入从中间调或高光以下开始的 soft knee、自动曝光、
全局压暗或峰值重分配。

该规则延续 D52 对高光压缩的真机否决：不能为了在 SDR 中模拟 HDR 层次，再次让现有高光变暗。
D58～D63 的去雾、配色和材质能量重组仍同时改善 SDR/HDR；只有 D57 定义的额外亮度维度在 SDR
能力下消失。SDR 与 HDR 继续共用同一材质计算和参数，不维护独立调色版本。

## D70 HDR 复用现有闪点生命周期，不增加专属闪光包络（2026-07-13）

代码核对确认：当前 GLES 镜面闪点是由 `FableSolGlOptics` 跟踪的持久实体，锚点强度约以
`0.30s` attack、`0.80s` release 平滑，并叠加既有慢呼吸；它不是逐帧随机出现的一帧亮点。
用户同意 HDR 直接复用该实体、位置、强度轨迹和生命周期，只扩展符合 D57/D69 条件的空间核心
亮度，不新增 HDR 专属的快速 attack、短脉冲、余辉或节拍闪光。

若真机上 HDR 闪点仍显得过于柔和，只允许把现有统一闪点包络作为单一、可回退的 A/B 项调整，
不得在 SDR/HDR 之间维护两套时间语义。受光浪峰和薄层透射继续随自身连续光学条件变化，也不套用
离散闪点包络。

## D69 最高 HDR 镜面核心趋近中性白，中间层保留身份色（2026-07-13）

用户同意细化 D58 的“同色系”边界：`1.6～2.0×` 的最高镜面闪点核心可以随亮度降低彩度、趋近
中性白，但仍保留轻微 ThingBackground 色倾向，不成为完全无身份的纯白斑点，也不得统一偏成
青白或蓝白。该低彩度只表达强反射光，不重新引入固定绝对色相。

`1.15～1.4×` 的受光浪峰和窄表面反射带应明显保留 ThingBackground 色相；`1.05～1.2×` 的
薄层透射保留最多身份色。由此形成“峰值核心最接近中性、浪峰仍有身份、透射身份最强”的彩度
阶梯。该规则修订 D58 对表面反射的绝对同色解释，但不改变只有最深传播路径允许约 2°轻微冷移
的边界。

## D68 不因假设的控件变暗预先限制 HDR 视觉上限（2026-07-13）

用户明确否决“为了保护同一 Dialog 的 SDR 文字和按钮，预先压缩 HDR 亮芯、缩小超白覆盖或自动
回退 SDR”的优先级。本轮应先完整实现 D57 的三级亮度与中等覆盖，按动画本身的视觉效果上限
验收；不得仅依据部分 OEM 可能压低混合界面 SDR layer 的理论风险，提前降低水面峰值或覆盖。

文字与控件的感知亮度只列为真机观察项，不作为当前 HDR 内容预算、能力启用或发布的先验门槛，
也不预先提亮控件补偿。只有用户在实际设备上明确认为控件表现不好时，才把该现象作为独立问题
复现、量化和裁决；届时不得静默改写已验收的 HDR 水面基线。

## D67 HDR 峰值不直接乘以音量、onset 或节拍（2026-07-13）

用户同意：HDR 额外亮度继续服从表面朝向、坡度、曲率、光向、Fresnel、薄层透射与材质能量
预算，不新增由音量、onset、节拍、prominence 或其他音频特征直接控制的 HDR gain。声音仍按
现有模型驱动波形、微表面状态与光学实体的出生条件，因此可以间接改变 HDR 高光的数量、位置、
持续时间和可见面积，但不能把同一个光学条件下的单个高光直接推得更亮。

该边界用于避免大音量时宽范围过曝、节拍闪烁和“亮度计”式表达，同时保留 Voice Waveform 对
声音的自然响应。HDR 与 SDR 仍共享同一套声音到几何/材质的映射；差异只发生在 D57 已定义的
局部受光结果是否可以超过 SDR reference white。

## D66 只有正在录音状态产生 HDR 额外亮度（2026-07-13）

用户同意：录音 Dialog 整个可见生命周期保持同一个 HDR-capable SurfaceView/EGL surface，状态
切换不得通过销毁和重建 surface 改变输出能力；但只有 `RECORDING` 状态允许场景线性结果中出现
高于 SDR reference white 的亮度。`PREPARED` 与 `STOPPED` 状态的全部内容保持 `<=1.0×`，现有
水面模拟、层级和柔和展示仍可继续运行。

进入 `RECORDING` 时，HDR 内容增益随现有水面 `0.16 → 1.0` 过渡逐步开启；停止录音时同步平滑
收回到 SDR，再保持 `0.16` 的展示状态。能力探测与 surface 配置不因状态切换反复执行；API 35+
的 desired headroom 可以随状态调整，但不得引发 surface 重建。该状态门控服从 D65 的自动能力
判定，并且只改变额外亮度，不改变几何、动画、身份色、材质语义或 SDR 基线。

## D65 HDR 自动启用，不增加正式用户设置项（2026-07-13）

用户同意：FableSol 的 HDR UI 渲染由运行时自动探测，不增加正式版手动开关。只有 API 34+、
当前显示器支持 HDR、`Display` 的实时 HDR/SDR ratio 可用且大于 1、FP16/scRGB EGL config 与
SurfaceView window surface 均创建成功时，才启用 HDR 输出；任一条件不满足或运行中 headroom
降至不可用时，自动回退同一 SurfaceView、同一场景结果的 SDR 输出。

API 35+ 可对 SurfaceView 请求 D57 所需的约 `1.5～2.0×` desired HDR headroom，并继续服从
系统返回的实时 ratio；API 34 不假定固定 headroom。Debug 版可以提供能力状态、false-color、
强制 SDR 和受保护的 HDR 探针，用于诊断与 A/B，但这些不构成面向用户的外观设置，也不得绕过
实际 surface/display 能力强制提交无效 HDR。正式版不因 HDR 自动切换而改变几何、动画、身份色、
材质语义或 SDR 基线。

## D64 渲染容器由 TextureView 改为统一 SurfaceView（2026-07-13）

用户确认：Android 官方能力表将 `SurfaceView` 标为完整 HDR 支持，而 `TextureView` 只在
Android T+ 提供有限 HDR 支持，因此 FableSol 的 GLES 容器由 `TextureView` 改为
`SurfaceView + 自管 EGL`。API 26+ 统一使用同一个 `SurfaceView`，不维护 HDR 设备使用
SurfaceView、旧设备继续 TextureView 的双容器分支；API 26～33 输出同源 SDR，API 34+ 仅在
显示器、实时 headroom、FP16/scRGB EGL 链路均满足时启用 HDR。

SurfaceView 保持在宿主窗口下方，不调用 `setZOrderOnTop(true)`，录音文字与控件仍由普通 View
叠在其上。由于 API 34 以前 SurfaceView 忽略 `0 < View alpha < 1` 的中间透明度，准备态与停止态
的 `0.16 ↔ 1.0` 过渡改为渲染器内的 presentation alpha，不再依赖 Host/View alpha。圆角也不得
假定普通 View outline 能裁切独立 surface；渲染器必须通过带 alpha 的输出明确形成圆角，并把
API 26、API 34 与 API 35+ 的无矩形漏边、控件遮挡、弹窗动画和 surface 重建列为发布门槛。

Android N 起 SurfaceView 的平移与缩放会和 View 渲染同步，项目 minSdk 26 已覆盖该边界；因此
现有弹窗约束不足以继续承担 TextureView 有限 HDR 的代价。本决策修订 D41、D56 与 ADR-0016，
但不改变 D40 的同源材质约束，也不授权新增第二套水体实现。

## D63 只保留 crest veil 作为独立柔雾通道（2026-07-13）

用户确认：为保留适度雾感，`crest veil` 继续作为唯一独立的柔雾通道，但必须保持低能量、克制覆盖，
并严格留在 SDR reference white 以内。它表达波冠附近的风格化柔化，不承担主要亮度，也不得通过
扩大范围补偿表面反射或透射。

现有九层 `body light` 不再作为独立宽光带叠加，而应并入统一的透射/体色计算，与 Fresnel 反射
共享能量预算。`thin glow` 继续表达较窄的浪峰透射；三者不得再重复表达同一片内部亮度。具体
`crest veil` 强度和宽度先以独立 A/B 校准，不修改 D59 的景深阶梯。

## D62 晶亮感以表面反射为主、内部透射为辅（2026-07-13）

用户确认：本轮亮度与晶亮感主要由表面反射、受光浪峰和镜面闪点承担；浪峰内部透射只作为较窄、
较弱的辅助，不再用大面积 body light 或 crest veil 塑造整体内发光。高光允许在材质上更集中，
但不得改变现有柔和浪形或把宏观波峰变尖变窄。

后续光学能量预算必须先满足反射主、透射辅的层级，再应用 D57 的 HDR 三级亮度。宽范围内部光
只能保留在 SDR 基线内，且不得通过扩大覆盖来补偿被削弱的峰值。

## D61 首轮不加入折射或焦散（2026-07-13）

用户确认：本轮先用现有反射、浪峰透射、光学层能量重组与 HDR 完成清澈度提升，不新增背景折射、
填充视差或焦散。此前 A5.5 的折射视差与多项结构变化组合已被整体否决；当前第 0 层不透明，也
缺少可被真实看穿的背景语义，不能为了“剔透”直接恢复假折射扰动。

只有上述主路径完成并经真机确认仍缺少透明介质感时，才允许把轻微折射作为单一、小幅、可完整
关闭的 A/B 项独立试验，不得与层级、配色、焦散或波形变化同批。焦散仍维持既有整体删除结论，
本决策不提供恢复条件。

## D60 首轮去雾对照锁定水层景深阶梯与远层羽化（2026-07-13；执行顺序由 D72 修订）

用户确认首轮隔离范围：`lighten_far`、九层 `alpha` 以及远层 `edge feather` 的强度和宽度保持
现状，不在同批调整。首轮只允许修改环境底色，以及 body light、crest veil、thin glow、halo
等内部宽柔光的颜色与能量关系，用于验证过量雾感是否主要来自环境和光学层累计。

该对照不得改变水面几何、波形、层级顺序、ThingBackground 身份色或音频映射。环境变化可能
改变 edge feather 采样到的颜色，但其几何、alpha 与出现条件仍须保持不变。首轮结果若已经清澈且
层级稳定，就不再调整景深阶梯；若仍需修改，返回 D59 的相邻层可辨识约束另行裁决。

2026-07-13 修订：D72 将本范围拆成两个独立步骤。第一步连环境也锁定，只重组内部光学层；仅当
结果仍过雾时，第二步才允许单独调整环境。

## D59 保留水层景深阶梯，不以完全去雾为目标（2026-07-13）

用户明确：不同水层越远越偏白、越透明，是区分层级的既有设计职责；优化不能把各层颜色拉近到
互相混合。目标是减少过量的材质泛白和柔化，而不是完全取消雾感或空气透视。

后续必须把两类现象分开处理：

- 水层景深阶梯：按深度单调提高明度/混白并降低 alpha，用于九层水体的前后分离，必须保留；
- 材质雾感：近白环境色与 surface band、body light、crest veil、thin glow、edge feather、halo
  等宽柔光累计形成的低对比泛白，可以重新分配和收敛。

“同色提亮取代混白提亮”只作为待验证候选，不得直接全局替换景深阶梯。首轮对照应锁定既有水层
颜色/透明度阶梯，只调整环境与内部光学层，以隔离雾感来源；若仍需修改景深阶梯，必须保持相邻层
可辨识度和远近单调性，并再次经用户验收。

## D58 表面中性同色，仅最深传播路径允许极轻微冷移（2026-07-13）

用户确认取消所有固定绝对色相目标：`thin glow` 不再向 165°偏移，deep 不再向 220°偏移，
subsurface 不再向 150°偏移。表面反射、受光浪峰与薄层透射均保持 ThingBackground 的同色系，
不得跨记事颜色持续注入统一的青蓝或蓝绿色气质。

只有最深水层中具有足够传播路径的体色可以保留相对当前身份色不超过约 2°的轻微冷移，用于维持
纵深，而不是作为全局水体色温。次表面透射默认保持同色或随光源产生克制的中性提亮，不使用固定
绿色目标。本决策修订 D53 的 deep/subsurface 色相部分；D53 的轻量双色结构、明度/彩度派生与
独立强度开关不因本次裁决自动删除。

2026-07-13 修订：最高 HDR 镜面核心允许按 D69 趋近中性白；中等亮度浪峰与薄层透射继续保持
身份色。该镜面去彩度不视为固定色相偏移。

## D57 HDR 覆盖不得仅限极稀疏闪点核心（2026-07-13）

用户否决“只有极少数镜面闪点核心进入 HDR”的过度保守分配：若正常观看时与现有 SDR 的差异
不明显，就没有达到加入 HDR 的目的。兼容设备上除少量最高亮度核心外，还应让更多实际受光的
浪峰段和薄层透射以较低增益进入 HDR，形成可明确察觉但仍有层次的中等覆盖。

用户确认采用三级内容亮度分配，数值均表示相对 SDR reference white 的场景线性倍数，并在运行时
服从设备实际 headroom：

- 闪点核心与最强浪峰约 `1.6～2.0×`；
- 较多受光浪峰与窄表面反射带约 `1.15～1.4×`，作为正常观看时主要可见的 HDR 差异；
- 少量浪峰薄层透射约 `1.05～1.2×`；
- 环境、水体基色和宽光晕不得超过 `1.0×`。

本决策不授权抬升环境、整片水体基色或宽范围均匀光幕；额外亮度仍须由表面朝向、曲率、光向与
透射条件约束。设备可用 headroom 低于目标时，各级亮度保持顺序并连续压缩，不得通过提高 SDR
基线补偿。

## D56 HDR 只放宽兼容设备上的受控局部高光亮度（2026-07-13；覆盖由 D57 修订）

用户确认：D40 的 API 26+ 一致性继续严格约束水面几何、动画时序、材质语义、ThingBackground
身份色与 SDR 基线；但在 API 34+ 且显示器、当前 headroom、EGL 扩展和 SurfaceView 实测均满足
条件时，允许受控高光区域使用 SDR reference white 以上的额外亮度。API 26～33、非 HDR 显示器或
能力探测失败时必须回退到同一材质的 SDR 输出，不得改变波形、配色身份或动效。

这项放宽只用于真正的 HDR 亮度维度，不重新授权 AGSL、设备专属几何、额外材质效果或其他
按 API 分级的视觉差异。Display P3 等广色域能力与 HDR 分开命名、分开探测，不能用扩大色域
冒充提高动态范围。HDR 覆盖范围由 D57 继续修订。

## D55 四项持续质感作为可独立关闭的一批接入（2026-07-13）

应用户明确要求，本批同时接入 1/f 全局呼吸、风梳微法线、朝阳 SSS 与闪点解析光晕，作为 D50
“逐项验收”的一次显式例外。四项分别由 `global_pink_breath_strength`、`micro_normal_strength`、
`sun_sss_strength` 与 `analytic_halo_strength` 控制，任一参数归零时不得影响其余三项。

1/f 呼吸只调制持续环境波幅、稀有二维波包的出生间隔和镜面闪点的新生速率，不改写已经形成的
音频主浪，也不让已有闪点随呼吸消失。风梳微法线由水体片元 shader 的三倍频解析导数值噪声生成，
沿 `surface_heading_deg` 拉伸和推进；每个倍频按远近行采样足迹带限，并复用
`specular_aa_strength` 控制过滤过渡。朝阳 SSS 只读取固定日照方向、视角、深度、同色派生的
subsurface 色与 `crestPinch`，方向瓣指数限制在 4～10，禁止接瞬态音频。解析光晕作为镜面闪点
亮芯之前的曲面内侧实体，使用数学指数衰减，不使用模糊纹理或越过水面轮廓。

## D54 解析镜面抗锯齿接入真实闪点坡度高斯路径（2026-07-13）

当前 GLES 镜面闪点不是 fragment shader 的传统 `pow(N·H,p)`，而是
`FableSolGlOptics.buildGlints()` 用 `exp(-(Δs/σ)²)` 对宏观坡度与十项毛细坡度谱选峰，再生成
持久曲面内侧光带。因此 Stage 2-3 不新增无消费者的 shader 指数，而在
`FableSolOpticalWaveSet` 按当前列采样足迹解析带限：每个波长在每波 2 个样本以下完全转为方差，
4 个样本以上完整保留，中间用 smoothstep 过渡。

被带限的坡度方差按高斯卷积关系进入 `σ_eff²=σ_base²+2·variance`，被带限的曲率方差以统计
RMS 补回稳定的微表面活性，并以 `σ_base/σ_eff` 保持一维积分能量。只有闪点选取使用带限后的
slope/curvature；体积光等既有光学
继续使用未过滤毛细坡度。`specular_aa_strength` 独立默认 1，设为 0 时过滤量和方差均为 0，逐值
恢复原闪点路径。此项不改变闪点实体数量上限、跟踪、颜色、曲面内侧几何、双色散射或水面运动。

## D53 Stage 2-2 采用轻量双色深度散射，不改变现有高光（2026-07-13；色相由 D58 修订）

高光压缩回退版已获用户确认，继续执行 D45 的下一项“双色深度散射”。每个水体渐变色在 CPU
的 OKLab/OKLCH 语义下派生 deep 与 subsurface：deep 使用 `L×0.70、C×1.15`，向蓝绿色最多
偏 8°；subsurface 使用 `L×1.15、C×0.85`，向绿色最多偏 4°。超出 sRGB 时沿同一 OKLab
色相收缩彩度，不用逐通道硬裁切改变色相。

GLES 顶点新增 Gerstner 横向轨道位移导数形成的浪峰收拢量；shader 只按远近视角、收拢量和
既有固定光向混合两个派生色，不接音频瞬态。`depth_scattering_strength` 独立默认 0.21，避免
大面积压暗；现有相对纵向受光、高光、光学实体、波形和运动均不修改。本项单独真机验收，
不满意则连同色板、顶点属性、shader 分支、参数和测试整项删除。

2026-07-13 修订：deep 向 220°最多偏 8°、subsurface 向 150°最多偏 4°的绝对色相目标退出
目标视觉，替换规则见 D58。

## D51 PBR Neutral 只作为线性高光 shoulder，不改 Stage 1 中间色（2026-07-13）

接近白色的高光平滑收束且不改变通道差方向。

③解析镜面抗锯齿（波分量坡度方差→高光指数）④风耦合（Cox-Munk 闪点统计与

真机、做不好整项砍（宁少勿烂）；A5.5 教训继续有效——不得同批同时改变层次、
颜色和表面结构。技法出处与参数细节见

## D37 前后俯仰采用完整输入与分通道软压缩（2026-07-12）

用户确认 `±55°` 并非必须，要求优化前后俯仰的临界停止。旧链路先在传感器入口和
`FableSolSimulation.setPitch()` 将角度硬截为 `±55°`，连续曲面内部再次截断；同时渲染观察角
以 `38°` 为基准硬限制在 `14°~68°`，使静态透视实际在前俯 `+30°`、后仰 `−24°` 就进入平台。

新增 `FableSolPitchPolicy`，把三种语义拆开：`pitchDeg` 保存手机完整 `−90°~90°` 俯仰；
`motionPitchDeg` 用归一化 `atan` 曲线将完整输入单调软压缩到 `±55°`，继续保护水体惯性幅度；
观察角用响应更快的归一化 `atan` 曲线，把完整输入按基准两侧分别软压缩到 `14°~68°`。
两条输出在整个物理范围内严格单调，只有手机到达 `±90°` 才到安全端点，不再在中途形成平台。

连续曲面的欠阻尼弹簧改用 `motionPitchDeg`，纵深透视改用原始 `pitchDeg` 经策略映射；内部
`±55°` 仅作为不接受越界目标的防御性安全阀，不再直接作用于传感器输入。该设计保留原最大
惯性幅度和观察角范围，同时让普通角度附近保持较快响应、越接近极限变化越缓。本决策取代
D30 中“手机法向分量转换为 `±55°` 前后俯仰”的输入限幅约定。

## D33 显式阴影统一由当前层颜色混黑生成（2026-07-12）

用户真机发现浪面经常出现难看的灰黑区域，要求阴影改为更深的记事颜色。诊断确认两条
显式路径违反该语义：猫爪暗纹把所有层色混入固定蓝黑 `#080C16`；波背自阴影采用
OKLab 固定降明度后再冷偏 `−hue_temp_deg`，部分颜色会丢失原记事色身份。

新增 `FableSolShadowColorPolicy` 作为唯一显式阴影颜色入口：波背阴影使用当前层色在
OKLab 中混黑 18%，猫爪暗纹混黑 24%。两者不再接受固定灰黑/蓝黑色，也不再做额外冷暖
色相偏移；几何强度、透明度、出现条件、空气透视和连续水面物理不变。深度吸收的标量
暗化本身等价于基色混黑，不属于本次固定偏色问题。

## D34 阴影混黑量随层深递减（2026-07-12）

用户指出 D33 的固定混黑比例仍不正确：远层水体本身经过空气透视已经更淡，同样比例的
黑色会在远层形成更显眼的暗斑。波背和猫爪的有效混黑量统一乘
`max(0.35, 1 − 0.85×depth01)`；第 0 层保持 D33 的 18%/24%，越远逐层降低，最远层
最多保留基础黑度的 35%。

当前波背只绘制到第 5 层，其混黑量约由 18% 降至 8.4%；猫爪只绘制到第 2 层，约由
24% 降至 18.9%。该衰减只改变阴影色，不重复修改已有的层 alpha、空气透视或阴影几何，
避免远层被多套规则直接裁掉。

## D35 远层阴影黑度采用平方衰减（2026-07-12）

用户进一步明确“远方的黑色要很淡很淡”。D34 的线性衰减与 35% 下限仍过重，改为
`max(0.05, (1−depth01)²)`。波背基础 18% 因而在第 2 层约为 10.1%、第 5 层约为
2.5%、最远端约为 0.9%；猫爪基础 24% 在其最远参与的第 2 层约为 13.5%。

平方曲线让近层保持可读阴影，中远层迅速淡出；5% 是对基础黑度的比例下限，不是直接
混黑 5%，因此最远波背实际只混黑约 0.9%。

## D36 纵向法线负向受光收敛到基色混黑轴（2026-07-12）

用户复测指出主要灰黑区域并非波背或猫爪，而是与光线相关。定位到连续水面新增的
`applyLongitudinalLight()`：完整三维法线与旧二维法线分别计算 `N·L`、透射和 Schlick
Fresnel 后，旧实现用 `base + full − reference` 逐 RGB 通道相减。背光坡的负差值中包含
天空反射色差，会让主题色同时丢失明度与色彩身份，形成大面积灰黑。

保留完整物理候选色的明暗判断：候选亮度不低于基色时原样保留正向受光与天空偏色；候选
更暗时，只提取相对亮度下降量作为阴影强度，并重新生成基色混黑结果。近层最大混黑 14%，
实际量乘 `sqrt(darkness)`；层深继续乘 D35 的 `max(0.05,(1−depth01)²)`，远层负向受光
接近不可见。实现使用 packed ARGB 与通道乘法，避免在逐顶点路径增加对象和 OKLab 开销。

## D30 Android 默认采用连续 2.5D 水面，旧九层渲染仅作内部回退（2026-07-12）

## D31 连续水面使用投影安全采样窗与分层批量网格（2026-07-12）

真机首轮发现 Z 轴翻滚时远处水体两侧偶发空白，且整体明显卡顿。连续路径不得再复用

LinearGradient。每个相邻九层锚点之间的 3 条 ribbon 合并为一次带逐顶点颜色的三角网格，

## D32 倾斜时固定连续渲染列预算，边界剖面只以 30Hz 更新（2026-07-12）

用户复测确认常态播放不卡，主要卡顿集中在倾斜手机期间。诊断发现宽 276dp 时，投影安全
采样窗的原始列数会从水平 `110` 增至 `30°=172`、`45°=186`、`60°=190`、`90°=160`；
若全部直接送入 25 行网格、顶点着色和九层光学，倾斜期间渲染工作量最高增加约 73%。

连续路径实际渲染列数因此固定为最多 120 列：水平原始列数不足 120 时全部保留，超过时在
完整安全窗口两端之间等距插值；首尾必须精确对应原始窗口首尾，不能以丢弃画外列换性能，
故 D31 的两侧覆盖保证不变。物理模拟仍使用完整 216 点网格，只有渲染投影降采样。

同一诊断还发现 `rebuildBc()` 在持续倾斜 2 秒内重建 227 次，几乎跟随 120Hz 物理子步；
原因是 `span`、`wallBlend` 和 `tiltAgit` 每个子步都改变缓存键。边界剖面是空间阻尼系数，
统一限为 30Hz 更新，最大滞后 33ms；波方程仍以 120Hz 求解，倾斜浪形激励和传感器输入
不降频、不额外低通，以免改变姿态手感。

## D29 文件名行与计时器共享水平约束（2026-07-11）

录音结束后，文件名输入框与 `.wav` 后缀的可见总长度必须与 `TimelyClockView` 一致。此前文件名行
外层写死为 `232dp`，内部又将 `EditText` 和后缀分别写死为 `192dp`、`40dp`；虽然外层数值碰巧
等于对话框宽度减去计时器两侧边距，但 `.wav` 文本不会填满固定的 `40dp`，可见右边缘会提前结束，
而且两处约束容易独立漂移。

文件名行与计时器统一使用 `match_parent` 加两侧 `24dp` margin；`EditText` 使用
`0dp + layout_weight="1"` 占据后缀之外的剩余空间，`.wav` 后缀使用 `wrap_content`。今后调整
计时器的水平边距时，应同步调整文件名行，保持两者等宽。

## D14 美学章程：克制的抒情（2026-07-11）

升级方向定位采用"克制的抒情"：以平静陪伴为基底（录音对话框里用户的主任务是说话，

一句话章程（暂定措辞）："你的声音是掠过一小片真实水面的风——它服从重力，短暂记住
你的能量，在你说完时归于平静。"运动总则："静中有动、动中有静"。

**范围事实**：当前主打麦克风录音可视化（录音内容可能包含音乐）；后续将加入离线音乐

**为何**：设计奖调研显示评审奖励克制、同步感与概念纯度（Odio/Journey/Monument
Valley 先例）；"准确反映声音"与"获奖美感"在 B 定位下不冲突。

## D15 表达状态：锚点配方 + 连续插值，非离散状态机（2026-07-11）

mood 性格档的继任机制：七个外观锚点（idle / silence / quiet-speech / active-speech /
melodic / loud-music / climax（瞬态）+ settle（尾声））各自是一组完整参数预设（波长
分布、chop 量、闪带宽度、猫爪率、驻波增益等）+ 触发条件；运行时由感知输入（响度
包络、4Hz 波动强度、谐波性、粗糙度、speech/music 门控、arousal）在锚点间**连续插值**，
迁移带迟滞与不对称时间常数（升快降慢）。用户永远看不到状态切换。

**境不是旅程而是查询表**（蒲福风级语义）：平淡人声整段录音只驻留 quiet-speech ↔
active-speech，表达力来自境内微观动态（4Hz 呼吸、音节猫爪、闪带宽窄、句中悬停、
句末沉降）；melodic/loud-music/climax 仅在录到歌唱、音乐、喊叫时出现。这同时修复
现状 mood 无锚点漂移导致普通语音落在未调参组合的问题。

命名：代码用功能名；马远《水图》对应题名（洞庭风细、湖光潋滟、层波叠浪、云舒浪卷、
细浪漂漂等）保留在文档与注释中，作为灵感来源与设计词汇。调参主战场明确为
quiet-speech / active-speech 两境的境内动态。

## D16 乐队分层：九层职责重分配，深两层"无动于衷"（2026-07-11）

取代"每层听全频段、远景=高频几何"的 `LAYER_ROLE_WEIGHTS` 模型：

- 装饰层（0~1）：onset/爆破音的水花与毛细闪光——高频内容改由前层**光学**表达；
- 旋律层（约 2~3）：音高轮廓与重读（语音主唱）；
- 织体层（4~6）：音节密度纹理 + 慢频段包络；
- 深层（7~8）：**永不响应逐帧人声**，只承载永恒慢涌，并以数十秒时间常数跟随能量
  积分与段落（"长曝光"语义）。

**为何**：Chion anempathetic 原则——有"不在乎的世界"，上层响应才读作"倾听"而非
仪表；透视上远水本就动得更慢更少，"远层跟齿擦音抖"违背距离感；高频以近层闪烁
表达（Journey glitter 纪律）比远层几何波动更像空气感。

**实施流程**（适用于本轮全部表达/映射改动）：先在 `audioVisualizerSimulatorFable`
Python 版实施，用户目测认可后再同构移植 Android/Kotlin 并补差分测试。

**修订（2026-07-11 用户目测）**：深层长积分只在**有声期间**生效；静默/停止后深层
以 τ≈2s 与全场一同快速归静，不做数十秒余韵沉降（第 8/9 层拖几十秒不落被明确否决）。
涌浪沉降半衰期同日由 6s 调至 3s。"结束沉降"整体求快、不求余韵。

## D17 三层时间记忆 + 波群包络，且包络只作用于浪的出生处（2026-07-11）

时间结构分三层：风浪 chop 即时跟随音节（现有注入+毛细纹）；涌浪 swell 以半衰期
积累短语级能量，是"结束沉降"尾声的本体——**默认半衰期 3s**（用户 2026-07-11 目测
6s 沉降过慢后修订；参数范围 1.5~10s 可调）；深层
（7~8）以 20~40s 长积分跟随整段录音能量史。涌浪对水位的贡献设上限并计入体积守恒，
防止长录音水位持续偏高。

响度进入涌浪 register 采用**波群包络**：能量以组为单位（一组约 2~4 个浪）乘载，
浪在组内生于尾、亡于首；一句话成为一组浪，句间停顿是组间间歇。

**D12 延伸（用户 2026-07-11 强调）**：已塑形的浪不得被随意改形（不得在波峰附近
凸起小包、不得突然变尖或变平），除非改变是必要、柔和且符合物理的（如新浪从边界
涌入引起的自然相互作用）。因此波群包络与涌浪记忆均只在**浪的出生处**起作用——
新生浪的振幅由包络/能量库决定，随后按正常物理传播；绝不以乘性场调制已存在几何。
水位类变化仅允许潮位式的缓慢均匀偏移。

## D18 注入反克隆纪律；"张力=相位"按受控边界试做（2026-07-11）

用户报告现状缺陷：强事件下九层在右侧同一位置出现九个近似相同的波包并同步流动，
"像复制粘贴一样"。成因是 `inject()`/`injectRhythmWave()` 对全部九层循环注入，抖动
（σ=7~16dp）相对波包宽度（100~216dp）过小、逐层固定延迟、形状同源。纪律：

- 同一事件的注入目标只限其**角色层**（D16），任何单一事件不得进入超过约 3 层；
- 逐层时序来自波群包络的自然传播差，废除全层固定 cascade 延迟；
- 逐层宽度/峰形/travel 独立变化，空间散布量级须与波包宽度可比；
- rhythm wave 重设计为单层（或两层交替）的单一行波，不再是九层齐发。

"张力=相位"（Whitney）采纳为试验项：以各层有效推进速度的缓慢偏置实现（洋流式、
浪形连续），相干度上限约 0.6 永不完全对齐，触发需持续数秒渐强证据 × speech/music
门控加权（平淡语音不触发）；静息态回到失谐（不均齐为常态）。对齐只作用于 hero
长模态相位，绝不同步化注入事件，避免再造克隆感。优先级在双 register 与乐队分层
之后，Python 先行。

## D9 自校准前增加频率边界与绝对可听度安全门（2026-07-10）

Android 近静音录音可能包含近 Nyquist 强电子干扰、低频嗡声和非平稳 AGC/噪声泵动。纯相对静音门与
flux 百分位会把这些不可闻或极低电平变化放大成约 0.5 响度和密集 onset，因此“自校准”不能等于
“完全没有绝对可信度边界”。

FableSol 前端统一采用以下规则，Python 蓝本与 Kotlin 实现保持一致：

- A 加权总能量、底噪、质心与平坦度只使用 16kHz 以下频谱；
- 32 个 flux 对数频带严格按相邻边界 `[edge[i], edge[i+1])` 求和并止于 12kHz，不再使用
  `reduceat` 最后一段延伸到 Nyquist 的语义；
- Analyzer 和时间基准重置后从静音状态启动；
- −66dBFS 为零可听度置信、−54dBFS 为满置信，中间采用 smoothstep；响度、低/中/高频动态与
  onset 包络/强度统一乘该置信度。绝对门仅拦截极低电平假活动，可信声音进入后仍使用原有底噪、
  慢中心和滚动百分位自校准；
- flux 环接收全部帧作为基线，保证稀疏真实脉冲无需先积满多个“有声帧”。

回归样本 `20260710215433.wav` 在 Python 48kHz 路径由 90 个假 onset 降至 3 个、平均响度由
0.272 降至约 0.004；Android/Kotlin 原生 44.1kHz 路径为 4 个 onset、平均响度约 0.008。

## D10 Android 重力倾角覆盖完整圆周并保持 Opus 方向锁定语义（2026-07-10）

录音 Dialog 的重力可视化必须接受完整 360° 屏幕平面方向。完全倒置手机时渲染角保持 ±180°，

传感器角度跨越 179°↔−179° 时，Simulation 选择与当前角度最近的等价角，避免水体反向旋转 358°。
墙面过渡按水面偏离水平面的角度计算，因此 0° 和 180° 都视为水平水面。

`AudioRecordDialogFragment` 在 `onCreateView()` 锁定宿主 Activity 的当前方向，并在
`onDestroyView()`/`onDismiss()` 恢复原 `requestedOrientation`。该代码在 Opus→FableSol 迁移中没有

## D11 Android 采集会话启动阶段抑制低频暂态（2026-07-10）

部分手机的 AudioRecord/MIC 在采集启动后会输出持续数秒、随后衰减的强低频暂态。样本
`20260710231609.wav` 前 0~3 秒约为 −20~−23dBFS，A 加权能量约 70%~90% 位于 250Hz 以下，
约 4.5 秒后才降至 −55dBFS 以下。该信号真实存在于 PCM；应用当前显式关闭 AGC/NS/AEC，不能把它
简单归因于应用层“先录噪音、再开始降噪”。

Kotlin Analyzer 在每个采集会话开头增加自适应预热门：低频主导且尚未稳定的输入不进入底噪、中心、
flux 与视觉输出；连续稳定静音或可信非低频内容达到 0.3 秒后立即开放，最多等待 4.5 秒。若超时后仍是
低频背景，则把当前电平种为噪声底。该门只影响 FableSol 可视化，不裁剪、滤波或延迟保存的 WAV，
避免在用户未授权的情况下改变录音内容。

## D12 已形成的浪形不得被瞬态参数直接重塑（2026-07-10）

已经显示的浪只能因相位传播、波动方程、阻尼、边界、重力，或显式注入的新能量自然变化。
onset 不得直接改写整层 HeroWave 的振幅和频段模态；快速事件统一进入有穿屏限流的 DynamicWave
物理波包。HeroWave 只表达慢变化的声音背景：默认攻击由 0.16 秒改为 0.85 秒，各模态最短约 0.72 秒；
几何粗糙度另用 1.2 秒慢状态，快速粗糙度/毛细度仍可用于光学高光，但不能重塑宏观轮廓。

真实样本的拍击 onset 位于约 6.30、6.76、7.15、7.26 秒。禁用物理注入时，旧 onset 仍使既有轮廓在
6 帧内变化最高约 0.56dp RMS；极端频段目标单帧变化约 3.97dp RMS。修复后前者严格为 0，后者约
0.39dp RMS；真实拍击窗口不再出现远层同步突变，剩余变化来自连续传播和新注入的物理能量。

## D13 连续流速由表层事件率主导，节拍不得删除 subdivision（2026-07-11）

人的主观速度由表层事件密度、节拍层级和强弱等多种线索共同决定。FableSol 的连续流速采用 1 秒快速事件率与 3 秒保持事件率：快速通道以 72% 权重负责及时上升，慢速通道作为下限负责稳定与自然释放。已通过 D9 绝对可听度/SNR 边界的 onset，在显著度加权之外固定保留 75% 原始 subdivision；`beatConfidence` 不得再降低该保底。

tempo/phase 继续负责节拍脉冲和相位同步；tempo 对连续流速仅能在剩余行程内提供最高 12% 的正向佐证，不得以中等 BPM 向下覆盖已经较高的表层事件密度。onset strength 主要控制波高、注入能量、punch 与材质。分析侧速度攻击为 0.35 秒，Simulation 流速执行平滑为 0.48 秒；物理流速上限和全局 `flow_gain` 不因本决策提高。Python 与 Android/Kotlin 必须维持同构实现。

**为何**：固定 3 秒分母会把新出现的密集声音系统性低估约 3 秒；可靠节拍下删除弱 subdivision 会把快速元音或密集音符误判为中速；tempo 与 density 的凸组合还会让约 110 BPM 反向拉低每秒 6~8 个事件的表层速度。两段 Android 真机录音证明瓶颈位于感知映射，而不是 213.6dp/s 的第 0 层物理上限。

## D14 GLES 倾斜期间边界剖面按显示帧限额重建（2026-07-12）

连续倾斜会让 `span`、`wallBlend` 与 `tiltAgit` 持续变化。边界剖面仍以最高约 30Hz 接受新参数，
但九层不得再集中在一个显示帧内重建：除首次初始化外，每帧最多处理 5 层，下一帧完成其余层；
即使该帧因延迟补跑多个 120Hz 物理子步，也不得突破显示帧预算。

边界系数只依赖 `abs(u)`，左右点必须共用同一次计算并镜像写入，保证数值与逐点实现一致、把每层
指数运算减半。传感器采样、120Hz 波方程、倾斜几何和水体惯性不降频。Debug 性能日志继续保留
`physics` 总耗时，并增加 `steps`、`bcLayers`、`bc`、`waves`、`surface`、`compose`，用于真机判断
剩余卡顿是否仍来自边界重建。

## D15 GLES 光学实体保留 CPU 身份跟踪并按层穿插绘制（2026-07-12）

闪点、珍珠、流光和猫爪属于数量少、生命周期逻辑复杂的实体，不转成片元着色器内的逐帧随机噪声。
CPU 继续维护跨帧身份、锚点匹配、攻击/释放、顺流平移与寿命；每帧只生成少量带局部 UV 的椭圆
三角形，GLES 片元着色器负责径向软边。实体总量使用固定上限与预分配顶点缓冲，稳态不扩容。

绘制顺序必须复刻 Canvas 层遮挡：每个远侧水层区间画完后立刻画该层实体，再由后续近层覆盖；
最后画第 0 层深水填充和第 0 层实体。不得把所有实体统一放到水体之后，否则远层闪点会错误浮到
近层水面之上。光学实体使用标准 alpha 混合，水体主体仍保持不透明覆盖与原有逐层合成。

## D16 顺流流光采用水体内侧单边几何（2026-07-12）

流光不得使用“中心点切线上的直椭圆”。其长轴必须沿整段水面轮廓分段采样并随曲率弯曲；短轴从
每个采样点的轮廓开始，只向水体内部展开。片元透明度在轮廓后的短距离内从零软入，并在长度两端
与水内下缘软出。这样既不会有高光从长轴两端或短轴外侧露到空气中，也不会因硬裁切形成新亮边。

闪点和珍珠不受本决定影响：它们分别表达贴边镜面闪光与圆峰斑块，有各自的跨轮廓视觉语义。
回归必须同时检查实际流光网格的局部法向坐标全部非负，以及每个顶点均位于其横坐标对应的水面
轮廓以内；不能只检查中心切线、最终顶点数量或截图主观结果。

## D17 镜面闪点与顺流流光必须分通道约束（2026-07-12）

镜面闪点 `glint` 是高 alpha、偏白、随受光峰锚点呼吸和跟随的长高光；顺流流光 `streak` 是低
alpha、按寿命持续随背景流平移的高光。二者视觉上都可能呈斜带，但身份、运动和亮度不同，诊断、
顶点范围记录与回归必须分开。

镜面闪点不得继续使用跨轮廓的完整直椭圆。保留其峰值检测、持久身份、位置跟随和呼吸强度，几何
改用与流光相同的逐段曲面带：沿整段轮廓弯曲、只向水内展开；镜面闪点另用更窄的亮芯和更长的
软出区，避免形成锐利平直白线。固定光学顶点容量提升到 1536，只增加预分配上限，不允许稳态扩容。

## D18 珍珠斑与猫爪暗纹退出目标视觉（2026-07-12）

珍珠斑 `pearl` 与猫爪暗纹 `gust` 从 Android GLES、Canvas 回退、Simulation 状态和 Mapper 事件
入口整体删除。不得保留不可见跟踪器、阵风 FIFO 或逐帧推进；Python 同构清理由后续双端收敛时
处理，本轮 Android 主线不再生成或消费这两类效果。

保留镜面闪点 `glint` 与顺流流光 `streak`。Stage 1 下一批按现有 Canvas 语义迁移表面软带、薄峰
透光、波背阴影和最远两层羽化，不借删除两项效果之机改变其他光学参数。

## D19 四类表面效果统一使用分层曲面带（2026-07-12）

表面软带、薄峰透光、波背阴影和远层羽化进入 GLES 时统一由 `FableSolGlOptics` 生成沿轮廓的
可变厚度三角带，复用同一预分配顶点缓冲与分层穿插绘制，不恢复 Canvas Path/Gradient 或另建
每效果纹理上传。

- 表面软带仅 0～6 层，宽度由迎光坡、上凸曲率和深度共同控制；
- 薄峰透光仅 0～4 层，继续使用高出均线 4～14dp 的绝对海拔门与上凸薄度；
- 波背阴影仅 0～5 层，颜色继续走当前层记事色混黑、随深度快速减弱；
- 羽化仅 7～8 层，以 `calm01` 控制环境地平色跨轮廓溶解。

前三项只向水体内侧展开；羽化为溶解轮廓，可按既有语义跨越轮廓两侧。片元着色器只根据带内
相对深度软入软出。光学顶点固定容量提升为 20000，覆盖最坏层数与 120 列，不允许运行时扩容。

## D20 GLES 曲面带透明度严格复刻 Canvas 半正弦（2026-07-12）

Canvas/AGSL 定稿的 fade 带透明度为 `baseAlpha × 0.66 × sin(π·relativeDepth)`，峰值 0.66，
归一化积分光量为 `0.66×2/π≈0.420`。GLES 表面软带、薄峰透光、波背阴影和远层羽化必须使用
同一剖面；不得使用中央覆盖率 1.0 的宽平台。

几何厚度继续按 Canvas 的原公式，不因视觉白边问题先行缩窄。若峰值和积分偏高，同宽几何会同时
显得更白、更厚；应先恢复剖面一致，再由真机判断是否还存在颜色或几何偏差。峰值与数值积分必须
有自动回归，防止后续 shader 调整重新放大量层边缘。
