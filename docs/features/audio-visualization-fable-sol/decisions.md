# 决策记录 · audio-visualization-fable-sol

## D138 层内 continuous sheen 整体退出，不再以点、短划或光带替代（2026-07-15）

用户复核 D137 的动态截图后确认：原扩缩光带虽然消失，但稳定微面片把同一效果缩成了分布在每层
内部的斜短光点，仍然不好看；这些点再次明确不是位于水体边缘的离散 `glint`。因此 D137 的
固定微面片方案被否决，层内 continuous sheen 的可见 SDR 反射、HDR excess 及其配套暗斑整体
退出，不再换成另一种点、线、环或 patch 图案。

共享 shader 删除固定微面片、GGX/Smith 连续太阳反射、bounded SDR reflection、同源 facet
暗面与 HDR sheen excess，同时删除 `uSunReflectionCoverageWeights`、`uSheenCoverageScale`、
`uHdrSheenPeaks` 及对应 varying。Android/Python 的连续 sheen 峰值表、覆盖率表、渲染上传和
`sheen_patch_scale`/`sheen_intensity` 参数一并删除，避免 Python 面板继续暴露无效旋钮。旧 preset
中的多余字段由 Python 参数加载器忽略。

这项删除不影响独立的边缘 `glint`、surface reflection、streak、thin transmission、折射、
Beer–Lambert、SSS 或各自已经确认的逐层数量与 HDR 峰值。`aSheenSlope/vSheenSlope` 名称暂时保留，
但其低通坡度现在只服务折射、Beer、SSS 与 HDR transmission，不得重新用于可见连续反射。HDR
transmission 保留既有不随微法线分块的 `V·H` Fresnel 标量，避免以透射名义重新产生层内点状
纹理。D138 取代 D137 的生产方案；D137 的诊断数据只作为失败候选记录，不得据此恢复微面片。

## D137 连续镜面覆盖使用稳定有界微面片，不再显示动态响应等值线（2026-07-15）

**状态：已由 D138 否决。固定微面片虽消除了扩缩等值线，但形成用户不接受的层内斜短光点。**

用户确认当前油漆感光带不是离散 `glint`，并要求动态诊断既能显示明显音乐响应，又不能因第 0 层
基础水位过高遮住中远层。单变量消融已证明：`full`、`no_glint` 与 `water_only` 都保留同一组
扩张、收缩的弯月光带，只有关闭连续 sheen 才消失。根因因此固定为连续 GGX 路径把动态
`sunResponse` 的窄阈值等值线直接当作空间覆盖，而不是闪点、表面带或波包半径变化。

连续镜面从此把“微面片在哪里”与“该处 GGX 能量多高”分开。空间覆盖使用屏幕空间
`42×16px`、按层加盐、稳定播种的短各向异性微面片；时间只平移连续坐标，不改变面片尺寸、半径
或命中阈值。GGX/Smith/Fresnel 只调制已经存在的面片能量，不得反过来决定几何边界。抗锯齿
footprint 必须从 `floor`/hash 前的连续坐标导数解析计算，不能对不连续的椭圆距离调用 `fwidth`。
逐层存在度从 uniform 的 `uSunReflectionCoverageWeights[uStartLayer]` 读取，禁止用跨层插值 varying
在单个面片内部切出未经抗锯齿的直边。D136 已恢复的闪点数量、HDR 峰值表和 `lighten_far` 主体
颜色合同均保持不变。

同源暗面只允许使用同一微面片 `spatialGate`，在当前线性水色上做保色曝光降低；不得用较宽的
活动覆盖重新生成跨层暗带，也不得混入黑、灰或压暗最终 HDR 高光。第 0 层前景填充不需要微法线、
hash、GGX、折射或 Beer–Lambert，shader 以 uniform `uFrontFill` 提前返回，保持既有颜色和 alpha
合同并降低片元成本。

回归场景固定为 129 BPM、中高能量、适中主浪，前景水位必须让九层仍可观察；`EmptyOptics`
明确排除 glint。四个主时相同时要求连续高光正残差峰值大于 `0.12`、支持面积大于 `256px`、
最大 8 连通域不超过 `512px` 且不超过总支持面积的 `24%`，禁止用整体关效通过测试。完整 16
时相实测最大连通域中位 `93px`、最大 `105px`，最大占比 `9.29%`；60Hz 相邻帧 mask IoU 中位
`0.8716`，证明形状已打散且保持时间稳定。

## D136 高光恢复既定逐层合同，峰值、覆盖率与同源暗面分开建模（2026-07-15）

保留 D135 的静态 `lighten_far` 主体色板、录音/HDR 不改写主体色以及零界面肩；撤销 D135 对
第 3～7 层特效数量和 HDR 峰值的过度收缩。镜面闪点恢复容量
`4/4/3/3/2/2/1/1/0`、出生权重、长度、核心 alpha 和 D103～D118 已确认的五组 HDR 峰值；
第 8 层仍不生成离散闪点。解析 halo 继续为零，不能用恢复数量之名重新引入扩张、收缩的圆环。

离散闪点使用出生时固定尺寸、沿真实水面向水内单调衰减的短实心曲面带；运行中只跟随位置和
强度，不再用锚点尺寸或周期函数改变半径。连续太阳响应删除 `216×129` 低频椭圆 patch，直接由
同一组宏观坡度、带限微法线、GGX/Smith/Fresnel 和光向生成破碎亮区。逐层权重只收窄命中面积，
不得线性降低命中像素的 HDR 峰值；由此把“存在数量、空间覆盖率、SDR 反射预算、HDR 峰值、
中性白比例”拆成独立职责。

同一片元的 `normal` 与 `lightDir` 同时决定受光高光和背光坡面。暗部只在当前线性色上小幅降低
曝光，深色允许压暗，浅色自动减弱，禁止混黑、混灰或在最终 HDR 合成结果上整体乘暗。SDR 高光
肩部主要保留 Thing 身份色，只有更小的 HDR 核心趋向银白。光学实体改用预乘 SDR 颜色加不受
alpha 二次衰减的有界 HDR excess，最终 presentation 统一按设备可用 headroom 截断；这项合成
规则修订 D80、D131 中仍让 alpha 同时控制峰值和覆盖率的旧描述。

折射与 Beer–Lambert 合成只允许当前层透明度参与一次。顶点阶段额外输出尚未混入当前层的
`behindColor`，片元阶段先对不可变背景执行折射和体积吸收，再以当前层透明度和主体色合成；
不得把已经包含当前层的颜色再次与同一层混合。体光 `mode 8` 必须把实时 `volume` 作为 HDR
资格传入，避免逐层峰值表成为不可达路径。第 8 层既没有正向连续 HDR 覆盖，也不得单独保留同源
负向暗面。

离屏验收固定分为两条证据链：8-bit RGB PNG 只判断颜色、层界、浑浊感、形状和空间分布；HDR
亮度只读取 FP16 线性 scRGB 原值，并按 `1.0/1.08/1.16/1.29/1.6/2.0× reference white`
输出逐层覆盖率和伪彩图。普通 PNG 即使来自 FP16 场景，也不得被描述为 HDR 图片或用于判断最终
超白亮度；Android 系统 tone mapping 与运动观感仍以真机为准。

## D132 九层主体采用亮向色域贴边弦长阶梯，界面肩仅补量化误差（2026-07-15）

**状态：主体色阶与界面肩已由 D135 取代。**

第 0 层继续精确等于记事身份色，第 1～8 层统一向亮。路径固定 OKLCH hue，在每个明度上取
sRGB 色域可容纳且不高于原色的最大 chroma，并在色域迫使下降后禁止远端回弹；最远明度不得
超过旧 `86.4%` 混白所对应的 `L0 + 0.864 × (1-L0)`。这保留“远处偏亮”的景深方向，同时
避免沿中性白直线主动降低饱和度。

八条相邻边界的目标 ΔE 为 `0.045/0.045/0.042/0.036/0.032/0.027/0.024/0.021`。
颜色余量不足时，先给八条边各保留 `0.014`；若仍不可行，则求八条边的最大共同等距；可行时
先同步满足最近两条边，再按 `1/.78/.62/.50/.42/.36` 给其余六条边分配余量。每一步必须按
相邻 OKLab 端点弦长在色域路径上求位置，不能用累计曲线弧长代替。录音、mood 与 color breath
不得再改变主体色阶；这些动态能量只进入局部光学和 HDR。

界面肩不再弥补“目标 ΔE 与色域可用量”的差额，只允许补偿 8-bit 量化造成的微小损失；当主体
相邻 ΔE 已达到 `0.012` 时权重必须为零，剩余情况也不得超过 `0.12`。深度方向渐变不附加界面
肩。由此以主体色差承担九层分界，避免宽粗身份色描边。D132 取代 D129 的主体缺口补偿职责和
D130 的 `.70/.60 chroma floor` 截止，但保留 D126 的随层保色阴影原则。

## D134 晶莹水体采用连续微表面、不可变背景折射与受限体积吸收（2026-07-15）

水体连续受光统一采用 GGX/Trowbridge–Reitz 法线分布、height-correlated Smith 可见性与
Schlick Fresnel；水的折射率固定为 `1.333`，法向入射反射率固定为 `0.020373`。低频坡面密度
采用 Cox–Munk 海面统计的设计方向，逐片元导数在任何非一致材质分支前求值，用 footprint
扩大有效粗糙度并带限微法线。SDR 反射预算封顶 `0.160`，太阳响应系数为 `72`；HDR 只开放
局部超白余量，局部门控使用 `response/(response+0.129)^2`，不得把整层或主体身份色抬到白点。

屏幕空间折射必须读取一张已经完成、之后不再写入的背景纹理，禁止同时采样当前 scene 写附件。
Python 与 Android 都维护 `pre-water`、`scene` 两张同尺寸离屏目标：先把相同环境写入两者，再在
scene 上绘制水体；HDR 离屏失败时两张目标必须原子回退到同一 SDR 格式。折射按 Snell 定律计算，
位移受视口和层深限制；Beer–Lambert 只衰减折射/透射分量，以 `exp(-sigma × opticalPath)` 在线性
光空间执行，再与当前主体身份色做有界凸组合。浅色使用感知明度保护，避免吸收把浅灰绿、浅粉、
浅黄压脏；主体、反射、闪点和 HDR excess 不参与体积吸收。

离散闪点核心与解析光晕共用一条扩展曲面带和一次 draw，核心/光晕比例打包进 mode 小数部分，
shader 内分别求解析覆盖；曲面带按 `≤3.2dp` 目标段长直接取 `6～32` 段，不再逐轮插点。九层均
保留非零闪点容量，连续微法线、SSS、银泽和透射按景深连续衰减，不在最近三层之后硬截止。
颜色变换性能优化只能缓存“精确 8-bit RGB → 固定 OKLab 变换”的纯函数结果，不得缓存、降采样
或近似水面几何与动态光照。

## D133 Python 与 Android 连续水面采用每层十二个纵深子区间（2026-07-15）

Python 视觉基准把九条层级锚线之间的纵深采样从每层 3 个子区间提高到 12 个，共 97 行。目的
是降低逐顶点坡度和受光量在三角形之间形成的直线/马赛克边界，并为逐片元 specular AA 提供更
平滑的宏观输入。索引缓冲容量必须从 `Z_ROWS` 推导，不能保留 `8×3×119` 的硬编码。

这项加密不得以牺牲交互性能为代价：640×840、FP16、动态模拟、GPU finish 的 Python 离屏基准
应维持 60fps 量级。颜色纯函数稀疏缓存和闪点核心/光晕合并后，高活动稳态保留 23 个闪点与
6 条流光，中位帧耗时为 `15.52ms`（约 `64.4fps`），P95 为 `18.86ms`。Android 同步为相同
`ROWS_PER_LAYER=12`、`Z_ROWS=97`；闪点纵深轴使用 `ROWS_PER_LAYER/3=4` 行，避免加密后
光学实体厚度缩为原来的四分之一。实机视觉验收仍由用户完成。

## D131 晶莹材质链以局部光学、屏幕空间界面肩和当前位置颜色统一收口（2026-07-14）

本轮实施不只调整九层颜色。Android GL/Canvas 与 Python ModernGL/QPainter 同步采用以下最终合同：

- D129 的界面肩从水体 ribbon 内的比例着色迁到真实轮廓几何，宽度按相邻分离缺口连续取
  `7～14dp`；每条内部轮廓先画较弱深肩、再画亮肩，两侧均使用峰值 `0.66` 的半正弦剖面，
  在轮廓本身和带外覆盖率归零，不形成细描边。第 8 层与环境之间不画内部界面肩。
- 纯黑端的亮肩额外获得向上明度余量，近白端的亮肩连续衰减并由同色深肩承担分离；浅粉、浅黄、
  浅青不得因 gamut mapping 退成中性白。两侧目标色都从当前层四停靠点及其 residual weight 派生，
  不混入白、黑、灰或环境色。
- 表面反射带先按当前位置和实际 Thing 渐变几何采样主体色，再沿该样本的固定 hue 提亮
  `ΔL=.045`；禁止以 `mix(start,end,.3)` 的单一中间色覆盖整条双色或互补渐变。
- 局部 SSS 从每一层最终四停靠点分别派生，不再回跳原始 Thing 色，也不主动执行 `C×.85`。
  明度增量为
  `(.045 + .025×(1-smoothstep(.35,.75,L))) × (1-smoothstep(.90,.985,L))`，目标上限
  为 `.965` 且不得反向压暗原色；纯白保持纯白。
- 界面肩、随层保色阴影、体光、轻纱、表面反射、流光和闪点按
  `interface → backShade → body/thin → veil → surface/streak → glint` 合成。界面肩与阴影均先于
  反射/透射，闪点最后绘制，后续半透明介质不得衰减已经存在的表面响应。
- 连续 HDR 银泽仍只由方向、Fresnel、波峰/坡度和低频 patch 共同门控，不恢复全域白色基线；
  局部响应系数设为 `3.0`，使默认强度在 FP16 中跨越足够量化级。录音增益只开放局部 excess，
  不改变九层主体、界面肩或 SDR 基线。

光学 HDR 不再执行 `excess/alpha` 反向预补偿。闪点 HDR 资格使用共同出生门后独立归一化的
`birthGate × min(intensity/.30,1)^.8`；源 alpha 与空间 coverage 自然控制最终合成能量，避免低
alpha 实体生成巨大白色源。该项修订 D80、D116 中关于 inverse-alpha 预补偿的旧描述。

## D130 九层主体颜色统一逐层提亮，不再按颜色分支（2026-07-14）

用户要求结束对个别颜色方向和色域预算的继续裁决：第 1～8 层统一相对第 0 层逐层提亮，不再根据
输入色自动选择向暗、不再为粉/黄/青/绿等颜色建立不同方向，也不把 Display-P3 或 HDR headroom
纳入主体阶梯分支。第 0 层继续保留 Thing 身份色锚点。

实现使用固定色相的感知明度上移，尽量保持原始绝对 chroma；目标色域无法容纳时才做必要的保色
映射，禁止重新沿白点直线混合。具体相邻步长、色度软目标与硬底线降级为 Android/Python 同构
调参项和回归观测量，不再作为需要逐色裁决的产品分支。D129 的随层保色界面肩继续承担颜色提亮
不足时的层界辅助，但不改变“所有主体逐层提亮”的单一方向。

本决策收口并取代 D120～D129 中仍可能被解释为按颜色选择方向的部分；其余关于相邻边界、近三层
优先、主体/HDR 分离、保色阴影与界面肩的约束继续有效。

## D129 向亮色域耗尽后的层界缺口由随层保色界面肩接管（2026-07-14）

**状态：界面肩职责继续有效；具体 `.70/.60` 色度预算已由 D130 降级为内部调参参考。**

九层主体按 D128 保持越远越亮。向亮路径默认在 `C/C0=.70` 的软目标处停止；只有为了保护最近的
`0↔1`、`1↔2` 两条边界，才允许继续消耗到 `.60` 硬底线，不得为拉开中远层而继续降低色度。
具体相邻 `ΔEOK` 目标仍可调，`.70/.60` 也必须通过最终动态画面复核，不解释为文献阈值。

颜色路径停止后，每个相邻边界尚未满足的分离缺口，由常驻 SDR/HDR 的 **随层保色界面肩** 接管：
沿低频水层轮廓形成宽软、低幅、从该层当前位置主体色派生的亮侧与更弱深侧响应。它不得混入白、
黑、中性灰或环境固定色，不得收缩成 1px 描边、九条等强横线或逐层交替明暗；局部响应不能改变
主体腹部，也不能让九层平均亮度停止递增。

界面肩是一项受限的感知层序后备，不宣称九层分别具有真实 Fresnel 界面。真实 Fresnel、环境反射、
折射、透射和 HDR specular 继续按连续水面的视角、法线与光路独立计算。未录音与录音 HDR 使用
相同主体阶梯和界面肩；录音状态只允许额外局部光学分瓣进入 HDR，不得再次整体抬亮第二、第三层。

## D128 主体景深阶梯以越远越亮为全局方向先验（2026-07-14）

**状态：已由 D130 收口为所有主体统一逐层提亮。**

用户否决按可用色域和远层色度保留自动在“向亮/向暗”之间择优的候选算法：该评分会让默认粉、
黄色、青色和绿色等大多数样本越远越暗，违背 FableSol 的景深外观。第 1～8 层主体仍以越远越亮
作为全局方向先验；不能只因为向暗更容易取得较高 `C8/C0` 或更大的八段 `ΔEOK`，就自动翻转整条
Thing 或渐变的深度方向。

当 sRGB 向亮色域不足时，算法必须先在不乳白、不显著消色的边界停止继续提亮，再由稳定、低频、
非黑阴影且不依赖录音 HDR 才可见的其它层序量补足相邻界限；不得静默切成大面积越远越暗。
近白等完全没有上行余量的极端输入如何分配剩余层差继续单独裁决。本决策取代 D120/D121 中“上行
余量不足即可自动反向”的部分，但保留二者关于渐变连续、不得趋白消色和层内光照独立的约束。

## D127 体积吸收与阴影分离并只作用于介质透射光路（2026-07-14）

FableSol 的物理体积吸收不纳入 D126 的随层保色阴影，也不能作为压暗主体的替代手段。它只作用于
穿过介质的透射、折射或背景采样分瓣，并在线性光空间随光程增加执行有界的逐通道衰减；主体身份
色、环境反射、镜面高光、闪点与 HDR excess 不参与该衰减。

吸收谱由当前位置的身份色关系派生。光程变长时，透射结果可以自然变深并适度提高饱和度，也允许
物理吸收造成的极小色相漂移，不强制沿 D125 的恒绝对 chroma 主体轨迹；但必须限制色相偏移、最大
光学深度和最低剩余能量，防止浅色退成灰雾或深色沉入黑泥。不得用黑色 overlay、编码 sRGB 标量
乘法或最终材质总和乘暗冒充体积吸收。

在当前尚未采样真实背景、没有完整介质厚度的 2.5D 水体中，可以先使用受控的近似光程，但必须
明确其分瓣职责，不能把 additive 薄峰光或整层体色称为物理透射。具体吸收强度、色相偏移和能量
下限继续通过 Android/Python 同构原型调节。

## D126 所有负向明暗响应采用随层保色阴影（2026-07-14）

FableSol 中由波背、宏观坡面、微表面或其它材质效果产生的阴影，必须以当前位置已经应用
景深阶梯和横向渐变后的水层主体色为颜色来源，再形成同色系的更深颜色；禁止向黑色、中性灰或
跨层复用的固定暗色混合。远层即使明显更亮，其阴影也必须从该远层当前色出发，而不是突然回到
第一层或原始 Thing 的深色。

这里的“当前位置主体色”明确处于材质合成顺序中的低频锚点：已经完成九层景深配色和 Thing
横向渐变采样，但尚未加入环境反射、透射、次表面散射、镜面高光、闪点与 HDR 增益。阴影不得从
已经包含这些光学分瓣的最终像素反向派生，否则会把本应保留的晶莹响应一并压暗。

显式暗色带或体色变化应在感知空间中主要降低明度，保持当前 hue 与绝对 chroma；目标色域无法
容纳时才受控压缩 chroma。物理遮挡则不生成黑色“阴影色”，而是只削弱对应的直射光分量，保留
主体体色、环境反射和其它未被遮挡的材质分瓣。禁止用最终 RGB 总和乘暗来模拟遮挡。

本决策把这类结果统一命名为 **随层保色阴影**。它适用于 Android HDR/SDR、Canvas 回退、共享
GLSL 与 Python 两条渲染路径；不能只修复命名为 `shadow` 的单一函数，也必须审计实际承担负向
明暗的微法线与合成步骤。物理体积吸收按 D127 使用独立的介质透射合同。

## D125 主体景深色板默认保持原始绝对色度且不自动增艳（2026-07-14）

第 1～8 层低频主体色板默认采用 `Cdesired=C0`：沿自适应明度方向移动时尽量保持 Thing 输入色
的绝对 OKLCH chroma，不使用 `C/Cmax(L,h)` 作为恒定饱和度合同，也不主动把主体提高到超过
`C0`。这样既避免向白路径主动消色，也避免色域切片形状导致某些颜色先过度增艳、随后快速褪色。

当固定 hue 下的目标色域无法容纳 `C0` 时，可以降低 chroma，但必须由色度保留下限约束可用明度
路径；在跌破下限前停止、换向或引入其它低频层序量。具体保留率继续以 `60%/70%/80%` 多档视觉
对照收敛，不在本决策中写死。

该合同只约束九层低频主体色板。局部反射、薄峰透射、镜面闪点和其它受光材质响应仍可产生更鲜亮
或更接近中性高光的局部像素，但不得反向把大面积主体自动增艳或消色。

## D124 远层明亮与远层消色分开裁决（2026-07-14）

FableSol 不把第 8 层或其它远层“较亮”本身视为缺陷，也不为保持深色身份而单独限制九层总明度
跨度。远层只要继续属于 Thing 身份色系、保持足够饱和与干净观感，就可以获得明显高于近层的
感知明度。

需要受限的是随深度趋向中性轴的消色：景深颜色路径不得为了提亮而系统性把 OKLab `a/b` 或
OKLCH `C` 压到接近零，也不得把高明度与乳白、发灰绑定。明度跨度、相邻层级距离和色度保持从此
作为三项独立约束验收；“最远层更暗”不再是候选方案的优势。

本决策修正 D121 中“只能小幅提高感知明度”的限制：典型中间色和深色仍默认越远越亮，但可在
色相、色度和相邻边界均合格时扩大亮度跨度。浅色或色域边界颜色若无法继续提亮而不显著失色，
仍按 D120 自适应反向或使用其它低频层序量。

## D123 景深阶梯按八个相邻边界验收，近三层优先（2026-07-14）

九层水体颜色不能再以第 0 层与第 8 层的端点总差作为主要分明度依据；正式验收对象是八对相邻
层级。任一相邻边界不足都可能让两片水体在运动和光影覆盖下混合，即使首尾颜色相差很大也不能
判定景深阶梯合格。

最靠近观察者的三层具有最高辨识优先级。`L0↔L1` 与 `L1↔L2` 必须得到最高等级的受保护间距；
后续边界可以采用不同目标，但不能低于动态画面仍可辨识的底线。八段目标允许不等距，不再由
单一端点提亮量间接决定。

相邻距离以完成色域映射和最终输出量化后的实际 `ΔEOK` 为数值检查，并同时在准备态 SDR 与录音
HDR 动态画面中验收。`ΔEOK` 只是一项可调的生成与回归参数，不代替边界视觉判断。前两段是否
等值、`L2↔L3` 如何过渡以及其余五段怎样收敛，仍留给下一轮阶梯对照确定。

## D122 第 0 层低频主体基线承载记事身份色锚点（2026-07-14）

第 0 层继续作为 FableSol 的稳定颜色参照：其进入局部材质计算前的低频主体基线必须等于 Thing
原始纯色，或完整保留 Thing Background 的横向渐变关系，不参与第 1～8 层使用的景深颜色派生。

身份锚点约束的是基线，不是要求第 0 层所有最终像素保持平色。局部表面反射、薄峰透射、受光
明暗、体积光程和其它有界材质响应仍可改变第 0 层局部输出，但必须留下稳定、可识别的原色参照，
不得让中性白高光或灰暗阴影成为该层的主要颜色身份。

第 1～8 层以第 0 层锚点为输入，按照 D119～D121 形成自适应 **水层景深阶梯**。本决策收敛 D117
尚未确定的身份锚点落点，并保留当前用户认为观感较好的首层基线，不要求重做首层颜色关系。

## D121 多数颜色保留越远略亮，只有上行余量不足时反向（2026-07-14）

**状态：方向选择部分已由 D128 修订。** 大多数颜色越远越亮已提升为全局方向先验；上行余量
不足时不再由色度评分自动改为向暗，而是在保色边界停止并使用其它低频层序量。以下保留原裁决
形成过程。

典型中间色和大多数深色继续沿用“主体越远略亮”的默认深度方向，但只能沿记事颜色关系小幅提高
感知明度并保持色度下限，不再通过大幅插值到中性白制造层差。近黑色同样可以有限向亮，但不得
因此变成灰色或与其它深色收敛。

当浅色、近白色或色域边界颜色没有足够的向亮余量时，主体阶梯可以连续转为越远略暗，或由其它
低频层序量补足差异。渐变中发生方向切换时必须平滑，并避免在切换位置让相邻层差归零。

跨层主体阶梯与层内光照是两项独立职责：深色水体仍可在波背、长光程或直射可见度较低的局部
区域有界压暗；这不表示其九层主体基线必须越远越暗。D121 收敛了 D120 中尚未决定的典型颜色
默认方向，具体切换条件和次要层序量继续后续裁决。

## D120 主体阶梯明暗方向按颜色余量自适应（2026-07-14）

**状态：自动反向部分已由 D128 取代。** 色域余量仍用于限制可走的向亮路径，但不再自行选择
整条主体越远越暗；渐变连续与无接缝约束继续有效。

FableSol 不再要求所有 Thing 颜色都采用同一个主体阶梯明暗方向。各输入颜色可以根据实际向亮、
向暗和色度余量选择能够保留颜色身份与相邻层差的方向；渐变输入的选择必须连续，不得形成横向
接缝或逐层方向跳变。

“自适应”不等于把当前“越远越接近白色”整体替换为“越远越暗”。当前实现确实通过
`mixOklab(identityColor, white, depth × lighten_far)` 固定让远层趋白；D120 取消的是这项全颜色
固定规则。深色仍允许在层内受光结构中压暗，近黑也可以在阶梯中有限向亮；浅色或近白色则可以
在向亮余量不足时改用有界压暗或其它层序量。

本决策只确定自适应原则；典型中间色随后由 D121 确认为继续默认“越远略亮”，何时切换方向以及
方向切换处由哪一项次要层序量维持相邻层差，继续由后续 grilling 裁决。

## D119 水层景深阶梯定义为独立于局部光影的层序结果（2026-07-14）

FableSol 的九层低频主体外观必须自身保持由近到远的有序关系，并使相邻水层在不依赖局部 HDR、
闪点、阴影或其它局部光影时仍然可辨。局部材质响应可以丰富各层内部，但不能承担层界存在与否，
也不得持续抹平相邻主体的边界。

**水层景深阶梯** 从此只规定上述结果，不再绑定“随距离逐层混白、提高明度并降低整体 alpha”这组
固定手段。混白、明暗、透明度、色度、反射、光程或粗糙度等候选量只有在适配任意 Thing 颜色、
保留 **记事身份色锚点** 且不制造乳白主体时才可参与实现，不能单独成为产品定义。

本决策保留 D59 的九层层序目标，但取代其“必须单调混白并降低 alpha”的实现约束；D60 锁定旧参数
的对照仍作为历史实验记录，不再限制后续材质重构。主体阶梯的明暗方向随后由 D120 确认为按颜色
余量自适应。

## D118 录音 HDR 态保留多类局部光学响应并服从九层边界（2026-07-14）

FableSol 继续只在开始录音后进入 HDR，准备态和停止态保持非 HDR；不得以保持主体基线为由取消
这项状态变化。HDR 也不限定为只增强镜面闪点：局部表面反射、薄峰透射、连续受光结构及其它能够
提高晶莹感、立体感和水体质感的材质响应均可使用实际可用 headroom。

所有 HDR 与 SDR 材质项仍须服从九层水体相对分明的边界和 **记事身份色锚点**。禁止的是整层或
大面积近中性白增益、多个独立效果无预算叠加后持续抬高主体，以及因此造成第二、第三层乳白、
低色度或与相邻层合并；并不禁止连续水面本身获得局部 HDR 响应。

本决策修正“录音 HDR 只能出现在局部镜面和闪点”的过窄建议；各层基线如何形成单调层序、局部
效果可以覆盖多大面积及怎样共享能量预算，继续由后续 grilling 分别裁决。

## D117 记事原色作为身份锚点而非全域固定填充色（2026-07-14）

FableSol 必须保留一处稳定、可识别的记事身份色锚点：纯色记事保留原始颜色，渐变记事保留原始
横向渐变关系。身份锚点不等于全部水体像素必须严格等于原色；其它区域可以因表面反射、光程、
受光与材质形体产生有界明暗和色度变化。

浅色、近白色允许在非锚点区域适量压暗，为 SDR 波面保留形体对比；深色、近黑色也允许继续压暗，
但不得让不同输入收敛成同一黑色。后续颜色派生必须按输入色的实际上下明度/色度余量连续适配，
保留色相关系并进行目标色域映射；固定混白、固定 `ΔL`、逐 RGB 通道裁切或灰黑覆盖不能再被视为
适用于任意 Thing 颜色的完整方案。

本决策只确定颜色身份与材质响应的关系，尚不裁决各水层的最终明度顺序、身份锚点具体落点或每种
材质分瓣的数值范围；这些项目继续通过本轮 grilling 逐项收敛。

## D116 闪点时间修正只补上 HDR 共用包络，不重做已验收生命周期（2026-07-14）

D70/D92 已经通过 `0.30s` attack、`0.80s` release、`0.018～0.060` 低强度软门、`0.015` 退休
阈值和 `1/15s` 跟踪步长上限解决 SDR/CPU 侧的主要突消问题，本轮不得重复重写这套生命周期。
现有出生初始强度 `candidate * 0.12`、`0.10s` 位置跟随和当前锚点匹配行为也先保持不变。

**状态：HDR 资格与 alpha 合成细节已由 D131 修订。** 闪点 mode 3 继续复用
`vHdrEligibility` 通道，但其值为
`birthGate × min(intensity/.30,1)^.8`：与 SDR 实体共享出生/退出门，同时在真实 track 强度
`.30` 达到满额。HDR mask 另乘空间 coverage；shader 不再执行 `excess/opticalAlpha`，实体 alpha

跨帧身份、自然出生/消失、随水体运动的连续性、specular AA 以及 HDR/SDR 质感。第 3～6 层可以
逐层降低显著度，但不能以矩形化、低质量几何、随机噪点或时间跳变换取覆盖。

## D99 闪点跨层分配采用软配额并回流未使用额度（2026-07-14）

D94 的跨连续面统一出生池继续保留，但不能再仅以全局最高分长期让第 0～2 层占尽出生机会。
每个具备闪点职责的水层按其目标占用率积累有限的出生机会；只有该层存在超过有效几何门槛的
真实坡面候选时，软配额才可被消费。候选层相对目标占用不足时获得有限优先权，第 0～2 层仍因
目标占用、容量和候选质量更高而保持主体地位。

某层没有合格候选或已经达到容量时，其未使用额度立即回流全局池，由当前质量最高的有效候选
使用。不得为满足配额生成与局部坡度无关的随机闪点，不采用逐层机械轮转，也不保证每层固定
保有数量。具体目标占用率、容量和候选门槛在后续层级锚点与候选形成裁决中确定。

## D98 顺流银线只延伸到第 4 层并继续保持 SDR（2026-07-14）

顺流银线。

D76 的亮度边界继续有效：所有顺流银线严格处于 SDR，不获得 HDR 超白峰值。第 3～4 层的数量

## D97 波峰薄雾只延伸到第 4 层，远处能量归入连续表面（2026-07-14）

## D95 水体材质采用公共层级锚点与四个效果族衰减（2026-07-14）

九层水体不再由各效果各自散落的 `layer <= N` 形成近三层与其它层的材质断崖。后续实现先定义

## D94 Sun-glitter 使用跨连续面的统一出生池（2026-07-14）

## D92 HDR 银泽使用独立低通法线，闪点只在不可感知后退出（2026-07-14）

## D54 解析镜面抗锯齿接入真实闪点坡度高斯路径（2026-07-13）

当前 GLES 镜面闪点不是 fragment shader 的传统 `pow(N·H,p)`，而是
`FableSolGlOptics.buildGlints()` 用 `exp(-(Δs/σ)²)` 对宏观坡度与十项毛细坡度谱选峰，再生成
持久曲面内侧光带。因此 Stage 2-3 不新增无消费者的 shader 指数，而在
`FableSolOpticalWaveSet` 按当前列采样足迹解析带限：每个波长在每波 2 个样本以下完全转为方差，
4 个样本以上完整保留，中间用 smoothstep 过渡。

被带限的坡度方差按高斯卷积关系进入 `σ_eff²=σ_base²+2·variance`，被带限的曲率方差以统计
RMS 补回稳定的微表面活性，并以 `σ_base/σ_eff` 保持一维积分能量。只有闪点选取使用带限后的
slope/curvature；体积光等既有光学
继续使用未过滤毛细坡度。`specular_aa_strength` 独立默认 1，设为 0 时过滤量和方差均为 0，逐值
恢复原闪点路径。此项不改变闪点实体数量上限、跟踪、颜色、曲面内侧几何、双色散射或水面运动。

## D37 前后俯仰采用完整输入与分通道软压缩（2026-07-12）

用户确认 `±55°` 并非必须，要求优化前后俯仰的临界停止。旧链路先在传感器入口和
`FableSolSimulation.setPitch()` 将角度硬截为 `±55°`，连续曲面内部再次截断；同时渲染观察角
以 `38°` 为基准硬限制在 `14°~68°`，使静态透视实际在前俯 `+30°`、后仰 `−24°` 就进入平台。

新增 `FableSolPitchPolicy`，把三种语义拆开：`pitchDeg` 保存手机完整 `−90°~90°` 俯仰；
`motionPitchDeg` 用归一化 `atan` 曲线将完整输入单调软压缩到 `±55°`，继续保护水体惯性幅度；
观察角用响应更快的归一化 `atan` 曲线，把完整输入按基准两侧分别软压缩到 `14°~68°`。
两条输出在整个物理范围内严格单调，只有手机到达 `±90°` 才到安全端点，不再在中途形成平台。

连续曲面的欠阻尼弹簧改用 `motionPitchDeg`，纵深透视改用原始 `pitchDeg` 经策略映射；内部
`±55°` 仅作为不接受越界目标的防御性安全阀，不再直接作用于传感器输入。该设计保留原最大
惯性幅度和观察角范围，同时让普通角度附近保持较快响应、越接近极限变化越缓。本决策取代
D30 中“手机法向分量转换为 `±55°` 前后俯仰”的输入限幅约定。

## D33 显式阴影统一由当前层颜色混黑生成（2026-07-12）

**状态：已由 D126 取代。** 本节保留当时从固定蓝黑阴影迁移到当前层色的历史背景；其中
“混黑”及固定百分比不是现行合同，禁止据此恢复实现。

用户真机发现浪面经常出现难看的灰黑区域，要求阴影改为更深的记事颜色。诊断确认两条
显式路径违反该语义：猫爪暗纹把所有层色混入固定蓝黑 `#080C16`；波背自阴影采用
OKLab 固定降明度后再冷偏 `−hue_temp_deg`，部分颜色会丢失原记事色身份。

新增 `FableSolShadowColorPolicy` 作为唯一显式阴影颜色入口：波背阴影使用当前层色在
OKLab 中混黑 18%，猫爪暗纹混黑 24%。两者不再接受固定灰黑/蓝黑色，也不再做额外冷暖
色相偏移；几何强度、透明度、出现条件、空气透视和连续水面物理不变。深度吸收的标量
暗化本身等价于基色混黑，不属于本次固定偏色问题。

## D34 阴影混黑量随层深递减（2026-07-12）

**状态：已由 D126 取代。** 现行实现应从当前层当前横向位置的主体色派生保色深色，不再
计算或衰减“混黑比例”；阴影强度仍可按层深与光照关系独立变化。

用户指出 D33 的固定混黑比例仍不正确：远层水体本身经过空气透视已经更淡，同样比例的
黑色会在远层形成更显眼的暗斑。波背和猫爪的有效混黑量统一乘
`max(0.35, 1 − 0.85×depth01)`；第 0 层保持 D33 的 18%/24%，越远逐层降低，最远层
最多保留基础黑度的 35%。

当前波背只绘制到第 5 层，其混黑量约由 18% 降至 8.4%；猫爪只绘制到第 2 层，约由
24% 降至 18.9%。该衰减只改变阴影色，不重复修改已有的层 alpha、空气透视或阴影几何，
避免远层被多套规则直接裁掉。

## D35 远层阴影黑度采用平方衰减（2026-07-12）

用户进一步明确“远方的黑色要很淡很淡”。D34 的线性衰减与 35% 下限仍过重，改为
`max(0.05, (1−depth01)²)`。波背基础 18% 因而在第 2 层约为 10.1%、第 5 层约为
2.5%、最远端约为 0.9%；猫爪基础 24% 在其最远参与的第 2 层约为 13.5%。

平方曲线让近层保持可读阴影，中远层迅速淡出；5% 是对基础黑度的比例下限，不是直接
混黑 5%，因此最远波背实际只混黑约 0.9%。

## D36 纵向法线负向受光收敛到基色混黑轴（2026-07-12）

用户复测指出主要灰黑区域并非波背或猫爪，而是与光线相关。定位到连续水面新增的
`applyLongitudinalLight()`：完整三维法线与旧二维法线分别计算 `N·L`、透射和 Schlick
Fresnel 后，旧实现用 `base + full − reference` 逐 RGB 通道相减。背光坡的负差值中包含
天空反射色差，会让主题色同时丢失明度与色彩身份，形成大面积灰黑。

保留完整物理候选色的明暗判断：候选亮度不低于基色时原样保留正向受光与天空偏色；候选
更暗时，只提取相对亮度下降量作为阴影强度，并重新生成基色混黑结果。近层最大混黑 14%，
实际量乘 `sqrt(darkness)`；层深继续乘 D35 的 `max(0.05,(1−depth01)²)`，远层负向受光
接近不可见。实现使用 packed ARGB 与通道乘法，避免在逐顶点路径增加对象和 OKLab 开销。

## D30 Android 默认采用连续 2.5D 水面，旧九层渲染仅作内部回退（2026-07-12）

用户确认将 `audioVisualizerSimulatorFable` 当前连续水面更新迁移到 Android。Android 以
`FableSolContinuousSurface` 承载 25 行二维方向波场：九层既有轮廓继续作为 Z 向几何、
颜色和声音角色锚点，二维场只叠加去除深度均值后的相对翻滚；第一层是唯一前景剪影。
渲染默认走连续 ribbon，旧九层完整填充路径保留为 `surface2d_on=0` 的内部回退，不暴露
用户调参入口。

连续路径同时迁移主波向/方向扩散、有限相干波包、深水色散、Gerstner X/Z 轨道、随波数
增强的耗散、前后俯仰欠阻尼惯性和纵向法线相对受光。手机三维重力的屏幕内分量继续控制

## D31 连续水面使用投影安全采样窗与分层批量网格（2026-07-12）

真机首轮发现 Z 轴翻滚时远处水体两侧偶发空白，且整体明显卡顿。连续路径不得再复用

`z01≤1.1` 的画外余量、±10dp Gerstner 轨道位移和至少 2 个网格列的边缘余量；离散
索引必须向外包含边界外第一列，不能向内取整。

渲染保持 25 行和九层锚点不变，但 24 条 ribbon 不再各自构建 cubic Path 与
LinearGradient。每个相邻九层锚点之间的 3 条 ribbon 合并为一次带逐顶点颜色的三角网格，
全水面固定为 8 次网格提交；共享边使用同一顶点坐标，颜色边界通过逐 ribbon 重复顶点

二维方向波采样使用等距 X 网格相位递推，有限相干波包的二维高斯拆为 X/Z 可分离包络，
替代每个 Z×X 采样点重复调用 `sin/cos/exp`。该变换只减少重复计算，不改变波数、相位、
包络、九层角色或 25 行纵深分辨率。

## D32 倾斜时固定连续渲染列预算，边界剖面只以 30Hz 更新（2026-07-12）

用户复测确认常态播放不卡，主要卡顿集中在倾斜手机期间。诊断发现宽 276dp 时，投影安全
采样窗的原始列数会从水平 `110` 增至 `30°=172`、`45°=186`、`60°=190`、`90°=160`；
若全部直接送入 25 行网格、顶点着色和九层光学，倾斜期间渲染工作量最高增加约 73%。

连续路径实际渲染列数因此固定为最多 120 列：水平原始列数不足 120 时全部保留，超过时在
完整安全窗口两端之间等距插值；首尾必须精确对应原始窗口首尾，不能以丢弃画外列换性能，
故 D31 的两侧覆盖保证不变。物理模拟仍使用完整 216 点网格，只有渲染投影降采样。

同一诊断还发现 `rebuildBc()` 在持续倾斜 2 秒内重建 227 次，几乎跟随 120Hz 物理子步；
原因是 `span`、`wallBlend` 和 `tiltAgit` 每个子步都改变缓存键。边界剖面是空间阻尼系数，
统一限为 30Hz 更新，最大滞后 33ms；波方程仍以 120Hz 求解，倾斜浪形激励和传感器输入
不降频、不额外低通，以免改变姿态手感。

## D29 文件名行与计时器共享水平约束（2026-07-11）

录音结束后，文件名输入框与 `.wav` 后缀的可见总长度必须与 `TimelyClockView` 一致。此前文件名行
外层写死为 `232dp`，内部又将 `EditText` 和后缀分别写死为 `192dp`、`40dp`；虽然外层数值碰巧
等于对话框宽度减去计时器两侧边距，但 `.wav` 文本不会填满固定的 `40dp`，可见右边缘会提前结束，
而且两处约束容易独立漂移。

文件名行与计时器统一使用 `match_parent` 加两侧 `24dp` margin；`EditText` 使用
`0dp + layout_weight="1"` 占据后缀之外的剩余空间，`.wav` 后缀使用 `wrap_content`。今后调整
计时器的水平边距时，应同步调整文件名行，保持两者等宽。

## D25 Hero 声音能量改为上游出生、空间传播（2026-07-11）

为根治连续“你好”时既有浪偶发上抬，D17 的“包络只作用于出生处”优先于较早 D12/ADR-0006
对全局慢标量包络的许可。保留每层六模态 `HeroWave`、低/中/高频段身份、A3 音高映射、A4
境乘子和 `Prominence` 旋律层事件；但 `heroBandTargetDp` 不再直接缩放整段可见解析波。

每层新增三频段空间能量包络：目标先按原攻击/释放常数平滑，只写入上游画外出生区，再以
`|flow|×1.5 + 0.45×waveSpeed` 的群速度随流进入可见区。可见区内已经存在的 Hero 只传播，
不会因下一帧响度、频段或音高改变而整体重塑；均匀潮位仍归 swell/level 通道。Python 与
Android 必须保持同构，并以双向不变量验收：传播到达前可见轮廓不得分叉；到达后不同声音
必须产生可测差异，防止以关闭 Hero 响应伪修复。

## D24 当前先收敛视觉材质，冻结声音驱动扩展（2026-07-11）

## D14 美学章程：克制的抒情（2026-07-11）

升级方向定位采用"克制的抒情"：以平静陪伴为基底（录音对话框里用户的主任务是说话，
水在周边视觉工作），但保留完整表达阶梯——七境式的状态分辨率、只在真峰值出现的瞬态
高潮，以及"张力=相位"级别的作品手段。表达力由阶梯的分辨率承担，不由反应幅度承担。
一句话章程（暂定措辞）："你的声音是掠过一小片真实水面的风——它服从重力，短暂记住
你的能量，在你说完时归于平静。"运动总则："静中有动、动中有静"。

**范围事实**：当前主打麦克风录音可视化（录音内容可能包含音乐）；后续将加入离线音乐
文件的可视化。音乐相关投入（节拍、speech/music 门控、高能境）须按可复用设计，原版
被裁掉的离线路径（`offline.py`/`sections.py`）未来可能回归。

**为何**：设计奖调研显示评审奖励克制、同步感与概念纯度（Odio/Journey/Monument
Valley 先例）；"准确反映声音"与"获奖美感"在 B 定位下不冲突。

## D15 表达状态：锚点配方 + 连续插值，非离散状态机（2026-07-11）

mood 性格档的继任机制：七个外观锚点（idle / silence / quiet-speech / active-speech /
melodic / loud-music / climax（瞬态）+ settle（尾声））各自是一组完整参数预设（波长
分布、chop 量、闪带宽度、猫爪率、驻波增益等）+ 触发条件；运行时由感知输入（响度
包络、4Hz 波动强度、谐波性、粗糙度、speech/music 门控、arousal）在锚点间**连续插值**，
迁移带迟滞与不对称时间常数（升快降慢）。用户永远看不到状态切换。

**境不是旅程而是查询表**（蒲福风级语义）：平淡人声整段录音只驻留 quiet-speech ↔
active-speech，表达力来自境内微观动态（4Hz 呼吸、音节猫爪、闪带宽窄、句中悬停、
句末沉降）；melodic/loud-music/climax 仅在录到歌唱、音乐、喊叫时出现。这同时修复
现状 mood 无锚点漂移导致普通语音落在未调参组合的问题。

命名：代码用功能名；马远《水图》对应题名（洞庭风细、湖光潋滟、层波叠浪、云舒浪卷、
细浪漂漂等）保留在文档与注释中，作为灵感来源与设计词汇。调参主战场明确为
quiet-speech / active-speech 两境的境内动态。

## D16 乐队分层：九层职责重分配，深两层"无动于衷"（2026-07-11）

取代"每层听全频段、远景=高频几何"的 `LAYER_ROLE_WEIGHTS` 模型：

- 装饰层（0~1）：onset/爆破音的水花与毛细闪光——高频内容改由前层**光学**表达；
- 旋律层（约 2~3）：音高轮廓与重读（语音主唱）；
- 织体层（4~6）：音节密度纹理 + 慢频段包络；
- 深层（7~8）：**永不响应逐帧人声**，只承载永恒慢涌，并以数十秒时间常数跟随能量
  积分与段落（"长曝光"语义）。

**为何**：Chion anempathetic 原则——有"不在乎的世界"，上层响应才读作"倾听"而非
仪表；透视上远水本就动得更慢更少，"远层跟齿擦音抖"违背距离感；高频以近层闪烁
表达（Journey glitter 纪律）比远层几何波动更像空气感。

**实施流程**（适用于本轮全部表达/映射改动）：先在 `audioVisualizerSimulatorFable`
Python 版实施，用户目测认可后再同构移植 Android/Kotlin 并补差分测试。

**修订（2026-07-11 用户目测）**：深层长积分只在**有声期间**生效；静默/停止后深层
以 τ≈2s 与全场一同快速归静，不做数十秒余韵沉降（第 8/9 层拖几十秒不落被明确否决）。
涌浪沉降半衰期同日由 6s 调至 3s。"结束沉降"整体求快、不求余韵。

## D17 三层时间记忆 + 波群包络，且包络只作用于浪的出生处（2026-07-11）

时间结构分三层：风浪 chop 即时跟随音节（现有注入+毛细纹）；涌浪 swell 以半衰期
积累短语级能量，是"结束沉降"尾声的本体——**默认半衰期 3s**（用户 2026-07-11 目测
6s 沉降过慢后修订；参数范围 1.5~10s 可调）；深层
（7~8）以 20~40s 长积分跟随整段录音能量史。涌浪对水位的贡献设上限并计入体积守恒，
防止长录音水位持续偏高。

响度进入涌浪 register 采用**波群包络**：能量以组为单位（一组约 2~4 个浪）乘载，
浪在组内生于尾、亡于首；一句话成为一组浪，句间停顿是组间间歇。

**D12 延伸（用户 2026-07-11 强调）**：已塑形的浪不得被随意改形（不得在波峰附近
凸起小包、不得突然变尖或变平），除非改变是必要、柔和且符合物理的（如新浪从边界
涌入引起的自然相互作用）。因此波群包络与涌浪记忆均只在**浪的出生处**起作用——
新生浪的振幅由包络/能量库决定，随后按正常物理传播；绝不以乘性场调制已存在几何。
水位类变化仅允许潮位式的缓慢均匀偏移。

## D18 注入反克隆纪律；"张力=相位"按受控边界试做（2026-07-11）

用户报告现状缺陷：强事件下九层在右侧同一位置出现九个近似相同的波包并同步流动，
"像复制粘贴一样"。成因是 `inject()`/`injectRhythmWave()` 对全部九层循环注入，抖动
（σ=7~16dp）相对波包宽度（100~216dp）过小、逐层固定延迟、形状同源。纪律：

- 同一事件的注入目标只限其**角色层**（D16），任何单一事件不得进入超过约 3 层；
- 逐层时序来自波群包络的自然传播差，废除全层固定 cascade 延迟；
- 逐层宽度/峰形/travel 独立变化，空间散布量级须与波包宽度可比；
- rhythm wave 重设计为单层（或两层交替）的单一行波，不再是九层齐发。

"张力=相位"（Whitney）采纳为试验项：以各层有效推进速度的缓慢偏置实现（洋流式、
浪形连续），相干度上限约 0.6 永不完全对齐，触发需持续数秒渐强证据 × speech/music
门控加权（平淡语音不触发）；静息态回到失谐（不均齐为常态）。对齐只作用于 hero
长模态相位，绝不同步化注入事件，避免再造克隆感。优先级在双 register 与乐队分层
之后，Python 先行。

## D19 音频前端 11 项全采纳；YAMNet 暂缓、条件触发（2026-07-11）

前端清单三批全部采纳：P1（自适应白化+SuperFlux、K 计权 momentary/short-term 响度、

## D20 渲染首批六手法（Canvas/Python 可达），AGSL 推迟到表达层收敛后（2026-07-11）

首批：
1. **闪光带升级**——废除"恒宽带内物体平移"式实现（用户明确否决"轨道车厢"观感）。
   闪点是波面微元坡度对准光源的瞬时事件：**原地生灭**（寿命约 150~400ms、各自独立
   包络），"带"只是闪点出现概率的包络（高斯软边、宽度=活动度），闪点大小不一、
   沿面微拉长、主题色染近白。验收：定格见柔边光斑贴在坡度合适处；播放是明灭，
   不是行驶。
2. **猫爪暗纹**——音节触发的局部暗色毛细斑块顺流漂移消散（OpticalWaveSet 的
   局部化+暗化变体）。
3. **句末沉降尾声**——D17 记忆结构的编排呈现（chop 快死、涌浪 4~8s 沉降、闪带收窄）。
4. **驻波呼吸（试验标签）**——仅 melodic 境把墙侧吸收缓慢调低使反射显现，墙侧出现
   原地起伏的共鸣呼吸；语音境保持海绵吸收。Python 目测不喜欢即砍。
5. **顶边羽化**——低能量时最上层轮廓向背景溶解，能量升高变锐利。
6. **波峰珍珠斑**——现有 crest glow + pearl 偏色的合并升级（非新增手法）：以峰为
   单位的局部软斑，强度=f(峰高×圆润度×坡向对光源对准度)，边界被 OpticalWaveSet
   长波长分量咬出不规则；单侧（受光峰肩）、向下慢淡出；斑心染色近白、边缘环用
   ±6° pearl 色相偏移；只在近 0~2 层、圆润峰上，语音电平同屏 ≤3~4 个；尖峰无斑
   （与"不尖窄"红线自洽）。验收：读作"贴在峰肩的软鹅卵石光泽"，无盖章椭圆感。

全部 Python 先行、用户目测认可后移植。AGSL 单 pass、bloom/RenderNode 推迟到表达
层收敛后另行立项（避免外观未定型时同一套视觉写两遍）；OLED 渐变 banding 等只有
shader 能根治的问题接受暂时存在。

## D6 第 0 层保持 Thing 原始颜色（2026-07-10）

距离屏幕最近的第 0 层代表当前 Thing 的主体身份色：纯色 Thing 的第 0 层必须完整使用
`background.color`；渐变 Thing 的第 0 层必须保留原始 `color`、`endColor` 与
`orientation`。原模拟器中“纯色 palette 自动生成向白混合 45% 的第二端色”不再用于第 0 层，
`color_breath`、`moodBright` 与 `lighten_far` 产生的混白也必须随 `depth01` 增长，因此第 0 层
混白量恒为 0。远层空气透视、声音明度变化、OKLab 层内混色、高光与物理逻辑继续保留。

**为何**：原模拟器 palette 是独立视觉配色，而 EverythingDone 的 `ThingBackground` 是记事身份色。
最近层若继续使用模拟器的自动提亮规则，会使纯色和渐变记事在正常录音态下都比记事本身浅灰，
也违背旧 `WaveVisualizerOpus`“主体/前景层使用记事本色”的既有语义。

## D7 PREPARED/STOPPED 持续监听并驱动水面（2026-07-10）

Android 录音对话框在 PREPARED 和 STOPPED 状态继续监听麦克风，以低透明度水面提供实时预览；
进入 RECORDING 时只开始写入录音文件，不重置 `FableSolRealtimeAnalyzer`、不重置其时间基准。
停止录音后立即重新开始监听也属于设计行为。保存 WAV 的起止仍严格由 `mIsRecording` 控制。

**为何**：这是 EverythingDone 的录音交互语义，不需要复刻 Python 桌面播放器只在
PLAYING/RECORDING 消费驱动的状态机。

## D8 物理容器宽度使用 View 最终实测宽度（2026-07-10）

运行时容器宽度必须来自 `WaveVisualizerFableSol.onSizeChanged(w, ...)` 的最终像素宽度除以 density。
不得直接使用 XML 的 `280dp`，也不得根据 TimelyClockView 的声明宽度自行推算；父布局、Dialog 测量和
屏幕约束共同决定出的最终 View 宽度才是唯一来源。

`REFERENCE_WIDTH_DP=320` 只保留为网格间距 `DX_DP` 的设计基准和 View 尚未测量时的回退值。
运行时的容器湿润跨度、沿重力方向尺寸、体积守恒倾斜水位、墙面边界、屏幕坐标注入中心以及
段落 surge 的 75% 宽度均使用实测容器宽度。波长、浪高、速度、固定 dp 注入宽度和
`DX_DP` 不随 View 缩放，以免改变原版的空间尺度、传播速度和数值稳定性。

## D9 自校准前增加频率边界与绝对可听度安全门（2026-07-10）

Android 近静音录音可能包含近 Nyquist 强电子干扰、低频嗡声和非平稳 AGC/噪声泵动。纯相对静音门与
flux 百分位会把这些不可闻或极低电平变化放大成约 0.5 响度和密集 onset，因此“自校准”不能等于
“完全没有绝对可信度边界”。

FableSol 前端统一采用以下规则，Python 蓝本与 Kotlin 实现保持一致：

- A 加权总能量、底噪、质心与平坦度只使用 16kHz 以下频谱；
- 32 个 flux 对数频带严格按相邻边界 `[edge[i], edge[i+1])` 求和并止于 12kHz，不再使用
  `reduceat` 最后一段延伸到 Nyquist 的语义；
- Analyzer 和时间基准重置后从静音状态启动；
- −66dBFS 为零可听度置信、−54dBFS 为满置信，中间采用 smoothstep；响度、低/中/高频动态与
  onset 包络/强度统一乘该置信度。绝对门仅拦截极低电平假活动，可信声音进入后仍使用原有底噪、
  慢中心和滚动百分位自校准；
- flux 环接收全部帧作为基线，保证稀疏真实脉冲无需先积满多个“有声帧”。

回归样本 `20260710215433.wav` 在 Python 48kHz 路径由 90 个假 onset 降至 3 个、平均响度由
0.272 降至约 0.004；Android/Kotlin 原生 44.1kHz 路径为 4 个 onset、平均响度约 0.008。

## D10 Android 重力倾角覆盖完整圆周并保持 Opus 方向锁定语义（2026-07-10）

录音 Dialog 的重力可视化必须接受完整 360° 屏幕平面方向。完全倒置手机时渲染角保持 ±180°，
水体填充方向转向 Dialog 顶部，不得沿用 Python 桌面调节滑块的 `[-90°, 90°]` 限制。
传感器角度跨越 179°↔−179° 时，Simulation 选择与当前角度最近的等价角，避免水体反向旋转 358°。
墙面过渡按水面偏离水平面的角度计算，因此 0° 和 180° 都视为水平水面。

`AudioRecordDialogFragment` 在 `onCreateView()` 锁定宿主 Activity 的当前方向，并在
`onDestroyView()`/`onDismiss()` 恢复原 `requestedOrientation`。该代码在 Opus→FableSol 迁移中没有
改动，继续作为录音 Dialog 的既有行为保留。

## D11 Android 采集会话启动阶段抑制低频暂态（2026-07-10）

部分手机的 AudioRecord/MIC 在采集启动后会输出持续数秒、随后衰减的强低频暂态。样本
`20260710231609.wav` 前 0~3 秒约为 −20~−23dBFS，A 加权能量约 70%~90% 位于 250Hz 以下，
约 4.5 秒后才降至 −55dBFS 以下。该信号真实存在于 PCM；应用当前显式关闭 AGC/NS/AEC，不能把它
简单归因于应用层“先录噪音、再开始降噪”。

Kotlin Analyzer 在每个采集会话开头增加自适应预热门：低频主导且尚未稳定的输入不进入底噪、中心、
flux 与视觉输出；连续稳定静音或可信非低频内容达到 0.3 秒后立即开放，最多等待 4.5 秒。若超时后仍是
低频背景，则把当前电平种为噪声底。该门只影响 FableSol 可视化，不裁剪、滤波或延迟保存的 WAV，
避免在用户未授权的情况下改变录音内容。

## D12 已形成的浪形不得被瞬态参数直接重塑（2026-07-10）

已经显示的浪只能因相位传播、波动方程、阻尼、边界、重力，或显式注入的新能量自然变化。
onset 不得直接改写整层 HeroWave 的振幅和频段模态；快速事件统一进入有穿屏限流的 DynamicWave
物理波包。HeroWave 只表达慢变化的声音背景：默认攻击由 0.16 秒改为 0.85 秒，各模态最短约 0.72 秒；
几何粗糙度另用 1.2 秒慢状态，快速粗糙度/毛细度仍可用于光学高光，但不能重塑宏观轮廓。

真实样本的拍击 onset 位于约 6.30、6.76、7.15、7.26 秒。禁用物理注入时，旧 onset 仍使既有轮廓在
6 帧内变化最高约 0.56dp RMS；极端频段目标单帧变化约 3.97dp RMS。修复后前者严格为 0，后者约
0.39dp RMS；真实拍击窗口不再出现远层同步突变，剩余变化来自连续传播和新注入的物理能量。

## D13 连续流速由表层事件率主导，节拍不得删除 subdivision（2026-07-11）

人的主观速度由表层事件密度、节拍层级和强弱等多种线索共同决定。FableSol 的连续流速采用 1 秒快速事件率与 3 秒保持事件率：快速通道以 72% 权重负责及时上升，慢速通道作为下限负责稳定与自然释放。已通过 D9 绝对可听度/SNR 边界的 onset，在显著度加权之外固定保留 75% 原始 subdivision；`beatConfidence` 不得再降低该保底。

tempo/phase 继续负责节拍脉冲和相位同步；tempo 对连续流速仅能在剩余行程内提供最高 12% 的正向佐证，不得以中等 BPM 向下覆盖已经较高的表层事件密度。onset strength 主要控制波高、注入能量、punch 与材质。分析侧速度攻击为 0.35 秒，Simulation 流速执行平滑为 0.48 秒；物理流速上限和全局 `flow_gain` 不因本决策提高。Python 与 Android/Kotlin 必须维持同构实现。

**为何**：固定 3 秒分母会把新出现的密集声音系统性低估约 3 秒；可靠节拍下删除弱 subdivision 会把快速元音或密集音符误判为中速；tempo 与 density 的凸组合还会让约 110 BPM 反向拉低每秒 6~8 个事件的表层速度。两段 Android 真机录音证明瓶颈位于感知映射，而不是 213.6dp/s 的第 0 层物理上限。

## D14 GLES 倾斜期间边界剖面按显示帧限额重建（2026-07-12）

连续倾斜会让 `span`、`wallBlend` 与 `tiltAgit` 持续变化。边界剖面仍以最高约 30Hz 接受新参数，
但九层不得再集中在一个显示帧内重建：除首次初始化外，每帧最多处理 5 层，下一帧完成其余层；
即使该帧因延迟补跑多个 120Hz 物理子步，也不得突破显示帧预算。

边界系数只依赖 `abs(u)`，左右点必须共用同一次计算并镜像写入，保证数值与逐点实现一致、把每层
指数运算减半。传感器采样、120Hz 波方程、倾斜几何和水体惯性不降频。Debug 性能日志继续保留
`physics` 总耗时，并增加 `steps`、`bcLayers`、`bc`、`waves`、`surface`、`compose`，用于真机判断
剩余卡顿是否仍来自边界重建。

## D15 GLES 光学实体保留 CPU 身份跟踪并按层穿插绘制（2026-07-12）

闪点、珍珠、流光和猫爪属于数量少、生命周期逻辑复杂的实体，不转成片元着色器内的逐帧随机噪声。
CPU 继续维护跨帧身份、锚点匹配、攻击/释放、顺流平移与寿命；每帧只生成少量带局部 UV 的椭圆
三角形，GLES 片元着色器负责径向软边。实体总量使用固定上限与预分配顶点缓冲，稳态不扩容。

绘制顺序必须复刻 Canvas 层遮挡：每个远侧水层区间画完后立刻画该层实体，再由后续近层覆盖；
最后画第 0 层深水填充和第 0 层实体。不得把所有实体统一放到水体之后，否则远层闪点会错误浮到
近层水面之上。光学实体使用标准 alpha 混合，水体主体仍保持不透明覆盖与原有逐层合成。

## D16 顺流流光采用水体内侧单边几何（2026-07-12）

流光不得使用“中心点切线上的直椭圆”。其长轴必须沿整段水面轮廓分段采样并随曲率弯曲；短轴从
每个采样点的轮廓开始，只向水体内部展开。片元透明度在轮廓后的短距离内从零软入，并在长度两端
与水内下缘软出。这样既不会有高光从长轴两端或短轴外侧露到空气中，也不会因硬裁切形成新亮边。

闪点和珍珠不受本决定影响：它们分别表达贴边镜面闪光与圆峰斑块，有各自的跨轮廓视觉语义。
回归必须同时检查实际流光网格的局部法向坐标全部非负，以及每个顶点均位于其横坐标对应的水面
轮廓以内；不能只检查中心切线、最终顶点数量或截图主观结果。

## D17 镜面闪点与顺流流光必须分通道约束（2026-07-12）

镜面闪点 `glint` 是高 alpha、偏白、随受光峰锚点呼吸和跟随的长高光；顺流流光 `streak` 是低
alpha、按寿命持续随背景流平移的高光。二者视觉上都可能呈斜带，但身份、运动和亮度不同，诊断、
顶点范围记录与回归必须分开。

镜面闪点不得继续使用跨轮廓的完整直椭圆。保留其峰值检测、持久身份、位置跟随和呼吸强度，几何
改用与流光相同的逐段曲面带：沿整段轮廓弯曲、只向水内展开；镜面闪点另用更窄的亮芯和更长的
软出区，避免形成锐利平直白线。固定光学顶点容量提升到 1536，只增加预分配上限，不允许稳态扩容。

## D18 珍珠斑与猫爪暗纹退出目标视觉（2026-07-12）

珍珠斑 `pearl` 与猫爪暗纹 `gust` 从 Android GLES、Canvas 回退、Simulation 状态和 Mapper 事件
入口整体删除。不得保留不可见跟踪器、阵风 FIFO 或逐帧推进；Python 同构清理由后续双端收敛时
处理，本轮 Android 主线不再生成或消费这两类效果。

保留镜面闪点 `glint` 与顺流流光 `streak`。Stage 1 下一批按现有 Canvas 语义迁移表面软带、薄峰
透光、波背阴影和最远两层羽化，不借删除两项效果之机改变其他光学参数。

## D19 四类表面效果统一使用分层曲面带（2026-07-12）

表面软带、薄峰透光、波背阴影和远层羽化进入 GLES 时统一由 `FableSolGlOptics` 生成沿轮廓的
可变厚度三角带，复用同一预分配顶点缓冲与分层穿插绘制，不恢复 Canvas Path/Gradient 或另建
每效果纹理上传。

- 表面软带仅 0～6 层，宽度由迎光坡、上凸曲率和深度共同控制；
- 薄峰透光仅 0～4 层，继续使用高出均线 4～14dp 的绝对海拔门与上凸薄度；
- 波背阴影仅 0～5 层，颜色继续走当前层记事色混黑、随深度快速减弱；
- 羽化仅 7～8 层，以 `calm01` 控制环境地平色跨轮廓溶解。

前三项只向水体内侧展开；羽化为溶解轮廓，可按既有语义跨越轮廓两侧。片元着色器只根据带内
相对深度软入软出。光学顶点固定容量提升为 20000，覆盖最坏层数与 120 列，不允许运行时扩容。

## D20 GLES 曲面带透明度严格复刻 Canvas 半正弦（2026-07-12）

Canvas/AGSL 定稿的 fade 带透明度为 `baseAlpha × 0.66 × sin(π·relativeDepth)`，峰值 0.66，
归一化积分光量为 `0.66×2/π≈0.420`。GLES 表面软带、薄峰透光、波背阴影和远层羽化必须使用
同一剖面；不得使用中央覆盖率 1.0 的宽平台。

几何厚度继续按 Canvas 的原公式，不因视觉白边问题先行缩窄。若峰值和积分偏高，同宽几何会同时
显得更白、更厚；应先恢复剖面一致，再由真机判断是否还存在颜色或几何偏差。峰值与数值积分必须
有自动回归，防止后续 shader 调整重新放大量层边缘。
