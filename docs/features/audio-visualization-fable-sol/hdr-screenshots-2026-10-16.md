## 已确认的内容

用户提供的第 1、3、4 张为 HDR，第 2、5 张为 SDR；华为图库识别前三者为 HDR Vivid。
只读检查原文件后，三张 HDR 均为 1320×2232 底图加 660×1116 增益 JPEG 的 MPF 容器，
同时有 ISO 21496-1 增益参数和 APP8 Vivid 元数据。两张 SDR 只有一幅 JPEG。
这批截图不是此前研究的旧 APP5 照片格式。

HDR 样本的三个通道参数相同：gamma=1、底图与 HDR offset 均为 0.01；最小／最大 log2 增益分别为：

| 截图 | 最小 log2 增益 | 最大 log2 增益 | 白色区域 |
| --- | ---: | ---: | --- |
| 1 | -0.0212 | 1.8452 | 录音按钮白圈 |
| 3 | -0.0291 | 1.8953 | 设置面板白底 |
| 4 | -0.0212 | 1.8772 | 录音按钮白圈 |

白圈选区避开红色图形、阴影和边缘。第 1／4 张底图的 RGB 均值约为 255／255／255，
增益 JPEG 均为 3／3／3；第 3 张设置白底为 255／255／255，增益为 4／4／4。
按 sRGB 传递函数和完整 ISO 增益计算，这些区域均约为 1.001 倍 SDR 白，三个通道相等或
仅有 JPEG 量化级差异，没有记录下用户所述的明显青绿色。

第 1 张顶部纯白背景选区的底图为 168／168／168，增益为 253／253／253，同样计算后约为
1.418 倍 SDR 白，高于原生按钮。这是截图数据中的白色亮度差异，**不是面板亮度实测**。
HDR 原文件没有 ICC，Exif ColorSpace=65535，ISO useBaseColorSpace=false；因此这里只用
中性区域核对通道与亮度关系，不把这份简化重建当作华为图库的完整彩色解码结果，也不据此
硬编码 1/1.418 之类的设备补偿。

聊天预览中的 HDR 海浪背景较暗，只是在查看这些文件的普通底图，不能单独作为 HDR 输出变暗
的证据。截图中没有发现海浪内的后方记事文字；四角的黑块在 SDR 样本也存在，不能归为
本次 HDR 独有现象。

截图样本并非同一冻结帧，不能把两张差别直接归为录音前后状态。

目前需要区分三个可检验方向：

1. 透明 PQ 图层的实际显示合成：固定图像和 EGL 配置，只将 SurfaceView 的格式声明从
   RGBA_8888 改为 RGBX_8888；若穿透随之消失，支持不透明声明相关的兼容问题。
2. PQ 与原生控件的叠加顺序：固定内容和 RGBA_8888，仅把 PQ 层放到窗口上方；比较画面内
   的白圈与背景。前置层会遮住原生左白圈，不能把“白圈不见了”当作白色已修复。
3. 白色亮度、周围颜色及显示映射：同屏放置原生白圈和 PQ 内容中的中性白圈，辅以 SDR 模式。
   若同一 PQ 层的白正常、原生白异常，和二者同时异常的后续方向不同。单张系统截图不能
   测量最终面板或排除局部色调映射、视觉对比等因素。

## debug 固定画面对照

入口仅在 debug 且命中现有卓易通判据时生效：设置 → 音频海浪动画 → 长按“HDR 高光增强”。
进入独立的测试 Activity 与 Dialog，背景为固定色条和“后方文字”，不读取或修改记事。
复用生产 `FableSolEglSession`、`FableSolGlProgram` 和 `present.frag`，使用固定 FP16 场景：
1 倍白底、彩色下半区、1 倍右白圈和 4 倍小高光；左白圈为普通 Android View。

- 模式 1：SDR 基准。
- 模式 2：现有 RGBA8 PQ、圆角、下置图层。
- 模式 3：仅把 holder 声明改为 RGBX；EGL 仍请求并验证同一 RGBA8 PQ。记录“请求不透明”，
  不声称已经读取硬件合成器内部标志；圆角外的黑块是预期试验代价，不用于正式界面。
- 模式 4：保持 RGBA8 PQ，仅前置图层；原生左白圈被遮住是预期结果。

API 35+ 的亮度余量和生产实现一样设置在 SurfaceView 上；不扩大整个 Dialog Window 的余量。
每项可记录正常／偏色／穿透／两者都有，并补充具体区域。日志即时写入私有目录，重进仍保留，
可保存为“下载/EverythingDone”中的 `.txt` 文件或通过系统分享文件。

记录包含版本、设备公开属性、请求格式、已验证 EGL 空间、GL 类型、真实 framebuffer 回读、
Surface／窗口的 PixelCopy 状态与指定位置样本、View／窗口 alpha 及肉眼反馈。
窗口 PixelCopy 不等于包含全部子 Surface 的系统截图，Surface 的 SDR 复制也不等于屏幕测量；
日志明确区分这些来源。只采样人工图案，不采集用户记事或截屏图片。
