# 卓易通音频弹窗偏色与 HDR 关闭排查

## 用户反馈与已知边界

- 新的关键对照：用户确认 HDR 开启和关闭时，系统截图都看不到后方内容；HDR 截图中的白色“相对正常”。实际屏幕仍穿透、偏色。已收到五张原始截图，依次为 HDR／SDR／HDR／HDR／SDR；HDR 三张均含 ISO 增益参数与 APP8 Vivid 数据，白色按钮／设置区的底图和增益没有青绿色通道偏差。详见 [原始截图分析](hdr-screenshots-2026-10-16.md)。尚无实际屏幕拍摄对照，不能据此断言某个驱动函数有错。
- debug `202610161504` 的 RGBA8 PQ 候选仍穿透、白色仍偏色。更换整数缓冲位深没有解决问题，撤回“主要由 2 位 alpha 导致”的倾向判断；下一轮应区分图层透明合成、原生控件叠加以及真实屏幕与系统截图的差异，不再用普通离屏 shader 通过作为修复依据。
- debug `202610161444` 新反馈：海浪区域半透明，能看到弹窗后面的元素。用户确认只在 HDR 开启时出现，强度 0、画面稳定后不穿透。上一轮 RGB10_A2 的桌面验证不能代表卓易通实际合成；此前偏色是否消失尚未确认。
- debug `202610161401`：录音、音频附件、海浪设置弹窗的粒子动画白底偏青绿色；录音按钮在静止时也偏色。关闭粒子动画后仍存在，弹窗外的记事详情页正常。
- 强度 UI 的 0 档对应内部 `STRENGTH_OFF=1`。上一版 `needsFloatBuffer` 在兼容环境忽略强度，`canBuildHdrSurface` 同样提前返回，且 headroom 固定自动；这是关闭档仍保留 HDR 合成状态的确定原因。此前 D220 已记录相同的关闭语义要求，D222 为免换格式而增加的例外需要撤回。
- 当前没有卓易通设备的程序化访问；本轮不使用 ADB。关闭策略以真实调用的纯策略回归复现，颜色以实际共享 shader 输出和捕获调用链验证；设备合成器是否修复必须由用户实测，不把离屏通过当成真机结果。

## 待验证假设（按优先级）

五张原图及图库回放后的更新：白色按钮的数据保持中性，但第 1 张在图库仍略偏青，第 4 张较正常。
不能只归因于原弹窗透明合成。新增固定画面对照同时检查透明声明、叠加顺序、原生白与 PQ 白的
亮度／颜色关系；详细预测、日志来源和限制见 [截图与合成对照](hdr-screenshots-2026-10-16.md)。

本轮穿透问题优先检查：① RGB10_A2 的 alpha／实际缓冲在兼容合成器中解释不一致；② EGL 配置与实际默认 framebuffer 格式不一致；③ HDR 切换遮盖或父层 alpha 未恢复。实际 shader 回读中，圆角内部 alpha 为 1，准备态的 0.16 只在 RGB 中与背景混合；这不足以复现设备侧穿透，也不能据此宣布透明度正确。

RGBA8 失败及截图反馈后，优先级改为：① PQ 图层在真实显示中的透明合成；② SDR 控件与 PQ 图层叠加的色彩／alpha 处理；③ 窗口或父层 alpha 状态。系统截图与屏幕拍摄是下一项对照；如仍需端侧探针，应对照透明／不透明 PQ 和前置／后置图层，并记录应用缓冲与窗口像素、真实会话格式，而不是再仅改变缓冲位深后称已修复。此前图片的成功不能证明透明弹窗的合成路径可靠。

前一轮偏色问题的假设：

1. FP16 PQ 在卓易通中的合成路径影响同弹窗普通 SDR 控件：若在颜色公式不变时改为已由图片验证的整数 PQ 格式，仍有 HDR 但不再出现局部偏色，支持该假设。
2. 独立 Surface 的 PixelCopy／SDR 转换存在兼容问题：若改用渲染器输出的显式 sRGB 快照，粒子材料的白色和彩色应与 SDR 原值一致。它不能单独解释关闭粒子后仍有的按钮偏色。
3. PQ shader 本身改变白色：实际 shader 的中性输入应有相等 RGB 输出；若相等，可排除公式直接使中性变青，不能排除系统的后续解释错误。

## 验证记录

- 关闭策略先红：7 项策略测试新增前的 6 项测试中，关闭档预期 SDR 的断言失败，日志 `memory/fablesol-pq-colors-red.log`。修正同时区分“用户主动关闭”与“PQ 初始化失败”，避免滑到 0 后设置被永久禁用。
- 共享 shader 实际离屏检查：48 组原 SDR／scRGB 与提交基线逐像素一致，24 组 PQ 公式对照通过；8 组中性输入的 PQ RGB 无通道偏移。因此公式本身未复现用户所见青绿色，不能据此排除真实系统合成／PixelCopy。
- 新增实际 RGB10_A2 目标的上下圆角检查，先量化 alpha 再预乘，透明像素 RGB 为零；与旧版 FP16 相比，屏幕边缘只有四档 alpha，不能称位深与上一版相同。SDR 快照仍保留 8 位完整 alpha，42 组灰阶／彩色／透明度与显式 sRGB 参考匹配，最大绝对误差 0.002168404（小于一个 8 位色阶）。
- 首轮合并构建成功；979 项 JVM 回归中，唯一失败为既有源码检查禁止出现任何 `linearToSrgb`，与新加的 SDR 快照分支冲突。将该断言收敛为要求编码受 `uOutputSdr` 保护，继续以实际 GPU 对照检查原生路径未变。
- 最终完整回归：979 项中 978 项通过，1 项既有按需 CPU 性能探针跳过，无失败；debug 构建成功。普通设备的首帧遮盖顺序保留原方法，只有卓易通采用新截图与窗口 commit 等待。

## 实现与测试边界

### HDR 穿透后续候选

- 静态核对：`presentationAlpha` 仅在 shader 中混合背景和场景的 RGB，没有设置 SurfaceView／遮盖 View 的整体透明度；圆角内部输出 alpha 为 1。桌面回读没有复现用户设备的穿透，因此未把“2 位 alpha 必然导致半透明”当成确定结论。目标缓冲的兼容解释为首要假设。
- 音频兼容窗口从 RGB10_A2 换为 RGBA8 PQ，检查 EGLConfig 的 native visual、四通道位深及窗口 framebuffer 实际四通道位深，仍实际创建 PQ 并核对色彩空间；不接受时回退 SDR。此候选尚未在卓易通验证。
- 场景仍为 FP16、高光亮度范围不变；最终 PQ 颜色只剩 8 位，加入共通道抖动抑制色带。圆角使用完整 8 位 alpha，量化后预乘；不改普通 SDR／scRGB、图片与视频导出。
- 由于 PQ／SDR 现在共用 RGBA8，显式按目标输出空间重建 EGL 会话。沿用窗口提交后的遮盖，补充恢复渲染循环、冻结状态补帧及会话序号，防止关闭无效、遮盖超时和旧状态覆盖新选择。
- 最新离屏结果 `pq-opacity-result-20261016.json`：48 组原生输出逐像素一致；24 组 PQ 公式、2 组 RGBA8 圆角、24 组双后景合成、8 组中性颜色及 42 组 sRGB 快照通过。双后景合成覆盖准备态 alpha 0／0.16／0.6／1、1／3.6／9.6 倍预算，内部始终完全不透明；测试尺寸下圆角保留 19 档 alpha，而非此前四档。它不复现卓易通的驱动／合成器。
- debug 构建与 980 项相关 JVM 测试通过：979 项成功，1 项既有按需 CPU 探针跳过。没有操作设备；本轮仍需用户检查高光、穿透、颜色和开关交接。

### RGB10_A2 迭代记录（已替换输出格式）

- 屏幕 PQ 改为与图片路径相同的精确 RGB10_A2 配置；场景继续 FP16，颜色转换公式不改。这是针对设备合成的修正候选，应用侧无法读取真实面板结果，仍需用户确认白色按钮是否恢复。
- 只有卓易通 FableSol 实现 `ParticleSurfaceSnapshotSource`，粒子源图与换格式遮盖统一从生产者线性场景生成 sRGB；普通设备、其它 SurfaceView 和粒子的真实缓冲恢复确认仍走原 PixelCopy。
- 强度 0 退回 RGBA8／SDR，撤销自动 headroom。切换先盖快照，等目标格式会话提交首帧才撤盖；连续请求只取最新强度，避免旧帧或迟到截图覆盖后续选择。

## 一手资料

- [Khronos PQ 扩展](https://registry.khronos.org/EGL/extensions/EXT/EGL_EXT_gl_colorspace_bt2020_linear.txt)：PQ 编码由应用执行，Surface 色彩空间用于告知平台如何解释像素。
- [Android PixelFormat](https://developer.android.com/reference/android/graphics/PixelFormat)：RGB10_A2 与 RGBA_F16 的不同位深。
- [AOSP SurfaceView](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/view/SurfaceView.java)：圆角专用方法仍为隐藏 API，本次不用隐藏 API，继续由 shader 生成圆角。
