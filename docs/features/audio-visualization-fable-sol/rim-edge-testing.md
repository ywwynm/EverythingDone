# 银丝沿轮廓连续性的测量方法

针对"银丝断断续续 / 上边缘有黑点"这类沿层轮廓的细线渲染缺陷（D219）。工具在
Python 模拟器侧，因为 `water.frag` 是两端共享 assets，改 shader 即双端同源：

```bash
C:\Users\ywwynm\miniconda3\envs\everythingdone\python.exe tools/rim_edge_report.py
```

工作目录 `E:\projects\audioVisualizerSimulatorFable`。常用选项：

- `--baseline-dir <另一份 glsl 目录>`：修复前后 A/B。基线目录用
  `git show <ref>:shared/fablesol/glsl/water.frag` 导出到一个含其余 glsl 副本的
  临时目录即可。
- `--strip`：附"沿轮廓拉直"的条带 PNG，绿色虚线标出轮廓所在行，可直接看出亮芯
  落在轮廓上还是内侧。
- `--width-sweep`：扫 0.16/0.28/0.60/1.20/2.00dp 五个粗细档，验证亮芯内移封顶
  以及"改善集中在细档"。
- `--samples 1`：模拟 MSAA 建立失败退化到单采样的设备。

场景是固定音频活性 + 固定种子的确定性中高能水面（与 `hdr_visual_regression`
同源），不读音频文件，所以数字可跨会话直接比较。

## 判据

**主判据 `phase_peak_corr`** —— |亚像素相位| 与逐列银丝峰值的相关系数。亚像素
相位是"层轮廓落在像素中心还是像素边界"，与水面几何无关；这个相关系数显著非零
就说明银丝亮度被像素栅格支配，肉眼即读作沿线忽明忽灭。目标：接近 0。

**辅助判据** `peak_ratio_p95_p05`、`peak_cv` —— 逐列峰值离散。银丝本身有滑动亮结
与顶点高亮，天生有起伏，因此报告同时给出关掉滑动调制（`uplift_rim_slide=0`）的
`noslide_*` 对照；只有 noslide 那一组的离散才适合当渲染质量指标。

`energy_median` 用来判断修复是"补缺口"还是"整体提亮"：配合拉直图的沿线亮度
p95 一起看——p95 基本不动而中位明显上升，说明补的是原先被削掉的暗列。

## D219 基线数字（density=2、`uplift_rim_width=0.28dp`、MSAA 4x、HDR 3.6）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| `phase_peak_corr` L0 / L1 | −0.548 / −0.312 | −0.154 / −0.029 |
| `peak_ratio_p95_p05` L0 / L1 | 5.4× / 11.4× | 3.5× / 6.8× |
| `noslide` 同上 L0 | 3.4× | 2.2× |
| `peak_cv` L0 / L1 | 0.482 / 0.857 | 0.371 / 0.696 |
| `energy_median` L0 / L1 / L2 | 0.277 / 0.417 / 0.130 | 0.726 / 0.873 / 0.269 |

L2 及更远层的 `p95/p05` 会是天文数字，因为银丝按设计只在波峰凸段出现、p05 为 0；
远层只看 `phase_peak_corr` 与 `peak_cv`。

## 排除性检查

判定"上边缘有暗带"之前必须先做这两步，否则容易把正常层间梯度当成缺陷：

1. 用参数消融确认候选：`back_shade_gain=0`（波背暗带）、`glint_capacity_gain=0`
   （闪点）、`glare_strength=0`（星芒）。D219 中三者与完整版数值一致，全部排除。
2. 关掉银丝（`uplift_crest_rim=0`）后看轮廓附近的逐 offset 平均亮度剖面。若剖面
   **严格单调**，就不存在独立暗带——D219 实测 L1 从 −5px 的 0.3833 单调降到 +1px
   的 0.3127，用户看到的"黑"其实是亮线上的缺口露出的下层水体色。
   注意：`near_min vs far_mean` 这类跨距离比较会把单调梯度算成负值，不能用作暗带
   判据；要判局部凹陷得用剖面形状或二阶差分。

## 颗粒感（"小矩形拼线"）的判据：逐像素粗糙度

`phase_peak_corr` 只测"亮度是否被栅格相位支配"，测不出"线是否连续"。后者看
`rim_edge_report.py` 输出的 `roughness`：

```
roughness = 逐列可见峰值序列的一阶差分 RMS / 该序列的 RMS
```

序列取每列在窗口内的最大值（该列银丝的可见峰值），**不要**换成"固定整数行"的
口径——亮芯内移量一变，固定行就抽到高斯的不同斜率位置，跨版本不可比（D220 中间
一版曾因此得出 L0/L1 互相矛盾的结论）。

参考值（0.28dp 档、density=2、MSAA 4x、HDR 3.6）：

| 状态 | L0 | L1 |
|---|---|---|
| D219/D220 之前 | 0.295 | 0.243 |
| σ 下限 0.72px | 0.059 | 0.114 |
| **σ 下限 1.0px（现行）** | **0.040** | **0.062** |
| σ 下限 1.30px | 0.036 | 0.058 |

L2 及更远层的 roughness 天然偏高（0.23 量级）：银丝按设计只在波峰凸段出现，大量
列为 0，差分 RMS 相对整段均值就大。远层只做同版本对比，不与近层比绝对值。

配套两步排除：先看 `high_freq_share`（周期 ≤6px 的能量占比）——D220 实测 0~2%，
说明不是高频噪声而是线的表示不足；再用"`waterEdgeCoverage` 恒 1"消融确认与边缘
软带/MSAA 无关（D220 实测逐位相同）。

判断颗粒感**不要**读 nearest 放大图的方块形状——任何 1px 宽的斜线放大后都必然呈
阶梯方块。要么看 roughness，要么看 `--strip` 的拉直条带。

## 遮挡与"反复横跳"的判据（D221 补）

`roughness` 与 `phase_peak_corr` 都只看**亮度**，测不出"银丝整段不见了"。判"看得见
/看不见反复横跳"要另外两个量：

1. **无丝列比例**：逐列银丝净贡献峰值低于阈值的列占比。
2. **它与"轮廓被更近层遮挡"的重合率**：逐列比较本层轮廓 y 与所有更近层轮廓 y 的
   最小值。D221 实测重合率 100%（L2 108/108、L3 218/218、L8 146/146），据此确认
   无丝列全部来自几何遮挡，而不是亮度调制。

判完遮挡还要再往上一层看**层带屏幕高度** `y[(L−1)*ROWS_PER_LAYER] − y[L*ROWS_PER_LAYER]`
的逐列分布。中位为负说明该层几乎整条轮廓都在别层后面，只会在波峰处露出零星几段——
观感就是"一串小矩形"。D221 实测 L3 中位 −6.1px、L8 −4.3px，根子是
`sim.layer_dc_dp()` 的九层基准高度在真实音频下 95% 的时刻存在反序。该层不修（用户
2026-07-25 裁决不动水位），但诊断时必须先排除它，否则会把它的症状误判成银丝实现的
缺陷。

## 两端表现可能不同：Python 的兜底会掩盖 Android 的爆炸

D221 踩过一次：Python 端复现不出用户截图里的小尺度缺口（真实音频 PEAK 帧缺口
0.0%），因为同一轮里 Python 侧先加了数值兜底钳制，而 Android 的对应实现把雅可比
行列式钳在 `1e-9`、梯度爆到约 1e7。**凡是两端各写一份的数值代码，复现不出来时先
逐行比对两端的退化保护，不要先怀疑场景不够极端。**
