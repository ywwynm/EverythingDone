# 偏好 · audio-visualization-fable-sol

## 解析光晕轻量强度为 0.21（2026-07-13）

- `analytic_halo_strength` 从 0.22 微调为 0.21；光晕范围、数学衰减、曲面内侧约束及其他三项
  质感参数不变。

## 本批四项质感优化一起实现（2026-07-13）

- 1/f 全局呼吸、微法线风梳纹理、朝阳 SSS 与解析光晕本批一起实现，不再逐项等待真机验收。
- 四项仍须保留独立强度参数，便于后续按观感单独调弱或整项删除。

## 双色深度散射轻量强度为 0.21（2026-07-13）

- Stage 2-2 的 `depth_scattering_strength` 采用 0.21；deep/subsurface 派生规则、浪峰收拢掩码、
  固定光向和其他水体参数保持上一版不变。

## GLES 表面边带不得比 Canvas 更厚或更白（2026-07-12）

- 表面软带、薄峰透光、波背阴影和远层羽化迁移到 GLES 后，感知厚度与亮度必须以 Canvas 定稿版
  为基准，不能因为 GPU 剖面不同而把每层轮廓都画成连续白边。
- Canvas 的 fade 带采用峰值 0.66 的半正弦透明度；GLES 必须保持相同峰值与积分光量。
- 在 GL 合成、颜色和光学语义尚未与 Canvas 对齐前，不得通过单独缩放表面软带或远层羽化的宽度、
  亮度、透明度来补偿整体观感；应先修复迁移差异，再基于相同参数比较。
- 2026-07-13 起，表面软带与远层羽化均恢复 Canvas 原始宽度和 alpha（100%）；此前 34%/62%
  与 15% 的 GLES 感知补偿全部撤销。

## 移除珍珠斑与猫爪暗纹（2026-07-12）

- 珍珠斑、猫爪暗纹不再属于 FableSol 的目标视觉，应从 GLES 主路径和红天空 Canvas 回退路径一起
  移除，不能只在当前后端隐藏。
- 对应的实体跟踪、阵风状态与事件映射也应删除，避免为不可见效果继续消耗 CPU。
- 镜面闪点与顺流流光保留；下一批继续表面软带、薄峰透光、波背阴影和远层羽化。

## 顺流流光不得越出水面轮廓（2026-07-12）

- 顺流流光是沿波面切线倾斜并随水流移动的高光，但几何必须只存在于水体内侧。
- 流光可以贴着波峰边缘滑动，不能因为完整椭圆跨越切线而有一部分露到空气侧；陡坡和宽流光
  同样必须遵守该边界。
- 长流光不能只沿中心点切线画成直线；必须随整段波峰曲率弯曲，避免两端从曲面穿出。
- 水面轮廓处应软入，不能用生硬裁切换来新的亮边或锯齿。

## 镜面闪点长高光同样不得越出水面轮廓（2026-07-12）

- 偏白、较亮、较长并随受光波峰移动的镜面闪点，与低透明度顺流流光是两个不同实体；诊断和
  回归必须分开，不能看到“斜高光”就默认属于流光。
- 镜面闪点也必须沿整段波峰曲率弯曲，并且只向水体内侧展开；不允许完整直椭圆的一半留在空气侧。
- 高光亮芯应柔和收拢，不能形成一条锐利、平直、像贴在曲面外侧的白线。

## OpenGL 失败回退必须显示红色天空（2026-07-12）

- OpenGL ES 未正常启用、EGL/GLSL/绘制失败或运行时切回 Canvas 时，Canvas 天空必须强制
  显示为纯红色，作为一眼可见的诊断标记。
- 正常 GL 路径不得出现该红色天空；不要只写隐藏日志或使用普通 Thing 色静态填充，让用户
  无法判断当前实际运行的渲染后端。

## 前后俯仰不得在中途硬截断（2026-07-12）

- 手机的完整 `−90°~90°` 前后俯仰都应有连续、单调的视觉响应。
- 可以为透视与水体惯性保留安全输出范围，但必须采用越接近极限越缓的软压缩；不得在
  `±55°` 或更早的观察角边界突然停止，也不得越过临界值后回退。
- 原始手机角度、用于水体惯性的角度和用于透视的观察角应分开表达，避免一个硬限幅同时
  截断多条视觉通道。

## 阴影必须保留记事颜色身份（2026-07-12）

- 浪面上的暗部不得出现脱离当前记事色的灰黑或固定蓝黑色。
- 波背阴影、猫爪暗纹等显式阴影应由当前层的记事颜色混合一定比例黑色得到，只允许
  变深，不应额外冷偏、换色相或混入一套固定阴影色。
- 混黑比例不得跨层固定：远层水体已经被空气透视提亮，阴影混黑量必须随 `depth01`
  快速递减，使远层黑色“很淡很淡”、接近消失，不能在淡色水体上留下可辨认的黑斑。
- 阴影几何可以继续表达背光坡和局部暗纹，但颜色必须仍能辨认出当前记事的色彩身份。
- 连续水面纵向法线受光的负向分支也属于阴影：可以保留背光强弱，但输出颜色必须回到
  当前水体基色混黑轴；不得让天空反射差或 RGB 减法把背光坡拉成灰黑色。正向受光不受此限。

## 录音完成后的文件名行与计时器等宽（2026-07-11）

- 录音结束后，上方重命名区域的 `EditText` 与 `.wav` `TextView` 组成的可见总长度，
  应与下方 `TimelyClockView` 一样长，不能更短。
- 两者共享同一组水平边距；文件名输入框弹性占用后缀之外的剩余宽度，后缀按实际内容宽度排列。

## 人声语义优先级（2026-07-11）

- 当前开始重点关注“人声是否存在”的准确检测，尤其是音乐混音中的唱歌、说唱、合唱与 spoken
  word 进出，而不是只区分 speech/music 或只看 top-1 音频类别。
- 目标平台以 Android 端侧实时分析为主；检测结果应能作为 FableSol 慢语义驱动，同时不得阻塞
  现有低延迟 DSP 与录音路径。

## 当前迭代优先级（2026-07-12 更新，取代 07-11 版）

- 当前主线：GLES 迁移三阶段（D41）——Stage 0 性能修复 → Stage 1 GLES 一比一
  复刻现有视觉 → Stage 2 逐像素视觉升级。
- **A6（声音驱动表达批）在 GL 计划整体完成后解冻**（D44，取代"视觉批目测通过
  后即解冻"的原约定）。A1~A4 的声音感知、映射和境状态系统仍保持现状。

## 性能与渲染架构（2026-07-12 grill 问答确认）

- 流畅验收：View 锁 60Hz，静置/说话/倾斜全程稳定 60fps（D38）；不追 120Hz。
- 新渲染路径必须 API 26+ 严格像素级一致（D40）——排除 AGSL 新特性，这是
  选择 OpenGL ES 的直接原因之一。
- 旧 Canvas 水体渲染在 GLES 验收后彻底删除（D42），不做长期双路径。

## 已否决的视觉方向（2026-07-11）

- A5.5 的“三段光学合成 + 组内层降权 + 向上展开的大面积浪顶平面 + 深度吸收 + 折射视差”
  整体观感不如此前 A5，用户要求完整回退。后续不得把这一整套方案重新应用；若借用其中单一手法，
  必须独立、小幅试做并与 A5 基线直接 A/B，不能再次同时改变层次、颜色和表面结构。

## 视觉质量红线（2026-07-11，升级调研问答中用户明确）

- **不要尖而窄的浪**：注入波包设最小宽度下限与峰形锐度上限，波高与宽度联动
  （高浪必须宽），任何"冲击性→峰形"映射（前端清单第 11 项）都在此约束内工作。
- **不要敏感的水位颤动**：水位通道只允许潮位式慢变（低通 + 死区 + 斜率限制）；
  快速能量一律进波场，不进水位。
- **宁少勿烂**：此前的水面粒子类效果实现质量不佳（用户 2026-07-11 反馈）。每个
  视觉手法必须在 Python 模拟器里先做到"单独看足够好"并经用户目测认可，才允许
  移植 Android；做不好的手法宁可整个砍掉，不上线降级版。

## 重力与屏幕方向

FableSol 的手机重力行为应与迁移前的 Opus 保持一致：完全倒置时水体来到录音 Dialog 顶部；
录音 Dialog 存续期间禁止宿主 Activity 自动旋转，关闭后恢复打开前的方向策略（2026-07-10）。

## Python 运行环境

分析、测试和运行 `audioVisualizerSimulatorFable` 时使用 Conda 环境 `everythingdone`（2026-07-10）。

## 浪形连续性

已经塑形完成的浪不得因音头或快速音频参数在短时间内生硬改变自身形状；只能依据物理传播、重力、
阻尼、边界，或显式进入的新能量/浪涌自然变化。该要求同时适用于 Python 蓝本和 Android 移植
（2026-07-10）。
