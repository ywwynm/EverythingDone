## 卓易通海浪：撤回消费等待，恢复控件及时捕获

用户反馈上一版感觉没有改善、略卡。新版日志确认：同为 60 Hz 的连续录音片段中，计时提交间隔从 21.45 ms 增至 23.25 ms，控件捕获到提交从 18.51 ms 增至 21.11 ms。海浪从约 49 恢复至 53 次提交／秒，但控件没有获得收益。两次录音并非严格受控，因此不把所有差值都归于代码。

上版为减少无效捕获，等待 GL 取用上一份前景才开始下一次捕获；这项等待平均约 10.5 ms。未消费替换虽降为 0，却限制了控件及时更新。本版撤回该限制，恢复 HWUI 捕获与 GL 处理重叠，继续保留资源就绪后的合并补捕获。

仍然只有一次 HWUI 绘制在途，三个缓冲按原 GPU fence 归还，不能提前覆盖 GPU 在用内容。消费回调只记录诊断，不改变下一次捕获的状态、超时或调度。日志按帧区分实际消费和未消费即归还，支持尺寸变化期间的新旧缓冲并存。

仅修改卓易通前景路径；未修改海浪基础计算、shader、GL 帧循环、普通设备路径、圆角、前景合成、粒子和 HDR 切换方案。涉及普通设备的后续优化仍会先确认。

构建及 517 项相关 JVM 回归通过。保留原日志导出、按版本清理和手动“清空并重新记录”。此次是撤回不合适的限制，尚不能宣称全部卡顿已经解决。安装后可用相近场景录音 20～30 秒，再导出日志，对比计时提交间隔与海浪耗时。
