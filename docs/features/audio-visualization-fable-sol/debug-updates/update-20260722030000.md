## FableSol：`sample()` 只对渲染窗口求值（零画质代价，约省 0.6ms）

`rs` 长期实测恒为 0——单调修复在真实参数下从不触发——因此把 `sample()` 限制在渲染
窗口内不改变任何输出。这是本轮唯一挡在裁窗前面的未知量，现已排除。

物理网格有 216 点，但 `buildFrame` 只读 `[i0, i1-1]`；容器 280dp、θ≈0 时其中约 **42%
永远不会出现在画面上**。现在这部分不再计算。

实施要点：

- 窗口分两层：`fair` 区间 `[i0-1, i1]` 覆盖 `buildFrame` 会读到的全部列；`raw` 区间再
  各宽一列，因为 fair 化在 p 处要读 `raw[p-1..p+1]`；
- **fairing 的端点式继续绑定真实数组端**（index 0 与 215），不绑窗口端。倾角大时 `i0`
  真的可能落到 0，若把窗口端当数组端处理，会在窗口边界造出一段不同曲率的曲线，
  表现为可见接缝；
- 相位递推锚点重锚到窗口起列（`modeBaseX = kx · uGrid[rawLo]`）。重锚后与从 0 递推的
  差异在 1e-13 量级，远低于下游 float32 精度；
- `layerMean` 保留全 216 列——它是各层的 DC 去除项，裁窗会改变水位；`depthMeanX` 是
  逐列纵深均值，只有窗口内的列被消费，可以裁；
- 单调修复随之限制在窗口内（`rs ≡ 0`，无实际影响）；
- `Sample` 新增 `windowLo`/`windowHi` 公开本帧实际求值的区间。GLES 与 Canvas 两条路径
  的取样下标都是 `[i0, i1-2]` 与 `next ≤ i1-1`，恒在窗口内，已逐条核对。

测试相应更新：`FableSolCurveFairnessTest` 原本遍历全部 216 点断言"解析切线 ≈ 中心差分"，
裁窗后窗口边界处会出现新旧数据交界。现改为遍历实际求值区间，**并新增两条契约断言**——
窗口必须完整覆盖 `[i0, i1-1]`，且必须窄于全网格（否则裁窗没有生效）。这样测试覆盖的
正好是生产路径。

桌面探针实测：`surface2d.sample` **172µs → 97.9µs（−43%）**，与 42% 的裁剪比例吻合。
真机上 `sample` 应从约 1.5ms 降到约 0.85ms。

全量 209 项 JVM 测试通过。**画面不应有任何变化**——被砍掉的是永远不显示的列。
