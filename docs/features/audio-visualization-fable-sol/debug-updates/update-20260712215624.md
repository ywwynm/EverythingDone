# 修复 FableSol 水面在 Stage 0 版本中完全静止

## 发布说明

### 用户反馈与诊断

用户安装 Stage 0 首版后发现录音仍在进行，但水面、波浪和倾斜响应全部静止，并回传
`fablesol_frame_perf.log`。日志中录音 Dialog Window 的 FrameMetrics 持续产生，但完全没有
水面每 120 次 `onDraw` 输出一次的六段耗时汇总，说明不是物理参数归零或传感器失效，而是
水面只留下布局触发的初始画面，Choreographer 帧循环根本没有启动。

### 根因与修复

Android View 通常先执行 `onAttachedToWindow()`，随后才完成首次 layout。前者调用
`ensureAnimating()` 时 `width/height` 仍为 0，启动条件不成立。Stage 0 已移除音频和传感器
回调里的逐次 invalidate，但首次 `onSizeChanged()` 得到有效尺寸后没有重新调用
`ensureAnimating()`，因此再无任何入口启动动画。

现已在 `WaveVisualizerFableSol.onSizeChanged()` 更新物理容器宽度后立即再次尝试启动帧循环。
这样无论 attach 与 layout 的先后顺序如何，较晚获得完整条件的生命周期回调都会启动
Choreographer；音频消费、物理推进、波浪绘制和 latest-value 倾斜消费随之恢复。

### 验证

- 完整 `:app:testDebugUnitTest`：通过。
- `:app:assembleDebug`：通过。
- 当前 JVM 测试环境没有真实 Android View attach/layout seam；使用用户日志作为原始复现信号。
- 新版真机恢复后，`debug_logs/fablesol_frame_perf.log` 应开始出现 `onDraw[...]` 汇总。
- 未使用 adb、模拟器或物理设备。

### 真机重点确认

- 打开录音 Dialog 后水面是否立即持续运动。
- 说话时波浪是否响应，倾斜手机时水面方向是否变化。
- 日志中是否出现 `onDraw drain[...] physics[...] sample[...]`。
