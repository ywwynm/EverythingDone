# FableSol Debug 更新

## 2026-07-11 - 阶段 C：AGSL 逐像素渲染增强（C1 抖动 + C2 软带）

### 背景

阶段 A/B（表达层 + Android 移植）收敛后，按 D20 启动阶段 C。用户确认真机为
Android 16，圈定 C1 + C2 范围；C3（单 pass 统一光学：吸收/折射/焦散）另行立项。

### 实现

- 新增 `FableSolAgsl`：两个 RuntimeShader 运行时编译，API < 33 或编译失败时
  返回 null，渲染自动回退到既有 Canvas 路径（D20 预案）。
- **C1 渐变抖动**：环境天空渐变与九层水体填充渐变经 `dithered()` 包装，
  shader 内叠加三角分布噪声（两次哈希求和，±1/255 × alpha）——消除 OLED
  大面积平缓渐变的色阶条纹（banding），该问题自迁移以来按 D20 暂存至今。
  视觉设计零变化，只是"更干净"。
- **C2 软带逐像素化**：`drawOneSidedBand` 的 fade 路径优先走 AGSL——把该带
  的轮廓上沿与厚度（≤216 列）作为 uniform 数组传入，shader 逐像素插值出带内
  相对深度并求连续钟形剖面（平台值 0.14/0.48/0.72 与 CPU 三子带堆叠一致，
  过渡 smoothstep 连续化）。表面带、薄峰透光、波背自阴影、体光、珍珠斑、
  猫爪、顶边羽化全部受益：无子带阶差、低透明度带不再用单填充近似，且路径
  光栅从 CPU 移到 GPU。uniform 上传缓冲复用，无逐帧分配。
- 光斑/流光的旋转径向渐变椭圆本就是 GPU shader，未改动。

### 验证

- `:app:testDebugUnitTest`、`:app:assembleDebug` 均 BUILD SUCCESSFUL；
  JVM 单测不触及 RuntimeShader（运行时按 API 门控）。
- shader 若在特定设备编译失败会整体回退，不影响既有渲染——真机若看到
  与上一版完全一致的画面（含 banding），说明回退被触发，需回报排查。
- 未使用 adb。真机验收点：① OLED 上天空/水体大渐变的条纹是否消失；
  ② 软带（浪顶表面带、透光、自阴影）是否更连续柔和；③ 帧率与发热变化。
