## 卓易通海浪：按前景消费继续捕获，减少无效重绘

新版日志确认补捕获有效：在两次均报告 60 Hz 的录音 18～26 秒片段中，计时捕获间隔从 23.44 ms 降至 16.69 ms，156 个绘制版本全部捕获；提交间隔从 24.18 ms 小幅降至 22.58 ms。GL 排队由 6.90 ms 降至 6.52 ms，并未变慢；但海浪整帧从 16.90 ms 增至 20.11 ms，成功提交由约 57 次／秒降至约 48 次／秒，形变到提交的总延迟也没有下降。两次录音负载并非严格受控，不能将全部差值归于补捕获。

本轮发现捕获端约每秒产生 60 帧，GL 实际取用约 45 帧；8 秒内 484 次捕获有 120 次在取用前被新帧替换。这些捕获未用于输出，构成可减少的额外工作。

本版新增 FableSolForegroundDelivery，仅在卓易通兼容路径等待前一份前景被 GL 取走后，再捕获最新控件变化。等待期间仍合并更新，确认后沿用及时补捕获；拒收或未消费即归还也可继续。消费确认只放行下一次捕获，不提前释放 GPU 使用的纹理或缓冲。保持三个缓冲、一次 HWUI 在途、原 fence 回收及关闭／HDR 交接；迟到的旧回调不会解除新帧等待，确认异常有超时回退。

用户明确要求可能影响非卓易通设备的优化提前确认。本版没有修改海浪共用物理、网格计算或 shader，也没有修改普通设备路径；共享 GL 线程仅在卓易通前景导入回调增加确认，海浪帧循环保持。

保留原日志导出、按版本清理和手动“清空并重新记录”。新增等待消费次数／耗时、消费确认回主线程耗时、消费与提前归还计数，继续记录计时捕获和提交间隔、总延迟、未消费替换数量及海浪耗时。捕获次数下降本身不代表更流畅，需联合观察实际提交和延迟。

构建和 517 项相关 JVM 回归通过，其中 10 项新增交付链测试覆盖慢消费者、最新更新合并、GPU 未完成禁止覆盖、旧回收、拒收、关闭及 1000 次周转。尚未执行设备操作，实际流畅度和转场仍待复验。

安装后重新打开录音弹窗，录音约 20～30 秒，观察计时和按钮动画，再从原入口导出即可。新版本会清理本功能旧版诊断；请在导出本轮结果前不要手动清空。
