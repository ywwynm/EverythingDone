## 安静环境下水流不再停死：静息流速回归（D179）

本版只改一个参数，其余一律没动。

### 为什么

你那段 12.5 秒的录音我分析了：整段 RMS **−84.0 dBFS**（峰值 −70.3）。作为对照，
历史 11 段录音是 −30.7 ~ −52.8 dBFS，也就是说这段比过去最安静的还低 31dB，幅度只有
1/35。16bit 下这个电平约等于 2 个最低有效位，基本是量化噪声。

离线回放的结果是全程「镜塘」（IDLE）、`flow01` 恒为 0、水流 0 dp/s。**判定本身没错**
——它确实落在「数字静音」这一侧。问题是当前设定下数字静音要求水**完全**不动。

而这个设计确实是后来才改的，你的记忆没问题：

| 时间 | 静息流速占比 | 静止时 L0 流速 |
|---|---|---|
| 7-10 最早基线 | 0.24 | 43.2 dp/s |
| 7-10 之后 | 0.18 | 32.4 dp/s |
| 7-20 因果耦合重构 | **0.0** | 完全静止 |

7-20 那次是有意归零的，当时的原则是「确认的数字静音严格保持零流速」。现在看，这条
原则在 −84dBFS 这种真实的安静环境里会让画面直接死住，所以改回来。

### 改了什么

静息流速占比 0.0 → **0.10**。它的作用方式是只抬低端、**满速完全不变**：

| 声音强度 | 改前 | 改后 |
|---|---|---|
| 完全静音 | 静止 | **18.0 dp/s**（15 秒穿屏） |
| 很轻 | 18.4 | 35.6 |
| 安静段典型值 | 48.6 | 63.7 |
| 中等 | 88.0 | 99.2 |
| 最大 | 200.0 | **200.0**（一点没变） |

静音时各层：最前层 18.0、中层 12.7、最后层 8.9 dp/s。用你那段录音复验过，水位和
状态判定都还是 0，**只有物理流速抬起来了**。

选 0.10 而不是当年的 0.18/0.24，是因为水面上本来就有一层运动跟水流无关——方向场和
环境波按重力波色散自己传播（最长的模态 46.2 dp/s）。所以「流速 0」从来不等于画面
冻住，再叠静息流速要留余量。

### 本版看什么

1. **完全安静时水是不是在缓慢地流**。目标是「看得出在走、但绝不抢戏」，15 秒穿一次屏。
   如果觉得太慢没感觉，我可以调到 0.18（8.5 秒穿屏）；太活跃就往 0.05 收。
2. **安静但有点声音时会不会变得太活跃**。这一档从 48.6 涨到了 63.7，是本版唯一可能
   过头的地方——上一版刚为「安静段像静止」抬过一次低端，两条抬升现在叠加了。
3. **大声时的流速应该和上一版完全一样**（满速 200 dp/s 没动）。如果感觉快了，那是错觉
   或者别的问题，请告诉我。

上一版那四项（巨浪触发不跳、平顶变平、流速滑停、高响度水位）本版没有任何改动，
如果你还没来得及看，这一版一起看即可。

另外你那段录音的 −84dBFS 本身我觉得偏低得可疑——正常手机麦克风的底噪一般在
−60 ~ −70 dBFS。**如果你录的时候屋里其实能听见空调、键盘或者窗外的声音，那大概率
是采集链路的问题**（这是改了采样率协商之后的第一段录音），请告诉我，我单独查。
判断办法：同一环境下用系统自带录音机也录一段，对比一下音量。
