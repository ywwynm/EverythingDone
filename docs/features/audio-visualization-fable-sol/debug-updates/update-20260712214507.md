# FableSol Stage 0 首轮性能修复与真机帧诊断

## 发布说明

### 背景

连续 2.5D 水面在真机上全程不够顺滑，倾斜手机时卡顿加重。已确定当前主线为
Stage 0 通用性能修复 → Stage 1 OpenGL ES 一比一复刻 → Stage 2 逐像素质感升级。
本次先交付可独立验证的 Stage 0 首轮，并加入不依赖 adb 的真机帧数据采集。

### 本次改动

- `WaveVisualizerFableSol` 改用 `Choreographer.frameTimeNanos` 固定 60Hz 自节流；在
  120Hz 屏上不再每个 vsync 都运行整套物理和渲染，模拟时间仍按实际渲染时间推进。
- 录音 Dialog 自身 Window 请求 60Hz；API 35+ 同时调用 View 级
  `setRequestedFrameRate(60f)`。
- 重力传感器监听移到独立 `HandlerThread`；传感器线程只写入无分配 latest-value
  信箱，渲染线程每帧最多消费一次最新三轴值，避免倾斜期间主线程消息竞争和跨线程
  修改 `FableSolSimulation`。
- `drawHighlights`、表面带、猫爪暗纹、闪点、珍珠、边缘羽化等光学路径的帧内
  `DoubleArray` 全部改为按锚层复用的 scratch 池；`FableSolMath` 和 optical wave
  增加 caller-buffer 入口，避免内部重新分配。
- 新增临时 `FableSolPerformanceMonitor`：采集录音 Dialog Window 的
  `DRAW/SYNC/COMMAND_ISSUE/SWAP/TOTAL/GPU` P50/P95/P99，以及 onDraw 的
  drain/physics/sample/color/mesh/submit_optics 六段耗时；日志位于应用文件目录
  `debug_logs/fablesol_frame_perf.log`，统一带 `[DEBUG-FABLESOL-PERF]` 标记。
- 位图 atlas 暂未实施：Stage 1 将删除现有 AGSL 上传路径；先看真机日志中
  `SYNC/COMMAND_ISSUE` 是否仍为主要瓶颈，再决定是否值得做过渡优化。

### 验证

- 新增 `FableSolFramePacerTest`、`FableSolGravityInboxTest`、
  `FableSolMetricWindowTest`、`FableSolMathBufferTest`。
- 关键测试先在实现不存在时确认编译失败，完成实现后转绿。
- 完整 `:app:testDebugUnitTest`：通过。
- `:app:assembleDebug`：通过。
- 未使用 adb、模拟器或物理设备。

### 真机重点确认

- 静置、持续说话和倾斜手机时是否都比上一版顺滑。
- 水体速度、光学形状、重力方向与上一版是否一致。
- 如需进一步归因，请回传 `debug_logs/fablesol_frame_perf.log`；探针会在性能验收完成后删除。
