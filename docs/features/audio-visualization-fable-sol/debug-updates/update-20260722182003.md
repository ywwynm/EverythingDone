# 巨浪纯实时链路收口：母带严格四次，Android 录音严格两次

## 用户要求与纠正

- 《Lose My Mind》母带只应在约 52～53、69～70、139、158 秒触发，整曲必须恰好 4 次；
  任何第 5 次都属于误触。
- 开头约有 2 秒静音、只覆盖歌曲前约 1:40 的 Android 录音，应在录音时钟约 54～55、
  71～73 秒触发对应两次。
- 《银花玉鉴逐人来》约 2:23 的明显高潮需要巨浪。
- 用户指出此前“Python 母带 0 次”的结论来自错误路径；本次必须使用真实 realtime 分析与
  动画消费路径，且不得写歌曲名、时间戳或固定每段配额。

### 实现

- Python 保留源声道声明，以 512 sample 批次喂入 `RealtimeAnalyzer`；GUI 传递并逐批、
  逐 hop 消费完整 `analysis_batch`，用 generation 隔离 load/seek，realtime 不再混入离线
  timeline section，后到事件不能跨观测批次回插。
- 巨浪门控按当前声学证据区分 physical attack、低水位 novelty/dense bridge、
  section-backed phrase 与 resurgence；Section 只开短鉴权窗，不直接制造巨浪。
- Android 的 GLES 与 Canvas 使用同一批次 inbox 与交织规则；Foote fallback 阈值、minor
  诊断事件、`state_sensitivity` 传递和 capture startup 语义与 Python 对齐。
- 修正 BeatTracker 的跨语言舍入：Kotlin 三处改用 ties-to-even 的 `Math.rint`，避免 76.5
  被 half-up 取为 77 后造成约 53 秒的 110→72.94 BPM 假换挡。
- 将进入巨浪证据链的 7 个定长 ring 也统一到 Python ties-to-even 容量语义，包括
  harmonic/low motion、onset/centroid 与三类 10s context 窗。
- Android 探针只把 48kHz 单声道 WAV 作为 `AudioRecord` 产品回放；拒绝把立体声母带算术
  降混后冒充 Android 产品路径。
