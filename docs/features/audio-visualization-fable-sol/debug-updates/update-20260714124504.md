# 修复 HDR 银泽网格分片与闪点突消

## 本轮目标

用户在 Android HDR 设备上反馈：新加入的水体亮银斑不够亮，边缘偶尔像未对齐的矩形或三角形
拼片；由 `glintCapacity(layer)` 控制数量的 HDR 闪点有时会突然消失。同时需要确认并清理
`depthScattering` 及 deep/subsurface uniform 链中的死代码。

## 诊断结论

- 使用 Python ModernGL 直接编译 Android 共享 GLSL，并在固定 FP16 帧上分离水体 HDR 增量。
  原银泽峰值约为 `1.17× reference white`；网格对角线处的二阶跳变约为单元内部 `1.54` 倍，
  说明拼片感主要来自粗网格坡度经过非线性 Fresnel 后被放大，不是色阶量化。
- 闪点原先在 `intensity < 0.04` 时硬裁剪，裁剪前一帧仍可有约 `7% alpha`；若暂停或卡顿造成
  2 秒帧间隔，`0.80s` release 还可能在单帧把强度压到原来的约 `0.082`，两者都会产生突消。
- `depthScattering` 的 strength 固定为 0，其函数、uniform、参数和两处调用确属空转；但
  `deepColor` 仍是局部保色背坡阴影的目标色，`subsurfaceColor` 仍由日出 SSS 使用，因此这两组
  派生颜色及上传不能删除。

## 实现内容

- 水面顶点新增一组只供 HDR 银泽使用的低通坡度；在实际渲染网格上横向滤波 3 次、纵深滤波
  4 次。原始坡度继续供几何、微法线和背坡阴影使用，不削平水体本身。
- HDR 银泽近层目标 headroom 从 `1.6` 提到 `2.0`，Fresnel×太阳响应使用 `0.70` 次幂拓宽；
  仍只在 scene-linear HDR 分支生效，并受设备 headroom、深度退出和统一 HDR 增益约束。
- 闪点在 `0.018～0.060` 强度区间软退场，track 在 `0.015` 退休前已不可感知；闪点跟踪的
  单帧时间步封顶为 `1/15s`，暂停或卡顿后的长时间差分多帧消化。顺流流光仍按真实时间推进。
- Android GLES、Canvas 回退以及 Python ModernGL/QPainter 使用同一闪点退场语义。
- 删除 `depth_scattering_strength`、`uDepthScatteringStrength`、`depthScattering()` 和两处空转
  调用；保留仍有实际消费者的 deep/subsurface 颜色链。
- Android 共享 shader 定稿后再一次性同步 Python；Python 继续保持 320dp 容器和 640px 宽度。

## 数值与回归结果

- 固定帧水体 HDR 峰值约由 `1.17` 提至 `1.28× reference white`。
- 网格对角线/单元内部跳变比约由 `1.54` 降至 `1.14`，银泽专用坡度总变化量下降约 `43%`。
- Android 114 项单元测试全部通过，`:app:assembleDebug` 通过。
- Python 105 项 `unittest` 全部通过，共享 GLSL 已由 ModernGL 实际编译并完成 FP16 离屏渲染。
- 未使用 ADB，未连接物理设备或模拟器。

## 真机观察重点

- 亮银斑是否明显更亮，同时边缘不再呈现矩形或三角拼片；
- 闪点在正常消失、短暂卡顿和录音状态变化时是否都能自然退场；
- SDR 基色、局部保色阴影、远层洁净度和水体运动是否保持不变。
