# FableSol 物理容器改用 Dialog 最终实测宽度

## 发布说明

用户确认 PREPARED/STOPPED 持续监听并驱动水面属于既定录音预览设计，不需要按 Python 播放器状态机
重置或门控 Analyzer。本次修复固定 320dp 物理容器与 Dialog 最终宽度不一致的问题：
`WaveVisualizerFableSol.onSizeChanged(w, ...)` 把布局系统最终测得的真实像素宽度换算为 dp 后传给
Simulation；容器跨度、体积守恒倾斜水位、墙面、渲染范围、屏幕坐标注入中心和段落 surge 宽度
全部改用该运行时宽度。XML `280dp` 和 TimelyClockView 只参与上游测量，不直接进入物理计算。

固定 320dp 现仅作为网格采样间距和 View 尚未测量时的回退，不缩放波长、浪高、速度和固定 dp
注入宽度。新增 `FableSolContainerGeometryTest`；修复后以真实宽度 280dp 为例，水平跨度为 280dp，
30° 倾斜跨度为正确的 452.487113dp。`:app:testDebugUnitTest` 与 `:app:assembleDebug` 均通过，未使用 adb。

## 用户反馈与确认

在完成 Python → Android 迁移审查后，用户确认 PREPARED/STOPPED 状态继续监听麦克风并驱动水面
属于既定录音预览设计，不需要复刻 Python 播放器的 analyzer reset/time-base/gating 状态语义。

用户进一步要求检查固定 320dp 物理宽度的影响，并明确“真实宽度”不是 XML 中的 `280dp`，而是
Dialog 完成全部布局测量后 `WaveVisualizerFableSol` 实际得到的最终宽度；该宽度可能受
TimelyClockView、父布局、Dialog 窗口和屏幕约束共同影响。

## 诊断

首版中 `Simulation` 的容器跨度、沿重力方向尺寸、倾斜体积守恒水位、墙面边界、屏幕坐标注入中心
都直接使用固定 `WIDTH_DP=320`；`FeatureMapper` 的段落 surge 宽度也固定为 `320×0.75`。
因此当 View 最终宽度不是 320dp 时，水面物理边界与屏幕可见边界不一致。

回归信号稳定复现：以最终宽度 280dp 为例，旧实现水平跨度仍为 320dp；30° 倾斜跨度为
487.128129dp，而按真实宽度计算应为 452.487113dp。

## 修改

- `WaveVisualizerFableSol.onSizeChanged(w, ...)` 使用最终实测像素宽度 `w`，除以当前 density 后传给
  `FableSolSimulation.setContainerWidthDp(...)`。不读取 XML `280dp`，也不直接查询 TimelyClockView。
- `FableSolSimulation` 的湿润跨度、沿重力方向尺寸、体积守恒倾斜水位、墙面边界、渲染可见范围和
  屏幕坐标注入中心全部改用运行时 `containerWidthDp`。
- `FableSolFeatureMapper` 的段落 surge 宽度改为运行时容器宽度的 75%。
- 原 320dp 常量改名为 `REFERENCE_WIDTH_DP`，只作为 `DX_DP` 网格采样间距和 View 尚未测量时的回退。
  波长、浪高、速度、固定 dp 注入宽度与网格间距不随 View 缩放，避免改变原版视觉尺度和物理稳定性。
- 更新 D2，并新增 D7（录音预览状态语义）与 D8（最终实测宽度语义）。

## 验证

- 新增 `FableSolContainerGeometryTest`，覆盖任意实测宽度下的水平/倾斜跨度、沿重力方向尺寸和
  View 中心到水面坐标原点的映射。
- 修复后 280dp 水平跨度为 280dp，30° 倾斜跨度为 452.487113dp，与公式完全一致。
- `:app:testDebugUnitTest`：`BUILD SUCCESSFUL`。
- `:app:assembleDebug`：`BUILD SUCCESSFUL`。
- 未使用 adb 或模拟器。
