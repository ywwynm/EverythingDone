## 发布说明

### 用户反馈

- 快速连续“啦啦啦”时，水流速度明显低于人的主观速度。
- 新的长录音 `20260710235706.wav` 同样表现偏慢，需要结合两段真机录音统一调整。

### 诊断

- 两段录音都没有触及第 0 层 213.6dp/s 的物理上限，瓶颈位于感知速度映射。
- 固定 3 秒事件率会让新出现的密集声音在前 3 秒被系统性低估。
- 旧实现会随着 beat confidence 升高而删除更多弱 subdivision；约 110 BPM 还会通过凸组合向下拉低高事件密度。

### 修改

- 新增 1 秒快速事件率，与 3 秒保持事件率组合：快速通道负责及时提速，慢速通道负责稳定和自然释放。
- 已通过听觉门的原始 subdivision 固定保留 75%，不再被可靠节拍删除。
- tempo/phase 继续驱动节拍；tempo 对连续流速只提供最高 12% 的正向佐证，不再压低表层速度。
- 分析侧速度攻击由 0.65 秒缩短到 0.35 秒；Simulation 流速平滑由 0.72 秒缩短到 0.48 秒。
- Python 蓝本、离线分析与 Android/Kotlin 保持同构；物理速度上限和全局 `flow_gain` 未提高。

### 验证

- `20260710234846.wav`：有声帧 `flow01` 中位数约 0.65，第二个 onset 后约 0.92 秒越过 0.5，第 0 层中位流速约 128dp/s。
- `20260710235706.wav`：有声帧 `flow01` 中位数约 0.83，第 0 层中位流速约 173dp/s，仍保留物理余量。
- 近静音 `20260710215433.wav`：仍仅 3 个 onset、97% 帧静音、平均响度约 0.007，没有复发噪声驱动高速水流。
