## 卓易通海浪：保留纹理复用，调整 90 Hz 动画请求

用户回传纹理复用版性能日志，要求核对计时和海浪性能，并排查 90 Hz 降到 60 Hz 的原因。日志显示前景替换耗时从 0.81 ms 降至 0.22 ms，稳定片段有 1040 次缓存命中、零重绑失败，纹理复用本身有效。但计时提交间隔从 20.73 ms 变为 21.52 ms，海浪从 54.57 降至 50.72 次提交／秒，整体没有继续改善；海浪计算也变慢，两次录音负载未严格受控，不能把差值全部归因于代码。

本次停止触摸约 4 秒后降到 60 Hz，再次触摸后恢复 90 Hz；省电和录音窗口节能选项关闭，温控没有报告异常。原窗口和 Surface 一直请求 120 Hz，但卓易通实际可达 90 Hz。这支持触摸升频结束后原请求没有维持高刷，尚不能证明兼容器内部具体原因。

本版仅调整卓易通 Direct 图层：同分辨率存在 90 Hz 档时明确请求 90 Hz；Android 16 接口可用时使用适合 UI 动画的“至少此帧率”语义，明确拒绝时回退原兼容语义。只允许无缝刷新率切换，不反复撤票刺激系统。请求失败会记录并限频重试，成功后才更新记录；暂停、粒子交接和 Surface 更换保持正确的撤票／恢复。模式枚举移到已有轮询，减少逐帧查询和列表分配。

保持纹理缓存、捕获调度、安全 fence、海浪共用计算、GL 帧循环、shader、普通设备路径和已验证的圆角／前景／粒子合成。涉及非卓易通设备的后续优化仍先确认。

构建及 544 项相关 JVM 回归通过。保留原日志导出、按版本清理和手动重录。可连续录音约 30 秒，开始后先 15 秒不触摸，再轻触界面，导出日志；同时检查刷新率、计时提交和海浪耗时。高刷请求是否被卓易通采用，以及整体实际收益，仍待设备复测。
