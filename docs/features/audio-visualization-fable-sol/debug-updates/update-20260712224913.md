# 修复 GLES 倾斜物理尖峰并细分性能日志

## 用户反馈

用户确认 OpenGL ES 已正常启用，但倾斜手机时仍感觉卡顿。真机性能日志中 GL draw、swap 基本低于
1ms，GPU P50 约 2.2ms；`glFrame.physics` 则从 P50 约 5.8ms 上升到约 12.5ms，P95 约 16ms。

## 诊断

- GLES 绘制和 GPU 不是本轮瓶颈，卡顿集中在 `FableSolSimulation.update()`。
- 倾斜会持续改变 `span`、`wallBlend` 和 `tiltAgit`，触发边界剖面更新。
- 旧实现每次把 9 层×216 点集中在同一帧重建，并为阻尼、摩擦执行大量 `exp`；30Hz 限频降低了
  平均次数，但没有消除单帧尖峰。

## 修复

- 边界剖面改为显示帧级预算：首次初始化后每帧最多处理 5 层，下一帧完成剩余层。
- 预算不随该帧补跑的 120Hz 物理子步增加，防止慢帧进一步堆积边界工作。
- 剖面只依赖 `abs(u)`，每层只计算左右半幅 108 点，再严格镜像到另一侧。
- 单个持续倾斜帧的边界采样点上限由 9×216 降至 5×108，约减少 72%；传感器采样、120Hz
  波方程、倾斜几何与惯性响应保持不变。
- `glFrame` 日志新增 `steps`、`bcLayers`、`bc`、`waves`、`surface`、`compose` 分项；若真机仍有
  卡顿，可直接区分边界重建、九层波方程、二维表面推进或逐帧轮廓合成。
- Canvas 回退红天空诊断保持不变。
