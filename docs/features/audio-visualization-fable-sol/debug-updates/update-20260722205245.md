## 音乐高潮巨浪泛化与录音展示一致性

### 用户要求与纠正

- 《Lose My Mind》母带只能触发 4 次；Android 短录音在约 2 秒前导静音后命中其实际录到的
  前两处；《银花玉鉴逐人来》约 2:23 必须触发。
- 用户纠正：`assets` 中的音乐都有足以产生巨浪的高潮，`Back To December = 0` 不是负样本；
  不能为了恢复其它歌曲而让《Lose My Mind》出现第 5 次。
- 使用修改前录制的 `20260722163150-Lose My Mind-全.wav` 与
  `20260722163541-银花-全.wav` 比较母带，除巨浪外还要检查水位、七境、普通浪、流速、
  颜色和逐层主浪；Python 与 Android 必须走相同实时产品语义。

### 路径与门限修正

- 验收保留源声道声明，以 512-sample feed 批次逐 hop 消费，只在事件真正被观察到的批次内
  交织；不再使用离线 timeline、latest-only 帧、单声道母带或未来 section。
- 巨浪门新增三类通用证据：中高水位盲区的多证据到达；12 秒因果响度范围成熟后达到滚动
  q95、`novelty >= 0.20` 且有物理攻击/音乐运动/arousal 的低响度高潮；结构窗内短而明确的
  50ms downbeat。相对高潮和结构短语各自独立确认，不能与普通 180ms 分支交替累计。
- 没有歌曲名、文件名、绝对播放时间或固定每段次数分支；14 秒全局可读间隔仍生效。

### 录音展示双轨

- raw 分析帧、raw 七境和巨浪 gate 保持权威；固定 capture display 轨只驱动连续动画和展示
  七境，避免录音补偿反向授权巨浪。
- display 响度使用固定 pivot/ratio/blend 展开；low/mid/high 相对份额使用固定
  `2.0 / 0.90 / 0.65` 校正并同步 centroid。master display/raw 逐帧恒等。
- 缺失 `display_*` 的旧缓存或 IPC 帧统一使用 `-1` 哨兵回退 raw，不再错误显示零水位。
- 更强动态展开、kinetic 平滑及全局 band magnitude 补偿都会恶化至少一条 Lose 对照，已通过
  三轨消融淘汰；不按单个房间/扬声器链路继续拟合。

### 发布后全录音复核

- Android 与 Python 对同一两份全录音的 raw/display water 逐帧一致，visible state 各只差
  1 个渲染帧；巨浪仍分别严格为 4 次和 1 次。
- Lose 相对母带的 level MAE 4.506dp、wave MAE 0.0833、state 87.65%、hero L0
  1.931dp，已无明显差异。《银花》的频谱/颜色已接近，但 level 11.456dp、wave 0.2182、
  state 66.09%、hero L0 8.583dp，仍有明显录音链残差。
- 继续消融的固定曲线会伤害 Lose；最安全的因果 p95 inverse-AGC 也只把《银花》level
  降到 10.750dp、state 提到 66.22%，同时让 Lose 的 wave/state 退化。即使用对齐母带水位
  做 oracle，《银花》state 仍只有 80.18%、wave MAE 仍为 0.1607，说明剩余误差不只来自
  响度，不能通过当前单录音曲内自学习安全消除。正式源码与已发布 APK 保持不变。
