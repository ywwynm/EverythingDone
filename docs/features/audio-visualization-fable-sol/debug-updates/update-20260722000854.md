## FableSol：安静更有流、高潮更克制、浪不再变来变去（D173）+ 双端 parity 修复

按五条观感反馈逐条以真实音频离屏回放定量确认后修改，Python 定稿、Android 同步。
全部改动都在阈值 / 时间常数 / 输运速度一级，**没有新增算法**：CPU 帧成本探针里
`sim.update` 11.1 → 12.0µs（占 120fps 预算 0.15%），其余阶段在噪声内。

### 1. 安静时水面真的在动

旧执行器的 10dp/s 听感微调在 K=0..0.25 上渐入，实测安静段（K01 中位 0.17）第 0 层
只有 **1.8dp/s，穿屏要 176 秒**——画面读作完全静止。改为 20dp/s 且在 K=0..0.10 内
渐入，低端锚点 24 → 42dp/s（K=0.25）；高端几乎不动（K=1.0 只从 190 → 200dp/s）。
数字静音仍严格为 0。

### 2. 巨浪回到「每个高潮最多两道」

取消配额后，同一段副歌平台上的第三、第四记重击也会成浪。段落通道保持不限次
（段落边界本身就是稀有的结构证据），只把无结构支撑的重复短语通道压回每 episode
一次；本地到达的攻击门 0.28 → 0.40。评审曲目回到 4 次 / 录音版回到 1 次，验证工具
新增「不得有额外巨浪」两项检查。

### 3. 声音停了画面立刻开始退潮

真凶是：确认静默的 2 秒里状态机**直接 return**，档位被冻住。实测一次咳嗽推上
CLIMAX 后，PEAK 段驻留 2.7 秒而期间平均响度只有 0.17。现在照常解码、只喂零证据；
另外 LIFT/CLIMAX 只允许在「正在充能」时点亮——正在释放的残余电量不得在跌过阈值的
途中重新点一次（旧版会冒出响度为 0 的 LIFT 段）。深层长积分 30s → 14s（原本第 8 层
的流速比第 0 层整整慢 **20.4 秒**，安静下来后远景还在演几十秒前的氛围）。
咳嗽后回到 CALM 由 6.3s 缩到 4.1s。

### 4. 已显示的浪不再自己变形

冻结音频实验显示 85% 的改形与声音无关，是场本身的问题。定位到一个真 bug：三个尺度
组共用一个「流速×1.5 + 0.45×波速」的输运速度，而每组载波各按 `c=sqrt(g/k)` 行进
——第 0 层安静时包络 142dp/s、载波只有 93dp/s，**包络从自己的波峰上滑过去**，屏幕里
的浪于是原地长高变矮。改为逐组按自己的相速度输运。同时把模态谱宽从 4.4 倍收到
2.9 倍（改形残差 10% → 8%，可见起伏 RMS 反而从 8.2 涨到 9.6dp），声像几何位移单独
限速 9dp/s（`pan01` 的 0.22s 时间常数原本会让整片主浪瞬移 ±24dp）。
高档位的改形残差降 25~35%。

### 5. 要高就必须也宽

实测 CLIMAX 段波峰的 height/width p90 已到 **0.134**，而 Stokes 破碎极限是 0.142
——贴着破碎线，正是「尖锐」的来源。现在按每个尺度组自己最短模态的波长设振幅上限
（红线 0.085，约破碎线的六成），被削掉的能量转给还有余量的更长模态。p90 降到
0.071（宽度稳定在高度的 14 倍以上），中位数约 0.05，可见起伏 RMS 只掉 2~5%。

### 6. Python / Android 实时链 parity

新增两侧同口径的离线回放探针，把同一个 WAV 在两端各跑一遍完整实时链逐帧比对。
`loud_db` 两端逐帧完全相同，说明 FFT、K/A 计权、频段与采集调理都在 parity；唯一实质
差异是 Python 缺了 Android 的采集启动抑制与底噪播种，导致 −51dB 的房间底噪被当成
音乐几十秒（K01 0.83、水流 130dp/s）。回移后状态一致率 73.0% → 92.9%、水位差
10.5 → 3.1dp、深层流速相关 0.874 → 0.999、巨浪次数 2 vs 1 → 1 vs 1。

**结论：耦合逻辑两端本就一致**。同一个 WAV 喂进去，Python 一样会因那次咳嗽进入
CLIMAX——之前觉得 Python「正常」是输入域差异（手机麦克风 + 固定采集校正 vs 笔记本
麦克风），而不是两端算法跑偏。

### 本版需要在真机上看什么

- 安静/接近安静时水面是否明显在流动，而不是几乎不动。
- 咳嗽、拍手这类突发之后，水位与浪高是否很快回落（档位应在 1 秒内离开 PEAK/CLIMAX；
  水位仍会因 3 秒响度窗撑住约 3 秒，这是既定刻度，本轮未改）。
- 高潮段的浪是否明显变圆变宽、不再出现尖峰。
- 屏幕里已经存在的浪，在声音变化时是否还在原地长高变矮。
- 整首歌里巨浪出现的次数是否回到「偶尔一次」的密度。
- 帧率：本轮不应有可感变化，HUD 的 `work p50/p95` 与上一版对比即可。
