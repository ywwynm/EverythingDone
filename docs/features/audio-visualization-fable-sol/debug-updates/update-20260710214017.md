# 修复第 0 层水面颜色偏浅

用户反馈：正常录音态下，距离屏幕最近的第 0 层水面比 Thing 本身明显更浅、更灰；并确认纯色与渐变
Thing 都应让第 0 层直接保持记事颜色。

诊断确认不是透明度或 OKLab 移植错误，而是原模拟器的 palette 规则被沿用到了 Thing 身份色：纯色会
自动生成向白混合 45% 的第二端色；纯色和渐变又都会在第 0 层叠加声音/性格驱动的混白。

本次修改：

- 新增 `FableSolLayerColorPolicy`，集中管理水层基础色和混白量。
- 纯色 Thing 的第 0 层两个基础端点都使用 `background.color`，不再生成浅色端点。
- 渐变 Thing 的第 0 层保留原始 `color`、`endColor` 与 `orientation`。
- `lighten_far`、`moodBright`、`color_breath` 产生的混白统一乘以层深 `depth01`，因此第 0 层混白量
  恒为 0，远层仍会逐渐变浅并保留声音驱动的明度变化。
- 高光、珍珠偏色、环境天空、水体物理和逐层透明度未改动。

验证：新增 4 项 `FableSolLayerColorPolicyTest` 回归测试；先确认旧规则下出现预期失败，再确认修复后
通过。完整 `:app:testDebugUnitTest` 与 `:app:assembleDebug` 均为 `BUILD SUCCESSFUL`。未使用 adb。
