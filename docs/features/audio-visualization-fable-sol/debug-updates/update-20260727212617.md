# 新增「画面响应设备倾斜」开关

## 画面响应设备倾斜

设置里此前只有导出侧的「保留录音过程中的画面倾斜」，它决定导出视频时要不要回放录音期间
记下的重力轨迹，管不到实时画面。实时侧的倾斜一直无条件开启，代价是录音对话框与音频附件
对话框打开期间会锁死记事详情页的屏幕方向。

本次在「音频海浪动画设置」里新增一条勾选行「画面响应设备倾斜」，位置在「HDR 高光增强」
滑杆正下方、第一个波浪参数组之前，默认开启。勾选框的外观、涟漪与整行可点的交互与
「保留录音过程中的画面倾斜」完全一致。

### 关掉之后

- **录音对话框与音频附件对话框的水体恒按竖直渲染**，不再注册重力传感器。
- **详情页恢复自动旋转**。锁方向原本只为倾斜服务——重力到屏幕坐标的换算按对话框打开时的
  屏幕方向定死，中途转屏就会算错；没有倾斜也就没有锁的理由。
- **录音写出的 WAV 不再包含重力轨迹**。既然当时的画面本就不倾斜，记下来的姿态没有可复现
  的对象。已经录好的音频里那条轨迹不受影响，导出要不要回放它仍由「保留录音过程中的画面
  倾斜」单独决定。

设置界面顶部的实时预览随勾选状态即时启停：勾掉的同时水面立刻回正，不必关掉对话框再打开。

该开关与 HDR 强度同属画面偏好，因此「恢复默认」会把它一并复位为开启。

### 实现与验证

- `FableSolTuning` 新增 `live_tilt` 偏好键与 `liveTiltEnabled` / `setLiveTiltEnabled` /
  `clearLiveTilt`。
- 两个对话框在打开时读取一次并固定，据此跳过锁方向与传感器初始化。
- `AudioRecorder.setGravityTrackEnabled(false)` 让录音开始时不启动重力轨迹收集器，收尾时
  自然不写 `EDmo` chunk；仅靠"不投递采样"不够——收集器启动本身就会把当前姿态落成起始点。
- 13 个 locale 补齐新字符串。
- `:app:assembleDebug` 通过；本轮未使用 adb，实机行为（关掉后详情页能自动旋转、录出的
  WAV 无重力轨迹）尚未在设备上验证。
- 已发布阿里云 debug 更新 `202607271327`。本地 APK、本地与远端元数据、远端 APK 的
  SHA-256 均为
  `20666195dbada67f2032587deae8b865385d8466133eca541b1195f721dece17`，
  文件大小均为 21,204,365 字节；远端发布说明与本地逐字符一致。

### 已知限制

关掉倾斜后横屏打开录音或音频附件对话框，对话框（竖直方向固有高度 420dp / 450dp）会被压扁，
按钮行仍可见但水体取景会被裁掉一截。后续可为这两个布局补横屏变体。
