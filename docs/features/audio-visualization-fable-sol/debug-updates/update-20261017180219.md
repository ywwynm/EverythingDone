## 卓易通海浪：补捕获被阻塞的控件更新，继续改善计时动画

本次分析用户回传的 202610170943 性能日志。与上一版同取录音 18～26 秒、均报告 60 Hz 的片段，缓冲占用从 66.92 ms 降至 45.45 ms，GPU 退休等待从 18.63 ms 降至 0.45 ms，无空闲缓冲跳过从 25.46% 降至 0.41%；计时新画面提交间隔从 30.01 ms 缩短至 24.18 ms，控件新前景提交从约 36 次／秒升至约 45 次／秒。这些是应用内指标，两次测试并非完全受控对照，也不等于屏幕实测 FPS。

剩余缺口集中在捕获：计时绘制平均间隔已约 16.67 ms，但 152 个绘制版本中只有 109 个捕获、108 个提交；约 23% 的遍历因上次捕获尚未完成而跳过。旧逻辑在资源返回后通过 invalidate 等下一次遍历，可能额外错过一个刷新周期。

本版只调整卓易通路径。FableSolCaptureRetry 将被阻塞的更新合并，在 HWUI 完成或 GL 安全归还缓冲后，通过一个主线程任务补捕获最新控件。已有遍历抢先更新时取消补偿；待布局时延后；关闭、失败时取消，静止时不持续刷新。仍保持三个缓冲、一次 HWUI 在途和 GPU 完成才归还的约束；海浪画质、计时字形和时长、圆角、颜色、粒子及 HDR 交接方案保持，普通设备不启用该路径。

保留原日志导出，新增补捕获等待、任务排队、成功／阻塞次数、补回的计时版本数，以及捕获外计时绘制是否遇到 pending。原 preDraw 跳过与补偿跳过分开记录，便于与旧版继续比较。前版日志治理已见效：本次文件约 400 KiB，只含本版记录；继续保留按版本清理、手动“清空并重新记录”和有界独立导出。

构建及 507 项相关 JVM 回归通过，其中 10 项新增测试覆盖补偿合并、资源返回时机、单次在途、无资源不忙重试、布局变化、关闭和 1000 次周转。真实卓易通上的计时流畅度、粒子／HDR 切换仍需复验，尚未执行设备操作。
