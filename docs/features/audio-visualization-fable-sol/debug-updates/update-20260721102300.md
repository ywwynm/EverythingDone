## FableSol：帧率回归修复第一批 + 屏幕内性能仪表

- 修复本轮迁移引入的**行并行屏障开销**：`FableSolRowParallel` 每次派发原本要付一整轮
  `notifyAll` 唤醒三个 worker、再等三个 worker 汇合的挂起/唤醒往返。桌面实测空任务
  一次就要 22.8µs，而一帧要派发五次，光同步就吃掉约 114µs——在手机上因 futex 往返和
  大小核调度还会更差。改为 worker 与调用线程都先自旋一小段（80µs / 60µs）再落到挂起：
  帧内相邻两次派发只隔几十微秒，自旋可整段避开唤醒；跨帧的 8.3ms 间隔仍然挂起，不空转
  烧电。空任务一轮的成本降到 **1.0µs（−96%）**；
- **合并连续水面的派发次数**：`sample()` 内原本分四次派发（方向场累加、层场合成、
  三路 C2 fairing、纵深梯度）。层场合成与 fairing 都只依赖本行，现在并入同一次派发，
  只保留"方向场必须全部算完才能求逐列纵深均值"这一个真正的汇合点，四次降为两次。
  逐行数学与拆开时逐位一致；
- **银泽坡度滤波按行并行**：3 次横向 + 4 次纵深共 7 个 pass，每个 pass 都是"读一份、
  写另一份"的乒乓双缓冲，逐行切分与串行逐位一致。生产中该滤波对 slopeX / slopeZ 各跑
  一遍，合计从约 136µs 降到约 44µs；
- **几何光学顶点色归一化外提**：`c / 255f` 中 255 不是 2 的幂，JIT 无法降级成乘法，
  每个顶点固定要付 6 次浮点除法。轮廓带内每列只有两组颜色却要发 6 个顶点，归一化提到
  列外后除法次数降为原来的 1/6；
- 桌面 JVM 探针实测（相对对照，绝对值不代表手机）：连续水面采样
  **407µs → 258µs（−37%）**，银泽滤波 **68µs → 22µs（−68%）**，每帧屏障总开销
  **约 114µs → 约 5µs**。以上四项**全部逐位等价**，画面不应有任何变化；
- 新增**屏幕内性能仪表**（仅 Debug 构建，叠在水面顶部）：直接显示实际渲染帧率、GL 帧
  间隔 p50/p95，以及 drain / 物理 / 构建 / 绘制 / 交换五段耗时；构建段进一步拆成
  采样、顶点填充、银泽滤波、配色、几何光学五项，另附每帧消费的音频 hop 数、事件数、
  物理子步数、丢帧数与热headroom。同样的分解也写进
  `files/debug_logs/fablesol_frame_perf.log`；
- 新增无设备的 CPU 帧成本探针 `FableSolCpuFrameCostProbe`（默认跳过，需
  `-Dfablesol.perf=1` 显式开启），用于在没有真机时做优化前后的相对对照；
- 新增两条逐位一致性回归测试：银泽滤波在生产规模 97×196（会越过并行阈值）与单列退化
  情形下都必须与参考实现逐位相等。这两条测试在开发中实际拦下了一处求和顺序错误
  （`(b + 2a) + a` 被误合并成 `b + 3a`，浮点加法不结合）；
- 全量 199 项 JVM 测试通过，`assembleDebug` 成功。

**本版仍未处理**：几何光学顶点流构建（`optics.build`，桌面实测约 274µs，是当前最大的
单项 CPU 开销，且完全没有并行化）、19012 顶点的填充与上传、GPU 侧四 pass + 4×MSAA
+ FP16 成本。请用屏幕内仪表反馈这三项在真机上的实际占比，据此决定下一批的取舍。
