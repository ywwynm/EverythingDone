## FableSol 光学实体形状 RGSS 超采样

### 用户反馈与诊断

用户在上一版 4x MSAA（D140）真机上确认波浪界线好多了，但发现 glint 闪点附近仍有锯齿，并担心其它特效
没开抗锯齿导致精细度不足。诊断把 glint 残余分成两类：

1. **程序化形状锯齿（真实缺口，本轮修复）**：glint、streak、surface reflection、halo、transmission 等
   光学实体的形状是在 `optical.frag` 里用 `smoothstep`/`sin` 逐像素程序化算出来的。MSAA 只多采样几何
   覆盖、不重算片元着色，所以完全不抗这类形状边缘的锯齿；细小/远处实体尤其明显。
2. **HDR 超白 clip 到 SDR 的固有残留（非抗锯齿问题）**：准备态（SDR）反射很淡、平滑无锯齿，只有录音态
   （HDR）核心变亮（峰值约 `2.3× reference white`）才出现台阶。薄而亮的 glint 线性梯度陡，SDR 可见边
   本质是亚像素宽，clip 又发生在着色下游的显示/截图映射，任何采样数都无法抗掉。真机 HDR 屏上更柔和，
   只在 SDR 截图里明显。

### 代码改动

- 共享 `optical.frag` 对光学 pass 单独做 **4x 旋转网格超采样（RGSS）**：覆盖计算抽成
  `opticalCoverage(vec2 uv,...)`，单样本最终预乘输出抽成 `shadeOpticalSample(vec2 uv)`，`main()` 用
  `dFdx/dFdy(vLocalUv)` 把四个子样本放在四个不同的 x 与 y 子位置再平均。glint 多为近水平光带，RGSS 的
  纵向分辨率优于轴对齐 2x2。
- 实体较大时导数极小、四点几乎重合，输出与逐像素一次着色一致，不改变既定 glint 尺寸、剖面、峰值与
  观感；D129 界面肩剖面、mode 判定、HDR excess 逐层峰值合同均不变。只用 GLES 3.0 核心的片元导数，
  无需 sample shading 或扩展；光学实体只占少量像素，4x 片元开销可忽略。
- 两端共享同一 shader，一次修复同时覆盖 Android 与 Python。

### 裁决

最亮 glint 核心的 SDR 台阶属 HDR 超白→SDR 固有现象。用户裁决**保持 glint 锐利/亮度，不为 SDR clip
展宽、柔化或压暗最亮核心**，以维持 D103～D118 的最高质量 glint 合同；本轮只做真正的形状抗锯齿。

### 验证

- Python 离屏对照确认光学形状边缘更平滑，且大实体观感不变；隔离测试确认 SDR 反射本就无锯齿、残余来自
  HDR clip。
- 新增/更新 Python 与 Android 的 `optical.frag` 结构测试，守卫 `opticalCoverage`/`shadeOpticalSample`
  重构、`dFdx/dFdy` 与 4 次子样本调用；D129 界面肩剖面断言同步为函数参数 `uv.y`。
- Python 167 项 unittest 通过；Android 全量 `:app:testDebugUnitTest` 与 `:app:assembleDebug` 通过，
  两个仓库 `git diff --check` 通过。未使用 ADB，Android 真机放大观感与帧率由用户验收。
