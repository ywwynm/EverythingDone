# 修复近静音录音被识别为高响度与高活跃度

## 发布说明

用户提供 Android 近静音录音 `20260710215433.wav`：人耳听感接近安静，但旧 FableSol 前端在前 10 秒
持续输出约 0.45~0.60 响度和每秒 7~8 个假 onset。诊断确认录音包含 18.3kHz 强电子干扰、约 100Hz
嗡声及非平稳 AGC/噪声泵动；旧分析器又把 A 加权总能量累计到 Nyquist、从非静音状态启动，并允许
纯相对 flux 归一独立把极低电平变化放大成有效声音。

本次同步修复 Python 蓝本和 Android/Kotlin 分析器：A 加权响度、底噪、质心与平坦度只分析 16kHz
以下；32 个 flux 频带严格按相邻边界求和并止于 12kHz；Analyzer 从静音启动；增加 −66~−54dBFS
smoothstep 绝对可听度安全门，统一缩放响度、频段和 onset；flux 环接收所有帧作为低变化基线，确保
真实稀疏脉冲无需先积满多个有声帧。原有底噪、慢中心和滚动百分位自校准仍保留。

真实 WAV 修复前后：Python 48kHz 路径由 90 个假 onset、平均响度 0.272 降至 3 个 onset、平均响度
约 0.004；Kotlin 原生 44.1kHz 路径降至 4 个 onset、平均响度约 0.008。新增回归测试同时确认明确
可听的 18 个稀疏脉冲仍至少检测到 14 个。完整 `:app:testDebugUnitTest` 和 `:app:assembleDebug` 通过，
未使用 adb。

## 诊断修正

另一会话指出 `np.add.reduceat` 最后一带越过 12kHz，这个代码问题成立，但它不是前 5 秒假 onset
从 37 降到 8 的直接原因：单独修正频带边界后仍为 37 个。真正让 18.3kHz 干扰撑开静音门的是
`p_total` 一直累计到 Nyquist；限制总感知能量到 16kHz 后，前 5 秒才降至约 6 个。5~10 秒仍有
约 40 个假 onset，随后由绝对可听度门解决 AGC/噪声泵动的相对归一误判。

## 代码与测试

- `FableSolRealtimeAnalyzer.kt`：16kHz 分析上限、静音启动、绝对可听度置信与可信 onset。
- `FableSolMath.sumAdjacentSegments()`：严格相邻频带求和，不再让最后一带延伸到 Nyquist。
- `FableSolRealtimeAnalyzerNoiseTest.kt`：覆盖频带上限、超声调制近静音及真实稀疏脉冲。
- Python `features.py` 与 `tests/test_realtime_noise_gate.py` 同步实现和回归。
