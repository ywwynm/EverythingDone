# 修复连续水面翻滚露白并降低渲染开销

## 发布说明

用户真机反馈：Z 轴翻滚时远处水体两侧偶发空白，且连续水面整体明显卡顿。本次为连续
路径增加投影安全采样窗，覆盖最远行透视收缩、Gerstner 轨道位移与网格边缘余量；同时
把 24 次 ribbon Path/Gradient 绘制合并为 8 次分层三角网格，并用相位递推、可分离
高斯消除二维波场的重复 `sin/cos/exp`。确定性覆盖测试、完整单测与 Debug 构建通过；
纯数学采样基准约由 1.56ms/帧降至 0.39ms/帧。未使用 adb，需真机复测两侧覆盖和流畅度。

### 反馈与复现

- 宽度 `276dp`、滚转 `-90°` 时，旧连续路径最远水面保证覆盖只有 `179.99dp`，
  容器半宽需要 `210dp`；新增回归测试可稳定失败，和用户所见“两侧空白”一致。
- 旧渲染每帧构建并提交 24 条 cubic ribbon、408 个颜色停靠点；九层渐变几何在颜色
  采样内重复扫描，约产生 18.36 万次点访问，另有 9 次完整光学链。
- 二维方向波与有限相干波包在每个 Z×X 采样点重复计算三角函数和二维高斯；本地 JVM
  40 帧采样基线为 `62.213ms`，约 `1.555ms/帧`。

### 修复

- `FableSolSimulation.continuousRenderInfo()` 单独计算连续路径采样窗：按最远行最大弱透视
  收缩、`z01≤1.1`、±10dp 轨道位移和 2 列边缘余量反推所需原始跨度，索引向外包含
  边界外第一列。旧九层路径继续使用原 `renderInfo()`。
- `WaveVisualizerFableSol` 将每个相邻九层锚点间的 3 条 ribbon 合并为一次
  `Canvas.drawVertices(TRIANGLES)`；全水面从 24 次 Path/Gradient 降为 8 次网格提交。
  共享边使用相同顶点，逐 ribbon 重复颜色顶点以保留九层清晰色界。
- 九层渐变几何每帧只扫描一次；环境色、颜色停靠点、顶点色、网格坐标和颜色数组复用。
  sRGB/linear RGB 转换改查表，避免逐顶点 `pow`。
- `FableSolContinuousSurface.sample()` 对等距 X 网格使用复数相位递推；波包二维高斯拆成
  X/Z 两个一维包络。波数、相位、振幅、包络和 25 行纵深保持不变。

### 验证

- 新增并先观察失败的全宽度/多滚转角覆盖回归；修复后通过。
- 新增分层网格批量计划约束：`ROWS_PER_LAYER=3`、`RENDER_GROUPS=8`。
- 优化后相同 JVM 40 帧纯数学采样为 `15.692ms`，约 `0.392ms/帧`，约快 4 倍。
- `:app:testDebugUnitTest`：34 项通过，0 失败。
- `:app:assembleDebug`：通过。
- 已清理本轮临时计时探针；未使用 adb、模拟器或物理设备。
