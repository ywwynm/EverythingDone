## FableSol 波浪边缘 4x MSAA 抗锯齿

### 用户反馈与诊断

放大观察波浪时，Android 上九层弯曲界线、水天轮廓和光学闪点边缘仍有明显阶梯锯齿与像素颗粒；上一版
（D139，原生 DPI + 196 列 C1 重建 + 边界 coverage）改动后感觉变化不大。诊断确认根因是整条离屏渲染链
（Android 与 Python 模拟器）都渲染到**单采样** framebuffer，没有任何多重采样；D139 的 `waterEdgeCoverage`
只是一条约 1 像素、方向盲的 depth01 平滑，无法消除近水平弯曲界线上的横向台阶。另外 D139 的原生 DPI 修复
实际只对 Python 生效——Android 的 `uRasterScale` 恒为 1，早就按 surface 实体分辨率渲染，所以那轮对
Android 锯齿基本没有作用。Python 离屏对照证明该锯齿是纯采样不足：2x2 超采样和 4x MSAA 都能直接把台阶
抹平，而单采样加 coverage 不能。

### 代码改动

- Android `FableSolGlRenderer` 与 Python `gl_renderer.py` 的场景离屏改用 **4x MSAA**：几何画进多重采样
  renderbuffer，再 resolve 进单采样 `sceneTexture`，折射与 present 继续采样这张已 resolve 的纹理。
- `pre-water` 折射背景保持单采样（只是平滑环境，且是折射采样源，不需要也不能接 MSAA）。
- 采样数按内部格式查询后取 `min(4, 支持值)`，与场景纹理同格式（SDR RGBA8 / HDR RGBA16F），维持既有 FP16
  精度语义。不支持该格式多采样或建立失败时**原子回退单采样**，仍保留 FP16→RGBA8 目标回退与不改写输出
  颜色空间的契约。
- Android 使用可移植的 `glRenderbufferStorageMultisample` + `glBlitFramebuffer` resolve（GLES3.0 保证），
  未依赖无 Java 绑定的 `GL_EXT_multisampled_render_to_texture`；多采样数据位于 tile 内存，pre-water 仍是两
  目标各画一次环境，不做 Blit。

### 关键结论

- MSAA 只对几何覆盖多采样，主体色、界面、光学、SSS、折射、Beer 与 HDR 的材质/颜色仍逐像素**只计算一次**；
  九层界线是几何边（每组三角带的远边压在其后一组之上），逐像素一次着色的 MSAA 足以修复，无需超采样着色。
- `waterEdgeCoverage`、196 列 C1 重建、glint 数量、逐层 HDR 峰值、主体色阶等既定合同全部保持不变。

### 验证

- Python 离屏：SSAA 与 4x MSAA 对照均消除九层界线台阶，内部深水无颗粒；18 色 FP16 回归的远/近响应比、
  相邻主体色差、超白覆盖与无 MSAA 基线一致；新增 MSE 测试确认 MSAA 比无 AA 明显更接近超采样真值。
- 性能：桌面 GPU 960×1260 FP16 完成时间 `10.94ms → 11.10ms`（约 +1.4%），基本无回退。
- 测试：Python 167 项 unittest 通过；Android 全量 `:app:testDebugUnitTest` 与 `:app:assembleDebug` 通过；
  两个仓库 `git diff --check` 通过。未使用 ADB，Android 真机放大观感与帧率由用户验收。
