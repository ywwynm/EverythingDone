# FableSol 调参更新 2026-07-25

## 银丝改用真实距离定位，"小矩形"的真正成因已消除

- 先纠正上一版的判断：上一版日志里写"既不是粗细在变，也不是波浪翻滚遮挡"，这个结论是错的，你的两个猜测才是对的，而且它们其实是同一个原因的两面。
- 根因在银丝如何算出"自己离水面轮廓多远"。它此前是用"名义深度差 ÷ 深度梯度"换算的，这个换算有两处会坏事。**一是粗细**：水体在纵深方向的轨道滚动会把相邻网格行挤压或拉开，同一帧里"每单位深度对应多少屏幕像素"实测从 24px 变到 200 多 px，换算随之失真，银丝实测宽度在 1.5px 到 9.1px 之间跳。**二是翻滚遮挡**：换算要除一个雅可比行列式，而水层在波形起伏下会互相交叉、层带被压到极薄甚至前后翻转（实测层带屏幕高度到过 −6.1px），此时行列式趋近于零、被钳在 1e-9，梯度爆到约 1e7，算出的距离变成约 0——那一整列的层带高度上银丝全按峰值亮度渲染，画成一个竖直亮块。亮块与正常细线交替出现，就是"一个个小矩形连在一起"。
- 修复把银丝的定位改成 CPU 直接算好的**真实法向像素距离**：只做减法和一次沿轮廓切向的归一化，没有行列式、不做除以小量的除法，层带翻转时距离只是变负而不会爆炸。同时补上原先漏掉的横向位移分量——轨道滚动会让相邻行也横向偏移，只按竖直差折算会算错距离。
- 实测：银丝宽度下限从 1.50px 稳到 2.38px，沿线逐像素粗糙度 0.062→0.047。Python 361 个测试、Android 全部 fablesol 测试通过，其中新增两条断言专门验证法向距离的手算值，以及层带翻转时数值仍然有限。
- 这次**没有**动水位：诊断中发现九层基准高度有 95% 的时刻存在前后反序，会让某些层几乎整条轮廓都被更近的层挡住、只在波峰处露出零星几段。按你的意见没有去动它——远层银丝翻滚到后方时看不见是符合当前设计的，本次只保证"能看见的时候是一条连续的线"。
- 银丝强度、光晕、峰值亮度、滑动等所有滑杆与默认值不变；波背暗带、闪点、星芒与九层水体边界也都未动。
