# 修复 GLES TextureView 充气崩溃并加入红天空 Canvas 回退

## 发布说明

### 用户反馈与根因

首个 Stage 1 版本打开录音 Dialog 时立即闪退。用户提供的崩溃栈显示异常发生在 XML
inflate 阶段，尚未进入 EGL：`TextureView` 不支持 background drawable，而布局给 GL View
设置了 `android:background="@android:color/transparent"`，OPPO Android 16 因此直接抛出
`UnsupportedOperationException`。

进一步检查发现 GL View 在 surface 创建和 fatal 回调中还调用了 `setBackgroundColor()`；
该方法同样会生成 background drawable，因此只删 XML 属性仍会留下第二个同类崩溃点。

### 修复

- XML 改用 `WaveVisualizerFableSolHost` 宿主，不再向 TextureView 设置任何 background。
- GL View 删除全部 `setBackgroundColor/setBackgroundDrawable` 路径，透明合成只使用
  TextureView 的 alpha/EGL alpha surface。
- 宿主同时持有 GL 与旧 Canvas，但正常只运行 GL，避免双份 Simulation 和 CPU 消耗。
- 任意 EGL 初始化、GLSL 编译/链接、绘制或 swap 失败时，宿主自动隐藏 GL、启动 Canvas，
  恢复当前 Thing 背景和最新重力。
- 按用户要求，Canvas 回退天空强制显示为纯红色；正常 GL 路径绝不显示该诊断红色。
- 性能探针随活动后端切换；GL 失败日志继续使用 `[DEBUG-FABLESOL-GL] fatal`。

### 验证

- 静态检查确认录音布局、GL View 和宿主不存在任何 TextureView background 调用。
- 完整 `:app:testDebugUnitTest`：通过。
- `:app:assembleDebug`：通过。
- 当前 JVM 测试环境无法执行真实 framework TextureView inflation；使用用户崩溃栈对应的
  禁用调用链作为回归信号。
- 未使用 adb、模拟器或物理设备。

### 真机判断

- 正常：显示 GL 水面，天空使用普通主题/Thing 染色，日志出现 `glFrame[...]`。
- 失败回退：仍能打开录音 Dialog 并显示 Canvas 水面，但天空为醒目纯红色，日志出现
  `[DEBUG-FABLESOL-GL] fatal ...`。
