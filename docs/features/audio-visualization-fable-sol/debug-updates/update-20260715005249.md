# FableSol 晶莹水体完整材质链升级

## 用户反馈与目标

- 第 0 层水体相对正常，但其它层偏灰、乳白、浑浊和暗淡；饱和度、对比度、阴影洁净度、晶莹感与立体感不足。
- 点击开始录音后才进入 HDR 是既定行为，但此前 HDR 会把第 1、2 层及其它水体大面积提亮成乳白；需要保留局部漂亮光影和超白响应，同时维持九层清晰边界。
- Thing 可以使用任意纯色或渐变；浅色、近白、深色、近黑和互补渐变都不能因提亮、阴影或 SSS 汇聚成灰白/脏黑。
- Android App 与 `E:\projects\audioVisualizerSimulatorFable` Python 版本必须保持同一材质语义。

### 本次更新

- 九层主体改为感知颜色空间中的逐层提亮路径：第 0 层保留 Thing 身份色，第 1～8 层固定 hue、尽量保持绝对 chroma，只在 sRGB 色域无法容纳时受控压缩；不再逐层混向白色，也不再按颜色自动改为向暗。
- 八个相邻边界分别计算实际分离度，最近三层优先。颜色路径无法继续提供足够间距时，使用从当前层当前颜色派生的宽软界面肩补足；界面肩采用真实轮廓几何、`7～14dp` 宽度和零端点半正弦剖面，不形成白边、黑边或细描线。
- 录音仍开启 HDR，但 HDR gain 不参与主体颜色与界面肩。连续银泽移除全域中性白基线，只在太阳方向、Fresnel、坡度/波峰和低频光斑同时成立时响应；表面反射、薄峰透射、连续受光结构和闪点继续使用受限 headroom。
- 阴影从当前层、当前位置的最终主体渐变色派生同色深色，不混黑色或中性灰。波背暗带在反射和透射前合成；宏观遮挡只削弱直射亮瓣，微法线不再负向乘暗整个主体，避免阴影把水体弄脏。
- 表面反射带先采样当前位置四停靠点渐变，再沿固定 hue 提亮；SSS 从每层最终四个停靠点分别派生。纯白保持纯白，浅粉、浅黄、浅青不会退成同一个中性白，远层也不会回用首层颜色。
- Android GLES/Canvas 与 Python ModernGL/QPainter 的同层顺序统一为 `interface → backShade → body/thin → veil → surface/streak → glint`。HDR 环境、水体和光学实体在 scene-linear FP16 中合成，SDR 基线按 RGB 比例共同限制到 reference white；取消低 alpha 的 inverse-alpha 超白预补偿。
- 保留已有九层材质存在度、闪点最高质量几何、太阳碎光路径和录音 HDR 状态机；真实折射及 Beer–Lambert 体积吸收因尚无独立背景采样和可定义光程，本次没有用压暗主体的方式伪造。

### 验证

- Android FableSol `137` 项单元测试全部通过，`:app:assembleDebug` 构建成功。
- Python 全量 `142` 项 unittest 通过，共享 GLSL 已由 ModernGL 实际编译。
- 两个仓库 `git diff --check` 无错误；未使用 ADB，也未改动用户录音和视频文件。
- 真机重点检查：开始录音前后第 1、2 层腹部基线是否稳定；近三层是否始终分明；浅色阴影是否干净；深蓝/近黑是否仍有形体；HDR 超白是否只出现在局部反射、透射和闪点区域。
