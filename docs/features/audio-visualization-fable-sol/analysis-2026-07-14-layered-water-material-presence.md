# 九层水体材质存在度审计与调研（2026-07-14）

## 状态与范围

- 本文前半记录 Android 修改前的实现审计，末尾“已确认裁决”记录本轮最终目标参数；审计表中的
  “当前值”不能误读成实施后的目标值。
- 本轮不修改渲染代码，也不改变 Python 模拟器的 `320dp×420dp` 宽度约束。
- 水层索引按 Android 当前实现定义：第 0 层最近，第 8 层最远，`depth01 = layer / 8`。
- 本文把“配置了非零参数”和“正常观看时能够形成稳定、可感知的结果”分开。容量、峰值或
  uniform 非零，并不等于该层真的会出现相应效果。

## 结论摘要

当前“近三层明显、其余层突然变平”不是单个参数造成的，而是多组独立截止叠加的结果：

1. 顺流银线和波峰薄雾在第 2 层后硬截止；
2. 离散闪点虽然给第 3～5 层配置了容量，但其候选场在第 3 层已经低于出生门槛，第 4～5 层的
   主镜面项严格为零；
3. 薄峰透射在第 4 层后截止，背坡窄阴影在第 5 层后截止，表面反射带在第 6 层后截止；
4. 连续 HDR 银泽和 HDR 透射在第 4 层附近已经退回 reference white，第 5 层之后没有超白差量；
5. 闪点还要进入一份全局出生池，与近层更强的候选竞争，进一步降低中层实际占用率；
6. 远到近的遮挡顺序会让较远层已经较弱的局部效果继续被近层几何遮住。

因此，单独增加 `glintCapacity()` 或统一提高远层 alpha 都不能解决问题。需要把散落的硬截止改为
一组共享层级锚点下的“分效果族连续衰减”，并同时处理候选形成、全局分配和 HDR 能量边界。

### 闪点为何“配置到第 5 层，却只看得到第 0～2 层”

`glintCapacity(layer)` 只是每层同时存活数量的上限，不是最低数量，也不保证该层能产生候选。
主镜面候选还乘以：

```text
depthGain = max(0, 1 - depth01 / 0.42)
```

对应第 0～8 层约为：

```text
[1.000, .702, .405, .107, 0, 0, 0, 0, 0]
```

第 3 层 `depth01=.375`。即使其它局部项取接近上限，主反射项也只有约
`0.9 × .107 = .096`；随后还要减去场阈值 `.08`、做归一化、乘 1.5 和空气衰减，结果约
`.022`，明显低于锚点门槛 `.085`。所以第 3 层不能仅靠主镜面项生成闪点，只能偶尔依赖较强的
Fresnel 细节。第 4～5 层的 `depthGain` 已经严格为零，配置的容量通常没有机会被使用。

即便中层偶尔形成候选，所有层还共用一份太阳碎光出生池。当前得分主要是
`anchorIntensity × sunPathWeight`，已有占用只通过 `1/(1+.28×occupancy)` 轻微降权。近层候选
更强，会继续优先占用出生额度。这解释了参数表面上“第 2～5 层都是 3 个”，画面里却长期只有
第 0～2 层可见。

## 外部调研及其对本项目的约束

### 1. 远近层不应只是开/关，而应在几何、法线与 BRDF 之间转移细节

Bruneton、Neyret、Holzschuch 的实时海洋光照研究指出，海面同时包含从大尺度到毫米尺度的
波列，跨观看距离直接渲染会产生 aliasing；其方案按距离简化几何，并把缺失细节编码进法线和
BRDF，以获得连续的远近过渡。来源：
[Computer Graphics Forum 论文页面](https://onlinelibrary.wiley.com/doi/abs/10.1111/j.1467-8659.2009.01618.x)、
[Eurographics 记录](https://diglib.eg.org/items/fb727c69-2be2-4edd-833e-f7a9baea9b63)。

对 FableSol 的直接含义是：远层不应简单复制近层的细碎实体，也不应把整类材质突然关掉。
高频细节应逐步转为更宽、更稳定、峰值更低的统计光泽；低频几何和宏观明暗可以保留得更远。

### 2. 高频波形要按采样足迹带限，但过滤不能等同于丢失全部光学能量

NVIDIA 的水面模拟章节按网格边长过滤无法解析的短波：波长为边长 4 倍时保留，降到 2 倍时
衰减为零；法线贴图在远处逐步收敛到几何法线，以避免 aliasing。来源：
[GPU Gems：Effective Water Simulation from Physical Models](https://developer.nvidia.com/gpugems/gpugems/part-i-natural-effects/chapter-1-effective-water-simulation-physical-models)。

LEAN Mapping 用法线分布矩保存未解析细节，使微小凹凸在远处变成展宽的高光而非突然消失；
Filament 的 specular anti-aliasing 同样以屏幕空间方差调整粗糙度，目标是降低闪烁并保持远处
高光形状。来源：
[LEAN Mapping](https://mdsoar.org/items/7babd5a3-62b6-4195-9fe3-af97c308bb0a)、
[Filament Materials Guide](https://google.github.io/filament/Materials.md.html#anti-aliasing-specularantialiasing)。

当前项目已经有采样足迹带限和未解析坡度方差，但中远层的离散候选在进入这套能量守恒逻辑前
就被 `depth/0.42` 清零；这一顺序需要调整。

### 3. 闪点必须由局部坡度和观察几何产生，但远处可表现为统计银泽

Cox 与 Munk 对海面太阳闪光的经典测量把亮度联系到“具有所需坡度的微表面出现概率”；离镜面
方向越远，需要的坡度越极端、概率越低，弱闪光还会被天空光和次表面背景掩盖。来源：
[Cox & Munk 1954 原论文](https://userpages.umbc.edu/~martins/phys650/Cox%20and%20Munk%20Glint%20paper.pdf)。

NASA 对 sunglint 的观测说明：水面粗糙度会把镜面反射分散到更宽的银色区域；大量细小波面
共同形成 glitter path，而不是每个距离都保持相同数量、相同尺寸的亮点。来源：
[The Subtleties of Sunglint](https://science.nasa.gov/earth/earth-observatory/the-subtleties-of-sunglint-151456/)、
[Ground to Space: A Glittering Path](https://science.nasa.gov/blogs/earth-matters/2016/11/09/ground-to-space-a-glittering-path-of-san-francisco-sunglint/)。

因此不能用与几何无关的保底随机闪点；更合适的是保留局部坡度门控，同时让第 3～6 层获得
公平的有效候选机会，并把未解析的离散能量逐渐并入连续银泽。

### 4. HDR 应保留给局部镜面/透射，不应把中远层水体基色整体推到超白

ITU-R BT.2408-9 把 HDR Reference White / diffuse white 定义为 203 cd/m²，并明确要求为
specular highlights 预留 headroom。来源：
[ITU-R BT.2408-9（2026）](https://www.itu.int/dms_pub/itu-r/opb/rep/R-REP-BT.2408-9-2026-PDF-E.pdf)。

这与项目既有约束一致：扩展中远层 HDR 时，应增加“局部存在率”，而不是提高整层基色或 APL；
第 0～2 层仍拥有最高峰值，第 3～6 层保留逐层减弱的小面积超白；第 7 层后来确定只保留极弱、
极低覆盖的闪点与局部反射 HDR 尾部，第 8 层完全回到 SDR。

## 方案比较

### 方案 A：只放宽现有层号判断和远层强度

- 优点：改动小，能快速让更多层生成顶点。
- 缺点：不能解决闪点候选低于门槛和全局竞争；各效果仍各自维护截止点，之后容易再次形成断崖；
  远层高频效果还可能 aliasing。
- 结论：不建议作为最终结构。

### 方案 B：所有效果共用一条逐层乘数

- 优点：层级关系容易理解和调参。
- 缺点：微法线、宏观阴影、SSS、闪点、轮廓光与远景羽化承担的物理/视觉职责不同。统一乘数会
  同时削弱不该同步衰减的频段，也不能把离散闪点自然转成统计银泽。
- 结论：可用于定义共同层级锚点，但不应直接作为所有效果的唯一曲线。

### 方案 C：共同层级锚点 + 分效果族衰减（已确认）

2026-07-14 用户已确认采用本方案；公共锚点、各效果族的退出边界、逐层参数及闪点质量规则均已在
本文末尾逐项裁决完成。

先定义一条只表达“第 0～8 层主次关系”的公共锚点，再由各效果族解释该锚点：

1. **连续表面族**：宏观坡面光/阴影、微法线、SDR SSS、连续 HDR 银泽/透射。低频形体保留
   更远；高频微法线逐步并入粗糙度/统计光泽；第 7～8 层接近零。
2. **局部轮廓族**：表面反射带、薄峰透射、背坡窄阴影、波峰薄雾。第 3～6 层保留更窄、更淡、
   更低频的版本，按几何门控，不允许整层连续白边。
3. **离散实体族**：闪点、解析光晕、顺流银线。数量上限、候选强度、尺寸、alpha、HDR 峰值和
   出生公平性分别衰减；未解析能量转移到连续银泽，而不是简单丢失。
4. **远景景深族**：第 7～8 层边缘羽化保持远景专属，不因“全层覆盖”而扩展到近层。

这套结构允许第 0～2 层基本不变，第 3～6 层形成逐级弱化的材质存在感，最后两层接近不可见，
同时避免把所有效果机械复制到远景。

## 最终实施方向

1. 用集中式层级策略取代散落的 `layer <= N`；公共锚点已经确定为
   `[1.0, 0.927, 0.81, 0.64, 0.48, 0.30, 0.16, 0.06, 0]`。各族只把它作为共同深度坐标，
   不得作为统一强度乘数。
2. 水体基色、近层效果上限和既有时间语义保持职责不变；按已确认数组调整逐层权重与 HDR 峰值，
   不夹带与九层材质连续性无关的前景重设计。
3. 闪点先修候选形成，再谈容量：取消 `depth/0.42` 对第 4～5 层主镜面项的严格清零，使第 3～6
   层在确有合适局部坡度时能够越过与其层级相匹配的门槛。
4. 全局太阳碎光池保留，并按已确认的 `4/4/3/3/2/2/1/1/0` 设置分层容量上限。公平性应保证
   “有效候选有机会”，不能保证无几何依据的固定闪点数；验证必须记录实际活跃数量而非只断言容量。
5. 第 3～7 层的离散闪点按 D103/D107/D113～D116 分别衰减出生机会、几何、alpha 与 HDR；被过滤
   的未解析微表面能量进入连续银泽，防止远层既无闪点又无材质。
6. 表面反射、薄峰透射、背坡窄阴影和波峰薄雾使用各自的平滑覆盖曲线；顺流银线按 D98 只弱化
   延伸到第 4 层并保持 SDR，第 5～8 层不生成。
7. 第 6 层基色保持 SDR；连续银泽允许 `1.08×` 的极弱尾部，镜面闪点核心允许 `1.29×`。
   第 7 层只保留 `1.16×` 闪点与 `1.08×` 局部反射带，第 8 层不使用 HDR。

## 验证要求

实现阶段不能只凭常量表判断成功，需要增加或复用以下逐层观测：

- 每层有效候选数、出生数、活跃闪点数及生命周期占用率；
- 每层连续银泽、透射与离散实体覆盖的像素比例；
- HDR 设备上每层高于 reference white 的像素比例与峰值，确认中层增加存在率但不抬高 APL；
- 固定音频、固定随机种子、固定时间点的逐层截图和 x 方向亮度取样；
- 动态序列中的高光闪烁、突然消失和远层 aliasing；
- 第 0～2 层相对当前基线不得出现明显回归，第 7～8 层仍须保持安静、轻和远。

## 已确认裁决

1. 采用“共同层级锚点 + 四个效果族”的结构；公共锚点表达单调主次，各效果族保留独立的物理与
   感知衰减方式。
2. 第 6 层基色保持 SDR，连续银泽允许 `1.08×` 的弱尾部；镜面闪点核心允许达到 `1.29×`。
   第 7 层只保留极低覆盖的 `1.16×` 闪点和 `1.08×` 局部反射带，第 8 层严格回到 SDR。
3. 波峰薄雾只延伸到第 4 层：第 0～2 层保持现状，第 3/4 层约为第 2 层的 `45%/18%`，第 5～8
   层不再使用独立薄雾，其微弱能量归入 SDR SSS 与连续银泽。
4. 顺流银线只延伸到第 4 层并继续保持 SDR：第 0～2 层保持现状，第 3/4 层各最多 1 条，初始
   强度约为第 2 层的 `45%/20%`，且出生频率逐层降低；第 5～8 层不生成。
5. 闪点跨层分配采用软配额并回流未使用额度：只有存在合格真实坡面候选的层才能消费配额；
   候选不足或容量已满时立即回流全局池，不生成固定保底闪点，不使用机械轮转。
6. 闪点先按镜面方向、坡度、曲率和 specular AA 判定真实候选，再做层级显著度衰减；闪点是
   水体流动感的主要载体之一，几何、时间连续性、抗锯齿和 HDR/SDR 质感均按最高优先级验收。
7. 公共层级锚点采用用户指定的
   `[1.0, 0.927, 0.81, 0.64, 0.48, 0.30, 0.16, 0.06, 0]`，只表达目标存在感和单调层序。
8. 闪点容量上限最终采用 `[4, 4, 3, 3, 2, 2, 1, 1, 0]`，软配额出生权重采用
   `[4.2, 3.6, 2.4, 1.92, 0.96, 0.6, 0.36, 0.16, 0]`。容量不等于固定数量，权重只控制出生
   机会积累速度；第 7 层极少出现，第 8 层退出。
9. 水体作为录音 dialog 主视觉，HDR 内容与 SurfaceView 期望 headroom 上限提高到
   `3.6× reference white`；实际值仍由设备动态裁减。最高峰优先给第 0 层闪点，连续银泽只作
   较低幅度增强，其它 HDR 通道不随全局上限等比放大。
10. 闪点 HDR 核心峰值最终采用 `[3.60, 2.80, 2.40, 2.00, 1.60, 1.36, 1.29, 1.16, 1.00]`；
    第 6 层通过低容量和低出生权重保持稀有，而不是把单点亮度压到不可感知。
11. 连续 HDR 银泽峰值采用 `[2.70, 2.40, 2.10, 1.80, 1.50, 1.29, 1.08, 1.00, 1.00]`；
    不扩大现有低通法线/Fresnel/太阳方向覆盖，第 7～8 层回到 SDR。

    几何弱化延伸到第 7 层，并以 `0.06` 公共存在度和局部门控保持极低覆盖。
13. 连续 HDR SSS 透射峰值采用 `[1.60, 1.50, 1.36, 1.29, 1.21, 1.14, 1.08, 1.00, 1.00]`；
    继续受波峰、背光、`1-Fresnel` 和统一 HDR gain 约束，不能解释为整层亮度。
14. 独立 `mode 8` 薄峰透射保持
    `[1.08, 1.06, 1.04, 1.02, 1.00, 1.00, 1.00, 1.00, 1.00]`，几何只覆盖第 0～4 层；
    第 5～6 层由连续 SSS 承担，不重复叠加亮边。
15. 连续表面族使用明确且易调节的逐层权重：宏观坡面提亮采用

    微法线距离带限和水体基色保持不变。

    保证远层抗锯齿，显著度主要由快速下降的 alpha、原有 facing/crest 门控与空气透视控制；
    D107 的 HDR 峰值表保持独立。
17. 波背局部阴影宽度采用 `[1, 1, 1, .84, .72, .60, .42, 0, 0]`，alpha 采用

    远近；局部坡面/波峰门控不变，第 7～8 层不生成独立暗带。
18. 闪点沿水面长轴采用 `[1, .96, .84, .75, .64, .56, .49, .42, 0]`，向水体内部的最大展开
    采用 `[2.56, 2.40, 2.24, 1.96, 1.60, 1.50, 1.36, 1.29, 0]dp`，半长最低 `2.4dp`；

    曲率的自适应细分；核心与光晕共享曲面采样边界，并禁止顶点容量不足导致静默截断。
19. 闪点核心最大 alpha 由 `0.92` 改为精确的 `0.9129`，逐层相对系数采用
    `[1, .96, .84, .75, .64, .60, .56, .49, 0]`。候选判定先移除现有 `depthGain` 与前置空气

21. 保留 D70/D92 已验收的闪点时间常数、软门、退休、出生初值和当前匹配行为；只让 mode 3 的

## 裁决状态

本轮视觉与行为参数已经逐项裁决完成，没有仍需用户选择的效果族参数。剩余工作是按上述决策实现
Android 与 Python 同构路径、补齐数值/动态/顶点预算回归并进行固定帧及 HDR 真机验证；测量发现
新证据时再以单变量方式修订，不在实现阶段静默改写本表。

## 实施与桌面验证结果（2026-07-14）

Android GLES、Android Canvas 兼容路径、Python ModernGL 与 Python QPainter 已接入同一组逐层
策略；共享 GLSL 负责两端主渲染链。实现包括候选形成、跨层软配额与额度回流、逐层容量/尺寸/
alpha/HDR、解析光晕、表面反射、波背阴影、薄峰透射、波峰薄雾、顺流银线以及连续银泽/SSS。
Python 仍严格保持 `320dp×420dp`（`640×840px`）。

最终遗漏审计还移除了 Android Canvas 兼容路径原有的“各层独立出生”分支：它现在与 Android
GLES、Python ModernGL/QPainter 一样，先更新持久实体，再把所有层未匹配的真实坡面峰汇入同一候选
池，按太阳反射路径、层级软配额和当前占用统一选择；连续水面闪点也使用相邻深度行决定向水体内部
的展开。候选池和匹配标记均为预分配数组，兼容回退不因此新增逐帧调度分配。

为减少移动 GPU 开销，宏观明暗在 vertex shader 计算；微法线、SDR SSS、连续银泽和连续透射的
四条逐层曲线也由逐片元动态数组采样迁移到顶点采样后插值。网格行与九层曲线节点对齐，因此该
调整不改变曲线结果，同时远层权重为零时可提前跳过微法线噪声，最远两层也跳过无 HDR 预算的
连续反射/透射计算。六组静态逐层 uniform 在 Android 程序初始化、Python shader 编译后各上传
一次，不再逐帧进入 JNI/driver；deep/subsurface 身份色按 RGB 缓存，并在一帧内只为四个身份色
各推导一次。

Python 还把自适应曲面边界评分、曲面四边形装配和表面反射带宽度改为批量 NumPy 运算；公式、
细分阈值、核心/光晕共享边界和输出顶点布局均不变。相同 180 帧高活动基准中，CPU 水面+光学网格
中位耗时由 `26.114ms` 降至 `11.484ms`，ModernGL 含同步读回的完整帧中位耗时由 `26.862ms`
降至 `12.114ms`，QPainter 由 `17.114ms` 降至 `15.760ms`；优化前后最大光学顶点数均为
`9,972`。该数据来自 `640×840px`、NVIDIA RTX 5090 桌面离屏环境，只用于同机前后对照，不代替
Android 真机帧时间。

固定高活动桌面场景运行 180 帧后，实际闪点出生数为
`[6, 3, 4, 8, 2, 2, 1, 1, 0]`，最终活跃数为
`[3, 2, 2, 3, 2, 2, 1, 1, 0]`；第 3～7 层均形成真实候选和弱化实体，第 8 层严格退出。该场景
最大光学顶点数 `11,196`，显著低于 `64,000` 的显式预算；核心与光晕的 `12～32` 段自适应边界
已经由回归测试逐段比对。桌面 FP16 场景峰值为 `2.0371× reference white`，高于 reference white
的像素为 `44,197`；这是固定场景的实际响应而非配置峰值上限，Android HDR 设备最终观感仍需本轮
发布后目测。

自动化回归新增 Android/Python 源码数组逐项一致性、所有效果族曲线、全局闪点池覆盖、自然退场、
HDR eligibility、共享曲面细分、shader 实编译和顶点预算检查。后续如真机发现单一问题，按本文
既定约束做单变量修订。
