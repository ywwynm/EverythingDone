## 已确认的问题

以下结论来自资源文件和当前调用链；文本样例通过读取实际 XML 并复现字符串组合得到，不冒充设备截图或运行时验收。

|---|---|---|
| 所有非中文的附件数量统一追加 `s` | `AttachmentHelper.kt:157`、`:198` | 日语两张图片会组成 `2 画像s`，俄语组成 `2 изображениеs`。首页卡片、桌面小部件、通知均有调用。需要数量资源与对应代码调用，不能只改名词。 |
| 时间单位统一追加 `s` | `DateTimeUtil.kt:76`、`:770` | 日语两天会组成 `2 日s`，影响延后提醒、计时设置和时长说明。应让数量规则决定整个数量短语。 |

| 统计页已有资源仍会混入英文 | `StatisticActivity.kt:166` | 使用天数说明中的 `this day`、`these … days` 在代码内。需要整句数量资源，而不只是翻译三个句子片段。 |

## 能在 XML 中解决的部分

- 固定文案补译，以及已有英文占位文案的翻译。
- 同一个完整句子里调整 `%1$s`、`%2$d` 等参数位置；有位置编号的参数不要求各语言保持中文语序。
- 对一个数量定义合适的 `plurals` 分支；但代码必须调用 `getQuantityString`，普通 `getString` 不会自动应用它。
- 标点、引用格式、空格及局部措辞。法语和意大利语撇号、XML 特殊字符、百分号与格式参数须分别处理。

## 必须由代码配合的部分

- 把固定的“动词＋对象”“日期前缀＋日期”等片段拼接改为完整语境模板。
- 删除业务展示路径中无条件追加英文 `s`、英文介词和英文序数的逻辑。
- 将数量、复合计数和日期时间的格式化集中到可复用入口，覆盖页面、桌面小部件、通知、分享和导出。
- 不把不同语言的词形简单归结为 `count > 1`；不通过强行首字母大小写修补句法。
- 复合计数可使用分别形成的数量短语与完整组合模板；若上下文需要同时处理多个数量的语法变化，再考虑 ICU MessageFormat。项目最低 API 为 26，可用平台 API，无需先引入额外翻译服务。

## 已排除的误判与边界

- `HomeActionWordingHelper` 当前主要通过整句资源与编号参数生成确认内容，不是全部硬编码；需要检查其中嵌入的动作标题、范围名和计数是否符合每种语言的语法，不能直接整体重写。
- 2026-10-10 报告中的 58 个“未见直接引用”键仍需核查动态查找后再决定去留，不因统计缺项就机械补译或删除。
- 文件夹操作的状态范围、子树影响、数量口径、可恢复性说明必须保持领域定义；翻译和格式化调整不改变操作实际影响的内容。
- 日期展示与时间计算分离。习惯规则中每月、每年的月末哨兵值和数字编码属于持久化协议，不可随着显示格式一起改动。
- 用户自填的标题、附件名称、设备名称及错误详情作为数据传入完整模板；不翻译这些数据，也不把它们重新当作格式模板执行。
- 品牌、模型名、技术标识与颜色数据集的既定例外继续遵守 `preferences.md`。

## 平台依据

- [Android 字符串与复数资源](https://developer.android.com/guide/topics/resources/string-resource#Plurals)：数量类别依语言语法决定；不带数字的单个/多个标签可能不适合用 `plurals`；编号参数可在不同语言中调整顺序。
- [Android DateFormat](https://developer.android.com/reference/android/text/format/DateFormat)：语言对应的日期顺序与系统时间制式是不同的输入，适合分别处理。
