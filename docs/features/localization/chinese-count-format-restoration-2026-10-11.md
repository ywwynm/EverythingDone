# 恢复中文数量摘要原有格式（2026-10-11）

用户指出首页 `ActivityHeader` 的“X个文件夹，Y件记事”变成了“X个文件夹和Y件记事”，明确要求保留中文原有内容。

已恢复并发布 debug `202610110612`，原 OPPO、三星、魅族三台设备各 5,101 项检查通过，数据库逐表摘要和语言设置一致。

原因是上一轮把文件夹数量和附件数量都交给 ICU `ListFormatter`，其中文规则插入了“和／及”；新增附件复数资源还改了原有空格和视频量词。外语复数修复不需要这些中文变化，属于修改范围判断错误。此前测试只验证格式化及部分新写的预期，没有将既有中文显示作为回归基准，因此没拦住该问题。

## 恢复范围

- 首页、文件夹卡片和小组件的共用数量入口，在中文下使用原有 `thing_folder_count*` 资源，例如“2个文件夹，5件记事”；单一类别和空内容的原有分支保持。
- 图片、视频、音频恢复数字后的空格；视频量词恢复“个／個”。混合附件恢复“2 张图片, 1 个视频”；台湾、香港繁体对应“2 張圖片, 1 個影片”。
- 文件夹操作影响范围恢复原有 `folder_impact_separator` 的“、”，例如“2个子文件夹、5件记事”。
- 未全局修改列表连接器，外语复数和语法修复继续使用本地化规则。24 小时制和日期顺序策略不变。
- 将“修复外语时保留既有中文格式，不任意润色中文”写入本功能偏好。

## 验证

设备探针增加简体、台湾及香港繁体的原样回归断言，覆盖图片与音频的 1 / 2 / 5 / 11 / 21、视频单项、混合附件，以及文件夹数量的零值、单一类别和双类别。静态核对以修改前的资源与拼接代码为依据，逐字比较分隔符、量词和空格。

附件原文对照 Git `HEAD`；简体文件夹资源同样对照 `HEAD`。繁体原先缺少文件夹计数键，使用此前补齐后的留存资源作为基准，保留其中文标点，未恢复为缺键时的英文回退。见 [基准核对](validation/2026-10-11-chinese-counts/baseline.json)。

首版 debug `202610110610` 构建与静态检查通过；三星、魅族各 5,101 项通过。OPPO 首次在探针启动时崩溃，堆栈位于 `LocalizationProbe.onStart` 读取 `App.getApp()`：测试线程先于应用初始化完成，尚未开始数量检查。探针增加主线程空闲等待，确保应用初始化结束后再读取上下文；生产修复未因此改动。[原始崩溃日志](validation/2026-10-11-chinese-counts/oppo-probe-init.txt) 和首轮已通过的结果均保留。

最终包三机各 5,101 项通过，每台均覆盖全部 13 套语言格式化及新增中文原样断言，另分别打开简体、台湾繁体、香港繁体界面。验证的是实际数量格式化入口，并非在首页新建文件夹或附件样例。没有保存测试记事，数据库逐表摘要及语言设置一致。三机结果：[OPPO](validation/2026-10-11-chinese-counts/9018f404.json)、[三星](validation/2026-10-11-chinese-counts/R5CW20BLNKL.json)、[魅族](validation/2026-10-11-chinese-counts/192.168.100.67_42641.json)。
