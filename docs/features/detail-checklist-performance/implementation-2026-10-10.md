## 实施结构

- 根布局保留固定工具栏、系统栏、底部栏和浮层；原纵向滚动内容交给一个有界 RecyclerView。
- ConcatAdapter 按原顺序连接媒体、标题、正文、清单、排序入口、音频及信息区。清单、媒体、音频使用各自 Adapter；标题正文等固定模块保留独立 View 及其编辑状态。
- 统一网格布局支持各附件区自己的列数，清单和普通区域占满宽度；不保留全高纵向嵌套 RecyclerView。
- 所有业务事件使用所属 Adapter 内位置，查询和定位通过统一位置映射；附件拖拽不跨分区，清单仍遵循同级同父与完成区边界。
- 编辑行绑定不生成撤销快照、不无条件重置文本；插入/删除后的焦点允许等待目标行布局，离屏状态与模型保持一致。
- 工具栏、键盘、播放可见性和自动滚动改用统一滚动来源；长截图须完整导出并恢复界面与编辑状态。

## 验证方式

1. 静态核对所有旧容器、全局/局部位置及 ViewHolder 常驻假设，针对状态与位置映射编写有实际行为断言的测试。
2. 合并构建后先在一台机定位实现错误，修复后在三台机运行同一套真实 Activity 测试与 UI 操作；平台差异单独记录。
3. 编辑、删除、媒体操作只针对专用测试数据；用户指定真实长清单用于非破坏性打开、折叠和性能比较。
4. 结果保存至本目录，原始截图、层级、帧数据和日志放忽略的临时目录。编译成功不等于验收完成。
5. 应用改造前保存三机基线：相同测试记事、媒体、外观参数、主题、方向及滚动位置；改造后对比像素和控件几何，动态媒体、光标、系统时间等变化单独解释，不直接掩盖无法解释的差异。
6. 外观验证同时包含静态结果和变更过程：设置应用、滚动离屏再返回、主题/方向变化、撤销重做与保存重开。新实现单独截图不能证明与旧行为一致。
