# 编辑行减负与附件弹窗分阶段展示

已随阿里云 debug `202610100704` 发布，线上元数据、说明及 APK 完整校验通过；详见[发布日志](debug-updates/update-20261010150416.md)。

## 需求与范围

用户批准编辑行 ripple 复用、减少重复样式设置，并反馈上一版触摸反馈已正常但弹窗出现仍晚。新增要求：先读取图像/视频尺寸等信息，按正确大小展示弹窗并开始现有粒子动画，同时异步加载媒体。

沿用三台授权设备和专用测试记事；指定真实记事只做打开、滚动、取消与性能测量。本轮开始重新备份数据库及偏好，只保存在本地忽略目录 `tmp/detail-checklist-diagnosis/staged-preview-2026-10-10/`。

## 实现

- 清单每按钮持有独立 ripple，在颜色变化时更新，绑定不再新建四份 ripple/轮廓对象。XML 中原本会被首次绑定移除的四份背景也不再创建。
- 绑定直接应用最终完成态、字号、缩进与颜色；布局参数和图标 tint 未变化时不重复提交。保留全部 EditText、行身份、组合输入、选区、层级、拖拽和主题逻辑；未改变回收数量和手写配置。
- `DetailCropPreviewLoader` 增加独立的轻量元数据队列；图片读取文件头和 EXIF 旋转，视频读取尺寸、旋转及时长。旧请求的原生解码尚未结束时，也不阻塞新窗口的尺寸读取。
- 元数据写入 DialogFragment 参数，按原尺寸计算构建完整控件；真实媒体后台准备。加载期间显示进度、禁用编辑/确认但保留取消；完成后只填入媒体并恢复控件，不改变窗口大小或重播出现动画。
- 缓存仍受文件状态、选帧和内存上限约束。刚完成元数据校验且已有有效位图时直接使用缓存，避免再次打开短暂显示占位。
- 关闭内容按请求身份取消，不干扰后续请求；正常 Activity 暂停不会无条件取消仍可恢复的窗口预览。尺寸无法单独读取时继续在后台用原解码器兜底，失败提示并退出。
- 新创建窗口在配置/进程恢复时有尺寸参数，不同步解码。仅为升级前保存的、缺少尺寸参数的旧 Fragment 状态保留兼容恢复路径；其它功能共用裁剪 View 的同步初始化行为不变。
- 用户追加要求图片加载进度与首页一致并支持记事渐变色。改为直接复用首页的 `BackgroundUtil.applyProgressBarGradient` 和 28 dp 尺寸，在创建时使用完整记事背景；视频原有加载指示也支持记事渐变，不重复叠加图片进度条。
