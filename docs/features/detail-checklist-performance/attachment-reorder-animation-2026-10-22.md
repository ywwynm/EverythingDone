# 详情附件换位动画诊断

## 现象与复现

用户反馈详情内移动图片／视频附件时直接跳到新位置，没有换位动画。本轮用实际 `DetailContentLayout`、`ConcatAdapter`、`GridLayoutManager` 和图片附件 Adapter 运行本地回归，只替换媒体解码、资源布局和着色；移动通知与视图布局仍走真实组件。

初次有效复现：图片由第 0 项移到第 1 项后，第一次布局的横坐标直接从 0 变为 200 px，原图片和让位视频的 View 实例保持，连续位置断言失败。输出为 `tmp/detail-attachment-reorder-red.txt`。这条回归检查可见位置和中间帧，不仅检查最终顺序。

## 待验证假设

1. 统一列表默认关闭动画器。只恢复 `DefaultItemAnimator`，保持移动通知和预测布局不变，应该出现连续位移。
2. 刷新过程重建媒体 View 或全量通知。若成立，换位后实例应改变；当前最小复现已保留两端实例，不支持该解释。
3. 关闭预测布局抑制换位动画。若仍关闭预测布局时对照可以连续移动，就能排除此项，不恢复曾导致清单拖拽中断的预测布局。

## 归因与修复范围

单变量对照已完成：原配置仍在首帧从 0 跳到 200 px；只设置 `DefaultItemAnimator` 后，两端首帧保留原位置，并采到连续中间位置，最终落位正确。预测布局始终关闭，两个媒体 View 始终复用。对照输出为 `tmp/detail-attachment-reorder-ab.txt`，2 项中只有原配置失败。

`git blame` 确认默认关闭动画来自 2026-10-10 的统一列表提交 `d60ef2730`。原本只需要禁止清单编辑动画，迁移后却通过整个列表的 `itemAnimator = null` 实施，连图片／视频与音频的 `notifyItemMoved` 动画也一起关闭。进入清单移动模式时，专用动画器又默认直接结束全部换位；退出模式后再次置空。这不是本次媒体预览滑动返回或弹簧轨迹引起的回归。

修复采用按区域过滤的动画器：附件保留标准位移动画，其它区域保持即时布局，不增加编辑时的新增／删除／变化淡入淡出；清单移动模式保留既有收束、展开和代理控制，只将非清单附件交回附件规则。退出模式后恢复附件动画器，继续关闭预测布局。

本地测试通过更新监听采集动画中的位置；测试时钟不用于推导真机动画耗时。

## 验证

新增 `DetailAttachmentReorderAnimationTest` 的 7 项回归均通过：正常图片／视频换位、标准动画器单变量对照、清单模式内部动画器、退出后的恢复、连续反向换位、动画中断，以及普通编辑区域重排／增删／刷新不产生动画。换位检查同时覆盖原视图复用、首帧原位置、中间位置、终点及透明度。

最终全套本地测试 1775 项，无失败或错误，3 项既有跳过；包含清单编辑、GIF 生命周期及媒体预览转场既有回归。结果及源码散列见[检查摘要](checks/attachment-reorder-animation-2026-10-22.json)。

首次修复阶段未操作 ADB，当时未重新进行三机真实触摸、通栏尺寸变化或录屏验收。本地回归能够确认动画器配置及位移生命周期，不替代这些实机检查；随后经用户明确授权补齐的实测见下文。

### 测试过程中的修正及证据边界

- 一加初次长按点位为 `y=304`，落入顶部工具栏 `y=135–331` 覆盖区，未选中附件。测试改为从工具栏以下的实际可见区域开始，未改应用命中规则。
- 通栏起点下移后，初版脚本仍把手指移到目标中心，实际移动仅 446.5 px，未越过目标 608 px 的换位边界。逐帧记录确认附件位置没变、动画器空闲；修正为保留手指在图片内偏移，按两附件原始中心差及 12 dp 过界量计算终点。
- 魅族首轮第 10 次手势发生过一次换位等待超时；同一安装包随后完整 20 次通过，最终统一脚本加测 28 次亦通过。首轮缺少失败状态快照，不能单独确认该次超时的唯一原因。测试现等待 `ItemTouchHelper` 的恢复动画完全结束再开始下一次，失败时记录顺序、位置、焦点与动画状态，原始未通过报告和录屏仍保留于本地。
- 新增失败快照后曾在诊断 JSON 序列化时与主线程逐帧采集竞争，产生 `ConcurrentModificationException`。序列化前停止监听后解决；该异常发生在独立测试程序，未修改应用实现。

最终被测包 SHA-256 与上文发布回执一致；独立测试 APK SHA-256 为 `27eef7e3a3cf3405f11057453e9be6f24f520019b55fc1c4eb803c1be164877d`。完整最终用例摘要与原始结果散列见[三机检查](checks/attachment-reorder-devices-2026-10-22.json)。此前 7 项 JVM 回归和 1775 项全套结果继续适用，本轮未改变应用实现。
