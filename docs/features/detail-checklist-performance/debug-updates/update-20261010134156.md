## 2026-10-10 — 优化详情附件外观按钮响应，继续核查首滑

### 问题与修复

用户反馈部分图片/视频附件的外观按钮响应慢，触摸 ripple 也会延迟。真实大图测试复现约一秒的主线程阻塞，方法采样确认主要来自外观编辑器创建期间的同步图片解码。

- 新增 DetailCropPreviewLoader，将常规点击的图片解码、视频代表帧提取与时长读取移到后台，保留原有预览精度、裁剪结果、外观控件和粒子动画。
- 每个详情页只缓存最近一次预览，按附件来源、视频帧时间、文件长度与修改时间失效。缓存限额为 64 MiB 与应用最大堆内存四分之一中的较小值；超限图片仍按原精度显示。
- 加载期间复用统一交互受理，避免重复打开；返回、主题要求关闭和离开页面会取消待展示请求。未开始的旧任务不再解码，迟到且未交付的位图会被释放。
- DetailActivity 不再为第二张及后续固定网格附件构建永远隐藏的比例滑杆；第一张附件的宽度与比例控制保持原规则。MediaCropAppearanceDialogFragment 接收已准备的预览。

### 验证与实际效果

- 魅族同一大图的同步/异步预览尺寸和像素校验一致。候选再次打开编辑器约 40–76 ms；首次加载时主线程可以继续处理帧与触摸。
- 首次完整打开仍需读取、解码大图，实测总等待仍有明显波动，部分场景超过两秒；本次不宣称首次打开总耗时已经稳定下降。配置/进程重建恢复已打开的编辑器仍沿用既有同步恢复路径。
- 三星、魅族和平板通过后台加载、缓存失效、取消与迟到结果回收，以及图片宽度/比例/缩放、确认/取消、撤销重做、视频选帧和离屏恢复等定向回归。魅族另通过加载期间返回、重复请求、主题关闭及退出检查。
- 32 项相关单元测试通过，三机原有七张业务表核对无修改、丢失或测试行遗留。
