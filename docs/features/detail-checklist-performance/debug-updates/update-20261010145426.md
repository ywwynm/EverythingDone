## 详情清单行减负，附件外观弹窗提前显示

用户确认上一版图片按钮的触摸 ripple 已及时播放，但外观弹窗仍等待整张图片解码；本次按要求先读取尺寸等信息，提前展示正确大小的弹窗，同时继续优化清单行的创建与绑定。

- 附件外观：`DetailCropPreviewLoader` 在后台先读图片尺寸与旋转信息、视频尺寸/旋转/时长，`DetailActivity` 随即按原规则创建窗口并使用既有粒子动画，完整图片或视频预览随后异步填入。加载前后窗口不改变大小，完整预览精度不降低。
- 加载期间可以取消，裁剪、宽度/比例、视频选帧及确认暂时禁用并有状态反馈，就绪后恢复原有操作。最近一次有效缓存直接用于首帧，避免再次打开时闪过加载占位。关闭、重复请求、主题变化和窗口重建均按请求身份处理。
- 元数据保存在 `MediaCropAppearanceDialogFragment` 参数中，正常新窗口重建继续异步加载；兼容升级前缺少尺寸参数的旧窗口状态时仍保留原恢复路径。
- 清单行：`CheckListAdapter` 为每个按钮保留独立 ripple，换色时只更新颜色；去掉 `check_list_et.xml` 中首次绑定就会被替换的四份背景，减少字号、颜色、缩进的反复重置及无效布局请求。保留完整编辑、焦点、输入法组合文本、层级、拖拽、折叠、撤销及主题行为。
- 指定魅族大图两组首开测试中，弹窗首次预绘制约 204/269 ms，完整预览仍约 1.22/1.97 秒就绪；同一预览像素与原版一致。这是预绘制时间，不是粒子动画完成时间。
- 清单第一轮超时帧一组对照由 20/222 变为 13/221，但仍有约 83 ms 长帧，且不同运行存在波动。本次不将首滑标为已稳定解决，也没有关闭系统触控笔输入或削减编辑能力。
- 三机通过清单操作、18 组明暗外观对照、附件宽度/比例/缩放、视频选帧、取消、撤销及加载中重建检查；粒子关闭/开启、图片/视频共 12 组重建场景通过。32 项 JVM 回归通过。三机原有七张业务表和测试涉及的非认证设置均保持不变。

源码修改保留在工作区，未创建 Git 提交。首滑、历史生命周期限制及其它尚未完成的专项验收继续保留在功能待办中。
