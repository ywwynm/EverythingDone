# Timely 数字排版偏好

## 2026-07-05 - 计时数字需要承载 Thing Background 颜色

- DoingActivity 的倒计时数字不应长期只保持白色；下一轮上色需要让数字显示当前 Doing Thing 的 Thing Background 颜色，包含纯色和渐变背景两种情况。
- 上色方案必须以可读性为硬约束。DoingActivity 背后是用户手机桌面壁纸，并叠加黑色透明蒙版；录音 dialog 背景则跟随 App Chrome 的亮色或暗色模式。
- 同一套方案需要同时支持 timely 数字的实心和空心渲染风格。
- 录音 dialog 的计时器准备迁移到 timely 数字方案时，也应复用同一套可读性策略，而不是只按普通 TextView 颜色处理。

## 2026-07-05 - 可读性辅助层应轻，不应改变字重层级

- Thing Background 字形色的辅助可读层不能做成明显变宽的描边。当前 timely 字体已经通过合成粗细区分时/分/秒，部分粗字体本身也很宽，额外宽描边会破坏层级和字形质感。
- 默认方向应采用轻微轮廓光或柔和外发光：只提高边缘分离度，不把数字视觉上变成更粗的一层字。
- 轮廓光应始终存在，但只分布在数字轮廓附近，不能在字形底部整块铺 glow。数字 0、4、6、8、9 的镂空洞必须保持透明，能继续看到背后的桌面壁纸或 dialog 背景。
- 轮廓光不应是纯黑或纯白；它应接近宿主背景所需的偏白/偏黑方向，同时混入 Thing Background 的增强色味，让辅助光也保留一点记事颜色身份。

## 2026-07-05 - 秒钟变化应更醒目

- timely 读数的位置透明度不应从左到右明显变淡；当前偏好是 90% -> 100% 的轻微增强，让右侧秒钟更醒目。
- 无限时长符号不需要套位置透明度梯度，内部透明度直接保持 100%。
- 录音 dialog 显示完整 `HH:MM:SS` 时不能顶到边界；当前 dialog 宽度仍保持 280dp，优先通过略缩小计时器、收紧冒号间隔和调整透明度处理，但数字之间不能连在一起。
- DoingActivity 中存在的整体透明度呼吸感也应出现在录音中的 timely 计时器上。

## 2026-07-05 - 录音计时器顶部留白

- 录音 dialog 的 timely 计时器在准备和录音阶段不应贴近 dialog 顶部，需要比 18dp 更大的上边距。
- 停止录音后，计时器下移动画的最终位置应保持调整前的绝对位置，不能因为准备/录音阶段上边距增大而继续向下偏移。

## 2026-07-05 - Doing 计时器进场

- DoingActivity 打开时，timely 计时器不应一开始就直接显示出来；它应和其它主要元素一样按进场动画慢慢出现。
- 普通倒计时不应再额外包一层 alpha 淡入；旧版 `TimelyView` 是靠自身从空形态到数字的 morph 出现，`TimelyClockView` 也应保留这种自身出现动画，避免先 alpha 到 1 再播放字形动画。
- 如果普通倒计时出现两次 morph，只保留服务首次 tick 触发的后一遍；不要在 `playEnterAnimations()` 里额外主动触发一次。
- 无限时长没有数字 morph，可继续使用 alpha 出现；进场后呼吸范围应限制在 1.0 -> 0.75，不要掉到 0 附近。

## 2026-07-05 - 录音完成态位置

- 录音完成后，文件名 `EditText` 和此时的 timely 计时器位置应比上一版稍微更靠上。
- 这只影响停止录音后的完成态，不影响准备和录音阶段计时器的上边距。
- 录音 dialog 的 timely 计时器只在首次出现时播放从空形态到 `00:00:00` 的 `animateIn` 动画。
- 录音 dialog 首次 `animateIn` 可以比 view 初始化略延迟，让它和下方录音波浪动画更同步；重新开始录音回到准备态时不再重复播放。

## 2026-07-05 - 计时器左右留白

- 不同 timely 字体的 digit advance 不同，`TimelyClockView` 不能因为宽字体而顶到屏幕或 dialog 边缘。
- DoingActivity 的计时器应保留屏幕左右留白；录音 dialog 的计时器也应保留 dialog 内左右留白。
- 当字体过宽时，应在 `TimelyClockView` 内部整体缩小读数以适配可用宽度，而不是让内容溢出或贴边。
