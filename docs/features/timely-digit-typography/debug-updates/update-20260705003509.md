# 计时数字：改用尺寸阶梯区分时/分/秒 + 按 advance 统一间距（修宽字体相撞）

## 用户反馈

- 除 Poppins 外几乎所有字体的时/分/秒粗细都分不清（Poppins 也不够明显）；希望有更好的统一办法。
- DoingActivity 里像 Orbitron 这样的宽字体会让相邻数字连在一起，其它字体也可能，需要统一解法。

## 调研结论（要点）

- **层级用尺寸最可靠**：设计与排版资料一致指出"大小"是最直观、最先被感知的层级线索；而"粗细/透明度"的小差异在元素**左右分开**时几乎无法察觉——这正是当前失败的原因。表盘实践也是**主要靠缩小秒针字号**来弱化秒。推荐：时 100% / 分 ~84% / 秒 ~68%（约 1.25–1.5× 跨两级），**基线对齐**，字重+透明度仅作次要强化，对单字重字体同样有效。
- **间距用等宽格子**：数字表（计时器）标准做法是给每个数字一个**固定等宽格子**（= 0–9 中最宽者 + 两侧约 8–12% 侧边距），字形居中，杜绝相撞与抖动。

## 本次修改

- **时/分/秒尺寸阶梯（问题 1）**：`TimelyView` 新增 `setScale`，`onDraw` 改为按 `scale` 缩放并**基线对齐**（时/分/秒共享基线，顶部依次降低、底部对齐）。`DoingActivity` 设 时=1.0 / 分=0.84 / 秒=0.68。字重与透明度仍保留作次要强化。选择器预览 `renderClock` 同步呈现该阶梯。
- **统一数字间距（问题 2）**：每个数字视图的宽度改由该字体的 `advance`（最宽数字 + 侧边距）× 尺寸系数决定，去掉了旧的负边距。宽字体（Orbitron）自动获得更宽格子，相邻数字不再相撞、也不会因数字变化而左右抖动。移除 `TimelyView` 里强制正方形的 `onMeasure`，改为遵循外部尺寸。
