# 待办 / 音频附件播放对话框

## 真机验收点（2026-07-25，首版未验证）

- **声画同步**：水面起伏是否与听感对齐。实现按 `AudioTrack.playbackHeadPosition` 喂入，
  理论误差在一个解码块内（约几十毫秒）；若目测偏早/偏晚，先查 `pumpAnalyzer` 的目标位置。
- **切曲卡顿**：`open()` 会在主线程 `join(200ms)` 等旧解码线程收尾（含 `MediaCodec.release`）。
  若切曲时有可感掉帧，改成后台线程释放旧引擎。
- **seek 后的水面**：跳转会让分析器看到一次谱通量突变（D7 允许），若目测出现刺眼的假巨浪，
  再考虑跳转后短暂压制 onset 注入。
- **多声道文件**（>2 声道）走 `setChannelIndexMask`，手上没有素材，未验证。
- **暂停时的水面**：暂停后不再有 frames 进入，水体按物理自然静下来；确认不会僵在半途或突然塌陷。
- **收尾停滞阈值 320ms**（D12）：这是个经验值。若真机上偶尔看到最后一小截声音被吞、
  或播完还要多等一下才切下一条，就是这个值需要调。判定命中时会把剩余样本一次性喂给分析器，
  水面不会断，但那一下的时间轴是压缩的。

## 已知取舍

- **外来音乐附件仍按 `PHONE_CAPTURE_V1` 校正**（D5）。附件绝大多数是本 App 录的手机录音，
  与录音表现一致是用户的明确要求；但从相册/文件选入的成品音乐会被多加一层采集域校正
  （+18dB 低架、trim），水位与音色身份会偏。若以后要分流，需要一个"这份附件是不是本机录音"
  的判据（Python 侧是 `file_input_profile`），并在对话框里透出档位。
- **两套播放实现并存**：卡片上的就地播放仍是 `MediaPlayer`，对话框是自建解码链。
  两者互斥出声，功能上没问题；若以后就地播放也要显示进度，可考虑统一到 `FableSolAudioFilePlayer`。
