## 修正详情页接收更新入口的展开动画

用户反馈点击“接收并更新记事”后，界面先上移再下移，要求复用当前按钮胶囊，从原位置直接向下展开“两台设备的 NFC 区域碰一下”提示。

新增逐帧验证后，在三星复现正文、图片及视频共 5 组失败：媒体内容向上回移约 104.63 px，胶囊位置变化 6 px，并短暂缩小、变淡。原因是 TapReceivePull 用包含提示的总高度计算胶囊显现进度，提示增加高度后进度回退；详情页的媒体让位也采用这一进度，因此同步回移。上一轮检查了动画结束位置，遗漏了这一过渡。

现在 TapReceivePull 以不含提示的高度计算胶囊显现进度，保持同一个胶囊的位置、缩放和透明度，按内容实际下移所留出的空间逐步显示提示。TapDetailReceiveController 共用这一进度为媒体让位；后续提示换行也从当前位置平滑调整。

指定三星、OPPO、魅族三台设备各 5 组逐帧专项通过：正文及图片、视频连续两次进入均没有向上回移，胶囊纵向变化为 0 px，缩放和透明度保持 1，提示有实际逐步展开的绘制帧。图片和视频顶部完整、尺寸不变，退出后复位；三星录屏抽帧检查通过。三台原有数据库各表摘要完全一致，临时记事已清理。122 项相关本地测试通过。

本轮只重跑上述动画专项，未重复上一轮 13 组完整入口回归，也未执行实体 NFC 互碰。实施与证据见 docs/features/thing-transfer-update/pull-entry-2026-10-19.md。代码和文档保留在工作区，未创建 Git 提交。
