# 碰一碰更新当前记事：用户要求

## 2026-10-10

- 用户明确指定 grill-me 技能，先逐项讨论设计；每次只问一个会改变实现或用户行为的问题。
- 入口位于记事详情页的溢出菜单，名称为“碰一碰以更新记事”。
- 点击后像首页一样进入接收记事的状态。发送方使用现有的分享记事操作，两机碰一碰后，让接收方当前这条记事变为收到的记事内容。
- 必须有粒子动画，并支持撤销和重做。
- 用户允许在真机上操作，要求将动画录屏发给用户查看。本会话已明确授权三星 `R5CW20BLNKL` 与魅族 `192.168.100.67:42641`，继续保留现有记事；遇到妨碍测试的突出通知先告知，不自行处理通知对应记事。

- 用户最初选择方案 1：标题、正文／清单、附件、背景、卡片与附件外观、记事类型、提醒／习惯设置一起采用收到的版本；其中提醒／习惯设置及相关类型已由下方后续对话框选择规则调整。当前记事在本机的身份、所属文件夹和置顶位置保留，一次更新作为一个完整的撤销／重做操作。

- 用户选择第二问的方案 1：只接受一条独立记事；收到多条或文件夹时提示“更新记事时，请只分享一条记事”，保留当前内容并继续等待。
- 用户提醒更新范围还应考虑私密等属性，需要明确内容、可编辑设置和本地状态的覆盖规则，不能笼统解释为所有字段一起替换。
- 用户同意保留接收方记事自身的私密设置，所属文件夹或任意祖先文件夹的私密保护继续生效；发送方私密属性不参与替换，撤销和重做本次更新也不改变这些设置。
- 用户选择第四问的方案 1：保留接收方整条记事的未完成／已完成状态及原完成时间；清单项勾选状态属于内容，仍采用收到的版本。
- 用户要求在接收更新时提供对话框，让用户选择保留当前提醒／习惯设置及打卡记录，或采用收到记事的设置并从零开始；不采用按周期类别自动决定是否保留记录的方案。
- 用户明确选择第六问的方案 1：撤销／重做仅在当前详情页编辑期间有效，沿用现有行为；退出详情页后不保留本次编辑历史，不新增跨页面或应用重启后的持久化撤销能力。
- 用户指定新内容的粒子直接覆盖旧内容，旧内容不先消散或淡出；原背景一直作为覆盖前的画面，避免旧内容退场后出现不明确的背景颜色。
- 用户查看首版后要求：进入接收时复用首页的页面下移、屏幕四周粒子和进度显示，不另行设计接收面板。
- “碰一碰以更新记事”菜单项紧接“分享”。
- 设置对话框按标题、说明文本、操作选项排列；两个选项各占一整行，只显示单行操作名称，说明集中在上方。沿用现有选项对话框的整行点击反馈。
- 设置对话框必须选择其中一项，不提供取消按钮，也不能通过返回键或点击外部取消；离开应用等生命周期中断仍安全放弃尚未写入的更新。
- 用户指出接收控件出现后，顶部图片类附件被裁掉一段；内容区域必须完整下移，不能通过裁掉附件顶部为控件让位。
- 设置对话框下方两个选项的文本向 `end` 对齐；标题和选项均使用当前记事色，包括渐变色。
- 核对本功能在所有现有语言／地区资源中的文本，补齐缺失翻译，避免非英语界面回退到英文。
- 用户指定最终说明：“记事内容将更新为接收到的版本。您可以保留当前的提醒、习惯设置和完成记录，也可以使用接收到的设置（这会使得习惯完成记录清零）。”第二个选项为“使用接收到的设置”；其它语言同步明确习惯完成记录清零的后果。

其它本地属性的保留规则按现有编辑行为继续收敛；动画的具体画面须经真机录屏核对。
