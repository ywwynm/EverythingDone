# 项目维护调试更新

## 清理语句里的完全限定名，本版没有任何功能与外观改动

用户注意到代码里大量把完全限定名直接写在语句中（例如粒子动画那一族的 com.ywwynm.everythingdone.views.particledismiss.XXX），要求先统计再全部清理。统计结果：657 个源文件里有 791 处，分布在 108 个文件；按来源 android 占 384、项目自己的包 186、java 153、androidx 51、其余 17，项目自己的包只占四分之一。其中 669 处同文件根本没有同名类、纯属啰嗦，59 处同文件已经 import 了它、纯属多余，另有 63 处是必须限定的。

本版把 791 处清到 44 处，改动 100 个文件（全部是 Kotlin），新增 296 行 import。改写脚本只做两件事：去掉包名前缀、需要时在已有 import 块里补一行，并按「与已有 import 共享最长包前缀的那一组、组内保持字典序」插入，因此新 import 落在原有分组里而不是堆到文件末尾。注释、字符串字面量与 import、package 行一律不动。

剩下的 44 处全部必须保留：与项目自己的 R 撞名的 android.R 26 处、androidx.appcompat.R 1 处；与 Kotlin 默认导入同名的 java.lang.Double 8 处、Float 5 处、Long 4 处。三类跳过规则同样写死在脚本里：同一文件里同一个简单名指向两个不同的类、同文件已 import 同名的别的类、包通配 import 引入未知类名。两处例外经过逐一核对：android.os.Process 按 import 处理，因为项目里已有多处 import 之后裸用、且没有任何文件用到 java.lang.Process；java.util.ArrayList 与 LinkedHashMap 在 Kotlin 里本来就有同名 typealias，只去前缀不补 import。

验证分两层。改写分七批推进，每批一次完整构建；最后一批加跑全量单测，1028 项通过，唯一失败是既有的 FableSol 曲线那一项，清理前后同一项、同一数量。另外写了一个与改写代码相互独立的核对脚本：把改前改后两个版本都抹掉所有包名前缀、去掉 import 行与空行，再逐字节比较，必须完全相同；新增的行必须全是 import 或空行；不得出现重复或丢失的 import。100 个改动文件全部通过，也就是说正文除了包名前缀没有任何别的差异。

这是一次纯粹的名称解析改动，不涉及任何逻辑、资源、布局、着色器或视觉参数，界面上应当看不出任何变化。发布这一版只是为了让实际安装包也跑一遍：如果某条路径被改坏了，表现会是进入某个界面时崩溃，而不是显示异常。请按平时的使用路径过一遍首页、详情、新建、正在做事、录音与播放、设置、空间照片这些主要入口，任何崩溃都请告知。本轮未提交 Git。
