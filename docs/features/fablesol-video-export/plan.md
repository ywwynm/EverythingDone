# FableSol 视频导出画质提升实施计划

状态：**画质批次 1～8 与 D179 规格确认流程已实现**（历史执行记录以
[execution.md](execution.md) 为准；未完成的真机复核见 [followups.md](followups.md)）。

2026-07-26 的首轮六批实现已经完成，过程与偏差保留在
[execution.md](execution.md) 的历史记录中。本文改为后续画质提升的唯一实施计划，覆盖
[decisions.md](decisions.md) 的 D62～D170，并继续服从 D50～D61 中已经生效的能力探测、
用户偏好与真实产物门禁。

## 目标

本轮完成后，FableSol 视频导出应具备以下性质：

- 共用工作空间仍是 **FP16 扩展显示线性 Rec.709**；SDR 最终输出 BT.709，HDR 最终才转换到
  BT.2020，并按 PQ 或 HLG 编码。
- 用户能明确选择原生 SDR、保留高光 SDR、HDR 自动或具体 HDR 格式；设置项表达创作意图，
  完成态表达实际产物。
- 所有 10-bit 输出优先采用应用自有 P010 颜色转换，统一控制色度位置、4:2:0 降采样、闭环
  亮度修正和码值量化；可用性不足时按同格式后备规则处理。
- HDR10/HDR10+ 使用与最终可见画面一致的亮度统计；HDR10+ 由逐帧精确测量累计出完整场景
  统计，并按场景生成符合 ApplicationVersion 1 语义的 Profile B 曲线。
- HLG 与杜比视界 8.4 正确处理显示参照源、逆 OOTF、逐颜色方向的信号色容积与经验证的
  super-white。
- 编码策略以离线画质为先：CQ 默认最高质量，VBR 自动码率，高复杂度默认开启；B 帧由用户
  独立决定且默认关闭。
- 自动候选按格式、位深、硬件／软件类型与编码器族形成有序公开规格；具体 `codecName` 与
  P010／Surface 才属于同规格内部候选。公开规格变化须确认，显式格式、显式编码器族、严格位深
  与帧率不得被运行时建议改写（D179）。
- 已经完整编码、封装并提交成功的产物，不因事后附加结构诊断而被删除、重编码或改报失败。

## 本轮不做

- HDR Vivid、Eclipsa Video、APV/P210 10-bit 4:2:2。
- API 35 ROI/QP offset map。
- Display P3 SDR、BT.2020 SDR、8-bit HDR。
- 改变现有卡片几何、导出画幅或凭空增加 4K 档位。性能测量一律使用
  `FableSolExportPlan` 的实际编码尺寸。
- 把屏幕实时预览改成与视频导出完全相同的蓝噪声/P010 流水线。
- 专业认证工具级的完整码流验收，或在成功导出后为了附加诊断重新渲染整段视频。

上述可行但延后的工作继续记录在 [followups.md](followups.md)。

（D164～D170 为 2026-07-28 实现前审查与用户逐项定案的产物，见
[plan-review-2026-07-28.md](plan-review-2026-07-28.md)）：

- D111 取代 D96～D99 的逐帧曲线启停：HDR10+ 全片固定采用 Profile B 结构；D177 进一步
  把判定提升到场景级，低峰值场景写 Case 3 中性曲线。
- D177 取代 D176 的母版峰值横轴与 D122/D125 的逐帧平滑发送模型：连续 FableSol 动画按
  一个场景累计统计，曲线横轴用场景 V8（失效时回退场景 MaxSCL），整段重复同一份载荷。
- D132 已直接修正 HLG 的源语义和 D126～D131 的处理顺序：输入是显示参照图形渲染，必须先
  执行逆 OOTF，不能把它重新解释为摄像机场景光。
- D141 将杜比视界产品能力收敛为 Profile 8.4；Profile 5 与 8.1 必须从产品候选中移除。
- D142 修正最终产物验收边界：编码前短探测与编码中的真实错误仍可淘汰候选；完整编码并成功
  封装后，附加解析结果只作诊断。D91 的应用权威静态元数据仍须在封装前正确生成和注入，但
  不在成功提交后触发整段重编；回读核对定位在短探测产物上，configure 阶段注入必须保留
  （D166）。
- D53 与 D161 定义自动编码器的公开规格建议顺序：先全部硬件规格，再全部软件规格；各实现
  类型内为 `HEVC → AV1 → AVC`。D179 要求规格间切换先获得用户确认。
- D162 取代现有 8-bit SDR 的三角哈希作为首选抖动；旧算法只保留为蓝噪声资源不可用时的
  同格式后备。
- D164 修正 D131：HLG 肩部一维参数表以归一化容量 `C_S(u)/q(u)` 为查表键，不得以
  `q(u)` 作键。

## 目标流水线

一次导出按以下边界组织：

```text
用户请求
→ 读取原始能力快照
→ 生成有序候选
→ 候选准备与短探测
→ 确定实际输出规格、输入路径和内部质量工具
→ 必要的全片预分析
→ 从第 1 帧执行正式渲染与编码
→ 封装并提交
→ 非破坏性诊断与实际结果展示
```

渲染侧固定分为：

```text
FableSol FP16 扩展显示线性 Rec.709
→ 格式专属输出变换
→ 高精度呈现中间面
→ 8-bit RGB Surface 或应用自有 P010
→ MediaCodec
```

统计取样点必须按用途分开：

- 动态 SDR 只统计 FableSol 内容合成完成后的 `>1.0` 超白内容，不包含 padding、画框、投影、
  描边和时钟。
- HDR10/HDR10+ 的静态亮度和 HDR10+ 场景元数据读取最终可见合成对应的高精度 BT.2020
  呈现目标；HDR10+ 预分析逐帧精确测量后跨全部帧累计，不读取抖动后的整数噪声，也不使用
  32×32 块平均冒充标准逐像素统计。

决策覆盖关系如下；同一决定可以同时约束基础设施批次和用户可见纵向切片：

## 批次 1：请求模型、持久化迁移与候选解析

先建立单一、可测试的用户意图和实际候选模型，暂不改变正式像素输出。

### 数据模型

- 将当前混合在 `FableSolExportOptions` 中的请求值与实际落点分开：
  - 色彩模式：原生 SDR、保留高光 SDR、HDR 自动、HDR10+、杜比视界 8.4、HDR10、HLG。
  - SDR 映射：稳定/动态，只在保留高光 SDR 下生效。
  - SDR 位深：自动、严格 10-bit、严格 8-bit。
  - HLG 系信号范围：自动增强/名义范围，只在显式 HLG 或杜比视界 8.4 下读取。
  - PQ 漫反射白：标准 203 尼特/自定义 200～800 尼特。
  - HDR10+ 参考显示峰值、高光起点、码控、B 帧、高复杂度、复杂帧质量保护等独立意图。
- 新增只读的“已解析候选”结构，完整记录格式、映射方式、分辨率、帧率、位深、编码器族、
  软硬件实现、Profile、Level/Tier、码控、输入路径、信号范围、关键帧间隔及内部质量工具。
- 文件名、进度、完成态和诊断都从实际候选生成，不能再分别猜测落点。

### 持久化迁移

- 旧 `hdrEnabled=false` 迁移为原生 SDR；旧 `hdrEnabled=true` 按原 HDR 格式迁移。
- 旧杜比视界 Profile 5/8.1 迁移为显式杜比视界 8.4，不再进一步改成自动。
- 旧“恒定码率”迁移为 VBR，并保留目标 Mbps；没有保存过码率的用户进入新的自动默认。
- 没有保存过 PQ 白点的用户进入“标准 203 尼特”；已有手动值进入“自定义”并夹入合法范围。
- 旧全局 CQ 自定义值只一次性归属到迁移时实际解析的候选签名，不扩散到其它编码器或输入路径。
- 新枚举使用稳定字符串或显式版本化编号持久化，不再依赖可被新增项破坏的 Kotlin ordinal。

### 候选顺序

- HDR 自动的格式建议顺序为 `HDR10+ → 杜比视界 8.4 → HDR10 → HLG → SDR`；每次格式变化
  均须确认。显式 HDR 只使用该格式，不建议其它格式或 SDR。
- 帧率是严格规格；60 fps 与 120 fps 不互相后备，也不进入建议流程。
- 自动 SDR 位深按 10-bit、8-bit 形成建议规格；严格位深不得改变。
- 同格式、同位深、同帧率下的公开规格建议顺序为
  `硬件 HEVC → 硬件 AV1 → 硬件 AVC → 软件 HEVC → 软件 AV1 → 软件 AVC`。
- 公开规格完全一致时，才可自动切换具体编码器组件；产生可见进度后的同规格重启必须显示
  正式分类原因，但无需确认。
- 10-bit P010 与同格式 Surface 是输入路径子候选，不得被错误提升为另一种 HDR/SDR 格式。

### 能力与测试

- 能力缓存只保存原始结构化结果、稳定标识和厂商异常原文；当前 locale 的说明在展示时生成。
- 能力事实不得回写用户偏好；设置页探测不得弹出一次“导出失败”。
- 为迁移、候选字典序、显式/自动失败语义、隐藏选项不参与求值及实际结果命名建立 JVM 单测。

**完成条件**：旧设置可无歧义迁移；同一请求与能力快照生成稳定、可解释的候选序列；正式导出
仍可通过兼容适配层保持原有产物，尚未启用的新画质路径不半成品暴露。

## 批次 2：高精度呈现与通用 P010 质量核心

这一批建立 SDR/HDR 共用的像素基础，避免后续每种格式各自实现一套 RGB→Y′CbCr。

### 高精度呈现

- 保持 FableSol 场景缓冲为 FP16 扩展显示线性 Rec.709。
- 应用自有 P010 路径优先把格式专属呈现结果写入 `RGBA16F`；必须实际创建 FBO 并检查
  completeness，不能只看 GLES 版本或扩展字符串。
- `RGBA16F` 不可用时在正式渲染开始前选定 `RGB10_A2` 兼容中间面；不在完整视频中途换路径。
- HDR10+ 统计、P010 亮度和色度都读取同一个抖动前呈现目标，避免元数据与编码输入精度不同。

### P010 转换

- 将现有仅服务 HDR10+ 的 `FableSolExportP010Bridge` 泛化为：
  - 10-bit SDR：BT.709 primaries/transfer/NCL matrix；
  - HDR10/HDR10+：BT.2020、PQ、BT.2020 NCL；
  - HLG/杜比视界 8.4：BT.2020、HLG、BT.2020 NCL。
- 用有明确相位的低通滤波替代无位置语义的 2×2 box average。短探测读取实际码流色度位置
  （HEVC 读 SPS/VUI，AV1 按 D170 读序列头 `chroma_sample_position`）：优先 Type 2；
  编码器明确声明其它合法类型时匹配其相位；未声明时按 Type 0 兼容语义。
- PQ 使用显示线性闭环亮度修正；HLG/杜比视界 8.4 使用场景线性修正；10-bit SDR 使用
  BT.1886 参考显示目标。正式路径采用单步闭式/局部线性化，测试使用高精度迭代 oracle。
- 最终 Y′、Cb、Cr 在目标 10-bit 码值域使用固定 64×64 蓝噪声阈值舍入；色度先量化，
  闭环读取实际色度码值，最后量化修正后的 Y′。
- 正确处理 stride、slice height、crop、plane row stride/pixel stride 与有界缓冲，不假定
  紧密 P010 排布。

### 输入路径资格

- 所有 10-bit 输出优先尝试同配置真实 P010 编码/解码短探测；不以 Android API 版本单独判定。
- HDR10+ 的 P010 是必需路径。
- HDR10、HLG、杜比视界 8.4 与 10-bit SDR 的 P010 失败后，只能先退到同格式、同 Profile、
  同编码器族的 10-bit Surface；之后才由全局候选处理真正失败。

**完成条件**：固定 RGB/P010 向量通过矩阵、范围、相位、量化与闭环 oracle；FP16 和
`RGB10_A2` 两条中间面均有明确落点；运行时资源失败不会推翻已经成功提交的产物。

## 批次 3：SDR 三种成片语义

以 SDR 建立第一个完整的用户可见纵向切片。

### 原生与保留高光

- 原生 SDR 关闭额外 HDR 高光并重新渲染，不增加 tone mapping。
- 保留高光 SDR 继续使用当前 HDR 强度；强度为 `1.0×` 时自然退化为原生观感并在信息栏说明。
- 稳定映射为默认，根据 HDR 强度生成全片固定曲线，不预扫描整段动画。
- 动态映射只用 FableSol 内容的真实超白 maxRGB 峰值调整 `>1.0` 高光，基础 `0～1.0` 映射
  全片固定；上升 `τ=0.08s`，释放 `τ=0.80s`，第一帧直接初始化。
- 映射以 BT.2446 Method B 的高亮压缩意图作标定，但不执行 PQ/HLG 往返；对 RGB 使用共同
  maxRGB 增益，不额外去饱和、不逐通道裁切。

### 位深与失败行为

- 10-bit SDR 接入批次 2 的 BT.709 P010 与 BT.1886 闭环。
- 8-bit SDR 在最终 BT.709 编码 RGB、写入 Surface 前使用静态 64×64 蓝噪声，共用 RGB
  阈值并保持真黑/真白；资源失败时才退现有三角哈希。
- 动态统计在正式导出中失败时，丢弃未提交尝试并从第 1 帧按稳定映射重启。
- FP16 扩展场景不可用时，丢弃未提交尝试并从第 1 帧按原生 SDR 重启。
- 严格 10-bit 无合法候选时只在真实导出后失败；自动位深才允许使用 8-bit。

### UI 与结果

- “导出色彩模式”显示两种 SDR、HDR 自动和具体 HDR 格式；保留高光 SDR 下显示稳定/动态。
- SDR 下显示“视频位深”，HDR 下隐藏且不读取该历史值。
- 信息栏解释稳定/动态、10/8-bit、强度 `1.0×` 退化及可能发生的实际后备。
- 文件名分别使用 `SDR`、`SDR-TM`、`SDR-DTM`，完成 Dialog、通知和日志显示最终完整模式。
- 补齐 13 套语言。

**完成条件**：三种 SDR 语义、两种位深和全部运行时后备都有候选/状态测试；原生 SDR 与当前
实现的基准画面无非预期变化；固定渐变素材显示 8-bit 蓝噪声与 10-bit 精度的预期差异。

## 批次 4：PQ 母版意图、全片静态统计与 HDR10

### 母版参数

- PQ 漫反射白默认固定为标准 203 尼特；自定义范围 200～800 尼特。
- 导出参数不随本机显示器改变。本机声明峰值只作诊断或用户主动采用的一次性参考值。
- 白点固定 D65；BT.2020 容器中的虚拟母版 primaries 使用 P3-D65；母版最小亮度
  `0.0001 nit`。
- 母版最大亮度取 `ceil(漫反射白 × HDR 强度)`，至少覆盖实测 MaxCLL，且不超过
  10000 尼特。

### 全片预分析

- HDR10/HDR10+ 在正式编码前用确定性离线渲染跑全片统计。
- `MaxCLL` 为全片最终可见 BT.2020 线性 maxRGB 峰值；`MaxFALL` 为逐帧平均 maxRGB 的最大值。
- 成功结果按完整渲染指纹缓存；取消、部分结果、失败回退值不写缓存。
- 统计失败但渲染有效时，使用理论 MaxCLL 和 `MaxFALL=0` 未知，并在信息与诊断中明示。
- 渲染本身失败时不得套统计回退发布。

### 静态元数据与发布边界

- 应用生成唯一权威的 ST 2086/MDCV、MaxCLL、MaxFALL 和色彩标记；configure 阶段注入始终
  保留，编码器输出缺失时在 `MediaMuxer` 轨格式中补齐；回读核对在短探测产物上执行，接受
  容器 box 或码流 SEI 任一有效承载，冲突在短探测阶段淘汰候选（D166）。
- 正式编码中元数据注入、有效视频样本和封装错误仍是候选成败条件。
- 完整编码和封装成功后，附加容器/码流解析只记录诊断，不删除、不重编、不改报失败。

**完成条件**：标准/自定义 UI、缓存指纹、理论回退、25 字节静态描述符和 HDR10 真实候选均有
自动测试；结果页能区分实测统计与理论/未知值。

## 批次 5：HDR10+ 精确场景统计与 Profile B 曲线

### 统计

- GLES 3.1 首选 compute shader/SSBO 直方图归约；GLES 3.0 使用全分辨率 RGBA8 精确打包与
  回读。首版不先做三像素紧凑打包，也不恢复 32×32 块近似。
- MaxSCL、AverageMaxRGB、DistributionMaxRGB、FractionBrightPixels 和内部完整 CFD 都在
  线性 BT.2020 中计算。
- 连续动画按一个场景处理：MaxSCL 取跨帧通道峰值，AverageMaxRGB 与 CFD 对全部帧的全部
  像素累计，FBP 取场景内平均亮度最高的 5:1 代理帧；跨帧桶计数使用 64 位。
- CFD 直方图桶按 D169 对齐载荷 `0.00001` 量化网格（100001 桶）；MaxSCL 与
  AverageMaxRGB 不过桶，两个统计后端同桶定义、结果逐项相等。
- ApplicationVersion 1 分布使用 nearest-rank 与已确认的九个百分位；V1=0、V2=0.00255，
  V8 为真实 99.98%（已于 2026-07-28 对照 ST 2094-40:2020 §8.5.4 原文逐字验证）。
- FractionBrightPixels 计算失败时写规范零值并继续；其它精确统计后端均失败时淘汰 HDR10+
  候选。

### 曲线

- 全片固定 Profile B 结构、`tone_mapping_flag=1`、9 anchors；场景源峰值不高于参考峰值时
  使用 Case 3 中性映射，不提亮。
- 源归一化峰值优先使用场景 V8，场景 MaxSCL 只作回退；高光起点直接查询场景完整 CFD。
- 内部优化在 PQ 感知域评价，载荷语义仍是线性归一化 maxRGB。
- CFD 密度与均匀先验各占 0.5；基础 OOTF 只压缩、不提亮、不放大局部对比度。
- 当前连续动画只求解一次场景映射并在每帧重复同一份载荷；不再用逐帧平滑掩盖场景边界错误。
  将来若引入真正的多场景时间线，应按明确场景边界另行设计过渡。
- KneePoint/anchors 量化后必须满足单调、连续、端点及斜率门禁；无解时先降低膝点，
  `S > 10T` 时判当前候选失败。

### 行为与验证

- 参考显示峰值为 300～10000 尼特滑杆，标准 1000 尼特，并提供已确认的快捷参考值。
- HDR 自动中的 HDR10+ 失败后继续
  `杜比视界 8.4 → HDR10 → HLG → 原生 SDR`；显式 HDR10+ 失败即结束。
- 失败提示来自真实导出，列出统计后端、曲线或编码阶段原因，并提供“调整导出设置”。
- 测试以语法/数学硬门禁、普通样片 A/B 和程序化边界统计为主，不要求为每个罕见边界制作完整
  片源或逐项实机验证。

**完成条件**：标准载荷逐字段解码测试、两个统计后端的一致性测试、曲线约束/时间序列测试及
自动/显式失败测试全部通过；成功完整产物不被事后附加解析推翻。

## 批次 6：HLG 与杜比视界 8.4

### HLG 输出变换

- 将显示线性 Rec.709 转成显示线性 BT.2020，按参考 HLG 显示条件归一化并执行逆 OOTF，再
  进入场景线性颜色方向肩部，最后应用 HLG OETF。
- FableSol `1.0` 固定映射到 75% HLG 信号；不增加绝对白点或目标峰值选项。
- 对每个像素按自身颜色方向计算 `q(u)`、共同的源显示线性 `2.0×` 肩部起点、可用端点与
  指数肩部；RGB 只乘共同增益。
- 参数表在导出开始前生成，以归一化容量 `C_n(u) = C_S(u)/q(u)` 为查表键（D164），
  shader 连续插值；同一输入跨帧得到同一输出，不做逐帧动态 HLG。

### super-white 与名义范围

- 自动增强只在真实 P010 编码—解码回环证明 100% 以上 limited-range 样本仍可辨认时使用。
- 回环分别求 Y′、Cb、Cr 连续安全区间，并按 D165 的方向域查表加二分连续推导每个颜色方向
  的设备上限，不把 RGB 测试点变成离散颜色档。测试图按 D172 逐分量走阶梯，判定以"与名义
  端点拉开成比例的距离"为准，容差必须小于阶梯步长。
- 结论未知时在正式动画渲染前执行短验证并缓存；验证失败或不可解析时继续名义范围 HLG，
  不回退 SDR、不弹导出失败。
- 显式 HLG 显示“HLG 信号范围”，显式杜比视界 8.4 显示“HLG 基层信号范围”；HDR 自动
  最终落到二者时固定采用自动增强语义，不读取隐藏的名义范围历史值。

### 杜比视界

- 只保留 Profile 8.4，删除 Profile 5/8.1 的 UI、自动候选和正式导出路径。
- 杜比视界 8.4 复用 HLG 输出变换、P010、闭环修正和 super-white；设备编码器继续负责动态
  元数据。
- P010 自动增强不可用时仍可用同格式名义范围 P010，必要时再用同格式名义范围 Surface。

**完成条件**：逆 OOTF/正 OOTF 参考向量、颜色方向连续性、指数肩部端点、回环缓存签名及
自动增强/名义范围行为均有测试；完成态只报告实际 HLG 基层范围。

## 批次 7：离线编码画质策略

### 码控与码率

- 用户可见模式为 CQ（默认）与 VBR；CBR 仅在实际编码器不支持 VBR 时作内部后备。
- CQ 默认只下发 `BITRATE_MODE_CQ + KEY_QUALITY`，默认值取当前候选 `qualityRange.upper`；
  编码器 configure 要求码率键时按 D167 的同模式兼容阶梯重试 CQ+码率提示，不改判模式。
- VBR 只下发 `BITRATE_MODE_VBR + KEY_BIT_RATE`。默认值按实际编码宽高、帧率、编码器族、
  位深和 HDR/SDR 信号推导并夹入合法范围；沿用现有码率滑杆，不新增自动按钮。
- 为 HEVC、AV1、AVC 的基础系数与信号系数建立集中版本化常量，用固定深色渐变、静水和高速
  高光回归标定。

### 编码工具

- B 帧独立开关默认关闭；开启且适用时请求 `KEY_MAX_B_FRAMES=1`，表示连续 B 帧上限，
  不是每个 GOP 只有一个 B 帧。不可用时保持同格式无 B 帧。
- 高复杂度默认开启，请求实际编码器 `complexityRange.upper`；关闭或不支持时省略该键。
- VBR 的复杂帧质量保护默认开启；API 31+ 且实际支持时请求 `KEY_VIDEO_QP_MAX=40`，不可用时
  省略，不改变格式。
- 所有导出请求 `KEY_PRIORITY=1`，不设置 `KEY_OPERATING_RATE`。
- Profile 保持画质/格式要求；Level/Tier 按实际尺寸、帧率、码率、位深和参考结构选择最低
  充分值（CQ 模式不以码率定档，按 D168 只以尺寸与像素率取档），High Tier 只在 VBR/CBR
  码率确实需要时使用。
- 关键帧间隔保留 0.5～10 秒、步长 0.5 秒、默认 2 秒；跨候选保持完全相同。

### 展示

- 信息栏解释 CQ/VBR、B 帧、高复杂度、复杂帧保护、关键帧间隔和软件编码代价。
- 设置摘要、进度、完成 Dialog、通知和诊断展示实际码控、平均码率、编码器名称/族、
  软硬件实现、B 帧请求落点与复杂度落点，不把“申请成功”表述成厂商必然采用某内部工具。

**完成条件**：每个 `MediaFormat` 键都有正反组合测试；候选短探测与正式编码使用同一解析结果；
不支持的压缩工具只省略或关闭自身，不触发格式/帧率/位深降级。

## 批次 8：集成验证与交付
