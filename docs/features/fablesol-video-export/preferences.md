# fablesol-video-export 用户偏好

- 播放对话框进度条与 Timely 数字左缘对齐时，以滑杆 handle 的可见外缘为准，不以轨道起点为准。
- handle 与轨道在几何对齐基础上还要整体向左轻微越过 Timely 数字左缘，以获得视觉对齐；当前采用 2dp 光学校正。
- 音频海浪动画设置中的选项胶囊必须随海浪换色正确变化；未选中态轮廓和选中态填充都要支持完整渐变，不得用 `representativeColor()` 或单一色值代替。
- 导出进度 Dialog 的标题必须与通知标题统一为「导出音频海浪动画视频」，底部间距跟随标准取消/确定 Dialog。
- 导出完成 Dialog 需要显示导出规格、实际视频大小和保存位置；操作只保留分享、添加到附件两个按钮，两者都使用当前记事的完整颜色或渐变。视频成功后默认已保存到相册，不再显示“保存到相册”操作。
- 导出完成通知需要与完成 Dialog 显示同一份结果信息，包括 HDR/SDR、实际帧率、实际视频大小和保存位置。
- 导出视频图标使用 Google Material Symbols 的 `video_frame_save`，不再使用海浪图形；
  在保留播放三角与保存箭头主体的基础上，把左侧和顶部画框补成连续完整的边框。
- `video_frame_save` 信息密度较高，在录音 Dialog 的 56dp FAB 和音频附件 Dialog 的
  40dp 导出按钮中，可见图形均使用 22dp；只缩小图标，不改变原 touch ripple 范围。
- 导出进行中与导出完成 Dialog 的底部按钮文字，必须在各自 touch ripple 胶囊的可见边界内水平、垂直居中。
- 导出视频宽、高都必须是 64px 的倍数；补齐尺寸时只重新绘制并对称扩展背景，卡片几何、水体和 density 不变。
- 导出视频的完整背景画面必须左右对称，不得因编码尺寸对齐、视口、crop metadata 或分享平台处理而只裁掉右侧背景。
- 音频附件的 FableSol 播放 Dialog 中，导出视频图标使用当前记事颜色，并完整支持渐变；播放/暂停按钮的图标要比上一曲、下一曲更大，与其更大的 touch ripple 层级一致。
- 音频海浪动画设置使用单一“导出色彩模式”选择器，统一表达原生 SDR、保留高光 SDR、
  HDR 自动和各具体 HDR 格式。选项可用性必须反映当前全部约束下的真实编码/渲染能力，但能力
  结论不得清除或改写用户已经保存的显式选择。
- HDR 实编码能力探测不得在每次打开设置 Dialog 时重复执行；首次探测必须避开弹窗首帧并在后台低优先级运行，结果应按设备系统版本和探测实现版本缓存。
- 色彩模式或其二级质量工具不可用时，选项仍应可见并明确显示原因；标签颜色和透明度必须与
  顶部 HDR 高光增强的不支持态一致，不能叠加系统 disabled 色而显得更淡。能力探测只更新
  行内状态，不弹出一次导出失败提醒。
- 导出设置中的术语使用“编码模式”，不用“码率模式”；恒定质量说明使用“视频大小随画面复杂度变化”，不得省略“视频大小”。所有支持语言保持同一语义。
- PQ 漫反射白默认采用与导出设备无关的标准 203 尼特；界面使用“标准/自定义”语义，自定义
  范围为 200～800 尼特。恢复默认回到标准值，不根据本机屏幕峰值、最大帧平均亮度或当前
  显示状态自动改写母版意图；本机显示值只作为诊断、观看参考或用户主动采用的一次性参考值。
- 设置 Dialog 中的技术公式必须使用标准 ASCII 函数写法、半角括号和英文逗号，例如
  `min(a, b, c)`，不得混用中文全角括号或顿号。显示本机 HDR 峰值与最大帧平均亮度时，
  必须明确它们属于设备诊断/观看参考而非默认导出参数；未声明或不可信的字段须明确标注。
- HDR 导出格式选择“自动”时，说明文字必须准确反映 `AUTO_ORDER` 的规格/画质能力优先策略，
  不得误写成兼容性优先。
- 自动 HDR 格式顺序固定为
  `HDR10+ → 杜比视界 8.4 → HDR10 → HLG`。
- 中文 locale 的所有用户可见位置必须使用“杜比视界”，不得显示英文 “Dolby Vision”；
  覆盖格式胶囊、自动选择说明、规格推导、设备诊断、导出完成 Dialog、通知及失败信息。
  内部缓存、文件名和格式匹配继续使用稳定的英文标识，不得随 locale 改变。
- HDR 相关的所有用户可见说明与设备诊断必须采用专业、严谨、正式的技术表述：陈述申请值、
  编码器实际回报、判定结果和可用的后续候选，不使用“这一档”“还有机会”“不打算产出”
  “没有别的办法”等口语化或拟人化措辞。
- 音频播放自然结束后，用户拖动进度条到可播放位置并点击播放，必须能够从所选位置继续播放。
- 音频附件 Dialog 的主播放/暂停图标可见尺寸固定为 32dp，外层 touch ripple 保持 56dp。

## 2026-07-27 规格优先于收益权衡

用户明确裁定：**"不用考虑收益，咱们这个就是能支持多高规格就支持多高规格。"**

背景是我在评估 HDR10+ 与杜比视界时反复给"收益可能很小"的成本收益分析（动态元数据对单一
连续场景买不到多少、HDR10 的静态元数据本来就是精确值）。这类权衡不要再拿来当作不做的理由。

**如何执行**：只要平台上存在更高规格的输出形态，就去实现并让设备实测判定；判断的唯一门槛
是"这台机器真编得出来吗"，不是"值不值得"。可以如实说明各档的差别（用户要靠它选），但不要
用"收益不大"去劝退一个技术上可达成的规格。

## 2026-07-28 HLG 按颜色方向利用信号色容积

- HLG 高光映射应逐像素按颜色方向利用各自仍可用的信号色容积，不得为了使用一条最不利全局
  曲线，就按 Rec.709 蓝色方向的较小容量提前压缩中性色及其它仍放得下的高光。
- 方向相关映射仍须确定、连续且跨帧稳定，不读取逐帧内容统计；对 RGB 施加共同增益以保持色度
  方向，不得用逐通道截断换取额外亮度。
- HLG 高画质路径应使用标准 limited-range super-white 扩展高饱和颜色的可用色容积：中性色
  仍止于 100%，其它颜色只按匹配参考显示色容积所需的程度使用最高 109% 信号。只有实际编码
  验证确认名义范围以外、视频数据范围以内的 10-bit 亮度或色度码值被保留时才能启用和对外
  报告，不得仅凭 Surface 编码成功假定支持。
- 设备无法验证 HLG super-white 时，仍应导出名义范围 HLG，而不是回退 SDR 或直接失败；设置页信息栏、
  导出完成信息和设备诊断必须明确说明实际使用的是“HLG 扩展信号范围”还是“HLG 名义范围”。
- HLG 应提供“自动增强”和“名义范围”两种信号范围选项：默认自动增强，在验证通过时使用 super-white、
  否则自动使用名义范围；用户也可强制名义范围以提高下游兼容性的可预测性。信息栏必须解释两者对高饱和
  彩色高光压缩和播放器、电视、分享平台兼容性的区别。
- 信号范围只在显式选择 HLG 系格式时显示并可编辑：普通 HLG 显示“HLG 信号范围”，杜比视界 8.4
  显示“HLG 基层信号范围”，均提供“自动增强/名义范围”。“自动”格式最终落到 HLG 或杜比视界 8.4
  时始终采用“自动增强”，不得受隐藏的“名义范围”历史设置影响。
- “自动增强”首次遇到尚未验证的 HLG 编码路径时，应在正式渲染前显示准备状态并完成一次短时验证；
  通过后使用 super-white，未通过则继续导出名义范围 HLG 而不弹失败提示。验证结果按实际编码器、
  输入路径和系统环境缓存，不得因后台探测完成时机不同而让相同设置的首次导出随机采用不同画质路径。
- HLG super-white 必须通过真实的 P010 编码—解码回环验证：检查 CPU 可读 10-bit 重建色块及色彩标记，
  不能仅凭编码器接受输入、产出文件或 Surface 显示成功判定。无法取得可靠 P010 解码输出时，保守使用
  名义范围 HLG，不把它描述成 HLG 编码失败。
- HLG 编码路径只保留部分 Y′CbCr 扩展余量时，应连续推导各颜色方向的安全上限并利用仍可用的余量，
  不因单个分量受限而全局退回名义范围；但不再逐项讨论测试色块和容差等次要参数，计划阶段采用保守默认值
  并通过回归测试固定。后续设计讨论优先处理会显著改变整体画质、导出架构或用户行为的核心问题。
- 杜比视界导出只支持 Profile 8.4；Profile 5 与 Profile 8.1 不作为产品选项、自动候选或导出能力。
  讨论和实现优先处理公开接口能够真实编码并验收的路径，不因设备广告了 Profile 常量就宣称应用支持。
- 不要把专业码流认证式的严格检验当成视频导出的核心任务。完整编码并封装成功后，不得因为附加结构检查
  失败或应用无法解析就删除产物、重新渲染、自动换格式或改报失败；实际播放端的格式识别与观看结果具有
  更高的产品证据价值。结构检查可以保留为低优先级诊断能力。
- 杜比视界 8.4 应复用普通 HLG 已确定的 super-white 自动增强：优先通过 Dolby 官方支持的 P010、
  BT.2020、limited-range HLG 输入路径保留扩展色容积，并由设备编码器生成动态元数据；当前路径无法
  保留扩展码值时仍导出名义范围的杜比视界 8.4，不因该增强不可用而切换 HDR 格式或把导出报为失败。
- 离线视频导出的用户可见码控模式使用“恒定质量（CQ）/目标码率（VBR）”，CQ 默认且默认不
  同时下发 `KEY_QUALITY` 与 `KEY_BIT_RATE`（编码器 configure 要求码率键时按 D167 的
  同模式兼容阶梯重试，不改判模式）；CBR 只允许在编码器不支持 VBR 时作为内部设备后备，并须在设置
  信息、诊断和完成结果中显示实际落点。旧“恒定码率”偏好迁移为 VBR，同时保留原目标码率。
- FableSol 视频导出以画质优先：CQ 默认值和“恢复默认”均使用当前实际编码器公开质量区间的上限；
  用户仍可手动降低。自定义原值按实际编码器路径分别保存，不跨编码器、MIME/Profile 或实质不同的
  输入路径套用，也不再使用没有标准依据的“质量区间 80%”作为默认值。
- VBR 默认码率按实际编码宽高、帧率、编码器族、位深和 HDR/SDR 信号自动推导，不再使用固定
  24/14.4 Mbps 或固定 0.6 倍缩放。不得为“自动/自定义”新增按钮、开关或标签组：沿用现有码率滑杆，
  默认位置跟随自动值，用户拖动后成为自定义 Mbps，现有“恢复默认”重新进入自动状态；信息栏用文字
  说明当前状态和解析结果。
- 自动选择编码器族时，在其它输出规格完全相同的候选之间优先 HEVC，再考虑 AV1；不得为了选择
  HEVC 改变帧率、HDR 格式、分辨率、位深或其它已确定的输出规格。用户说明其设备上的 AV1
  编码器均为软件实现，这是设备事实，不代表要求产品排除软件 AV1，也不得据此推导跨设备的
  软件编码器过滤策略。
- 自动档不得完全排除软件编码器：软件规格排在全部同格式硬件规格之后。设置摘要解析到软件
  编码时，应说明速度、耗电和发热影响；正式导出从硬件规格切换为软件规格前必须请求确认。

## 2026-07-29 设置界面的两处措辞与顺序

- 「导出色彩模式」的胶囊顺序 **HDR 在前、SDR 在后**：`自动 → HDR10+ → 杜比视界 8.4 →
  HDR10 → HLG → SDR（原生渲染） → SDR（保留高光层次）`。默认值是「自动」，把降级选项摆在
  最前面与本功能的规格优先取向相反（D173）。
- 勾选框的标签用**动词短语**，不用裸名词：「启用 B 帧编码」而不是「B 帧」。同组的
  「高复杂度编码」「复杂帧质量保护」在勾选框语境下读得通，可以保持名词短语。

- **每个选项的说明必须贴在该选项正下方**，不得统一堆到底部信息栏；说明常显，不随开关显隐
  （D174）。底部信息栏只承担"这一组设置推导出了什么"与设备能力报告。

- 取自设备的参考值必须写明**它测的是什么**并带单位（「本机屏幕峰值（2000 尼特）」而不是
  「本机（2000）」）：同一行里其它胶囊是无单位的创作参考值，不写清就分不出是不是同一回事（D175）。

## 2026-07-29 HDR10+ 时间稳定性

- HDR10+ 可以为星芒、银丝等高光压缩肩部，但高光出现或消失时不得让主体水体产生可感知的
  整体明暗呼吸；漫反射白 203 尼特与 350 尼特都要满足这一点。
- 验收时重点比较无星芒的平静段与星芒出现后的水体主体亮度。高光层次增强不能以明显压暗
  整片水体为代价；当前工作区改动前、上一次提交版本的观感可作为稳定性参考。

## 2026-07-29 HDR10+ 用户文案风格

- HDR10+ 设置说明、格式说明、完成结果与失败提示统一使用专业、简练、清晰、正式的书面语。
- 避免「装得进」「多带了一层」「想让……真的……」「把……提到」「这套组合生成不了」
  等口语表达，也不使用面向用户的祈使式营销措辞。
- 完成结果只陈述本次产物的客观状态和参数含义；参数调整建议使用中性、条件式表述，不以
  第二人称引导用户追求某种效果。
- 13 套语言必须保持相同的信息层级、技术含义与正式语域，不能只修订中文。

## 2026-07-29 导出重试状态文案

- 导出开始后若需要改变编码器族，不能自动重试；Dialog 必须同时显示上一规格、失败原因及拟
  采用的新规格，并在用户明确确认后才开始重试。
- 重试说明统一使用专业、简练、清晰、正式的书面语，不使用口语表达。
- 输出格式、编码器族、位深及硬件／软件编码类型中的任一项发生变化，都必须执行上述确认流程。
- 帧率不提供建议降级：120 fps 失败后结束本次导出；需要 60 fps 时由用户返回设置页重新选择。
- 只有用户原先设为“自动”的轴可以出现在建议规格变化中；显式选择的格式、编码器族和位深不得
  由运行时建议改变。
- Dialog 中的公开规格统一包含输出格式、编码器族、位深、硬件／软件编码类型、帧率和编码模式；其中任一项
  变化均须明确说明。
- 具体 `codecName` 与应用 P010／Surface 输入通路属于内部实现，不作为输出规格名称展示。
- 六项公开规格完全一致时，可自动尝试其它具体编码器组件或输入通路。
- 同规格内部候选在进度为 0 时失败，可静默切换；已产生可见进度并需要重新处理时，Dialog 应
  显示完整规格、正式分类的失败原因以及“正在以相同输出规格重新尝试”的状态，但无需确认。
- 失败原因必须明确写出发生失败的完整公开规格，再说明具体失败阶段；不得仅写“编码器无法初始
  化该规格”等缺少实际规格内容的概括性句子。
- 底层异常、厂商错误码与内部实现名称只进入设备诊断，不直接进入面向用户的重试文案。
- 公开规格变化确认态固定显示“失败规格／失败原因／建议规格”，并仅提供“使用建议规格重试”
  和“结束导出”两个操作；等待确认期间不得开始建议规格，也不显示“在后台运行”。
- 规格确认态禁止点击外部关闭；系统返回键等同于“结束导出”，不得因关闭 Dialog 留下未决任务。
- 应用位于后台时，不依赖弹出 Dialog；直接将导出通知更新为规格确认通知，并允许用户在通知中
  采用建议规格或结束导出。
- 点击规格确认通知正文直接采用建议规格，不打开或恢复原导出界面；正文与“使用建议规格”按钮
  执行同一幂等操作，重复点击不得创建多个导出任务。
- 通知同时保留“使用建议规格”和“结束导出”两个操作按钮。
- 后台规格确认不设置超时；等待期间释放全部导出资源与唤醒锁，通知持续保留。系统终止服务时
  本次任务按失败结束，不自动恢复或改动规格。
- 每次公开规格变化都单独确认；确认一次不得授权后续连续降级。
- 多次失败时，Dialog 与通知仅显示最近一次失败、下一建议及已尝试规格数量；完整历史保存在
  设备诊断中。
- 确认建议规格后，最近一次失败说明在重试期间持续显示；成功完成时显示实际规格、尝试数量和
  最近调整原因，最终失败时显示最后失败规格及原因。
- 多个建议规格可用时，固定帧率并保持显式轴；依次优先维持格式和位深、其他硬件编码器族、
  同格式软件编码、下一自动格式，SDR 自动位深最后才由 10-bit 转为 8-bit。

## 2026-07-29 设置页精确联动

- 格式、编码器和帧率选项必须按同一组精确可行组合对称联动。
- 自动解析、按钮置灰和导出可用性不得引用其它帧率的能力结论。
- 当前组合无解时禁用导出并显示正式原因，不得静默修改帧率。
- 编码模式必须与格式、编码器族、位深和帧率使用同一精确能力结论；选择恒定质量时不得实际
  输出 VBR。CQ 不可用时置灰该选项，质量滑杆只读取当前具体编码器的实测区间。

## 2026-07-29 真机画质验收

- 使用同一录音、同一设备与同一播放器比较各导出规格，重点检查水体主体的时间稳定性、颜色、
  星芒及银丝高光、暗部层次和压缩质量。
- 发现问题后必须保留修复前样片，并以相同参数、相同取帧时刻、相同逐帧统计方法复测；只有
  修复后结果可量化地优于修复前，才接受该修改。
- 真机样片、逐帧分析结果和截图统一归档到任务指定的电脑目录，文档必须记录原因、修改方法、
  决策依据及修复前后证据。
