# fablesol-video-export

把一个音频附件导出成一段 **Voice Waveform Video**：画面是该音频的 FableSol 水体，
自带该音频的声音，条件允许时是 HDR Media。产物由音频**重新渲染**得到，不是屏幕录制。

架构裁决见 [ADR-0018](../../adr/0018-fablesol-visualization-video-offline-render.md)；
术语见根目录 `CONTEXT.md` 的 **Voice Waveform Video** / **非实时驱动** /
**整曲前瞻分析** / **重力轨迹** / **导出画框**。

## 本目录文档

- `decisions.md` — 逐条决策与理由
- `plan.md` — 实施批次
- `sessions.md` / `followups.md` — 会话记录与遗留项（随工作推进新建）

## 范围

**做**：离线渲染引擎、HDR/SDR 编码降级阶梯、重力轨迹记录与回放、两个入口、
前台服务与通知、导出参数设置项。

**不做**：录音或播放时旁路屏上渲染实时编码（见 ADR-0018 的 Considered Options）；
整曲前瞻分析；带 alpha 的产物格式；9:16 等改变水体物理容器的画幅。

## 产物形态

| 项 | 取值 |
|---|---|
| 构图 | 与触发入口无关，恒用录音对话框那套紧凑构图：420dp 高、时钟贴顶 36dp、内容不做取景平移 |
| 画面内容 | 水体 + TimelyClockView 计时动画 + 圆角卡片；无按钮、无文件名、无进度条 |
| 画框 | 卡片四周 24dp padding，底色跟随 Appearance Mode，卡片带投影与发丝描边（描边随底色翻极性） |
| 外观 | 画框底色、**卡片底色**与时钟 hostDark 一起跟随应用当前的深浅色，判定来自 `FableSolExportAppearance`（D44），不读 Service Context 碰巧带的那份主题与配置 |
| 宽高比 | 跟随对话框实测 dp 几何。宽度是 `max(280dp, 时钟固有宽 + 48dp)`，随用户选的数字字形在 280～383dp 间变化 |
| 像素尺寸 | dp 几何照抄，像素高度提到固定档，density 由此反推；最终画布按 codec 要求与 64px 分享边界共同向上对齐，只对称扩展画框 |
| 帧率 | 用户严格选择 60 fps 或 120 fps；运行时不得在两者之间自动降级 |
| 视频编码 | 见下面的「当前能力」表 |
| 音频编码 | AAC-LC 192 kbps |
| 落地 | `Movies/EverythingDone/`，不自动挂成附件，完成后提供「分享」与「添加为附件」 |

## 当前能力（2026-07-30，OPPO 全格式复核完成）

用户在设置里选的是**创作意图**，完成信息报告的是**实际产物**——两者可以不同（例如显式
选了「自动增强」而设备验不出扩展信号范围），任何时候以完成信息为准。

| 轴 | 可选值 | 说明 |
|---|---|---|
| 色彩模式 | `SDR（原生渲染）`、`SDR（保留高光层次）`、`HDR 自动`、`HDR10+`、`杜比视界 8.4`、`HDR10`、`HLG` | 显式 HDR 格式失败即结束，不静默发布 SDR |
| SDR 映射 | 稳定 / 动态 | 仅「保留高光层次」下出现；两者共用固定的 `0～1.0` 基础段 |
| 视频位深 | 自动 / 严格 10-bit / 严格 8-bit | 仅 SDR 下出现；HDR 一律 10-bit |
| HLG 信号范围 | 自动增强 / 名义范围 | 仅显式 HLG 与杜比视界 8.4 下出现（后者叫「HLG 基层信号范围」） |
| PQ 漫反射白 | 标准 203 尼特 / 自定义 200～800 | 与导出设备无关的创作基准 |
| HDR10+ 参考显示峰值 | 300～10000 尼特，标准 1000 | 只改动态元数据，不改 PQ 像素 |
| 编码模式 | 恒定质量（默认）/ 目标码率 | 按当前格式、编码器族、位深和帧率精确置灰；不支持 VBR 时内部落 CBR 并如实显示 |
| 目标码率 | 自动（跟随实际输出推导）/ 拖动后为自定义 Mbps | 「恢复默认」回到自动态 |
| 编码工具 | 高复杂度（默认开）、复杂帧质量保护（默认开，仅 VBR）、B 帧（默认关） | 当前档位不适用时省略对应的 `MediaFormat` 键并在完成信息如实说明 |
| 编码器族 | 自动 / HEVC / AV1 / H.264 | 自动档建议顺序：硬件 HEVC → 硬件 AV1 → 硬件 AVC → 软件同序；编码器族或软硬件类型变化须确认 |

内部质量通路（无用户开关，全部按实际能力自动选择并在完成信息/诊断中如实报告）：

- **应用自有 P010** 优先于编码器 Surface：色度位置按码流声明匹配、相位正确的低通降采样、
  闭环亮度修正、64×64 蓝噪声码值域量化都握在应用手里；不可用时退同格式 Surface。
- **HDR10/HDR10+ 的静态元数据按产物实测**：编码前跑一遍全片确定性离线渲染得
  MaxCLL/MaxFALL，结果按完整渲染指纹缓存。
- **HDR10+ 场景统计**：预分析逐帧精确测量最终线性 BT.2020 合成，再把全部帧累计成一个
  连续场景；GLES 3.1 compute/SSBO 优先，退 GLES 3.0 RGBA8 精确回读。曲线横轴优先使用
  场景 V8、失效时回退场景 MaxSCL；整段只生成一份 ST 2094-40 ApplicationVersion 1 载荷
  与内容驱动 Profile B 曲线，并在每帧重复，避免接收端随星芒改变全局亮度（D177）。
- **AOSP 软件 AV1 HDR 恒定质量保护**：仅当 `c2.android.av1.encoder` 声明 QP bounds、
  且用户采用公开质量上限时，额外申请 QP 上限 8。该限制来自 1152×1472、60 fps、10-bit
  HDR 水体渐变的同规格实机 A/B 结果；不改变用户选择的 AV1 公开规格或编码模式（D181）。
- **HLG super-white**：真实 P010 编码—解码回环验证通过后，按颜色方向使用最高 109% 信号；
  验不出来就用名义范围，不回退 SDR。

运行时只允许在输出格式、编码器族、位深、软硬件类型、帧率与编码模式完全一致时自动切换具体编码器组件
或 P010／Surface 输入通路。任一公开规格字段变化都先显示完整失败规格、分类原因与建议规格；
前台由 Dialog 确认，后台由持续通知确认。帧率始终保持用户选择，不进入建议流程（D179）。

## 两个入口，一个引擎

- **录音对话框**：停止录音后，对号 FAB 右侧多一个「保存并导出视频」FAB。它先照常保存
  WAV，再立刻对这份 WAV 执行导出。
- **音频附件播放对话框**：进度条右侧一个「导出视频」图标按钮。

两处共用补全左、上画框的 Material Symbols `video_frame_save` 图标；播放对话框里的图标
使用当前记事的完整颜色或渐变。

GLES 不可用（`WaveVisualizerFableSolHost` 走了 Canvas 回退）时两个入口都不出现。

## 与 FableSol 主体的关系

导出复用 `FableSolGlRenderer` 的**全部场景渲染代码**，差异只有三处：谁调用 `render()`、
dt 从哪来、present 到哪个 surface。因此送进 GL 之前的一切必然等价，验收不需要逐像素比对。

需要改动 FableSol 主体的只有一处：**场景缓冲 / 窗口呈现 / 导出呈现三层解耦**。目前
`hdrContentEnabled` 与 `sceneLinear` 跟 EGL 窗口是否 HDR 绑死，导致"屏幕 SDR 但导出 HDR"
无法表达。见 decisions.md D5。

## 重力轨迹

录音时把 `TYPE_GRAVITY`（回退 `TYPE_ACCELEROMETER`）的读数按音频时间记下来，
50Hz × 三个分量 × float32 = **600 B/秒 = 36 KB/分钟**，写进 WAV 的自定义 RIFF chunk
（chunk id `EDmo`，放在 `data` chunk 之后）。传感器本来就跑在 `FableSolTiltSensor`
独立线程上，记录动作与渲染路径无关。

本功能之前的历史录音没有轨迹，按竖直渲染。设置里可以整体关掉重放（默认保留），关掉后与
"没有轨迹"走同一条路径；只有本应用录制的音频带得动这份轨迹，所以它只对实时录音有意义（D44）。
