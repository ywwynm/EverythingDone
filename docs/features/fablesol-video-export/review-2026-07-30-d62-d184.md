### P02【D114/D115/D177】膝点斜率门禁在 kneeX < 1/256 时假阳性，S/T ∈（约 9.72，9.978]的可行组合必然导出失败

- 位置：`app/src/main/java/com/ywwynm/everythingdone/views/recording/fablesol/FableSolExportHdr10PlusCurve.kt:465-477`（`gateFailure` 膝点检查）
- 机制：膝点检查用固定步长 `h = 1/GATE_SAMPLES = 1/256` 做有限差分。当场景 V8 与参考峰值之比
  `S/T` 接近 10 时，可行上限把膝点压到 `kx = (10T−S)/(9S) < h`，`evaluate(max(kx−h, 0))`
  跨过原点，`below = Ky/h` 严重低估真实线性段斜率 `Ky/kx`，相对差按 `h/kx − 1` 放大。
  五档 `BLEND_STEPS` 共用同一膝点，包括注释声明"必定可行"的纯解析形状在内全部被误杀，
  `shapeForScene` 抛出误导性的英文 "Knee slope discontinuity"。
- 数值验证（模拟复现代码逐行复刻 Kotlin）：`unsupportedReason` 允许 S/T ≤ 10·4095/4104 ≈ 9.978；
  S/T = 9.70 门禁通过，9.75 起失败（relative 0.344），9.9 时 0.287·h 的 kx 给出 relative 2.383，
  9.978 时 14.68。T 取 300～4000 尼特结论相同。
- 触发条件：场景 V8 落在参考峰值的 9.72～9.978 倍，例如漫反射白 350 尼特 × 强度 9.6
  （理论峰值 3360，场景 V8 可达约 2900+）配参考峰值 300 尼特档。
- 后果：`unsupportedReason`（设置页与预检共用）判可行，正式导出必然失败；显式 HDR10+ 直接
  终止，自动档浪费一次全片预分析后换档。
- 修复方向：膝点两侧差分的分母改用实际采样跨度（below 用 `min(h, kx)`），或直接用解析斜率
  `Ky/kx` 与 `B'(0)` 比较。
- **已修复（2026-07-30，方案 B）**：膝点两侧改为量化后载荷值的闭式斜率比较（`Ky/Kx` vs
  `10·P1·(1−Ky)/(1−Kx)`），容差 = 基础 0.12 + 量化步长传播上界（Kx/Ky 各半档 1/4095、P1 半档
  1/1023 的一阶和；P1 分母下界 1/10 防止清零蒙混）。364 个 (S/T, T, 膝点位置) 组合扫描零假
  阳性（最坏用到容差 43%），P1 截断 20% 的坏曲线仍被抓住；新增回归测试
  `aFeasibleCombinationNearTheTenfoldLimitStillYieldsACurve`（S/T = 9.9，旧门禁必杀区）。

### P07【D157 第 6 条、D162 第 5 条】蓝噪声上传失败时回退门失效：以 1×1 占位纹理当 64×64 表做越界 texelFetch

  必须同步改该断言。

- **已修复（2026-07-30）**：两处改为 `blueNoiseTextureId = upload()?.takeIf { it != 0 }`、

## 四、待裁定 / 待确认（非缺陷，需产品或真机证据定论）

1. **回环验证瞬时失败永久缓存**：临时文件创建失败、6 秒超时等一次性异常以 `encode-failed`
   永久锁死该签名为名义范围（直到系统指纹变化）。D139 把解码侧失败定为可缓存结论，D138 对
   "受控异常或超时"的措辞是"**本次**继续使用名义范围"——两个方向都有依据。
   **已裁定（2026-07-30，随 P04）**：瞬时失败不写持久缓存，只缓存确定性结论。
2. **D167 正式导出侧无形态阶梯**：`resolveRateControlForm` 缓存缺失/编码器名不匹配时回退纯 CQ
   一次性下发，configure 失败即淘汰候选（代码注释声明有意）。与 P10 冷进程放行叠加时，华为
   OMX 类设备的 CQ 候选会整批淘汰——正是 D167 要避免的方向。
   **已裁定（2026-07-30，D186）**：对"无探测结论回退的纯 CQ"开放一级运行时阶梯（同候选改
   CQ+码率提示零进度重试一次）；缓存有结论时不启用；不回写矩阵。
3. **HDR10+ SEI 门禁语义**："任一视频样本含 SEI 即通过"（命中即停止扫描）vs D91 第 4 条
   "逐帧 SEI 的现有硬门禁保持不变"的原始语义，需早期批次佐证。输入侧确实每帧 `setParameters`。
   **已裁定（2026-07-30）**：佐证查实——门禁引入（07-27，`55a2452f`）即任一样本形态，D91
   （07-28）"现有门禁"指认的就是它，字面歧义消解。按 A 落地：门禁维持"确实携带"；取消命中
   即停改逐样本计数，覆盖率进诊断；部分覆盖在完成信息如实说明（新字符串 ×13）；D91 第 4 条
   措辞已修订。
4. **hdr_stats.frag pack16 舍入 vs MaxCLL ceil 上界**：块峰值经 round-to-nearest 量化可下移
   至多半个 16-bit 台阶（约 0.015 尼特），真值恰高于整数尼特 0.015 以内时 ceil 的上界性质
   毫厘级失守。HDR10+ 路径无此问题。
   **已裁定（2026-07-30，按 B）**：`pack16` 改上取整（两个通道一并），量化方向与上界语义
   同侧；最多高报一个台阶（约 0.03 尼特），上界语义下无害。无测试钉扎与 CPU 复算牵连，
   解码侧不变。
5. **探测基线不含用户 B 帧设置**：探测固定 B 帧关，用户开启后正式 MediaFormat 比短探测多一个
   `KEY_MAX_B_FRAMES=1`。该键为上限提示、拒绝概率低，是否纳入探测配置需裁定。
   **已裁定（2026-07-30，维持现状）**：基线固定关；分歧由 P20 的运行时 B 帧退让自愈（同候选
   0 B 帧重试，回到探测已证明的形态）。纳入探测会让矩阵结论随用户开关漂移或升为第七维，
   成本收益不成比例。D148 已补充说明。
6. **HLG 闭环在 super-white 域退化为保留原 Y′**：p010_luma.frag 的 toLinear 夹到 [0,1]，
   与 export_present.frag 不钳上界的 hlgOetfChannel 口径不一致；方向安全（保留原值），是否
   有意将闭环限制在名义域待确认。
   **已裁定（2026-07-30，确认为有意限制）**：闭环修的是名义域内色度量化的亮度误差，扩展域
   延展无可感知收益；shader 与 Kotlin `toLinear` 两侧补注释固化意图（域限制、退化行为、
   与呈现侧口径差异的缘由、不得单侧放开）。零行为变化。
7. **AV1 色度位置只解析 av1C**（0x81 门禁）：若编码器 csd-0 给裸序列头 OBU，显式 CSP_COLOCATED
   会被当"未声明"落 Type 0（兜底语义正确但损失信息）；Android AV1 编码器 csd-0 实际形态待查。
   **已裁定（2026-07-30，维持现状）**：Android MediaCodec 文档把 video/av01 的 csd-0 规定为
   AV1CodecConfigurationRecord，av1C-only 与契约一致；裸 OBU 属假设形态（实测过的 AOSP 软件
   AV1 走 av1C）。若真机日后出现（矩阵行"未声明"+ ffprobe 可查），拿具体码流再建 OBU 解析；
   完整序列头位解析（百行级、错一字段即读偏）不为假设预建。
8. **`chooseFromAdvertised` 在单条目 profileLevels 设备上的退化**：若编码器只广告最高 Level，
