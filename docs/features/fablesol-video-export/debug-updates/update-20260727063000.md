# 视频导出：四种 HDR 格式随你选，杜比视界翻案

## 现在可以自己挑 HDR 格式，且只列出真编得出来的

设置里的「HDR 格式」不再只有自动 / HDR10 / HLG，而是把这台机器**实际能编出来的**格式
全部摆出来，最多四种：HDR10、HDR10+、HLG、杜比视界。选中哪个，下面就写清楚它是什么、
跟别的差在哪；选「自动」时会直接告诉你本机会落到哪一种。

「能编出来」是真去编的：每一种格式都单独走一遍完整的编码加封装，编不出一帧就不出现在
界面上。设备广告说支持、真配置时却悄悄降级成别的，这种事是存在的——那样界面上就会摆着
一个选了也不生效的选项，比不给这个选项更糟。

顺带说明为什么是四种而不是五种：**PQ 和 HDR10 是同一件事的两种说法**（HDR10 就是 PQ 曲线
加 BT.2020 加静态元数据），并列出来只会让人以为是两个不同的东西。

四种的实际区别：

- **HDR10**——绝对亮度曲线，上限 10000 尼特。我们的峰值是算得出来的，最亮的一段完全不用
  压。播放端支持最广，所以是自动档的首选。
- **HDR10+**——在 HDR10 之上加逐场景的动态元数据。这里要说实话：我们的画面是直接送进
  编码器的，而这种模式下**动态元数据只能由设备自己生成**，我们既设不了也验不了。所以它
  排在 HDR10 后面——拿一个验证不了的东西去换一个已经准确的东西，不叫升级。
- **HLG**——相对亮度曲线，在不支持 HDR 的播放端上被压成普通画面时更温和。代价是普通白
  之上只有约 3.77 倍余量，HDR 强度调过 4 之后就基本看不出区别了。
- **杜比视界**——见下。

### 杜比视界：之前说"做不了"是我判断错了

上一轮我给的结论是杜比视界需要逐帧的动态映射元数据、没有公开接口所以做不了。这个结论
**没有查证就下了，是错的**。

Dolby 自己给第三方开发者的示例程序用的就是标准的系统编码接口，而且和我们一样是把画面
直接送进编码器；应用**根本不需要自己产生那份元数据**，编码器会自己生成。你那台 OPPO 上
枚举到的编码器 profile 值，正好就是示例里用的那一档。

所以杜比视界现在真的做了，用 profile 8.4。但有一点必须讲清楚，免得期待落空：**8.4 的
底层画面就是 HLG**，所以它的高光余量和 HLG 一样，并不比 HDR10 大。它的长处在动态元数据
带来的更好色调映射，不在能画多亮。

另外删掉了上一版那行「DV 封装」——它没有任何证据价值：三星那台连杜比视界编码器都没有，
照样回答"接受"。现在杜比视界和其余格式一样走真实编码探测，那才作数。

### 请这样验

两台机器各开一次设置，看「HDR 格式」下面列出了哪几个（OPPO 预计能看到杜比视界）。然后
**各种格式都导一段出来**，看相册和播放器怎么认。杜比视界那段尤其值得看：能不能被识别成
杜比视界，还是只当作普通 HLG，这一步我在代码里验证不了。
