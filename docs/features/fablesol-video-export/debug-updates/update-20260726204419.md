# 视频导出：完整链路可靠性修复

## 这次不再逐个补洞，把一次导出重新定义成完整事务

视频只有在音轨、画面和 MP4 索引都写完，`MediaMuxer.stop()` 与 `release()` 成功后，才会
提交到相册。此前“界面报成功但文件仍没写完甚至损坏”的窗口已经关闭；发布失败也不会再重复
渲染整段视频。

每个 HDR/SDR 编码候选现在都会从音频、编码器、图形上下文和渲染器完整重建。创建、首帧交换、
实际输出格式、添加音视频轨、后续编码或封装任何一步失败，都会删掉本档半成品，再尝试下一档。
系统若把 Main10/HDR 静默换成 8-bit、丢掉色彩标记，或者 FP16 场景回退成 RGBA8，也不会再
谎报 HDR 成功。编码尺寸会按具体硬件要求补齐，且只扩大外围画框，不改变水体构图。

Android 8/9 现在会在导出前申请写入公共影片目录的权限，不再把应用专属目录当作相册。输出
文件先原子占位，连续点击不会覆盖或误删前一份；媒体扫描回调确认入库后才显示成功。

后台任务队列改为按任务编号管理。排队任务可以只取消自己，旋转屏幕不会丢自己的状态；旧任务
收尾不能再撤掉新任务的前台通知。系统时限到达时会立即把当前及排队任务标成超时失败，工作线程
稍后返回的旧进度或“已取消”不能覆盖它。

恒定质量模式不再拿不可信的提示码率拦截导出，改为开始前保留实际空间并在编码中滚动复查；
恒定码率估算补入 AAC 音轨。完成对话框只展示真正可执行的分享或添加附件动作。

新增任务状态、编码尺寸与封装事务三组回归测试；全量单测和 debug APK 构建通过。未使用 adb。
