
# 进度条渐变、掉饱和的成因、以及「高光起点」

## 进度条：确实偷懒了

之前用的是 `accent.color` 去给进度条着色——那只是渐变的**起点单色**。所以换色时看不出渐变
方向，跟同一个对话框里其它强调色元素也对不上。现在改用和调参滑杆**完全同一套**轨道绘制，
不再有两份着色逻辑。

不定长那一档（还在准备、进度未知时）仍然只能是单色：平台的不定长动画是另一个图形对象，
只接受一个颜色，塞不进渐变。

## 深红变粉红：机制说清楚，并且给了控制手段

这不是渲染画错了。我们画出来的颜色比例是准确的，问题出在**下游的压缩**。

任何"逐通道各压各的"压缩都会掉饱和：一块深红的红通道最大，压得最狠，绿蓝几乎不动，
三者的比例于是被拉近——**颜色就朝白色走**，深红先变正红，再变粉红。

而压得有多狠，取决于画面峰值超出屏幕能力多少。关键在于：

> **峰值 = 漫反射白 × HDR 强度**

你把漫反射白从 203 推到 800（约 3.9 倍），强度还留在 9.6，峰值就从 1949 尼特涨到 7680。
屏幕只有 2000 尼特，等于要硬压掉近四倍——掉饱和就是这么来的。

所以底部那行推导结果现在**把峰值直接写出来**。两根滑杆各调各的，很容易在不知不觉间把乘积
推到屏幕根本装不下的量级，而那个乘积才是真正决定画面会不会发白的数。想要背景亮又不掉饱和，
就得把 HDR 强度往回收一些——这两个数是乘在一起的，不可能同时都要。

## 「高光起点」

「膝点」确实是黑话，换成**「高光起点」**：这条界线以下是主体，原样保留；以上才算高光，
才会被压缩。

现在它可调，范围 50% 到 99%，默认 90%。含义是"画面里最亮的百分之多少算高光"：

- **调高**（比如 95%）——更多画面被当作主体保护起来，压缩来得更晚。深红这类饱和色更不容易
  被压到掉色，代价是留给高光层次的空间变窄。
- **调低**（比如 75%）——更早开始压缩，银丝星芒之间的层次留得更足，但更多水体会进入被压
  的区间。

它只在选了 HDR10+ 时出现——只有这个格式带色调映射曲线，别的格式调它没有任何作用，摆出来
只会误导。

底部那行现在会完整写出：格式 · 漫反射白 · 峰值 · 高光起点。

## 建议怎么调

先把高光起点推到 95% 看深红有没有回来。如果还不够，那就是峰值超得太多，把 HDR 强度往下收
——比如漫反射白 800 配强度 3，峰值 2400，和你屏幕的 2000 就在一个量级上了。
