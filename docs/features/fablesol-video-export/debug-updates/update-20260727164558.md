# FableSol HDR 格式顺序、本地化与能力信息专业化

## FableSol HDR 格式与能力信息

用户在复核自动漫反射白和 HDR 格式信息后提出以下修正：

- 自动漫反射白公式必须使用标准 `min(...)` 语法，并显示本机可用的 HDR 峰值、最大帧平均
  亮度、原始约束结果和最终量化结果。
- “自动”并非兼容性优先；格式顺序应为
  `杜比视界 5 → 杜比视界 8.1 → HDR10+ → 杜比视界 8.4 → HDR10 → HLG`。
- 中文 locale 的所有用户可见位置必须使用“杜比视界”，不能显示 `Dolby Vision`。
- 杜比视界和其他 HDR 能力判定需要全面改为专业、严谨、正式的技术描述，移除口语化、
  拟人化和结论边界不清的表达。

### 实现

- `FableSolExportHdrFormat.AUTO_ORDER` 已按用户指定顺序调整；“自动”说明改为按 HDR 规格与
  画质能力顺序选择本机通过实际编码验证的首个格式。
- 格式名称拆分为两层：
  - 固定英文 `stableLabel` 供能力缓存、编码档位和内部关联使用；
  - `displayNameRes` 供设置胶囊、自动格式说明、能力报告、导出完成 Dialog、通知和失败信息
    使用。简体与繁体中文均显示“杜比视界 5 / 8.1 / 8.4”。
- HDR 能力报告改为结构化验证结论：
  - 明确列出通过完整单帧编码与封装验证的格式和自动选择结果；
  - 编码器改写传递函数或 Profile 时，列出请求值、实际值和“目标格式验证未通过”；
  - 杜比视界各 Profile 明确为独立候选，仅陈述对应基层、请求参数和验证结果；
  - HDR10+ 分别报告“未提交动态元数据”和“提交 ST 2094-40 元数据”的结果，并以输出码流
    是否检测到 HDR10+ ST 2094-40 SEI 为判据；
  - 显示设备、EGL 和编码器摘要统一使用“支持 / 不支持 / 未发现 / 未声明”等状态。
- 重写 HDR10、HDR10+、HLG、杜比视界 8.1 / 8.4 的格式说明，移除“无需压缩”
  “最高的一档”等不严谨或与实际顺序冲突的描述。
- 自动漫反射白信息改为：
  - 显示“可用峰值”和“可用最大帧平均亮度”；
  - 使用 `min(a, b, c)` 的半角括号和英文逗号；
  - 分开显示 `min(...)` 原始结果、200–400 尼特约束、25 尼特向下量化和最终值；
  - 手动值明确说明不执行自动推导。
- HDR 探测契约版本升至 5，使旧缓存中的口语化诊断失效并重新验证。
