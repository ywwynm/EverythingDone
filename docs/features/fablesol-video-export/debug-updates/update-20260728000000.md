# OPPO 也能编 HDR10+：你截图的最后一行已经证明了

## 那张截图是修复前的版本

你发的 OPPO 截图里 HDR10+ 的失败原因是「编码器接受了配置却把 profile 降了回去」——**那正是
我上一条消息里刚修掉的 bug**（我自己的校验不认编码器回报的 Main10）。截图上的版本还没带这个
修复，所以它仍然被挡在门外。

而同一张截图的**最后一行**已经把答案给出来了：

> HDR10+ 字节缓冲：P010 有 · 裸通路 码流里没有 HDR10+ SEI · **带元数据 码流带 HDR10+ SEI**

那一行走的是独立探测，不经过我那道坏掉的校验，所以它说的是设备的真话：**OPPO 这台同样能编
HDR10+。** 装上带修复的版本再开一次设置，HDR10+ 应该会进「实测通过」那一行，而且因为它排在
HDR10 前面，自动档会直接选它。

## 杜比视界 8.1：查到头了，这台机器做不到

失败原因是编码器把基层的亮度曲线从 PQ 改回了 HLG。这不是配置写错——**它这一档只出 HLG 基层，
也就是只出 8.4**。三条证据互相印证：

1. 设备只广告 profile 8 这一种；
2. 我们明确要求 PQ，它明确改回 HLG；
3. **Dolby 官方给第三方的示例程序，发行说明里写的就是"编码与转码到 Dolby Vision 8.4"**——
   8.1 和 profile 5 一个字都没提。也就是说这不只是这台机器的限制，是 Android 上这条路本来
   就只通到 8.4。

我不想就这么下结论，所以这一版加了一件事：**直接问这颗编码器它自己有哪些私有参数**。系统从
Android 12 起提供了这个接口。厂商文档我抓不到（Qualcomm 那个文档站是动态渲染的），与其照着
猜参数名，不如让设备把自己的旋钮列出来——有跟杜比视界或色彩相关的，我就去试；一个都没有，
那就是真的没有别的办法。诊断里会多一行「DV 厂商参数」。

顺带把这类失败的措辞改成人话：以前直接甩一句异常，现在会说明白"编码器把基层曲线改回去了，
说明它这一档只出另一种曲线"。

## 请这样验

两台都开一次设置：

- **三星 / OPPO**：「实测通过」里有没有 HDR10+，自动档是不是变成了 HDR10+；
- **OPPO**：新增的「DV 厂商参数」那一行写了什么——**这行是 8.1 还有没有指望的唯一线索**，
  麻烦发我。

HDR10+ 通了的话，**用它导一段看颜色**。这条路上 RGB→YUV 是我们自己算的，错了会直接表现为
颜色不对或画面上下颠倒，很显眼，但我只能靠你看。
