# 800 尼特下背景发青：曲线被我写退化了

## 先回答亮度读数

我读的是系统给出的「屏幕希望内容达到的最大亮度」。它和厂商宣传的 3600 尼特不是同一个数：
宣传值通常是**极小面积（百分之一二的画面）下瞬时能冲到的峰值**，实验室条件、也撑不了多久；
系统报的 2000 更接近这块屏幕**持续给内容用**的峰值。两个都不算错，量的不是一回事。

顺带说一句，这个接口在新版系统里已经被标记为"厂商填的值不可靠"，所以我本来就自己夹了一道
合理区间。你要是觉得 2000 偏保守，直接把滑杆往上推就是。

## 青蓝色：是我的曲线在高白点下退化了

这个现象很可能不是设备的锅，是我上一版曲线的一个缺陷，而且**恰好只在你把漫反射白拉高之后
才出现**——这正好对上。

曲线的肩部由一个控制点决定，它是按"膝点两侧斜率必须接上"解出来的。这个解有个上限，超过
上限只能夹死。之前我把曲线的目标显示峰值**写死成 1000 尼特**。当你把漫反射白拉到 800，
高光峰值就去到 7680——要把 800 到 7680 这一大段压进 800 到 1000 这一小段，解出来的控制点
远远超过 1，于是被夹死。

夹死的后果是**肩部退化成一道断崖**：膝点以上的所有亮度被压成几乎同一个值。这时红、绿、蓝
三个通道会在各自不同的亮度处先后撞上这道崖，播放端逐通道处理时，颜色就跑偏了——星芒最亮
的地方通常偏暖（红先撞顶），红被压掉之后剩下的绿蓝就显出**青蓝色**。而它"有时候有有时候
没有"，是因为要画面里真的出现足够亮的高光才会撞到那道崖。

两处都改了：

- **目标显示峰值不再写死**，改成取屏幕自己声明的峰值（你那台是 2000），并保证至少是漫反射
  白的两倍。800 的白点配 2000 的目标，控制点解出来是 0.57，稳稳在合法范围内。
- **膝点加了上限**，直接由"控制点不许超过 1"这个条件解出来。哪怕目标峰值再低，膝点也会自动
  退到曲线不至于退化的位置。

加了一条覆盖整根滑杆（200 到 800）× 四档强度的单测，任何组合下肩部都不许退化成平顶。

## 请这样验

把漫反射白仍然放在 800，重新导一段有明显星芒的，看背景还会不会发青。**如果还会**，那说明
不是这个原因，请把当时的漫反射白、HDR 强度和播放器告诉我，我换个方向查。
