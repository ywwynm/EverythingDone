# 视频导出画质整体重做：八个批次全部落地

## 本次更新

这一版把 FableSol 音频海浪动画的视频导出**从像素通路到元数据整体重做了一遍**，对应八个批次、
117 条设计决定。设置界面、内部渲染与编码通路、写进文件的色彩元数据三者都变了。以下按
「你能看到的」「你看不到但影响画质的」「代价」「已修的问题」四部分说明。

**一、设置界面能看到的变化**

- **导出色彩模式改为七档，顺序改为 HDR 在前**：自动 → HDR10+ → 杜比视界 8.4 → HDR10 →
  HLG → SDR（原生渲染）→ SDR（保留高光层次）。此前两个 SDR 排在最前，等于让人先读完两个
  降级选项才看到默认值。**显式选定某个 HDR 格式后失败即结束，不会静默发布一个 SDR 文件**；
  只有「自动」允许跨格式并最终回到原生 SDR。
- **SDR 分成两种成片语义**。「原生渲染」是按 SDR 重新渲染一遍，不是 HDR 的降级产物；
  「保留高光层次」把动画的 HDR 超白高光降映射进 SDR，另有稳定 / 动态两种映射方式（默认稳定，
  以 BT.2446 Method B 为标定依据）。三者的文件名互相区分。
- **视频位深**（仅 SDR 下出现）：自动 / 严格 10-bit / 严格 8-bit。8-bit 使用 64×64 静态蓝噪声
  阈值抖动，不再是硬截断。
- **HLG（基层）信号范围**：自动增强 / 名义范围。自动增强会先跑一次**真实的 P010 编码—解码
  回环验证**，确认设备真的能保住超白信号才用；验不出来就退名义范围 HLG，**不会因此退到 SDR**。
- **PQ 漫反射白默认改为标准 203 尼特**，语义改为「标准 / 自定义 200～800」。此前它按导出设备
  的屏幕能力推导——但母版亮度意图是创作参数，与你用哪台机器导出无关。
- **HDR10+ 参考显示峰值**滑杆 300～10000 尼特，标准值 1000。原先写作「本机（2000）」的胶囊
  改为「本机屏幕峰值（2000 尼特）」，补上单位并说清这个数测的是什么。
- **编码画质选项成组**：编码模式（恒定质量，默认 / 目标码率）、目标码率（默认自动，按实际输出
  推导）、高复杂度编码（默认开）、复杂帧质量保护（默认开，仅目标码率下有效）、启用 B 帧编码
  （默认关）、关键帧间隔（0.5～10 秒，默认 2 秒）、编码器族（自动 / HEVC / AV1 / H.264）。
  当前档位用不上某个键时直接不下发，并在完成信息里如实说明。
- **说明文字重排**：每个选项的说明改为紧跟在它自己下面并**常显**，不再统一堆在最底部那段信息
  栏里——改的是这一行、要读的却在几屏之下，等于没写。底部信息栏现在只回答「我得到了什么」：
  体积估算、实际帧率、实际格式与编码器、漫反射白与峰值、参考显示峰值、高光起点，随后是推导
  过程与设备能力报告。关键帧间隔与高光起点此前在任何地方都没有解释，这次补齐（13 套语言）。

**二、看不见但直接决定画质的**

- **应用自有 P010 成为所有 10-bit 导出的首选输入通路**，优先于把画面直送编码器表面：FP16
  高精度中间面、相位正确的色度降采样且色度位置与码流声明一致、闭环亮度修正、量化到最终码值
  时用蓝噪声无偏舍入——这几件事全部握在应用手里，不再听凭驱动。不可用时才退回同格式表面。
- **HDR10 / HDR10+ 的 MaxCLL 与 MaxFALL 改为实测**：编码前先跑一遍全片确定性离线渲染统计
  最终线性 BT.2020 的逐像素峰值与帧平均，结果按完整渲染指纹缓存，同素材同设置只算一次。
- **HDR10+ 改为整段连续动画按一个场景统计**，只生成一份 ST 2094-40 载荷并在每帧重复；曲线
  横轴优先用场景 V8、失效时回退场景 MaxSCL；肩部曲线由完整亮度分布驱动而非固定缓动。
- **HLG 整条重做**：固定以 75% 信号表示参考白，执行标准逆 OOTF，再逐像素按颜色方向计算可用
  信号色容积并拟合端点一致的肩部——不再用最不利颜色的全局肩部一刀切。杜比视界 8.4 复用
  同一套超白机制。

**三、代价：导出时间变长两到五倍**

上述画质通路是有单价的：全片预分析约 21 ms/帧、HDR10+ 逐帧统计约 20 ms/帧、应用自有 P010
相对直送表面约 27 ms/帧，P010 通路峰值内存高约 95 MB。同一段素材，8-bit 表面通路 12.1 秒
导完，HDR10+ 首次约 68 秒。这是本次最需要你实际体感确认的一点。

**四、修掉的一个明显问题**

你此前反馈的 **HDR10+ 产物亮度频繁往复变化、星芒出现时水体变暗**已定位并修复。像素层其实
完全稳定，问题全部出在动态元数据：旧实现把 120 fps 的每一帧都当成一个新场景来统计，而
ST 2094-40 里这些量本就是**场景量**，播放端可以不看曲线直接拿它们做全局亮度调整——于是星芒
一闪，整幅画面的亮度就被改写一次。现已按上面说的场景统计口径重做。

**请确认以下几项**（本轮全量 526 例单元测试通过、`assembleDebug` 通过，但未安装到设备，
也没有生成新样片）：

- OPPO 上各导出一段 203 尼特与 350 尼特的 HDR10+，确认星芒出现时水体不再变暗；
- 设置页的七档色彩模式、各选项紧随其下的说明行、底部信息栏的推导结论；
- HLG 与杜比视界 8.4 的信号范围两档，以及自动增强验不过时是否如实退到名义范围；
- 三星上 SDR 的三种成片语义与三种位深；
- 编码模式 / B 帧 / 高复杂度 / 复杂帧质量保护在你的设备上是否真的可选（我的测试机没有恒定
  质量区间，这一组只验到了目标码率一侧）；
- 产物在系统相册里的格式标识、普通播放观感，以及分享到平台二次转码后的结果。
