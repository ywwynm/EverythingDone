# 导出期间冻结实时水体（冻结不再改不透明度）

## 2026-07-30 - 冻结时水体保持原样直接停住，不再淡到背景档

紧接上一版（202607300946）的修正：冻结时把水体淡到背景不透明度是不对的。水体是播放对话框
的内容本身，淡下去会被读成"内容没了"——退居背景那套语言属于录音对话框录完之后的空转态。
现在冻结不碰不透明度，水面保持原样直接停住，也不必再等那 360ms 淡出，冻结提前生效，这一段
的编码资源也省下来了。

以下是这项能力的完整说明（上一版起生效）。

**导出进度对话框在前台时**

- 水体完全停止渲染：不再逐帧计算水面、不再绘制、不再向系统申请高刷新率。不是"画面静止但
  照样渲染"，是连帧都不出了。导出与水体跑在同一个进程里，而实时渲染线程在 CPU 调度上的
  优先级高于导出工作线程，不让路就是一直压着编码。
- 音频播放暂停。关掉对话框后不会自动续播，何时接着听由你按播放键决定，与"对话框看不见
  就暂停"是同一个约定。
- 倾斜传感器注销；屏幕方向锁保持不变（解锁再转屏会让恢复后的倾斜方向算错）。
- 播放对话框不再在你盯着进度条的时候自动把剩下的音频附件一条条放完。

**解冻时机**：进度对话框消失即恢复，包括点「在后台运行」。不看导出跑到哪一步——完成态与
等待确认态继续冻着是有意的，那时水面被对话框盖住，冻着反而省电。自动重试与「使用建议
规格重试」期间对话框一直在，不会出现解冻又冻上的闪烁。

**已覆盖的边界**

- 冻结期间切到桌面再切回来：水体不会变成空白，也不会偷偷恢复动画或重新注册传感器。
- 折叠屏展开、暗色模式切换、关闭实时倾斜后旋转屏幕等重建场景：解冻信号不会丢失，不会
  留下一潭解不开的死水。

**顺带修复**：应用进程被系统杀掉后重新进入详情页时，恢复出来的导出进度对话框此前会永远
转圈（服务与任务其实早已不存在）。现在直接显示「导出已中断」并给出确认按钮。

**请确认**：点导出后水面停住这一下的观感；以及同一段录音在这一版与冻结之前那一版下的导出
耗时差异（建议交替各跑两轮取中位数，连续满载会热降频，单轮对比不作数）。
