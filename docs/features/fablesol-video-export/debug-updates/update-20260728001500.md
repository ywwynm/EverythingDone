# FableSol 视频导出：修正探测链路，补齐失败原因

## 2026-07-28 8-bit 档按 8-bit 链路验证；诊断补齐被淘汰组合与尺寸帧率答复

三星 Z Fold4 上编码器清单里有四个高通 HEVC 与若干 H.264，实测却一个都不可选，连 SDR 都落到
了软件 AV1。本次先把两处**探测自身**的问题修掉，并把此前被丢弃的判断依据全部显示出来。

**8-bit 档此前被拿 10-bit 输入表面验证。** 能力探测创建输入表面时把位深写死为 10-bit，而正式
导出对 H.264 与 HEVC Main 这类 8-bit 档给的是 8-bit 表面。验证的与实际使用的不是同一条链路，
结论也就不作数。现在跟随档位。

**编码器报错不再只剩一个异常名。** `MediaCodec.CodecException` 继承自
`IllegalStateException`，其消息经常为空，诊断里因此只有一句 `IllegalStateException:`。现在
一并显示厂商诊断串、错误码，以及该错误是否为瞬时错误、是否可恢复。

**瞬时错误改为重试一次。** 一次完整探测会连续创建并释放数十个编码器实例，而硬件编码器实例
数量有限且释放并非立即生效。平台以 `isTransient` 明确标出"只是当时被占用"，此前一律记成不
支持。

**诊断补齐两类此前看不到的信息。** 其一是被淘汰的编码器组合及原因：此前只有整种格式都编不出
来时才保留原因，HDR10 靠软件 AV1 通过之后，四个高通 HEVC 的报错被整批丢弃，SDR 一列更是完全
没有报告。其二是每个编码器对本次画布的尺寸与帧率答复，用于区分"被这道筛拦下"与"编码器自己
拒绝"这两种表现完全相同的情形。

能力探测契约版本升至 7，旧缓存作废并重新验证。
