# HDR10+ 补上了色调映射曲线

## 你在杜比视界上看到的那个效果，现在 HDR10+ 也有了

之前我们只把亮度统计交给播放端，没有给曲线，所以拿不到"高光出现时压暗背景来衬托"的适配。
现在补上了，而且这条曲线是**从每一帧的实测数据算出来的**，不是编的。

它的形状很直白：**膝点以下原样保留，膝点以上才压缩**。水体本身是主体，银丝与星芒是点缀；
真要压，压点缀。膝点放在这一帧实测的高分位处——也就是水体主体的顶部；整帧本来就装得进目标
显示时，膝点直接放到峰值，等于完全不压。

两个容易出错、我特意处理了的地方：

**膝点两侧的斜率必须接上。** 接不上会在水体与高光的交界处留下一道折痕。曲线的第一个控制点
正是为此解出来的。

**膝点必须随时间平滑，而且要"快起慢落"。** 逐帧算出来的分位点是会抖的，膝点跟着抖，背景亮度
就会一跳一跳地"呼吸"。所以高光涌上来时迅速让出空间（慢了会削顶），高光退去后缓慢回升
（快了背景会闪）。统计量本身仍是逐帧实测值，不做平滑——平滑的只是"我们想怎么映射"这个意图。

曲线单调、端点正确、膝点斜率连续、快起慢落，这四件事都加了单测钉住。写错一位的后果是播放端
色调映射离谱，而那在设备上极难反查，只能在这一层守住。

## 顺带

之前那个独立探测里自带了一份元数据写入器，现在删掉了，统一用正式通路那一份。两份实现迟早
会漂移，而这东西错一位后面所有字段全部错位。

## 请这样验

用 HDR10+ 导一段**有明显银丝、星芒的**片段，和之前那版（没有曲线的）对比着看。

要看的是**高光的形状**：没有曲线时，超出屏幕能力的那部分会被播放端一刀切平，星芒变成一团
死白；有曲线之后它是被平滑地卷进去的，芒尖的层次还在。**水体本身的亮度不应该有任何变化**
——这条曲线明确不动膝点以下的东西。

（更正：本文件初版写的"高光一来背景稍微让开"是错的。那描述的是杜比视界的做法，不是这条
曲线的做法。这条曲线只压高光，不动背景。）

另外还是那句：这条路上 RGB→YUV 是我们自己算的，颜色不对或画面上下颠倒会很显眼，麻烦一并看。
