# 视频导出：第二轮评审后的修复

## 又修掉八处问题

**120fps 的每一帧并没有正好推进一步。** 帧时间用整数纳秒表示，而物理步长是精确的
1/120 秒，两者差着不到一纳秒——累加起来就变成"这一帧原地不动、下一帧跳两步"的循环。
平均速度是对的，但画面会有极细微的顿挫。现在直接把精确步长交给模拟，120fps 每帧一步、
60fps 每帧两步，严格成立。

**导出开头比录音时更平。** 分析链里有一道防麦克风冷启动杂音的门。录音时这道门早在你打开
对话框的那一刻就已经放行了，所以录进 WAV 的头几秒在屏幕上是正常起伏的；但导出时它又从头
拦了一遍，产物开头因此比你当时看到的更平。读文件本来就没有麦克风冷启动这回事，现在导出
不再走这道门。

**连续导出仍可能出乱子。** 上一版只堵住了"取任务"那个瞬间，没堵住"收尾"那个瞬间：如果新
任务恰好在旧任务收尾途中提交，旧任务会把新任务的唤醒锁释放掉、把新任务的线程关掉、还可能
直接停掉整个服务。现在收尾前会确认自己仍然是当班的那个。取消也改成只作用于正在跑的那一个，
不会误伤刚提交的下一个。

**降级过程中可能耗尽编码器。** 尝试某一档失败时，已经建好的编码器没有被释放；连试几档就可能
把系统的硬件编码器实例占满。另外正常结束时也漏掉了一个绘图表面的释放。都补上了。

**HDR 判定还不够严。** 之前只看编码器支持 10-bit，但那不代表它能接受 HDR 输入；新系统上有
专门的能力标志，现在会查。另外 AV1 档位在旧系统上会被选中却在封装时失败——旧系统的封装器
根本不支持把 AV1 放进 MP4，现在只在支持的系统上才考虑它。编码器启动失败也纳入了降级重试。

**收尾出错会让进度卡死。** 让产物对相册可见这一步如果失败，会顶掉本该返回的成功结果，
进度对话框就永远停在"进行中"。现在这一步出错也会如实报出来。

**超过系统时限会被判异常。** 新系统对后台媒体处理有每天累计 6 小时的上限，到点必须马上停。
现在会收到通知并干净地停下，而不是被系统强行处理。

**录音开头那一瞬的倾斜是错的。** 重力记录从录音开始那一刻起算，但第一个传感器读数总是稍晚
才到，之前会把这个稍晚的姿态反填到第 0 帧。现在开始录音时先把当下的姿态存成起点。

另外三处小的：图形加速失效时导出按钮立刻消失（不用等你点一下才发现）；编码器候选会优先挑
支持你所选码率模式的那个；导出时钟补上了录音开始时那 360ms 的淡入，之后才进入呼吸，和屏上
一致。
