## 本次修正

### handle 与轨道共同向左做 2dp 光学校正

上一版已经按 `TimelyClockView` 的字体稳定着墨包络对齐 handle 外缘。用户复核后希望它再向
左侧略微越过数字边缘，让圆形 handle 与数字竖边在视觉上更齐。

本次保留字体轮廓、实心/描边与 Stencil kerning 感知的测量逻辑，只把 SeekBar 的起始边界
固定向左调整 2dp。由于 handle 外缘与轨道共享同一 View 边界，两者会作为一组移动；导出图标
右侧仍独立对齐 Timely 数字右侧。

### 导出进度 Dialog 统一标题与底部间距

对比应用内标准取消/确定 Dialog 后，确认导出进度布局的根节点 12dp 底部 padding 比标准动作行
8dp 底边距多 4dp。现移除根节点底部 padding，改用同一个
`app_chrome_dialog_action_row_margin_bottom`。

标题不再使用「正在导出动画」，而是直接复用通知栏的 `fablesol_export_title`，中文统一为
「导出音频海浪动画视频」。

### 完成态改为三行同强调色操作

导出完成后改用应用既有的 `ThreeActionsAlertDialogFragment` 纵向三行结构，依次显示：

1. 分享；
2. 添加到附件；
3. 保存到相册。

三项不区分主次，统一消费当前记事的完整 `ThingBackground`；纯色和渐变均用于文字及触摸
涟漪。第三行被配置为普通操作后，返回键或点击外部只关闭 Dialog，不会误执行保存。

导出成功时 `FableSolExportSink` 已经把视频提交到 `Movies/EverythingDone/` 与
`MediaStore`，所以「保存到相册」采用幂等处理：现代系统确认既有相册条目，旧系统对原路径
补一次媒体扫描，不复制出重复视频。

源码反馈回路确认 2dp 光学校正、标准 8dp 底边距、统一标题、纵向三项与完整渐变调用链均已
生效；13 套语言资源完整。`:app:testDebugUnitTest` 与 `:app:assembleDebug` 均通过，未使用
adb。
