# HDR10+ 真的建起来了；杜比视界补上 profile 5

## 三星那条是绿灯，所以这一版把整条通路建完了

你截图里那行「带元数据 码流带 HDR10+ SEI」就是决定性证据：**换成字节缓冲输入并由我们逐帧
提供元数据，这台机器确实会把 HDR10+ 的动态元数据写进码流。** 所以 HDR10+ 现在是真的做了，
不再只是探测。

新增的三步都在 GPU 上跑：画面先画进一张离屏的 10 位缓冲，再由两个着色器分别转成编码器要的
Y 平面和色度平面（这一步原来是编码器代劳的，字节缓冲模式下得我们自己做），同时第三个着色器
把画面归约成 32×32 的亮度统计。那份统计就是元数据里的峰值、均值和各分位点——**全部是量出来
的，没有一个数是编的**。这一点很重要：上一轮我拒绝做 HDR10+ 的理由是"统计量只能猜"，那个
理由只在画面已经交给编码器的模式下成立；现在画面在我们手里，它就不成立了。

顺带修正一个判据错误：我之前用"编码器回报的格式编号"判断 HDR10+ 成不成立，那是错的——
HEVC 层面根本没有 HDR10+ 这个编号，回报 Main10 是如实陈述。现在改成**在编出来的码流里找那段
元数据**，找到才算 HDR10+，找不到就不给这个选项。

## 杜比视界：补上 profile 5，但 OPPO 的天花板是 8.4

你截图里 8.1 的失败原因是「编码器把 color-transfer 从 6 改成了 7」——6 是 PQ，7 是 HLG。
也就是说 **OPPO 那颗杜比视界编码器只出 HLG 基层，也就是只出 8.4**，我们要 PQ 基层它就自己
改回去。这不是配置写错，是它的能力边界。而 8.4 已经实测通过了，那是这台机器上杜比视界能到的
最高一档。

按你的要求补上了 profile 5，顺序是 5 → 8.1 → 8.4，各自真编一帧去试。但要提前说清楚：
**profile 5 不向下兼容**——它用杜比自家的色彩空间，任何不支持杜比视界的播放端打开都是一片
绿紫，而 8.1 在同样场合会正常按 HDR10 播。而且 OPPO 那颗编码器只广告了 profile 8，所以
profile 5 大概率压根不会出现在列表里。加它是为了"设备要是给了就用上"，不是因为它更适合分享。

自动档现在的顺序是：杜比视界 5 → 杜比视界 8.1 → HDR10+ → HDR10 → 杜比视界 8.4 → HLG。

## 请这样验

三星那台重点看 **HDR10+ 有没有进「实测通过」那一行**。进了就说明整条新通路走通了，然后
**用 HDR10+ 导一段出来**——这一版颜色是我们自己转的，万一转错会直接表现为画面颜色不对，
非常明显，麻烦你看一眼。

OPPO 那台预计还是 HDR10 / 杜比视界 8.4 / HLG 三种，profile 5 和 8.1 应该都不会出现。
