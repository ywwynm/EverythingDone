# 音频附件播放对话框：按 Timely 字形着墨边界对齐

已发布阿里云 debug 更新 `202607260649`；APK SHA-256：

## 进度条与导出图标不再按 advance 字槽边界对齐

用户反馈上一版把 `TimelyClockView` 改为 `wrap_content` 后仍未视觉对齐，并特别指出不同数字
字体的测量宽度不同，不能只改布局边距。

复核 `TimelyClockView.onMeasure()` 与 `onDraw()` 后确认：测量宽度使用当前字体的
`advance × 6.84 × 高度`，这是六个数字和两个冒号的**字槽宽度**；真正字形轮廓横向只按
字高的 80% 绘制，还包含各字体不同的左右侧边留白。对全部 33 套 Timely 字形资产做几何复现，
40dp 高度下左右可见留白会随字体明显变化，因此 View 边界并不是数字着墨边界。

本次修改：

- `TimelyClockView.contentLeftPx()/contentRightPx()` 改为按真实字形轮廓、当前实心/描边 stroke、
  绘制缩放和 Stencil 秒钟动态字距计算稳定着墨包络；
- 包络覆盖当前字体的全部数字组合，不随末位数字每秒变化，避免进度条与按钮位置抖动；
- `AudioPlayDialogFragment` 使用该包络设置进度条左边距和导出按钮右边距；
- 导出图标矢量的取景框在 24dp viewport 内还留有 1dp 右侧空白，本次一并补偿；
- 移除上一版临时的 `FableSolExportAlign` 日志。

验证：33 套字体 × 实心/描边共 66 组资产几何检查通过；`:app:testDebugUnitTest` 与
`:app:assembleDebug` 通过；远端 `latest.json` 已核对为本次更新。未使用 adb，视觉结果待用户
通过阿里云 debug 版本确认。
