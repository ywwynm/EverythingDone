# 视频导出：三星那台的「HDR 不可用」是校验写错了

## 修好了：色彩范围由编码器说了算

诊断行这次把原因问出来了，而答案是——**跟设备没关系，是我的校验太严**。

三星那台每一档 HDR 候选都失败在同一句：编码器把色彩范围从 limited 报成了 full，而当时
的代码把这个差异当成"这一档不能用"直接判死。于是色彩空间齐全、Main10 编码器一整排的
一台旗舰，被自己人挡在门外。

区别在于**谁才是权威**。色域（BT.2020）和传递函数（HDR10 / HLG）是我们画出来的像素本身
的属性，编码器改不了它们的含义，报的不一样就是真出问题；而色彩范围描述的是编码器自己做
的那一步色彩转换选了哪一档——它做了什么，只有它自己知道。现在改成采纳编码器回报的值并
写进文件的容器标记，让标记与码流一致，而不是反过来拿我们的请求去否定它。

顺带修掉诊断里两处会误导人的地方：一是档位名写死了 HLG，导致出现"HDR10 … HEVC Main10
HLG"这种自相矛盾的行；二是「DV 封装」——三星一个杜比视界编码器都没有，却同样答"接受"，
可见那一步只认轨的类型、并不校验别的，作为证据太弱。现在它只在设备真有 DV 编码器时才
出现，措辞也改成"接受该轨类型"，不再暗示"能封装出合规的杜比视界视频"。

三星那台请重新打开一次设置：这一版会强制重新探测，预期是直接变成「HDR 导出：可用
（HDR10）」。真正的验收还是导一段出来看——这才是第一次有机会在这台机器上导出 HDR。
