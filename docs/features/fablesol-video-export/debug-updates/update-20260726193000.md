# 播放 handle 对齐与导出选项完整渐变换色

已发布阿里云 debug 更新 `202607260708`；APK SHA-256：
`2a93c469059b354a3884f301c91bd0bee4fd47ecd63df2e3a706f3f334843f8a`。

## 本次修正

### 进度条改为对齐 handle 外缘

用户复核上一版后指出，Timely 数字左缘对齐的是轨道起点，但真正需要对齐的是滑杆 handle
的可见外缘。

本次按 AOSP `AbsSeekBar` 的实际绘制公式修正：自定义 thumb 安装后会自动得到半个固有宽度的
`thumbOffset`；SeekBar 左右 padding 现在使用该实际 offset。最小进度时 handle 左缘正好落在
SeekBar View 左缘，也就是 Timely 数字的稳定着墨左缘；轨道则从 handle 中心自然开始。

### 「帧率上限」「码率模式」胶囊保留完整渐变

此前两个选项组虽然会进入换色回调，但选中填充和未选中描边都只读取渐变起点
`mAppliedBackground.color`，`endColor` 与 `orientation` 被丢弃，因而不能正确显示和过渡渐变。

本次修改：

- 选中胶囊用 `BackgroundUtil.fillDrawable()` 绘制完整 `ThingBackground`；
- 未选中胶囊用 `BackgroundUtil.GradientStrokeDrawable` 自绘完整渐变轮廓，并统一降低整条
  shader 的 alpha；
- 两种状态继续由 `mAccentChipPainters` 在海浪换色的每个 UI 色阶同步刷新；
- 胶囊填充与描边不使用 `representativeColor()`，也不再只取渐变起点色。

验证：修复前反馈回路稳定得到 handle 左缘 −10dp、胶囊渐变丢失；修复后分别为 0dp 与完整
`ThingBackground`。`:app:testDebugUnitTest`、`:app:assembleDebug` 均通过。未使用 adb。
