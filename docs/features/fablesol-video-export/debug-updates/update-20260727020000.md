# 视频导出：诊断信息终于能说清 HDR 为什么不可用

## 上一版的诊断行是坏的

它显示的永远是「尚未探测」——因为能力探测是延后到后台跑的，而诊断文字在那之前就已经生成、
之后再也没有刷新。结果是最关键的那句「不可用的原因」一次都没显示出来。

现在诊断会**等探测真正跑完**再出结果，并且列出**每一档具体失败在哪一步**——是创建编码器时
拒绝、是图形表面建不起来、是启动失败，还是输出格式与申请的对不上。

## 为什么这次尤其重要

从你两台机器的截图看，三星那台的情况和我原先的判断**不一样**：它的两种 HDR 色彩空间都有、
HEVC 10 位编码器一整排也都在，能力全都具备，却仍然判成"设备不支持"。也就是说卡点不在我上
一版修的那道门上，而在后面真正编一帧的某一步——而那一步的原因恰恰被坏掉的诊断行吞掉了。

装上这一版再打开一次设置，那一行会直接写出来卡在哪儿。

## 杜比视界

OPPO 那台确实枚举到了杜比视界编码器（高通的实现）。诊断现在会额外列出它支持的 profile
编号，作为下一步判断的依据。

仍然要说清楚：**存在编码器不等于第三方应用能用**。杜比视界要授权，还要逐帧的动态映射
元数据，而后者没有公开接口。列出这些只是为了让判断建立在数据上，不是靠猜。
