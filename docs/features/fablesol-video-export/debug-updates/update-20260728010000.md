# FableSol 视频导出：区分位深落点，编码器被夺走时重试

## 2026-07-28 报告写明通过的是哪一档 Profile；状态类错误改为重试

三星 Z Fold4 上 SDR 通路已经恢复为硬件编码（HEVC 120 fps、H.264 120 fps），上一版把 8-bit 档
的输入表面位深改为跟随档位起了作用。剩下的失败集中在 HDR：

- HDR10+ / HEVC 与 HDR10 / HEVC：`Invalid to call at Released state; only valid in executing state`
- HLG / HEVC：`Pending dequeue output buffer request cancelled`

两句描述的都是编码器**状态**问题，即编码器在使用过程中被释放、排队中的请求被取消，而不是这
份编码参数不成立。它们又都不是 `CodecException`，因此上一版依据 `isTransient` 的重试一次都
没有触发。

**状态类错误改为重试一次。** 判据不再只看 `isTransient`，同时按错误消息中的状态特征识别；每
个失败的候选之后加入短暂沉降，避免底层实例尚未拆除完就创建下一个。

**能力报告写明通过验证的是哪一档 Profile。** 此前只写编码器族，而同一族里 10-bit 与 8-bit 是
两个不同的阶梯项，无法判断这台机器是 10-bit 编不了，还是仅 HDR 信号编不了。现在写成
「HEVC Main10 SDR 120 fps」这种形式，SDR 一列的答案即可区分这两种情形。

能力探测契约版本升至 8，旧缓存作废并重新验证。
