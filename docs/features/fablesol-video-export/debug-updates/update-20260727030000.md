# 视频导出：诊断细节不再被缓存吞掉

## 为什么上一版还是什么都没说

能力探测的结果是带缓存的，而缓存里**只存了"支持 / 不支持"这一个结论，没存原因**。
命中缓存时探测过程根本不会重跑，那句原因也就无从产生——所以你看到的一直是光秃秃的
「可用」「不可用」。更麻烦的是否定结果有 24 小时有效期，等于这一整天里都问不出所以然。

现在原因、用的是哪种 HDR 格式、以及每一档的具体失败信息都**跟着缓存一起存**，命中缓存
照样显示。同时把探测契约版本推进了一格，让已经存下来的旧结果全部作废、立刻重新探测一次
——所以这一版装上后打开设置，两台机器都会重新走一遍并给出细节。

## 杜比视界

OPPO 那台的 DV profile 是 256，也就是 **profile 8（dvhe.st）**——单层、带兼容基层的那一档，
是杜比视界里最有可能被第三方用上的形态。诊断现在会直接写成人看得懂的名字，不再是原始数字。

同时新增一行「DV 封装」：直接问系统的封装器**肯不肯把杜比视界轨写进 MP4**。这一步不需要
真的编码就能问出答案，而它恰恰是"设备有 DV 编码器"之后真正决定成败的一关——封装器要是
拒收，这条路在平台层面就已经断了，再谈编码没有意义。
