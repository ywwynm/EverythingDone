# 杜比视界 8.1、判据修正，以及一个害你看了旧数据的缓存 bug

## 你截图里有三行是旧数据——那是我的 bug

先说这个，因为它让上一版的判断整个不可信。

能力探测的结果带缓存，缓存签名里我放了「应用版本号」，本意是每发一版就重探一次。但那个
版本号在构建脚本里是**写死的**，两次 debug 发布之间根本不变。于是我删掉某道筛子之后，
设置页仍然把改动前的结论从缓存里读出来给你看。

证据就在你的截图里：「HLG：没有编码器广告支持这个 profile」——这句话的**措辞**是上上版的，
上一版我已经把它改成了另一种说法。也就是说那三行失败原因全是旧的，HLG 那一行尤其冤枉，
它是被我上一版就删掉了的筛子挡下来的。

现在签名改用发布任务自己生成的时间戳，每发一版必然变化，这个问题不会再出现。这一版装上
后看到的会是真正重新探测的结果。

### 杜比视界 8.1：你的直觉对，8.4 确实不够

8.4 的底层画面是 HLG，所以高光余量只有约 3.77 倍——这正是我们一直嫌弃 HLG 的那个限制。
而 **8.1 的底层是 PQ**，余量到 10000 尼特，和 HDR10 一样宽，并且它本身就与 HDR10 兼容。

关键在于：**两者用的是同一个格式编号，区别只在亮度曲线**——给 PQ 就是 8.1，给 HLG 就是 8.4。
Dolby 官方样例只演示了 8.4，但没有任何地方说 8.1 不行。所以这一版把它们拆成两个独立选项，
各自真编一帧去试，能编出来才出现在界面上。

顺带按你的意思调整了「自动」的顺序，现在是**规格从高到低**：
杜比视界 8.1 → HDR10+ → HDR10 → 杜比视界 8.4 → HLG。前三种都是 PQ 基层（满余量），
后两种是 HLG 基层。同基层里，带动态元数据的排在静态的前面。

### HDR10+ 的判据我用错了

上一版探测报「降回 profile 2」，我据此说三星不产 HDR10+。**这个判据是错的。**

HEVC 层面根本没有"HDR10+ 这个 profile"——码流的真实格式编号就是 Main10（2），HDR10+ 只是
额外多一段元数据而已。系统里那个 8192 是 Android 自己拼出来的合成编号。编码器回报 2，
完全可能只是在如实陈述码流格式，而不是拒绝了 HDR10+。

所以判据换成**直接在编出来的码流字节里找那段元数据的签名**。找到了就是真有，与它回报什么
编号无关。这才是能作数的证据。

请再开一次设置，把「HDR10+ 字节缓冲」那一行发我——这次它会说"码流带 HDR10+ SEI"还是
"码流里没有"。如果是前者，那条路就是通的，我接着把它建起来。
