# 视频导出：新增 HDR10（PQ）通路与设备能力诊断

## HDR 不再只认一种信号格式

之前整条 HDR 通路**只认 HLG 一种色彩空间**。而三星那一系的自家格式 HDR10+ 是基于 PQ 的，
PQ 那个图形扩展出现得也更早、支持面更广——所以只提供 PQ 的设备会被判成"不支持 HDR 导出"，
其实硬件完全够格。S23 Ultra 上看到的"HDR 编码不可用"很可能就是这个原因。

现在两种格式都会尝试，**默认优先 HDR10（PQ）**。这还顺带解决了另一个问题：HLG 在普通白之上
只有约 3.77 倍空间，而 HDR 强度上限是 9.6，超出的部分只能压缩，导致强度调到 4 以上几乎看不
出区别。PQ 是绝对亮度、上限 10000 尼特，9.6 倍约合 1949 尼特，**完全放得下、一点都不用压**。

设置里新增「HDR 格式」：自动 / HDR10 / HLG。默认自动 = 设备支持哪些就按顺序试。选 HLG 的
理由只有一个——如果产物主要在不支持 HDR 的设备上回看，HLG 被压缩成普通画面时更温和。

## 设置里能看到设备到底提供了什么

以前 HDR 不可用只给一句"不支持"，出了问题只能猜。现在「视频导出」分组末尾会列出：

- HDR 导出是否可用；不可用时**说明卡在哪一步**（缺哪种色彩空间、还是没有编码器能真编出一帧）；
- 图形层面：FP16 场景缓冲、PQ、HLG 各有没有；
- 编码器清单：HEVC Main10、AV1 Main10、**杜比视界**分别有没有、具体是哪个实现。

杜比视界那一行是应你要求加的检测。说明一下预期：系统相机能录杜比视界**不等于**第三方应用
能编——中间隔着授权，以及逐帧的动态映射元数据（这部分没有公开接口）。这一行只是如实报告
系统里到底存不存在这样一个编码器，好让判断有依据而不是靠猜。

## 顺带

导出的 HDR10 产物会带上母版元数据。我们的峰值是可以直接算出来的（HDR 强度 × 203 尼特），
所以里面填的是准确值，而不是像实拍内容那样只能估。
