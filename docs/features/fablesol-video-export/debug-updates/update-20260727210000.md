# HDR10+ 还是显示成 HDR10：又是我自己的校验挡的

## 你说得对，标签本来就该写 HDR10+

上一版把整条通路建完了，但设置里仍然只显示 HDR10——查下来是**同一类错误又犯了一次**：
我自己的输出校验把 HDR10+ 判成了"编码器降了档"，于是它压根进不了「实测通过」那一行，
标签和自动档文本自然还是 HDR10。

具体是这样。我们向编码器申请 HDR10+ 这个格式编号，编码器回报的是 Main10。上一版我已经
认识到"回报 Main10 是如实陈述，不是拒绝"，也把 HDR10+ 从"必须原样回报"的名单里拿掉了——
但**没有把 Main10 加进允许的回报值列表**。结果是：不再要求原样回报，可回报的那个值又不在
白名单里，照样判失败。修一半等于没修。

现在 Main10 在列表里了。判定 HDR10+ 成不成立，唯一的依据仍然是**编出来的码流里有没有那段
动态元数据**——那是真凭实据，profile 编号说明不了任何事。

## 顺带两处

- 交给编码器的一帧长度改成规范的整帧长度，而不是"我实际写到哪个字节"。有的实现会按这个数
  校验，短一截直接判非法。
- 档位名不再重复写格式：之前会出现「HDR10+ HEVC Main10 HDR10+」这种同一个词说两遍的行。

## 请这样验

三星那台开设置，看两处：

1. 「实测通过」那一行里**有没有 HDR10+**，以及自动档是不是变成了 HDR10+；
2. 如果还是没有，它下面会有一行 `· HDR10+：…`，把失败原因写清楚了——那行发我。

进去了的话，**用 HDR10+ 导一段出来看颜色**。这条路上 RGB→YUV 是我们自己算的，万一矩阵或
行序错了会直接表现为颜色不对或画面上下颠倒，非常显眼，但我只能靠你看一眼。
