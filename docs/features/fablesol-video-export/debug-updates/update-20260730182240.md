# 冻结的两处生命周期修正

## 2026-07-30 - 冻结时把刷新率控制权真正交还系统；修掉切后台回来那一下的画面跳动

接上一版（202607300954）的评审修正，两处都与"冻结/恢复"的生命周期边界有关。

**冻结时不再占着高刷诉求**

此前冻结虽然撤掉了显式的刷新率请求，播放对话框的窗口却仍然处于"退出系统动态刷新率省电
调节"的状态——等于一边说"我不需要高刷"，一边又不许系统降下来。现在这两项一起切换：动画
期间保持原样，冻结期间把刷新率控制权完整交还系统。导出时长的功耗因此更低。

**修掉切到后台再回来时画面跳一下**

这是一个更早就存在的问题，不限于导出场景：任何一次切后台再回到播放对话框，恢复的第一帧
都会按"离开之前的那一刻"计算时间步长，导致水面在那一帧走出约六倍于正常的位移，看上去是
轻微一顿。现在帧循环每次重启都会重新对时，解冻、后台返回、画面尺寸变化三条路径都覆盖。

**一项评审意见经复核不成立，未改动**：有意见认为在音频播放到最后一段缓冲时发起导出，
声音会继续跑到结尾才停。实际不会——解码循环每一轮开头都会检查暂停状态，收尾阶段同样经过
这个检查，暂停在下一轮就生效并真正停住音频输出。

**冻结本身的行为不变**（上一版起生效）：导出进度对话框在前台时，水体保持原样直接停住、
不再出帧，音频暂停且不自动续播，倾斜传感器注销而屏幕方向锁保持；对话框消失即恢复，包括
点「在后台运行」。

**请确认**：切后台再回到播放对话框时，水面恢复得是否平顺；以及同一段录音在这一版与冻结
之前那一版下的导出耗时差异（建议交替各跑两轮取中位数，连续满载会热降频，单轮对比不作数）。
