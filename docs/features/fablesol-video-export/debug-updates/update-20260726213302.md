# 导出画布分享兼容与播放界面视觉修复

## 用户反馈

1. 导出进行中和导出完成 Dialog 的底部按钮文字没有居中于 touch ripple 胶囊。
2. 导出视频分享到微信或朋友圈后，右侧背景被裁掉一部分，左右不对称；用户判断不止
   2px，并要求视频宽、高都按 64px 的倍数重新绘制背景。
3. 导出海浪视频图标仍需重做，希望从 Python 模拟器离线渲染真实 FableSol 画面并提取轮廓。
4. 音频附件的 FableSol 播放 Dialog 中，导出图标应使用记事颜色并支持完整渐变；主播放/
   暂停图标应比上一曲、下一曲更大，与其更大的 touch ripple 层级一致。

## 诊断与修改

- `dialog_fablesol_export_progress.xml` 的两个动作是固定 36dp 高 `TextView`，ripple 覆盖整个
  View，但文字没有 `gravity`，仍按默认顶部基线布局。两个动作现统一使用
  `android:gravity="center"`。
- `FableSolExportTier.alignForEncoder()` 原先只满足 codec 宣称的最小对齐，默认字形可能产生
  `1106×1444` 等尺寸。现在按 codec alignment 与 64px 的最小公倍数向上扩展宽高，
  `FableSolExportPlan.withCanvasSize()` 只对称增加中性背景并重新居中卡片，不改变卡片像素、
  density 或水体物理几何。默认 310dp 卡片现在得到 `1152×1472`，左右画框各 97px。
- `FableSolExportEncoder` 新增完整 crop rectangle 校验：没有 crop keys 视为全画幅；一旦存在，
  必须严格覆盖 `[0, width-1] × [0, height-1]`，否则放弃该编码候选，防止单边裁切 metadata
  进入 MP4。
- 使用 `E:\projects\audioVisualizerSimulatorFable\tools\shoot_frames.py` 对真实录音离线渲染
  2/4/6 秒帧；选择 4 秒帧，逐列提取顶层水面 y=542～551px，再拟合为 24dp 图标内的低振幅
  开放贝塞尔轮廓。原圆角视频画框保留，不再拼接抽象正弦波。临时帧与预览验证后已清理。
- `AudioPlayDialogFragment` 的导出图标清除 XML 单色 tint，改用
  `BackgroundUtil.tintDrawable()` 直接消费完整 `ThingBackground`，保留渐变端点和方向；
  中性 App Chrome 圆形 ripple 保持不变。
- 主播放/暂停按钮保持 56dp touch ripple 和 14dp padding，仅将 `scaleType` 从
  `centerInside` 改为 `fitCenter`，使 24dp vector 在 28dp 内容区内实际放大；两侧按钮仍为
  48dp ripple 与 24dp 图标。
