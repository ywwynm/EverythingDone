# FableSol 视频导出：三条轴互相约束；修复 profile 未回报被判为降档

## 2026-07-28 帧率成为硬约束；未回报 profile 不再判死；恒定质量按可用编码器判定

**编码器未回报 profile 不再判为降档。** 不少编码器（OMX 系尤其常见）不把 `KEY_PROFILE` 写进
输出格式。此前将该字段为空一律判为「编码器降了档」，导致一台已经产出 10 位 HDR 输出的华为
平板被自身校验否决，报错为 `Encoder changed profile 2 to null`。现在与色彩键的处理保持一致：
字段缺失即没有信息，只有回报了**其他值**才算真的更换。HDR10+ 与杜比视界不受影响，前者的判据
本就是码流中的 SEI，后者更换的是 MIME 且传递函数另有校验。

**帧率、导出 HDR 格式、视频编码器三者改为互相约束。** 帧率此前是「上限，不成立时自行降级」，
界面因此会同时摆出三个各自看着成立、合起来却不成立的选择：选定 120 fps 后仍可选 AV1，点击后
帧率被改为 60；HDR10 与 HLG 同样可选，而它们在 120 fps 下没有通路。现在每一条轴的可选性均以
另外两条的当前取值为前提；确实产生冲突时，按「保住刚变更的那一条、其余改动最少」枚举出一个
成立的组合。

**恒定质量档按真正可用的编码器判定。** 恒定质量与编码器绑定，此前只要有任一编码器声明支持
即显示该档位。三星 Z Fold4 上声明支持的编码器尺寸上限为 512×512，本项目画布根本不会用到它，
于是设置中摆着恒定质量、导出时静默换成恒定码率。现在要求该编码器能够处理本次画布。

**「帧率上限」改称「帧率」**，13 套语言同步。

**推导文字与完成信息同时标注硬件编码与软件编码**，此前只标注软件，未标注者无法区分是硬件
编码还是该项未解析出来。
