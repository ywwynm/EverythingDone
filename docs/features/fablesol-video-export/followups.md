# fablesol-video-export 遗留项

## 验收

- **D15 ① 逐位门禁未建立，且判据本身要改写**（2026-07-26 第四轮修正）。

  原判据"实时与离线逐帧 max|Δ| = 0"**不可能达成**，因为两条路径的初始状态本就不同：

  - 实时分析器从**准备态**就开始吃麦克风数据（`AudioRecorder.RecordingThread` 无条件喂
    分析器，只有 WAV 写入受 `mIsRecording` 门控），开始录音时不重置——这是 README 明写的
    录音预览设计；
  - 水体模拟同样不在开始录音时重置，屏上那一帧带着准备态的历史；
  - 离线导出只有 WAV 里的样本，从零状态起步。

  这三条都是**有意为之**，不该为了对齐判据去改。正确的判据应改成两条：

  1. **离线自比对**（可进 CI）：同一个 WAV 连跑两次，逐帧状态向量 max|Δ| = 0——这测的是
     离线路径本身的确定性，也是真正能自动化的那一条。
  2. **受控初值的双路对照**：给实时侧喂等间隔 1/120 的合成时间戳**并且**把分析器与模拟
     显式复位到零状态，此时才应逐位相同。做不到复位就只能退回事件层（D15 ②）。

  预热门这一项已在代码侧解决：离线路径调 `FableSolRealtimeAnalyzer.skipStartupGate()`，
  因为那道门拦的是麦克风冷启动暂态，读文件没有这回事，而实时侧它早在准备态就放行了。
- **D15 ② 事件层比对未做**：真机录一段、离线导同一份 WAV，比对 onset / 七境转移 / 巨浪触发 /
  段落切换的序列与时刻（容差一个 hop ≈ 10.7ms）。
- **D15 ③ 观感层未做**：构图、配色、时钟位置、圆角、投影、padding 只能人眼验收。
- **播放对话框的字形着墨对齐缺少 Android View 级自动回归**：当前用 33 套真实 JSON 资产的
  纯几何检查覆盖字体/实心/描边组合，并由 JVM 单测与 APK 编译兜底；项目尚未接入 Robolectric
  或截图测试，最终像素对齐仍需真机确认。
- **handle 光学校正、选项胶囊渐变与导出完成 Dialog 缺少 Android Canvas/View 级截图回归**：
  当前以 AOSP `AbsSeekBar` 坐标公式、完整 `ThingBackground` 调用链、布局结构静态检查、
  JVM 单测与 APK 编译兜底；项目没有 Robolectric/截图测试环境，handle 向左越过数字 2dp
  的观感、胶囊换色及完成信息换行与双按钮着色的最终像素结果仍需真机确认。
- **完成通知与新版导出图标缺少系统 UI 级视觉回归**：当前已用共享 `Done` 状态和资源文案
  保证数据同源；图标已改成补全左、上画框的 Material `video_frame_save`。通知在不同厂商
  系统的折叠/展开行数、长路径换行，以及 24dp 图标的边框连续性仍需真机确认。
- **64px 画布与本轮播放界面仍需真机分享/视觉验收**：JVM 已证明 280/310/383dp 三档宽高
  都被扩展为 64px 倍数、左右背景等宽，输出 crop keys 也会被完整画幅校验；但微信聊天与
  朋友圈的真实二次转码是否还会额外裁切，只能用新产物实发确认。按钮文字在 ripple 内的
  光学中心、Material 导出图标的记事渐变着色及 32dp 主播放/暂停图标也需在常用尺寸下复核。

- **HDR 开关与结束态重播仍需目标真机验收**：源码契约覆盖 HDR 120→60 优先于 SDR 的
  尝试顺序、能力缓存与延后后台探测、失败时取消偏好并置灰，以及自然结束后 seek 必须重建
  解码线程；但一帧 `MediaCodec`/10-bit HLG EGL 探测在用户的三星设备上是否正确置灰或
  放行、首次未缓存时设置 Dialog 是否完全无卡顿、放行后实际产物是否标为 HDR，以及
  “播完→拖到中段→点击播放”的声音与进度同步，仍须在该设备实测。

- **导出链路仍缺真实 Android 框架级测试**（2026-07-26 第六轮更新）。现有 JVM 门禁包括
  `FableSolExportFixedDtTest`（定步长）、`FableSolExportStateRegistryTest`（任务隔离与终态）、
  `FableSolExportGeometryTest`（编码尺寸对齐）和 `FableSolExportPipelineSourceTest`
  （封装/发布顺序、HDR 与旧版落地源码契约）。以下行为仍必须由 MediaCodec / Service /
  Robolectric 或真机覆盖，项目目前没有这套环境：
  - 文件播放与导出的分析器事件序列一致；
  - 两个真实 Service 任务排队、取消与结果不串任务；
  - worker 完成与新 START 同时到达时 foreground 不被旧任务撤掉；
  - 真实 `MediaMuxer.stop()` / MediaStore commit / MediaScanner / 系统超时失败路径；
  - Android 14 HDR 候选与 Android 15 `FEATURE_HlgEditing` 的真实厂商实现；
  - 设置页最大画布一帧 HDR 探测的厂商 codec/EGL 结果与正式导出一致性；
  - 音频自然结束后重建 decoder、初始 seek 与立即点击播放的真实时序；
  - API 26–28 的权限拒绝、文件冲突和公共相册扫描。

## 标定

- **码率与 CQ 质量档默认值是推测值**（120fps 24 Mbps / 60fps 14.4 Mbps，质量 80%）。
  要用最容易暴露色带的场景实测校准：大面积缓变的深色渐变记事 + 静水。
- **投影与描边参数未经真机确认**：offset 6dp / radius 24dp / alpha 0.28（深）0.40（浅），
  描边 1dp / alpha 0.10（深）0.06（浅）。

## 已知取舍待复核

- **HLG 的超白余量只有约 3.77 倍**（BT.2408 漫反射白落在场景线性 0.26497），而用户 HDR
  强度上限是 9.6。当前用线性域软肩（knee = 2.0，之上指数渐近到上限）承接超出部分，
  逐通道压缩因而高光自然趋白。若真机上观感不可接受，替代方案是改走 PQ（ST.2084）+
  HDR10 静态元数据——PQ 是绝对亮度、10000 nits 上限，9.6 倍 SDR 白（约 1949 nits）完全放得下，
  代价是要写 mastering display metadata、且播放端兼容性略差。
- **`FableSolRealtimeAnalyzer` 预热门是否纯采样驱动未确认**（`:157` "预热门只拦截采集会话
  开头"）。若掺了挂钟，离线导出的头几秒会与实时不一致，须改成采样驱动。
