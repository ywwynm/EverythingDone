# Thing Card Bottom Status Layout Decisions

## 2026-06-28 - 术语与界面范围

**术语**：把"音频 + 提醒/目标 + 习惯"这一组、需要锚定在卡片内容区底部的区域
统一称作 **Thing Card Bottom Status**（卡片底部状态块）。代码对应
`view_thing_bottom_status_spacer`、`hasThingCardBottomStatus`。提醒类与目标类
共用同一个 `rl_thing_reminder` 块（仅图标/文案不同），习惯是 `rl_thing_habit`。

**界面范围**：状态块置底规则只作用于真正渲染状态块的界面——首页
（ThingsActivity）、单一记事 widget、记事列表 widget、widget 配置候选列表。
NoticeableNotificationActivity 与 DoingActivity 在 `onBindViewHolder` 里继续
隐藏提醒/目标/习惯状态块，不改动。

**理由**：NNA/Doing 已用标题 + 底部操作按钮 / 计时蒙层另行表达提醒/习惯信息，
重新显示完整状态块会改变其既有信息结构，改动范围过大。Issue 3 中"首页与 NNA
渲染比例不一致"因此被理解为"两个界面显示的内容本就不同"的自然结果，单独讨论
其处理方式，而非通过让 NNA 显示状态块来强行对齐。

## 2026-06-28 - Issue 1：侧图模式状态块置底

**事实**：侧图高度 = `max(128dp 侧图最小高度, 内容列自然高度)`，而内容列自然
高度已包含状态块。因此"侧图比内容高、底部留白"只在"内容列(含状态块)整体矮于
128dp"时发生（典型：正文短 + 一条提醒/目标；习惯通常较高，一般不触发）。侧栏
宽度占 30%–60%。

**决策**：侧图模式复用媒体背景已有的置底机制——把内容列撑到侧图高度，用 flex
spacer（`view_thing_bottom_status_spacer` weight=1）把状态块（音频 + 提醒/目标 +
习惯）顶到内容列底部，保留 16dp 底部边距；标题/正文/清单留在顶部。spacer 同时
保证状态块不与上方内容重叠。

**否决项**：让侧图缩短到内容高度以消除留白——与"侧图不宜过矮"的 128dp 下限初衷
冲突，且用户明确要求状态块置底而非缩图。

## 2026-06-28 - Issue 2：媒体背景底部顺序

**现状**：媒体背景模式下，"X张图片，Y段视频"提示是卡片级 overlay 固定在
`bottom|start`，同时加大 `padding-bottom` 给 overlay 让位——这会让提示排在状态块
下方或与之重叠，与用户期望相反。

**决策**：把媒体背景提示移进底部置底组，作为最上面一项。底部置底组从上到下统一为：
提示（仅媒体背景模式有）→ 音频 → 提醒/目标 → 习惯 → 16dp 边距，整组由 spacer 顶到
卡片底部。提示不再是 overlay，因此会计入自然内容高度。该置底组顺序与侧图模式
（Issue 1）共用同一套逻辑，保持各模式一致。

## 2026-06-28 - Issue 3：封面比例语义与编辑器

**现状（已核对代码，无渲染 bug、自洽）**：
- 媒体背景卡片高度 = `max(比例换算高度, 自然内容高度)`，图片作为整卡背景 cover
  裁切到最终高度。封面比例本质是"卡片的期望/最小形状"，只能把卡片撑得比内容
  更高，**几何上不可能比自身内容更矮**。
- 所存 `mediaBackgroundTargetAspectRatio`**不会自动重算**。`RatioSlider.setRatio`
  是 programmatic、不触发 `onRatioChanged`；草稿里的比例只有用户拖动才写。所以
  内容变化后所存值原样保留，确认时存的还是原值。
- 各界面按各自显示的内容量渲染。NNA/Doing 隐藏习惯块、且放开正文 maxLines，自然
  内容高度与首页本就不同，于是 `max(比例高度, 内容高度)` 算出不同结果——按设计接受
  （见本文件界面范围决策）。该语义与 ADR-0003"低于自然内容高度的比例就按自然内容
  高度投影"一致，无需新 ADR。
- slider 区间按内容动态推导，且是真护栏：侧栏用 30%–60% 宽度两端各自实测高度算
  可达比例；媒体背景 `maxRatio = 卡宽/自然内容高度`。拖动时用
  `mThingCardActiveRatioDragRange` 冻结区间。

**决策（渲染语义不变，只改编辑器体验）**：
- 媒体背景渲染语义保持不变（图片覆盖整卡、随内容长高）。想要固定比例的封面，用
  "顶部/底部图片"位置（图按比例固定、内容在下，与内容高度无关）。
- 媒体背景封面比例 slider：当**内容高度 > 所设比例换算高度**（即比例被内容覆盖、
  再也减不短）时，把 slider 置灰（inactive）并显示提示，文案形如"记事内容高度已超出
  封面图片/视频比例可调范围对应的最大高度"。内容变矮、比例可生效时自动恢复可调；
  所存比例始终保留。
- 触发条件用"被内容覆盖"而非"完全卡死"（content ≥ 96% 上限极少见），以覆盖最常见
  的"thumb 钉右端、够不到更矮比例"场景。代价：被覆盖期间也不能把卡片拖得更高（该
  效果对内容多的卡几乎用不到）。

**侧栏模式**：同样的"所设比例被夹到端点"机制会发生（所需宽度超出 30%–60%），但侧栏
比例对应宽度、宽度永远能在 30%–60% 间调，slider 不会卡死到"无可调"，因此不进入置灰
状态。侧栏比例被夹到端点时**不特殊处理、不加提示**——这是正常边界行为，与媒体背景的
"可能完全不可调"区别对待。

**实现约束（备忘）**：状态块置底（Issue 1/2）需作用于单一/列表 widget，但 widget 走
RemoteViews、无应用进程内测量。置底需用 RemoteViews 的 LinearLayout 权重 spacer 实现，
媒体背景下高度依赖现有行高估算（`estimateThingsListWidget...RowHeightDp`），故为近似置底。
