# 首次横屏返回的外观解析优化

## 范围与已有证据

前轮魅族首次横屏、展开初期返回的两个无采样样本为 762.7／610.4 ms，后续约 0.17～0.25 秒。采样确认主要应用内路径为 `publishDetailReturnList → justNotifyAll → ThingManager.loadThings → Thing(Cursor)`，反复解析卡片、详情附件和背景外观 JSON。相关快照和报告保留于 `tmp/thing-detail-widget-quick-return/`。

本轮保留保存完成等待、完整列表重读、稳定身份匹配、所有动画时长及绘制规则。测试在一加 `3B1629006YC00000`、三星 `R5CW20BLNKL`、魅族 `192.168.100.67:40807` 上进行，已有记事只读，模拟记事及测试小组件按所属 ID 清理。

## 排序后的假设

1. 同一份 JSON 每次重读都重新解析：按完整 JSON 复用结果，应减少解析调用及列表恢复耗时，外观变更后的新 JSON 必须立即生效。
2. 解析后的规范化、集合或序列化重复分配：如果解析复用后耗时仍高，调用栈会转移到上述步骤；需分别测量，不能以缓存命中率代替整体返回时间。
3. 横屏首次窗口布局本身较慢：解析成本下降后，窗口恢复至目标准备的其他阶段仍可能保留独立开销。

## 正确性约束

- 不缓存可变的 Thing，不按记事 ID 或更新时间判断外观是否相同，避免导入和编辑产生过期值。
- 共享解析结果前检查完整对象图的不可变性，防止两条相同外观的记事互相影响；嵌套集合必须受保护。
- 缓存有容量上限、支持并发读取，损坏或过大的输入维持原解析及回退语义。缓存只影响内存和计算，不回写数据库。

## 实现决策

- 三类 `fromJson` 使用独立、按完整字符串匹配的内存缓存；分别最多 1024 项、512 Ki 字符，单项超过 64 Ki 字符直接解析。无需按记事 ID、更新时间或编辑入口维护失效分支。
- 只在解析成功创建的本地 `sources`、嵌套 `presentations` 映射上加不可修改包装；其余值为只读字段。编辑接口仍创建新对象，调用方传入的模型和可变 Thing 不进入缓存。
- 查询和写入缓存时短暂加锁，解析在锁外进行；并发首次解析允许重复计算，提交时复用已发布结果，避免后台视频小组件阻塞主线程命中读取。
- 新增模型回归在旧实现上出现四项预期失败：重复读取不复用、嵌套集合可修改、跨对象读取不复用、并发读取不复用。旧数据回退、变更生效、导入路径重写检查已通过。测试宿主沿用现有 Robolectric 的轻量 App 初始化。
- 新一轮无采样魅族基线首次为 266.1 ms，后续约 212.8～222.1 ms，表明首次成本受运行状态影响；最终效果将同时报告同轮对照和真实数据构建耗时，不直接用前轮最慢样本计算改善比例。

## 当前验证与测量边界

- 三机原有记事的外观语义摘要在优化前后完全一致。魅族、三星的外观变更、快速返回、完整返回、小组件及导航／保存审查通过；一加 USB 中断的一轮已执行夹具清理、原数据校验通过，改用已授权且序列号核对一致的 Wi-Fi 地址继续回归。
- 第一轮优化后魅族首次为 507.2 ms，后续约 189.5～231.1 ms，不能据此声称整体首次等待已稳定降低。追加带采样的一轮首次为 285.1 ms，长 JSON 解析栈已消失，出现的是缓存读取、窗口恢复、普通 Thing 构建和文件夹查询；采样数据只用于定位，不与无采样耗时直接计算收益。
- 早期完整数据库读取计时包含主线程排队，首次出现秒级值，不能当作 JSON 解析成本。已将排队时间单列，并增加同一进程、相同原始 JSON、交替顺序的原解析器／缓存入口对照，计时区间排除排队、摘要计算和断言。输入重新创建 String，避免只测已有对象的哈希缓存。探针只记录耗时、数量和摘要，不导出正文或外观 JSON。

## 三机结果

同进程的三类外观解析各做八轮交替顺序对照，缓存预先填入同批数据。下表为八轮中位数，属于重复读取的解析成本，不是首次返回总延迟。

| 设备 | 原记录数 | 直接解析 | 缓存入口 |
| --- | ---: | ---: | ---: |
| 一加 15T | 114 | 18.27 ms | 5.71 ms |
| 三星 S23 Ultra | 374 | 22.57 ms | 10.91 ms |
| 魅族 20 无界版 | 181 | 40.57 ms | 5.71 ms |

- 三机现有唯一 JSON 均能保留在容量限制内，没有驱逐导致的重复解析；三个缓存保留的文本总长度分别约 2.9 万／5.6 万／4.4 万字符。全部输出值与直接解析器相等，优化前后的真实数据语义摘要也相同。
- 魅族前两轮微基准有明显首次执行开销：直接解析约 1864／1058 ms、缓存入口约 509／500 ms；完整历史数据的首次三轮 Thing 构建也有 690～964 ms，排队仅 0.4～20 ms。因此秒级异常不能全部归为主线程排队，亦不能把上述重复读取中位数用于承诺首次窗口等待。
- 魅族另外按“旧→新”“新→旧”交替安装，分别测独立进程首次横屏快速返回。两组旧版首次 442.3／342.9 ms，新版 337.8／362.8 ms；后续新版 187.9～230.3 ms。加上前述初轮 266.1→507.2 ms，整体首次耗时仍有明显波动，本轮只确认重复解析成本降低，不宣称首次总等待有稳定百分比收益。后续可以继续定位窗口、数据库与模型构建的首次成本。
- 三机基础功能回归共 391 项通过：外观同 ID／同更新时间更新、独立记事隔离、展开三个阶段快速返回、真实工具栏与系统返回、完整返回场景、小组件后台读取、保存与更新顺序；三星追加外部入口和嵌套导航，魅族追加延迟保存与私密审查，一加追加图片／视频等模拟类型。另有 26 项采样定位、57 项成本与读取核对、52 项交替版本中的优化版检查通过。
- 21 组返回终点与真实列表全通道逐像素一致，视觉复核确认新外观立即生效、旧外观的另一条记事不被污染。没有改变展开／收回动画代码、时长、截图或交接规则。
- JVM 共 1732 项，0 失败／错误，3 项既有跳过；新增 13 项覆盖有界驱逐、完整文本匹配、损坏数据、并发解析、嵌套不可变性、编辑隔离和导入重写。
- 每轮均核对原记录与累计数量一致，测试小组件检查原绑定与配置未变。所有写入只使用模拟记录，夹具按创建时间及所属 ID 删除；三机共 669 条原记录保持不变，不做整库备份。

本轮原始数据位于 `tmp/thing-detail-appearance-cache/`，其中 `summary.json` 汇总测量和像素检查。一加 USB 中断的首轮单独保存为 `apc-oneplus-interrupted/`，确认夹具删除与原记录未变后改用 Wi-Fi；不将该轮计入功能通过数。
