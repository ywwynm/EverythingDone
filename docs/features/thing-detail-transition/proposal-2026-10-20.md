# 2026-10-20：记事列表到详情页的连续转场方案

本文保留方案阶段的分析；用户随后批准实施，当前实现、设备证据和限制见 [实施与验证](execution-2026-10-20.md)。

## 建议

保留 `ThingsActivity` 与 `DetailActivity`，复用新建页的一次性列表快照承接机制，在详情窗口内完成容器变换和关键元素过渡。

动画的范围包括卡片外框、背景、能够对应的标题和封面；布局不同或没有对应项的内容采用局部交叉淡化。页面末帧必须与实际详情布局一致，不能用整张卡片截图拉伸后突然换页。

用户在首轮方案后明确要求不能改成 Fragment，并确认现有新建记事的粒子、涟漪、边框光效动画在卓易通上均交接正常。因此以现有承接机制为已可用基础，撤回同窗口详情组件备选，不再把首帧可行性作为架构选择的前置试验。新增卡片及元素变换仍需按实际效果验收。

## Android 库能提供什么

- **共享元素转场**：建立来源与目标元素的对应关系，对两端状态做动画；不意味着两个页面持有同一个 View 实例。[Android 官方说明](https://developer.android.com/develop/ui/views/animations/transitions/start-activity)
- **MaterialContainerTransform**：主要处理容器的边界、形状和两端内容切换，适合卡片展开为详情；不会自动把容器内部的每个子元素逐一对应。AndroidX 版本用于 View／Fragment，跨 Activity 版本仍走平台窗口转场。[Material 官方说明](https://github.com/material-components/material-components-android/blob/master/docs/theming/Motion.md)
- **页内 Transition／属性动画**：可以在当前窗口更新 View 状态，不要求执行跨 Activity 动画。`ValueAnimator` 仍受全局动画开关影响，新转场沿用现有新建路径的开关规则；用户已确认三种新建动画在其卓易通环境正常，无需另设可行性验证阶段。[页内 Transition](https://developer.android.com/develop/ui/views/animations/transitions)、[ValueAnimator](https://developer.android.com/reference/android/animation/ValueAnimator#areAnimatorsEnabled())

因此，不建议仅把现有 `makeScaleUpAnimation()` 替换为平台共享元素调用，就认为卓易通问题已经解决。

## 固定架构与实现边界

- 列表与详情继续由各自 Activity 承载，保持编辑、保存、录音、权限、附件、返回结果及外部入口的既有职责。
- 新增独立的 `ThingDetailTransition` 管理卡片展开与关键元素过渡。现有 `ThingCreationTransition` 的快照传递、首帧显示及清理方式作为复用依据，不改变三种新建动画的视觉规则。
- 动画在目标窗口的应用绘制层内执行，跨 Activity 的平台共享元素转场不作为兼容性基础。
- 不迁移 Fragment，不安排同一 Activity 内承载详情的替代路线。

本轮继续停留在方案阶段。具体公共工具的抽取范围待实施时按已有快照所有权与清理流程确定，不先做无关架构重构。

## 推荐路线的具体过程

### 1. 点击与来源准备

鉴权成功后，按记事 ID 与当前列表投影重新确认来源，记录：

- 卡片在窗口中的真实边界、可见裁剪、圆角和背景，不只记录点击点或 adapter position。
- 可见标题、正文摘要、封面的窗口坐标及显示状态。
- 记事 ID、投影键、媒体来源标识、两端外观版本。
- 一次性列表画面，以及本次过渡必需的元素素材。

来源卡片可能被顶部界面遮挡、只露出半张，或正在按压缩放；起点应使用实际可见状态，避免第一帧先补成完整卡片。鉴权期间列表可能刷新，不能直接使用过期 View 引用。

输入受理应沿用 `UiInteractions`，并覆盖异步准备到启动之间的阶段，避免抓图期间再次受理另一张卡片。来源数据只保存在有大小上限、可失效的一次性内存会话中；Intent 传令牌，不传大 bitmap，也不把页面快照持久化到磁盘。

### 2. 目标页面首帧

本次启动关闭系统 Activity 过渡。目标窗口的第一张应用画面显示来源列表画面，其上是起始卡片状态；实际详情在覆盖层下面完成首屏布局。

沿用新建页已有的快照安装时机和窗口承接顺序，保持首帧连续。接入时核对系统栏样式和 inset 的对应关系；系统栏图标交给系统实时绘制，不重复画进应用快照。这些属于新增转场的常规回归，不重新设为现有承接机制的可行性试验。

只等待本次动画涉及的首屏几何与必要素材，不等待所有附件或全部清单生成 View。目标不足以匹配的元素走降级路径，不为动画强制滚动详情，也不取消 RecyclerView 的回收。

### 3. 容器与内容同时变换

由一个统一进度控制容器和子元素，建议先以约 300～360 ms、无明显回弹的曲线调试，实际时长以观感和首帧等待评估为准。

| 对象 | 过渡方式 |
| --- | --- |
| 外框与背景 | 从卡片实际边界扩展到详情内容区域，圆角连续减小，完整保留纯色或渐变规则；不要只取背景代表色。 |
| 标题 | 两端均可见且能对应时，对齐文字基线、位置与字号；按等比变换处理字形，不跟随容器做横纵不同倍率的拉伸。 |
| 正文摘要 | 保持已有可见文字的位置关系；详情新增部分逐渐显露，截断、省略号和换行差异用短区间交叉淡化。 |
| 封面 | 按同一附件身份匹配实际目标缩略图，连续改变显示矩形与裁剪；不能默认对应第一张附件。 |
| 工具栏、底栏及新增内容 | 随容器展开在后段出现，没有来源对应项时不强行做共享元素映射。 |

推荐新增独立的 `ThingDetailTransition` 及其绘制层，以 Material 容器变换为视觉参照。应用自身控制背景、裁剪和元素绘制，避免容器动画与子元素动画重复绘制同一内容或互相修改 alpha。可先用 `MaterialContainerTransform` 的页内版本做容器效果比较，但不能把它的默认内容交叉淡化当作已经实现逐元素过渡。

普通 View／Canvas 绘制和统一属性动画足以作为首选，不因新建页复用了粒子设施而把粒子模拟或独立 Surface 引入本需求。

### 4. 与真实详情交接

转场末帧使用实际详情的最终几何、颜色、文字排版与媒体占位；在同一次绘制交接中恢复真实控件并撤下过渡层，避免先出现整页截图、下一帧又重新排版。

输入法、编辑光标和详情自动播放在交接后按原有规则恢复。过渡层持有的 bitmap 与真实控件资源要有明确所有权，不复用可变 GIF 解码器或把列表播放器直接移交给详情。异常、中断、后台化与尺寸改变必须释放会话并恢复真实页面的可见性和交互，不能只等待正常动画结束回调。

## 两个需要明确处理的限制

### 文字排版不能全部按同一字形移动

卡片和详情的宽度、字号、最大行数不同。标题可能从两行变一行，正文可能从省略摘要变成完整文本，清单也可能改变结构。对于排版一致的部分可以连续移动缩放；对于不一致的部分，建议在对齐后的局部区域交叉淡化。

第一版不做复杂逐字形重排。画面连续是验收目标，但不承诺所有文字都能完全消除淡化。这也不要求实际复用列表的 TextView 或详情的 EditText。

### 已烘焙裁剪的封面不能直接恢复原图

列表封面可能只保留原图的一小块，详情则显示另一块。若要连续改变取景区域，需要复用已有裁剪计算，从同一媒体来源准备有界尺寸的共同图像，再在上面变化采样范围；不能对已经裁剪的 bitmap 简单插值 imageMatrix。

实际显示帧用于保证起点一致。共同素材未准备好、视频选帧不同、动态封面帧不同、同源附件不在详情首屏或目标未挂载时，先采用局部交叉淡化。动态内容第一版允许在短暂过渡期间保持当前帧，结束后启动详情自身的播放；无缝衔接播放进度是另一项成本更高的能力，不默认包含。

## 返回与特殊情况

返回已于同日完成[专项设计](return-proposal-2026-10-20.md)，尚未实施；以下为方向概述，刷新提交、并发变化及具体边界以专项方案为准。不能直接反放打开时保存的旧坐标。

- 保存或内容变化后，列表需先处理真实结果，再按记事 ID 和投影重新绑定、找到当前卡片。
- 可以在返回接收方 `ThingsActivity` 的首帧用当前详情画面覆盖，待真实列表布局就绪后收回到对应卡片。沿用结果回传，不为提前开始动画绕过保存或确认框。
- 卡片移动后仍在当前页面可见时，收回到新位置；被删除、过滤掉、移出当前页面或完全离屏时，采用短淡出，不为了寻找目标强行滚动列表。
- 进入中立即返回、连续点击、旋转、窗口尺寸变化、进程重建和外部入口均需明确结束状态。外部入口缺少来源卡片时，正常显示详情。
- 私密记事仅在原有鉴权完成后提供对应的可见内容；未揭示的卡片不能在捕获过程中突然露出正文。

## 分阶段实施与验收建议

1. **在现有承接机制上实现容器变换。** 使用真实卡片边界、圆角、背景与详情首屏布局完成展开；回归新增接入的首帧、末帧、系统栏与坐标一致性。保持双 Activity 架构，不另行设立首帧可行性试验或 Fragment 备选。
2. **加入标题与静态封面匹配。** 验证窄卡、宽卡、图上文下、侧图、媒体背景、多附件和不同裁剪；特别核对起点、末帧与真实页面是否一致。
3. **补齐复杂内容和返回。** 覆盖长标题、清单、动态封面、源卡局部可见、鉴权、快速返回、内容更新、旋转及来源失效。

衡量时分别记录「点击到第一帧运动」与「动画持续时间」，不能用播放时长掩盖启动等待；同时看长帧和反复开关后的快照释放。使用现有测试方式验证真实路径，JVM 测试仅覆盖有意义的来源匹配、失效和清理状态，不用源码字符串断言代替视觉验收。

方案阶段仅完成静态核对和资料验证；后续实施进度以上方链接为准。
