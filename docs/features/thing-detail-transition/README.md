# 记事列表到详情页的连续转场

状态：2026-10-21 已实现保留 `ThingsActivity` 与 `DetailActivity` 的应用内展开及返回动画，并完成缓存视频和真实样本的返回等待优化。用户确认现有新建记事的粒子、涟漪和边框光效在卓易通上均交接正常，本功能复用其一次性画面承接机制。

最新 debug `202610210308` 已发布并安装一加 15T、三星和魅族。三类外观按完整 JSON 复用不可变解析结果，保留完整列表重读及现有动画；魅族重复解析中位数 40.57→5.71 ms。三机基础回归 391 项、发布包补测 125 项通过，27 组末帧逐像素一致，669 条原记录和原小组件配置未变。整体首次横屏返回仍有波动，发布包首次无采样为 534 ms，不能将解析收益等同于整体等待已消除。详见 [首次横屏返回的外观解析优化](appearance-parsing-2026-10-21.md)。

此前 debug `202610210122` 已发布并安装三机。必要小组件刷新改为持久化后台工作，实际编辑后仍正确显示最新内容；同一视频封面样本六次返回中位数 501.8→165.3 ms。快速返回从当前展开画面连续收回，三机横竖屏及窗口交接检查通过，六组末帧逐像素一致。669 条原记录和原小组件配置未变。详见 [必要小组件刷新与快速返回](widget-quick-return-2026-10-21.md)。

此前 debug `202610201753` 已发布并安装主设备 Find X9 Ultra。真实按钮复现出未修改记事也刷新桌面小组件、主线程重取视频静态封面造成约半秒等待；跳过这次多余刷新后，六次对照中位数 519.6→158.2 ms。16 次修复后返回及 53 项检查通过，两组末帧逐像素一致。按用户要求只检查“新的测试君”，不做整库备份或创建副本；目标记录和提醒摘要未变。详见 [主设备定向诊断](find-x9-ultra-return-delay-2026-10-21.md)。

前轮 debug `202610201714` 已发布并安装 OPPO 手机、三星和魅族，远端、本地及安装包散列一致。真实样本副本通过返回按钮的等待中位数进一步从约 173／179 ms 降至 155／149 ms（OPPO／魅族）；保留完整动画及两帧稳定检查。追加 746 项检查通过，669 条原记事、其他业务表、累计数量及样本原附件均未改变；测试数据清理、方向恢复及安装后审计通过。平板按用户要求不再操作，该轮尚未连接主设备。详见 [视频封面返回等待优化](video-return-performance-2026-10-21.md)。

此前 debug `202610201543` 已发布并安装四台授权设备。仅对真实详情目标执行展开，将返回来源一次性绑定到实际详情实例，修复计时页误接管及复制 Intent 继承来源。横屏、进入后旋转、通知、嵌套导航及小窗共 2307 项有效检查通过，64 组末帧像素一致；740 条原记事、其他业务表及累计数量均未改变。安装后审计再次通过，远端、本地与安装包散列一致。详见 [横屏、导航及小窗验证](landscape-validation-2026-10-20.md)。

此前已修复返回时真实卡片提前显现、不同换行文字叠画两处残影，并补齐打开动画的进度防倒退；本次保留该动画效果。

此前功能复核已修复返回取消时提前读旧值、完成通知与新写入交错、外部新建结果重复通知三项问题。初始化优化使魅族同方法首次整体等待从约 680 ms 降到 632 ms，仍有后续优化空间；返回动画的耗时不能替代该首次打开指标。

返回动画已实现并完成三机回归。由列表页先等待保存并提交当前展示状态，再按记事身份收回到真实可见卡片；动画期间的新变化在交接后合并呈现，无目标时淡出。655 条原有记事和 1754 项设备检查通过，数据审计保留一组到期习惯的正常推进，详见返回实施记录。

用户反馈当前列表卡片打开详情页的 Activity 放大动画在其卓易通环境不播放，希望由应用实现卡片到全屏详情的连续变换，并尽量让对应元素连续衔接。
