## 修复详情转场与保存、列表更新之间的竞态

用户要求再次全面检查打开和关闭动画是否影响应用功能。沿保存、结果合并、列表刷新、私密认证、输入、媒体播放及生命周期检查，并用专用模拟记事复现了三项问题。

返回准备超时或切后台时，旧清理路径会在保存完成前重载数据库；正常返回也可能漏掉完成通知排队期间新增的写入。两种情况都可能使数据库已保存新内容，而列表及再次打开仍读取旧正文。现在所有退出原因统一等待当前写入完成，新增 SerialWriteQueue 在主线程实际读取前核对写入版本，覆盖等待期间新到来的更新。

另一入口的新建结果与当前详情返回重合时，旧 300+300 ms 回调可能重复通知插入。现在两段回调也纳入统一调度，与返回合并时只发布一次最终差异；普通新建保留原有揭示时序。

私密认证失效仍立即遮蔽当前卡片的正文和附件，不等待保存队列；标题继续遵循既有可见规则。展开和收回的时长、曲线、元素效果及双 Activity 架构不变。

新增三个 JVM 顺序测试，以及慢保存超时、切后台、回调交错、等待期间私密遮蔽和新建结果重合的真机回归。全量 JVM 1719 项，1716 项通过、3 项既有跳过、0 失败。三台指定设备各 100 项、合计 300 项检查通过，包含原有返回变化场景、新建三档、不同裁剪及普通接收更新。新建调度修正后，三星与魅族另各重跑 8 项兼容检查，不重复计入 300 项。
