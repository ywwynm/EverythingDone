## 修复详情转场的导航来源，并完成四机横屏及小窗验证

用户要求补测横屏，并指出“开始做”进入计时页、通知打开详情、详情跳转其他记事或页面，以及进入后旋转、切小窗再返回等场景可能错误播放关闭动画。本轮继续保留两个 Activity 和当前展开／收回效果。

真实导航复现确认：列表重开正在做的记事时，目标是 DoingActivity，却仍生成详情转场；复制详情 Intent 打开第二个详情时，会错误继承第一个窗口的返回来源。新 Intent 替换入口还会留下旧来源。

- `ThingDetailTransition.kt` 仅接管实际目标为 DetailActivity 的打开；计时页保持原有导航方式。
- `ThingDetailReturnTransition.kt` 将来源从 Intent 一次性交给实际详情实例，并核对记事及任务身份，避免复制 Intent 或重建窗口继承错误来源。
- `DetailActivity.kt` 在新 Intent、普通关闭和销毁时清理来源；暂时进入其他页面再回同一详情，仍可正常返回。
- 返回始终使用当前详情画面及当前列表卡片。旋转或小窗导致两端尺寸不一致、系统重建详情或迁移任务时，正常关闭，不套用旧坐标。未添加按厂商、小窗标志或横竖屏分类的生产分支。

OPPO 手机、三星、魅族和新增 OPPO 平板共 2307 项有效检查通过。覆盖 727 条已有可打开记事及独立模拟记事、两侧横屏、旋转后保存、真实计时、普通／突出通知、同记事及不同记事嵌套、设置页往返、列表刷新、私密失效、媒体和新建动画。13 条真实私密记事未解锁，私密路径仅用测试夹具模拟。

四台均完成系统小窗返回；三星和平板完成实际逻辑尺寸调整，OPPO 手机完成显示比例调整。厂商小窗可能固定自身方向或不报告标准多窗口标志，验证按实际行为记录。64 组动画末帧逐像素一致；JVM 1719 项，3 项既有跳过，0 失败。740 条原记事及全部业务表、累计数量与测试前一致；测试数据和设备素材目录已清理。
