## 实施记录

- 三台授权设备在线。新一轮备份和证据独立保存到忽略目录 `tmp/thing-detail-return/`，不覆盖此前展开及等待优化的证据。
- 保存和结果语义沿用现有代码；返回期间集中执行待发布结果，合并列表差异，期间的新呈现请求延后发布。
- 普通卡片与文件夹缩略记事提供统一的身份标记。原有数据仅只读打开，测试修改限本次 ID 与创建时间共同标识的记录。
- 三星首轮静态末帧与实际列表逐像素一致。扩展测试发现目标检查不能依赖 `Adapter.getItemId()`：现有 adapter 未启用该 API，改为校验当前展示条目的身份与 ViewHolder 的绑定位置。
- 删除测试暴露模拟夹具未维护头部占位 ID 的问题，导致旧 DAO 在 ID 冲突后递归重试。已保留中断现场，确认原有记事所有字段未变；仅按夹具 ID、创建时间、全行散列进行恢复，并修正模拟创建的不变量。
- 同时确认返回必须等待原有单线程保存队列完成，再重载列表；否则取消原 540～560 ms 延迟后可能读到尚未写入的数据库。新增真实完成回调，不引入固定等待。
- 三星扩展场景 41 项全部通过，包含搜索移出、文件夹缩略卡／预览模式变化、模拟保存队列延迟、后台与旋转中断后再次打开。
- OPPO 运动采样发现一次 ValueAnimator 进度从 0.731 回到 0.701，现统一保持已显示进度单调。重复点击检查发现第二次未被受理的打开也会替换返回来源，已将来源登记移至输入受理成功之后。
- 列表生命周期会重设系统栏样式，准备期间需持续保持来源详情的图标明暗，运动越过状态栏后再交还列表样式；新增首帧状态栏断言。
- 输入保护延续到动画后的待呈现更新也已发布，避免末帧与列表切换之间按过期位置点击。私密失效使用立即重绑，不通过普通卡片变化动画继续显示旧的已揭示内容。
- 提交返回后，正常返回和状态变更入口拒绝重复执行，避免承接画面捕获期间连续按返回键再次保存。最终专项加入连续返回键、保存时间不重复改变的检查。
