# 返回动画残影诊断

## 用户反馈与复现

用户反馈返回动画有残影。继续保留两个 Activity 和现有容器收回方向；设备操作限此前授权的三台设备，所有写入仅针对本轮模拟记事。

上轮三星 `review-final-return/return-unchanged-frame-2.png` 已清楚呈现同一张卡片、标题和正文在两个位置叠加；`frame-1` 另有正文换行不一致的交叉显示。原有末帧像素对照仅证明动画结束时能对齐，不能排除运动中的重复绘制。

## 待验证假设

1. `progress=0.84..1` 将真实列表直接叠在仍移动的卡片上，提前出现最终位置的卡片。
2. 详情正文和卡片摘要换行不同，两份文字截图交叉淡化造成重复笔画、行。
3. 去除目标后的背景截图仍保留目标卡片，导致整个运动过程中出现重复内容。

先在生产绘制路径上补充可重复的中间帧采样，再分别排除原因；不能仅缩短动画或只测试末帧。

## 已确认的原因

- 三星连续两次重现。固定动画时刻调用真实 `ReturnLayer`，运动中纯色卡片区域本应不透明，旧版最大通道误差达 185/255；检查均失败。
- 单独导出的背景截图没有目标卡片，排除背景捕获重复。
- 仅改变交接时序后，上述两次检查通过。原来按已经过缓动的几何进度 `0.84..1` 混入整张真实列表，此时容器和文字还没到终点；修改为总时长内前 252 ms 收回、后 48 ms 在同一几何位置交接，保持 300 ms 总时长和原缓动曲线。
- 另有独立的正文问题：详情中未换行的后半句与卡片的第二行同时出现。使用真实两端文字位图并仅将墨色分别染红、染绿，检查生产 `drawPart()` 是否在同一帧画出两种排版，作为第二项回归信号。

证据目录：`tmp/thing-detail-return-ghosting/`。`ghost-baseline` 是原版复现；`ghost-handoff` 只修复交接时序，用来区分两项问题。

## 修正与初步验证

- `ghost-text-red` 在仅修复整卡交接的版本上，三组真实正文都检出了 3 个排版重叠时刻，证明文字问题独立存在。
- 返回层新增两端文字的行数和省略状态。单行同文保留基线对齐；其他文字及不对应控件先退后进，避免不同换行同时出现。未引入按记事类型或业务变更原因区分的返回分支。
- `ghost-fixed` 在三台指定设备上各 13 项通过。两次短正文卡片颜色误差均为 0；短正文、长正文的排版重叠帧均为 0。已人工检查三机固定时刻图，确认没有提前出现真实卡片或两份正文。
- 全量 JVM：1719 项，0 失败／错误，3 项既有跳过。

## 回归中补齐打开动画的防倒退

OPPO 的 `authentication-focus-handoff` 真实绘制记录出现 `0.3095802 → 0.27681503` 的展开进度回退。其余功能断言正常，原有数据未变。返回动画已有防倒退处理，但 `ThingDetailTransition` 的更新回调直接采用 `animatedValue`。

打开动画也改为只接收不小于已显示进度的值；不改变时长、缓动和焦点等待。三机重新完成相同的模拟认证、普通打开、媒体播放及已有记录只读用例，64 项均通过。保留首次失败证据，没有以重跑通过覆盖原记录。
