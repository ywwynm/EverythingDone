# 决策状态

## 2026-10-21：确认导航时立即关闭时间弹窗

- 在 `BaseDialogFragment` 增加显式的 `dismissForNavigation()`，仅由已确认的页面跳转使用；普通 `dismiss()` 与取消路径保留现有粒子消散。
- 导航关闭同步清理凝聚、入场效果和暗层，关闭窗口动画，并沿用原交互状态释放流程，避免弹窗退到后台后仍等待消散结束。
- `StartDoingActivity` 确认可开始后，倒序关闭本组时间选择与确认弹窗。通过 `startingDoing` 阻止重复启动，并在目标启动后结束宿主，避免关闭回调提前结束页面。
- 在既有导航探针中检查目标获得焦点时宿主已退出或正在退出，且没有残留粒子层。实施与验证见 [时间选择框粒子退出修复](time-chooser-dismiss-2026-10-21.md)。

## 2026-10-21：按完整 JSON 复用不可变外观

- 卡片外观、详情附件外观与记事背景分别使用有界解析缓存，完整 JSON 字符串决定结果。保留 `Thing(Cursor)` 和当前列表的完整重读，外观变更不依赖更新时间或特定编辑入口通知失效。
- 共享的外观对象及嵌套集合不可修改，编辑继续创建新对象；不缓存 Thing、View、数据库对象、鉴权状态或附件内容。缓存仅驻留内存，不增加数据库写入。
- 每类最多 1024 项、512 Ki 字符；超过 64 Ki 字符的单项直接解析，不驱逐常用值。损坏输入可复用空结果，旧格式及回退语义不变。
- 解析在锁外执行，已缓存读取不等待后台小组件的解析；并发首次读取允许重复计算，发布时合并为同一不可变值。
- 动画、保存顺序、当前列表匹配和私密规则均沿用现有实现。性能结论区分解析成本与整个首次返回，不把缓存命中直接等同于窗口无等待。见 [诊断与验证](appearance-parsing-2026-10-21.md)。

## 2026-10-21：必要刷新后台执行，快速返回承接当前展开画面

- 单记事与列表小组件的广播回调只提交持久化工作。工作按小组件 ID 替换，等待保存队列完成后读取数据库、渲染及提交；移除小组件时取消工作，连续更新使旧渲染失效。清单服务同样只读取已保存对象，并应用有效私密规则。
- 提交返回时不因入场仍运行而直接 `finish()`。冻结当前合成画面、容器几何和圆角，再由原有首页返回转场寻找当前目标。通常返回的元素匹配、动画时长和业务保存流程沿用已有实现。
- 入场覆盖层只额外接受返回按钮区域的完整点击，继续拦截编辑操作；关闭或取消时恢复原窗口输入回调。
- 快速返回时将当前合成帧保留到详情窗口分离，暂停阶段不露出完整详情、不恢复附件播放；分离后统一释放画面。后台与旋转等其他清理路径仍立即结束覆盖层。

## 2026-10-21：无修改返回不重复刷新小组件

- 主设备真实返回按钮复现出约半秒等待，调用栈确认：详情返回广播刷新小组件，小组件在主线程重新解码视频静态封面，阻塞转场截图回调。
- 仅正常返回且 `RESULT_NO_UPDATE` 时跳过小组件刷新。实际编辑、创建、状态改变、碰一碰接收及后台自动保存沿用原有刷新；自动保存不能仅按结果码跳过，使用 helper 默认开启的刷新参数保持原行为。
- 不改变转场视觉、保存或通知流程；只读实测、像素对照和局限见 [主设备诊断](find-x9-ultra-return-delay-2026-10-21.md)。

## 2026-10-21：缩短缓存 GIF 返回准备

- 普通 GIF `ImageView` 的当前帧已经解码，按控件实际矩阵绘制到独立位图；不重新打开 GIF、不共享解码器，也不改播放进度和分辨率。具有背景、前景或自身 outline 的媒体继续走原硬件快照。
- 最新列表已经完成提交后，仍等待连续两个无待处理布局和适配器更新的 `OnPreDraw`，给旧 holder 的清退留出完整帧；截图准备与焦点恢复并行。真正开始缩小仍要求首页取得焦点，超时、隐私失效、窗口变化的取消规则保留。
- 保留 252 ms 几何变化与 48 ms 固定位置交接，不缩短动画掩盖准备等待；保存队列、列表展示版本、身份匹配及后续更新机制不变。
- 真机对照详见 [缓存视频封面返回等待](video-return-performance-2026-10-21.md)。四机共 24 组 GIF 当前帧对照与原硬件捕获逐像素相同。
- 用真实样本追加优化后，将不可见抽屉的文件夹树／统计展示合并到返回交接后、恢复输入前；可见抽屉仍即时更新。无论正常结束、取消还是保存延后，均通过同一收尾位置处理，并在销毁时清理待刷新状态。数据库读取、当前列表和标题刷新维持原有顺序。

## 2026-10-20：返回资格归属实际详情窗口

- 正向动画先校验真实目标组件；工厂返回 `DoingActivity` 时保留其原有打开方式，不捕获详情画面、不生成返回资格。
- 详情初始化只领取一次来源，将它从 Intent 移除并绑定当前 Activity 实例。来源校验同时要求同一任务，避免复制 Intent 后第二个窗口误用卡片来源。
- 新 Intent、关闭和销毁释放绑定；暂时进入设置、附件等页面再返回原详情不取消资格。外部入口本身不携带列表来源，继续执行原有关闭行为。
- 统一按窗口归属处理，不为通知种类、开始做、详情间跳转分别维护特殊返回分支。诊断及真机证据见 [横屏与导航验证](landscape-validation-2026-10-20.md)。
- 旋转、小窗及调整窗口后，仍按返回时的实际尺寸和真实列表决定能否交接；尺寸不一致、实例重建或任务不同则正常关闭，不复用进入时坐标。厂商可能不报告标准多窗口标志，不能以该标志替代实际窗口检查。

## 2026-10-20：返回残影修正

- 返回总时长仍为 300 ms：先用 252 ms 和原缓动曲线完成容器、元素的几何收回，再用 48 ms 在完全相同的位置交接真实内容。不能在尚未到位时叠入真实列表。
- 单行同文继续按基线、字号对齐；不同换行、摘要和不对应内容采用先退后进，避免两套文字排版同帧叠加。同源媒体继续采用原有局部裁剪过渡。
- 不改变保存完成等待、展示版本、身份匹配、取消和输入释放逻辑。
- 回归必须检查中间帧，末帧像素一致不能作为运动中无残影的证明。复现与验证见 [返回残影诊断](return-ghosting-2026-10-20.md)。

## 2026-10-20：功能复核后的保存与呈现顺序

- 取消只结束动画画面，不能跳过保存完成。正常结束、超时、后台和其他取消均在写入完成后发布待处理结果并释放列表输入。
- “写入完成”以主线程实际准备读取时的提交版本为准。若通知排队期间又新增写入，继续等待该版本完成，避免消费了新结果却读取旧数据库。
- 认证失效立即重绑现有展示以遮蔽正文和附件；等待保存不能延长私密揭示状态。保持现有标题可见规则。
- 外部新建结果也纳入统一调度；与返回合并时只由最终差异通知插入，普通新建维持既有揭示时序。
- 三项问题的受控复现、修复与回归见 [功能影响复核](review-2026-10-20.md)。

## 2026-10-20：返回动画方案，待实施

- 用户要求先全面分析返回时的内容、位置及列表变化，并尽量避免按变化原因堆叠分支；本轮仅更新文档。
- 建议以“先提交当前列表，再按身份匹配真实目标，同一动画持有固定展示版本”为统一规则。后续变化只延后呈现，不阻塞业务写入；有目标收回，无目标淡出。这些具体规则尚属建议。
- 源码确认首页多条返回刷新路径仍延迟 540～560 ms，置顶还有二次重绑；旧通知等待队列只保留最后一项且移动通知不受其保护。实施重点是返回接收方的呈现调度，不能仅增加缩小动画或开启现有等待开关。
- 继续保留结果处理中的撤销、庆祝、计数和现有普通更新动画；文件夹缩略记事纳入统一目标匹配。新建三档保持独立。
- 方案、源码依据、视觉规则及后续验收见 [返回专项方案](return-proposal-2026-10-20.md)，本轮未修改生产代码或操作设备。

## 2026-10-20：减少首次打开准备

- 先移除会被替换的系统复选框资源、无媒体时的图标栅格化，按需创建提示条，并延后不参与展开画面的接收入口初始化。
- 初步分段修正不足以稳定降低首次总等待，进一步使用 AndroidX `AsyncLayoutInflater` 与 `AsyncAppCompatFactory` 预创建一份空详情布局、固定内容区和快捷提醒选择器的空 View。首页显示后异步准备，不查询或绑定任何记事。
- 预创建只持有应用 Context；取用时通过 `MutableContextWrapper` 改接真正的详情 Activity。配置不匹配、准备未完成或被回收时直接走同步路径，不让点击等待后台结果。
- 只缓存一份、一次性取用；首页停止和内存告警时清除。真实窗口负责首次测量、inset、焦点、状态恢复与全部业务初始化。
- 保持展开时长、曲线、元素和状态栏交接。预创建的收益和控件兼容性必须用三台真机验证，不用缓存命中本身作为流畅验收。
- 媒体准备最多等待 250 ms；窗口焦点和连续两帧稳定布局不能被此超时绕过，否则慢设备会在首次可见帧之前消耗动画时长。准备整体 1500 ms 兜底在开始运动时移除，不占用 360 ms 运动期。
- 最终保留实测局限：魅族同方法首次整体 680→632 ms，初始化 271→152 ms；普通进程首次仍有较大波动。不靠移除焦点条件或改变动画来制造较短的等待数字。

## 2026-10-20：实现方式

- 通过一次性内存令牌承接列表快照，在目标 Activity 的覆盖层内统一驱动容器、文字和同源封面，时长 360 ms。系统 Activity 动画关闭，View 不跨 Activity 迁移。
- 整屏画面在 API 29 及以上优先保留硬件位图；捕获失败、来源失效和缺少来源的外部入口均可正常打开详情。
- 目标尺寸、媒体和窗口焦点准备有时间上限，正常结束、返回、后台及尺寸变化统一清理。详情动态附件只暂缓播放，不修改用户播放设置。
- 字体排版及媒体裁剪不一致时使用局部渐变，本轮不实现逐字形重排、共同原图取景插值、播放进度共享或反向收缩动画。
