# 触摸波纹回归

用户反馈内框修正版后，卡片触摸 ripple 消失。上一轮真实触摸像素对照在点击后又记录了一次真实首页，可能提前初始化原生波纹，不能证明首次捕获正确。

新增不提前绘制来源的真实触摸探针，分别使用 0、48、120 ms 的按下时长；只包装本次模拟卡片的前景，记录生产捕获期间实际调用的透明度，并保存实际来源图。验证只使用模拟记事，原记事保持只读。

## 复现与原因

一加基线 11 项检查中的三种触摸均失败。首次真实遮罩 alpha 从 255 被改为 0，后两次开始时已是 0；前景接收到的 alpha 写入均为 `[0, 0]`，来源图没有波纹。不是单纯的截图时机问题，遮罩已永久改变。

Android SDK 本地源码确认：`LayerDrawable.getAlpha()` 返回第一个非空子层的 alpha；卡片原生 ripple 的第一层是透明内容、第二层才是白色 mask。`drawOwn()` 保存到的 0 并不代表所有子层都为 0，恢复时 `setAlpha(0)` 却会写入包括白色遮罩在内的全部子层。

去除来源投影只需拆开父链，在独立卡片节点中将高度归零；卡片自身无需拆开。调整受影响路径的选择，使卡片原样绘制一次，避免改写前景、重复消费首次绘制，也保留卡片原有的内部绘制行为。其余捕获路径保持原选择，内框外侧裁剪继续生效。

## 定向修复验证

一加定向检查 11 项通过，三种时长的遮罩始终为 255，捕获期间不再写入前景 alpha。120 ms 按住时的真实窗口与展开来源画面均可见原生波纹。窗口采样使用异步 PixelCopy，不重新调用来源 View.draw，也不在松手前压缩 PNG，避免采样本身提前初始化波纹或把短按拖成长按。

诊断包装层必须在 View.setForeground 清除旧前景回调后，重新连接被包装 Drawable 的 callback，否则探针自身就会阻止原生波纹的失效重绘。此修正在 debug 探针内，生产前景不做包装或替换。

最终合并验证覆盖深色、浅色、高对比渐变、0／48／120 ms 实际触摸，以及横竖屏、连续阴影与快速返回；只使用专用模拟记事，逐轮核对原记录及统计缓存。
