# 普通工具栏范围操作的粒子退场

## 范围与验证方法

用户要求全部完成、已完成恢复、全部删除、回收站恢复和全部彻底删除复用多选动画。保持当前范围、类型／搜索筛选、Doing 保护和回收站恢复语义。使用现有独立包 `com.ywwynm.everythingdone.batchvalidation` 的真实 ThingsActivity 和确认弹窗，扩展探针走普通工具栏菜单分发；先记录失败样本，再验证修改。

## 候选原因

1. 范围操作在确认后直接写库并全量刷新，绕过 `animateHomeListRemoval`。若成立，同一菜单路径不会出现批量退场；改接共享入口后应出现卡片粒子和延迟差分。
2. 普通模式不满足粒子来源筛选。若成立，接共享入口后业务与差分正常，但没有可见卡片来源。
3. 确认框的消散覆盖卡片动画。若成立，存在批量动画实例，但卡片粒子先于确认框完全关闭。共享入口已有等待逻辑，实测分别检查确认框与卡片退场。

本次是明确的入口遗漏，复用已有探针，不扩展为粒子渲染性能诊断。

## 复现与修改

三星隔离包经普通 Toolbar 菜单分发与真实确认按钮执行「全部完成」，6 条虚构记事的状态变更全部成功，但 143 帧记录中没有卡片退场粒子，断言「普通工具栏未播放卡片粒子」失败。证据：`tmp/selection-transition-20261013/toolbar_baseline_asserted_1015/`。此前首次录像样本也未出现退场；其业务 ID 采集遗漏已在第二次复现前修正。

确认原因是候选 1：`applyFinishScope` 仅在选择模式复用入口，其余四个确认回调直接执行 DAO 操作与全量刷新。生产修改仅将这些入口统一到 `applyUnionStateChange`；不新增渲染实现。
