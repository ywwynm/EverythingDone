# 批量退出后的媒体与子控件恢复

## 反馈与验证缺口

用户在更新 `202610122152` 后反馈：批量动画完毕，继续上下滚动，有些媒体卡片背景已恢复正常，但图片／视频区域仍有未选中的淡化效果；要求一起核对正在做标识及其它子控件。

上一轮矩阵覆盖阶段顺序、当前位置卡片的颜色与移动，虚构记事主要为纯文字，未充分覆盖真实媒体遮罩和退出后缓存 holder 的重新挂载。本轮在真实首页隔离测试包加入本地图片、GIF、视频，以及正在做、不同媒体布局与内容控件；退出后反复滚动并检查每个子控件的可见性／透明度、媒体就绪状态及实际截图。

## 验证范围

正常绑定、批量局部绑定、已绑定的缓存重新挂载、回收后改绑需恢复同一外观。媒体自身的背景遮罩强度属于用户外观设置，不能当作选择遮罩清空；正在做标识必须保留且不能使业务操作误完成正在计时的记事。仍保留 SurfaceView 与原交接顺序，不通过整体重载媒体恢复外观。

## 复现与可证伪的候选原因

三星隔离包 `appearance-baseline-samsung-03` 复现 5 次子控件不一致：批量完成后 `view_thing_image_cover` 仍为 VISIBLE／alpha=1，而正常参考为 GONE。涉及左侧 GIF 与底部视频等媒体；正在做记事被保护保留。首轮被隔离包媒体权限弹窗挡住；第二轮跳转到顶部后再检查，触发了完整重绑而掩盖问题，因此改为从当前画面开始连续往返滚动，不用重绑替代恢复。

1. 局部选择外观只更新根背景和普通 alpha，图片遮罩可见性仍只在完整媒体绑定中更新。预测：把遮罩纳入连续选择外观后，当前屏幕残留消失且不需要重新解码。
2. 恢复动画只遍历当前 child，缓存中的已绑定 holder 可能停在中间值。预测：在真实缓存重新挂载时检查并校正外观，能消除滚动后残留；不必反射访问 RecyclerView 缓存。
3. 特殊标识还含独立资源／可见性状态，单纯将根 alpha 恢复为 1 不够。预测：与进入选择前逐控件比较，可区分图片遮罩遗漏、Doing 蒙层透明度遗漏和置顶／常驻通知资源未恢复。

## 修正与扩大检查

- 三星第二组文件夹内删除同样复现图片遮罩残留。单独构造退出动画中途离屏的缓存用例，复现 48 次文字、附件计数与音频区域 alpha 残留（约 0.656）。修正图片遮罩进度和 holder 挂载恢复后，两类用例通过。
- “正在做”缓存专项在约 alpha=0.806 时移出屏幕，确认原 holder 已脱离再挂回，最终 alpha=1、标识仍可见；业务批量完成会保留它的 UNDERWAY 状态。
- 正常参考快照须先关闭测试数据的逐卡入场延时，否则参考项可能暂为 INVISIBLE，使子控件比对失效；媒体背景必须单独等待 drawable 就绪，不能只看图片的 loading 控件。
- 增加真实提醒、习惯、私密、清单、音频、置顶／常驻通知的测试项，并开启隔离包的直接勾选清单设置。复现保留清单的 `ll_check_list_tv` 从正常 clickable=true 变为 false，说明局部绑定还遗漏了模式交互。修正为重设清单回调并只刷新现有行的点击目标，不调用清单 bind、不改变布局或媒体。
- 完整媒体背景的用户遮罩 alpha 保持不动；置顶／常驻通知图标和 Doing 状态在局部绑定／重新挂载时按最新模型同步，不在粒子帧循环中重载资源。

## 四列媒体列表的补位检查

OPPO 横屏四列、底部混合选择的恢复／普通淡出用例中，外观比对通过，但阶段断言发现保留项 `8000006` 的 x 从 1280 跳到 42，同时 alpha 从 1 变为 0，约 300 ms 后才淡入。尺寸始终为 577×721；本轮挂载更新没有改根 alpha 或坐标。不能把最终颜色通过当作全部表现正确。

优先验证预测布局将旧可见 holder 标记成新插入项的原因；候选仅在批量交接的下一次布局关闭预测布局，继续启用真实前后位置的移动动画，不清空已有 span 分配。尺寸未变化，不支持“媒体解码后尺寸变更”这个候选；挂载函数不改根位置／alpha，也不支持它直接设置了错误坐标。

关闭单次预测布局的实测仍有同一张卡片 alpha=0／重新插入，且改变列分配；该候选已撤回。改为在批量业务变更前记录仍可见、最终保留的稳定 ID 及真实位置，仅本次交接用 `ThingListRetainedItemAnimator` 将这些 ID 的 add／move 从真实原位开始。动画参数沿用原 ItemAnimator；结束或中断后恢复原实例与 change-animation 设置。原来不在屏幕内的卡片仍按正常新增／出现处理，不使用全列表固定坐标。
