# Selection Batch Actions Decisions

## 2026-06-27 - 搜索态选择操作完成后不得跳出搜索结果

搜索模式下的选择操作完成后，列表刷新必须维持当前搜索文本和颜色筛选。纯记事、纯文件夹、记事+文件夹混合选择都遵守同一规则：先按搜索范围决定动作影响哪些记事或文件夹，再按同一搜索范围刷新结果列表和 no-result 状态。

对文件夹属性或结构位置的批量操作（移动到文件夹、置顶、设为私密）如果需要调用 manager 中原本会 `loadThings()` 的方法，应通过 reload 开关延迟刷新，由 Activity 统一恢复搜索投影；对状态类内容操作，确认后也要通过搜索感知的 scope refresh 收尾。

## 2026-06-27 - 结构操作确认提示合并搜索范围

选择模式下的结构操作（解散文件夹、永久删除文件夹容器、含文件夹的结构性永久删除等）作用于整个文件夹子树，不受当前搜索结果范围限制。若用户在搜索模式中触发这些操作，确认弹窗的隐藏范围提醒必须把“搜索范围”与既有状态筛选、类型筛选合并到同一句提示中，例如“该操作作用于整个文件夹子树，包含当前状态和类型筛选（回收站、记录）以及搜索范围下看不到的内容。”

这条规则不同于内容类状态操作：内容类操作在搜索中只处理搜索范围内实际命中的记事；结构操作处理容器及其完整子树，因此搜索范围提示是警告式而不是“本次操作仅作用于……”式安抚提示。

## 2026-06-27 - 搜索模式下内容类选择动作受搜索范围限制

在首页搜索结果中进入选择模式后，完成、删除、恢复、永久删除等影响记事状态或生命周期的动作，只作用于当前搜索范围内的记事。纯记事选择天然已经来自搜索结果；包含文件夹的选择则只收集所选文件夹子树中实际命中当前搜索关键词和颜色筛选的记事，不因文件夹标题或文件夹颜色自身命中而连带处理夹中其它记事。

确认弹窗的范围提醒由 `HomeActionWordingHelper` 统一生成。若同时存在类型筛选和搜索范围，合并成同一句“本次操作仅作用于当前类型筛选（X）和搜索范围内的记事……”，不再追加第二段独立提示；仅搜索范围时显示“本次操作仅作用于当前搜索范围内的记事……”。范围提醒统一使用“本次操作仅作用于”开头。

## 2026-06-23 - 状态动作标题应包含当前状态限定，作为确认弹窗正文的语义来源

状态类批量/范围动作的 action 文本不再只写短对象（如“完成文件夹中所有记事”），而应包含当前状态限定，形成完整语义句，例如“完成所选文件夹中所有正在进行的记事”。确认弹窗标题应与 action 文本一致，确认弹窗正文应继承该文本，形成“将[action 文本]，共 N 件……”的句式；确认按钮统一使用通用 `confirm` 文案，中文保持“确定”。

理由：此前 action 标题、dialog 标题、dialog 正文分别从不同字符串和路径生成，导致“文件夹中所有记事 / 所选文件夹中的所有记事 / 所选文件夹的所有正在进行的记事”等漂移。让 action 文本本身成为完整作用描述后，可由单一 `ActionWording` 生成 action title、dialog title、dialog body，避免各入口各自补词。

## 2026-06-23 - 范围短语统一用“中”，不用“的”承接

状态动作的目标范围短语统一使用“中”表达范围归属，例如“所选文件夹中所有正在进行的记事”“所选项中所有正在进行的记事”“当前文件夹中所有正在进行的记事”。避免使用“所选文件夹的所有……的记事”“所选项的所有……的记事”这类双“的”结构。

## 2026-06-23 - 确认弹窗正文也必须由统一文案模型生成

确认弹窗正文不能再由各调用点分别拼接或选择资源串；正文、数量、子文件夹提醒、类型筛选提醒、可恢复/不可恢复提醒都应由同一个 `ActionWording` 生成。基础句式为“将[action title]，共 N 件……”，后续提示作为标准化片段追加，例如子文件夹命中提示和当前类型筛选提示。

理由：只统一 action title 不足以消除漂移。此前正文中“所选文件夹的所有……”“所选项的所有……”等表达来自独立 body 模板；若正文不继承同一个 action title，仍会重新出现标题与正文不一致。

## 2026-06-23 - 子文件夹命中提示属于数量解释，放在数量后

内容操作命中子文件夹中的记事时，子文件夹提示放在数量后面的括号中，例如“将[action title]，共 N 件（包含所有子文件夹中的记事），可在回收站恢复。”未命中子文件夹时省略该括号。类型筛选提醒不放入同一句，而是另起一行追加。

## 2026-06-23 - 统一文案模型必须支持国际化，且不得放进 ThingsActivity

`ActionWording` / 状态动作文案生成逻辑应从 `ThingsActivity` 中拆出，作为独立 helper / formatter 维护。它可以接收 `Context`、动作语义、目标范围、数量、子文件夹命中、类型筛选等参数，但不能用中文顺序在 Kotlin 中硬拼完整句子；完整句式必须由 Android string resource 模板承载，以便不同语言调整词序、介词、复数和提示结构。

实现约束：`ThingsActivity` 与 `ModeManager` 只负责提供语义输入和显示 `ActionWording` 结果；action 标题、dialog 标题、dialog 正文、确认按钮文本都应来自该统一结果。

放置位置：`app/src/main/java/com/ywwynm/everythingdone/helpers/HomeActionWordingHelper.kt`。它属于 Home 列表业务 UI 文案 helper，不应放在 Activity 内，也不应作为通用 `StringUtil`。

## 2026-06-23 - Action title 也必须由完整资源模板生成

状态动作的 action title 不能在 Kotlin 中通过“动词 + 目标范围 + 状态 + 记事”硬拼。每个语义组合应由 Android string resource 模板承载，例如中文可为“完成%1$s中所有正在进行的记事”，英文可自行调整为“Complete all underway things in %1$s”。确认正文再引用已经生成的 action title。

代价是资源字符串数量增加；收益是词序、介词、状态词和对象词均由各语言资源控制，避免国际化时被中文语序固定。

中文资源里的数字和单位之间不加空格，例如“共%1$d件”“%1$d个子文件夹”。其他语言如果需要不同词序、冠词、介词或复数形式，应在完整 string resource 模板中处理，Kotlin 不拼接完整中文式句子。

目标范围短语也按语法用途分开维护：状态内容操作使用一组目标资源（用于“在/中某范围内处理记事”），结构操作正文使用另一组目标资源（用于“解散/永久删除某文件夹”）。这样德语、俄语等需要不同格或介词的语言不必复用同一个目标短语。

Root scope 与直接选中记事不能套用“%1$s中所有……”模板：root 用专门模板（如“完成所有正在进行的记事”），直接选中记事用专门模板（如“完成所选记事”），容器类范围（当前文件夹、所选文件夹、所选项）才使用容器模板。

## 2026-06-23 - 统一文案 helper 覆盖状态动作、属性切换与结构动作，但三者模板分开

统一文案 helper 的覆盖范围不应只包含完成/删除/恢复/永久删除，还应覆盖置顶、设为私密、解散文件夹、结构性永久删除文件夹等 Home 列表 action。但这些 action family 不能共用同一套模板：

- 状态内容动作：使用完整语义标题，例如“完成所选文件夹中所有正在进行的记事”，正文继承 action title。
- 属性切换动作：保持短动词式标题，例如“设为私密”“取消设为私密”“置顶”“取消置顶”，不强行写成“设为私密所选项”。对象细节可在必要的鉴权/错误提示中表达。
- 结构动作：使用结构专属模板，例如“解散所选文件夹”“永久删除所选文件夹”，正文说明容器被删除、内容处理方式、影响数量和不可恢复性。

可见性判断仍归 `ModeManager` / 业务逻辑负责；helper 只负责在动作可用时生成 action title、dialog title、dialog body、confirm text。

## 2026-06-23 - 批量动作采用"按每项类型分别执行"的统一语义模型

选择模式下，当选中集为"多文件夹"或"记事+文件夹混合"时，批量动作采用统一模型：
一个动作词对选中集里的每一项执行其类型对应的语义，工具栏里同一动作只保留一个入口。

例如：
- 完成 → 选中记事置为已完成 + 每个选中文件夹递归"完成夹中所有记事"（内容操作）。
- 删除 → 选中记事移入回收站 + 每个选中文件夹"删除夹中所有记事"（容器不动）。

理由：
- 数据模型（`Thing.selected` / `ThingFolder.selected`）与单文件夹内容操作
  （`confirmFinishAllThingsInScope` 等）都已存在，本模型只是把"1 文件夹"推广到"N 文件夹 + M 记事"。
- 用户预期"全选→完成/删除"一次到位；保守模型会让混选后动作突然消失，造成困惑。
- "文件夹删除 = 删除夹中所有记事、容器不动"在单文件夹场景已确立（use-cases T1），统一模型与之一致，不引入新概念。

代价：选中文件夹卡片点"删除"删的是其内容而非容器本身——与现有单文件夹行为一致。

被否决的方案 B（保守模型）：混合时只放开无歧义动作（置顶/私密/移动），完成/删除/恢复仍要求纯记事或单文件夹。

## 2026-06-23 - 批量动作的边界：内容/状态操作批量化，结构操作保持单选专属

纳入批量（支持多选 + 混合）的动作：完成、删除、恢复、永久删除、移动到文件夹、设为私密、置顶。
其中文件夹的"完成/删除/恢复/永久删除"走内容操作语义（递归处理夹中记事，容器不动，跟随当前类型筛选）；
"永久删除"对文件夹也是内容操作（永久删除夹中所有记事），不销毁容器。

保持单选专属（多选/混合时不出现）：
- 卡片外观：编辑面板针对单一目标，无法对异质集合调参。维持仅单个记事或单个文件夹。
- 解散文件夹（结构）：破坏性强、低频整理操作，"多夹一起解散"无真实场景。维持单文件夹。
- 永久删除文件夹容器（结构）：销毁整棵子树。维持单文件夹；与回收站里"永久删除（内容）"是两个不同入口。
- 导出：维持只导出选中记事，混选时忽略文件夹，不递归导出夹内记事。

理由：结构操作破坏性大、低频，批量化只会放大误操作风险；纳入批量的 7 个动作语义对两种类型都清晰。

## 2026-06-23 - 切换型动作（置顶 / 私密）批量方向采用"智能置位"

置顶、私密在批量时，方向判定为："选中集里只要还有未置位的项，就全部置位；全部已置位时才全部取消。"
工具栏图标/文案据此显示目标方向。置顶与私密复用同一套判定逻辑（单选是 N=1 的特例）。

被否决：逐项翻转（混合现状下结果难预测，易误操作）。

## 2026-06-23 - 批量"设为私密"的不合格项处理与鉴权

- 置位方向遇到不合格项（空标题记事、正在计时的 doing thing）：跳过这些项，把能设的都设为私密，
  结束后一句话提示"X 项未能设为私密（标题为空或正在计时）"。不因个别不合格项整批失败。
- 无密码且方向为置位：弹一次"请先设置密码"并中止（与单选一致）。
- 取消方向：整批只鉴权一次，验证通过后取消所有选中项（含记事与文件夹）的私密。借此统一现有不对称
  （此前记事取消私密需鉴权、文件夹取消私密不需鉴权）。

## 2026-06-23 - 批量状态变更走确认弹窗、无撤销（权威记录见 undo-to-confirm-dialog / ADR 0005）

"全局移除撤销 snackbar、状态变更改为操作前确认弹窗（单条滑动手势除外）"是 App 级决策，
权威记录见 `docs/features/undo-to-confirm-dialog/` 与 `docs/adr/0005-replace-undo-snackbar-with-confirmation-dialog.md`。
对本 feature 的影响：

- 选择模式的批量动作（含纯记事批量、仅 1 项的选择）都走确认弹窗，不再有撤销 snackbar。
- 确认弹窗数量文案用拆分表述："完成选中的 M 件记事，以及 N 个文件夹中的所有记事，共 K 件（含子文件夹）"，
  并保留"仅作用于当前类型筛选（X）"安抚句（文件夹部分跟随类型筛选）。
- 习惯/目标三选项弹窗：主确认弹窗之后、当并集含习惯/目标时出现一次，作用于整批并集。
- 不变量：选中项都是当前投影里的同级兄弟，选中文件夹后代不会同时被选中，故"选中记事 + 各选中文件夹
  递归内容"两集合天然不重叠，无需去重。

## 2026-06-23 - 批量"移动到文件夹"的规则

- 禁止目标：目标不能是任何选中文件夹本身，也不能是任何选中文件夹的后代（取并集）。
  即不能把文件夹移进自己/子树，也不能移进一个同时被选中的文件夹。
- 弹窗强调色：混合批量无单一归属色，用 App accent 渐变（`App.defaultAccentBackground`）。
- 跨私密边界鉴权：移动跨越私密边界（移入私密文件夹、或把私密项移出）时整批只鉴权一次。
- 预选目标：选中项可能来自不同父级，移动弹窗默认选中"全部记事"根节点，由用户改选。

## 2026-06-23 - 工具栏每个动词合并为一个自适应文案的菜单项

模型 A 下混合选择时每个动词只能有一个入口。每个动词合并为一个菜单项，文案随选中集自适应：

| 动词 | 纯记事 | 仅单文件夹 | 多文件夹 / 混合 |
|---|---|---|---|
| 完成 | 完成 | 完成文件夹中所有记事 | 完成所选项 |
| 删除（进行中） | 删除 | 删除文件夹中所有记事 | 删除所选项 |
| 恢复（已完成/回收站） | 恢复 | 恢复文件夹中所有记事 | 恢复所选项 |
| 永久删除（回收站） | 永久删除 | 永久删除文件夹中所有记事 | 永久删除所选项 |
| 移动到文件夹 | 移动到文件夹 | 移动到文件夹 | 移动到文件夹 |
| 私密 / 置顶 | 自适应设为/取消 | 自适应 | 自适应 |

弹窗内用拆分文案说明具体影响。被否决：保留按类型分的多个项（混合时仍须临时合并，等于做 A 的一部分）。

范围约束（维持现状）：
- 置顶、私密、卡片外观仅在"正在进行"状态可用（已完成/回收站多选不出现）。
- 卡片外观、解散文件夹、永久删除文件夹容器仍是单选专属。

> 注：上表文案为当时方案，后续已进一步统一（动词在前 + 所有、混合用"所选项中的记事"消歧等）。
> 文案的权威现状见 `wording-matrix.md`，演进见 `sessions.md`。

## 2026-06-23 - 卡片外观/私密/置顶仅"正在进行"可用

卡片外观、设为私密、置顶三项仅在"正在进行"状态提供；已完成、回收站不提供。私密、置顶此前已是
仅正在进行（sticky 仅在 underway 菜单、private 有 `limitIsUnderway` 判断）；卡片外观此前对单条记事在
回收站漏开（`canCustomizeSelectedThingCardAppearance` 只挡了已完成），现加 `status==UNDERWAY` 判断收口。

## 2026-06-23 - 回收站新增结构性批量永久删除，与内容操作区分

回收站里对含文件夹的选择，提供两个区分清楚的永久删除：
- 内容操作「永久删除…中的记事」（`act_delete_selected_forever`，作用于回收站里的记事，容器保留，跟随类型筛选）。
- 结构操作「永久删除文件夹 / 永久删除选中的文件夹 / 永久删除所选项」（`act_delete_thing_folder` 推广为
  `hasFolder && deleted` 可见，文案随单/多文件夹/混合自适应）：真正销毁选中文件夹整棵子树（所有状态/类型）
  + 选中记事，不可恢复，确认弹窗强提示"含当前筛选下看不到的内容"。

执行：`confirmDeleteSelectedStructural()` —— 单文件夹复用 `showDeleteThingFolderForeverDialog`；
多文件夹/混合聚合 `countDescendantFolders`/`countAllDescendantThings` 计数后，逐个 `deleteFolderForever`
+ `deleteThingsForever(选中记事)`。这是"永久删除文件夹容器仍是单选专属"的修订：结构性永久删除现支持多选与混合。

## 2026-06-25 - 选择操作确认弹窗按单选/多选配色（修订移动弹窗"混合用 accent"）

选择模式下移动到文件夹、完成/恢复、（结构性）永久删除等确认弹窗的标题与确认按钮配色统一为：

- 单选（只选 1 个记事或文件夹）→ 用该项自身的颜色（`getBackground() ?: pure(getColor())`）。
- 多选（多个记事/文件夹/混合）→ 用当前所在文件夹的颜色（`getCurrentFolderBackgroundForChrome()`），
  根目录则用 accent+accent2 渐变（`App.defaultAccentBackground`）。

由 `ThingsActivity.selectionDialogBackground()` 统一表达：按当前选中数判定单/多选。移动弹窗经
`MoveToThingFolderDialogFragment.setAccentBackground` 接收；完成/恢复（`confirmThingsOnlyStateChange`
/ `confirmMixedStateChange`）与结构性永久删除（`confirmDeleteSelectedStructural`）经
`AlertDialogFragment.setTitleBackground` / `setConfirmBackground` 接收。单文件夹专属弹窗
（`showMoveThingFolderDialog`、`showDeleteThingFolderForeverDialog`）本就用该文件夹颜色，是单选分支。

修订：本条取代上面 2026-06-23"批量移动到文件夹的规则"里的"弹窗强调色：混合批量用 App accent
渐变"——混合/多选现按当前文件夹色，仅根目录退回 accent 渐变。
