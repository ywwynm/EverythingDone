## 修复首页批量操作的粒子退场、选择模式退出与列表补位

根据另一台 OPPO 手机的两段视频，修正首页批量完成、恢复、删除、彻底删除后的状态栏图标提前变色、菜单提前消失、退出与颜色恢复动画缺失、工具栏阴影加深及剩余卡片跳动。保留 SurfaceView、动态背景和既有粒子表现；原应用内对照、显示诊断和 ZIP 导出继续保留。

- 确认弹窗和粒子整页前景完整释放后，才派发列表差分并退出选择模式。真实 View 接管的同一次交接中隐藏已移除卡片，防止闪回；输入封锁延续到工具栏、卡片补位和布局稳定。
- ModeManager 保留工具栏菜单至退场结束，系统图标按可见状态切换，普通阴影在旧阴影移开后渐显。未选记事和文件夹的颜色、透明度连续恢复。
- ThingsAdapter 保留项仅更新必要外观，避免重载媒体和取消位置动画；ActivityHeader 只更新计数，避免标题占位二次改变。动画时钟在布局完成后启动，较慢设备的布局准备不会吞掉动画。
- 实测另外发现文件夹内批量彻底删除会由不同 SQLite 连接互等而回滚，已在 ThingDAO 的同一写事务内更新容器时间。
- 魅族旧实现也存在系统二次反色：浅绿卡片被绘成深紫，颜色动画开始才恢复。已验证由 App 声明自行处理深色配色后，原生背景和 Canvas 像素恢复一致；继续使用应用原有浅色／深色设置，不增加动画兼容模式。

三星、魅族、OPPO 平板共 36 组核心矩阵通过，覆盖根目录／文件夹、顶部／中段／底部、可见／混合／全不可见选中项、移空列表、两种粒子及普通淡出；另补纯色／渐变、浅深外观、三机返回中断、关闭系统动画。全部使用独立测试包的虚构记事，未改动既有记事。1448 项 JVM 测试为 0 失败、1 跳过。

三星与魅族核对代表性录像；OPPO 平板使用实际截图和逐帧 View 状态，未取得可靠录屏。用户视频中的 OPPO 手机和卓易通仍由用户安装复测，不把回调通过等同于所有设备画面完全一致。
