## 修复批量操作后媒体残留淡化、缓存卡片和子控件恢复

上一版批量转场结束后，继续上下滚动可能出现卡片颜色正常、图片或视频仍变淡。本轮复现确认：局部外观更新遗漏了媒体选择白罩，动画中途离屏的缓存卡片还可能保留透明度中间值；扩大检查又发现保留清单的点击状态未恢复。

- BaseThingsAdapter 将媒体选择白罩纳入连续恢复进度；ThingsAdapter 在局部更新及已绑定卡片重新挂载时统一恢复外观，并同步正在做、置顶／常驻通知等标识。媒体背景的用户遮罩保持原强度，不通过重新加载媒体解决。
- ThingCardChecklistView 只刷新现有清单行的点击目标，遵守直接勾选设置和正在做保护，不重建布局；通过真实触摸和数据结果核对。
- OPPO 四列媒体列表的补位测试还发现，旧可见卡片可能被当成新增项先隐藏。ThingListRetainedItemAnimator 仅在本次批量操作中保留这些卡片的真实起点，使其连续移动；结束或返回中断后恢复原列表动画器。
- 保留 SurfaceView、动态背景、粒子释放后再退出选择模式和列表补位的顺序，以及应用内对照和诊断导出。

三星、魅族、OPPO 平板各 9 例、共 27 例通过，覆盖根目录／文件夹、不同滚动和选中位置、五类批量动作、两种粒子及普通淡出、移空列表和返回中断。24 例媒体／子控件往返滚动审计无差异；正在做标识缓存返回恢复正常，正在计时的记事不会被误完成；21 例正常转场通过阶段及位置连续性检查。1448 项单元测试为 0 失败、1 跳过。

破坏性测试只作用于独立测试包的虚构数据，未改动既有记事。三机核对代表性截图；OPPO 平板补位以过程截图和 View 逐帧记录核验，未取得可靠录像。另一台 OPPO 手机及卓易通仍请安装本包复测。
