### 一处措辞：初稿写反了，已更正并单独发过一版

第 3 条的说明初稿是用户逐字给的「标准精度使用 **8 位浮点数**表示颜色…高精度使用 16 位」，
先按「明确指令即定案」原样采用并把出入记在这里；实现里这一档是 `SRGB8_ALPHA8`（8 位定点），
只有「高」那一档的 `RGBA16F` 才是浮点。用户随后裁定改成：

> 标准精度使用 8 位**整数**表示颜色，计算压力更轻；高精度使用 16 位**浮点数**，过渡更细腻。

13 个语言目录同步按同样的信息量意译（英文 `8-bit integer` / `16-bit floating point`），
**代码与默认取值一个字没动**，单独发了一版 `202609180332`（见第 8 节）。

## 2 卡片：完成 → 倒放回来

### 为什么撤掉第六批的做法

第六批让这一页的滑动**永远判不成完成**（`getSwipeThreshold` / `getSwipeEscapeVelocity` 都返回
`Float.MAX_VALUE`），松手一律走 `ANIMATION_TYPE_SWIPE_CANCEL`。那样绕开了「判完成之后 itemView
归待清理队列管」的麻烦，代价是**半程松手不再自动播完**，与首页的手感不是一回事——正是用户这一条
要改的。

### 做法

三个覆写（阈值、甩动速度、回位时长）**全部删掉**，回到 `ItemTouchHelper` 的默认值，也就是首页那一套：

- **没过阈值**：松手走 `SWIPE_CANCEL` 的回位动画，`onChildDraw` 每帧位移单调回零，
  `ParticleSwipeAnimator.draw` 据此把相位倒放回 0，粒子沿原轨迹聚回卡片。这一段与第六批相同。
- **过了阈值**：`onSwiped` 里先 `swipeAnimator.finishSwipe(itemView, list.width) { … }`，
  与首页逐字相同——把剩下那一段按 420 ms 的速率播完，卡片彻底消失。
  完成回调里 `adapter.notifyItemChanged(0)` 换上一张新 View，再交给
  [ThingSwipeReturn]`.start(0, particles = true)` 以 `appearContent(appearanceDirection = 180f)`
  把粒子从左侧聚回卡片——**与首页「卡片留在列表里」的回位是同一条代码**。

`ThingSwipeReturn` 加了两个可选参数，都不改首页的行为：

- `alwaysParticles`：这一页的左滑本来就绕开「滑动完成记事动画风格」那一项设置、永远用粒子，
  回位当然也不能因为用户把首页风格设成「滑动」就变成滑回来；
- `start(…, onSettled)`：回位真的结束时回调一次，设置页靠它解锁滑动。

### 锁与解锁

`returning` 表示「松手之后的收尾还没走完，不接受新手势」，由页面自己的 `OnItemTouchListener`
吞掉整个手势（**必须先于 `ItemTouchHelper` 注册**，第六批已经踩过）。新增的 `condensing` 表示
「卡片已经彻底消失、正在聚回来」：

- 没过阈值那一条由 `clearView` 解锁；
- 过了阈值那一条**不能**由 `clearView` 解锁——它是被 `notifyItemChanged` 换下旧 View 触发的，
  那一刻粒子才刚开始聚回来。所以 `clearView` 只在 `!condensing` 时解锁。
- 另有一道看门狗，两档标称时长：松手到卡片消失 1800 ms（回位 250 + 播完 420 + 等末帧 700 + 余量），
  卡片回来 2400 ms（以 `ThingSwipeReturn` 自己那道 2000 ms 兜底为准）。都按设备的动画缩放放大，
  **缩放小于 1 时不跟着缩短**——看门狗宁可晚到也不能早到。

## 3 对话框：播一轮就停，点按钮重播

### 步数与一条奇偶性

自动播放排三步：**出现 → 消散 → 出现**，之后静止在可见态，不再循环；点「稍后 / 继续」排两步：
**消散 → 出现**。

用户给的是「出现与消失各自动播放一次」，落地成了「出现两次、消散一次」，原因是**奇偶性**：
对话框从不可见起步，而静止态必须是可见的（否则「稍后 / 继续」两个按钮点不到，也就没法重播），
从不可见到可见，出现与消散的次数必然差一次。取舍是「按钮可点」优先。

### 两个按钮的涟漪为什么会一起播

根因是 `ViewGroup.dispatchSetPressed`：

```java
// 子 View 自己可点时，父容器的按下态不下发给它
if (!pressed || (!child.isClickable() && !child.isLongClickable())) child.setPressed(pressed);
```

第六批里两个按钮都**不可点**（点击由整块预览区的 `dialogHost.setOnClickListener` 接管），
于是按下预览区的任何一处，按下态会沿视图树一路下发到两个按钮，两层
`GradientRippleDrawable` 同时起播。

修法就是让它们各自可点：`isClickable = true` + 各自的 `setOnClickListener { replayDialogRound() }`，
并**去掉预览区那一层点击**。魅族上按住「稍后」截到的那一帧里只有它自己在播涟漪，「继续」没有任何反馈
（`light-dialog-ripple.png`）。

### 重播真的发生了：判据是读数行，不是那张「播放中」的截图

点按钮之后 0.2 s 就截图**抓不到消散**——从 `stepDialog` 到粒子真的接管，中间还有「等涟漪播完 →
抓图 → 建材料 → 首帧上屏」，实测这一段比 `screencap` 的往返还长，截到的仍是完好的对话框。
可用的判据是**读数行**：每走一步都会 `beginStats()` 重新量一轮，而每一轮的材料是重建的，
粒子总数会微动。魅族那三张连续截图上依次是

```
粒子总数 80,665 · 渲染帧数 35 / 35   ← 自动播完，静止
粒子总数 80,648 · 渲染帧数 35 / 35   ← 按住「稍后」松手那一次重播
粒子总数 80,630 · 渲染帧数 34 / 34   ← 点「稍后」那一次重播
```

三次各不相同，也就是按钮确实各触发了一轮；而两次重播之间页面一直停着不动，证明**不再循环**。
三星那一轮没跑按住那一步，所以只有一次重播：静止时与点按钮当下都是
`83,524 · 32 / 31`（读数 1.5 s 后才汇总，那一刻还是上一轮的），重播播完变成 `83,514 · 33 / 32`。

### 深色：魅族那一轮是系统的强制深色，不是应用自己的深色

应用的深色由它**自己的设置**决定（`follow_system_dark_mode` / `force_dark_mode`，见
`AppearanceUtil`）。两台的值不同，于是同一条 `cmd uimode night yes` 得到两种结果：

- **三星**（`follow_system_dark_mode=true`）→ 应用真的进了 `values-night`，页面底色 `#121212`，
  **换色按钮的图标是白的**，第 2 条达成；
- **魅族**（两项都是 false）→ 应用仍是浅色，Flyme 把它**强制反色**（页面底色量到 `#292929`，
  而 `values-night` 是 `#121212`）。强制反色不会反转 `ImageView` 的内容，所以那一轮的图标仍是黑的。

这是系统级强制深色对**整个应用所有 on-surface 图标**（例如 `ic_arrow_back`）的既有行为，
不是本批引入的。**不代为改用户的应用内深色设置**，因此魅族的深色证据只到强制反色这一层，
真正的深色以三星那一轮为准。

   OPPO OPD2515 不在线。
3. **涟漪那一张只有魅族有**：三星上长按 `TextView` 会触发系统的「拖放」引导页（第 7 节），

## 7 真机驱动踩到的三条（已写进 `.claude/rules/adb.md`）

1. **左滑的起点必须离屏幕右边缘足够远**。示例卡最宽 640 dp，在三星上几乎顶到右缘，
   从 `x2 - 24` 起手正好落进系统返回手势区，整页被直接退掉，后面每一步都在设置页上瞎点。
   改成 `min(x2 - 24, 屏宽 - 140)`。
2. **三星上不能用「按住不放」截图**。`input swipe x y x y 1800` 在 `TextView` 上是长按，
   One UI 的「拖放」功能会把 `com.samsung.android.onetouch` 的引导页拉到前台，整轮驱动作废。
3. **参数区的定位要先滚回顶部**。`find_rid` 只会往下滚，上一次为了找底部的控件滚下去之后，
   上面那两根滑杆就落在屏幕外，再找它们会一路滚到底也找不到。

另加一条老规矩的复用：对话框在出现 / 消散那一段是不可见的，`uiautomator dump` 只输出可见节点，
按 `resource-id` 找按钮**必须轮询**，一次没找到不等于按钮不存在。
