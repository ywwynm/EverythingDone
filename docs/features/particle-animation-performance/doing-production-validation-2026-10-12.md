## 接入版本验证

### 最终判断与证据范围

- 三机的 90 行长卡片上下滚动、左／右滑动、回弹、真实计时控件填充／描边数字变形、无限计时呼吸、加 5 分钟、严格模式、取消确认与返回、后台恢复及尺寸变化已执行。服务由 debug 内存 Binder 替身提供，使用真实 Activity 回调和控件，但没有让真实服务完成已有记事。
- 三星、魅族录像中没有发现整卡闪空或顶部计时冻结；媒体记事只读预览中 GIF 持续更新。OPPO 无系统录屏权限，仅有 UI、状态、驱动时间戳和前后截图，不能称作逐帧画面验收。
- 静止态对照将计时器、卡片、三个 FAB 的矩形各扩展 24px，纳入边缘及阴影。三星／魅族所有像素通道差异不超过 2/255；OPPO 各区 p99 不超过 2/255，少量动态壁纸／边缘像素仍有差异。这里只覆盖这些取样状态，不是所有主题与所有控件组合的数学等价证明。
- 固定种子为 `20261012`，两侧相同长卡片、计时更新、手势，无录屏／关键图像导出。FPS 使用首粒子呈现回调 150ms 后至释放前的驱动呈现时间戳；延迟为识别滑动至首粒子回调，不是外部高速摄影得到的精确触摸延迟。

下一步应隔离整页 HWUI 捕获、GPU 复制和粒子合成的竞争；不通过冻结动态背景、降低计时刷新率或减少粒子数量换取数字达标。首帧超时与现存媒体冷加载问题的材料保留，不能把慢到没进入有效采样区间的运行计作高帧率通过。

- 魅族已有媒体记事只读预览连续三次复现整页首帧超时：硬件捕获返回状态 0，图像及 fence 正常，停在 `upload_queued`。超时线程栈明确指向 `ParticleDriftRenderer.warmSample` 的 `DirectByteBuffer.put`，GL 队列到约 3.5 秒才消费首帧；这是旧 CPU 预热占用唯一 GL 线程，不能通过延长超时解决。将纯 CPU 合成样本／分析移到独立后台线程，GL 线程只保留着色器预热，使用同一现存媒体记事回归。
- 魅族流体一次 1.086 秒长停顿保留为异常样本；随后相同输入交替复测新路径 98.5／94.2 FPS、原路径 87.0 FPS，没有再次出现长停顿。尚不能仅凭复测断言原因，继续核查冷启动与预热争用。
- 移开 CPU 预热后，进一步的首帧阶段采样定位到 `ParticleFrameTimestamps.enable → ParticleMaterialNative.<clinit> → System.loadLibrary` 的 APK ZIP 索引查找，仍在 GL 线程等待约一秒。Doing 提前在后台加载本地库；页面开始绘制时不等待可选驱动时间戳，本地库就绪后再启用。初始页面交接继续使用同一 GL 缓冲和提交回调，诊断区分时间戳尚不可用的判定。
- 修正捕获缓存强制更新标志向独立 Surface 祖先下的普通子树传播；同时把 scene 启动移到所有者登记之后，保证同步初始化失败也能完整恢复原树。
- 性能测例新增固定粒子种子 `20261012`，消除原路径／整页路径的随机粒子分布差异。原来的未固定种子数据保留作排查材料，不用于最终等价结论。
- 页面捕获期间保留显示节拍，避免每次上传之后停钟、下一张上传再重启；GPU 缓冲回收仅在整页内容路径把轮询间隔从 4ms 缩到 1ms，始终等待同一 fence，不提前归还图像。页面已有内容时，也为其刷新保留原有的 GL 工作预算。继续以固定种子的 A/B 对照验收此项。

- 三机分别完成后台恢复；三星／OPPO 的左滑完成和魅族流体右滑完成均经过粒子路径，静止状态恢复正常。录像仍须作画面复核。
- 补充真实 Doing 入场与按钮回归：只在 debug 内使用 DoingBinder 内存替身，调用真实 `initAfterBindService`、计时监听、+5m、严格模式、取消弹窗。避免此前三个 FAB 都直接 finish 的简化掩盖业务交互差异。

- 真实按钮配对复现：Dialog 暗层留在 Decor overlay 时被整页 Surface 遮挡，候选的计时与卡片未按原路径变暗；暗层改挂整页内容 overlay，原有淡入／淡出与 0.6 浓度不变。与此同时，主线程已收到后续计时与 `stop`（固定 25:00）更新，但 GL 仍显示 29:54，排除服务停止。修正为每次捕获通过真实 draw 更新失效的后代显示列表，不能只依赖根 `isDirty`；仍由 HWUI 缓存静态子 View。
- 背景明暗取样同步改读承载页面的 Surface；整页捕获开启后，原窗口内容缓冲是透明的，继续取原窗口会错误地视为纯黑。
- 魅族和 OPPO 的第一轮真实按钮样本受外部 ADB 服务中断影响，未计入有效结果，未主动重启全局 ADB。

## 首轮发现

- 相同长卡片、计时器、无录屏／图像导出的三星配对：原路径 115.9 FPS／133.4ms，整页候选 95.0 FPS／87.1ms；纹理上传任务曾耗时 8–13ms。复用既有双缓冲纹理后为 117.0 FPS／83.3ms。魅族同一修正从 108.3 FPS 提至 111.8 FPS，仍需重复配对。这里延迟均为识别至粒子呈现回调，不等同于最终屏幕响应。
- 发现没有粒子会话时，整页动态内容仍受粒子线程 60 Hz 默认节拍限制。新增页面内容刷新需求，计时与滚动可请求现有 120 Hz 通道；最终是否一致仍以实机画面、驱动时间戳与重复测试为准。

- 三星、魅族 90 行长记事滚动与计时画面已取得配对材料；魅族第一次脚本失败来自命令文件尚未写完就读取，已改为临时文件加原子重命名，该轮不计入结果。
- OPPO 长卡片滚动复现 `hardware_draw_8`：无暂停／尺寸变化记录，也无队列超时，捕获约 6.5ms。候选错误地把 `SYNC_FRAME_DROPPED` 当成失败并退出页面。按 [Android 官方文档](https://developer.android.com/reference/android/graphics/HardwareRenderer#SYNC_FRAME_DROPPED)，这是已同步内容、渲染器将自行在下一次 vsync 出帧的状态，不能清空当前画面或结束页面。修正为继续等待图像，仅丢失 Surface／停止状态进入失败处理；同一真实滚动回归作为验证入口。
