## 待验证假设

1. 当前流体中心色被逐片元重复处理：把颜色链外移后，大尺寸粒子的绘制收益应明显高于小尺寸。
2. 飘散重复的静态参数及噪声计算占主要 compute 成本：初始化缓存和带取样误差检查的时间拟合应减少稳态耗时，且整轮包含初始化后仍有收益。
3. 普通流体死亡后仍积分：保留末端历史邻帧后裁减应不改变可见状态，并减少后半段和准备成本。
4. 近圆旋转／宽记录以及较密压力网格有额外成本：真圆和较粗网格需分别检查轮廓、轨迹、局部密度，不能只比较帧率。

## 飘散候选的取舍

第二轮提高到 120 帧、5 次交错，并增加跳过绘制的拆分条件、模型更换、视口缩放再恢复的缓存失效检查。六场景的三次失效对照均与新建渲染器逐字节一致，未发现缓存污染。

| 场景 | 原式 → 拟合（ms/帧） | 含初始化整段（ms） |
| --- | --- | --- |
| 新建页 | 1.444 → 1.336 | 175.64 → 163.40 |
| 多选移除 | 1.256 → 1.241 | 154.66 → 152.01 |
| 附件弹窗 | 0.730 → 0.685 | 89.82 → 84.83 |
| 矮卡片 | 0.586 → 0.585 | 71.88 → 72.49 |
| 加光／奇数尺寸 | 0.532 → 0.515 | 65.79 → 63.45 |
| 80,000 颗／3 倍大弹窗 | 1.567 → 1.570 | 190.47 → 191.90 |

- 拆分结果同样受 GPU 调频、固定提交与清屏成本影响；未得到所有场景一致的计算收益，不能将省掉噪声指令数直接换算成帧率。
- 缓存每粒子新增 96 B，80,000 颗为约 7.32 MiB；含副本更多时还会增长。初始化额外约 0.5～1 ms。已存在的整帧复用仍保留。
- **默认不启用飘散缓存与拟合。** 实现和数值检查保留为线程局部对照候选，正式会话继续使用最新视觉版本的原算法；不增加首帧和显存成本。未来需在目标设备上得到稳定端到端收益才考虑切换。
- 五组桌面完整时间轴的 0.56 px 是实测最大误差，不是严格数学上界；初始化三点检查的 0.16 px 也不构成全区间证明。三星六场景五时刻最终帧的平均通道差最大约 0.026/255。
- 复测原始结果：`tmp/harmony-particle-android-port/fast-20261008-split/bench-result.json`。

## 真实大弹窗与回归

以最终默认选项测试三星：只在空白新建页开关附件和颜色对话框，不输入内容、不选附件、不改颜色、不保存。每种样式各两轮出现／消散，数量 1.6 倍、粒径 3 倍。测试后恢复原粒子偏好、调试配置及采样开关；首页记事计数与自动旋转状态均未变化。

- 只统计粒子会话实际提交并呈现的缓冲，排除预热透明帧与收尾清屏。离屏加速比例不能当作上表的同比提升；本轮没有真实 UI 基线帧率的同条件 A/B。
- 流体当前出现／消散计划主要为 60 Hz。高数量、大粒径颜色弹窗仍存在压力更新与排队开销，绘制阶段优化尚未消除全部掉帧。飘散使用原算法已接近 120 Hz，不为微小理论收益增加首帧和显存负担。
- 原始记录：`tmp/harmony-particle-android-port/fast-flow-dialog/`、`fast-drift-dialog/`。没有测试其他设备。
- 365 项粒子相关 JVM／GLES 着色器编译测试全部通过，无跳过；桌面颜色 32 组、飘散五组完整 120 Hz 时间轴以及三星缓存失效对照通过。GPU 基准包括原式、各单项和组合条件，数据按测量阶段分别保留。
