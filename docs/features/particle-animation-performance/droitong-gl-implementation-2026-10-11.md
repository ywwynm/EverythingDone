# 卓易通共享 GL 前景与交接候选

用户授权的第二轮实现，保留 SurfaceView、Dialog 内容隐藏和应用内对照，完成后发布阿里云；全程不使用 ADB。前置证据见 [首轮结果](droitong-results-2026-10-11.md)。

## 实现范围

- 在共享粒子窗口中增加有序位图层：卡片静态交接位于前景之下，前景按原控件顺序绘制。真正的粒子帧就绪时在同一次 GL 合成中替代静态卡片。
- 复用 `ParticleForegroundSurface` 的控件捕获、姿态更新及 FAB 硬件阴影；新候选不创建或直接提交独立前景 SurfaceControl。静止控件复用纹理，内容／姿态变化才更新。
- 先准备并提交替代图像，再隐藏原控件；退出先准备静态末帧，再恢复真实 View 并等待宿主帧提交后撤下替代图像。公开 API 无法保证容器中的跨表面呈现时刻，记录交接依据和超时，不宣称已达到屏幕原子交接。半透明阴影短暂重叠是本轮待用户验证项。
- 固定色块改用显式满足 composer overlay 与 GPU sampled 用途的硬件缓冲来源；增加同一色块直接进入共享 GL 的对照，导出实际缓冲用途。
- GL 卡片交接完全绕开普通硬件 Bitmap 直接提交 SurfaceControl 的旧路径。旧卡片实现仅作基线保留，不在这一轮同时变更正常页面的缓冲分配方式；色块探针独立修正，不把旧色块分配当作基线。
- 应用内入口保留原实现／上轮根节点／新 GL／Dialog 的对照；新建测试默认组合 GL 与内容隐藏。导出配置、原图、GL 合成图、提交和恢复事件，严格区分用户观察与回调推定。

已发布 debug `202610110948`，公开下载和元数据核验通过。GL 候选只在显示兼容性检查的测试页生效，普通首页仍走原路径；不根据设备品牌自动启用。用户随后确认默认组合的色块、Dialog 和前景可见性改善，但阴影／文字及独立 Surface 恢复存在短闪，交接质量尚未通过；见 [后续反馈](droitong-gl-feedback-2026-10-11.md)。

## 实现与验证

- `ParticleGlBitmapRenderer` 与两份着色器将预乘 alpha 位图叠入共享 SurfaceView，复用前景捕获和 FAB 硬件阴影。图像尺寸不变时更新原纹理，静止内容不持续读回；GL 专用捕获只在关键图像开关打开时执行。
- `ParticleGlCardHandoff` 负责准备、原控件隐藏、粒子接替和回退；静态卡片被粒子替代后保持撤下，避免会话结束时闪回。恢复等待宿主帧提交，超时明确记录为推定；取消、后台和迟到回调不能重新隐藏原控件。
- `ParticleCompositorBitmap` 为独立色块请求并核对 composer overlay／GPU sampled 缓冲用途，提交带获取栅栏；GL 色块直接上传同一已知图案。两条探针均不隐藏原控件，便于区分独立层和 GL 输出。
- 默认选中“GL 前景与 Dialog 一起验证／额外隐藏普通内容”；保留原实现、上轮根节点和单项对照。简报逐条附构建号，ZIP 增加前景上传、交接、原始驱动时间、缓冲用途和 GL 合成图，避免把旧报告或回调当作新包上屏结果。
- `assembleDebug` 与 32 项相关单元测试通过：交接状态 4 项、静态卡片替换 3 项、诊断事件缓冲 2 项、捕获路线 8 项、既有 UI 契约 15 项。记录见 `tmp/droitong-gl-final-build.log`。
- 桌面实际着色器检查共 5 项通过，包括方向、坐标、预乘透明度叠加；像素最大误差为 0。脚本及输出见 `diagnostics/droitong-2026-10-11/check_gl_composite.py` 与 `gl-composite-check.json`。桌面检查未验证 Android 位图上传和卓易通合成器。
- 未使用 ADB、未操作物理设备或模拟器、未创建 Git 提交。目标机显示正确性、连续操作恢复及性能仍由用户验证。

## 用户最小验证顺序

1. 设置 → 粒子动画设置 → 右上角菜单 → 显示兼容性检查，保持默认组合与关键图像采集。
2. “首页前景”中慢拖、停留、回拉取消和滑动完成，观察菜单、ActivityHeader、图标、FAB 和阴影是否全程存在；检查卡片首尾是否闪回、重影。
3. 分别用默认 GL 组合和“原实现”打开固定色块。两者均使用本轮修正后的探针，记录橙蓝色块是否可见。
4. 默认组合复查普通／叠层 Dialog；此前未判断的底部面板和独立 Surface 可继续补充。
5. 每项返回后记录肉眼结果，再保存或分享最近 12 次诊断 ZIP。若显示正常，关闭关键图像再比较流畅度；不依据抓图开启时的耗时判断常规性能。
