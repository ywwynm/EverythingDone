# 压力输入复用与绘制记录合并

## 范围与验证

用户确认先试上一轮建议的第 1、2 项；第 3 项带约束求解器安排下一步。基线为调试版 `202610080554` 和当前工作区，保留已采用的高刷、严格压力阈值与可见实例压缩。仅操作三星 `R5CW20BLNKL`，不保存／修改真实记事。

沿用已有固定输入、同 APK 交错测量和实际大弹窗呈现工具；已有高负载颜色消散约 92～103 fps 可复现记录作为问题基线，不单独重复整轮旧包测试。

三个可证伪假设：

1. 压力各批重复准备散度有成本；每次压力更新准备一次应降低求解总耗时，保持压力和轨迹相同。
2. 全量记录再扫描的读写有成本；合并记录生成与组内扫描、只写有效记录应降低绘制链耗时，保持混合顺序和像素。
3. 新的输入读取与工作组同步可能抵消收益；需包含较小粒径、无粒子可见、全组可见及组边界条件，未超过噪声的候选不默认启用。

先做真实 GLSL 数值／像素检查与编译，再一次同包独立及组合测量，最后核对大附件、颜色弹窗实际呈现。额外测量仅由失败或归因需要触发并记录。

## 初始实现选择

- 散度预计算并入已有 tile 收集分发，在活动区域早退之前覆盖整个输入网格，保证边带与边界取值同原式；不增加新分发。
- 绘制采用记录生成与组内稳定扫描合并，候选几何只算一次，屏外粒子提前跳过颜色计算。局部有效记录再按组前缀拷贝到最终缓冲，保留原顺序；省去全量扫描分发与逐粒子偏移表，避免重复计算几何。
- 新变体先默认关闭，实测后决定保留范围。实验产物放在 `tmp/particle-reuse-20261008/`。

## 状态

已完成同输入整段测量、两项正确性验证，以及真实材料逐帧交替测量。记录合并默认采用；散度复用默认关闭，保留 debug 对照。高负载稳定 120 fps 的目标尚未达到。

## 桌面验证

- 真实生产 GLSL 的压力输入复用通过 320 组对照：寄存器／shared 两种路径，48×48／47×61 两种尺寸，空／平滑／稀疏／噪声场，完整／裁小活动区域，1／8／33／100／200 次迭代及两档阈值。压力输出最大差为 0。
- 合并记录通过 270 组对照：1／255／256／257／10007 颗，两种颜色精度，0.5／3／6 倍大小，出生／死亡／倒序请求以及全组可见。有效数量、顺序与最终记录最大差为 0。
- 初次 JVM 测试有一条静态宏组合断言仍期待旧调用文本，已补上输入复用宏；实际 GLSL 编译没有失败。
- 测时沿用同输入整段执行前后 `glFinish` 的墙钟，不使用已知可能漏计 compute 的 GPU 查询。它包含本段提交和 GPU 成本；现场呈现另行验证。

## 首轮三星结果与追加原因

- 366 项 JVM／着色器测试通过，APK 安装成功。四组大弹窗及一组 4949 颗小场景，分别测基线、仅散度复用、仅记录合并与组合，预热后各三次交错测量。
- 记录合并的附件／颜色现场耗时约降 4%～8%；轨迹差为 0，RGBA8 最大差 1 灰阶。小场景未见稳定收益，差异在噪声范围。
- 全网格散度准备在多数场景没有稳定收益；压力变体在一组颜色现场异常快，但在不执行压力的回放中也出现明显波动，不能只采用这组最好数字。
- 再检查求解器读取范围：一个 tile 的输入只延伸到输出边界外 8 格。因此把散度准备缩到活动输出区域加 8 格边带，不额外清空缓冲；每次实际读取的格子仍全部由当次写入。桌面以 NaN 初始化未写区域验证不会读取未准备输入。
- 因上述新改动安排一次追加同包对照，仅复测两种大弹窗 3× 粒径和小场景，不重复整个首轮矩阵。原始数据保留在 `tmp/particle-reuse-20261008/reuse-one/`。

## 真实呈现波动与补查

- 高负载实际弹窗各两轮：关闭合并时附件消散 120／115 fps、颜色 84.3／108 fps；开启后附件 103.1／118 fps、颜色 90／106 fps。尚不能据此宣称稳定提高实际帧率，其中一轮附件比关闭更慢。
- 两组的随机材料数量略有不同；真实快照附件为 1050×1047、颜色为 1380×2281，宽高比例也不同于原离屏样例。现有整段均值不足以排除合并后某一阶段变慢。
- 因此追加一次真实材料逐帧交错 A/B：同一份快照、种子、材料和时间，轮换前后顺序，预热后测三次；同时记录完整推进和不推进模拟的重复绘制。每帧 `glFinish` 仅用于相对成本归因，不解释为实际呈现帧率。
