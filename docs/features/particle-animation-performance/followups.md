# 后续事项

## 3b 之后新增（2026-09-15）

- **三星上把材料库的并行道数从 3 提到 6 没有可测收益**（OPPO 57.7 → 36–43 ms，三星 63–72 ms
  没变）。怀疑是工作线程用默认优先级、被调度到小核，而材料线程本身跑在 `THREAD_PRIORITY_DISPLAY`。
  下一步可以试：把工作线程也设成 `THREAD_PRIORITY_DISPLAY`（或跟随调用线程），或用
  `sched_setaffinity` 绑大核。要单独一轮验收，并且注意 1.7 的「有反馈时让出优先级」不能被绕过。
- **三星的「提交 → 上屏确认」比真实呈现晚 18–55 ms**：真实呈现中位 29.7 ms，确认中位 47.5 ms、
  最大 102 ms，首帧的 `EGL_DISPLAY_PRESENT_TIME_ANDROID` 返回 INVALID、83 ms 才放行。
  确认时刻驱动着「撤快照 / 起暗层 / 撤真实弹窗」，所以这一段不只是测量问题。可以试：
  给 PENDING 的首帧加一条「目标时刻已过两拍且缓冲已入队」的提前放行，但必须守住
  「暗层不得早于粒子首帧」的保序不变式。
- **`TOUCH_FULL`（触点强度也归零）留在开关里没有默认启用**：它让分布更散、前沿更糊，
  观感增益小而 OPPO 上每采样再贵 5%。若用户看实机后更喜欢那一档，把
  `creationAppearanceTouch` 改成 3 即可。

  两台都过。以后这一形态在三星上失败不必当成回归，但要留意 OPPO 是否也出现。
- **三星的「提交 → 上屏确认」中位数 21–49 ms**（OPPO 14–16 ms），第二批最终轮同样如此。它让
