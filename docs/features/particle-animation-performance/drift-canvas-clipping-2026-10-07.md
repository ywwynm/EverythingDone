# 飘散粒子内部硬边界检查与修复

## 需求与范围

用户反馈首页和记事详情的「改变记事颜色」在向左上消逝时，粒子似乎被面板上边缘截断，要求检查所有弹窗和其他粒子入口，消除这类内部硬边界。

本轮先提交上一轮已发布的参考概率改动（`eb5a3b341`），再独立处理本问题。未获本轮 ADB 授权，验证采用源码检查、JVM 回归和生产 GLSL 离屏渲染。

## 诊断

按以下顺序检查假设：

1. 飘散的离屏工作面受参考动画扩展尺寸限制，飞出粒子被工作面边界裁掉。
2. Android 父容器、弹窗窗口或叠加层只允许在面板矩形内绘制。
3. 快照圆角或原面板消蚀遮罩被重复应用到飞出的粒子。

第一项得到复现。旧 `ParticleDriftRenderer.ensureTargets` 使用不超过 2100 像素宽、2400 像素高的参考扩展尺寸（但至少与快照一样大）；高度同时按视口的 85% 计算。工作面围绕快照中心放置，实际绘制范围并不总能覆盖窗口。

例如窗口 1440×3120、面板 1344×2600、面板原点 (48, 472)，旧画布为 1440×2600，原点 (0, 472)。因此仍在屏幕内、但飞到 y < 472 的粒子会消失，形成恰好贴住面板上边缘的直线。横屏短卡片也可能在内部画布边缘被裁掉。

保留同一份计算后的粒子数据，仅把绘制目标扩展到窗口之外进行对照，直线截断消失，足以把问题定位到绘制范围，而非轨迹本身。

## 全入口检查

| 入口 | 调用路径和检查结论 |
| --- | --- |
| 首页改变记事颜色 | `ThingsActivity` 的页内面板通过 `ParticlePanelAnimator` 调用共同出现／消散管线，命中本次修复。 |
| 详情页改变记事颜色 | `ThingBackgroundEditorBottomSheet` 继承 `BaseDialogFragment`，进入 `ParticleDismissController`，命中本次修复。 |
| 其他普通／嵌套弹窗 | 控制器使用 Activity 的 DecorView 或 `ParticleElevatedHost` 全窗口宿主，粒子层不限制在 Dialog 面板内。 |
| 新建记事出现与收尾 | `ThingCreationTransition` 进入共同控制器；飘散由同一个渲染器处理，正放／倒放使用同一绘制范围。 |
| 左滑完成及批量移除 | `ParticleSwipeAnimator`、`ThingListRemovalAnimator` 使用共同叠加层；旧系统下放到原生前景之下的父容器也覆盖窗口。 |
| 设置预览 | 卡片和面板预览使用共同动画管线，修复同样生效。 |
| 流动样式及碰一碰 | 流动材质直接在窗口目标绘制；`TapParticleFlight` 使用带终点的流动路径。未发现以来源面板矩形裁剪已飞出粒子的规则。 |

生产代码只有 `ParticleDriftSession` 创建 `ParticleDriftRenderer`，不存在其他独立的飘散绘制实现。`ParticleOverlayHost`、`ParticleWindowSurface` 与抬高宿主均按窗口尺寸布局。卡片可见区域裁剪用于捕获原内容，临时快照的圆角和 `drift-card.frag` 的矩形判断只限制残留面板；这些都不限制运动中的粒子。

## 实现

- 新增纯几何类 `ParticleDriftCanvas`，保留旧模拟尺寸和原点。湍流读取绝对模拟坐标，因此直接扩大模拟尺寸会改变原来的运动，不采用该方式。
- 实际工作面覆盖整个窗口，仍按半分辨率绘制；工作面原点按旧像素网格整格移动，每格对应两个设备像素。
- `drift-particle.vert` 增加 `u_workOffset`，只把最终粒子坐标平移到新工作面。发射、运动、粒径和消蚀计算不变；桌面调用未设置该 uniform 时默认 0。
- `ParticleDriftRenderer` 按新范围分配与合成工作面；尺寸变化重建目标，模拟尺寸或坐标偏移变化会使颗粒帧缓存失效。
- 工作面最多比窗口每轴多不到两个设备像素的对齐余量，不随面板偏移无限扩大。相较旧内部画布，部分场景会增加清空和合成面积；粒子数量和模拟计算量不变。本轮没有做设备性能测量。

## 验证

### JVM 与构建

执行 `:app:testDebugUnitTest --tests '*ParticleDrift*' --tests '*ParticleDismissShaderCompileTest' :app:assembleDebug`，58 项测试通过，失败、错误、跳过均为 0。

新几何测试覆盖高颜色面板、普通弹窗、短卡片、全屏／超窗口快照及横屏／平板，输出 61 组正式布局供 GPU 检查使用。另外覆盖小数原点、奇数尺寸、超出窗口的原点、旧模拟基准、粒子坐标映射和自定义参考尺寸。最初仅抽取几何而未修复时，两项范围回归稳定失败；修复后通过。

### 生产 GLSL 离屏对照

`checks/check_drift_canvas.py` 读取 JVM 导出的正式布局，执行生产 compute、粒子与合成着色器、同一张 9×9 软点贴图和 RGBA16F 工作面。四类场景 × 两个相反方向 × 1／6 倍大小 × 两个时刻，共 32 组；对照画布在窗口四周额外扩展 256 像素，粒子数据与像素网格一致。

不同工作面尺寸会改变顶点归一化的浮点舍入。初查以 2/255 为阈值报出 18 组差异，其中包含微小光栅化差异；改以 8/255 为明显透明度损失阈值，并独立检查对照 alpha > 16/255 的粒子是否在正式图中变成 alpha ≤ 2/255。修复后最大差异只有 6/255。

| 检查 | 旧布局 | 修复后 |
| --- | ---: | ---: |
| 存在明显裁剪的场景 | 16 / 32 | 0 / 32 |
| 明显损失的像素（各场景累计） | 381,648 | 0 |
| 可见粒子变透明的像素（各场景累计） | 354,976 | 0 |
| 最大 alpha 差异 | 255 / 255 | 6 / 255 |

本机证据保存在 `tmp/drift-clipping-20261007/`：`before-layouts.json`、`after-layouts.json`、`before-gpu-guarded/`、`after-gpu/`。已查看高面板对照图，修复后粒子可越过原面板上缘。图像为合成输入的离屏诊断图，不是真机应用截图。
