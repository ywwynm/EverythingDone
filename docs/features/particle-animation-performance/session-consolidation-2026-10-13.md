# 卓易通兼容与粒子动画连续性：会话改动汇总

## 范围与最终状态

本记录汇总 2026-10-11 至 2026-10-13，从“卓易通打开 Dialog 时面板先出现、粒子位于下层”开始，到按住卡片转纵向滚动后的空白卡片修复。用户于 2026-10-13 确认“目前 OK 了”，明确要求将本会话相关改动集中提交，并逐项解释问题、原因及解决方式。

最终保留 SurfaceView、现有粒子模型和参数、动态背景、长短卡片共用逻辑，以及“添加附件 → 录音”的重叠转场。正常业务按系统绘制能力使用统一方案，没有按品牌增加用户兼容模式；API 34 及以上的 Doing 粒子页面采用持续整页合成，低版本保留既有能力回退。原实现和阶段候选只保留为 debug 对照。

本次整理不修改动画代码，不重新发布 APK。最近已发布版本为 debug `202610130351`。空间照片实验及其它会话的本地化发布日志不纳入本次提交。十月八日及更早的粒径、数量、求解器优化属于已提交历史，不重复算作本轮新增实现。

## 问题、原因与最终修正

### 1. Dialog 出现时面板提前显示、粒子被压在下层

- 现象：卓易通普通弹窗和叠层弹窗均受影响，关闭动画相对正常。提前设置窗口透明度的候选没有解决问题；额外隐藏普通内容的候选获得用户正面反馈。
- 原因边界：应用提交成功不能证明兼容环境最终按预期合成窗口。窗口 alpha 对普通内容的隐藏在目标环境中不足以保证出现阶段正确，不能只把问题归因于弹窗嵌套。
- 修正：`ParticleDialogVisibility` 保存窗口 alpha、Decor alpha、elevation 和 translationZ，在出现阶段隐藏普通内容与原投影；捕获和粒子交接使用受控路径，结束、失败、取消、关闭、分离时只恢复一次。`BaseDialogFragment` 与控制器共享恢复状态，避免重入后留下隐藏内容。
- 证据：[最初分析](../dialog-particle-dismiss/analysis-2026-10-11-droitong-window-alpha.md)、[首轮反馈](droitong-results-2026-10-11.md)。

### 2. 首页滑动时 ActionBar、ActivityHeader、FAB 等前景消失

- 现象：只剩粒子卡片，其他前景在动画期间消失；前景源图正确，自有 SurfaceControl 色块即使提交回调成功也不可见。单改父节点挂载没有解决。
- 修正：前景、静态卡片和粒子由共享 GL 合成，避免依赖未通过目标机验证的独立前景缓冲层。新增位图合成器、图层组、图像租约与交接状态机，保留现有前景捕获、阴影和层级；正式后端仍是 SurfaceView。
- 色块探针同时修正缓冲用途、栅栏及提交记录，分别提供自有 SurfaceControl 与共享 GL 的同图对照，明确两种结果不能互相替代。
- 证据：[SurfaceView 历史取舍](surface-texture-history-2026-10-11.md)、[GL 实施](droitong-gl-implementation-2026-10-11.md)。

### 3. 真实 View 与 GL 首尾重叠导致阴影、文字加深和闪烁

- 原因：两份半透明文字／阴影短暂重复混合；前景、卡片和粒子分开撤除还会造成 FAB 遮挡关系反转。窗口提交与 GL 提交分别成功仍可能出现中间空档。
- 修正：首尾使用完整画面保护交接，卡片、底图与前景成组进入和撤除；以状态机、一次性完成和超时清理处理取消、迟到回调及失败。准备未完成时保留真实内容，避免单独显示恢复卡片；正式统一路径不靠反复改变整张 Surface 的 alpha 交接。
- 验证中失败的整层 alpha／位置同步候选保留历史证据，不描述成最终修复。
- 证据：[视频否定的候选](droitong-handoff-video-feedback-2026-10-11.md)、[完整画面交接](droitong-complete-frame-implementation-2026-10-11.md)。

### 4. 独立 Surface 恢复时短暂露出深灰区域

- 原因：窗口恢复与生产者新缓冲不是同一完成条件；早期恢复遮盖还混用了屏幕坐标和窗口坐标，可能空裁剪后根本没有覆盖。PixelCopy 成功只证明源缓冲可读。
- 修正：`ParticleSurfaceFrames` 和 `ParticleSurfaceRecovery` 保留独立 Surface 像素、布局与祖先变换，在真实窗口及新缓冲就绪前维持恢复画面；修正坐标、量化比较、取消及超时处理。FableSol 在自身 GL 队列提交新帧之前绑定恢复事务，不覆盖原来的首帧通知。
- 后续把恢复帧准备提前到粒子播放期间，减少结束后的等待；SurfaceHolder 重建时撤销旧就绪结果，防止拿旧表面的成功恢复新表面。
- 证据：[ZIP 定位](droitong-handoff-zip-feedback-2026-10-11.md)、[恢复等待优化](recording-dialog-transition-2026-10-12.md)。

### 5. 快速滑动松手后直接消失、只播放回聚

- 原因：准备期间 ItemTouchHelper 已在松手后把卡片位移推向屏外，这段位移被误当成已播放的粒子进度；同卡回聚也可能早于上一组真正释放。
- 修正：前景、卡片和底图并行准备；横滑由正式选中回调激活；首帧前松手停止采纳系统后续外推位移，完成动画从实际呈现进度继续。同卡业务回调延后到旧 GL 组完整释放，再开始回聚。保留原阈值、粒子轨迹及取消语义。
- 证据：[启动与快速手势](droitong-startup-feedback-2026-10-11.md)。

### 6. 静态底图冻结背景、复杂控件与嵌套阴影缺失

- 修正：`ParticleLiveBackdrop` 持续捕获需要由 GL 承载的动态背景；普通页面在交接完成后继续使用原窗口动态内容。`ParticleViewCaptureTree` 分开处理真实硬件子树与独立 Surface，保留变换、裁剪、透明度、轮廓和嵌套阴影。普通控件投影也进入捕获，解决独立 Surface 弹窗关闭按钮阴影在出现完成后才补上的问题。
- 首尾重新取当前背景，不沿用开始时的静态底图。GL 会话保持原创建顺序和独立完成条件，前景独占范围不被扩大成“整个窗口只能有一个动画”，保留附件关闭与录音出现重叠。
- 证据：[统一方案](unified-presentation-implementation-2026-10-11.md)。

### 7. Doing 不出粒子、透明背景闪烁及卡片浓度错误

- 原因：透明壁纸窗口不能照搬不透明首页底图；把容器透明度烤进飘散材料会将实心卡面误判为半透明阴影；临时转移祖先 alpha 又使取消恢复后的卡片偏亮。
- 修正：材料 alpha 与最终合成浓度分开，保留真实 View 的祖先透明度，飘散最终合成使用 `sourceAlpha`。短长卡片采用同一粒子手势与恢复逻辑。
- 仅调整 Surface 属性的候选在卓易通首尾仍有空白／提亮，最终使用 `ParticleDoingPage`／`ParticleDoingGlScene` 从页面首次显示起持续合成同一 SurfaceView，卡片、动态页面和粒子在同一缓冲内替换。原控件树保留输入和可访问性；同时覆盖 draw 与 dispatchDraw，避免容器快速路径重复绘制。
- 证据：[Doing 首尾诊断](doing-start-flash-2026-10-12.md)。

### 8. Doing 关闭残影、返回后无法滚动及 Android 退出闪屏

- 原因：原生波纹可由 RenderThread 自行产帧，ImageReader 消费依赖主线程时会形成缓冲队列互等；Activity 退出过程中提前清空整页纹理造成闪屏；主线程解析历史报告延迟恢复交互。
- 修正：有界持有和消费 Image，过期帧在消费者线程及时归还，空通知不误判失败。退出先停止生产，保留已显示整页随原窗口转场退出，等 Decor 分离再释放最终纹理；后台／前台、尺寸变化及失败恢复纳入生命周期。报告汇总移到工作线程。
- 证据：[退出链路](doing-scene-exit-2026-10-12.md)。

### 9. 整页方案的三星流体、魅族飘散性能回退

- 修正：HardwareBuffer 直接导入并复用 EGLImage，以 GPU 栅栏保护图像租约；普通连续帧上传与换层在 GL 队列连续处理，减少主线程往返，首帧和交接仍绑定对应提交。唯一整页底图合入飘散最终合成，减少重复全屏通道；CPU 样本预热移出 GL 队列，原始颜色采样移到 JNI。
- 持续整页内容参与刷新率请求，即使暂时没有粒子会话也维持动态页面节拍；本地库后台预载，未加载时用已有的无驱动时间戳路径继续首帧，诊断仍标明呈现依据。合成程序随 EGL 上下文复用，避免每个窗口重复编译。
- `TimelyClockView` 按 Shape 引用、插值版本、位置与缩放复用每位数字 Path，消除静态数字及字形／轮廓光的重复构建；原地插值递增版本，不修改字体、轮廓、颜色或时长。
- 正式接入以前保留了性能未通过的候选。优化后三星 FLOW 三次均值 98.6→107.2 fps，魅族 DRIFT 117.8→118.9 fps；不通过降低粒子数量、质量或背景刷新率换取结果。
- 证据：[性能对照与限制](doing-scene-performance-2026-10-12.md)、[计时记录](../timely-digit-typography/sessions.md)。

### 10. Dialog 的外部阴影突然出现或消失

- 原因：窗口根投影位于粒子主体材料之外，原 Dialog 被隐藏或关闭时投影直接消失。
- 修正：`ParticleDialogShadow` 单独捕获并承接外部根投影，按实际呈现进度渐变，和原生投影同步交接；不扩大粒子主体材料，不改变首页卡片既有阴影处理。`DialogDimLayer` 同时支持 Doing 整页变暗。
- 证据：[外部阴影与入口覆盖](media-dialog-shadow-2026-10-11.md)。

### 11. 录音计时数字变淡、额外描边及水体恢复晚

- 原因：拆分捕获树的 RenderNode 没有复制 View 的有效重叠绘制语义，半透明控件的内部蒙版合成被改变；整块恢复遮盖在旧图上停留，掩盖了恢复后的真实控件。
- 修正：保留 `hasOverlappingRendering` 对应的合成属性；不调整原字体、描边、配色或准备态 alpha 作为补偿。独立 Surface 提前准备恢复帧并验证生命周期，减少粒子结束后的遮盖停留。
- 证据：[真实附件 → 录音对照](recording-dialog-transition-2026-10-12.md)。

### 12. 首页其他卡片阴影强度与设置预览卡片阴影突变

- 两类原因分别处理：离屏背景使用的光照与真实窗口不一致；设置预览使用普通 CardView，按压 elevation 从 30 px 降至 1 px，而材料仍按静止姿态捕获。
- 修正：统一读取窗口光照、显示尺寸与旋转参数，供背景、整页和硬件捕获使用；预览改用真实卡片的 `InterceptTouchCardView` 和粒子姿态锁，保持阴影几何连续，不按阶段手工调低阴影浓度。
- 证据：[窗口光照](recording-dialog-transition-2026-10-12.md)、[预览回归](ripple-recording-preview-2026-10-12.md)。

### 13. 关闭 Dialog 时按钮 ripple 被冻结在消散材料里

- 原因：原先同步隐藏波纹的作用域包住了异步准备入口，真正记录像素时过滤早已恢复，波纹被烤入静态材料。
- 修正：只在实际同步记录和提交期间过滤自绘 `GradientRippleDrawable`，保存并恢复原状态，恢复闭包仅消费一次。Surface PixelCopy、阴影准备和 GPU 读回期间不隐藏真实反馈；动态背景继续呈现反馈，不通过统一延迟打开或强制结束波纹处理。
- 证据：[分析](ripple-capture-analysis-2026-10-12.md)、[修正](ripple-capture-implementation-2026-10-12.md)。

### 14. Doing 原生波纹冻结、首帧偏深及末帧残留

- 原因：原生 RenderThread 续帧未可靠传播到 GL 捕获；只续帧仍可能保留未清理的按钮显示列表；离屏提交早于原窗口初始化原生动画会造成首帧反向变深。
- 修正：原生续帧触发按需失效和受控刷新，忙碌期间保留末次请求，末帧经过原窗口提交后有界清理。仅输入改变及首次提交安排在当前窗口遍历后，普通动态帧维持原节拍。
- 所有帧持续后移的中间候选造成魅族 FLOW 约 90 fps，已撤回；没有增加固定延时或常驻轮询。
- 证据：[原生波纹与性能反证](ripple-recording-preview-2026-10-12.md)。

### 15. 魅族录音准备偶发中止与图片加载慢的区分

- 已确认的准备开销：零旋转路径无意义等待本地库加载；内容／阴影串行准备；布局阶段占用捕获预算；独立 Surface 尚无首帧时过早结束重试。
- 修正：零旋转直接返回，阴影与内容并行，布局及捕获分别有界，Surface 使用已有完整 900 ms 截止时间；成功即继续，不加固定等待。修正后严格要求附件与录音均实际播放首帧和完整动画。
- 图片冷加载仍另列：设备静置无系统性资源不足证据，应用媒体检测、字体及粒子预热存在并发竞争。本轮没有改变媒体解码或启动调度，不能写成图片慢已解决。
- 证据：[准备与冷启动调查](ripple-recording-preview-2026-10-12.md)。

### 16. 批量操作跳过退出选择与列表补位动画

- 现象：粒子末段系统栏图标先变色、选择菜单提前消失，选择工具栏和未选卡片瞬间恢复，列表剩余项跳变。用户视频来自另一台 OPPO 手机，问题不限于卓易通。
- 原因：`onBodyReleased` 在统一 GL 前景仍持有旧页面时发布列表差分；布局准备又消耗了已经启动的退出动画时钟。
- 修正：确认 Dialog 完整释放后执行批量流程；保留旧列表投影直到移除粒子及前景完整释放，再派发差分、退出选择和补位。工具栏与颜色动画从布局完成的 pre-draw 开始，输入封锁持续到相关动画和布局稳定，覆盖全不可见选择、关闭系统动画及返回中断。
- 证据：[批量转场](../selection-batch-actions/transition-2026-10-13.md)。

### 17. 选择工具栏／状态栏错色、菜单闪失及双重阴影

- 修正：`ModeManager` 让整组选择工具栏按实际高度平移退出，动画完成后再清菜单和切换系统栏状态；选择状态栏外观覆盖完整退场阶段。旧阴影移开后逐步显露普通 ActionBar 阴影，避免叠加加深。
- 只更新未改变的 ActivityHeader 计数，不重建标题约束；保留记事走选择外观 payload，避免完整绑定重置几何或媒体，卡片／文件夹颜色和子控件透明度连续恢复。
- 证据同上。

### 18. 批量彻底删除文件夹内记事时数据库互锁

- 原因：`ThingDAO.updateStates` 的写事务内通过 `ThingFolderDAO` 的另一连接更新时间，同库互等后报 `SQLiteDatabaseLockedException`，整批回滚。
- 修正：使用删除事务的同一连接更新所属文件夹时间，使删除和容器更新共同提交或回滚；不吞异常或拆成非原子更新。
- 证据同上。

### 19. Flyme 二次反色导致原生卡片与动画颜色不连续

- 原因：该设备厂商绘制逻辑会在标准 `forceDarkAllowed=false` 之外改写 Canvas 颜色，纯软件 drawColor 对照也受影响，不能归因于 GL。
- 修正：`App.mzNightModeUseOf()` 声明由应用自行处理配色，并保留 JVM 名称；不调用隐藏 API，不根据品牌选择动画后端，继续遵守用户的系统／浅色／深色设置。
- 设备框架反汇编仅保存在本地临时目录，不进入应用或本次提交；实测证据见批量转场记录。

### 20. 批量退出后媒体仍变淡、Doing 标识与清单交互遗漏

- 原因：图片选择白罩只在完整媒体绑定中设置，退出动画只更新部分外观；缓存 holder 中途离屏后重新挂载不一定触发绑定，保留了中间 alpha；部分状态图标及清单点击目标未恢复。
- 修正：统一完整绑定、选择 payload 和已绑定 holder 挂载时的外观计算；媒体选择罩、文字／附件／音频及 Doing 蒙层连续恢复，按当前模型同步置顶／常驻通知和正在做标识。清单仅刷新已有行的回调，不重建布局、不重新加载媒体；用户自己的媒体背景遮罩保留。
- 证据：[媒体与子控件恢复](../selection-batch-actions/appearance-recovery-2026-10-13.md)。

### 21. 四列瀑布流保留项瞬移并被当成新增项淡入

- 原因：差分后的预测布局会把本来可见的保留 holder 交给 add 路径。关闭预测布局的候选仍失败且改变列分配，已经撤回。
- 修正：业务变化前记录仍可见保留项的稳定 ID 和真实坐标，本轮临时使用 `ThingListRetainedItemAnimator`，让这些 ID 的 add／move 从实际原位开始，沿用原动画参数；原来不可见的项仍走正常出现。结束和中断均恢复原 ItemAnimator 实例与配置。
- 证据同上。

### 22. 按住卡片再纵向滚动后出现空白矩形和浓重阴影

- 复现时 View 的尺寸、alpha、轮廓和子控件属性均正常，粒子覆盖层已归零；仅改销毁线程仍失败。保留捕获树的诊断实验及对原卡片单次 invalidate 的对照共同确定是共享绘制缓存的失效传播问题。
- 原因：离屏树通过真实 `View.draw` 借用子 RenderNode，销毁捕获树可清理子显示列表；原窗口的父缓存仍被认为有效，滚动／复用后跳过了缺失内容的重建。
- 修正：共享节点的记录和销毁在 UI 线程串行，释放时仅对实际借用的 View 子树发出一次失效通知，包含已离屏缓存；覆盖持续背景、单次硬件快照、Doing 整页及同步兜底。私有位图前景仍可后台释放，ImageReader 和 GPU 缓冲保持原队列，不重绑记事、不重载媒体、不每帧重录列表。
- 临时保留树、延后销毁及反射恢复探针均已删除。证据：[空白卡片根因和回归](../swipe-complete-animation/scroll-reuse-2026-10-13.md)。

### 23. 无 ADB 诊断、自动化与可复核证据

- 粒子设置页提供应用内对照、用户观察、简报复制及 ZIP 分享／保存，覆盖普通／叠层／独立 Surface Dialog、固定色块、卡片、动态背景、Doing 长短卡片和模拟计时。虚构入口不启动真实计时服务或改用户记事。
- 诊断记录构建、实际后端、窗口／缓冲／提交阶段、关键图像、退出与资源释放、帧时间来源及事件丢弃情况；区分驱动有效呈现时间、回调成功、无效时间戳后的推定和用户观察，不能把它们混为屏幕验收。
- 调试报告生成离开主线程。阶段状态、一次性结果、Surface 恢复屏障、图层顺序和事件缓冲补单元测试；加入真实界面探针、隔离包批量矩阵、媒体及滚动复用审计脚本和精简结果。新增 GIF、视频和音频仅为 debug 合成夹具。

## 验证结论与证据边界

- 正常包最近一次完整构建和单测结果为 1448 项、0 失败、0 错误、1 跳过。测试不能证明不同系统合成器逐帧相同。
- 整页性能轮次：三星、魅族、OPPO 每台 60 组实际 GPU 合成对照（最大通道差 1/255），每台 792 组计时 Path 对照（覆盖 33 种字体，逐像素一致），以及正式入口和长短卡片回归。
- 波纹／准备／设置页轮次：13 次原生波纹、12 组预览、6 组真实录音准备及 18 组其它入口；42 次固定种子性能手势保留新旧差异及失败候选，不宣称性能严格相等。
- 批量顺序核心矩阵 36 例，另有中断、动画关闭、深色及纯色扩展；媒体／子控件最终矩阵 27 例，含 9 次实际清单触摸和缓存 Doing 恢复。具体数量不跨轮次重复累计为一个独立样本总数。
- 最新滚动复用最终矩阵 21 组、342 次输入、4156 个可见卡片像素样本，另 18 组其它入口。空白卡片稳定失败序列已通过；媒体、Doing、清单及批量阶段复验通过。
- 三星与魅族保存代表性录像；OPPO 平板未取得可靠系统录像，采用实际截图、源像素和 View 状态，不能称三机都完成逐帧录像等价验证。用户另一台 OPPO 手机及卓易通由用户安装包反馈，本次总体认可不扩大为未执行的设备矩阵。
- 已有复杂记事只读验证；破坏性批量及复用压力操作在独立测试包的虚构数据上执行。每阶段按其记录恢复原 APK／设置，最终三台隔离包均已卸载；没有以清空原应用数据完成测试。

## 保留的限制和后续事项

1. 魅族冷启动图片加载仍有媒体识别、字体和粒子预热并发竞争，尚未实施启动调度专项。
2. 最新性能初轮保留魅族一次 1031 ms GL 提交停顿和 424 ms 首帧回调；六次复测未再现，同条件旧版也有冷／热准备差异，原因未确认，不能写成已解决或完全没有延迟变化。
3. OPPO 录音计时最终屏幕仍有小幅合成差异记录；常见控件和已测入口通过不等于任意第三方控件、所有系统版本逐像素一致。
4. 静态材料中的任意系统 RippleDrawable 无损排除不属于已完成的通用能力；本轮主要关闭按钮的自绘波纹已修正，Doing 原生动态波纹单独处理。
