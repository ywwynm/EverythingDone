# 多轮优化后的剩余空间（2026-10-08）

本轮回应用户对剩余优化价值的追问。核对九月批次、十月两轮实施、当前生产着色器与三星已有结果，并补查原始资料；只做分析，未修改生产代码、连接设备、重新实测或发布。

## 判断依据

- 最新版本三星默认档附件／颜色流体约 119～120 fps；数量 1.6×、大小 3× 时附件消散约 112～113 fps，颜色约 92～103 fps。高负载出现多数轮次可到 120 fps，但也有约 116 fps 的一轮，不能据此保证绘制已经完全无压力。
- 当前出现主要播放已准备轨迹，消散还要现场模拟。两者差异说明现场计算与排队值得优先归因，不能仅凭这组差异认定压力必然占绝对多数。
- 颜色下沉、32 B 真圆记录、活动压力区域、批量 Jacobi、死亡后积分早退、积分分发合并、可见绘制实例压缩和提交后末步压力，均已实现，不再计为新增机会。
- 严格压力阈值 0.001 的单项现场收益仅约 −0.4%～1.5%；后半段降频仅约 2%～4%，却出现数十像素的最坏轨迹误差。72 网格同样未通过误差验收。重复放宽这组参数不是当前优先方向。
- 九月 A2 已试过将风向／频段基向量等 uniform 常量外移，收益落在约 ±2% 噪声范围；不能把源码中仍有三角函数直接当作可兑现收益。

## 1. 压力求解的散度只算一次：最明确的新候选

`pressure-batched.comp` 每个工作组读入 32×32 格、输出中央 16×16 格。每次分发都重新从四邻域速度求散度，并读取占据度；每批执行 8 次迭代，默认 100 次需 13 批。一个压力更新内的速度和占据度不变。

九月 U6 只是把这些量从 shared 移到每线程寄存器，消除了**同一批内**的重复读取，没有消除**各批之间**重新求散度的工作。若未提前停止，同一网格值还会因相邻 tile 的边带多次参与计算；这部分有明确的重复来源。

候选是在模糊后的速度场就绪时，单独算一次散度与占据标志，之后各批读取紧凑输入。可以先保留高精度和原运算顺序，追求数值一致；不减少网格、频率或用户迭代上限。标准 GPU 流体实现也把散度作为独立结果交给多轮 Jacobi 使用，见 [GPU Gems 38 的 Projection 小节](https://developer.nvidia.com/gpugems/gpugems/part-vi-beyond-triangles/chapter-38-fast-fluid-dynamics-simulation-gpu)。

边界与活动区域外的输入必须与旧路径一致。额外分发、缓冲读写和屏障都要计入，尤其是较早收敛或粒子少时；不能把 13 批宣称为压力提速 13 倍。收益只来自散度准备这一部分，真正的邻域迭代仍然存在。

## 2. 提前筛选，再生成绘制记录：第二个明确候选

当前每帧先对全部 N 颗粒子生成 32 B 记录，然后进行组内可见性扫描、组间前缀和、存活记录复制，最后间接绘制。它已减少不可见实例的顶点／片元工作，但保留了全量中间记录及其读写。

候选是把寿命、透明度和保守屏外判断前移，稳定压缩粒子 ID，再仅为候选粒子计算最终颜色和绘制记录，或融合记录生成与局部扫描。保留原始顺序是透明混合正确性的必要条件；[GPU Gems 39 的流压缩说明](https://developer.nvidia.com/gpugems/gpugems3/part-vi-gpu-computing/chapter-39-parallel-prefix-sum-scan-cuda)可作为算法依据，不代表 CUDA 性能可直接移植。

25.5 万粒子的全量 32 B 中间记录约 8.16 MB。若能移除这份临时记录，可降低相应容量和每帧写入；这只是流量核算，不是 GPU 读写耗时预测。可见性需要的尺寸与 alpha 也有计算成本，应采用不会误删的保守判定，避免在筛选与最终生成中重复求昂贵几何。颜色计算留到筛选之后，比直接增加一份大静态缓存更值得先试。

## 3. 真正更快的带约束压力求解器：潜力较大，实施风险较高

当前公式含 `max(..., 0)`、占据阈值和边界钳位。直接把普通线性 PCG／FFT／多重网格替换进去，不能保证仍在解相同的问题。

可以研究投影红黑 Gauss–Seidel 或带约束多重网格；相关非负约束求解路线存在原始研究，见 [Chentanez 与 Müller 的作者材料](https://matthias-research.github.io/pages/publications/separatingBoundariesSlides.pdf)及 [Lai 等 2020 年论文](https://uwspace.uwaterloo.ca/items/d5b88286-d408-47a0-b8d7-d7dcb2be4adc)。本项目具体占据域、非负投影和暖启动仍须重新推导，不能照搬论文的大型三维网格加速倍数。

还要区分“更快收敛到方程解”与“接近原来固定 100 次的画面”：原来的有限迭代结果已经参与形成当前外观，更精确并不天然等于更相似。验收仍应看屏幕轨迹、密度、轮廓与时间连续性。

先测当前压力占比，再决定投入。例如压力占整段 40%、该阶段减半，整段才下降 20%；这只是条件算例，不是当前占比或性能预测。

## 4. 消散轨迹提前准备：适合少数稳定场景，不作为通用缓存

创建页已经有空闲预热，普通出现也已有历史回放，不能重复提出“加入预计算”。新增方向是把适用的**消散**也改为有缓存时回放，例如内容、方向、触点规则稳定的附件弹窗。

普通 `ParticleSession.dispose()` 当前关闭 renderer；不会自动保留出现时的历史给下一次关闭用。即使保留，也必须确认材料权重、触点、方向、随机种子、参数与完整播放区间相符，不能直接将一次出现倒着重用。

额外代价是提前计算的功耗、历史内存，以及动态内容／快速关闭时的未命中回退。颜色选中状态或关闭触点变化可能失效，命中时接近纯回放性能，未命中时仍要现场计算。它能改善特定入口，但不能承诺所有关闭操作均为 120 fps。

## 下一轮范围与停止条件

1. 校准测量后，只先验证散度预计算和绘制生成／筛选重排两项，按同材料、同 APK 交错 A/B 比较净收益。
2. 特别注意现有 `ParticlePerfProbe` 已记录 Adreno 的 `GL_TIME_ELAPSED` 可能漏计 compute；分段 `glFinish` 又会串行化流水。须先核实计时覆盖，再用受控离屏阶段成本和真实呈现长帧交叉判断，不直接复用九月的占比。
3. 将整段耗时下降 5%～15% 作为这轮低风险候选的**试验目标**，不是收益保证，两项不能直接相加。保留条件是净收益超过测量波动且实际长帧改善；否则删除实验实现。
4. 若仍不足，依据最新占比在带约束求解器和特定消散预热之间选择。先做局部原型，验证同等画面误差下的净收益，再扩大入口。
5. 目前真实高负载颜色场景仍有 16.7／25 ms 呈现间隔；稳定 120 fps 要控制尾部耗时，不能用平均接近 120 或提高刷新率请求代替验收。

以上为分析排序，未新增生产默认项。已有结果与原始产物位置见 [最新 120 Hz 实施记录](implementation-2026-10-08-120hz.md)。
