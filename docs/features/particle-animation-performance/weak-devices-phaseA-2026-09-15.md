# 弱设备上的消散动画：不播的根因、修复与两台实测（2026-09-15）

任务书见 [weak-devices-2026-09-15.md](weak-devices-2026-09-15.md) 第 1–5 节。本文是阶段 A
（诊断）与随后的修复、验证。用户中途裁定：**消散提前预算暂缓，先把「不播」修掉**，因此
「消散每帧 integrate / pressure / render 分段耗时」这一项按裁定跳过。

## 1 结论

**根因已定位并修复。** 魅族 20 Infinity（Flyme / Android 15 / Adreno 740）上，
「调整颜色」面板用**点外部**关闭时，对弹窗窗口的 `PixelCopy` 在整个 700 ms 重试窗口里
一直返回 `ERROR_SOURCE_NO_DATA`（状态码 3），快照为空，消散整场不播——修前 2/2 复现，
修后 2/2 正常。同一台设备、同一个面板，点「取消」「确定」走的是**离屏硬件抓图**
（`ParticleHardwareSnapshot`），11–53 ms 就拿到图、动画照常。也就是说：**不是 GPU 跟不上，
是那条只在「没有涟漪」时才走的窗口 `PixelCopy` 在这台设备上不可靠。**

修法：**弹窗里没有可见的独立 Surface 时一律走离屏硬件抓图**（与点按钮时同一条路径），
只有确有可见 `SurfaceView` 时才用窗口 `PixelCopy`；离屏那条路万一没拿到图，再用窗口
`PixelCopy` 兜一次，而不是直接放弃整场动画。

华为 MatePad Pro 13.2 上这一轮**没有复现「不播」**（32 格全部开播）。它的问题是另一件事：
「调整颜色」面板 15.7 万片时消散只有 22–34 帧（p90 50–83 ms），确认了任务书第 2 节
「消散每帧现场积分 + 压力求解，弱 GPU 跟不上 60 fps」的判断，那一项留给阶段 B。

一处**自己踩的坑**值得记下来：`消散未接管` 第一版每次成功关闭都会打两条。接管成功后

失败。加了 `particleFlowTookOver` 之后才只在真失败时打。

`ParticleCaptureDiagnostics` 的两个字段都在 `BuildConfig.DEBUG` 之外不写不读，抓图本身的
调用序列一个字节没动。

## 5 修法

`ParticleDismissController.startContent` 里，抓图的离屏 lambda 此前只在
`feedback != null || captureOffscreen` 时才构造；`feedback` 就是「点下去有没有涟漪」。
于是返回键与点外部退回窗口 `PixelCopy`。现在**无条件构造**，由
`ParticleSnapshot.capture` 内部既有的「有没有可见 `SurfaceView`」决定实际走哪条：

- 没有可见的独立 Surface → 离屏硬件抓图（`ParticleHardwareSnapshot`，重录显示树离屏画）；
- 有 → 仍然窗口 `PixelCopy` 并逐个合成各 Surface。这一条不能动：离屏重录画不出 `SurfaceView`
  的真实透明洞，各 Surface 的像素就合成不回去。

外加一次**单向兜底**：离屏没拿到图、且弹窗与宿主这一刻还在，就用窗口 `PixelCopy` 再试一次。
~~反方向不做——有 Surface 时用离屏图回退会在画面上留一块空洞，比退回系统默认退出更糟。~~

> **2026-09-15 当晚推翻这一段。** 「离屏重录画不出 SurfaceView 的真实透明洞」只对软件
> `Canvas` 成立：[ParticleHardwareSnapshot] 用的是 `RenderNode.beginRecording()` 给出的
> `RecordingCanvas`，`SurfaceView.draw` 在它上面照常记下 `punchHole`，离屏渲染器也已经
> `isOpaque=false`。于是反方向的回退是安全的，并且是必须的——录音弹窗（有可见 Surface）
> 在这台设备上点外部关闭同样卡在窗口 `PixelCopy` 的 `ERROR_SOURCE_NO_DATA`，本文的修法
> 覆盖不到它。反方向回退已于 `202609151529` 补上，见 decisions 与 sessions 里 2026-09-15
> 的「窗口 PixelCopy 失败时改走离屏重录 + 逐个 Surface 合成」。

两条规则抽成纯逻辑 `ParticleCaptureRoute`，`ParticleCaptureRouteTest` 6 项钉住（含
「有 Surface 时不往反方向回退」这一格）。顺带删掉已经没有意义的 `captureOffscreen` 参数
（`ParticlePanelAnimator` 是唯一调用方，它此前传 `true`，行为不变）。

守住的约束：出现路径一个字没改；消散的观感来源不变（离屏抓图正是出现动画与点按钮关闭
一直用的那条，且出现动画的末帧要求与真实面板逐像素相同）；`BuildConfig.DEBUG` 之外零新增
开销；不改任何窗口属性；没有引入任何 `glFinish`。

**快照等价的量化旁证**：片数由快照里的非透明像素决定。同一个面板、同一台设备，
窗口 `PixelCopy`（修前的返回键）与离屏抓图（修后的返回键）给出的片数分别是
158 474 / 158 459 与 158 486 / 158 491，附件弹窗是 107 060 / 107 052 与 107 049 / 107 046，
落在同一条路径自己重复两次的波动范围（±30）之内。

## 8 预测性返回（`enableOnBackInvokedCallback`）

`app/src/main/AndroidManifest.xml` 里**没有**声明 `android:enableOnBackInvokedCallback`，
整个仓库（含 gradle / properties）也搜不到这个名字。应用 `targetSdk 36`：Android 15（API 35）
起该清单开关对 targetSdk ≥ 35 的应用不再作为「应用级开启」的开关（系统默认开启预测性返回，
清单里只能按 Activity 显式设成 `false` 关掉）；华为这台是 API 31，这套机制根本不适用。

弹窗这一侧走的是 `ComponentDialog` 自带的 `OnBackPressedDispatcher`。两台 32 + 32 格里
返回键关闭全部正常开播，帧数与点外部同档，**没有观察到预测性返回对消散的任何影响**。
