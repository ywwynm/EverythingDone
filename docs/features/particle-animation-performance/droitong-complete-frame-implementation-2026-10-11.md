# 卓易通完整画面交接与色块恢复修正

## 依据与范围

用户提供第三轮失败录像及 `particle-display-1791715803168.zip`，要求保留 SurfaceView，同时保护原生 Android 已有阴影和 FAB／actionbar 层级。原始证据与定位见 [ZIP 分析](droitong-handoff-zip-feedback-2026-10-11.md)。第三轮整层 alpha 方案继续作为失败对照，不作为本轮默认。

候选仍只在应用内“显示兼容性检查”的虚构页面启用；没有根据品牌自动启用，没有推广到真实首页。新增诊断入口不访问记事 DAO、不改动画偏好。原生默认重新使用原有 SurfaceHolder.Callback 和首次 EGL 初始化行为，保持既有 SurfaceControl 卡片／前景交接。

## 两项修正

1. `ParticleOpaqueGlCardHandoff` 和 `ParticleBackdropSnapshot`：GL 按不透明窗口底图、粒子／静态卡片、前景绘制；真实前景不隐藏，SurfaceView alpha 不切换。不透明底图阻止真实半透明阴影与 GL 副本重复混合。整组资源在一个 GL 队列操作中撤除，待真实窗口呈现后再清除覆盖。前景租约由该候选独占，回聚预热等待上一组释放。准备未完成就取消时不显示孤立的静态卡片，迟到进入也被拒绝。
2. `ParticleSurfaceRecovery`：正确换算 ViewRoot／屏幕／捕获根坐标，记录每个裁剪和跳过原因；普通内容恢复时保留独立 Surface 区域的覆盖，等待窗口、生产者呈现 fence 和 PixelCopy 颜色检查后撤除。色块默认 RGB_565 存在量化误差，检查允许 5 位通道的 ±8 偏差，并记录实际颜色。恢复期使用有界的独立看门狗。

没有调整卡片、FAB 或 actionbar 的阴影参数。保留 Dialog 隐藏普通内容方案、旧 GL 组合、单项候选及旧 alpha 对照。默认“本轮两项组合／额外隐藏普通内容”。诊断增加 `opaqueGlHandoff`、完整组成员、底图准备时间、未完成准备的恢复分支、几何、实际色块值与呈现 fence。

## 尚需目标机验收

完整帧候选临时固定单卡片场景的背景，多一张窗口大小的底图及上传成本；不能直接用于真实列表滚动、多卡并发或含其他独立 Surface 的背景。魅族诊断采图开启时有约 1.48 s 的底图准备，松手过早会保留真实控件，可能没有完整播放粒子；该分支在简报明确提示，不能将“不闪烁”解释成该次动画已完整播放。
