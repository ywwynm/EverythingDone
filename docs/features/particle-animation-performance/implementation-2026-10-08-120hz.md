# 两种粒子的 120 Hz 优化实施

## 目标与基线

用户要求按后续建议继续实施，以实际稳定 120 fps 为目标。基线为已发布的 `202610080427`，保留流体颜色下沉、真圆和飘散新版清晰轮廓；不重复计算此前收益。仅操作三星 `R5CW20BLNKL`，空白记事的大附件、颜色弹窗是主要实机场景。

## 本轮假设与验证顺序

1. 飘散方框从 `h + 1` 收紧到 `0.64h + 0.5`，保留原覆盖函数与坐标导数。四点覆盖采样偏移为 0.25 工作像素，额外余量用于浮点和光栅化边界。先测小尺寸、亚像素中心、加法混合，再量同包收益。
2. 流体普通出现动画复用已有相邻历史状态插值，以连续进度播放；历史仍最多 60 份，正常 36 份。不靠复制 60 fps 画面达到 120 次提交。
3. 压力求解保留 96 网格、非负投影与暖启动，试 GPU 批间提前停止。用最后两次 Jacobi 结果差的全局最大值判断；投影 Jacobi 在最大范数下非扩张，因此该值也是下一步缺陷的保守上界。停止后仍保持双缓冲一致，不做逐批 CPU 回读。是否采用由检查开销、轨迹误差和三星净收益共同决定。
4. 先完成上述测量，再决定是否需要平稳段降频；未经误差和净收益验证的候选不默认开启。

## 状态

实现与验证已完成。默认数量和大小的两类流体大弹窗在本轮三星两次实测约 119～120 fps；高负载颜色消散仍未稳定 120 fps。只对已测设备、场景与设置给出结果。

## 第一轮取证

- 桌面实际 GLSL：覆盖 576 个半宽 0.001～40 的粒子、四组亚像素位置、两种混合。小于 0.5 工作像素时保留原方框；收紧后无可见边缘缺失，最大覆盖差 0.005354（约 1.37／255），平均约 0.0000006。直接裁剪极小点会有明显的光栅化舍入差，已加回退。
- 连续历史插值补足两端采样到实际积分时刻的差，避免正常 36 份历史与 240 步积分不能整除造成整数帧附近跳动。线性运动合成检查最大位置误差 0.0000032。
- 压力批间停止的着色器已与 CPU 100 次投影 Jacobi 对照：空场、平滑场、稀疏场、噪声场均通过；严格零阈值与原式一致。该数值缺陷并不是最终屏幕位移的上界，仍须完整时间轴验证。
- 三星首轮阈值 0.01～0.2 被否决：附件整段仅省约 7%，而 P99 轨迹偏移累计到约 22 px，颜色弹窗约 33 px。生产默认仍为完整求解；下一轮改测更严格阈值，不能把这一实验作为已经采用的优化。
- 飘散同包五次轮换：80,000 颗、3 倍粒径的颜色大弹窗 1.566→1.347 ms／帧，约省 14%；小场景收益较小。保留默认裁剪，小粒子仍走原方框。
- 新增不改变积分步长的候选：压力更新之间各粒子的积分独立，可把相邻 2～4 个原始 240 Hz 积分步骤合在一次 GPU 分发中，减少全局屏障和提交。仍逐步执行原公式、在每个压力／历史边界停下。与后半段降低计算频率分开对照。
- 首轮实际 UI 只启用高刷与连续回放、未启用压力近似：大附件和颜色弹窗出现达到 120 fps；现场消散约 69～81 fps，仍有计算和队列等待。后续须继续减少现场工作，不能把出现结果推广到所有流体动画。

## 第二轮算法取舍

- 压力阈值收紧到 0.001：附件 P99 位移 0.35 px、最大 0.59 px；颜色 P99 0.06 px、最大 0.11 px。单项正向净收益约 -0.4%～1.5%，准备阶段部分场景有收益；组合后仍在相同误差范围，采用这个严格阈值，不采用粗阈值。最少 32 次，最多仍遵循原用户上限，默认 100 次。
- 后半段压力 30 Hz／积分 120 Hz 不采用：颜色场景 P99 分别约 7／9 px，最大约 20／47 px，而整段收益只有约 3%～4%。
- 保留 240 Hz 公式的积分合并采用：正向约省 5%～7%，准备约省 15%～27%；P99 接近零，最大位移 0.29 px（浮点计算路径不同）。压力和历史采样边界不跨越。
- 稳定可见实例压缩采用：先组内前缀、再组间前缀、最后按原顺序复制 32 B 记录，GPU 生成间接绘制命令；不改变材料 ID、不跳过模拟、不改变混合顺序。三星附件／颜色各五时刻的 RGBA8 完全一致；桌面 1／255／256／257／10007 条记录验证分组边界和顺序。增加每颗 36 B 临时缓冲，255,059 颗约 8.76 MiB。
- 大粒子组合对照（同包轮换中位数）：附件正向 600.8→474.2 ms／120 帧（21.1%），颜色 790.5→591.8（25.1%）；73 帧连续回放分别 363.3→244.9（32.6%）、900.9→667.1（25.9%）。不同测量轮次受设备调频影响，不跨轮比较绝对值。
- 新增流体优化先限于经过实测的 Adreno 路径；其他 GPU 保留原积分分发与实例绘制。新高刷显示计划仍独立于历史缓存密度。

## 实际呈现的补充假设

现场正向每逢压力更新步，原逻辑先求出供后续积分读取的压力，再绘制当前状态；当前画面并不读取这份新压力。候选将该末步压力延至 `eglSwapBuffers` 及当前帧栅栏之后提交，并保证下一次积分前完成同一份计算。没有改变更新频率或模拟公式，待同包实际 UI 对照决定是否保留。

- 三星两个大弹窗、各五时刻验证：延后压力后的状态与 RGBA8 画面完全一致。
- 36 份历史的连续插值相对该时刻重新积分存在采样近似；当前五时刻 P99 最大约 6 px、末段少数粒子最大 16.4 px，整帧平均差最高约 2.06／255。它只影响采样之间的显示，不改变缓存轨迹或模拟；不能将压力阈值的 0.59 px 误差推广到所有插值帧。
- 最终 UI 首轮测到附件消散 119 fps，随后 ADB 的 `input tap` 子进程非零退出，批次中止；脚本 `finally` 已恢复粒子偏好及调试配置。该不完整轮次单独保留，补测使用新运行标识，不混入完整两轮统计。

## 最终实际呈现

三星 SM-S9180，120 Hz 显示，两个完整轮次。只统计粒子会话实际呈现的缓冲，剔除预热空帧与收尾清屏。压力迭代用户设置为默认 100。

| 样式／设置／弹窗 | 出现 fps（两轮） | 消散 fps（两轮） | 消散间隔 P90 |
| --- | --- | --- | --- |
| 流体／数量 1×、大小 1×／附件 | 120、120 | 119、119 | 8.34 ms |
| 流体／数量 1×、大小 1×／颜色 | 120、120 | 120、120 | 8.34 ms |
| 流体／数量 1.6×、大小 3×／附件 | 120、120 | 113、112 | 8.34 ms |
| 流体／数量 1.6×、大小 3×／颜色 | 120、116.1 | 92.2、103 | 16.67 ms |
| 飘散／数量 1.6×、大小 3×／附件 | 120、120 | 118、118 | 8.34 ms |
| 飘散／数量 1.6×、大小 3×／颜色 | 118.3、120 | 120、120 | 8.34 ms |

- 同包关闭末步压力后移时，流体重负载附件消散为 97.2、98.2 fps，颜色为 86、87.5 fps。因此保留后移；没有降低压力更新频率。不能将离屏平均耗时降幅直接等同于实际帧率提升。
- 默认档流体八次动画约 119～120 fps：附件消散每轮各有一次约 16.67 ms 间隔，其余六次为 120 fps；重负载下仍有 16.67～25 ms 间隔，尤其颜色消散。稳定 120 fps 的目标尚未覆盖全部设置／入口／设备，不宣称已全部达成。
- 对照图已检查：稳定实例压缩没有丢掉颜色、边缘或改混合次序；严格压力近似的对照保持整体形态。
- 所有场景使用空白新建页，只开关弹窗，不输入、不选附件或颜色、不保存记事。每轮首页计数一致，测试后还原粒子偏好、采样开关、调试配置及旋转状态。
- 实际呈现原始数据：`tmp/harmony-particle-android-port/hz120-flow-default`、`hz120-flow-final-on2`、`hz120-flow-final-off`、`hz120-drift-final`。离屏原始数据：`tmp/particle-120hz-20261008/flow-refined`、`flow-compact`、`order-final`。

## 回归

- 366 项粒子相关 JVM／GLES 编译测试通过，0 失败、0 跳过。
- 桌面实际 GLSL 共 100 组压力检查，覆盖 8／24／33／100／200 次迭代、空／平滑／稀疏／噪声场及五档阈值；另外验证亚像素覆盖、历史插值和稳定实例压缩。
