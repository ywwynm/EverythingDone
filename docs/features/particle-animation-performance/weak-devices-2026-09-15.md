## 3 问题一：新建按钮坐标移出预算指纹

**没有影响。** 预算用的轨迹几何（`virtualTouchX/Y`、`touchGap`、`touchStrength`）来自**上一次真实创建页**
记下的 `spec`（`ParticleCreationPrewarm.remember`），按配置键存取；同一个键下按钮的标称布局位置由窗口尺寸、
方向、系统栏与输入法高度决定，这些项都还在键里。会变的只有按钮的瞬时 translation / scale（提示条上移、
列表滚动收起、点击缩小），而那正是不该进键的量。剩余差异只是方向差几度（Opus 在华为上算的是 3.5°），
用户已裁定接受。转场自己的揭示圆心仍用标称中心，涟漪档不受影响。

## 4 问题二 (a)：「消散不播」的候选路径

> **2026-09-15 阶段 A 已逐条验证，结论标注在每一条开头**，数据见
> [weak-devices-phaseA-2026-09-15.md](weak-devices-phaseA-2026-09-15.md)。第 1 条就是根因，
> 已修复并发布 `202609151437`。

下面按可疑度排序；每条都写明是否有日志、怎样一次验证。**当前代码里第 1、4 两条失败时一条日志都不打**，
这是先要补的。

1. **【已证实，且就是根因】快照为空，静默走系统默认退出。** `ParticleDismissController.startContent` 在 `snapshot == null` 时直接
   `onAnimationStarted(); onOverlayShown()`，弹窗立即消失、没有粒子、没有日志。抓图有三条路径：
   - 点按钮（弹窗里有可见涟漪）→ `ParticleHardwareSnapshot.capture`（离屏 `HardwareRenderer`，1200 ms 超时，
     `syncAndDraw` 非 OK、`acquireNextImage` 为空、fence 700 ms 超时都返回空）；
   - **返回键 / 点外部（没有涟漪）→ 窗口 `PixelCopy.request(window, …)`**（`ERROR_SOURCE_NO_DATA` 重试 700 ms，
     其它状态直接为空；整体 900 ms 超时）；
   - 弹窗内有 SurfaceView → 同样窗口 `PixelCopy`，且先等涟漪结算。
   魅族（Android 15 / Flyme）对弹窗窗口做 `PixelCopy` 是否可靠，没有任何数据；华为 API 31 亦然。
   这一条能同时解释「有时」（取决于关闭方式）和「魅族更频繁」。

   **实测**：魅族「调整颜色」面板 + 点外部，窗口 `PixelCopy` 整个 700 ms 重试窗口都返回
   `ERROR_SOURCE_NO_DATA`（状态 3），修前 2/2 不播。修法就是这里预想的那一条——没有可见
   `SurfaceView` 时一律走离屏硬件抓图。修后魅族 12/12、华为 16/16 全部开播。
2. **【未测到】动画层 attach 时拿不到窗口 Surface**（`ParticleWindowSurface.of` 返回空：宿主 decor 未附着或 Activity 已销毁）
   → `onSessionFinished(false)` → 240 ms 整层淡出。观感是「淡出而不是粒子」，无日志。
   两台共 60 格一次都没有出现「消散降级淡出」。日志已补齐，以后出现就能认出来。
3. **【未测到】GL 线程异常** → `ParticleSession.fail` 打 `粒子动画回退`（有日志）→ 淡出。共享资源尺寸不允许改
   （`allowResize = sessions.none { it.started }`）时 `ensureShared` 失败会 `failAll()`。日志里一次都没有。
4. **【未测到】`start()` 前置条件不满足返回 false**（主线程、`areAnimatorsEnabled`、decor 未附着或尺寸 0、宿主 finishing、
   宿主 decor 未附着）→ 系统默认退出，无日志。出现路径上 Opus 已把同类拒绝改成具名日志，消散没有。
   已补成具名日志「消散未受理：…」，本轮一次都没有触发。
5. **【已排除】**`BaseDialogFragment.dismiss()` 的 `particleDismissAttempted` / `particleFlowPending` 重入保护误判
   （例如上一次尝试失败后同一实例再次 dismiss）。每次关闭都恰好受理一次；接管成功之后
   fragment 的 `dismissInternal` 与 `onDestroyView` 各再调一次 `Dialog.dismiss()`，那是正常收尾。
6. **【已排除】**预测性返回：`targetSdk 36` 在 Android 15 上若清单开了 `enableOnBackInvokedCallback`，系统会先对弹窗窗口
   做返回预览动画，再进入我们的回调；只影响观感（窗口先缩再散），不是「不播」。要核一下清单。
   清单里没有这个属性（全仓库搜不到）；两台返回键关闭共 32 格全部正常开播，帧数与点外部同档。
7. **【已证实「仍播」】**弹窗→弹窗（附件 → 录音）在弱 GPU 上是「消散现场积分 + 下一弹窗预计算」同时跑，消散会更卡，但应当仍播。
   华为 4/4 全播（55 / 54 帧），并不比单独关闭更差。魅族缺 `RECORD_AUDIO`，这一格跳过。

## 6 阶段 B（设计，待用户裁定后再派 Opus）：消散提前预算

### 6.1 原理

把创建页出现动画的做法搬到消散上：**轨迹与贴图分离**。弹窗静止时，用当时的快照建材并把整段正向轨迹算成
历史采样（与出现动画共用 `beginReverse / stepReverse / endReverse` 与 `HistoryPool`，只是播放时下标递增）；
真正关闭时，只把**当次现场抓的真实快照**上传为前景贴图（`replaceForeground`），逐帧 `drawReverseFrame`。
每帧成本从「4–6 步积分 + 一次压力求解 + 绘制」降到「一次历史转存 + 绘制」，即出现动画的每帧成本——
华为上已经证明能到 60 fps。首帧是全部微片静止在原位、按恒等映射采样真实贴图，与真实弹窗逐像素相同；
末帧全透明。预测偏差只影响途中每片的权重与出生时刻，不影响任何像素来源。

### 6.2 必须裁定的点：轨迹依赖触点

消散方向由「弹窗中心 → 触点」决定，`touchGap` / `touchStrength` 又由触点相对弹窗与可见屏幕的位置决定，
都是建材输入——**一份轨迹只对应一个触点**。提前预算时不知道用户会点哪里，只能按候选锚点预算：

- 无触点关闭（返回键、代码关闭）：固定方向、无 touchGap，完全由快照决定，**总能预算**。
- 点按钮 / 点某一行 / 点外部：触点各不相同。

可选方案（**D7**）：

| 方案 | 做法 | 观感 | 代价 |
|---|---|---|---|
| B1 只预算无触点档 | 只覆盖返回键与代码关闭 | 逐位不变 | 覆盖面最小，按钮点击仍走现场 |
| B2 按控件锚点 + 容差 | 每个会关闭弹窗的控件以中心为锚点各算一份；真实触点落在该控件且离锚点 ≤ R（建议 24–32 dp）时用预算，否则现场 | 方向差与剥离起点差都在 R 以内 | K 份轨迹（附件弹窗 4 行 + 无触点 = 5 份） |
| B3 按控件锚点、不设容差 | 同上但落在该控件内即用 | 方向最多差控件的张角（底部按钮约 ±15°），剥离起点最多差半个控件 | 同 B2 |
| B4 现场触点，弹窗静止期只预建材 | 触点到手后再算轨迹 | 逐位不变 | 弱 GPU 上仍跟不上，只省建材 35–70 ms |

我的建议：**B2**，并按「上次在同类弹窗上点过的控件 → 无触点档 → 其余控件」的顺序预算，弹窗开着的时间
不够就只覆盖前几份；R 取 24 dp，用户看实机后可放宽。

### 6.3 内容变化与不适用的弹窗（D8）

- 触发：弹窗出现动画结束后，decor **300 ms 内没有任何绘制且没有触摸在途**才开始；预算完成后每次绘制都把
  这份标成过期，再次静止 300 ms 后重算（弱 GPU 上一份 0.5–1.1 s，重算有上限）。
- 因为播放时贴图总是真实快照，**只改像素不改版式**的变化（调整颜色面板的选中环、颜色预览）不需要重算，
  按弹窗类型声明「版式稳定」即可；尺寸变了则在 `adopt` 处按现有尺寸校验退回现场路径。
- 不适用：持续绘制的弹窗（FableSol 海浪、录音计时、加载进度）——静止判定天然排除，另加类型级开关避免反复尝试；
  弹窗内有 SurfaceView 的（快照必须走窗口 `PixelCopy`，不能在静止期离屏抓）。
- 提前关闭：预算没算完就关 → 丢弃走现场（简单版）；或让播放边消费边算（手势路径的追赶机制），作为后续项。

### 6.4 资源（D9）

- 显存：历史按实测约 8.7 B / 片·采样，60 采样：106k 片约 55 MB、157k 片约 82 MB，**每份锚点一份**；
  弹窗关闭即释放，内存告警时释放。B2 下附件弹窗最多 5 份，需要给「同时保留的份数」设上限（建议 3）。
- GPU 时间：每份华为 0.5–1.1 s、OPPO 0.24 s、魅族估 0.3–0.4 s，在弹窗静止期以节流队列跑，有涟漪时让路。
- 静止期抓图：离屏硬件抓图 12–70 ms，主线程只录制显示列表。

### 6.5 预期与验收

- 华为消散 32–54 帧 → 与出现同档（≥ 58/61 帧）；魅族在 0.75 缩放下同样脱离每帧积分数的影响。
- 点按钮到首帧：去掉建材与首帧积分，预计缩短 50–120 ms。
- 验收口径：命中率（按关闭方式分）、`完成 count=` 的帧数与 p90、首帧延迟；G0 只对无触点档与 B2 命中且触点
  恰在锚点的情形要求逐位相同，其余按 G1 由用户看图。真机仍是每台一轮。
