# 卓易通完整帧候选：启动延迟与按钮阴影回归

debug `202610111242` 已发布并核验，见 [发布日志](debug-updates/update-20261011204237.md)。三台设备已恢复原包；本地对照通过的范围见下文。

## 最新目标机反馈（2026-10-11，debug 202610111242）

- 用户反馈“感觉 OK 了”，并追问这套方法是否会改变 Android 端的画面、行为。记录为当前诊断候选的正面观察，不扩展为全部入口、连续操作和媒体生产者已通过。
- 当前兼容候选仍按调试 Activity 注册，普通业务页和 release 构建没有启用。普通 Android 默认路径的回归结论与“在 Android 也强制启用候选后完全等价”是两个不同结论；后者尚未证实。
- 固定窗口底图、首帧前松手后的补播以及独立 Surface 下的普通控件阴影补录仍是候选特有行为。当前接入阶段需保留原生默认路径，并另行验证真实业务页面，不能仅凭诊断页的正面反馈全局替换；这不构成长期维持两套实现的架构决定。

## 关于直接全局启用的解释（2026-10-11）

用户进一步询问为何要单独兼容、全局采用有什么具体问题。这是方案讨论，未授权将候选全局开启。“兼容模式”是当前过渡建议，不是平台要求；保留 SurfaceView 与将来统一实现并不冲突。

- **源码已明确的限制**：`ParticleBackdropSnapshot` 只捕获一次不透明底图；动画期间，未被单独重绘的背景内容即使在真实窗口更新，也会被旧图覆盖。卡片完整画面交接调用的 `ParticleWindowSurface.claimGlVisibility` 拒绝同窗另一粒子会话；该分支的前景成员也按完整组独占，重叠操作可能等待或结束动画，不能直接承诺多卡连续播放。这不是普通 Dialog 粒子会话的全局互斥规则。底图捕获还明确拒绝可见独立 Surface。
- **实际开销但尚未证明全局性能回退**：增加整窗底图捕获、纹理保留和 GL 绘制。最新候选比上一轮兼容候选更快，不代表比原生既有路径更快；不能把候选间的启动对照解释成原生性能收益。
- **已测范围之外的边界**：独立 Surface 的生产者恢复完整验证来自自有色块；未知生产者只能检查现有缓冲。补阴影目前选择普通叶控件及自身单位变换，不能保证嵌套容器、裁剪和复杂层级完全等价。快速松手补播也改变该边界下的进度处理。
- **可统一的方向**：分别评估 Dialog 内容隐藏、独立 Surface 恢复、前景与粒子同 GL 绘制。全局使用完整组合前，先补齐动态背景和并发会话，再对真实业务页、阴影、交互及性能做原生基准对照。没有证据要求永远按 Android／卓易通维护两套实现。

## “添加附件 → 录音”的复核及需求收敛（2026-10-11）

- `AddAttachmentDialogFragment.showRecordAudioDialog()` 先请求打开录音 Dialog，再调用自身 `dismiss()`；没有等待旧粒子播完。`GestureAnchoredDialog.dismiss()` 在受理消散后立即登记 leaving，`ParticleDialogStack` 据此让新的普通弹窗继续使用同一个 Activity 粒子宿主；真正仍保留的下层弹窗才走抬升宿主。
- 普通 Dialog 的控制器没有传入卡片阴影原子交接参数，`ParticleDismissOverlay.glCard` 为 false，因此不会进入完整底图的单卡独占。`ParticleWindowSurface` 仍逐个绘制多个粒子会话，再统一提交。源码支持该重叠；本轮没有实际运行“添加附件 → 录音”，不能声称卓易通已通过这个流程。
- 应区分“一次用户操作”和“一个粒子会话”。一次弹窗转场可包含前一个消散、后一个出现；必须保留这种现有行为，不用排队等待解决交接。用户未要求新增任意数量卡片并发，不将这项泛化能力列为本轮前置条件；已有可发生的重叠仍纳入回归。
- 用户明确性能验收重点为渲染帧率和交互延迟，耗电、内存占用暂不单列为取舍指标。需要原生旧路径与统一候选在相同场景下对照，不能以纹理数量或兼容候选之间的提速代替。
- 静态底图需改为能持续显示背景变化的实现，同时维持阴影不重复叠加；应用实际控件的完整捕获与恢复是必须完成的功能，不能把普通叶控件补录当成通用方案。后续设计按普通 View 层级与独立渲染内容分别处理，但要保留原始变换、裁剪、遮挡、阴影和状态动画。

## 用户反馈（debug 202610111152）

- 用户确认当前候选的闪烁已经消失，但卡片粒子开始播放的延迟明显增加。
- 快速滑动并松手会直接不播放粒子动画；这是交互回归，不能以保留真实卡片作为通过条件。
- 独立 Surface 弹窗出现时，关闭按钮的阴影没有进入粒子画面，动画结束后才突然出现。
- 上轮“暂时固定背景”指动画期间用窗口底图遮住重复绘制；“准备慢时保留真实卡片”指底图未准备完就已进入收尾，实际可能漏播。两者只是候选限制，不能作为最终行为接受。

## 本轮验收约束

保留 SurfaceView 和已确认有效的内容隐藏、独立 Surface 恢复方案；不能用关闭粒子、吞掉快速手势、增加首帧等待或删除阴影来消除闪烁。需分别测量触摸到粒子首帧、准备各阶段，以及按钮捕获图与真实画面的阴影。兼容试验继续限于应用内诊断页面，普通 Android 默认路径保持原行为。

## 可重复验证入口

沿用 debug 真机探针和系统输入录屏，新增快速完成／取消手势与采图开关对照。上轮魅族底图准备约 1.48 秒及准备中取消记录是现成的失败样本；以同一手势下实际出现粒子及结束状态为依据，不能只看回调成功。独立 Surface 同时检查粒子材料图和动画结束后的按钮阴影。

## 已确认原因

- 三星旧包 100 毫秒快速完成手势：触摸到首帧回调约 315 毫秒；前景准备之后才抓底图，底图自身约 82 毫秒，之后还有上传和两次窗口帧。取消回弹则可能在这个串行准备完成前关闭交接。
- 按钮阴影并非尚未结束的透明度变化：独立 Surface 强制离屏时，`captureSnapshotAsync` 选用软件 Canvas；已导出的源图确实没有 elevation 阴影。该路由原本用来避免第二个 HardwareRenderer 重新渲染活的 SurfaceView 节点，引发真实 SurfaceControl 裁剪变化。不能简单把整个弹窗改回硬件绘制。
- 新验证发现报告文件可能仍是异步落盘的旧版本；计时以启动器最终取得的内存报告为准，不能把初始 report.json 只有 run_created 误判为无手势。

## 快速手势澄清与复现

- 用户澄清是在虚构调试页：卡片直接消失，然后播放回聚。这对应完成分支，问题是前半段消散被跳过，不再要求用户区分业务完成／取消状态。
- 快速首帧迟到时，ItemTouchHelper 的松手位移已推进到 1；粒子第一次显示就接近末尾，之后只看得到回聚。三星新准备路径虽降到约 133～165 毫秒，未经进度修正时首帧仍可从约 0.80 开始，不能只凭首帧变快认为漏播已经修复。
- 魅族极短手势暴露尚未执行激活绘制便结束输入的边界。最终候选从 `ItemTouchHelper.onSelectedChanged` 确认真正进入滑动后激活，不从原始 MOVE 猜测；测试页接入这一回调。首帧前松手则保留未播放进度，等待真实完成回调继续消散。普通 Android 分支不启用这一策略。
- 三星新旧关闭采图对照：旧候选首帧约 279 毫秒，新并行／硬件纹理候选约 133 毫秒；底图约 83→16 毫秒。单次计时不代表卓易通实际收益，需连同两种样式和实际画面继续验证。
- 按钮安全阴影候选的源图已经包含阴影，三星两次出现／恢复录像 416 帧未见色块在正常显示后插入灰块；还需检查另一设备与收尾阴影一致性。

## 未采用的试验

- 原始 MOVE 提前激活会在列表尚未接管时建立粒子会话，实测可等不到真实完成回调，已撤回。保留真实选择事件作为接管依据。
- 延后 DOWN 捕获及飘散卡片原图保持硬件缓冲未消除魅族极短输入的边界，均已撤回，不为没有收益的试验改变既有卡片材料。保留已测有效的底图／前景纹理导入、并行准备和同帧开播。
- 回归工具加入系统异步触摸序列，明确注入 10 次 MOVE，并保存序列参数；不能把 shell input 在繁忙设备上的同步耗时当作实际手势时长。注入失败的场次不计入通过。

## 本轮验证结果

- 关闭采图的同手势首帧回调：三星旧组合约 279 ms，新组合约 151 ms；魅族 200 ms 手势旧组合约 1,079 ms，新组合约 339 ms。底图硬件导入准备约 12～17 ms。这里是回调计时，不等同于屏幕呈现测量，也不代表卓易通性能。
- 三星飘散与流体、OPPO 飘散的 100 ms 快速完成，以及魅族飘散 200 ms 完成，均记录首帧前松手、从 0 开始、完成一次消散和一次回聚；三星短拖回位也已复测。魅族 100 ms 注入未触发列表选择事件，不计为通过，未改变系统滑动判定去强制完成。
- 三星／魅族分别复测原生默认短滑取消和完成回聚，与旧包基线比较结束 alpha、位移、z、完成次数、卡片阴影和前景层级。局部录屏指标与原基线相近，未发现新增的整组消失或 FAB 遮挡。OPPO 原生及候选运行、结束状态和静态截图通过；系统仍拒绝录屏，不能用于逐帧无闪烁结论。
- 独立 Surface：三星飘散、魅族流体各连续打开两次，新源图包含按钮阴影；954 帧录像未发现已稳定色块之间的灰块中断。普通按钮采用真实 z／outline 和窗口光源，没有修改阴影参数。
- 本地 assemble、7 类 40 项相关单测通过；真实导出 ZIP 为 1,060,213 字节、12 份报告、86 张图，CRC 正常并包含新开关。单测和导出成功不能替代目标机显示验收。
- 过程材料在 `tmp/particle-fifth-validation/`；持久摘要见 [验证证据](diagnostics/droitong-2026-10-11/startup-shadow-evidence.json)。保留 SurfaceView、旧组合及全部独立 Surface 恢复逻辑；只在新诊断候选启用，不推广普通首页。静态背景、多卡并发、真实媒体生产者和嵌套投影仍需另行验证。
