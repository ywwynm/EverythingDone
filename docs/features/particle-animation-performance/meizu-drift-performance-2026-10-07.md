# 2026-10-07：魅族飘散动画性能诊断

用户反馈魅族上的飘散动画仍有可感知掉帧，允许快速算法与近似算法，并明确授权 Wi-Fi ADB 连接。开始时工作区已有空间照片等无关改动，本轮保留这些改动。

## 连接与测量范围

- 无线配对成功，随后使用用户提供的主页面连接端口建立调试连接；设备标识 `392QBFED2226B`，MEIZU 20 Inf，1368×3192，Adreno 740。
- 已备份安装包至 `tmp/meizu-drift-20261007/baseline.apk`；原包 27,730,747 字节，用户设置为飘散，数量和大小均未覆盖默认值。初始旋转设置与显示状态另存于同一目录。
- 只在该魅族设备上操作。优先用既有调试 Activity 的合成快照、虚构卡片，不操作真实记事数据。
- 测量分开记录 GPU 整套绘制与各阶段成本、呈现间隔和起播延迟。先完成一轮基线，改动之后一轮合并回归；避免无目的重复跑机。
- 最近的内部裁剪修复将半分辨率工作面扩展到全窗口，尚未做真机性能测量；此前三星上的普通帧 GPU 基准是扩展之前的数据，不能直接外推到当前魅族版本。

## 实施状态

- 既有基准已运行：新建页 1.72 ms、多选移除 1.22 ms、弹窗 0.97 ms、矮卡 0.59 ms，均为整段离屏命令提交及 GPU 完成的平均耗时。
- 小弹窗消散出现 80/122 帧、最大间隔 41.5 ms；需要逐帧节拍进一步归因。原 UI 脚本会在消散期间调用 uiautomator，可能引入测量干扰，因此补做两段仅记录节拍、动画期间不导出 UI 的受控观察。
- 基线阶段待证伪的假设按顺序为：节拍或提交不均匀；现场 GPU 耗时尖峰；共享准备任务挤占绘制线程；时间量化带来的重复状态。当时尚未修改生产渲染路径。
- 用户追加重点为「添加附件」和「改变记事颜色」大弹窗，后续现场验收以这两类为主，并覆盖首页颜色面板和详情页颜色弹窗。

## 已确认的刷新率问题

- 两段小弹窗与两类真实大弹窗均复现；动画期间不运行 uiautomator 后问题仍存在。
- 添加附件快照 980×965，约 30,863 颗；详情页颜色快照 1312×2099，约 57,814 颗。出现约 120 Hz，消散只收到约 82～89 次节拍／秒，多数合成从节拍到提交为 3～5 ms，栅栏通常仅 0.02～0.03 ms。
- 消散期间的 SurfaceFlinger 与 DisplayManager 输出同时显示：粒子 Surface 请求 120 Hz、策略 OnlySeamless；应用 uid 被覆盖为 60 Hz，物理显示模式也为 60 Hz。证据保存在 `tmp/harmony-particle-android-port/meizu-large-before/`。
- 先只检验高刷 Surface 请求允许模式切换这一项；调试开关支持同一 APK 内 A/B。Android 官方的 [帧率接口说明](https://developer.android.com/media/optimize/performance/frame-rate) 指出仅无缝请求可能无法切换模式；[View 帧率机制](https://developer.android.com/develop/ui/views/animations/adaptive-refresh-rate) 区分 View 与 Surface 的投票。
- 此处正确性需要 ROM／合成器参与，JVM 无法复现，使用真实大弹窗与驱动呈现时间作为回归入口。
- 仅将 Surface 切换策略改为 ALWAYS 没有改善：系统仍为 60 Hz，附件／颜色消散分别只记录 72／65 个真实呈现时间。该改动和调试开关已撤回。
- 宿主 Activity 窗口的 `preferredRefreshRate` 同样无效：两类消散各记录 62 个真实呈现时间，显示模式与应用覆盖仍为 60 Hz；系统标记 `ignore_app_preferred_refresh_rate_request=true`。该实现撤回，未作为优化保留。
- 接下来只验证窗口 `preferredDisplayModeId`：在当前分辨率内选择不超过目标 120 Hz 的最高模式，动画结束恢复原模式偏好，不修改系统刷新率设置。预计一轮两类大弹窗；检查系统 base mode 是否真正变化，再决定是否补充同包对照。
- 首轮显示模式请求有效：附件与详情颜色消散均为 123 次合成、117 个真实呈现时间，121 个相邻节拍为单个 vsync；系统 base mode 改为 120 Hz，应用 uid 覆盖也变为 120 Hz。记录在 `meizu-mode-candidate/`。接下来保留这一项，补上模式选择与多 Surface 请求恢复的行为测试，再以同 APK 开关做两轮对照并覆盖首页面板；不降低数量、分辨率或改变轨迹。
- 同包两轮证明详情弹窗改善，但首页面板仍约 91 fps，后半段降为 60 Hz。窄范围请求日志证明窗口模式请求从准备一直保留到动画收尾，未提前释放；后半段 SurfaceFlinger 同时显示各可见粒子相关层明确投 120 Hz、系统仍选 60 Hz。下一项只验证 API 35 的窗口节能平衡开关（项目音频连续动画已使用），动画期间关闭、结束恢复，预计仅补测首页一轮。
- 窗口节能平衡开关无收益，首页仍 88 fps，已撤回。首页降频时间与系统 1000 ms 触摸提速结束吻合；详情消散还有暗层更新，首页的窗口内容本身已静止。下一项仅测试在真实粒子缓冲提交后通知 SurfaceView 重绘，让窗口渲染链知道外部表面仍在动画；不生成假触摸、不改系统设置。只补首页一轮，需同时检查增加的窗口提交是否仍能稳定高刷。
- SurfaceView 每帧通知重绘同样无效（首页约 86 fps），也增加了窗口绘制负担，已撤回；临时请求日志也已删除。进一步只捕获首页消散 2 秒内的 gfx/view 跟踪，确认系统最终降频的判定路径，不继续叠加未经验证的刷新率提示。
- `home-late.atrace` 明确记录触摸加速结束后转为 `60 Hz (scored)`，不是 `Idle`；三张活动层都是 ExplicitExact 120 Hz，粒子提交仍连续。仅窗口模式偏好不足以阻止该设备的合成器评分降频。下一项使用系统为 View 自绘动画提供的 HIGH 类别请求，只在高刷会话开始／结束时变更，不逐帧重绘，补测首页一轮。
- HIGH 类别请求也未改变首页的约 91 fps，已撤回。最后检查公开窗口属性的组合：保留有效的模式 ID，同时表达数值刷新率偏好，以验证 ROM 是否另有只读数值偏好的策略分支；预计首页一轮，无收益即撤回并保留系统限制的明确记录。
- 两个窗口属性并用也无收益（首页 90.3 fps），已撤回，最终仅保留经过同包对照证明有效的模式请求。系统限制尚未消除，不能声称首页所有飘散入口都达到 120 fps；继续补测首页展开颜色页、流体与其他公共入口的回归，并在交付中明确区别。

## 同 APK 对照结果

`meizu-final-off/` 与 `meizu-final-on/` 各两轮，唯一配置差别为 `driftWindowFrameRate`，沿用实际随机轨迹。按会话实际提交的目标时刻匹配驱动呈现记录，排除预热空帧和末尾清屏；未返回真实时间的缓冲不计作呈现。下列 fps 是已观测呈现间隔的有效帧率，不等同于面板标称 Hz。

| 消散入口 | 关闭请求 | 开启请求 | 呈现间隔 P90 |
| --- | --- | --- | --- |
| 添加附件，980×965 | 58.5～59.4 fps | 112.2～115.8 fps | 16.6 → 8.3 ms |
| 详情页颜色，1312×1463 | 58.4～58.5 fps | 112.6～113.6 fps | 16.6 → 8.3 ms |
| 首页外观面板，1368×986 | 90.1～91.3 fps | 两轮均 91.1 fps | 16.6 → 16.6 ms |

本轮与手机原始安装包之间还有既有提交差异（如取消灰度内容强调、面板结构调整），因此最终收益使用同包开关对照，不能将安装新版本的全部差异归到本次修复。两类详情弹窗出现阶段原先已高刷，主要改善为消散。个别 16～41 ms 间隔仍存在，不声称零掉帧。

模式选择与多 Surface 重叠请求、重复释放、外部修改、不同窗口隔离等行为回归共 5 项，连同相关既有测试共 78 项通过。诊断开关和调参文件由脚本 finally 恢复；空白新建返回后首页计数不变，所有轮次旋转设置均保持 `(0, 0)`。

最终候选附件约 31,029 颗、详情颜色约 61,655 颗。首页另外展开真实颜色页后消散，快照 1368×1666、约 59,881 颗，两轮均 86.1 fps、P90 16.6 ms（`meizu-home-expanded/`）；与较矮外观面板一致，仍有后半段系统降频，未将此项记作已优化。

对照后的空闲窗口检查：模式偏好已撤销，粒子层不再表达刷新率请求；没有把静止页面锁在高刷。新增的真机脚本只操作空白新建页和不提交的外观草稿，未改变任何真实记事内容。

最终公共入口合并回归 `meizu-final-regression/` 完成：流体、飘散分别执行小弹窗开关、合成卡片左滑、批量移除和空白新建返回。飘散出现／消散／跟手的 P90 均为 8.3 ms；流体完成原流程，不将此轮结果解释为流体性能改善。脚本确认偏好逐字恢复、旋转仍为 `(0, 0)`。
