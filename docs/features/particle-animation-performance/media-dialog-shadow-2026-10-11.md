# 媒体负载与 Dialog 外部阴影诊断

## 用户反馈与范围

用户观察到魅族首页有较多视频和 GIF，怀疑媒体加载占用资源导致粒子准备慢，要求验证。另反馈新旧方案均有 Dialog 外部阴影在消散启动时突然消失，出现时也可能缺失，要求排查、修复并发布阿里云。用户离线休息，授权内的诊断、修复与发布连续完成，不等待额外确认。

继续使用已授权三星、魅族和 OPPO，不改变已有记事；测试前保存当前 APK 和数据摘要，结束恢复原包并比对用户记事。保留 SurfaceView、共同默认方案、动态背景和弹窗重叠，不用全局暂停媒体掩盖性能问题。

## 反馈循环

- 媒体：同一首页、相同取消手势，比较进入后初期、加载稳定后、仅诊断时暂停已加载动图三种条件；记录实际动图数量、准备阶段耗时、UI 帧与线程工作量。暂停只在 debug 探针进程生效并恢复，不修改偏好、记事或缓存。
- 阴影：普通 Dialog 与独立 Surface Dialog 的出现、静止、消散连续录屏；对照窗口外下方阴影带和源快照，检查交接是否缺影或叠加变深。真实附件／录音转场再复验；不以回调成功替代画面。
- 先保存本轮修复前基线，再按证据修改；避免改动首页卡片已验证的阴影参数与粒子行为。

## 新增入口要求

用户继续反馈 DoingActivity 卡片滑动漏播并伴随背景闪烁。本轮将实际调用入口逐项纳入核查：首页、Doing、设置预览、新建页、滑动回归、普通／嵌套／底部／独立 Surface Dialog 与附件到录音转场。不能把首页或诊断页通过外推为所有入口正确；Doing 验证不得启动或结束真实任务计时。

## 已取得的媒体对照证据

魅族同一首页执行六次相同取消手势：刚进入两次、等待 8 秒两次、等待 8 秒且仅探针暂停动图两次。实际可见媒体为一个 600×450、75 帧 GifDrawable（视频预览也使用该管线）。识别滑动至首帧回调分别为 588–951 ms、109–158 ms、58–59 ms；稳定后移动阶段约 112–114 FPS，暂停动图并未明显提高持续帧率。刚进入时 GIF 线程最高消耗 2.26 核秒，主线程布局也明显较重；稳定后 GIF 约 0.48–0.55 核秒。证据支持媒体初始加载／解码参与资源竞争，但等待也改变 JIT 和其它启动工作，不能把全部早期延迟归于媒体。生产行为继续保持背景动画，不默认暂停 GIF。

三星及魅族普通 Dialog 录屏已复现整体外部阴影在消散起点提前消失；源码当前仅捕获 DecorView 本体，未包含根 RenderNode 在父级合成的阴影及外扩区域。尚需验证首尾交接不会形成双重阴影。

## 实现与验证范围

- Doing 使用透明壁纸窗口，GL 完整背景再覆盖原窗口会重复半透明遮罩。透明窗口改为直接对应用自有 SurfaceView 的 SurfaceControl 提交 alpha 事务，并与真实 View 的窗口帧同步；不复用已有反例的 View.alpha 方案，也不读取壁纸或冻结动态壁纸。此能力分支与品牌无关，需由实际屏幕验证事务语义，不能仅看 committed。
- debug 新增真实 DoingActivity 子类：复用生产布局、适配器、ItemTouchHelper 和 ParticleSwipeAnimator，仅隔离服务绑定与完成动作；虚构普通文本记事不进入 DAO。应用内也可左右滑动测试。
- Dialog 外部阴影独立捕获根 outline／elevation 的投影，随主体形成／消散平滑变化。粒子材料本体边界不扩大，避免改变粒径、方向与已有卡片阴影；首尾使用多窗口帧同步，在原生投影和承接投影间切换。内容与独立 Surface 继续原恢复协议。Android 录像结果见后文，卓易通仍需用户验收。

### Doing 漏播的第二个根因

三星逐帧录像确认：起先所谓“消散播完”只有卡片消蚀，实际没有飞出的飘散颗粒。Doing 列表的 0.84 浓度被烤入快照，而飘散着色器明确跳过材料 alpha 小于 1 的像素，整张卡片因此都不生成颗粒。这与背景闪烁是两项问题。修正为材料保留原始 alpha，容器浓度在最终颗粒／主体合成与静态交接时应用；默认浓度 1 的首页和 Dialog 输出不变，半透明阴影仍不产生飘散颗粒。流体既有材料浓度处理保持原样。

### 批量移除的重叠会话遗漏

扩展到真实批量退场控制器后，三机虚构列表发现确认 Dialog 主体消失、尾部颗粒仍在播放时，卡片交接因窗口还有其它会话而拒绝，最终只刷新列表。根因是完整背景交接沿用了“会隐藏整张 Surface”的独占限制，而当前这一交接只修改自己的 GL 图层，并不改 Surface alpha。修正只放宽此路径对普通粒子会话的限制，仍拒绝另一组前景交接；透明窗口需要改 Surface 事务 alpha，继续保留独占要求。用原有真实确认弹窗→虚构批量退场场景验证，不能以直接无弹窗触发替代复现。

放宽后 OPPO 再现另一项旧时序错误：前一个 Dialog 已到进度 1，却等整个在途帧计数归零才退出；后一个动画不断带着它重画 HOLD 帧，使其迟迟不归零并触发看门狗。飘散与流体均改为确认本会话的进度 1 末帧后自然结束，出现动画仍保留末态到真实 View 恢复；不增加等待或延长看门狗。验证覆盖原确认流程和真实附件→录音的重叠回调。

设置页又捕获同一卡片“消散→回聚”的间歇漏播：完成回调在真实 View 属性恢复时就触发，前一组 GL 层尚有约数十毫秒的呈现／释放过程，下一轮回聚因此申请失败。`ParticleSwipeAnimator` 改为在旧 overlay 的 `afterRelease` 后发送完成通知，不添加固定延迟；取消回拉仍在原时刻恢复属性，业务完成恰好一次。

## 数据差异核对

三机用户记事主体逐列一致（371／180／72 条，排除既有启动重建的 HEADER 行）。三星数据库在北京时间 10 月 11 日 23:54 新增两条用户取消的做事记录，来源记事 ID 为 1259；发生于用户反馈 Doing 问题之前，也早于 10 月 12 日 00:02 才建立的无服务 Doing 探针。回查本聊天该时段工具调用，三星没有测试输入，后台媒体试验仅操作魅族。这两条记录不作为探针写入删除，保留设备上的现状。魅族习惯记录仅从 `10` 补为 `100`，其余字段不变，符合跨午夜 `DailyUpdateHabitReceiver → HabitDAO.dailyUpdate` 补未完成记录的既有路径，同样保留。OPPO 除 HEADER 外全部表一致。不能将此次数据核验写成“三机所有数据库表完全未变”；没有整库覆盖或数据回写。

## 画面与性能证据

- Doing 使用真实 Activity 子类安全复现：三星、魅族均逐帧看到实际飞出的飘散颗粒，左右完成、快速完成、快速取消和流体回拉纳入检查。六段初轮录像中，卡片／粒子之外背景区域相对静止基线的最大平均差异为 1.28–1.74/255，未再出现之前整片重复变暗；差异包含录像压缩，不能作为逐像素等价证明。
- 实际着色器离屏对照：容器浓度 1 时，两份修改后的 fragment shader 与 Git HEAD 输出最大差异均为 0；0.84 浓度与预期最终合成结果最大差异为 5.96×10⁻⁸。此项证明默认合成公式不变，不替代 Android／卓易通交接验证。
- 三星普通 Dialog 同主题录像测量：原实现下方投影对比度在约 0 与 0.14 之间突变，候选平滑淡入、淡出，稳定投影仍约 0.14，交接点没有额外加深。见 `diagnostics/shadow-doing-2026-10-12/shadow-curves.png`。魅族夜间主题在录制间改变，不将跨主题样本作直接像素比较。
- 三星、魅族独立 Surface 流体弹窗的顺序解码共 1,008 帧；稳定橙蓝区域之间未检出小于 150ms 且色区减少到 60% 以下的短缺口。此检测只约束明显灰块，不声称所有像素零闪烁。
- 已有复杂首页、等待加载稳定后的移动阶段：三星 120.0、魅族 118.7、OPPO 119.6 FPS，帧间隔 p95 均约 8.3ms；识别滑动至首帧回调分别 65.6／108.4／32.6ms。有限单轮数据、且加载状态不同，不能将其和上轮刚进入页面的数值直接比较成性能提升。

## 入口覆盖及边界

| 入口 | 本轮方式 |
|---|---|
| 首页卡片与滑动回聚 | 三机已有复杂卡片只读取消手势；虚构卡片完成与回聚、200ms 快速滑动 |

| ThingListRemovalAnimator | 三机真实确认弹窗→虚构混合列表批量移除；检查补位、前景和层释放 |
| BaseDialogFragment | 普通、叠层、底部、独立 Surface、复杂变换控件、连续弹窗；另跑已有复杂详情的附件→录音和颜色面板 |
