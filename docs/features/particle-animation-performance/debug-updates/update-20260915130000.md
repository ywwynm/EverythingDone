## 粒子动画性能专项 第五批：单像素差异的定性与两项回归补跑

本批只有一处生产代码改动，**画面与性能一个字节都没变**；主要工作是把第四批留下的那个疑点查清。

1. **第四批在 OPPO 上出现的「整帧只有 1 个像素不同」定性完毕：是驱动层面的非确定性，
   不是我们的代码。** 第四批把它记成「并发 GPU 负载下的偶发」，这个说法站不住。本批把离屏
   对照从「参考路径 vs 优化路径」改成**每条路径自己跑多遍**——同一个渲染器、同一批着色器、
   同一份 uniform、同一份材料、同一个上下文、同一条线程，两遍之间没有任何代码上的自变量，
   而它照样会有一帧不一样：OPD2515（Adreno 829）上约 **0.5–0.9%** 的整段运行会这样。
   三条排除都做了：①不是共享资源在两个会话之间泄漏（自比较里根本没有第二个会话）；
   ②不是对照工具的回读不稳（每帧 `glReadPixels` 连读两次，全部轮次恒等）；③不是并发——
   把并发负载做成可独立开关的自变量之后，开 328 试次 3 次、关 384 试次 2 次，分不出差别
   （第四批「关掉提前预算后清零」只是 2 次运行，按这个事件率本来就有 98% 的概率清零）。
   差异的形态是「某一片微片的四边形在一个像素上覆盖翻转」，临界帧是**那一份材料**的属性，
   幅度是单像素，产品路径上看不见。**G0 的验收口径因此改成两步**：孤立单帧、个位数像素的
   差异先跑一遍自比较，自比较也出分歧就是本底噪声，自比较干净而 A/B 有差异才是真回归。
2. **共享状态审查：两个会话之间的 GL 资源没有泄漏，但找到并修掉了一处真实的隔离缺陷。**
   逐项核过了共享程序对象的全部 uniform、六个纹理单元与图像单元、累积纹理与帧缓冲、
   SSBO 绑定点 0–7、历史缓冲池、GL 全局状态、以及几处进程级 Kotlin 状态（见结果文档的审查表），
   结论是切换会话时全部重设、无残留。唯一的缺陷在诊断侧：离屏对照的「基线 GPU 配方」改的是
   **进程级**开关，而常驻 GL 线程上的**提前预算**同时在读同一批开关、还把它们写进缓存键。
   已改成线程局部（读点一个字没动）。默认配置下没有画面后果，但会让提前预算白白未命中。
3. **补上第四批跳过的两项功能回归，两台各一轮全过。** 弹窗四条关闭路径（返回 / 点窗口外 /
   取消 / 确定）每条 3 个循环、真实系统输入：每循环恰好一个出现层 + 一个消散层、输入次数对得上、
   无残留刷新率投票。出现层从 38 帧降到 34 帧是第四批 2c 的预期效果；帧距 P90 与第二批同量级
   （OPPO 18.2–21.0 ms、三星 18.0–30.7 ms）。独立 Surface 窗口的交接像素：OPPO 两种窗口
   「保护后 > 2/255 的像素比例」都是 **0**（无保护对照 98.5% / 98.3%），三星 9.7e-06 / 8.2e-06
   （无保护 98.7% / 97.8%），与第一、二批逐格相同。
4. **工具**：`device_particle_perf.py` 新增 `--gpu-seed`（固定对照种子）、`--gpu-diagnostics`
   （自比较 + 逐帧连读两次 + 定点复现并定位差异像素）、`--gpu-load`（另起 EGL 上下文制造
   与提前预算同形态的并发负载）、`--gpu-repeats`、`--gpu-pin-frame`，并自动把 `gpu-parity-*.json`
   拉回本地。单元测试 1013 项，1 失败（既有的 FableSol 那一项）、1 跳过。
