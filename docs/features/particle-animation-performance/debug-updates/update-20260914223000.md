## 粒子动画性能优化 第一批

这一版只动性能与时序，不动粒子动画本身：材料规则、随机、粒子数量、积分步数、压力迭代、
寿命、材质、着色器数学与动画时长全部原样保留。两台真机上「消散 61 帧 + 出现 37 帧」的
GPU 输出逐位散列与改动前完全一致。

**最明显的一处：点添加附件里的「录音」，面板不再多停一秒多。**

OPPO 平板（OPD2515）上原来点「录音」之后，添加附件面板的画面要在屏幕上多停 1.3 秒，
录音弹窗的凝聚先在它上面演完，然后面板才开始消散。根因不在粒子这边：这台设备的系统里
其实没有「动画时长缩放」这一项设置（应用读到默认的 1 倍），而框架实际给所有属性动画乘了
**5 倍**。于是应用自绘的水波纹真实寿命变成 1.8 秒，超过了「等水波纹播完再消散」那条 1.5 秒的
兜底时限，每次都走满超时。同一原因还让弹窗背景的暗层淡出被拉成 5 秒，与 1 秒的粒子消散脱节。

这一版新增了一次进程级的时长换算：自绘水波纹、弹窗暗层、降级淡出都回到与粒子动画同一条
时间基准；等待水波纹的兜底也改成按它的真实寿命算，并且在「控件已经移走」「没有任何动画器
还在推进」时立即放行。实测：

- OPD2515「录音行 → 添加附件消散首帧」：1523–1528 ms → **399–413 ms**（水波纹仍然完整铺满并淡出）
- SM-S9180 同一项：462–469 ms → 420–451 ms
- 两台设备的水波纹寿命现在都是约 0.4 秒，与设计值一致

**其余几项**

- 粒子播放的节拍从主线程挪到一条专用节拍线程：主线程卡顿时粒子帧不再跟着停。
  OPD2515 上「同一个弹窗连开关 10 次」的 20 个粒子层，此前每轮有 1–3 层的帧间隔 P90 掉到
  33–50 ms，现在**一层都没有**（全部稳定在 17.1–17.3 ms）；快速左滑的不同画面数从 24–39 提到 39–42，
  SM-S9180 从 8 提到 11–15。
- 快照的圆角裁剪从主线程挪到材料线程；粒子层与暗层改挂宿主窗口的 overlay，不再为了挂一层
  全屏透明层而让整个界面重新测量布局。
- 录音弹窗的倾斜传感器注册推迟到出现动画结束之后，通知渠道改在后台线程建：这两处此前会在
  凝聚期间卡住主线程。录音本身的行为没有变化。
- 准备与预计算的线程优先级改成「只有在已经有水波纹或别的粒子层在播时才让出大核」，
  播放中的渲染线程仍保持显示优先级。
- 列表行的水波纹裁剪由路径裁剪改为矩形裁剪（外观逐像素相同，GPU 那边便宜很多）。

**这一版没有做到的**

- GPU 侧原计划的四项里有三项被实测否决，**一项收益也没有拿到**：
  把 Jacobi 压力求解改成 32×32 大块（输出逐位一致，但两台设备上都更慢 8%–20%，
  片上共享内存吃太多、并行度反而掉下来）；把历史转存并入积分着色器、把四个积分子步合并成一次
  调度（这两项都会让驱动对重组后的着色器生成不同的浮点代码，GPU 输出不再逐位一致，按规矩撤回）。
  只保留了「最早出生时间之前跳过空转」，但它实际能跳的步数随机在 0–26 步（共 240 步），收益接近零。
  出现动画的预计算时间因此**基本没有变化**（OPD2515 约 180 ms，SM-S9180 约 270 ms）。
- 「进程内常驻一条渲染线程与 GL 上下文」推迟到下一批，与 SurfaceView 改造一起做：实测每次动画
  重建整套 GL 环境只花 9–11 ms，而改造要重做全部跨窗口交接的保证，不值得在这一批冒险。
- SM-S9180 上水波纹期的长帧还在，但已经定位清楚不在自绘水波纹的绘制上（它只占零点几毫秒），
  而在窗口层面的命令下发与 GPU 执行；这部分留到下一批去掉 TextureView 之后再处理。
- 左滑过程中「拖到 60% → 回到 20% → 再回到 60%」两次同一进度的画面仍有约 0.7% 的像素不同
  （改动前约 1.0%），不是这一版引入的。
