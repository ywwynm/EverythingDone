## Doing 整页 SurfaceView 绘制：独立诊断对照

上版在卓易通仍有起滑空白和收尾短暂提亮；原实现的自有色块不能显示也是已知结果，不再要求重复测试。本次提供不同绘制方式的隔离对照，尚未宣布实际 Doing 的闪烁修复完成。

请进入“显示兼容性检查”，点击新增的“Doing 对照：整页 GL 绘制（不计时）”。它使用虚构卡片，不启动计时、不修改已有记事；实际 Doing 页面和原来的 Doing 测试按钮尚未切换此实验。

- 保留 SurfaceView，测试页自首次显示起持续绘制页面内容，静态卡片和粒子在同一个 GL 缓冲中替换，避免每次滑动切换真实 View 与独立 Surface 的显示。系统壁纸继续由系统显示，顶部动态色条用于检查内容是否冻结。
- 新增 debug 专用 ParticleDoingGlScene 和绘制容器；拦截 draw 与 dispatchDraw，保持原控件的透明度、输入和可访问性树正常。没有新增按设备品牌选择的兼容模式。
- 保留现有 Dialog 内容隐藏、独立 Surface 恢复、原实现对照、关键图像与 ZIP 导出。新诊断记录整页绘制、卡片进入和返回的同缓冲层清单；成功回调仍不代表最终屏幕正确。
- 三机完成 15 个候选与 5 个基线样本，15 项相关单元测试通过。三星、魅族取消录像未见整卡空白，取消后的颜色恢复；200ms 快速完成均播放至消散终点。连续弹窗仍可重叠。OPPO 无录屏权限，只有截图和状态记录。
- 这仍有性能限制：魅族 DRIFT 两次配对首帧回调从约 242／250ms 增至 340／407ms，驱动帧率约 109／115 降至 101／97 FPS；100ms 短距离取消可能只保持卡片而未开始粒子。三星和 OPPO 的本轮样本没有同样的延迟退步。不能据此直接全局推广。
- 三台设备已恢复测试前 APK；371／180／72 条已有记事和其它数据库表均未修改（排除已有 HEADER 初始化记录）。

本轮请只验证新入口：刚起滑、快速完成、回拉取消时是否闪烁，顶部色条是否持续移动。先保留“采集关键图像”，记录结果并导出本轮诊断；再关闭图像采集比较响应和流畅度。卓易通无需连接 ADB。
