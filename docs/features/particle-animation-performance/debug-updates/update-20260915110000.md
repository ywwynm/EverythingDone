# 粒子动画性能专项 第四批

## 新建记事几乎不用等，弹窗出现没有开头空白，三星涟漪更连贯

**新建记事的粒子动画几乎不用等了。** 应用在首页空闲时（没有触摸、没有动画在播）会先把下一条
记事的粒子轨迹算好，点下新建按钮之后只需把真实的页面画面贴上去就能开播。实测从抬手到看见
第一帧粒子：OPPO 平板 484 → **171 毫秒**，三星手机 871 → **305 毫秒**。进程刚启动后的第一次
新建仍走原来的完整流程（那时还没有可参考的画面），第二次起才有这个提速。旋转屏幕、切换深浅色、
换文件夹、改字号或语言之后，预先算好的那一份会自动作废，等页面恢复空闲再重算——绝不会拿不对的
轨迹去播。动画画面本身一个像素都没变：末帧仍然是用真实页面的画面按格子拼回来的，与页面逐像素相同。

**弹窗与面板的出现也不再有开头的空白。** 出现动画原本的开头几帧几乎没有粒子，看上去像「点了
之后先愣一下」。这一批把弹窗、页内面板与新卡片的出现也改成从「真正开始有粒子」的那一刻起播，
首帧提前约 50–100 毫秒，起始段更明显。同一段动画保留下来的每一帧与之前完全相同，只是不再播
开头那几帧空画面。

**三星手机上的触摸涟漪更连贯。** 查清了涟漪一顿一顿的原因：涟漪只重画很小一块区域，系统的
可变刷新率据此把整个窗口的刷新率压了下来，于是同样一段动画能画出来的帧数少了一截。现在自绘
涟漪播放期间会显式要求高刷新率，播完立刻撤回。实测同一段涟漪期内出的帧数增加约四分之一，
外观没有变化。

**其它。** 建材用的工作线程现在跟随调用线程的优先级，不再固定在默认档；「有触摸反馈或别的
动画在播时让出优先级」的既有行为原样保留。另外修了一处诊断工具的缺陷：并行道数的「恢复自动」
实际把道数钉死在 1，导致上一批的一致性对照比的是两次相同的串行运行；修好后重新核对，1 道与
6 道的材料数据逐位相同。
