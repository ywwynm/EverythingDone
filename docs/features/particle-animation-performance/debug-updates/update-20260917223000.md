## 逐帧成本第四批：压力投影在华为平板上从未运行，以及「粒子动画调参」

### C7 的根因：原子操作写在向量分量上，Maleoon 不按下标寻址

上一版给出的两个待定夺选项里，「压力求解迭代数」在华为 MatePad Pro 上**改了画面逐位不变、
耗时也分不出**，而魅族上差别明显。这一版把它查到底：不是收敛，是缺陷。

`peel-splat.comp` 原来写 `atomicAdd(accumulation[k].x, …)`——原子操作的目标是**数组元素的
一个向量分量**。Adreno 按预期寻址；**Maleoon 910 上这三次累积落到的地址与下标 `k` 无关，
十万片的贡献全部压在第 0 格**。后果是一条完整的链：累积缓冲除第 0 格外恒为零 → 模糊算出的
占据度恒为零 → 压力的活动 tile 一个也收不到 → 间接分发的组数为 0 → **Jacobi 一次也不跑**。
也就是说，**压力投影这一整段在那台设备上从来没有真的工作过**，迭代数自然改不动任何东西。

判据是新加的四项读数：活动 tile 数、splat 真正写到的格数与第一个非零格的下标、压力场的
非零格数与总和、积分结果的 64 位散列。华为修前读到的是「活动 tile **0**、写到的格数 **1**、
下标 **0**」，而活动区域与包围盒都正常（`region=[112,64,223,223]` 与
`splatBox=[8,5,12,12]` 严格对得上）——缺陷位置因此唯一。

修法是把累积缓冲改成**标量数组**（`int accumulation[]`，三个分量按 `k*4`、`k*4+1`、`k*4+2`
寻址）。std430 下 `ivec4` 的步长就是 16 字节，所以这与原来是**同一批字节**，读它的模糊
着色器一个字不用改。间接分发计数 `atomicAdd(workgroups.x, 1u)` 是同一类写法（目标恰好是
第 0 个元素，因此碰巧正确），一并改成标量成员。

修后华为：活动 tile **0 → 54**、splat 写到的格数 **1 → 9051**、压力场总和
**0.0024 → 3920.8**，迭代数 100 / 60 / 40 三档的画面与状态散列全部不同，与魅族同形。

### 这条修复会让华为平板变慢，而且是应该的

压力这一段本来就该跑，修好即是新增的工作量：现场消散每帧 **23.9 → 40.7 ms**、
出现预计算 33 个采样 **446 → 978 ms**。魅族那一侧落在噪声里（10.67 → 10.55 ms），
因为它本来就在跑。把迭代数调到 40 即回到 **26.9 ms**，微片尺寸再调一档还能再降——
这正是下面这套设置的用处。**默认值不动。**

### 新增设置：微片尺寸与压力求解迭代数

设置 → 「粒子动画调参」（在「音频海浪动画设置」之后），两项都作用于全部粒子路径：
弹窗、页内面板、新建记事、左滑卡片。

- **微片尺寸**：0.9 / 1.0 / 1.2 / 1.6 / 2.0 / 2.4 / 2.7 / 3.0 / 3.2 dp，默认 **0.9**。
  微片越大片数越少、每帧越省，单片也越容易看清。最低一档就是此前一直在用的取值——
  归一空间里既有的下限正好是 0.88 dp，所以默认值下的画面与这一版之前**逐位相同**。
- **压力求解迭代数**：20 / 30 / 40 / 60 / 80 / 100，默认 **100**（现状）。

两项都进新建记事的提前预算指纹，改了设置旧预算与磁盘上的预测素材一并判废、下次重算。

### 调参页：上面实时预览，下面参数

顶部预览有两种内容，可以切换：

- **记事卡片**：一张示例卡，可以像在列表里一样用手指左滑或按住来回拖。走的是与首页
  **同一条代码路径**（同一个手势动画器、同一套 `ItemTouchHelper` 回调），松手按现有阈值
  判完成或回位，完成之后卡片自动回原位，可以反复试。
- **示例面板**：圆角与内容照确认弹窗，循环播出现与消散，点一下立刻走下一步。

预览下方是本机读数：**片数 · 上一轮 x / y 帧（比值）· 间隔 p90**。拖动滑杆抬手后
300 ms 内重建材料，下一轮即按新值播。华为平板上这套读数直接说明问题：默认档位下整屏
示例面板只出三成帧（8 / 27，间隔 p90 67.5 ms），调到 2.4 dp + 40 次之后片数降 82%、
呈现比例升到 0.47。
