## 粒子动画性能优化 第三批（3b：定下出现动画的最终配方，并补掉一段空等）

上一版（第三批）在新建记事的出现动画上加了两处外观改动，并留了一个没查清的问题：把新建按钮
当真实触点之后，预计算好像变贵了两成。这一版做了受控对照，结论和上一版的猜测**不一样**，
顺带把「算完了却还没上屏」的那段空等查清并消掉了。

**出现动画的最终配方：方向 + 触点距离，不要触点强度。**

用同一张页面截图、同一个随机种子，把三项输入逐项叠加各完整算一遍：

| 输入 | OPPO 平板 每采样 | 三星 每采样 |
| --- | --- | --- |
| 上上版：固定 315 度、屏幕外的虚拟触点 | 6.55 毫秒 | 9.08 毫秒 |
| 只把方向改成指向新建按钮 | 6.82（+4%） | 9.20（+1%） |
| 再把触点距离换成真实值 | 7.17（+10%） | 8.89（−2%） |
| 再把触点强度也换成真实值（上一版发布的那档） | 7.51（+15%） | 8.77（−3%） |

上一版说的「贵两成」是拿两次不同随机背景色、不同机器热度的运行相减得到的，噪声占了大头：
真正的代价在 OPPO 上是一成半，在三星上根本没有。

**「粒子从右下角那一点扇形汇入」这个观感，来自触点距离归零**——汇聚点落到页面边界上，
每一片按到那一点的方位角偏转，倒过来播就是从那一点扇开。再把触点强度也归零只会让分布更散、
前沿更糊，观感提升很小，却要在 OPPO 上再多花 5%。**所以这一版定为「方向 + 距离」**，
另外三档仍留在开关里，想换随时可以换。

**开头更明显了。** 跳过空白帧的门槛从「还有 5% 的微片在画面上」提到 10%：两台设备都多跳一帧，
出现动画第一帧的微片占比从 6–7% 提到 **10.1%（OPPO）/ 15.6%（三星）**，起步不再是几乎空白。

**补掉一段与动画无关的空等。**

上一版量出来「预计算算完了，首帧还要再等 108 毫秒（OPPO）才上屏」。查清是两件事：

1. **节拍在预计算期间没在跑**——算完才启动节拍，还得重新登记一次垂直同步再等一拍。
   现在准备阶段就让节拍空转（没内容时立即返回），算完当拍就能出画。
2. **粒子显示层的第一张缓冲，要等系统合成器给这一层做首次合成**。上一版的数据里其实写着：
   同一次运行里第一次动画的「提交到上屏」是 82–88 毫秒，之后每一次只有 14–17 毫秒。
   现在显示层一就绪就先交换一张全透明的空帧（屏幕上看不出来），把这次等待挪到动画开始之前。

结果：**OPPO 上「预计算完成 → 画面真的上屏」从 108 毫秒降到 26 毫秒**（9.5 毫秒提交 + 一个
垂直同步）。从点新建按钮到首帧上屏，整条链路从 596 毫秒降到 **484 毫秒**。

三星剩下的部分在设备一侧：这一版新加了「每一帧真实上屏时刻」的记录，可以看到三星每帧从提交到
真的上屏是 29.7 毫秒（OPPO 14.0 毫秒），也就是两个垂直同步；而系统把这个时刻告诉应用还要再晚
18–55 毫秒，首帧干脆先返回「无效」、83 毫秒后才给出来。这一段应用改不了。

**建材更快了（OPPO）。**

给每一片微片算出生时刻、寿命、颜色这一步，本来就是多线程按行分的，这一版把并行道数从固定 3 道
改成按核心数决定（两台设备都是 6 道），并把剩下三处逐元素的串行循环也并了进来。
**OPPO 上这一步从 57.7 毫秒降到 36–43 毫秒**；三星没有可测的变化（它的工作线程可能被调度到
小核，已记下待查）。

并行道数**不会改变任何一个数值**：每一道只写自己那些下标、只读别的缓冲。这一版在设备上加了
逐位对照——用 1 道和 6 道各算一遍，三个材料数组必须逐字节相同，两台设备两种尺寸全部通过。

**这一版验证了什么**

两台真机：归因一轮（四种输入各一次）、合并验证一轮（新建按钮 → 创建页），加上新建保存的三阶段
顺序、入场动画中按返回、本地材料库的逐位对照各一次。992 项单元测试只有一项既有失败（与本次无关）。
出现动画的两项外观改动仍然各带开关，想回退随时可以。
