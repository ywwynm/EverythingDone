## 修正 Dialog 关闭按钮的波纹残留与 Doing 原生波纹冻结

用户先要求分析粒子动画期间的 ripple 定格，随后授权细化并实施，并明确主要是点击 Dialog 的取消／确认按钮后，波纹被固定在消散材料内。本轮以该具体场景为重点，保留 SurfaceView、动态背景、现有粒子参数和重叠弹窗流程。

- `ParticleHardwareSnapshot.captureMaterial` 将自绘波纹过滤移到真正记录内容并提交绘制的同步区间，覆盖之前异步阴影／Surface 准备后过滤失效的问题。异步读回不持有隐藏状态，恢复闭包只消费一次；软件回退路径也在实际 draw 时过滤并恢复。真实按钮仍按原节奏播放反馈，不统一延迟新弹窗。
- `ParticleDoingGlScene` 在原生波纹自行产帧时按需刷新，繁忙时保留末帧刷新请求，并使相关按钮的显示列表失效，避免停在半透明的最后一层。保留有界图像消费、卡片交接确认与退出保护，没有常驻刷新定时器。
- 显示兼容性检查新增“按钮波纹：关闭 Dialog 时的消散”“按钮波纹：连续弹窗转场”“按钮波纹：Doing 页面自然淡出”，新增“波纹冻结或残留”观察项。继续提供原实现对照及诊断 ZIP 导出；材料和采样记录可在应用内导出，无需 ADB。
- 三星、魅族、OPPO 共 25 项波纹断言通过，含飘散／流体、按住后松开；21 项独立 Surface、连续弹窗、Doing 滑动与退出回归及诊断 ZIP 校验通过。JVM 测试 1448 项，0 失败、1 跳过。
- 真实“添加附件→录音”三星、OPPO正常；魅族首次出现准备中止，旧包与最终候选补测均正常。保留首次失败，不宣称独立 Surface 首帧偶发问题已解决。
- 三机帧率与首帧回调时延已对照，FLOW 有设备及运行顺序波动，不承诺性能完全相同。末轮滑动报告显示新增原生反馈刷新分支未触发。三星一次导出缓存文件消失，清理本轮已备份的临时产物后复验成功。
- 仍保留范围限制：三星原生 Doing 波纹首帧偏深在旧包已出现，本轮未解决；通用系统 RippleDrawable 的静态材料过滤未纳入。本次主要关闭控件使用 GradientRippleDrawable。卓易通的最终屏幕仍需继续验收。
