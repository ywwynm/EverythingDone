# 正在做事：修复底部回弹的停顿，覆盖所有卡片类型

用户反馈 OPPO 手机在惯性滚动到底部、回弹或急停时仍不流畅，指定首项为“右滑记事的动画优化”的记事，并指出此前测试未真正到达底部、不能只测清单。本轮改为明确到达底部后反复甩动，补齐长文本、图片、视频生成的 GIF 与长清单；旧版在多类卡片上都复现了相同停顿。

定位到厂商预测动画阶段让惯性和系统边缘效果读取未来时间，以及惯性结束后回弹的下一帧等待。DoingRecyclerView 保留普通帧执行阶段，只有动画时间确实超前时才把同一次回调移到当前阶段结束后执行；EdgeEffect 在实际时间执行系统原算法。ParticleDoingGlScene 只对活动边缘效果延后未来时间下的记录，并用真实 vsync 接续未结束效果的重绘。保留整页 GL、原滚动物理参数、粒子效果、计时数字动画和 GIF 播放，不调整系统刷新率。同步修正复杂卡片首开时过早计算 Surface 等待期限的问题，仍保留 2 秒实际等待上限。

最终三星、魅族、OPPO 三机共验证 30 次真实撞底、15 次惯性中按下急停、96 次复杂卡片 fling。OPPO 撞底后的相邻画面捕获间隔从约 33ms 降至 7–10ms；持续惯性完整时段约 118–119 FPS，三星约 112–117、魅族约 116–120。仍有少量掉帧，不能宣称全部场景稳定 120 FPS。急停触摸处理旧版本身已较快，本次不把边界改善误称为输入延迟的大幅下降。

六轮飘散／流体、计时描边与填充、GIF、弹窗、尺寸变化和后台恢复检查通过；三机合成像素、硬件缓冲复用、792 组计时路径和流体程序对照通过。1496 项 JVM 测试零失败、一项跳过，真实记事及计时记录测试前后摘要一致。调度过度推迟导致惯性变慢的候选已弃用，仅发布最终通过版本。

完整过程与证据见 doing-edge-scroll-2026-10-14.md。本轮按项目默认流程发布 debug，未提交 Git；卓易通仍使用原兼容方案，但未连接卓易通设备做屏幕复验。
