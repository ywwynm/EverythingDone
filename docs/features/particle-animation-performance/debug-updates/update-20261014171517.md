# 正在做事：改善上下滚动与首次流体拖动

用户要求继续优化 DoingActivity 的滚动掉帧和首次流体拖动延迟，保留为卓易通确定的整页 GL 方案，不能影响粒子动画、计时数字动画和 GIF 封面；三台指定设备必须覆盖图片、视频 GIF、长清单等复杂卡片。

分段诊断发现两类主要开销：整页捕获稍超过一个刷新周期后额外等待下一次遍历；首次流体的着色器源码处理、像素分类和历史范围计算阻塞准备。ParticleDoingGlScene 现在及时消费已经完成遍历的更新，仍保留原生波纹遍历要求与 GPU 图像保护。ParticleGl 复用后台共享上下文预热的程序；材料边界与手势历史前移到材料线程，整数像素统计及原数值循环放入现有 particle_material JNI 库，保留 Kotlin 参考／回退。粒子数量、动画公式、计时逻辑、GIF 播放和页面 GL 方案不变。

三机四卡型两样式共 24 轮完成，另对魅族图片／视频完成 8 轮包间配对。三星纵向均值约 61–63 → 116–118 FPS，OPPO 约 88–91 → 109–113，魅族长清单约 96 → 109；魅族视频首次流体回调配对约 996 → 353 ms。仍未达到所有场景稳定 120 FPS，保留魅族视频飘散约 2.5 FPS 的单轮差异与冷启动波动，不将回调延迟称为光学输入延迟。

395 项粒子 JVM 测试通过；每机 60 组数值逐位、3 相位程序像素、792 组计时路径、60 组合成检查通过。三机真实 GIF、计时切换、手势取消／完成、弹窗返回、尺寸变化和后台恢复验证完成；平板录屏受限，以低频无损截图补充状态核验，性能仍来自独立驱动时间戳。真实记事与计时记录前后语义摘要一致。完整方法、结果及限制见本功能目录 doing-scroll-flow-optimization-2026-10-14.md。
