## 粒子动画性能专项 第五批追加项：创建页预测素材持久化

第四批的提前预算用「上一次真实创建页的首屏」当预测素材，所以**进程启动后的第一次新建必然
未命中**——每次冷启动之后点新建都要等一下。本次把那一屏无损存进应用私有目录，冷启动之后
按键读回来，**第一次新建也能命中**。

1. **效果**：从新建按钮抬手到首帧真的上屏，冷启动后的第一次新建
   **OPPO 549.7 → 221.5 ms、三星 971.2 → 324.9 ms**，与同一进程里的第二次新建
   （196.1 / 310.2 ms）基本持平。多出来的二三十毫秒是首页静置期解码那张图，
   不在点击之后的关键路径上。
2. **存什么**：**空白创建页的首屏**——标题与正文都是空的，没有任何记事内容；
   `Bitmap.compress` 无损（API 30+ 用 `WEBP_LOSSLESS`，以下退回 PNG），只写
   `filesDir/particle-prewarm/` 这个应用私有目录，不经任何导出路径。实测单张全屏只有
   **69–143 KB**（OPPO 2520×1680 浅色 143 KB / 深色 93 KB，三星 1440×3088 浅色 140 KB /
   深色 67 KB），两种配置合计 0.2 MB。
3. **按什么匹配**：与图一起存的是**去掉新记事背景色之后的那 15 项缓存键**与来源时间。
   背景色每次新建都重掷，把它放进键等于永远不命中；而它只影响途中每一片的出生、寿命与权重，
   **末帧照旧由当次真实快照按格子拼回，逐像素等于真实页面**（G0 的两条命中对照本次复测仍通过）。
   深浅色、语言、字号、密度、方向、窗口尺寸、多窗口、系统栏与刘海 inset、输入法高度、
   文件夹祖先链、动画档位、时长缩放、刷新率、新建按钮位置、影响轨迹的开关——任何一项变了
   就不匹配，直接忽略这张图、走原来的完整路径。实测切到深色之后第一次冷启动新建确实未命中
   （OPPO 555.5 / 三星 935.1 ms），它把深色那一张存下来，再冷启动一次就命中了（209.1 / 294.8 ms）。
4. **占多少、怎么淘汰**：最多保留 4 个配置各一张，超出按「最旧先走」；目录总大小上限 8 MB，
   超限同样从最旧那一端淘汰；单张自己就超上限时不收它。写盘在自己的后台线程上、真实首屏被
   捕获之后，同键那张还新鲜（6 小时内）就不重写；读回在首页静置、准备预算的那条后台线程上，
   图片只在键匹配时才解码，不挡首页首帧。任何一步失败都只记日志，不影响功能。
5. **内存告警与退后台只清内存态，磁盘缓存原样留着**。实测「冷启动 → 退后台 +
   `RUNNING_CRITICAL` → 回前台 → 新建」仍然从磁盘命中（195.5 / 315.0 ms）。
6. 单元测试 1020 项，1 失败（既有的 FableSol 那一项）、1 跳过；淘汰规则由 5 条纯逻辑单测覆盖。
   两台真机各跑了一轮完整验收（冷启动命中、深浅色换键、退后台回来、G0 对照）。
