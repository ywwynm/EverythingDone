## 逐帧成本第一批：绘制记录与压力活动区域

这一版只改「同一件事在哪一级算」，不动粒子模型、参数与外观。落地两项，同批评估过的另外
三项按实测回退或判定不成立。魅族 20 Infinity 与三星 SM-S9180 两台各测一轮。

### A1 逐顶点数学下沉成每片每帧一次（视觉：G1，浮点噪声）

原来 `material.vert` 里那一长串旋转、尺度、明暗的计算，每片每帧要算 16 次——Adreno 把顶点
着色器编成分箱与渲染两份，而算位置的依赖链几乎把昂贵数学全吃进去了，两遍绘制、四个顶点、
两段各跑一遍。现在改成 compute 每片每帧算一次，写进一条 64 字节的「绘制记录」（位置流
32 字节 + 外观流 32 字节），顶点着色器只剩一次 2×2 矩阵乘加。

离屏 A/B（每条件 5 对，配对取比值）：

| 设备 | 材料 | 现场消散 每帧 | 回放出现 每帧 |
| --- | --- | --- | --- |
| 魅族 | 弹窗 10.7 万片 | 9.56 → 7.56 ms（−21.4%） | 6.98 → 4.97 ms（−28.8%） |
| 三星 | 弹窗 10.8 万片 | 8.72 → 6.98 ms（−19.7%） | 6.70 → 4.94 ms（−25.5%） |
| 魅族 | 左滑卡片 2.4 万片 | 4.56 → 4.11 ms（−11.3%） | 2.35 → 1.87 ms（−19.8%） |
| 三星 | 左滑卡片 2.4 万片 | 3.85 → 3.49 ms（−10.3%） | 1.90 → 1.52 ms（−20.8%） |

顺带把「按边缘权重丢掉整片」那条判据从片段着色器搬到逐片一级——两个操作数本来就都是逐片量，
对一片的所有像素给出同一个答案，等价于整片不进光栅化，每像素少一次运算。

### C10 压力更新只跑活动区域（视觉：G0，逐位相同）

splat 用原子 min/max 记下本帧真正写到的格子，两遍模糊、tile 收集与投影只在
「上一帧包围盒 ∪ 本帧包围盒，再外扩一个 tile」那片区域里算。区域之外三个缓冲恒为零，
所以整张网格逐位不变——两台设备的 61 帧 / 37 帧对照全部零差异。

| 设备 | 左滑卡片 现场消散 每帧 | 左滑卡片 预读 每采样 |
| --- | --- | --- |
| 魅族 | 4.56 → 4.38 ms（−3.7%） | 4.47 → 4.14 ms（−6.4%） |
| 三星 | 3.88 → 3.72 ms（−3.9%） | 3.83 → 3.58 ms（−6.2%） |

弹窗侧两台都在 ±2.3% 以内（整屏动画的粒子很快铺满网格，区域收不动），中性、不是回归。

这一项返工过两次，教训值得写下来：第一版用间接分发 + 命令屏障，整段反而慢 4%–13%；
把间接分发整个去掉之后数字几乎没变——贵的根本不是分发，是十万个线程无条件地对同四个地址
做原子操作。改成「按 16 格 tile 记 + 先普通读一眼、已覆盖就不发原子」之后才转正。

### 创建页的提前预算终于能命中了

缓存键里有一项取自面板的**瞬时**刷新率：首页空闲时预算读到 120、点新建时已回落 60，
键永远对不上，每次新建都白算三百多毫秒的轨迹再丢掉。核实之后确认采样数对 60 以上的
刷新率本来就取同一个值，真正该用的是粒子层自己投的 60 Hz；键里去掉这一项，
会话与预算两侧统一取同一个常量。

### 同批评估过、没有落地的三项

- **方向常量提成 uniform**：每步每片省 6 次 atan、12 次三角函数，但两台三条路径上都落在
  ±2% 的本底噪声里（判据是「回放路径根本不做积分，却也报同样量级的变化」）。整段删除。
- **流场与置信度并成一张纹理**：每步取数从 32 次降到 16 次，实测符号都对不齐，同样删除。
- **第 0 遍改成一张权重图**：等价性不成立。那一遍的四边形四角带整数散列抖动，改成权重图
  之后像素归属会从抖动边界变成轴对齐的网格边界——释放前沿的形状会变，属于要看画面定夺的
  改动，超出本批的约束，没做。

### 真机表现

两台各一轮修前（同一个二进制把两个开关关掉）+ 一轮修后，九个场景：最长呈现间隔整体缩短
（魅族多格从 190–254 ms 降到 33–102 ms），消散那一层的呈现比例普遍上去（三星的附件弹窗
消散 0.926 → 1.016、点外部 0.934 → 1.016，魅族颜色面板 0.731 → 0.805）。
唯一没变好的是左滑慢拖的帧数，但它的「识别 → 首个非零画面」两台都快了 20–50 ms，
已记入后续事项。每帧多两次 GPU 提交，CPU 侧提交耗时涨 0.1–0.8 ms，远在每帧预算之内。
