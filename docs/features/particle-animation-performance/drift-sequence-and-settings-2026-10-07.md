# 飘散连续播放去重与粒子设置统一

后续核对：用户试用后指出读数大于可见粒子。本文的「基准大小」只验证了几何换算，飘散数值对应软点贴图外框，可见中心明显更小；两种样式尚未按同一可见直径校准。见 [尺寸含义纠正与实测](visible-particle-size-analysis-2026-10-07.md)。

## 需求与分析

- 用户要求连续播放的飘散动画不要重复同一参考轨迹，移除灭霸候选，两种样式数量下限改为 0.1 倍，并统一粒子大小单位。
- 弹窗、页内面板、新建页、卡片出现与移除最终都经 `ParticleDismissOverlay` 调用 `ParticleDriftInputs`。出现动画另建模型再倒放；同一次左滑的回退沿用本会话模型。
- 复核三个可能来源：随机抽样没有历史记录；跨动画复用轨迹缓存；出现／消散复用一次模型。后两项不成立：飘散没有跨会话轨迹缓存，创建页预计算只用于流体，每个飘散层单独建模。
- 修改前，固定种子的正式模型调用复现三个失败：同方向相邻选择重复、开关交替时同类选择重复、抽到灭霸。交替场景在 seed=2 已再次选到旧钢铁侠。原始报告保存在 `tmp/drift-selection-before.log`。此处可以用纯 JVM 调用直接复现，不需要新增运行日志或设备归因实验。
- 卡片按下就开始预热，因此不能把「准备模型」等同于「播放」；未发生滑动的点击不应改变记录。多个候选同时准备时，也要按实际开播顺序再检查。

## 实现口径

- 参考来源按去掉变体后缀的名字识别；全局最近一段与同类最近一段分别去重。随机生成仍具有不同的格点值和湍流偏移；筛选不满足方向时直接生成随机模型。
- 新的播放对象把准备与确认分开。实际开播才记录选择；更换候选不改变数量、尺寸、快照和内容分析，只更新模型与格点、使旧工作面缓存失效。
- 数量使用十分位整数持久化；旧的 0.2～1.6 倍下标及更早的飘散数量键都按取值迁移。
- 原方案只换算 dp 显示。用户继续指定共用 0.5～6 dp 的三十档，因此改为实际的 dp 设置，旧倍率仅保留在迁移表和底层绘制输入中。
- 共用档位：0.5、0.54、0.56、0.6、0.64、0.72、0.84、0.96、1.08、1.29、1.5、1.6、1.8、2.0、2.1、2.4、2.56、2.7、3.0、3.2、3.6、4.0、4.2、4.5、4.8、5.0、5.1、5.4、5.6、6.0 dp。
- 流体显式大小按所选 dp 绘制，独立于网格密度；默认自动粒径继续沿用规则。飘散按 `dp × density / 9.8` 换算内部倍率。两种动画仍保留逐粒变化、生长和衰减，读数表示基准大小。
- 旧流体十六档均在新梯度中，直接按原 dp 迁移；旧飘散按实际像素直径和升级设备密度換算至最近档位。比如密度 3 时旧 1 倍约 3.27 dp，迁到 3.2 dp；旧 2 倍约 6.53 dp，受新范围限制迁到 6 dp。未显式设置飘散大小时同样选旧原始大小最接近的一档。
- 流体 0.1 倍数量的旧固定取整余量会吃掉 6.25% 预算，实测比例约 0.0949；余量改为最多 5% 后，更接近十分之一，0.2 倍及以上沿用原预算公式。
