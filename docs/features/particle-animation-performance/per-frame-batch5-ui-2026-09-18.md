## 3 粒子大小：十六档，标出本机像素，默认逐位不变

档位（dp）：**0.64 / 0.72 / 0.84 / 0.96 / 1.08 / 1.29 / 1.5 / 1.6 / 1.8 / 2.0 / 2.1 / 2.4 /
2.56 / 2.7 / 3.0 / 3.2**。当前值写成 `0.84 dp（2.5 px）`，像素按本机密度换算，整数能表示时
不写小数点；刻度上每一档都画出来，档位文案上下两排交错排布，选中的那一档用强调渐变着色。

### 默认值为什么仍与改动前逐位相同

材料在「720 逻辑像素 = 384 dp」的归一空间里建，一个 dp 是 1.875 个单位，而
`rules.properties` 里自带的下限 `cell=1.65` 个单位 = **0.88 dp**——这个值在新梯度上没有
正好对应的档。做法是：

- **「未设置」时 `cellDpFloor` 返回 0**，即不往模型里写这条下限，沿用规则里的取值；
- 滑杆停在梯度上最接近 0.88 dp 的那一档（**0.84**），当前值旁边标「· 默认」；
- 用户一旦拖动，就按选中的 dp 显式生效。

顺带一条事实，写在这里免得以后被当成缺陷：模型取的是
`max(规则下限, 设置下限)`，所以 **0.64 / 0.72 / 0.84 三档都在规则下限之内，选中它们与默认
逐位相同**；真正开始改变画面的是 0.96 dp 起。

### 档位键换了名字

新梯度的下标含义与上一版九档完全不同，沿用同一个键会把旧下标读成另一档，因此键名从
`microflake_cell_dp_index` 换成 `particle_size_dp_index`。**用户在上一版显式选过的那一档
会按 dp 取值迁移到新梯度上最接近的一档**（上一版的最低一档本来就等于「不写下限」，
因此只删旧键、不写新值，默认行为分毫不变）。迁移在 `ParticleTuning.apply` 里做一次，
旧键删掉即为完成。

## 4 预览的主题色取自用户自己的记事

做法与「音频海浪动画设置」页一致：后台线程读一次记事表，把每条记事的背景
（纯色或 accent 方向的渐变）与应用的强调渐变一起放进颜色池去重，页面打开时随机取一条；
预览区右上角的调色盘按钮（位置与样式照海浪设置页那两个按钮）换一种颜色。
**一条记事都没有时**退回应用给新记事用的那组默认记事色。整条链路只读，不改任何记事。

颜色只作用在**预览内容**上：示例卡的底色、示例对话框的标题与「确定」——与详情页里
真实对话框跟着记事颜色走的做法一致。页面自身的顶栏、选项卡、滑动条、恢复默认仍用应用的
强调渐变，否则整页会跟着一条随机记事变色。

## 5 新增的两个控件

`LevelSlider` + `LevelTicksView`（`views` 包）：等距档位的滑动条。`SeekBar` 的量程就是档位数
减一，滑动天然吸附到刻度上；轨道与滑块走 `DisplayUtil.setSeekBarBackground` 的强调渐变，
刻度与选中档位的文案同样走渐变。刻度视图与 `SeekBar` 用**同一组左右内边距**——滑块中心的
行程正好是 `paddingLeft` 到 `width - paddingRight`，刻度按同一条直线摆才对得上。

与既有的 `RatioSlider` 的区别：那一个是比例专用（对数映射 + 吸附阈值），这一个是等距档位，
两者的取值语义没有交集，所以没有合并。

## 6 默认值逐位不变：跨版本的逐帧散列对照

判据分两层。

**第一层，单测**：`cellDpFloor(index, explicit = false)` 对**任何**档位都返回 0，也就是「未设置」
时一个 dp 下限都不往模型里写；迭代数默认仍是 100。加上模型那一行取
`max(规则下限, 设置下限)` 的源码契约，默认值下推给管线的两个值与加入本设置之前完全相同。

**第二层，真机跨版本对照**：同一台设备上先装**上一版发布包 `202609171434`**、再装本版，
两轮都删掉 `shared_prefs/particle_tuning.xml`（两版各自的默认），都用**同一个固定种子**
（`--gpu-seed 20260918`）跑同一条真实路径（打开记事详情 → 添加附件弹窗 → 返回键），
比对 `ParticleTrajectoryCheck` 落盘的逐帧散列。

| 设备 | 动画层 | 正向 61 帧 | 倒放 37 帧 |
| --- | --- | --- | --- |
| 魅族 20 Infinity | **消散** | **逐位相同** | **逐位相同** |
| 魅族 20 Infinity | 出现 | 自帧 1 起不同 | 自帧 1 起不同 |
| 华为 MatePad Pro 13.2 | **消散** | **逐位相同** | **逐位相同** |
| 华为 MatePad Pro 13.2 | 出现 | 自帧 1 起不同 | 自帧 1 起不同 |

「出现」那一格**不是回归**，而是本底：按本专项既有的两步判据，先让**同一个包跑两遍**
（魅族 `g0new` 与 `g0new2`），结果**同样是「消散逐位相同、出现自帧 1 起不同」**。
也就是说出现路径的输入（它的快照在弹窗刚显示时抓取、触点取自打开弹窗的那一次点击）
本身就不跨轮复现，这一层做不了跨版本判据；而消散路径（返回键，虚拟触点固定）完全确定，
两台都逐位相同。旁证：同一轮里的 `perFrameBatchOne.forwardSelf` 与 `reverseSelf`
（同一条路径自跑两遍）在所有运行里都是 **0 帧差异**。

产物：`tmp/particle-perf/phase0/<序列号>/runs/{g0old,g0new,g0new2}-0/gpu-parity-00{1,2}.json`。

写回去再启动，读回来是 `particle_size_dp_index=9`（新梯度上的 2.0 dp），旧键已删，迭代数不动。
