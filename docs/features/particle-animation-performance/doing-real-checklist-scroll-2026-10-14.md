# 指定真实清单与松手惯性滚动测量

2026-10-14，在已发布 debug `202610140919` 上完成三星、魅族共 28 轮测量。使用原有只读调试入口，本轮没有修改 Android 渲染代码、构建、发布或提交 Git。用户确认，感觉松手后卡顿的是尚未连接的 **OPPO 手机 PMA110**；本报告没有该手机实测，不将 OPPO 平板 `9018f404` 的结果代入。

## 结论

只测手指拖动会漏掉持续惯性滚动的问题。魅族在两类长卡片上均重复出现百毫秒级停顿，三星相同测试约 113～117 FPS。主要优化方向应转向松手后的离屏图像生产、栅栏等待与 GL 消费链路。

下表按**完整滚动时段内、驱动确认的唯一呈现帧数 ÷ 时段时长**统计，包含阶段首尾无新帧的时间；惯性阶段仅使用有实际位移的 `RecyclerView.SETTLING`。

| 场景 | 三星 SM-S9180 | 魅族 20 Inf | 每机样本 |
| --- | ---: | ---: | --- |
| 指定真实记事，反复上下滚动 | 111.54 FPS | 114.95 FPS | 3 轮，72 次输入，69 次有效滚动 |
| 指定真实记事，松手后惯性 | 115.75 FPS | 99.81 FPS | 3 轮，72 次有效 fling |
| 90 项长清单，松手后惯性 | 117.11 FPS | 34.05 FPS | 2 轮，24 次有效 fling |
| 带 GIF 的长文本卡片，松手后惯性 | 113.35 FPS | 38.13 FPS | 2 轮，24 次有效 fling |

指定记事本身可滚动距离较短，三星每次惯性约 0.19～0.46 秒，魅族约 0.06～0.27 秒，无法覆盖一秒以后的表现。补充长卡片后，魅族清单 24 次中有 19 次、视频长卡 24 次中有 21 次惯性持续超过一秒；三星同输入自然结束较早，最长约 0.95 秒，没有宣称其已完成“一秒后”验证。

魅族长清单的呈现间隔 P95 为 **132.51 ms**、最长 **537.91 ms**；视频长卡 P95 **140.73 ms**、最长 **546.63 ms**。这些时间来自实际驱动呈现，无法用平均拖动帧率掩盖。

## 指定记事与只读边界

用户指定首项为“右滑记事的动画优化”的清单。三星唯一匹配 ID 1259，3453 字符、141 项；魅族唯一匹配 ID 780，3582 字符、148 项，后续内容版本不同。两机实际封面均为播放中的 73 帧 GIF，三星 1125×632、魅族 1050×590。

当前满宽卡片规则实际只展示 12 行清单：`DoingActivity` 虽调用 `setChecklistMaxItemCount(-1)`，但 `BaseThingsAdapter.getThingCardChecklistMaxItemCount()` 的满宽分支优先返回 12。该事实与 UI 结构及滚动范围一致，本轮未改变它。三星滚动范围／视口 2327／1369 px，魅族 2083／1440 px。不能把这一真实样本说成“同时绘制 148 行”的压力测试。

长清单和视频长卡使用已存在的虚构入口，分别包含 90 项三级清单、90 行文本与实际视频派生 GIF，未写入数据库。长清单总范围三星 19805、魅族 18848 px；视频长卡三星 26375、魅族 21904 px，足以覆盖长距离惯性。

所有场景沿用正式 DoingActivity 布局、适配器、整页 GL、计时动画与媒体加载；服务边界使用内存替身，不设置真实正在做事 ID，不写计时记录。仅纵向输入，未点击清单勾选项，横向粒子激活数为零。测量前后三星 374 条、魅族 181 条用户记事及各 2 条计时记录的语义 SHA-256 完全一致；正常重建的内部 HEADER 行排除。数据库和 UI 文本只留本地临时目录。

## 输入与统计方法

- 常规滚动：每轮 24 次上下交替，单程 1200／700／180 ms。日志 `top/middle/bottom` 实际只是三组速度；指定卡片不足一屏，不代表独立的顶部／中段／底部空间分层。定位输入不计入。
- 接触方式对照：每机两轮交换先后顺序。相同 700 ms 单程、40% 视口位移、4 ms 异步 MOVE，比较按住连续折返 20 段与分开按下／抬手 20 次。连续折返首尾位置相同，不能因净位移为零排除整段。
- 短卡 fling：18% 视口位移、140／80 ms 后立即 ACTION_UP，各 12 次，松手后等待 1.1 秒。72 次 UP 均与有位移的 SETTLING 一一对应。
- 长卡 fling：50% 视口位移、140／80 ms，各 6 次，松手后等待 2.5 秒，每卡型重复两轮。没有把下一次按下打断的拖动当作自然惯性结束。
- 详细取证：常规拖动和长清单 fling 各一轮／设备，共 4 轮。长清单取证每组 4 次、松手后等 2 秒。它们不并入上方低开销 FPS。

输入工具沿用 `HlsGestureInput`，只注入系统 MotionEvent，记录设备端 `System.nanoTime()` 的 DOWN／UP。分析用 UP 核对 `SETTLING` 起点，避免将前一段手指拖动或入场自动滚动混入。所有性能轮次关闭截图、录屏及图像采集；计时与 GIF 保持开启。28 轮均无诊断记录溢出、场景超时或失败；系统报告的 thermal status 均为 0。

保留两种明确的统计字段：`presentedFramesPerActiveSecond` 是上表完整时段口径；`fps` 是段内已呈现帧之间的平均间隔换算。后者会略去首尾空白时间，极端停顿时偏乐观，不能单独表示整段出帧率。过程中先报告的数字属于后者，复算原值如下：

| 场景 | 三星：间隔换算 | 魅族：间隔换算 |
| --- | ---: | ---: |
| 指定记事常规滚动 | 112.98 | 116.90 |
| 指定记事 fling | 115.82 | 104.35 |
| 长清单 fling | 117.03 | 40.49 |
| 视频长卡 fling | 113.20 | 39.51 |

常规滚动各轮间隔换算值三星 111.05／113.34／114.51，魅族 117.28／118.09／115.31。长清单两轮三星 116.68／117.40，魅族 42.00／39.10；视频长卡三星 112.61／113.78，魅族 38.07／40.82。不是依赖一个偶发慢样本得出结论。

## 已验证的瓶颈范围

先列出三个可证伪解释再取证：松手后节拍降频、整页捕获消费阻塞、手势材料回收重合。长清单松手 100 ms 以后的取证结果如下，耗时单位为 ms：

| 项目 | 三星 | 魅族 |
| --- | ---: | ---: |
| 独立输出节拍 | 119.97 Hz | 120.73 Hz |
| 整页记录 P95 | 0.124 | 0.282 |
| syncAndDraw 调用 P95 | 0.822 | 0.983 |
| 图像获取／栅栏等待／硬件包装 P95 | 3.347 | **87.821** |
| 进入 GL 队列到完成接收 P95 | 1.316 | **44.593** |
| 整条捕获消费链 P95 | 9.348 | **140.179** |
| 合成开始到驱动绘制完成 P95 | 2.558 | 2.704 |
| 惯性窗口内材料硬件资源销毁次数 | 0 | 0 |

魅族节拍仍正常到达，最长间隔约 8.59 ms；页面遍历请求也持续到达，后段 2275 个请求间隔中大量请求遇到捕获繁忙。实际捕获间隔换算降至 38.45 次／秒，最长约 392.93 ms。由此排除“单纯没有请求 120 Hz”、清单绘制记录本身很慢及本次长停顿直接来自材料销毁。不能把原始回调数直接解释为面板刷新率，三星回调更多，但经过现有相位选择的输出仍约 120 Hz。

等待区间含图像获取、fence、硬件 Bitmap 包装；GL 接收区间含排队和导入，均非纯 GPU 计算计时。当前证据定位到离屏生产／缓冲同步及消费链，**尚未区分厂商对离屏 RenderThread／GPU 的调度和具体缓冲复用等待**。没有通过删除栅栏、忽略状态或更改渲染策略来掩盖问题。

## 剩余优化顺序与限制

1. 优先针对长 fling 的离屏生产及同步等待做调度／驱动取证，比较同一材料、同一缓冲生命周期；主线程记录优化不是这次大幅掉帧的主要方向。
2. 普通触摸的快照资源复用仍有空间：每次 DOWN 会预备横滑材料，三轮常规滚动每机各 102 次；主线程资源销毁中位耗时三星 1.809、魅族 1.356 ms。但这不能解释已在 DOWN 后很久出现、且无销毁事件重合的长 fling 停顿。
3. 接触方式对照的间隔换算值：三星连续按住 117.15、反复抬手 116.19；魅族 115.48／109.97。只比较手指仍接触时，后者分别为 116.46／111.76。该对照也改变触摸状态及惯性，不将差值全部归因快照；沿用[此前撤回方向延迟预备的结论](../home-list-scroll-performance/decisions.md)。
4. 保持整页 GL、粒子效果、计时数字动画和 GIF 播放；不以缩短惯性、减少内容或停播换帧率。用户指定真实清单的满宽显示上限是独立行为，本轮未改。
5. PMA110 本机尚未测试。魅族已经复现同类持续滚动掉帧，但不能据此断言 OPPO 手机具有同一根因。
