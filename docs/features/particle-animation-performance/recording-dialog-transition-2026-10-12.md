# 添加附件到录音的样式与恢复排查

用户在 debug `202610121039` 后反馈：Android 与卓易通打开录音 Dialog，粒子期间计时文字变淡且疑似增加描边；粒子结束后延迟恢复，时长不定。FableSol 水体在延迟期间疑似停顿，水体颜色是否改变未确认。

沿用既有三台 Android 授权、SurfaceView 与不修改记事的约束。只打开真实录音准备页，不开始麦克风或系统音频录制。先建立实际“添加附件 → 录音”的图像和交接时间对照，再分离文字绘制、准备态动画和 Surface 恢复原因。

当前状态：已在三星真实附件→录音准备页复现。以用户描述的样式差异和动画结束后的停顿作为判据；普通固定色块与回调成功不能替代本场景。

追加反馈：首页滑动记事卡片，粒子开始／结束时其它卡片阴影强度疑似突变。并入本次图像对照，先分别复现，再判断是否共用透明度或硬件阴影的原因；不预设同因。

## 复现与第一项验证

- 新增 debug `ParticleRecordingAppearanceProbe`，只打开真实录音准备页，不开始录制；保留原 APK 与数据库只读基线。
- 三星修复前录屏和 PNG 复现计时数字变淡、边缘突出。粒子取图与 4.5 秒后再次捕获的计时区域完全一致，排除数字入场动画的中间态；它们相对最终屏幕的文字区域平均通道误差为 20.31，着色强度约为真实文字的 39.5%。
- 第一轮有效日志：粒子完成至恢复遮盖撤除约 480 毫秒；恢复遮盖覆盖 1164×1575 的整个录音面板，包含普通计时控件。`particleHolds` 已释放时，旧图仍在遮盖新画面。
- 候选根因：拆分 View 树时创建的 RenderNode 未复制 `hasOverlappingRendering`。Android 默认值为 false，会让整体 alpha 参与内部蒙版绘制；先仅补齐此属性，保持计时颜色、0.36 准备态透明度与字体实现不变，再用相同真实场景验证。
- 光照和恢复遮盖作为独立假设继续验证；尚不宣称修复完成。

参考：[AOSP RenderProperties](https://android.googlesource.com/platform/frameworks/base/+/master/libs/hwui/RenderProperties.h)，`mHasOverlappingRendering` 默认为 false，半透明重叠内容需要独立合成。

## 已确认的分离原因

- **数字透明度**：只复制 View 的有效重叠绘制属性后，三星的出现快照、稳定态捕获与最终屏幕计时区域逐像素一致（最大通道误差 0），不改 TimelyClockView 配色、准备态透明度或字形。
- **恢复等待**：关闭中途截图后的基线仍约 312ms；仅预热生产者约 273ms，效果不足。把带呈现 fence 与有效像素检查的恢复帧提前到粒子播放期间，结束后仍等待窗口恢复，实测约 65ms。增加 SurfaceHolder 生命周期检测；若预备后表面重建，旧就绪结果作废，必须等待新缓冲，避免重新引入灰块。
- **背景阴影**：多卡片虚构列表中，不动卡片底部阴影的录屏均值跨约 4 个灰阶；读取窗口主题光源及显示尺寸校正后缩到约 1 个灰阶。统一 `ParticleWindowLighting`，供整页、动态底图和普通硬件捕获共用，单卡片原有光照计算保持不变。无损截图与真实首页仍需验证。
- 魅族第一轮实际录音测试发生准备超时，没有真正播放粒子，因此不能计为通过；保留该样本，后续区分复杂记事加载与本次绘制修正。

## 最终回归范围与限制

- 三星、魅族真实录音准备页的计时截图与最终屏幕逐像素一致。OPPO 为渐变与描边字体，窗口缓冲合成对照最大误差 1/255，最终屏幕最大 8/255、文字区域平均 1.39；保留差异，不能宣称三机均逐位相同，未为匹配后续屏幕合成反向改动字体或配色。验证脚本可检出修复前样本（文字区域平均误差 20.31、最大 44）。
- 录音恢复遮盖在本次有效样本为三星 78ms／FLOW 55ms、魅族 62ms、OPPO 37ms；关闭中途截图的三星配对约 312→65ms。这是等待缓冲与窗口恢复的时间，不是水体物理更新耗时，不能将其当作所有设备的固定上限。
- 三机真实首页只读短拖并回到原位：三星 3、魅族 1、OPPO 10 处非目标卡片阴影区域，开始前／播放中／结束后无损截图最大通道差 0。排除屏外及 FAB 自身阴影覆盖的区域；原始记事截图仅留本机，不放入文档或发布包。
