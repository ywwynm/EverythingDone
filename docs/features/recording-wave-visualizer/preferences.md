# 偏好 — 录音波形可视化改造

## 2026-07-02 — 保留随机、灵动、有个性的波浪

用户明确偏好：波浪要有随机、灵动的感觉，每道浪像有自己的个性。不要让所有波浪在同一时刻做出同样的上升、下降或变化动作；需要随机的先后顺序、错峰响应、不同惯性和不同局部表现。

D20 的波形美感收束让整体变得平稳、波浪彼此相似，野性不如上一版。后续优化应回到 D19 的自由多分量基底，再解决形状问题，而不是继续加强统一谱形约束。

## 2026-07-02 — 歌曲场景需要更跟节拍

用户反馈：旁边播放比较激情、节奏较快的歌曲时，当前录音波形动画仍显得慢悠悠，和歌曲节拍、演唱速度不够贴合。后续优化需要让高能量、快节奏音乐触发更即时的视觉反应，同时不能牺牲此前确认的随机、灵动、每层有个性的波浪观感。

## 2026-07-02 — 避免水面轮廓细纹过多

用户反馈：D24 的细纹太多，水面容易全是细纹，观感像锯齿，很不好看。后续节奏响应不能通过大量高频几何细纹来体现；应优先让主体轮廓保持圆润、清楚，把节奏感放到更宽的脉冲、局部浪涌、相位/速度变化或不破坏轮廓的轻量表面效果里。
## 2026-07-02 — 响应要快，但不能用跳变换速度

用户确认 D25 整体效果和响应速度更好，但仍不接受某个波浪在已经升起后突然上下颤动或峰值被重新改写的感觉。后续所有节奏、瞬态、beat phase、backfill 之类的低延迟优化，都必须通过连续包络、限速相位吸附或目标合并实现，不能直接写当前视觉值来换取即时响应。

## 2026-07-02 — 录音水体必须遵循记事渐变方向

当当前记事使用渐变背景时，录音波浪的渐变方向需要与 `ThingBackground.orientation` 保持一致，而不是固定横向渐变。

## 2026-07-02 — 锁屏返回后动画必须自动恢复

用户反馈打开录音 dialog 后锁屏再回来，动画可能完全停止。录音波浪的自驱动画循环需要显式处理 window 可见性、聚合可见性和焦点恢复，不能只依赖 attach 时启动的一次 `postInvalidateOnAnimation()` 链。
## 2026-07-02 - 小变化不应过度驱动波浪

用户偏好：录音波浪不需要对所有很小的音量、频段或节奏参数变化都敏感；细小变化可以被忽略，以避免果冻感和局部反复颤动。后续优化应优先保留强音节、明显节拍和音色差异的表现，而不是让微小输入噪声持续改变已经成形的波峰波谷。

## 2026-07-02 - 安静场景应降低视觉活跃度

用户反馈：相对安静的情况下不需要高频率动画播放和波浪变化。后续优化应让近静音或低能量输入进入更低活跃度的视觉状态，只保留很慢、很轻的水体漂移；不要让 20ms 音频特征刷新、持续 rhythm energy、微小 onset 或高频噪声持续触发明显波峰波谷变化。

## 2026-07-02 - 自然水感优先于逐帧音频拟合

用户判断：及时反映音量、音调、节奏等音乐变化，和自然、灵性的波浪动画之间可能存在冲突。后续方案应把音频事件检测和水体渲染分层：音频层可以敏感地检测强音节、节拍、频段变化，但视觉层必须通过连续包络、状态机、惯性和较低频的主体轮廓承接这些事件，避免把每个短时特征都直接画成几何变化。

## 2026-07-02 - 高位波峰微小变化应冻结

用户反馈：部分波峰到达高点后仍会出现很小的局部变化。后续优化应对高位波峰设置视觉阈值，低于阈值的 y 方向变化不更新；只有明显变化才让峰顶继续运动，避免峰顶细小抖动破坏自然感。

## 2026-07-02 - 横向流速应跟随安静程度与节奏

用户偏好：安静时波浪横向变化也应明显减少，只保留慢慢流动；真的有声音时要及时响应，并根据声音或音乐节奏该快则快、该慢则慢。后续不应让主相位在近静音时仍保持全速漂移。

## 2026-07-02 - 空调风噪不应触发明显波浪

用户反馈：工位环境中主要声音是中央空调，偶尔有键盘声；这种持续背景声不应让水面出现明显波浪或快速左右流动。后续调参应把稳态风噪 / hiss 视为背景噪声底，而不是有效音乐节奏、语音事件或高频细节。

## 2026-07-02 - 波峰高度不应出现抖动式上下变化

用户反馈：当前动画中仍能看到一些波峰高度的抖动式上下变化，观感不好。后续峰高稳定应优先在连续 envelope、crest 和组件微扰层做死区与平滑，不应回到逐采样最终 y 值冻结，以免重新引入峰顶锯齿。

## 2026-07-02 - 声音大小和节奏快慢必须有明显视觉差异

用户反馈：正常音量说话与大声说话、普通音乐与大声音乐，不应在动画上差不多；正常语速与快速说话、慢节奏音乐与快节奏音乐，也不应在横向流速和波形变化速度上差不多。后续不能只用 `activity` 表示“有声音”，还要单独保留声强对比和节奏 / 事件密度对比。

## 2026-07-02 - 音量大小应带来水位高低变化

用户确认：水位本身也应根据音量大小有一定变化，声音小时处于低位，声音大时处于高位。此前 D15 为避免“整片水体机械匀速抬升”而把水位变化降级为近固定；后续应恢复适度涨落，但保持限幅和慢速潮位感，不让水位变化压过波浪振幅本身。

## 2026-07-02 - 录音确认按钮应跟随记事颜色且不能使用 FAB 叠层

用户偏好：录音完成后，点击确认/保存的主按钮应使用当前记事颜色，纯色记事显示纯色，渐变记事显示对应渐变；按钮内图标颜色根据该记事颜色自适应明暗。录音开始、录音中、重新录音等普通状态仍保持白色圆形按钮。

2026-07-02 的第一版 “透明 FAB + 背后色层” 在真机上出现普通态方形背景、确认态图标附近多边形残留。后续不要在该 dialog 的主录音按钮上使用 `FloatingActionButton` 或 FAB 叠层方案，应统一使用单个圆形按钮，由按钮本身承载圆形纯色/渐变背景与自适应图标。

## 2026-07-02 - 录音 dialog 高度按宽度四比三

用户偏好：记事详情页录音 dialog 当前宽度为 `280dp`，高度不要维持原来的 `320dp`，应调高为宽度的 `4/3`，即约 `373.33dp`。由于该 dialog 根布局以 `null parent` 充气，`layout_height` 与 `minHeight` 需要同步设置。

## 2026-07-02 - 录音 dialog 高度改为 360dp

用户进一步调整：录音 dialog 高度不再使用 `373.33dp`，改为固定 `360dp`。根布局 `layout_height` 与 `minHeight` 仍需要同步设置。
