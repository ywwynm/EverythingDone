# 偏好 — 录音波形可视化改造
## 2026-07-03 - 三个已有版本的偏好排序（用户明确）
用户对三个录音波浪版本的喜好排序：v2 `RecordingWaveVisualizer`（提交 753a1bf7，生成式波浪生命周期 + 多浪包 + `RecordingAudioAnalyzer`/`RecordingWaveDriveFrame`）最喜欢；其次 v1 `VoiceVisualizer`（提交 3cacdd19，多层多分量正弦合成 + layer-local surge + `VoiceAudioFrame`）；Fable `OceanWaveVisualizerFable`（当前 HEAD 接线，仅因是最新提交而挂在 dialog 上）效果不好，只是放着。新一轮 Opus 版本设计与取舍应以 v2 为主要正面参照、v1 为次要参照，Fable 不作为参照。

## 2026-07-03 - 水位覆盖按钮不能只做微调
用户反馈：上一版水位只升高了一点点，最深色那道浪仍然没有明显盖过录音按钮。后续校准应按按钮实际 top 高度来判断，而不是凭比例微调；在 `360dp` dialog 中，底部按钮行高 `96dp`，主录音按钮 top 大约在 `284dp`，最前景深色浪的静态水面需要明显高于这个位置，例如约 `270dp` 附近，才能视觉上真正进入按钮区域。

## 2026-07-03 - 初始水位要盖过录音按钮高度，毛刺要柔化
用户反馈：波浪偶尔仍会出现一些毛刺；初始水位稍低，导致最深色前景浪没有盖过录音按钮的高度。后续调参应把整片水体基座略微上移，让前景深色水面在静态或低能量时也能进入按钮所在高度；毛刺处理应优先针对孤立尖点、过细表面细节和局部高频，而不是降低大浪高度、减少层数或削弱整体野性。

## 2026-07-03 - 残余阶梯感优先检查合并连续性
用户反馈阶梯状折点已经少了很多，但仍偶尔存在，并怀疑波浪合并处还有问题。后续处理这类问题时，应优先检查同层多浪包合并是否仍依赖单个浪包的正负分段、合并后的限幅支持量是否连续，以及 cubic 路径重建是否在波峰/波谷附近过冲；不要只通过继续增加采样点、削弱浪高或降低野性来掩盖。

## 2026-07-03 - 波峰卡顿应通过保质优化解决
用户反馈：声音比较大、动画比较丰富时，波峰处会有一些小卡顿。后续处理这类问题不能通过降低浪高、减少层数、降低野性或削弱高能量响应来掩盖；应优先优化同帧重复计算、路径重建方式、缓存和连续插值，让高能量场景保持丰富画面同时稳定帧时间。

## 2026-07-03 - 阶梯式下折应优先检查连续性，而不是只加采样点
用户反馈仍能看到一种不易描述的锯齿：像阶梯一样，本来平滑的曲线会突然往下折一下。后续判断这类问题时不能只归因于采样点数不足；采样不足会放大锯齿，但如果几何合成中存在正负分量分段、硬阈值、软限幅平台或相邻浪包抵消时的斜率突变，就算提高采样密度也会保留这种折点。优先保证生成浪合成函数本身连续、斜率自然，再用更高采样密度辅助渲染。

## 2026-07-03 - 低水位应更慢，强声必须能生成高大浪
用户确认同层多浪包版本比之前效果更好，但仍有三点偏好需要继续遵守：低水位时波浪横向流速也要更低；不能出现矩形锯齿感的硬折角；在声音较大、强节拍或音乐高潮等必要场景，必须能出现明显更高、更大的浪，不能因为软限幅和稳定性约束把所有波峰都压得偏低。

## 2026-07-03 - 后浪不能瞬间压掉已升起的前浪
用户反馈：有时会出现一个波峰在瞬间突然下压。后续同层中新生成的浪不应覆盖、抹掉或瞬间反相压低已经升起/正在渲染的浪；它应作为新的波浪包进入同一层，和已有波浪通过连续叠加、错峰、软干涉和生命周期演化来影响画面。允许出现建设性叠加形成更大的浪，也允许有限的抵消，但抵消必须是随传播和包络渐进发生，不能表现为当前波峰突然塌下去。

## 2026-07-03 - 生成式波浪也必须足够野性
用户反馈生成式生命周期版本虽然减少了当前波浪原地乱颤，但整体太平淡、野性不够。后续不能因为避免当前波浪被改写，就把新浪出生参数做得过于保守；强音、强节拍和音乐高潮应在下一道浪出生时体现为更高的 crest、更快的传播、更明显的尾浪、更多错峰叠加。可以让强事件同时生成主浪和副浪，但仍要保持每道浪出生后按自身生命周期自然演化。

## 2026-07-03 - 音乐变化主要影响下一道浪的生成
用户提出并确认一个更好的方向：音乐或声音变化不应强行改变当前正在呈现的波浪，而应主要体现在下一道波浪的生成上。每道波浪自身应按自然方式完成从上升到下降的完整生命周期；音乐越密集、节奏越快，新波浪生成越快。由于界面中有 6 道波浪，可以通过多个生命周期错峰叠加来跟上音乐，而不是让同一道浪原地乱颤。

## 2026-07-03 - 声音变化应生成行进波峰，而不是原地长成山
用户反馈：当前版本在出现声音变化时，会在原地把已有波形拉成波峰和波谷，看起来像一座座山，而不是自然升起并传播的波浪。后续强声、节拍和能量变化不应主要通过整条基础波的振幅乘法体现；应优先注入局部、有生命周期、会沿水面移动的波峰/波场扰动，让波峰从水体里自然升起并前进。

## 2026-07-03 - 波谷不能明显低于基座水位
用户反馈最新高能版本会在声音变化时让波谷直接落到 dialog 底部。后续波浪可以保留较大的向上波峰和高能量野性，但向下位移必须相对每层平均基座水位设置软阈值，不能让 trough 比基座水位低太多；限幅也不能做成硬裁切或逐点冻结，避免产生平直边、锯齿或机械感。

## 2026-07-03 - 小幅输入变化需要阈值门控并平滑追赶
用户强调轻微颤动不应通过瞬时 `set` 式改变传到视觉层。音频 drive 的微小变化需要先经过死区/阈值过滤，只有超过阈值才更新目标值；已经更新的目标仍必须由动画状态连续追赶，像 `animate().xxx()` 一样顺滑变化，而不是直接改写最终几何位置。

## 2026-07-03 - 主波浪个性不要过度固定职责

用户偏好新录音波浪的 6 道主波浪不要被分配过细、过明确的职责；可以保留轻微层次倾向，但整体应更随机、更自然。每道浪通过透明度、惯性、延迟、相位、局部扰动和响应曲线形成个性，而不是像固定频段轨道。

## 2026-07-03 - 音频特征层也要重新设计

用户不同意直接复用当前 `VoiceAudioFrame` 作为新 visualizer 的输入。新一轮方案需要重新调研并设计音频特征提取层，再由新的视觉层承接；现有录音链路和特征字段只能作为集成边界参考，不能作为方案前提。

## 2026-07-03 - 动画质量目标不能折中

用户再次强调新录音波浪不能选择偷懒或折中的方案；目标是高质量、自然、美观、流畅、响应充分且接近完美效果的动画。实现时可以分层、渐进和调参，但每个设计选择都应服务于最终质量，而不是为了少改代码或快速完成而牺牲表现。

## 2026-07-03 - 新建录音波浪，不参考现有实现

用户要求重新设计录音 dialog 的波浪动画时，不再沿用或参考现有 visualizer 源码。本轮可以读取录音 dialog 的宿主、布局和音频特征数据流以完成集成，但不得打开现有 visualizer 实现文件。用户已取消“必须使用 `Fable` 类名后缀”的要求，新类使用清晰的领域命名即可。

新的波浪动画需要同时满足两组看似冲突的审美要求：在安静、空调风噪、低能量背景下保持平缓、轻柔、慢速；在明显人声、强音节、快语速、音乐高潮和强节拍下，要有足够明显的音量、音色、节奏和速度差异，不能一直显得普通、慢悠悠或不紧不慢。

视觉内容应足够丰富，优先采用约 6 道半透明波浪。每道浪之间需要共享同一片水体的整体语言，但拥有不同透明度、惯性、延迟、局部扰动、相位和随机个性；随机性应是连续、有机的，而不是逐帧跳变。

允许在 6 道主波浪之外加入轻量“表面生命层”，例如有效声音时出现的微弱高光、泡点、涟漪斑或短促光泽扫过；但它只能在 `alive` / `surge` 状态出现，不能改变主轮廓，也不能在安静态持续显眼。

## 2026-07-02 — 保留随机、灵动、有个性的波浪

用户明确偏好：波浪要有随机、灵动的感觉，每道浪像有自己的个性。不要让所有波浪在同一时刻做出同样的上升、下降或变化动作；需要随机的先后顺序、错峰响应、不同惯性和不同局部表现。

D20 的波形美感收束让整体变得平稳、波浪彼此相似，野性不如上一版。后续优化应回到 D19 的自由多分量基底，再解决形状问题，而不是继续加强统一谱形约束。

## 2026-07-02 — 歌曲场景需要更跟节拍

用户反馈：旁边播放比较激情、节奏较快的歌曲时，当前录音波形动画仍显得慢悠悠，和歌曲节拍、演唱速度不够贴合。后续优化需要让高能量、快节奏音乐触发更即时的视觉反应，同时不能牺牲此前确认的随机、灵动、每层有个性的波浪观感。

## 2026-07-02 — 避免水面轮廓细纹过多

用户反馈：D24 的细纹太多，水面容易全是细纹，观感像锯齿，很不好看。后续节奏响应不能通过大量高频几何细纹来体现；应优先让主体轮廓保持圆润、清楚，把节奏感放到更宽的脉冲、局部浪涌、相位/速度变化或不破坏轮廓的轻量表面效果里。
## 2026-07-02 — 响应要快，但不能用跳变换速度

用户确认 D25 整体效果和响应速度更好，但仍不接受某个波浪在已经升起后突然上下颤动或峰值被重新改写的感觉。后续所有节奏、瞬态、beat phase、backfill 之类的低延迟优化，都必须通过连续包络、限速相位吸附或目标合并实现，不能直接写当前视觉值来换取即时响应。

## 2026-07-02 — 录音水体必须遵循记事渐变方向

当当前记事使用渐变背景时，录音波浪的渐变方向需要与 `ThingBackground.orientation` 保持一致，而不是固定横向渐变。

## 2026-07-02 — 锁屏返回后动画必须自动恢复

用户反馈打开录音 dialog 后锁屏再回来，动画可能完全停止。录音波浪的自驱动画循环需要显式处理 window 可见性、聚合可见性和焦点恢复，不能只依赖 attach 时启动的一次 `postInvalidateOnAnimation()` 链。
## 2026-07-02 - 小变化不应过度驱动波浪

用户偏好：录音波浪不需要对所有很小的音量、频段或节奏参数变化都敏感；细小变化可以被忽略，以避免果冻感和局部反复颤动。后续优化应优先保留强音节、明显节拍和音色差异的表现，而不是让微小输入噪声持续改变已经成形的波峰波谷。

## 2026-07-02 - 安静场景应降低视觉活跃度

用户反馈：相对安静的情况下不需要高频率动画播放和波浪变化。后续优化应让近静音或低能量输入进入更低活跃度的视觉状态，只保留很慢、很轻的水体漂移；不要让 20ms 音频特征刷新、持续 rhythm energy、微小 onset 或高频噪声持续触发明显波峰波谷变化。

## 2026-07-02 - 自然水感优先于逐帧音频拟合

用户判断：及时反映音量、音调、节奏等音乐变化，和自然、灵性的波浪动画之间可能存在冲突。后续方案应把音频事件检测和水体渲染分层：音频层可以敏感地检测强音节、节拍、频段变化，但视觉层必须通过连续包络、状态机、惯性和较低频的主体轮廓承接这些事件，避免把每个短时特征都直接画成几何变化。

## 2026-07-02 - 高位波峰微小变化应冻结

用户反馈：部分波峰到达高点后仍会出现很小的局部变化。后续优化应对高位波峰设置视觉阈值，低于阈值的 y 方向变化不更新；只有明显变化才让峰顶继续运动，避免峰顶细小抖动破坏自然感。

## 2026-07-02 - 横向流速应跟随安静程度与节奏

用户偏好：安静时波浪横向变化也应明显减少，只保留慢慢流动；真的有声音时要及时响应，并根据声音或音乐节奏该快则快、该慢则慢。后续不应让主相位在近静音时仍保持全速漂移。

## 2026-07-02 - 空调风噪不应触发明显波浪

用户反馈：工位环境中主要声音是中央空调，偶尔有键盘声；这种持续背景声不应让水面出现明显波浪或快速左右流动。后续调参应把稳态风噪 / hiss 视为背景噪声底，而不是有效音乐节奏、语音事件或高频细节。

## 2026-07-02 - 波峰高度不应出现抖动式上下变化

用户反馈：当前动画中仍能看到一些波峰高度的抖动式上下变化，观感不好。后续峰高稳定应优先在连续 envelope、crest 和组件微扰层做死区与平滑，不应回到逐采样最终 y 值冻结，以免重新引入峰顶锯齿。

## 2026-07-02 - 声音大小和节奏快慢必须有明显视觉差异

用户反馈：正常音量说话与大声说话、普通音乐与大声音乐，不应在动画上差不多；正常语速与快速说话、慢节奏音乐与快节奏音乐，也不应在横向流速和波形变化速度上差不多。后续不能只用 `activity` 表示“有声音”，还要单独保留声强对比和节奏 / 事件密度对比。

## 2026-07-02 - 音量大小应带来水位高低变化

用户确认：水位本身也应根据音量大小有一定变化，声音小时处于低位，声音大时处于高位。此前 D15 为避免“整片水体机械匀速抬升”而把水位变化降级为近固定；后续应恢复适度涨落，但保持限幅和慢速潮位感，不让水位变化压过波浪振幅本身。

## 2026-07-02 - 录音确认按钮应跟随记事颜色且不能使用 FAB 叠层

用户偏好：录音完成后，点击确认/保存的主按钮应使用当前记事颜色，纯色记事显示纯色，渐变记事显示对应渐变；按钮内图标颜色根据该记事颜色自适应明暗。录音开始、录音中、重新录音等普通状态仍保持白色圆形按钮。

2026-07-02 的第一版 “透明 FAB + 背后色层” 在真机上出现普通态方形背景、确认态图标附近多边形残留。后续不要在该 dialog 的主录音按钮上使用 `FloatingActionButton` 或 FAB 叠层方案，应统一使用单个圆形按钮，由按钮本身承载圆形纯色/渐变背景与自适应图标。

## 2026-07-02 - 录音 dialog 高度按宽度四比三

用户偏好：记事详情页录音 dialog 当前宽度为 `280dp`，高度不要维持原来的 `320dp`，应调高为宽度的 `4/3`，即约 `373.33dp`。由于该 dialog 根布局以 `null parent` 充气，`layout_height` 与 `minHeight` 需要同步设置。

## 2026-07-02 - 录音 dialog 高度改为 360dp

用户进一步调整：录音 dialog 高度不再使用 `373.33dp`，改为固定 `360dp`。根布局 `layout_height` 与 `minHeight` 仍需要同步设置。

## 2026-07-03 - 新 visualizer 不能参与撑大 dialog

用户反馈：新 `RecordingWaveVisualizer` 发布后，录音 dialog 的宽高又发生变化，尤其高度明显变高。后续任何录音波浪自定义 View 都必须在 `WRAP_CONTENT / AT_MOST` 测量链里声明不超过 `280dp * 360dp` 的固有尺寸，不能依赖默认 `View.onMeasure()` 接受父容器可用高度。

## 2026-07-03 - 波峰应圆润且跳动不能过快

用户反馈：新波浪的波峰太尖锐，且跳动太快。后续调参应优先使用较宽的局部浪涌包络、较慢的视觉 attack、较低的高频交叉分量和更弱的 crest 线条；不要用窄而快的瞬态波包来体现“野性”。

## 2026-07-03 - 圆润后仍要保留显著起伏和较深颜色

用户反馈：修圆润后，浪的上下起伏可以再大、更显著，水位起伏也可以再大一点点；当前颜色太淡，需要更深。后续调参应优先增加主体波幅、慢速潮位跨度、填充透明度和颜色深度，而不是通过尖锐峰值或快速跳动来制造存在感。

## 2026-07-03 - 顶部水体不能是平直浅线，渲染不能有滑动竖条

用户反馈：最上方总有一道几乎一直平着的浅浪，希望它也有起伏；同时当前实现里像有从左往右滑动闪烁的竖条，渲染质量不高。后续水体底层边界不能用明显水平直线，主波填充应使用平滑曲线和足够密的采样；表面高光不能表现为短促、竖向、持续滑动的亮条。
## 2026-07-03 - 去除波浪白边、增强野性并让音量优先于音调
